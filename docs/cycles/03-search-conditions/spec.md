# 기능 명세: 검색 조건 강화 (제목 / 저자 / 출판사 중 하나 고르기)

- 사이클: 03-search-conditions, 작성일 2026-09-29
- 범위: `scope.md` "포함"만 다룹니다. 사이클 01·02의 규칙(묶음 검색, 우선순위, 가입 표시, 정렬, 호출 예의)은 바꾸지 않고, 달라지는 곳만 적습니다.
- 여러 조건 AND 검색은 조사 후 제외했습니다 (사용자: "A만 가고", 2026-09-29). 조사 기록은 3장에 남깁니다.
- 입력 방식, 글자 수, 조건 변경 동작, 옮긴이 처리는 사용자가 Claude 추천안을 골랐습니다(2026-09-29). 고른 이유는 [이유 미확인]입니다. 글자 수는 "어짜피 조회 결과에 페이지 수 제한있는거 아니야?", "외자 이름 얼마나있나"를 확인한 뒤 골랐습니다.

## 1. 사용자 이야기

- 읽고 싶은 책의 저자를 아는 사람이, 저자 이름으로 검색해 그 저자의 책을 어느 도서관에서 빌릴 수 있는지 보고 싶다. 제목이 기억나지 않을 때도 찾기 위해.
- 특정 출판사의 책을 찾는 사람이, 출판사 이름으로 검색하고 싶다.
- 지금처럼 제목으로 찾는 사람은 달라지는 것 없이 그대로 검색하고 싶다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 검색 조건 | 검색어를 도서관 사이트의 어느 칸에서 찾을지: 제목, 저자, 출판사 중 하나 [확정] (사용자, 2026-09-29). 옮긴이는 없음 [확정] |
| 조건별 검색 | 고른 조건 하나를 사이트의 해당 칸으로 검색하는 것. 사이클 02까지의 제목 검색은 조건이 "제목"인 경우 |

## 3. 화면 종류별 검색 지원 (조사 결과)

실제 호출로 확인했습니다 (2026-09-29, 우리 User-Agent `chaekcheck/0.0.1`, 1.2초 간격, 각 종류 표본 1~2곳). 모두 부분 일치입니다 (예: 저자 "김달" → "김달우"도 나옴).

| 화면 종류 | 제목 | 저자 | 출판사 | 사이트가 해 주는 AND (기록용, 이번 범위 밖) | 표본 |
|---|---|---|---|---|---|
| `KYOBO_V1` | `schClst=ctts` | `schClst=autr` | `schClst=pbcm` | 느슨함: `schClst`에 필드를 쉼표로 여럿 주면 "그중 어디에든"(OR), `reSch=1&reSchTxt=`(결과 내 재검색)로 둘째 검색어를 AND. 두 검색어 모두 같은 필드 묶음에서 찾음, 검색어 2개까지 | 고흥: 제목 "사랑" 100건, 저자 "김" 671건, `ctts,autr` "사랑" + 재검색 "김" 19건, `autr` "김" + 재검색 "사랑" 0건 |
| `KYOBO_SUBSCRIPTION_V1` | 같음 | 같음 | 같음 | 같음 | 세종(구독): 저자 "김달" 37건, `ctts,autr` "사랑" + "김달" 8건(김달우 책 섞임) |
| `YES24_V1` | `srch_order=title` | `author` | `publisher` | 없음. 띄어 쓴 두 단어는 0건 | 원주: 제목 "사랑" 20건, 저자 "김달" 2건, 출판사 "빅피시" 1건 |
| `YES24_V2` | `srch_order=title` | `author` | `publisher` | 느슨함: `srch_order=total`에 단어를 띄어 쓰면 단어마다 제목·저자·출판사 중 어디에든 있는 책 | 횡성: 제목 "사랑" 91건, 저자 "김" 942건, 출판사 "빅피시" 15건, `total` "사랑 김달" 2건 |
| `YES24_V3` | `srch_order=title` | `author` | `publisher` | 느슨함: `total` + 띄어쓰기 | 김천: 저자 "김달" 6건, 출판사 "빅피시" 50건(제목 "빅피시" 0건), `total` "사랑 김달" 3건 |
| `GANGNAM_V1` | `search=title` | `search=author` | `search=publisher` | 없음 | 강남구: 저자 "김달" 10건, 출판사 "빅피시" 60건 |
| `ELIB_PORTAL_V1` | 제목 전용 없음 → 기본 검색 (사이클 02와 같음) | `table.do?search_text=김달&author_name=김달` (검색어 + 저자 거르기) | `table.do?search_text=빅피시&book_pubname=빅피시` | 없음 | 아래 "포털 재조사" |

**포털 재조사 (2026-09-29, 7곳 모두)** — 처음 조사(부산·경북)의 판정 "`search_type=AUTHOR`로 저자 검색"은 **틀렸습니다.**
- `search_type`의 AUTHOR/TITLE/PUBLER는 필드가 아니라 **자료 종류**입니다 (부산 화면 표시: "소장자료 / 구독자료 / 학술원문"). "사랑"으로 기본 검색과 `search_type=AUTHOR`의 건수가 같았습니다: 부산 279, 경북 665, 인천 154, 전북 1420, 강원 222. 경기교육청은 `search_type=AUTHOR`·`PUBLER`에 0건을 돌려줍니다. **보내면 안 됩니다.**
- 기본 검색(`search_text`)은 제목·저자·출판사를 모두 찾습니다 (부산 "빅피시" 기본 검색 100건). 처음 "김달" 저자 검색이 되는 것처럼 보인 이유입니다.
- 저자·출판사 거르기는 결과 옆 목록(저자별·출판사별 건수)이 쓰는 `table.do`의 `author_name`·`book_pubname`입니다.
  - 검색어(`search_text`)와 함께 줄 때만 동작합니다. 검색어 없이 거르기만 주면 0건입니다 (부산). `index.do`에서는 무시됩니다.
  - 값과 **정확히 같은** 저자·출판사만 남습니다. "김달" 기본 검색 → 거르기: 부산 11→3, 대구 14→3, 경기교육청 18→7. 기본 검색에 섞여 있던 "김달국", "김달우" 책이 빠집니다. 다른 사이트는 부분 일치라 "김달"로 김달국도 나옵니다.
  - 쪽 넘김이 됩니다 (전북 출판사 "빅피시" 58건, 1·2쪽이 다른 책).
- 대구는 우리 조사 도구(Python)로는 TLS 연결이 안 되어 Windows curl로 확인했습니다 (서비스 JDK에서는 ADR-0022로 연결됨).

정리
- 저자·출판사 검색은 **7종 모두 사이트가 지원**합니다. 포털만 방식이 다릅니다(검색어 + 정확히 일치하는 거르기) [확정] (사용자: "검색어 + 걸러내기, 이름 정확히 일치", 2026-09-29).
- 포털의 "제목"은 제목 전용 칸이 없어 기본 검색입니다. 저자·출판사에 검색어가 든 책도 섞일 수 있습니다 (사이클 02와 같은 동작).
- 전주(`YES24_V1`)는 화면에 저자 이름을 표시하지 않습니다(저자 칸이 비어 있거나 ","). 저자 검색 자체는 됩니다(저자 "김" 329건). 그래서 전주 결과 줄은 저자 칸이 비어 보입니다 [확정] (호출 시험).
- 부산 포털 결과에는 오디오북(`data-type="ADO"`)이 섞여 있습니다. 사이클 02부터 같은 동작이며 이번 범위 밖입니다 (backlog).

| 항목 | 내용 | 규칙 | 상태 태그 |
|---|---|---|---|
| 입력: 검색 조건 | 제목 / 저자 / 출판사 중 하나 | 기본값은 항상 제목. 주소에 조건이 있으면 그 조건. 마지막에 쓴 조건을 기억하지 않음 | [확정] (사용자, 2026-09-29) |
| 입력: 검색어 | 정규화 후 2~50자 (앞뒤 공백 제거, 연속 공백 하나로. 사이클 01과 같음) | 모든 조건에 같은 규칙. 외자 이름은 성을 붙이면 2자라 검색됨(김훈, 한강). 성만("김") 넣는 검색은 막음 | [확정] (사용자 "모두 2자부터 유지", 2026-09-29) |

| 출력: 결과 | 사이클 02와 같은 결과 줄·요약 줄·건수 | 사이트가 고른 칸으로 찾은 결과를 그대로 씀 | [확정] (사이클 02 규칙) |

## 5. 동작 규칙

### 5.1 입력 화면

- 검색창 안 왼쪽 드롭다운으로 조건(제목 / 저자 / 출판사)을 고릅니다 [확정] (사용자, 2026-09-29). 기본은 항상 제목입니다 [확정] (사용자, 2026-09-29). 화면 구조는 `flow.md`.
- 참고: 한 글자 검색을 막는 이유는 요청 양이 아니라 결과의 쓸모입니다. 요청 양은 도서관당 10줄·묶음 20줄 규칙으로 이미 제한됩니다(사용자 질문에 대한 확인, 2026-09-29).
- 검색창의 안내 문구는 고른 조건에 맞춥니다 (예: "저자 이름을 입력하세요"). 문구는 screen-flow에서 정합니다.
- 모바일에서도 같은 구성입니다. 배치는 screen-flow에서 정합니다.

### 5.2 조건별 검색

- 고른 조건을 그 사이트의 해당 칸으로 검색합니다 (3장 표). 포털의 제목은 사이클 02처럼 기본 검색입니다.
- 결과·순서·묶음 규칙(20줄, 8초, 동시 5곳, 라운드 로빈 "더 보기", 도서관별 "더 보기")은 사이클 02 제목 검색과 같습니다.
- 캐시(3분)는 조건과 검색어가 모두 같을 때만 같은 것으로 봅니다. 제목 "김달"과 저자 "김달"은 다른 검색입니다 (ADR-0009, 캐시 키에 필드가 이미 있음).
- 결과 줄의 제목 비교 키(`titleKey`)와 묶음 안 정렬은 사이클 02 그대로입니다. 저자·출판사 검색에서도 같은 제목끼리 모읍니다.

### 5.3 조건 바꾸기

- 검색 결과가 보이는 상태에서 드롭다운의 조건만 바꾸면, 검색 버튼을 누르지 않아도 입력창의 검색어로 **바로 다시 검색**합니다 [확정] (사용자, 2026-09-29). 사이클 02의 필터·범위 토글과 같은 동작입니다.
- 다시 검색하면 계획과 묶음 상태를 버리고 첫 묶음부터 시작합니다.
- 입력창의 검색어가 2자 미만이면 다시 검색하지 않고 안내만 합니다 [안].

### 5.4 바뀌지 않는 것

- 도서관 우선순위·범위(`scope`)·가입 표시·주의·안내, 판정(`availability`), 포털 상세 판정, 호출 예의(캐시 3분, 같은 호스트 동시 1건·1초, User-Agent), 바쁜 호스트 건너뛰기 (ADR-0020)

## 6. 상태별 동작

| 상태 | 동작 |
|---|---|
| 입력 오류 | 검색어가 정규화 후 2자 미만이거나 50자 초과이면 검색하지 않고 안내합니다 (사이클 01과 같음). API에 조건 파라미터(`title`/`author`/`publisher`)가 없거나 둘 이상이면 서버가 400을 돌려줍니다 (ADR-0025) |
| 로딩 | 사이클 02와 같음 (도서관 N곳 조회 중) |
| 결과 없음 | 사이클 02와 같음. 안내 문구에 고른 조건을 넣습니다 (예: 저자 "…"(으)로 찾은 책이 없습니다) [안 문구] |
| 외부 오류·지연 | 사이클 02와 같음 (그 도서관만 `library-failed`, 8초) |

## 7. 수용 기준

- AC-1: 조건 "저자"로 "김달"을 검색하면 결과 줄의 저자 칸에 모두 "김달"이 들어 있다. 요청 URL은 교보 `schClst=autr`, YES24 `srch_order=author`, 강남구 `search=author`, 포털 `table.do?search_text=김달&author_name=김달`이다. 포털 결과는 저자가 정확히 "김달"인 책만이다. (화면 + 서버 로그)
- AC-2: 조건 "출판사"로 "빅피시"를 검색하면 결과 줄의 출판사 칸에 모두 "빅피시"가 들어 있다. 요청 URL은 교보 `schClst=pbcm`, YES24 `srch_order=publisher`, 강남구 `search=publisher`, 포털 `table.do?search_text=빅피시&book_pubname=빅피시`이다. 어느 포털 요청에도 `search_type=AUTHOR`·`PUBLER`가 없다. (화면 + 서버 로그)
- AC-3: 조건 "제목"(기본)으로 검색하면 사이클 02와 같은 URL(교보 `schClst=ctts`, YES24 `srch_order=title`, 강남구 `search=title`, 포털 기본 검색)과 같은 결과가 나온다. (서버 로그 + 기존 테스트)
- AC-4: 저자 검색에서도 라운드 로빈 "더 보기"와 도서관별 "더 보기"가 같은 조건으로 다음 쪽을 부른다(포털 2쪽 포함). (화면 + 서버 로그)
- AC-5: 결과가 보이는 상태에서 드롭다운 조건만 바꾸면 검색 버튼 없이 바로 다시 검색되고, 이전 결과와 "더 보기" 상태가 사라지고 첫 묶음부터 나온다. 새로고침하면 고른 조건과 검색어가 그대로다. (화면)
- AC-6: 같은 조건·검색어로 3분 안에 다시 검색하면 캐시에서 나오고(`cached: true`), 조건만 다르면(제목 "김달" / 저자 "김달") 캐시를 함께 쓰지 않는다. (API 응답 + 서버 로그)
- AC-7: API에 조건 파라미터(`title`/`author`/`publisher`)가 없거나 둘 이상이면 스트림을 열기 전에 400이다 (ADR-0025, design-delta에서 바뀜). 검색어 1자·51자는 조건과 상관없이 요청이 가지 않고 안내가 보이며, API에 직접 보내면 400이다. (화면 + API 호출)
- AC-8: 사이클 01·02의 호출 예의가 지켜진다: 같은 호스트 요청 간격 ≥ 1초·동시 1건, 모든 요청에 우리 User-Agent. (서버 로그)

## 8. 비목표

- 여러 조건을 함께 거는 AND 검색 — 조사 후 제외 (사용자: "A만 가고")
- 옮긴이 검색 — 제외 [확정] (사용자). YES24는 저자 칸에 옮긴이가 함께 있어 저자 검색에 옮긴이 이름이 걸릴 수 있지만, 걸러 내지도 따로 안내하지도 않음 [확정] (사용자 "그대로 둠", 2026-09-29)
