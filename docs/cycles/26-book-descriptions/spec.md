# 기능 명세: 책 설명 한 곳에 모으기 (사이클 26)

- 작성 2026-10-27. 범위는 [scope.md](scope.md) "범위 결정" 표 (#1~#7 사용자 결정 2026-10-27)
- 지금 상태는 dev main `905eab7` 코드에서 확인 (scope.md "지금 상태")

## 사용자 이야기

- 책을 찾는 이용자는 추천목록·책첵 추천·AI 검색·일반 검색 어디서 책을 열어도 **같은 요약**을 보고 싶다. 화면마다 설명이 다르면 같은 책인지 헷갈리기 때문 [이유 미확인: dev 제안의 "생기는 문제"를 사용자가 승인]
- 일반 검색으로 책 상세 화면에 들어온 이용자는 그 책이 어떤 책인지 **요약과 표지**로 알고 싶다 (#5 승인)
- 운영자(사용자)는 새 종류의 책 설명을 넣을 때 **한 곳**에만 넣고 싶고, 다시 가져오기 뒤에 설명이 엉뚱한 책에 붙지 않기를 바란다 (#2 승인)

## 입력과 출력

| 항목 | 내용 | 규칙 | 상태 태그 |
|---|---|---|---|
| 책 요약 | 책마다 하나, 해요체, 1~300자 | 지금 `foryou.book_blurb`의 글(책첵 요약)이 유일한 요약. 추천목록 요약 파일 `picks/ai-summaries.tsv`는 없앰 | [확정] (#3) |
| 요약 표시 | 요약 위 「AI 요약 ⓘ」 | 책 창과 책 상세 화면에 붙임. 책첵 추천 탭 카드 목록은 지금처럼 탭 맨 위 한 줄 | [확정] (명세 결정 #1, 2026-10-27) |
| 책 표지 | 책마다 하나, 표지 파일 키(sha1) → `/covers/<key>.jpg` | 지금 `foryou.book_cover`의 값 | [확정] (#1, #4) |
| 추천목록 책의 표지 | 목록 줄마다 저장된 표지(사서추천은 `picks.cover`의 200px JPEG, 나머지 목록은 표지 파일) | 사용자 구조 (2026-10-28, #5·#7~#10 대신): ① 우리 책 목록에 있고 표지 있는 판이 있으면 그 판의 `catalog` 표지 ② 우리 책 목록에 있지만 어느 판에도 표지가 없으면 추천목록 그림 ③ 우리 책 목록에 없으면 추천목록 그림. 추천목록 그림은 `catalog`에 넣지 않음. 사서추천 그림은 그림 파일로, `picks.cover` 지움 | [확정] 구조. ①에서 판 고르는 차례: 줄이 연결하는 판(소장 많은 판)의 표지 먼저, 없으면 같은 책의 다른 판 중 최신 판 → 소장 많은 판 [확정] (명세 결정 #11 승인 2026-10-28) |
| 꼬리표 + 사전 | 책마다 여러 개, 사전에 있는 낱말만 | 지금 `picks.book_tag`, `picks.tag_dictionary` 그대로의 내용, 지금 0줄 | [확정] (#4) |
| 책 프로필 | 분야, 세부 분야, 소설 여부, 장르, 나라, 대상, 수준, 형식 (지금 파일의 9칸: id 포함) | 지금 `book-profiles.tsv` 내용을 DB로 | [확정] (#4) |
| AI 검색 찾기용 한 줄 | 책마다 1~300자 | `catalog`로 옮김. 사용자: "지금 더 군데 중복저장되는거는 없었으면해" (명세 결정 #3 미승인). AI 검색 사본 표(`aisearch.search_book`)도 없애고 `catalog` 찾기 기능을 부름. 도서관 목록(`library_ids`)만 `catalog.book_search`에 예외로 남음 | [확정] (명세 결정 #6, ADR-0165, 예외 ADR-0160) |

## 동작 규칙

### R1. 한 곳에서 맡음
- 요약·표지·꼬리표+사전·책 프로필은 `catalog` 모듈이 저장하고, 다른 모듈은 `catalog` 공개 API로만 읽는다 [확정] (#1)
- `foryou.BookBlurbs`, `foryou.BookCovers`, `ListedBook.aiSummary`의 파일 출처는 없어진다. `foryou`·`aisearch`·`picks`는 `catalog`에서 읽는다 [확정] (#1, #3)

### R2. 화면마다 같은 요약
- 추천목록 책 창, 책첵 추천 카드, AI 검색 카드, 책 상세 화면은 같은 책이면 같은 요약을 보인다 [확정] (#3, #7)
- 요약이 없는 책은 요약 칸 없이 보인다 (빈 칸·"요약 없음" 글 없음) [확정] (명세 결정 #1)
- 요약은 어디서도 자르지 않는다 [확정] (사이클 23 결정 "소개 글은 어디서도 자르지 않음", `docs/research/ai-recommend/session-state.md` 1-4절)
- 추천목록 줄 중 책 목록에 없는 책(책 번호 없음)은 요약이 없다. 지금은 ISBN이나 제목으로 목록 요약 파일에서 찾아 보이던 책이다 [확정: #3에서 파일을 없애기로 해 생기는 결과] — 운영 838줄(dev 26 0단계, 2026-10-28). 책 번호는 있지만 책첵 요약이 없던 783권은 배포 1 전에 채움 [확정] (사용자 "그래", 2026-10-28)

### R3. 책 상세 화면
- `/books/<책 번호>` 화면 위 책 정보(제목·저자·출판사·보유 도서관 수) 왼쪽에 표지, 그 아래에 요약 전체 [확정] (#5)
- 표지가 없으면 표지 자리를 비우지 않고 글을 왼쪽에 붙인다 [확정] (범위 결정 #5 설명, 사용자가 #5를 승인)
- 일반 검색 결과 목록의 줄에는 요약·표지를 넣지 않는다 [확정] (#5)

### R4. 다시 가져오기
- 설명은 책 번호로 저장한다 [확정] (#2)
- 다시 가져오기가 책 번호를 버리면(합쳐진 책의 큰 번호, 사라진 책), 같은 가져오기 작업 안에서 그 번호의 요약·표지·꼬리표·프로필을 지운다 [확정] (#2)
- 이어진 번호의 설명은 그대로 남는다. 새 번호(새 책, 갈라진 책)는 다음 설명 넣기 때까지 설명이 없다 [확정] (#2, dev `Ids.decide` 동작)
- 지운 수를 가져오기 기록(`collection.catalog_import.description_deleted_count`)에 남긴다 [확정] (ADR-0162)

### R5. 설명 넣기 (`book-texts`, `book-profiles`)
- 요약·표지·꼬리표·찾기용 한 줄은 지금처럼 `book-texts` 넣기로, 책 프로필은 새 넣기 명령 `book-profiles`(지금 9칸 파일, 전체 바꾸기)로 들어간다 [확정] (설계 결정 #7, ADR-0165)
- PC 쪽 만들기: 23·24 배치 합치기(24 결정 페이지 2026-10-24, 미결정)는 dev가 이미 다른 길로 끝냄 — 10만 권 작업(2026-10-26, dev `6-aisearch.md` 9절)에서 스크립트 하나(`scripts/aisearch/build_100k.py`)가 Haiku Message Batches로 `search_line`·`for_you_blurb`·`profile`을 만들었고, 결과는 kind별 파일 셋(AI 검색 넣기 파일, 요약 파일, `book-profiles.tsv`) [확정: dev 문서]. 사이클 26에서는 이 스크립트의 결과가 `catalog`로 들어가는 `book-texts` 파일(요약·찾기용 한 줄)과 `book-profiles` 파일로 나오고, 둘 다 첫 줄에 가져오기 번호를 적게 맞춘다 [확정] (ADR-0162·0165). 대상 범위(보유 많은 10만 권 중 소개 50자 이상 76,974권)는 바꾸지 않음
- 파일 첫 줄에 어느 가져오기 기준으로 만든 파일인지(`export_id`) 적고, 마지막으로 성공한 가져오기와 다르면 파일 전체를 거절한다 [확정] (#2). `book-texts`·`book-profiles` 둘 다 `neighbours` 넣기와 같은 방식(`# export_id=<uuid>`, 강제 넣기 설정) [확정] (ADR-0162)
- 같은 책에 요약이 다시 들어오면 새 글로 바꾼다 (출처 순서 없음: 요약은 한 종류) [확정] (#3)

### R6. AI 검색이 느려지지 않게
- AI 검색 카드는 표지·요약을 지금처럼 AI 호출과 겹쳐(동시에) 읽는다. 표지·요약은 카드에만 쓰고 AI 질문에는 넣지 않는다 [확정] (dev 24 세션 2026-10-27, scope.md "dev 세션이 알려 준 제약")
- 책 프로필은 요청마다 DB를 읽지 않는다. 서버가 시작할 때 한 번 읽어 메모리에 두고, 새로 넣은 뒤에는 서버를 다시 켠다 [확정] (dev 24 제약, ADR-0165)

### R7. 옮기기
- 사이클 26을 23·24 dev보다 먼저 개발한다. 23·24 dev 세션은 바뀐 표·API에 맞춰 고친다 [확정] (#6)
- 한 번의 배포에서 새 표를 만들고 옛 표·파일 내용을 그대로 복사하고 읽는 곳을 바꾼다. 옛 표(`foryou.book_blurb`, `foryou.book_cover`, `picks.book_tag`, `picks.tag_dictionary`, `aisearch.search_book`)는 다음 배포에서 지운다 [확정] (명세 결정 #4)
- 추천목록 요약 파일은 복사하지 않고 지운다 [확정] (#3)
- 책 프로필은 배포 1 뒤 지금 모델 폴더 파일을 `book-profiles` 명령으로 처음 넣는다. 첫 줄 가져오기 번호로 지금 책 목록과 같은 기준인지 검사된다 [확정] (ADR-0162·0165)

### R8. AI 검색 사본 표 없앰 [확정] (명세 결정 #6)
- `aisearch.search_book`(제목·저자·도서관 목록·찾기용 한 줄·글자 색인의 사본)을 없앤다. 찾기용 한 줄·글자 검색 색인·도서관 목록(예외, ADR-0160)은 `catalog.book_search`에 두고, AI 검색은 `catalog`의 찾기 기능을 불러 후보 책을 받는다
- 같은 글자 색인·같은 질의로 옮겨 빠르기를 유지한다. dev가 옮기기 전후 AI 검색 첫 글 시간을 재고, 늘었으면 배포 2(옛 표 지움) 전에 알린다
- 찾기 대상은 `catalog.book_search`에 줄이 있는 책. `collection`의 `book-texts` 넣기가 추천목록 책 전부 + 많이 가진 책 상위 N권에서, 넣기 파일의 kind `search_exclude` 줄에 적힌 책을 빼고 정한다(빼기 목록은 따로 저장된 표가 아니라 파일에 있음) [확정] (ADR-0165, architect F6)

### R9. 모든 책 표지를 운영에 [확정] (사용자 질문 2026-10-28) — 둘 곳은 **S3 + CloudFront** [확정] (사용자 "S3 + CloudFront 이걸로 하자", 2026-10-28, 비교는 research.md 1절)
- 사용자: "그건 카탈로그에 표지도 있도록 수집해야 하는 거 아니야? 지금 수집 중이고 반영할 것이지 않나?" (2026-10-28)
- 수집 PC가 받은 모든 책 표지(약 12~15GB [추론], 장당 9~11KB × 1,340,875권)와 추천목록 그림(사서추천 `picks.cover` 포함)을 S3 버킷(시드니)에 두고 CloudFront로 보낸다. 운영 서버 디스크(`/srv/chaekcheck/covers/`)에는 두지 않는다. 지금 운영에 올린 약 8만 장도 옮긴다
- 주소는 CloudFront 기본 도메인, CSP `img-src`에 추가, S3에는 PC만 올림 [확정] (ADR-0163)
- 비용: 저장 월 약 $0.38, 처음 올릴 때 PUT 약 $7.4(한 번), 전송은 CloudFront 늘 무료 한도(매달 1TB) 안 [추론]. 무료 플랜 동안 크레딧에서 빠짐
- 그러면 "우리 책인데 표지 없음"은 어느 도서관 사이트에도 그림이 없는 책(먼저 받은 범위에서 0.8%)만 남는다

## 상태별 동작

- 로딩: 책 상세 화면은 지금처럼 책 정보를 받은 뒤 그린다. 요약·표지는 책 정보와 같은 응답으로 받아 따로 기다리는 칸이 없다 [안]
- 결과 없음 (요약·표지 없는 책): R2, R3대로 칸 없이 보인다
- 외부 API 오류·지연: 해당 없음 (외부 호출 없음)
- 입력 오류 (설명 넣기 파일): 가져오기 번호 불일치, 줄 형식 오류면 파일 전체 거절, DB는 그대로 [확정: 지금 `book-texts` 동작 + #2]

## 수용 기준

- AC-1: 책첵 요약이 있는 책 하나를 추천목록 책 창, 책첵 추천 카드, AI 검색 카드, 책 상세 화면에서 열면 네 곳의 요약 글이 글자까지 같다
- AC-2: 일반 검색에서 그 책을 눌러 책 상세 화면에 들어가면 표지와 「AI 요약 ⓘ」 아래 요약 전체가 보인다. 검색 결과 줄에는 요약이 없다
- AC-3: 요약이 없는 책의 책 상세 화면에는 요약 칸이 없고, 표지가 없는 책은 표지 자리 없이 글이 왼쪽에 붙는다
- AC-4: 배포 1 직후, 옛 표와 새 표의 줄 수가 같다 — 요약(`foryou.book_blurb` → `book_summary`, dev 기록 2026-10-27 68,414), 표지 연결(`foryou.book_cover` → `book_cover`, 같은 기록 80,091 — 복사 시점, 134만 장 올리기 전), 꼬리표, AI 찾기(`aisearch.search_book` → `book_search`, 같은 기록 76,759). 프로필 수는 넣은 파일 줄 수(운영 `book-profiles.tsv` 77,551줄 [확정: dev 24 확인 2026-10-28, 서버 파일 md5가 PC 100k 모델과 같음])와 같다 (DB 조회)
- AC-5: 지금과 다른 `export_id`가 적힌 `book-texts` 또는 `book-profiles` 파일을 넣으면 거절되고, 새 표의 수가 바뀌지 않는다 (명령 결과 + DB 조회)
- AC-6: 두 책이 하나로 합쳐지는 다시 가져오기 뒤에, 버려진 번호의 요약·표지·꼬리표·프로필이 남아 있지 않고 남은 번호의 설명은 그대로다 (시험 DB에서 가져오기 + 조회)
- AC-7: AI 검색 첫 글 시간이 옮기기 전보다 늘지 않는다 (dev `6-aisearch.md`의 시간 기록과 비교) [안: 비교 방법은 design-delta에서]
- AC-8: `foryou`·`aisearch`·`picks` 코드가 옛 표나 `foryou.BookBlurbs`·`BookCovers`, 요약 파일을 더 읽지 않는다 (Spring Modulith 모듈 검사 통과)
- AC-9: 추천목록 줄 표지가 ADR-0164 차례대로 나온다 — 줄이 연결한 판에 표지가 있는 책, 그 판엔 없고 다른 판에 있는 책, 우리 책 목록에 없는 책 각 1권 (화면)
- AC-10: 책 상세·추천목록·책첵 추천·AI 검색의 표지가 CloudFront 주소에서 CSP 차단 없이 보인다 (브라우저 개발 도구에 CSP 오류 없음)
- AC-11: S3에 올린 그림 수(`covers/` 객체 수)가 `book_cover`의 서로 다른 그림 이름 수 이상이다 (S3 목록 + DB 조회)
- AC-12: 사본 표를 없앤 뒤 같은 질문 묶음의 AI 검색 후보가 옮기기 전과 같다(제목 기준 차이는 dev 24가 표로 보고) (dev 시험)
