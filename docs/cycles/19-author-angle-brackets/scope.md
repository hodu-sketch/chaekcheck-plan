# 사이클 19: 꺾쇠 저자 표기 정리

- 시작: 2026-10-14. 사이클 17 첫 배포 전에 끝내는 작은 사이클 [확정] (사용자 승인, 2026-10-14, [결정 페이지 #1](../15-usage-log/easy/2026-10-14-retro-followup-decisions.html))
- 사용자: "사이클 17 배포 전에 고치자" (2026-10-14, 캔버스)
- 출발점 (내용은 옮기지 않고 링크): dev `docs/plan-feedback.md` `# 사이클 12` 3355~3360행(R5, 꺾쇠 표기 2,944권)·3458행(AC-3 미통과), plan [`docs/cycles/12-grouping-rules/retro.md`](../12-grouping-rules/retro.md) 82·94·113행, `docs/backlog.md` 274행
- 폴더 이름 `19-author-angle-brackets` [안]

## 목표 (한 문장) [안]

저자를 「<김정은>,<김지혜> 저」, 「<모리세 시게토모> 저/<이민연> 역」처럼 꺾쇠로 쓴 줄도 첫 저자가 「김정은」, 「모리세 시게토모」로 읽히게 저자 정리를 고쳐, 같은 책이 한 줄로 모이고 저자 이름 검색에서도 보통 표기와 똑같이 찾히게 한다.

## 포함

1. 저자 정리 규칙(`catalog.normalize`의 `Contributors`, 검색어 정리에도 쓰임)에서 이름을 감싼 꺾쇠를 다룸 [확정] (사용자 승인, 2026-10-14, 결정 페이지 #1). 다른 괄호(`〈 〉`, `《 》`)도 저자 칸에 실제로 쓰였으면 같이 뗌(먼저 수집 데이터에서 셈) [확정] (사용자 승인, 2026-10-14, [범위 결정](easy/2026-10-14-scope-decisions.html) #3)
2. 고친 규칙으로 내 PC에서 책 목록을 다시 가져옴 [확정] (사용자 승인, 2026-10-14, 결정 페이지 #1; ADR-0069 "정리 규칙을 바꿀 때 다시 가져옴")
3. 운영 역할 DB에 반영 — 사이클 11 방식(내 PC 내보내기 → 운영 `apply`, ADR-0078) [확정] (사용자 승인, 2026-10-14, 결정 페이지 #1)
4. 순서: 사이클 19 반영 → 사이클 17 첫 배포 [확정] (사용자 승인, 2026-10-14, 결정 페이지 #1)
5. 바뀐 결과를 사이클 12 기준값과 비교(책 수, 합쳐짐·나뉨, 표본) [안]
6. 꺾쇠가 아닌 원인 셋도 이번에 함께 고침: 저자 칸에 다른 이름이 적힌 줄(「김근아 저자」), 제목 앞 괄호로 본제목이 달라지는 줄(「(부를 끌어 당기는) 백만장자 마인드」), 역할 낱말 뒤 띄어쓰기가 빠진 표기(「루이스 캐럴 저이소연 역」) [확정] (사용자: "같이 고치자", 2026-10-14, [범위 결정](easy/2026-10-14-scope-decisions.html) #2 미승인). 고치는 방법 ([research.md](research.md)):
   - 다른 이름 저자 줄: 먼저 dev DB·도서관 사이트로 그 줄이 무엇인지 확인하고, 공급사 상품 코드가 여러 도서관에서 같은 책을 가리키면 "코드가 같으면 저자를 보지 않고 모음", 아니면 "같은 날·같은 제목·같은 출판사면 모음" [확정] (사용자 승인, 2026-10-14, [세 원인](easy/2026-10-14-extra-causes-decisions.html) #1)
   - 제목 앞 괄호: 책 묶기 비교 제목에서만 앞 괄호를 떼고, 책 종류 괄호((만화)·(큰글자책)·(영문판)·(오디오북) 등)는 떼지 않음. 화면 제목·검색은 그대로 [확정] (사용자 승인, 2026-10-14, [세 원인](easy/2026-10-14-extra-causes-decisions.html) #2)
   - 역할 낱말 띄어쓰기: 좁은 규칙(저·지음·글 + 한글 2~4자 + 역·옮김·그림) [안] — 사용자: "이거 한번 너가 실험해봐" ((2026-10-14, [세 원인](easy/2026-10-14-extra-causes-decisions.html) #3)) → 수집 데이터로 실험 중
8. 저자·출판사가 뒤바뀐 줄(「백만장자 마인드」 저자 「율리시즈」, 출판사 「모리세 시게토모」)도 이번에 함께 고침 [확정] (사용자: "같이하자 어짜피 cycle19가 내용이 그렇게 안 많아", 2026-10-14, [세 원인](easy/2026-10-14-extra-causes-decisions.html) #4 미승인). 찾는 방법·고치는 방법은 [확인 필요: 실험 뒤 사용자에게 질문]
7. 사이클 18의 다시 가져오기와 묶지 않고 19를 먼저 따로 반영. 반영 뒤 ADR-0069대로 서비스를 새 코드로 다시 켬 [확정] (사용자 승인, 2026-10-14, [범위 결정](easy/2026-10-14-scope-decisions.html) #5)

## 먼저 조사할 것 [확인 필요]

지금 코드 (dev, 읽기만, 2026-10-14 확인):

- 저자 나누기 `backend/src/main/java/com/chaekcheck/catalog/normalize/Contributors.java` `parse` 112~159행, 이름 다듬기 `name` 161~176행: `/`로 나누고 한글이 있으면 `,`로 나눔. 끝의 역할 낱말(`TRAILING_ROLE` 66~67행, `ROLE_WORDS` 39~56행)은 공백 뒤 또는 괄호 안이면 뗌 — 「저」, 「저자」, 「지은이」 모두 `AUTHOR`(긴 낱말부터 맞춤이라 「김근아 저자」 → 이름 「김근아」). 괄호 `( )`만 별명으로 뗌(`ALIAS` 69행). **`<`, `>`는 아무 데서도 다루지 않음** → 「<김정은>,<김지혜> 저」의 첫 사람 이름은 「<김정은>」
- 비교용 이름 `CatalogText.java` `nameExact` 118~120행 = `norm`(44~49행: NFKC, 영문 소문자, 공백 제거) + `.` 제거. 꺾쇠는 남음 → `name_exact` 「<김정은>」 ≠ 「김정은」
- 앞의 「지은이:」 떼기(`LEADING_ROLE_LABEL` 80행)는 사서추천 맞추기용 `firstNameExact`(97~110행)에만 있고 `parse`에는 없음
- 첫 저자 고르기: `collection/internal/importer/SameTextKey.java` `firstAuthor` 338~345행(④ 키, `of` 142~143행), `BookGrouper.java` `firstAuthor` 113~120행(③ 키, `BookGrouping.java` 385행은 가장 많은 표기를 대표로 씀, `CompactGrouping.java` 619행, `SqlGrouping.java` 256행, `NationalBibliography.java` 189행)
- 검색: `catalog/internal/search/PgBigmBookSearch.java` 196~209행 — 단어 검색은 `c.name_norm`, 정확히 일치는 `c.name_exact = CatalogText.nameExact(검색어)`. 사서추천 맞추기 `JdbcBookLookup.java` 70·84행도 `name_exact`
- 제목 쪽 `CatalogText.java` 20행 `LEADING_SERIES`는 제목 앞 `<…>`를 시리즈로 뗌 — 저자와 따로이며 이 사이클에서 건드리지 않음 [안]

## 영향 받을 모듈 [안]

- `catalog`: `normalize`(named interface)의 `Contributors`(꺾쇠 다루기), 필요하면 `CatalogText.nameExact`. 검색(`PgBigmBookSearch`)·사서추천 맞추기(`JdbcBookLookup`)는 같은 정리를 부르므로 코드 변경 없이 따라 바뀜
- `collection`: 가져오기(`importer`)는 코드 변경 없이 새 규칙으로 다시 돌림. 묶기 시험(`SameTextKeyTests` 등)에 꺾쇠 예를 더함
- 표·API·화면: 바뀌지 않음 (저자 칸 표시 방식은 명세에서 정함)
