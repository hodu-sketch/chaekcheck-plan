사이클 19 회고에서 정할 것 4개 (2026-10-18)

사이클 19(저자 꺾쇠 등 같은 책을 갈라 놓던 표기 정리)는 운영 역할 DB까지 반영됐고(2026-10-16, 기록 12번), 수용 기준 19개 중 17개를 통과했습니다. 책 수는 1,568,453 → 1,331,194(−15.1%). 회고(retro.md)를 쓰고 docs/current와 같은 책 규칙 문서를 실제 코드에 맞췄습니다. 아래 4개만 정하면 닫습니다.

1공급사 코드로 잇는 조건을 ADR-0114에 맞추기

무엇인가. dev에서 정하신 대로 공급사 상품 코드로 같은 책을 이을 때 제목·출판사도 같아야 잇게 바뀌었는데, ADR-0114 본문은 옛 내용("제목 조건은 두지 않음")입니다. dev가 함께 넣은 것: 출판사가 "기타·미상·unknown" 같은 자리 채움이거나 공급사가 「기타」·「기타 전자책」이면 코드로 잇지 않음(이 부분은 말씀하신 기록이 없음).

[안] ADR-0114에 "결정 고침 (2026-10-16)" 절을 덧붙여 실제 조건을 적고 Accepted 그대로 둡니다. 「기타」·자리 채움 출판사 빼기도 같은 절에 승인으로 적습니다.

다른 선택: 새 ADR로 0114를 대체.

2같은 회사로 묶은 공급사 목록 승인

무엇인가. 공급사 이름이 도서관마다 다르게 적혀 있어(예: 같은 회사의 다른 표기) dev가 supplier_families.tsv에 46줄을 16묶음으로 묶었습니다. 같은 회사인지 확실하지 않아 넣지 않은 것: 웅진·웅진북센, 한국학술정보·(주)학술정보, 북큐브D, 누리미디어 이러닝, 오디오락 등.

[안] 지금 목록 그대로 승인하고, 넣지 않은 것은 따로 둡니다(확인되면 다음에 더함).

다른 선택: 넣지 않은 것 중 묶을 것을 기타로.

3국가서지 원본 파일(TTL)을 다시 받을지

무엇인가. 국립중앙도서관 국가서지 전체 파일(TTL)이 내 PC에서 지워져 있어, dev에서 "저장된 표로 읽기"를 고르셨습니다(결과는 TTL로 읽을 때와 같음).

[안] 지금은 받지 않고 저장된 표로 계속 씁니다. 국립중앙도서관이 새 전체 파일을 내면 그때 받습니다.

다른 선택: 지금 다시 받아 둠.

4남은 잘못 합침 약 0.2%를 언제 고칠지

무엇인가. 교보 화면 도서관의 공급사 「북큐브」 줄은 상품 번호와 책 정보가 어긋나 있어 약 0.2%가 잘못 합쳐진 채 남았습니다. 저자 칸의 [ ] 기호(예: 「KBS [슈퍼차이나] 제작팀 저」)도 범위 밖으로 둬서 따로 남습니다.

[안] 공개 배포는 그대로 하고 둘 다 백로그에 둡니다(이미 적음). 다음에 묶기 규칙을 고치는 사이클에서 다룹니다.

다른 선택: 공개 전에 고치는 작은 일로.

물으신 것 (#4): 이미 개발된 것 아닌가 — 확인 결과

아직 고쳐지지 않았습니다. dev 기록과 코드를 다시 봤습니다(2026-10-18).

  • 잘못 합침 약 0.2%: dev 기록 plan-feedback.md "# 사이클 19" 4515행에 "남은 알려진 문제 … plan backlog 후보"로만 적혀 있고, 그 뒤(사이클 20·21 기록 포함)에 고친 기록이 없습니다. 묶기 코드(BookGrouping.java, CollectedCatalog.java)에도 교보 화면의 「북큐브」 줄을 따로 빼는 규칙이 없습니다. dev가 적어 둔 고칠 방법은 두 가지인데 둘 다 정해지지 않았습니다: ① 교보·YES24 화면에서 공급사가 그 회사가 아닌 줄의 번호는 코드로 잇지 않기(단, 수용 기준 AC-2의 와이투북스 줄도 같이 빠져 다른 방법 필요) ② 번호와 정보가 어긋난 도서관(921·890·740·818 등)을 찾아 규칙 파일로 빼기.
  • 저자 칸 [ ]: 4527행에 AC-5 "부분 통과, [ ] 처리는 plan 판단(backlog 후보)"으로 남아 있습니다. 사이클 21에서 대괄호를 더 읽게 한 것(4924행)은 추천도서 책 제목의 권 표기를 읽는 것이라 저자 칸 묶기와는 다릅니다.

그래서 제안은 그대로입니다: 공개 배포는 그대로 하고 둘 다 백로그(이미 적음)에서 다음 묶기 규칙 사이클 때 다룸. 이대로면 #4를 승인해 주세요.

#3 "지금 다시 받아 둠" 진행 방법

국가서지 일반도서 전체 파일은 국립중앙도서관에서 이용 설문을 제출해야 받을 수 있는 약 1.1GB 압축 파일입니다(지난번 2026-09-30: book_ttl_20260807.zip, 설문 기관명 "개인 개발자 (비영리 도서 검색 웹 서비스 개발)", 목적 "웹 개발"). 설문 제출과 내려받기는 매번 허락이 필요해 제가 바로 하지 않았습니다. 대화에서 "받아"라고 해 주시면 같은 설문 내용으로 받아 dev data/nlk/ttl에 둘 수 있게 dev 세션에 넘기거나, 직접 받으시면 위치만 알려 주세요. 다음 가져오기부터 ttl-path로 읽고, 받은 날짜·파일 이름을 회고에 적습니다.

5저자 칸 [ ]를 지금 고칠 수 있나

무엇인가. 사이클 19에서 [ ]를 그대로 둔 것은 직접 고르신 범위였습니다(명세 R1-2, "확인 결과 결정 #2", 2026-10-15). 저자 칸의 [ ] 안에는 사람 이름이 아니라 역할 낱말이 든 경우가 있기 때문입니다: 예 「존 버거 [지음]」. 괄호 표시만 떼면 「존 버거 지음」이 되어 다른 판의 「존 버거」와 여전히 다르게 보일 수 있습니다.

  • 고치는 것 자체는 작습니다: 저자 글 정리 규칙(dev Contributors.stripMarks)에 [ ]를 더하고, 안이 역할 낱말(지음·저·글·역·옮김·엮음·편 등)이면 그 낱말을 역할로 떼고, 이름이면 괄호만 뗍니다(「KBS [슈퍼차이나] 제작팀」 → 「KBS 슈퍼차이나 제작팀」).
  • 시간이 드는 부분: 책 묶음이 바뀌므로 시험 가져오기(dry run) → 표본 확인 → 반영이 필요합니다. 사이클 19 반영은 4분 40초였습니다.

[안] 사이클 20 dev 세션에 작은 일로 넘깁니다: ① 저자 칸 [ ] 꼴을 세어 역할 낱말/이름으로 나눔 ② 규칙 더함 + 시험 ③ 시험 가져오기 표본 확인. 운영 반영은 따로 하지 않고 사이클 17 배포 때 하는 가져오기에 함께 들어갑니다. 「북큐브」 줄 0.2%는 원인이 달라(상품 번호와 책 정보가 어긋난 도서관) 백로그에 그대로 둡니다.

다른 선택: 지금 바로 따로 반영 / 백로그에 둠.
