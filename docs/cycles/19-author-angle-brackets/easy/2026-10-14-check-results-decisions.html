4「김근아 저자」 줄은
공급사 상품 코드로 모을지

목원대 북큐브 줄(저자 「김근아 저자」)의 공급사 상품 코드 1210492004114가, 명지대·부천 교보 줄(저자 「모리세 시게토모」)의 상품 번호와 같습니다. 같은 책이고, 김근아는 다른 책(「숏폼 영상 편집 3일 만에 마스터하기」)의 실제 저자 이름이 잘못 들어간 것입니다.

북큐브 화면의 공급사 코드가 교보 화면의 상품 번호와 같은 값입니다. YES24 상품 번호 108608605도 북큐브 공급사 코드로 똑같이 나옵니다.

이미 정한 두 방법 중 "공급사 상품 코드가 같으면 저자를 보지 않고 모음"으로 갑니다. 같은 날·제목·출판사로 모으는 방법은 쓰지 않습니다. [안]

다른 선택: 같은 날·같은 제목·같은 출판사면 모음 → 코드가 없는 줄도 모이지만, 같은 날 같은 제목을 낸 다른 저자의 책이 잘못 합쳐질 수 있음. 코드가 다른 책을 가리키는 경우가 없는지는 dev가 해 볼 때 셉니다(research.md SQL 2).

5역할 낱말이 셋째 사람까지 붙은 저자 칸도
이번에 고칠지

「마키타 겐지 저전선영 역강재헌 감수」 모양은 실제로 40줄, 32가지뿐입니다(처음 넓게 센 12,370줄보다 훨씬 적음). 지금 정한 좁은 규칙을 셋째 사람까지 늘리면 함께 고쳐집니다.

지금 읽히는 것고친 뒤
지은이 「마키타 겐지」, 옮긴이 「전선영 역강재헌」(감수 낱말만 뗌)지은이 마키타 겐지 · 옮긴이 전선영 · 감수 강재헌

다른 예: 「카를로 로벨리 저김현주 역이중원 감수」, 「안네마리 노르덴 저원유미 그림배정희 역」.

좁은 규칙(저·지음·글 + 한글 2~4자 + 역·옮김·그림)을 한 번 더 이어 셋째 역할(감수·편집·엮음·그림·역 등)까지 자릅니다. 백로그 줄은 "→ 사이클 19"로 옮깁니다. [안]

다른 선택: 이번엔 안 함 → 40줄은 옮긴이 이름이 틀린 채 남음. 첫 저자는 맞게 읽혀 같은 책 묶기에는 영향 없음.

6사이트 직접 찾기의 「김달 저」 문제는
19에 넣지 않을지

부산 같은 통합 포털에서 저자 "김달"로 찾으면 「김달 저」로 적힌 줄이 빠지는 문제는 지금도 남아 있습니다. 하지만 우리 책 목록이 아니라 도서관 사이트의 "정확히 일치" 거르기를 그대로 쓰는 부분이라 저자 정리와 관계없습니다.

이 거르기를 쓰기로 한 것은 사용자 결정입니다(ADR-0026, 사이클 03). 코드는 dev ElibPortalV1Adapter 39~41행.

19에 넣지 않고 백로그에 그대로 둡니다. [안]

다른 선택: 19에 넣음 → 도서관 사이트 실시간 조회 쪽 코드를 고쳐야 해서 19 범위가 다른 모듈로 넓어짐.

7세 도서관 수집기는
"출판사가 먼저인 포털" 목록으로 고칠지

원인을 확인했습니다. 같은 통합 포털 화면인데 사이트마다 목록의 칸 순서가 다르고, 이름표가 없습니다. 수집기는 첫 칸을 언제나 저자로 읽습니다.

사이트목록에 보이는 순서 (2026-10-14 확인)지금 결과
부산·강원·인천·경북저자 │ 출판사 │ 날짜 (예: 「이중석 │ 다반 │ 2026-06-20」)바름
경기도교육청·대구·전북교육청출판사 │ 저자 │ 날짜 (예: 「미래의창 │ 이준용 │ 2026-08-03」)뒤바뀜

확인한 곳: lib.goe.go.kr/elib, library.daegu.go.kr/elib, lib.jbe.go.kr/elib, library.busan.go.kr/elib의 새 책 목록. 서비스의 실시간 조회는 상세 화면의 "저자 :"·"출판사 :" 이름표를 읽어 영향이 없습니다.

수집기에 "출판사가 먼저 나오는 포털" 세 곳을 적은 목록을 두고, 그 사이트만 두 칸을 바꿔 읽습니다. 가져오기 규칙 파일로 지금 사본을 바로잡는 것은 앞서 정한 대로 합니다. [안]

다른 선택: 수집기가 사이트마다 상세 화면 하나를 열어 이름표로 순서를 알아냄 → 새 포털이 생겨도 저절로 맞지만, 수집할 때 요청이 늘고 코드가 커짐.

819를 반영한 뒤 숫자를
무엇과 견줄지

순서가 바뀌었습니다. 사용자 결정(2026-10-14, dev 18 세션)으로 사이클 18 B가 19보다 먼저 들어가고, 18 B 끝에 내 PC 가져오기를 한 번 합니다(2026-10-12 사본). 18은 도서관 22곳도 껐습니다.

19의 결과(책 수, 합쳐짐·나뉨, 「백만장자 마인드」 줄 수)는 사이클 12 숫자가 아니라 18 B 가져오기 결과와 견줍니다. 같은 사본·같은 도서관 목록이라 19 규칙 때문에 바뀐 것만 보입니다. [안]

다른 선택: 사이클 12 숫자와 견줌 → 22곳을 끈 영향과 18 B의 밑줄 주소 도서관 영향이 섞여, 19 때문에 바뀐 수를 따로 볼 수 없음.

덧붙임(2026-10-14, dev 18 알림): 18 B는 dev main에 들어갔고(dev 커밋 a0e438a), 18 가져오기는 복사본 DB에서만 했습니다. 원래 DB에는 아직 안 들어가서, 19가 원래 DB에 다시 가져오면 밑줄 주소 도서관(2624)의 241권도 함께 들어옵니다. 그래서 기준은 "18 B 복사본 DB의 결과"입니다.
