# 사이클 02: 도서관 확장 (교보·YES24 전국 + 많은 도서관을 위한 검색 구조)

## 목표 (한 문장)

교보·YES24 플랫폼을 쓰는 전국 전자도서관을 검색 대상에 넣고, 도서관이 수백 곳이어도 검색이 느려지거나 결과가 넘치지 않도록 도서관을 우선순위대로 나눠 찾아 약 20권씩 이어 보여 준다. [확정] (사용자, 2026-09-27)

## 포함

세부 규칙은 `spec.md`에서 정합니다. 여기서는 범위만 적습니다.

- 교보·YES24 플랫폼을 쓰는 전국 전자도서관 추가. 기존 adapter 2개를 그대로 씀 [확정]
- 교보 구독형 도서관(`*.dkyobobook.co.kr`, 교보 공공도서관 목록 기준 19곳)을 포함하고 새 adapter를 만듦 [확정] (사용자, 2026-09-28). 구독형은 "책 1권당 동시 대출 제한이 없어 예약 없이 바로 대출 가능" [확정] (영등포구립도서관 안내 https://www.ydplib.or.kr/intro/40010/contents.do, 확인 2026-09-28). 보유·대출·예약 수량 대신 "구독형 · 바로 대출"로 표시하는 방향 [안]. 다만 "월별 배정된 예산 소진 시 해당월 이용불가"라서 도서관별 그달 이용 가능 여부가 변수임. 사이트에서 이를 알 수 있는지 [확인 필요]. 1인 월 대출 권수는 도서관마다 다름 (영등포 월 10권, 순천 월 20종) [확정]
- 도서관 목록 만들기: 공공도서관 홈페이지(공공데이터 전국도서관표준데이터의 홈페이지주소)에서 출발해 전자도서관 링크를 따라가고, 주소 모양으로 플랫폼을 분류 [확정] (사용자, 2026-09-28). 도서관 정보나루에는 전자도서관 목록이 없음 (https://www.data4library.kr/libDataL 참여 도서관 1,616곳은 실물 공공·작은도서관, 이름·주소만. 2026-09-28 확인)
- YES24 옛 방식 화면(`…/YES24` 경로 등, 조사 때 결과를 못 읽은 28곳)과 주소가 바뀌었거나 없어진 곳(`/B2B_…` 404 등 34곳)도 이번 사이클에 넣음 [확정] (사용자, 2026-09-28). 옛 방식 화면 구조와 새 주소는 조사 필요 (research.md 10절)
- 지역·교육청 통합 전자도서관 포털(부산·대구·인천교육청·경북교육청·전북교육청·경기교육청 등, `/module/elib/search/index.do`)을 이번 사이클에 넣고 세 번째 adapter를 만듦 [확정] (사용자, 2026-09-28). 보유 수 없이 대출·예약 수와 대출 가능 여부만 나옴 (research.md 12절). 포털 결과는 사이트 판정("대출 가능"/"예약 가능")으로 나눔. 경북·전북처럼 검색 목록에 판정이 없으면 대출 0은 대출 가능, 대출 1 이상만 상세 페이지를 열어 판정을 읽고, 이런 포털은 검색에서 후순위 [확정] (사용자, 2026-09-28. research.md 12절)
- YES24 한 세대 전 화면(EUC-KR)은 YES24 adapter 변형으로 읽음 [안]
- 강남구 자체 전자도서관 시스템(`ebook.gangnam.go.kr`, EUC-KR, 보유·대출·예약·공급 업체 표시)을 이번 사이클에 넣고 전용 adapter를 만듦 [확정] (사용자, 2026-09-28)
- 새 주소를 찾지 못한 약 20곳(research.md 12절 목록)은 이번 사이클에서 빼고, backlog의 "도서관 정보 주기적 재조사"에서 다시 찾음 [확정] (사용자, 2026-09-28)
- 교보·YES24 외 플랫폼(북큐브 `…/FxLibrary`·`*.bookcube.biz`, 알라딘 `*.aladinebook.co.kr`, 다산 `*.dasangng.co.kr`, 자체 시스템)은 목록 분류까지만 하고 adapter는 만들지 않음 [안]
- 조회 전용 서비스를 분리해 여러 대로 운영하고, 조회 서버 자체가 죽었을 때만 다른 조회 서버로 넘김. 캐시와 호출 간격 제어는 본 서비스 한곳에서 함 [확정] (ADR-0011)
- 호출 간격 제어 단위를 호스트 이름으로 바꿈 [확정] (ADR-0010, ADR-0007 대체)
- robots.txt가 막은 도서관도 조회 대상에 넣음. 차단되면 그때 다른 방법을 찾음 [확정] (사용자, 2026-09-28. 조건과 제외한 방법은 `research.md` 9절)
- 가입 자격을 확인하지 못한 도서관도 넣고 "가입 자격 확인 필요"로 표시 [확정]. 지금 모델은 "규칙 없음 = 누구나 가입"이라서 '자격 미확인'을 따로 나타낼 방법이 필요함 (design-delta에서 정함) [안]
- 도서관이 많을 때의 검색 구조 (사이클 01 retro "다음 사이클 후보", dev feedback U-11). 사용자가 정한 방향 [확정]:
  1. 지역 입력은 강제하지 않음
  2. 도서관을 우선순위 그룹으로 나눠 찾음. 지역이 없으면 누구나 가입 → 자격 필요(전국 지역별)
  3. 같은 그룹 안에서는 보유 전자책이 많은 도서관부터
  4. 한 번에 약 20권, 목록 맨 아래 "더 보기"
  5. 아래 "더 보기"는 다음 순위 도서관으로 넓히고, 한 바퀴 돌면 첫 도서관의 다음 페이지부터(라운드 로빈)
  6. 도서관별 "더 보기"도 유지
  7. 새 결과는 기존 목록 아래에 붙이고 이미 본 결과의 위치는 바꾸지 않음
- 지역을 고른 경우의 그룹 순서: 내 시군구에서 가입 가능 → 내 시도에서 가입 가능 → 누구나 가입 → 자격 미확인 [확정] (사용자, 2026-09-28). 묶음 안에서만 spec 01 5.4 순서로 정렬 [확정] (사용자, 2026-09-28). 세부는 `spec.md`
- 도서관이 수백 곳일 때의 도서관 요약 줄 (사이클 01 U-8 "… 외 N곳"을 넓힘)
- dev 인계: Spring Modulith `Documenter`로 모듈 구성도(PlantUML)와 모듈 캔버스를 만드는 테스트 추가. 다음 `/cycle-start`에서 plan의 설계 그림과 비교하기 위함 [확정] (사용자: "이렇게 해줘", 2026-09-28). 출처: https://docs.spring.io/spring-modulith/reference/documentation.html (확인 2026-09-28, 기본 출력 위치는 빌드 폴더의 `spring-modulith-docs`)

## 제외 (backlog.md로 보낸 항목)

- 새 플랫폼 adapter(북큐브, 알라딘, 다산, 서울도서관·충남도서관 같은 자체 화면 등). 교보 구독형 adapter는 포함
- 저자·출판사 검색 API 열기 (ADR-0009의 `field` 파라미터)
- 같은 책 묶기, 인기 도서 사전 수집, 학교·소속 기관 자격, 회원가입
- 도서관 사용 여부·목록을 관리하는 운영자 화면 (지금처럼 SQL과 seed로 관리)
- IP별 rate limit, Redis, 서버 여러 대

## 완료 기준 (사용자가 화면에서 확인할 수 있는 것)

세부 AC는 `spec.md`에서 정합니다. 핵심은 다음과 같습니다.

1. 지역 없이 제목을 검색하면 첫 화면에 약 20권이 나오고, 누구나 가입 도서관 결과가 먼저 나온다.
2. 목록 맨 아래 "더 보기"를 누르면 다음 순위 도서관의 결과가 기존 목록 아래에 붙고, 이미 보던 결과의 위치는 바뀌지 않는다.
3. 거주·직장 지역을 고르면 가입할 수 있는 도서관이 정해진 그룹 순서로 먼저 나온다.
4. 자격을 확인하지 못한 도서관 결과에는 "가입 자격 확인 필요"가 붙는다.
5. 도서관이 수백 곳이어도 검색 한 번에 모든 도서관에 요청하지 않는다 (서버 로그로 확인).
6. 도서관별 "더 보기"로 특정 도서관의 다음 페이지를 받을 수 있다.
7. 사이클 01의 호출 예의(캐시 3분, 같은 호스트 동시 1건·1초 간격, User-Agent)가 그대로 지켜진다.

## 영향 받을 모듈 [안]

- `library`: 전자도서관 사이트 하나 = 도서관 한 줄, 자격도 사이트마다, 종류 칸으로 나중에 실물 도서관 (ADR-0017), 도서관 수백 곳의 seed(또는 적재 방법), '자격 미확인' 표현, 보유 전자책 수 같은 순위 값, 우선순위 그룹을 나누는 공개 API
- `availability`: 묶음 단위 검색(라운드 로빈), 스트림 API 변경(ADR-0005), 병렬 조회 수와 묶음 제한 시간. adapter는 그대로 씀
- `region`: 바뀌지 않을 것으로 봄. 시도 단위 판정에 필요한 공개 API는 이미 있음(`expandForMatching`)
- 웹: 이어 붙이는 결과 목록, 아래 "더 보기", 수백 곳 요약 줄
