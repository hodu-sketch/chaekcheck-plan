### robots.txt가 막은 도서관도 조회함 [확정]

- 사용자: "꼭 지킬 필요는 없다던데 그냥 robots.txt가 막고 있는 도서관을 조회하도록 해줘 나중에 차단되고 말지 뭐", "나중에 차단되면 다른 방법을 찾는다는 거야"
- 함께 지키는 것 [안]: User-Agent로 우리를 밝힘, 호출 간격·캐시 규칙 유지, 사용자가 검색할 때만 조회
- 차단되면: 그 도서관을 끄고 "도서관에서 검색하기" 링크로 대신하거나, 도서관·업체에 허용을 요청 [안]
- 감수하는 점: 차단, 항의, 법적 분쟁 가능성. 법적 위험 정도는 확인하지 않음 [확인 필요]
- 설계에 넣지 않는 것: IP를 바꿔 가며 차단을 피하는 방법, 다른 봇(구글봇 등)으로 위장하는 방법. 사용자가 고려를 요청했으나(2026-09-28), 운영자의 명시적 차단을 속임수로 넘는 일이라 Claude가 설계에서 뺌. 이 결정은 사용자와 다시 논의 필요
- 검색엔진 결과(색인된 페이지)로 대출 정보를 얻는 방법: 강서구는 검색 봇을 허용해 책 상세 페이지가 색인돼 있음. 하지만 수집 시점의 값이라 현재 수량이 아니고, 검색엔진 약관 문제가 있음. 추가 조사는 이 세션에서 권한이 거부되어 멈춤

### 조회 전용 프록시(나가는 서버) [안]

- 사용자 요청: 크롤링용 프록시 서버를 따로 두는 것을 고려 (2026-09-28)
- 제안 형태: 도서관 조회만 하는 서버를 따로 두고 **고정 IP 하나**로 나감. 서비스 서버와 분리돼 조회 쪽이 막혀도 서비스는 동작하고, 도서관이 허용 목록에 넣을 주소가 생기고, 호출 기록을 한곳에서 관리함
- IP를 돌려 쓰는 프록시 풀은 넣지 않음 (위와 같은 이유)
- 결정 (2026-09-28): 별도 서비스로 분리하고 여러 대로 운영 → ADR-0011. 호출 간격 제어 단위는 호스트 이름으로 → ADR-0010
- 교보 구독형 포함, 목록은 공공도서관 홈페이지에서 출발 → scope.md
