# 기능 명세: 도서관 확장 (교보·YES24 전국 + 많은 도서관을 위한 검색 구조)

- 사이클: 02 (`scope.md`)
- 작성일: 2026-09-28. 조사 결과와 출처는 `research.md`, `eligibility.md`, `eligibility-by-library.md`에 있습니다.
- 태그: [확정] 사용자 확인 또는 공식 확인 / [안] 제안, 미확정 / [확인 필요] 미확인 (9장에 확인 방법)
- 이 명세는 사이클 01 명세(`../01-ebook-availability-search/spec.md`)에서 **바뀌거나 늘어나는 것만** 적습니다. 여기 적지 않은 규칙(검색어 2~50자, 지역 브라우저 저장, 캐시 3분, User-Agent, 원문 미저장, 도서관 사용 여부, 행정구역 변경 등)은 사이클 01 그대로입니다.

---

## 1. 사용자 이야기

- 전자책을 빌리고 싶은 사람은 전국 전자도서관 가운데 그 책이 있고 지금 빌릴 수 있는 곳을 알고 싶다. 시범 도서관 두 곳으로는 찾는 책이 없는 경우가 많기 때문이다. [확정] (scope 목표)
- 지역을 고르지 않은 사람도 검색을 바로 할 수 있어야 한다. [확정] (scope: 지역 입력 강제 안 함, 이유 미확인)
- 도서관이 수백 곳이어도 첫 결과가 빨리 나오고, 결과가 한꺼번에 쏟아지지 않아야 한다. [확정] (scope 목표)
- 더 보고 싶을 때 "더 보기"를 누르면 다른 도서관 결과가 이어서 붙고, 이미 보던 결과는 제자리에 있어야 한다. [확정] (scope 포함 7)

## 2. 용어 (사이클 01에서 바뀌거나 늘어난 것)

| 용어 | 뜻 |
|---|---|
| 플랫폼 유형 | 도서관 사이트 화면의 종류. 이번 사이클은 교보 일반, 교보 구독형, YES24 지금 방식(UTF-8), YES24 한 세대 전(EUC-KR), 통합 전자도서관 포털, 강남구 자체 시스템 6가지 [확정] (research.md "플랫폼 유형 정리") |
| 사이트 판정 | 통합 포털이 결과 줄이나 책 상세 페이지에 적어 주는 "대출 가능 여부" 값 ("대출 가능" / "예약 가능") |
| 판정 없는 포털 | 검색 목록의 "대출 가능 여부"가 비어 있어 상세 페이지를 더 열어야 하는 통합 포털. 지금 확인된 곳은 경북교육청, 전북교육청 [확정] (research.md 12절) |
| 자격 미확인 | 가입 자격을 조사했지만 찾지 못한 도서관. 추정값을 붙이지 않음 [확정] (eligibility.md) |
| 판정 불가 자격 | 책이음 회원, 학생, 시각장애인처럼 거주·직장 지역만으로 맞는지 판단할 수 없는 자격 [확정] (eligibility.md 관찰) |
| 도서관 순위 | 검색할 때 도서관을 조회하는 순서 (5.2) |
| 순위 값 | 같은 가입 묶음 안에서 도서관 순서를 정하는 값. 도서관의 보유 전자책 수 [확정] (scope 포함 3) |
| 묶음 | 검색 한 번, 또는 목록 맨 아래 "더 보기" 한 번에 조회하는 도서관들과 그 결과 (5.3) |

## 3. 대상 도서관

- 교보·YES24 플랫폼을 쓰는 전국 공공 전자도서관 + 통합 포털 + 강남구 [확정] (scope 포함)
- 조사로 결과를 읽을 수 있다고 확인한 곳부터 넣습니다. 목록과 주소는 `research.md` 8·10·12절에 있습니다.
- 새 주소를 찾지 못한 약 20곳, 로그인이 필요한 울산 전자도서관, 북큐브·알라딘·다산 사이트는 이번에 조회하지 않습니다. [확정] / 울산은 링크만 [안]
- 한 운영 기관이 전자도서관 사이트를 여러 개 가질 수 있습니다 (예: 세종시립도서관 일반 + 구독형). 사이트 하나를 도서관 하나로 다루고, 가입 자격도 사이트마다 따로 적습니다. 이름으로 구분합니다 (예: "세종시립도서관(구독)"). [확정] (사용자, 2026-09-28. ADR-0017)
- 너무 많아 한 사이클에 다 못 넣으면 검색 구조를 먼저 완성하고 도서관은 확보한 만큼 넣습니다. [확정] (scope)

## 4. 입력과 출력

**입력**: 사이클 01과 같습니다 (검색어, 거주 지역, 직장 지역). 지역은 선택 입력입니다. [확정]

**출력 (결과 한 줄 = 도서관 사이트 하나의 책 하나)**

| 항목 | 규칙 | 상태 태그 |
|---|---|---|
| 제목, 저자, 출판사, 공급 업체 | 사이트가 보여 주는 값. 공급 업체를 보여 주지 않는 사이트는 빈칸 | [확정] |
| 도서관명, 사이트 종류 | 구독형 사이트는 "구독형"을 붙임 | [안] |
| 가입 조건 | 누구나 가입 / 자격 문구 / "가입 자격 확인 필요" (5.5) | [확정] |
| 수량 | 플랫폼 유형별 (5.4) | [확정] |
| 대출 가능 여부 | 5.4 | [확정] |
| 도서관으로 이동, 조회 시각 | 사이클 01과 같음 | [확정] |
| 도서관 요약 줄 | 사이클 01 U-8 그대로 (5곳 + "… 외 N곳" 팝오버), 결과 있는 도서관을 앞에 둠 (`flow.md`) | [확정] (사용자, 2026-09-28) |

## 5. 동작 규칙

### 5.1 조회할 도서관 고르기

- 지역을 고르지 않음: 사용 중인 모든 도서관 사이트가 조회 대상입니다. [확정]
- 지역을 고름: 누구나 가입 + 자격이 내 지역과 맞는 도서관 + 자격 미확인 + 판정 불가 자격 도서관. 자격이 확인됐는데 내 지역과 맞지 않는 도서관은 숨깁니다. [확정] (사용자, 2026-09-28)
- 인접 지역을 받는 도서관(천안: 세종·아산·공주·평택·안성·청주·진천 등)은 지역 규칙 여러 개로 판정합니다. [확정] (eligibility.md 원문 확인)
- 판정 불가 자격만 있는 도서관은 자격 미확인과 같은 자리에 두고, 자격 문구를 그대로 보여 줍니다 (예: "책이음 회원 가입 가능"). [확정] (사용자, 2026-09-28)
- 지역 규칙과 판정 불가 문구가 함께 있는 도서관(예: 금정)은 내 지역이 규칙과 맞으면 가입 가능으로, 안 맞으면 "가입 자격 확인 필요" + 문구로 둡니다. [확정] (사용자, 2026-09-28. ADR-0013)

### 5.2 도서관 순위 (조회 순서)

**지역을 고르지 않았을 때**
1. 누구나 가입
2. 자격 필요
3. 자격 미확인·판정 불가 자격 [확정] (자격 필요 다음에 따로. 사용자, 2026-09-28)

**지역을 골랐을 때** [확정] (사용자, 2026-09-28)
1. 내 시군구에서 가입 가능 (자격 범위가 내 시군구인 규칙이 맞음)
2. 내 시도에서 가입 가능 (자격 범위가 내 시도인 규칙이 맞음)
3. 누구나 가입
4. 자격 미확인·판정 불가 자격 ("가입 자격 확인 필요")

**같은 묶음 안의 순서**
- 순위 값(보유 전자책 수)이 큰 도서관부터 [확정] (scope 포함 3)
- 판정 없는 포털(경북·전북)은 같은 가입 묶음 안에서 **다른 도서관을 모두 조회한 다음에** 조회합니다. [확정] (사용자: "전북 포털 같은 것들을 검색에서 좀 후순위로 나오도록해줘 너 안대로 하고", 2026-09-28. 조회 순서를 뒤로 미루는 방식: 사용자 선택, 2026-09-28)

### 5.3 묶음 단위 검색과 "더 보기"

**한 묶음** [확정] (사용자, 2026-09-28)
- 도서관 사이트마다 첫 요청은 **결과 10줄**을 가져옵니다 (교보 `recordCount=10`, YES24는 원래 10줄 고정).
- 도서관 순위대로 몇 곳씩 병렬로 조회하고, 모인 결과 줄이 **20개를 넘으면** 새 도서관 조회를 멈춥니다. 이미 요청한 도서관의 결과는 받아서 보여 줍니다.
- "지금 빌릴 수 있는 책만" 필터(사이클 01 U-3)를 켜면 **대출 가능한 줄**이 20개를 넘을 때까지 조회합니다. 필터를 바꾸면 이미 붙인 묶음을 지우고 첫 묶음부터 다시 검색합니다. [확정] (사용자, 2026-09-28)
- 한 번에 병렬로 조회할 도서관 수는 설계에서 정합니다. [안]
- 한 묶음의 제한 시간은 **8초**입니다. 8초 안에 응답하지 않은 도서관은 "조회 실패"로 표시합니다 (사이클 01과 같은 값). [확정] (사용자, 2026-09-28)
- 결과가 없는 도서관은 줄을 만들지 않고, 요약 줄의 "결과 없음"에만 셉니다. [안]
- 한 번 조회에 실패한 도서관은 같은 검색의 이후 "더 보기"에서 다시 조회하지 않습니다. 새로 검색하면 다시 시도합니다. [확정] (사용자, 2026-09-28. ADR-0014)

**목록 맨 아래 "더 보기"** [확정] (scope 포함 4·5·7)
- 누르면 다음 순위 도서관부터 같은 방식으로 한 묶음을 더 조회합니다.
- 모든 대상 도서관을 한 번씩 조회했으면, 첫 순위 도서관부터 다음 페이지를 조회합니다 (라운드 로빈). 다음 페이지가 없는 도서관은 건너뜁니다.
- 새 묶음의 결과는 기존 목록 **아래에** 붙입니다. 이미 보이는 줄의 위치는 바뀌지 않습니다. 예외: 경북·전북의 "대출 정보 조회 중" 줄은 판정이 오면 같은 묶음 안에서 알맞은 칸으로 옮깁니다 (5.4).
- 더 조회할 도서관과 페이지가 없으면 "더 보기"를 없앱니다.

**도서관별 "더 보기"**: 사이클 01처럼 유지합니다. 받은 줄은 그 도서관의 기존 줄이 있는 묶음 아래가 아니라, **목록 맨 아래 새 묶음**으로 붙입니다. [안] (이미 본 줄 위치 유지 규칙을 지키기 위함)

**결과 순서** [확정] (사용자, 2026-09-28)
- 첫 묶음: 결과가 도착할 때마다 5.6 순서로 다시 정렬합니다 (사이클 01처럼).
- "더 보기"로 붙는 묶음: **그 묶음 안에서만** 5.6 순서로 정렬해 아래에 붙입니다. 그래서 "지금 빌릴 수 있어요", "예약하고 기다려요" 제목이 묶음마다 다시 나옵니다.

### 5.4 수량과 대출 가능 여부

| 플랫폼 유형 | 보여 주는 수량 | 대출 가능 여부 | 상태 태그 |
|---|---|---|---|
| 교보 일반, YES24 두 방식, 강남구 | 보유·대출 중·예약 | 보유 − 대출 중 ≥ 1이면 대출 가능 | [확정] |
| 통합 포털 (부산·대구·경기교육청·인천교육청) | 대출 중·예약 (보유 없음) | 사이트 판정: "대출 가능" → 대출 가능, "예약 가능" → 예약 | [확정] |
| 판정 없는 포털 (경북·전북) | 대출 중·예약 | 대출 중 0 → 대출 가능. 대출 중 1 이상 → 상세 페이지를 열어 사이트 판정을 읽음. 그동안 그 줄은 묶음 아래쪽 "대출 정보 조회 중" 자리에 먼저 보이고, 판정이 오면 **그 묶음 안에서** 알맞은 칸으로 옮김. 최대 30초 기다림 | [확정] (사용자, 2026-09-28. ADR-0014) |
| 교보 구독형 | 없음. "구독형 · 바로 대출"로 표시 | 대출 가능 | [확정] 위치 (사용자, 2026-09-28) / 표시 문구 [안] |

- 결과 줄의 판정이 비어 있는 줄은 포털이 어디든 판정 없는 포털과 같은 방법으로 처리합니다 (인천교육청은 빈 줄이 섞여 있음). [안]
- 상세 페이지를 30초 안에 못 읽었거나, 판정이 "대출 가능"·"예약 가능"이 아닌 값이면 "대출 가능 여부 확인 필요"로 표시하고 "예약하고 기다려요" 칸의 맨 아래에 둡니다. [안]
- 구독형은 도서관의 그달 예산이 떨어지면 빌릴 수 없습니다. 사이트에서 이를 알 수 있으면 반영하고, 알 수 없으면 "월 예산 소진 시 이용 불가" 안내를 붙입니다. [안] (9장 확인 필요)

### 5.5 가입 조건 표시

| 도서관 | 표시 | 상태 태그 |
|---|---|---|
| 누구나 가입 | "누구나 가입" | [확정] |
| 자격 필요 | 자격 문구 (예: "서울 거주·재직·재학") | [확정] |
| 자격 미확인 | "가입 자격 확인 필요" | [확정] |
| 판정 불가 자격 | "가입 자격 확인 필요" + 자격 문구 (예: "책이음 회원 가입 가능") | [확정] (사용자, 2026-09-28) |
| 방문 가입만 가능 | 자격 표시에 "방문 가입"을 붙임 | [확정] (사용자, 2026-09-28) |

### 5.6 결과 순서 (한 묶음 안)

모든 묶음에 각 묶음 안에서 적용합니다. 이미 붙은 묶음은 움직이지 않습니다. [확정] (사용자, 2026-09-28)

**1단계**: "지금 빌릴 수 있어요" → "예약하고 기다려요" [확정]

**2단계: 칸 안에서 같은 제목끼리 모음** [확정] (사용자, 2026-09-28)
- 같은 제목인지는 서버가 준 **제목 비교 키**(`titleKey`, 5.8)가 같은지로 봅니다.
- 제목 묶음의 순서
  - "지금 빌릴 수 있어요": 그 제목의 재고 합계가 많은 순 [확정]. 수량이 없는 줄(포털, 구독형)만 있는 제목은 재고 합계가 있는 제목 다음 [안]
  - "예약하고 기다려요": 그 제목의 예약 인원 합계가 적은 순 [확정]
  - 합계가 같으면 그 묶음에서 먼저 나온 도서관(도서관 순위)의 제목 먼저 [안]
- 사용자: "기존 정렬 순서는 새 정렬 순서의 후순위로 가게 해줘" → 아래 3·4단계는 **같은 제목 묶음 안의 순서**입니다.

**3단계 (같은 제목 안)**: 가입할 수 있는 도서관의 줄 → "가입 자격 확인 필요" 줄 [확정] (사이클 01 규칙, 제목 다음으로 내려감)

**4단계: 같은 제목·같은 가입 구분 안**

| 칸 | 순서 | 상태 태그 |
|---|---|---|
| 지금 빌릴 수 있어요 | ① 재고가 있는 줄: 사이클 01대로 재고 많은 순 → 도서관 대출률 낮은 순 → 원래 순서 ② 그 다음 수량 없는 줄(통합 포털, 구독형): 도서관 순위 순 → 사이트가 보여 준 원래 순서 | [확정] (사용자, 2026-09-28) / ②의 도서관 순위 순 [안] |
| 예약하고 기다려요 | 예약 인원 적은 순 → 보유 많은 순(보유를 모르는 포털 줄은 보유를 아는 줄 뒤) → 원래 순서 | [확정] 예약 순 / 포털 줄 자리 [안] |

- 도서관 대출률은 그 도서관의 첫 요청 결과(이번 사이클부터 10줄)로 계산합니다. 보유를 모르는 포털·구독형에는 계산하지 않습니다. [확정] 10줄 / 나머지 [안]
- "대출 정보 조회 중" 줄과 "대출 가능 여부 확인 필요" 줄은 제목으로 모으지 않고 지금 자리(묶음 아래쪽 / 예약 칸 맨 아래)에 둡니다. 판정이 와서 칸으로 옮길 때 그 칸의 제목 묶음에 들어갑니다 [안].

### 5.7 도서관 호출

- 같은 **호스트 이름**에는 동시 1건, 요청 사이 1초 이상 [확정] (ADR-0010)
- 판정 없는 포털의 상세 페이지 요청도 같은 규칙과 캐시(3분)를 따릅니다. [안]
- robots.txt가 막은 도서관도 조회합니다. 차단되면 그 도서관을 끄고 "도서관에서 검색하기" 링크로 대신합니다. [확정] (research.md 9절)
- 호출은 조회 전용 서비스를 거칩니다. 사용자 화면의 동작은 달라지지 않습니다. [확정] (ADR-0011)
- EUC-KR 사이트(YES24 한 세대 전, 강남구)에는 검색어를 EUC-KR로 바꿔 보냅니다. [확정] (collection-method.md 4-4)

### 5.8 제목 비교 키 [확정] (사용자, 2026-09-28. ADR-0018)

- 서버가 결과 줄마다 **제목 비교 키**를 붙여 보냅니다. 프론트는 키가 같은 줄을 같은 제목으로 보고 모읍니다.
- 이번에는 **제목만** 씁니다. 저자·출판사는 도서관 화면마다 있는지와 표기를 조사한 뒤 키에 더합니다 (9장).
- 정리 규칙 [안]: 유니코드 정규화(NFC), 앞뒤·연속 공백과 띄어쓰기 차이 없앰, 영문 대소문자 통일, 문장부호 제거. 괄호 부제·"큰글자책"·권차를 같게 볼지는 실제 제목 표기를 모아 본 뒤 정합니다 [확인 필요].
- 줄을 합치지 않습니다. 같은 제목의 줄을 **옆에 붙여 정렬**만 합니다 (같은 책 묶기는 backlog 별도 사이클).

## 7. 수용 기준

**도서관 순위와 묶음**
- AC-1: 지역 없이 제목을 검색하면 첫 화면에 결과 줄이 약 20개(20개를 넘긴 시점에 조회 중이던 도서관 결과까지) 나오고, 누구나 가입 도서관 결과가 자격 필요 도서관 결과보다 먼저 조회된다. (화면 + 서버 로그)
- AC-2: 대상 도서관이 수백 곳이어도 첫 검색에서 모든 도서관에 요청하지 않는다. (서버 로그)
- AC-3: 도서관 사이트마다 첫 요청은 10줄이다 (교보 요청에 `recordCount=10`). (서버 로그)
- AC-4: 목록 맨 아래 "더 보기"를 누르면 다음 순위 도서관의 결과가 기존 목록 아래에 붙고, 누르기 전에 보이던 줄의 순서와 내용은 바뀌지 않는다.
- AC-5: 모든 대상 도서관을 한 번씩 조회한 뒤 "더 보기"를 누르면 첫 순위 도서관의 2쪽부터 요청한다. (서버 로그)
- AC-6: 도서관별 "더 보기"로 그 도서관의 다음 페이지를 받을 수 있다.
- AC-7: 한 묶음에서 8초 안에 응답하지 않은 도서관은 "조회 실패"로 보이고, 다른 도서관 결과는 정상으로 보인다.
- AC-8: 경북·전북 포털은 같은 가입 묶음의 다른 도서관이 모두 조회된 뒤에 조회된다. (서버 로그)

**지역**
- AC-9: 거주 지역으로 시군구를 고르면 조회 순서가 내 시군구 가입 가능 → 내 시도 가입 가능 → 누구나 가입 → 자격 확인 필요 순이다. (서버 로그)
- AC-10: 지역을 고르면 자격이 확인됐는데 맞지 않는 도서관에는 요청하지 않는다. 자격 미확인 도서관은 "가입 자격 확인 필요"로 나온다.
- AC-11: 거주 지역으로 세종을 고르면 천안시중앙도서관이 가입 가능한 도서관으로 나온다.
- AC-12: 책이음 회원 문구가 있는 도서관(예: 금정도서관)은 내 지역이 그 도서관의 지역 규칙과 맞으면 가입 가능으로 나오고, 맞지 않거나 지역을 고르지 않았으면 "가입 자격 확인 필요"와 자격 문구가 함께 보인다.

**수량과 대출 가능 여부**
- AC-13: 교보 일반·YES24(두 방식)·강남구 결과의 보유·대출 중·예약 수가 같은 시점의 사이트 표시와 같다.
- AC-14: 통합 포털(부산·대구 등) 결과에서 사이트가 "대출 가능"이면 "지금 빌릴 수 있어요", "예약 가능"이면 "예약하고 기다려요"에 나온다.
- AC-15: 경북·전북 포털에서 대출 중 1 이상인 책은 상세 페이지 판정대로 나뉜다 (예: 경북 「신 퇴마록 신세편 1」처럼 상세 판정이 "예약 가능"인 책은 "예약하고 기다려요"). 판정을 읽기 전에는 그 줄이 묶음 아래쪽 "대출 정보 조회 중" 자리에 보이고, 판정이 오면 같은 묶음 안에서만 칸을 옮긴다. 대출 중 0인 책은 상세 페이지를 요청하지 않는다. (화면 + 서버 로그)
- AC-16: 교보 구독형 결과는 "지금 빌릴 수 있어요" 칸에서 재고 수가 있는 줄 다음에 나오고, 수량 대신 구독형 표시가 보인다.
- AC-17: 한 묶음의 "지금 빌릴 수 있어요" 칸의 같은 제목 안에서, 통합 포털 줄은 재고 수가 있는 줄 다음에 나온다.

**호출**
- AC-18: 같은 호스트 이름(예: `ebook.jbe.go.kr`의 여러 포트)으로 가는 요청은 동시에 1건이고 간격이 1초 이상이다. (서버 로그)
- AC-19: YES24 한 세대 전·강남구 사이트로 보낸 검색어가 EUC-KR로 인코딩돼 있고 결과가 읽힌다.
- AC-20: 사이클 01의 캐시 3분, User-Agent 규칙이 그대로 지켜진다. (서버 로그)

**제목 정렬**
- AC-21: 한 묶음 안의 각 칸에서 제목 비교 키가 같은 줄이 붙어서 나온다. "지금 빌릴 수 있어요"에서는 재고 합계가 많은 제목이, "예약하고 기다려요"에서는 예약 인원 합계가 적은 제목이 먼저 나온다.
- AC-22: 같은 제목 안에서는 가입 가능 → 확인 필요, 그 안에서는 재고 많은 순(예약 칸은 예약 적은 순)이다.
- AC-23: 제목 표기가 띄어쓰기·문장부호만 다른 두 줄(예: "채식주의자"와 "채식 주의자")은 같은 제목 비교 키를 받는다. (API 응답)
- AC-24: "더 보기"로 새 묶음이 붙어도 이전 묶음의 줄 순서는 바뀌지 않는다.
