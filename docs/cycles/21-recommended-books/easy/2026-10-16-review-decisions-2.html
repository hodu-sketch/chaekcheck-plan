1반드시 고칠 것 중 그대로 고치면 되는 4개

[안] 아래 넷을 설계 변경서에 고쳐 적습니다. 새로 정하는 것은 없고, 정한 것을 dev가 만들 수 있게 빠진 칸 · 자리를 채우는 일입니다.

무엇이 빠졌나고침
책 이름 보정(ADR-0129)과 출판사로 좁히기에 필요한 책 제목 · 출판사가 catalog가 주는 값에 없음 (dev IsbnBook 등은 번호 · 보유 도서관만)catalog 공개 값 셋과 BookChoice 후보에 제목 · 출판사 정리값 칸을 더한다고 적음
가져오기 파일을 만들 때 어느 책 표(새로 만든 표 / 지금 표)로 맞출지 목록 쪽이 알 길이 없음collection이 맞출 책 표를 골라 넘겨 줌 (read(목록 폴더, 찾기))
사서추천 108줄을 옮길 때 순서 칸 · 새 분야 번호를 매기는 법이 없음지금 화면 순서(추천 월 · 등록일 늦은 순)대로 번호를 매기고, 모르는 분야는 6번부터 붙임. 받기 판단("목록 없음")도 사서 줄만 봄
첫 목록 파일(이동진 44권 · 서울대 100권)을 만드는 단계가 없음조사 문서 → 목록 파일 바꾸기, 이동진 44권 분야를 국립중앙도서관 분류로 다시 매긴 결과를 보여 드리고 확정하는 단계(명세 R3-9)를 dev 작업에 넣음

2파일 판이 다르면 반영을 거절, 목록 폴더가 없으면 만들기를 멈춤

[안] 가져오기 파일 판이 앱과 다르면 지금처럼 반영을 거절합니다("판 2 파일도 받는다"는 문장은 지움). 내 PC에서 파일을 만들 때 목록 폴더가 없으면 만들기를 멈춥니다.

어디서 생기는 일: 설계 변경서 한 곳은 "판 2 파일도 받되 목록은 건드리지 않음", 다른 곳과 ADR-0123은 "판이 다르면 거절"이라 서로 어긋났습니다. dev 코드는 판이 정확히 같아야 받습니다(JdbcCatalogLoad).

예: 목록 폴더 경로를 잘못 적고 파일을 만들면 — 멈추면 바로 알아챕니다. 멈추지 않으면 목록 없이 반영돼 운영의 이동진 · 서울대 목록이 비게 됩니다. 사이클 19의 규칙 폴더도 없으면 멈춥니다.

다른 선택: 목록 폴더가 없으면 목록만 건드리지 않고 나머지는 반영. 덜 막히지만 빠뜨린 것을 늦게 알게 됩니다.

3목록은 책 표를 바꿔 끼우는 그 트랜잭션 안에서 함께 넣기

[안] 운영 반영(apply)과 내 PC 마무리(finish) · 바로 바꾸기(in-place) 모두, 책 표를 바꿔 끼우는 짧은 트랜잭션 안에서 이동진 · 서울대 목록도 함께 넣습니다. ADR-0123의 "첫 트랜잭션"을 "바꿔 끼우는 트랜잭션"으로 고칩니다.

첫 트랜잭션
도서관 정보 · 비교
→
복원 · 색인
→
바꿔 끼우기 + 목록 넣기
한 트랜잭션
→
10분 안 화면

어떻게: catalog의 바꿔 끼우기가 "함께 할 일"을 하나 받아 같은 트랜잭션에서 부르고, collection이 거기에 목록 넣기(picks)를 넘깁니다. catalog는 picks를 모른 채 받은 일만 부르므로 모듈 의존은 늘지 않습니다.

감수할 것: 바꿔 끼우는 동안 검색이 기다리는 시간이 목록 넣기만큼 늘어남(약 250줄 + 표지 약 3MB, dev 측정 [확인 필요]). 목록 넣기가 실패하면 바꿔 끼우기도 멈춤 — 목록은 파일을 만들 때 검사하므로 드묾, 그때는 고쳐서 다시 반영.

다른 선택: (가) 바꿔 끼운 뒤 작은 트랜잭션으로 따로(앞 페이지 8번, 실패하면 옛 목록이 남음) (나) 처음대로 첫 트랜잭션(복원 · 색인 동안 새 책이 흐리게 보이는 틈)

답: 2번 "판이 무슨 판인데"
