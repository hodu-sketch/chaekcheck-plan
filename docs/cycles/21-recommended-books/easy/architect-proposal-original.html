결정 1: 새 두 목록을 어느 모듈에

  • B안 새 모듈(booklists 등) — 표지·캐시·고르기·API가 두 벌, 공통 모듈이 필요해짐
  • 추천: A안 [안]

결정 2: 목록 파일을 반영 파일(export)에 싣는 길

  • A안 load_manifest.notes.listPart + 반영 파일 판 3 (ADR-0086 도서관 부분과 같은 방식) — export 때 collection이 picks 공개 API CuratedListTransfer.read(listsDir)를 불러 검사된 JSON 글자를 받아 Notes.listPart에 실음. apply는 도서관 부분과 같은 첫 트랜잭션에서 replace(listPart), 비교가 다르면 함께 되돌림. finish·in-place도 replace. 판 2 → 3(판 2만 아는 앱이 목록을 버리지 않게). 장점: 파일 하나 원칙(ADR-0078), 모듈 경계 지킴, 사이클 13에서 실데이터로 통과한 방식. 단점: collection → picks 의존이 새로 생김, 판 3 배포 때 내 PC에 기다리는 판 2 내보내기가 있으면 finish 거절(ADR-0086과 같은 감수)
  • B안 dump 안에 표 — catalog 덤프 코드가 picks 표를 알게 되어 경계를 어김
  • C안 반영 파일 옆 작은 파일 — 옮길 파일이 둘, 짝 맞추기 검사가 새로 필요
  • 추천: A안, 호출은 같은 트랜잭션의 직접 호출(가져오기 명령은 곧 내려가는 프로세스라 비동기 이벤트로는 반영이 보장되지 않음) [안]

결정 3: 고정 판을 우리 책 번호(bookId)로 바꾸는 때

  • A안 캐시를 만들 때 맞춤 (ADR-0090과 같음) — DB에는 고정 판 글자(제목·저자·출판사·ISBN)만. 캐시가 10분마다 ① pinned_isbn13 → byIsbn13 ② 없으면 byTitleAndAuthor(pinned_title, pinned_author)를 출판사 정리값으로 좁힘 ③ 그래도 여럿이면 BookChoice. 고정 판이 비면 목록의 ISBN → 제목+저자. TitleAuthorBook에 출판사 정리값 칸을 더함. 장점: 다시 가져와 책 번호가 바뀌어도 10분 안에 바로잡힘, 사서추천과 같은 길. 단점: 10분마다 조회 약 144번(묶어서 SQL 둘), catalog 공개 레코드 바뀜
  • B안 apply 때 맞춰 book_id 저장 — 맞추는 길이 둘, 바꿔 끼우기 뒤 실패 처리가 새로 필요
  • 추천: A안 [안]

결정 4: 수집기(Python)가 판을 고를 때 무엇을 읽나

  • A안 내 PC 서비스 DB를 읽기만 (조사 때와 같음) — catalog.book·book_contributor·library.library.lending_model을 SELECT만. 같은 책 범위·거르기·보유량 공식은 Python. 장점: 조사에서 87권을 이 방법으로 맞춤, 새 Java 코드 없음. 단점: Modulith 밖 스크립트가 두 모듈 표에 기댐, 보유량 공식이 Java·Python 두 곳 → reference-index.md 6절에 재작업 항목을 더하고 같은 입력으로 두 결과를 비교하는 시험을 dev 작업에 넣음
  • B안 Java 명령(프로필)이 판을 골라 파일을 채우고 수집기는 부르기만 — 공식이 한 벌이지만 "수집기가"(spec R3-4 [확정])를 Java로 읽는 해석이 필요
  • C안 수집 SQLite 원본으로 Python이 직접 묶기 — 묶기 규칙을 다시 짜야 해 권하지 않음
  • 추천: A안 [안]

결정 5: 새 목록 표지를 누가 받나

  • A안 운영 서버 picks가 받음 (ADR-0091과 같음) — 수집기는 TITLE_URL을 목록 파일 cover_url에 적기만. 서버가 캐시를 새로 읽을 때 저장 안 된 표지만 1초 간격으로 받아 200px JPEG. 실패한 주소는 다음 05:00에 한 번 더 [안]. CoverUrls에 ISBN 서지 표지 주소 하나 더함, 표지 정리는 pick ∪ list_book 기준. 장점: 표지 코드·제한 그대로, CSP 그대로. 단점: 새 줄 직후 최대 10분(실패면 다음 날)까지 제목 글자
