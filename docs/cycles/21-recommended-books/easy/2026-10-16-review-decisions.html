설계 검토에서 나온 것 가운데
정할 것 9개를 골라 주세요.

마무리 첫 단계로 검토 담당(design-reviewer)이 설계 변경서·명세·ADR·dev 코드를 맞춰 봤습니다. "반드시 고칠 것" 8개, "고치면 좋은 것" 11개가 나왔습니다. 그대로 고치면 되는 것은 1번·9번에 묶었고, 방향을 고르셔야 하는 것은 2~8번에 하나씩 두었습니다. 다 고르시면 고친 뒤 지금 설계 문서(docs/current)를 고치고 dev 인계서로 넘어갑니다.

낱말뜻
가져오기 (export · apply)내 PC에서 전자책 목록 파일을 만들고(export), 운영 서버에서 그 파일을 반영(apply)하는 일
바꿔 끼우기반영 때 새 책 표를 다 만든 뒤 옛 책 표와 한 번에 바꾸는 마지막 단계. 이때부터 새 책 번호가 운영에서 보임
파일 판가져오기 파일 형식 번호. 이번에 목록을 실으면서 2 → 3
Liquibase 변경 파일DB 표를 바꾸는 파일. 번호 순서대로 한 번씩 돎 (예: usagelog/003)
구독형 도서관교보·북큐브 구독형처럼 여러 도서관이 같은 목록을 함께 쓰는 곳 (11곳)

1반드시 고칠 것 중 그대로 고치면 되는 4개

[안] 아래 넷을 설계 변경서에 고쳐 적습니다. 새로 정하는 것은 없고, 정한 것을 dev가 만들 수 있게 빠진 칸 · 자리를 채우는 일입니다.

무엇이 빠졌나고침
책 이름 보정(ADR-0129)과 출판사로 좁히기에 필요한 책 제목 · 출판사가 catalog가 주는 값에 없음 (dev IsbnBook 등은 번호 · 보유 도서관만)catalog 공개 값 셋과 BookChoice 후보에 제목 · 출판사 정리값 칸을 더한다고 적음
가져오기 파일을 만들 때 어느 책 표(새로 만든 표 / 지금 표)로 맞출지 목록 쪽이 알 길이 없음collection이 맞출 책 표를 골라 넘겨 줌 (read(목록 폴더, 찾기))
사서추천 108줄을 옮길 때 순서 칸 · 새 분야 번호를 매기는 법이 없음지금 화면 순서(추천 월 · 등록일 늦은 순)대로 번호를 매기고, 모르는 분야는 6번부터 붙임. 받기 판단("목록 없음")도 사서 줄만 봄
첫 목록 파일(이동진 44권 · 서울대 100권)을 만드는 단계가 없음조사 문서 → 목록 파일 바꾸기, 이동진 44권 분야를 국립중앙도서관 분류로 다시 매긴 결과를 보여 드리고 확정하는 단계(명세 R3-9)를 dev 작업에 넣음

2파일 판이 다르면 반영을 거절, 목록 폴더가 없으면 만들기를 멈춤

[안] 가져오기 파일 판이 앱과 다르면 지금처럼 반영을 거절합니다("판 2 파일도 받는다"는 문장은 지움). 내 PC에서 파일을 만들 때 목록 폴더가 없으면 만들기를 멈춥니다.

어디서 생기는 일: 설계 변경서 한 곳은 "판 2 파일도 받되 목록은 건드리지 않음", 다른 곳과 ADR-0123은 "판이 다르면 거절"이라 서로 어긋났습니다. dev 코드는 판이 정확히 같아야 받습니다(JdbcCatalogLoad).

예: 목록 폴더 경로를 잘못 적고 파일을 만들면 — 멈추면 바로 알아챕니다. 멈추지 않으면 목록 없이 반영돼 운영의 이동진 · 서울대 목록이 비게 됩니다. 사이클 19의 규칙 폴더도 없으면 멈춥니다.

다른 선택: 목록 폴더가 없으면 목록만 건드리지 않고 나머지는 반영. 덜 막히지만 빠뜨린 것을 늦게 알게 됩니다.

3여러 권짜리는 1권: 이동진 · 서울대는 수집기가, 사서는 서버 고르기가

[안] 판을 고를 때 여러 권짜리면 1권을 고릅니다. 이동진 · 서울대는 수집기가 고정 판을 고를 때, 사서는 서버의 같은 책 고르기(BookChoice)가 제목 끝 권 번호(1, (상))를 보고 1권(또는 권 번호 없는 판)을 먼저 고릅니다.

어디서 생기는 일: 명세 R2-2(세 목록 공통)는 "여러 권짜리는 그 판의 1권"인데, 서버 고르기에는 책 제목이 없어 권을 모릅니다. 1번에서 제목 칸이 더해지므로 쓸 수 있게 됩니다.

예: 서울대 「토지」 — 지금 규칙만이면 보유 도서관이 가장 많은 「토지. 2(1부 2권)」이 뽑혔습니다(조사 2026-10-15). 1권 규칙으로 「토지. 1(1부 1권)」.

다른 선택: 사서는 권 규칙 없이 지금처럼 (사서추천에 여러 권짜리가 드묾). 명세 R2-2를 "이동진 · 서울대만"으로 고칩니다.

4DB 변경 파일 번호: 21이 usagelog/003, 사이클 20은 004로

[안] 이용 기록 표 변경 파일 번호를 21이 usagelog/003으로 쓰고, 사이클 20 쪽에 004로 바꿔 달라고 공유 파일로 알립니다.

어디서 생기는 일: 사이클 19가 002, 21과 20이 둘 다 003을 적었습니다. 파일 이름이 달라 DB가 깨지지는 않지만 번호가 겹쳐 헷갈립니다. dev는 21을 먼저 만든다고 하셨습니다(2026-10-15).

다른 선택: 둘 다 003 그대로 두고 "이름이 달라 충돌 없음, 합치는 순서만 맞춤"이라고 적음.

5유튜브 30일 규칙: 수집할 때마다 이미 넣은 영상도 다시 확인

[안] 수집기가 돌 때마다 재생목록 전체를 다시 읽어, 목록 파일에 있는 영상이 아직 공개돼 있는지 확인하고 확인한 날을 적습니다. 사라지거나 비공개가 된 영상의 줄은 지우고 기록에 남깁니다.

어디서 생기는 일: 유튜브 개발자 정책은 API로 받은 정보를 30일이 지나면 새로 받거나 지우라고 합니다(III.E.4, https://developers.google.com/youtube/terms/developer-policies , 2026-10-15 확인). 설계는 "매달 다시 읽어 지킴"이라고만 했는데, 수집기는 새 영상만 보게 그려져 있었습니다.

비용: 재생목록 「이달의 책」 약 30개 · 업로드 목록은 한 번에 50개씩 읽으므로 몇 번의 요청(각 1단위)이면 됩니다. 하루 한도는 10,000단위입니다.

다른 선택: "영상 ID는 30일 규칙 대상이 아니라고 본다"로 두고 확인 필요로 남김. 정책에 ID를 따로 적은 곳이 없어 확실하지 않습니다.

6ADR-0129 (책 이름 보정) 초안 그대로 확정

[안] 책 이름 보정 페이지에서 고르신 것을 결정 기록 ADR-0129로 남겼습니다. 초안 그대로 확정합니다 (Proposed → Accepted).

정하는 것: 맞춘 책은 그 책 제목에서 판 표시를 덜어 낸 이름, 못 맞춘 책은 목록 이름, 세 목록 모두, 다르면 책 창에 목록 이름 한 줄. 검토 담당이 "구조에 영향을 주는 결정인데 ADR이 없다"고 짚었습니다. 기록: docs/adr/0129-picks-shown-title-from-matched-book.md

7보유량은 켜진 도서관만 셈

[안] 같은 책 고르기의 보유량은 지금 켜진 도서관만 셉니다(구독형도 켜진 곳만 보고 1). 사이클 14 사서추천도서도 이 셈으로 바뀝니다.

어디서 생기는 일: 책마다 가진 도서관 목록에는 지금 꺼진 도서관도 남아 있습니다(dev IsbnBook 설명). 구독형 번호를 켜진 곳만 받으면, 꺼진 구독형 도서관이 일반 도서관 한 곳으로 세져 보유량이 부풀 수 있습니다.

예: 판 A는 켜진 일반 3곳, 판 B는 켜진 일반 2곳 + 꺼진 구독형 2곳. 지금 셈이면 B가 4로 이기고, 켜진 곳만 세면 A(3) 대 B(2)로 A입니다. 꺼진 도서관에서는 빌릴 수 없으니 A가 맞습니다.

다른 선택: 구독형 번호만 꺼진 곳까지 받아 셈을 맞춤. 꺼진 일반 도서관은 여전히 셉니다.

8목록은 책 표를 바꿔 끼운 뒤 넣기

[안] 운영 반영에서 이동진 · 서울대 목록은 새 책 표로 바꿔 끼운 뒤 작은 트랜잭션 하나로 넣습니다. ADR-0123의 "도서관 정보와 같은 첫 트랜잭션"을 이렇게 고칩니다.

어디서 생기는 일: 목록 줄의 책 번호는 새 책 표 기준입니다. 첫 트랜잭션에서 넣으면 그 뒤 복원 · 색인이 끝나 바꿔 끼울 때까지 운영은 옛 책 표인데 목록은 새 번호를 가리킵니다.

9고치면 좋은 것 나머지 그대로 고침

[안] 아래를 그대로 고칩니다.

  • ADR-0124 결과에 "ADR-0090의 '짝은 저장하지 않음'이 이동진 · 서울대 줄에 한해 바뀜" 추가
  • 명세 · 화면 · 범위의 옛 문장 정리 (R3-4 "서버는 고정 판 칸을 그대로 씀", 끝난 확인 필요 둘, 범위 "제외"에 남은 자동 받기, 범위 상태 줄), 책 이름 보정 수용 기준 AC-16 추가
  • 머리말 행에 "ADR-0121(모든 화면 같은 머리말)은 사이클 20이 확정할 초안"이라고 적고 인계서에 넣음
  • backlog에 세 줄: 도서관 클릭 기록에 목록 이름, 목록 반영 기록 표, 보유량 공식 공통 시험 자료. 참고 문서 목록 6절에 "책 · 도서관 칸이 바뀌면 수집기 판 고르기도 고침"
  • 표 제약을 세 목록 대칭으로, 표지 넣기는 이미 있으면 건너뜀, 수집기 표지도 폭 200px · 품질 0.8 · http는 https로
  • 목록 잠금 이유 한 줄, 정책 주소 · 5MB 한도 태그, 제안서 맨 위에 "옛 그림, 최신은 설계 변경서"

답: 8번 "같은 트랜잭션으로 해주면 안 돼?"

됩니다. 책 표를 바꿔 끼우는 그 짧은 트랜잭션 안에서 목록도 함께 넣으면, 새 책 표와 새 목록이 한순간에 같이 바뀌고 실패하면 둘 다 옛것으로 남습니다.

내용
좋은 점새 책 번호와 새 목록이 함께 보임. 바꿔 끼우기가 실패하면 목록도 옛것 그대로
걸리는 점책 표 바꿔 끼우기 코드(catalog)에 "바꿔 끼울 때 함께 할 일"을 받는 자리를 하나 둬야 함. 바꿔 끼우는 동안 검색이 기다리는 시간이 목록 넣기(약 250줄 + 표지)만큼 늘어남 — 짧을 것으로 보지만 dev 측정 [확인 필요]. 목록 넣기가 실패하면 책 표 바꿔 끼우기도 멈춤(목록은 파일 만들 때 검사하므로 드묾)

이 방식으로 할지는 새 탭 「사이클 21 설계 검토 2」에서 골라 주세요. 1번 · 2번은 아직 선택이 오지 않아 그 탭에 다시 두었습니다.
