사이클 21 회고에서 정할 것 4개 (2026-10-17)

dev 기록(plan-feedback.md "# 사이클 21")과 dev main 836bd7b 코드를 설계와 비교해 회고(retro.md)를 쓰고 docs/current를 실제 코드에 맞췄습니다. 모듈 구조·표·API는 설계 그대로였습니다. 바뀐 것은 대부분 화면에서 직접 정하신 것이라 이유가 기록돼 있고, 아래 4개만 정하면 회고를 닫습니다.

1머리말 ADR-0127을 지금 화면에 맞추기

무엇인가. dev에서 직접 바꾸신 머리말(큰 메뉴 셋 「도서검색」·「추천도서」·「마이페이지」, PC는 누르면 펼침, 폰은 ☰ 없이 줄 누르기 + ▾, 로고는 메인으로만)이 ADR-0127 본문에는 옛 모양("폰은 ☰")으로 남아 있습니다. 결정은 이미 하셨고 기록만 낡았습니다.

[안] ADR-0127 "결과"에 "바뀜 (2026-10-16~17)" 줄을 더하고 제목의 "폰은 ☰"를 고칩니다. 명세 R1-5·R1-6 문구도 같이 고칩니다(ADR-0128·0129와 같은 방식).

다른 선택: ADR을 새로 하나 써서 0127을 대체.

2수집기가 "저자를 보지 않고 다시 고르기"를 하는 문제

무엇인가. 이동진·서울대 목록의 책 판은 수집기(dev scripts/crawl/recommended_lists.py 490~500행)가 고릅니다. 거르기 뒤 남은 판이 없으면 dev가 저자를 보지 않고 같은 본제목 판 전체에서 다시 고르는 규칙을 더했습니다(코드 주석: "어린이판·요약판만 남은 경우"). 명세 R3-3은 "같은 책 = 본제목 + 저자"라 이 규칙과 어긋나고, 이유를 말씀하신 기록이 없습니다.

[안] 이 규칙을 없애고 그런 줄은 "못 맞춤"(흐린 표지)으로 둡니다. dev가 다시 돌려 바뀌는 줄을 보고하면, 바른 판이 있는 책만 사람이 manual로 고정합니다(지침 matching-guide.md 4절).

다른 선택: 규칙은 두되 이 길로 고른 줄을 수집 기록에 따로 남겨 사람이 매번 확인.

3표지 출처가 바뀐 것을 ADR-0123에 적기

무엇인가. ADR-0123 본문은 "ISBN 서지 표지"인데, dev 결과 검토에서 정하신 대로 실제로는 표지 출처가 다섯 곳 + 출판사 공식 페이지 한 장이고 카카오는 뺐습니다(저장 금지 조건). 결정은 이미 하셨고 기록 방식만 묻습니다.

[안] ADR-0123 "결과"에 "바뀜" 줄로 표지 차례와 카카오를 뺀 까닭을 적습니다.

다른 선택: 새 ADR로.

4이유가 기록되지 않은 dev 세부 셋

무엇인가. dev가 화면을 다듬으며 정한 것인데 이유가 남아 있지 않습니다. ① 화면 책 이름에서 끝 낱말 "세트"를 덜어 냄 ② 2권부터는 「토지 2」처럼 권 숫자를 남김 ③ 이동진 영상은 2023-12보다 오래된 것은 보지 않음. 실제 폰 확인 때 "폰 확인했어 괜찮아"라고 하셨습니다.

[안] 셋 다 지금대로 [확정]하고 회고에 적습니다.

다른 선택: 바꿀 것을 기타로.
