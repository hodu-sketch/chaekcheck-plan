dev가 국립중앙도서관 API를 시험해 보니
분야 · 표지를 거기서 얻을 수 없었습니다. 6개를 골라 주세요.

dev 사이클 21이 0단계(API 시험)를 마쳤습니다(2026-10-16, dev docs/plan-feedback.md "# 사이클 21"). 수집기가 이동진 추천도서의 분야와 표지를 국립중앙도서관 ISBN 서지 API에서 받기로 했는데, 그 API가 이동진 책에는 둘 다 거의 주지 않습니다. 이 페이지에서 "판"은 책의 판(출판사 판)만 뜻합니다.

시험에서 나온 것

이동진 43권은 분류 번호(KDC)가 모두 비었고, 표지는 40권이 비었습니다. 서울대도 분류는 92%, 표지는 88%가 빈 줄입니다.

1새로 들어오는 이동진 책의 분야는 사람이 정함 (수집기가 제안)

[안] 수집기는 새 이달의 책을 "확인 필요" 파일에 넣으며 주제 한 자리로 고른 분야를 제안만 하고, 사람이 목록 파일의 분야 칸을 정해 적으면 목록에 들어갑니다. 한 달에 1~4권입니다.

어디서 생기는 일: 처음 정하신 것은 "수집기가 분야까지 자동으로 넣고 바로 확정"(명세 R4-3 · R4-4)이었는데, 자동으로 정할 근거(KDC)가 없어졌습니다.

2지금 44권 분야는 조사 때 정한 그대로

[안] 이동진 44권의 분야는 조사 때 정해 보여 드린 것(분야별 목록) 그대로 씁니다. "국립중앙도서관 분류로 다시 매겨 기준을 하나로"(명세 R3-9)는 하지 않습니다.

어디서 생기는 일: 명세 결정 #7에서 지금 44권도 새 책과 같은 근거(KDC)로 다시 매기기로 하셨는데, KDC가 하나도 없어 다시 매길 수 없습니다. 1번에서 새 책도 사람이 정하면 기준이 "사람"으로 같아집니다.

예: 「대온실 수리 보고서」는 지금처럼 한국 소설, 「히스토리아 비테이」는 과학·의학 (docs/research/leedongjin-picks/picks.md 5절).

3표지는 우리 수집 DB의 전자책 표지를 줄여서

[안] 수집기가 이동진 · 서울대 책의 표지를 국립중앙도서관 대신 우리가 이미 모은 전자책 목록의 표지 주소에서 받아 폭 200px로 줄여 싣습니다. 그 책을 가진 도서관 사이트의 표지 가운데 하나를 씁니다. 없으면 국립중앙도서관 표지, 그것도 없으면 지금처럼 제목 글자 표지입니다.

어디서 생기는 일: 국립중앙도서관 표지가 이동진 43권 중 3권뿐이라, 이대로면 목록 대부분이 제목 글자로 보입니다.

dev가 세어 봄 (2026-10-16, 수집 사본 2026-10-12): 우리 책을 맞춘 이동진 36권 · 서울대 87권 모두 수집 DB에 표지 주소가 있습니다. 표본 12장을 열어 보니 12장 모두 그림이 열렸습니다. 못 맞춘 책(이동진 8 · 서울대 13)은 국립중앙도서관 표지가 있으면 그것, 없으면 제목 글자 표지입니다.

감수할 것: 저작권 위험은 지금 설계와 같은 "작게 줄여 저장 + 출처 표시 + 삭제 요청 받으면 내림" 수준(조사 docs/research/popular-books/cover-copyright.md 6절, "중간")입니다. 도서관 사이트에서 표지를 한 장씩 더 받습니다(새 책만, 사람 손 속도).

다른 선택: 국립중앙도서관 표지만 쓰고 나머지는 제목 글자 표지. 받는 곳이 하나로 단순하지만 이동진 목록은 거의 글자 표지가 됩니다.

6표지 주소가 여럿이면 YES24 · 교보 그림 먼저

[안] 한 책에 도서관마다 표지 주소가 있으면, 수집기는 YES24(image.yes24.com) · 교보(dcontent.dkyobobook.co.kr) 그림 서버 주소를 먼저 쓰고, 없으면 그 책의 첫 주소를 씁니다. 받지 못하면 다음 주소로 넘어갑니다. 3번을 고르실 때만 씁니다.

어디서 생기는 일: 같은 책을 여러 도서관이 가지고 있어 표지 주소도 도서관마다 하나씩 있습니다(가운데값 이동진 260개, 서울대 60개, dev 2026-10-16). 그림 서버는 YES24 · 교보와 도서관 전자도서관 사이트들로 여러 곳입니다.

알려 드릴 것 (고를 것 아님)

  • YouTube Data API 키가 dev .env에 없어 유튜브 쪽 시험을 못 했습니다. 키를 만들어 넣어 주셔야 다음으로 갑니다(Google Cloud 콘솔 → API 사용 설정 → 사용자 인증 정보 → API 키).
  • 영상 ID 꼴은 유튜브 공식 문서에 정해져 있지 않아, DB 검사는 지금처럼 "1~64자 영문 · 숫자 · _ · -"로 두고 근거는 "관찰"로 적습니다.
  • 국립중앙도서관 표지 주소는 호스트가 셋(www 있음 · 없음, http · https)이라 DB 검사를 그에 맞게 넓힙니다. 3번을 고르시면 도서관 사이트 주소도 받도록 "https://로 시작"만 봅니다.
