사서추천도서도 가져오기 길로 옮길지
정할 것 3개를 골라 주세요.

"사서추천도서도 가져오기로 같이 하는게 어떨까해"라고 하셔서 따져 봤습니다. 그렇게 하면 세 추천 목록이 모두 한 길(수집기 → 가져오기 파일 → 운영 DB → 서버는 읽기만)로 모입니다. 대신 범위·명세에서 정한 "사서추천도서는 지금처럼 서버가 주 1회 받음"과, 사이클 14에서 이미 만든 서버 받기 장치가 바뀝니다. 앞 페이지 「사이클 21 설계 결정」의 #4·#11은 그대로 열려 있습니다.

지금과 제안

지금은 사서추천도서만 서버가 직접 받아 옵니다. 제안대로 하면 서버는 바깥에 아무것도 받으러 가지 않고 DB만 읽습니다.

1사서추천도서도 수집기 → 가져오기 길로

[안] 사서추천도서 목록도 내 PC 수집기가 국립중앙도서관 API에서 받아 목록 파일에 적고, 가져오기 파일에 실어 운영으로 보냅니다. 세 목록이 같은 표·같은 맞추기·같은 표지 길을 씁니다.

좋은 점: 운영 서버는 바깥 사이트에 요청하지 않고 DB만 읽습니다(국립중앙도서관 키도 운영에 둘 필요 없음). 맞추는 길이 하나라 설계 #4 새 제안이 사서추천도서에도 그대로 들어맞습니다.

바뀌는 것: 범위 "포함 4"와 명세 R3-1의 "사서 추천도서는 지금처럼 서버가 주 1회 받음", 사이클 14 명세 R1(받기 규칙)이 이 길로 바뀝니다. 사이클 14에서 이미 만든 서버 쪽 받기 장치를 고쳐야 합니다(3번).

표도 줄어듭니다: 사서추천 줄을 담던 pick 표가 필요 없어지고 세 목록이 책 줄 표(list_book) 하나를 씁니다(앞 페이지 「PICK 표는 왜 필요한가」 답 참고).

다른 선택: 지금처럼 사서추천도서만 서버가 받기. 이미 만든 것을 건드리지 않지만, 길이 둘이고 사서추천도서만 서버가 따로 맞춥니다.

2받는 때: 수집기를 돌릴 때마다

[안] 사람이 수집기를 돌릴 때마다 사서추천 목록도 받고, 가져오기 반영 때 화면에 나옵니다. 매주 월요일 자동 받기와 "실패하면 매일 다시"는 없어집니다.

국립중앙도서관이 새 추천 등록
보통 2달에 한 번, 8권
다음 수집 실행
사람이 돌릴 때
가져오기 반영
화면에 새 추천

국립중앙도서관은 보통 2달에 한 번 8권을 추천하고, 등록일도 며칠에 걸쳐 들쭉날쭉합니다(사이클 14 조사: 2026년 10월 추천 등록 9월 22~28일). 수집을 한 달에 한 번 이상 돌리면 새 추천은 늦어도 한 달 안에 화면에 나옵니다.

다른 선택: 수집기 대신 내 PC에 예약 작업을 두어 매주 자동으로 받기. 빨리 반영되지만 반영(apply)은 어차피 사람이 하므로 화면에 나오는 때는 크게 다르지 않습니다.

3서버의 사서추천 받기 장치는 지움

[안] 운영 서버의 사서추천 받기 예약(매주 월요일), 받기 기록 표(fetch_run), 서버의 국립중앙도서관 키 설정을 지웁니다. 아직 배포 전이라 남겨 둘 까닭이 없습니다.

사이클 14에서 출판유통통합전산망 받기를 지울 때도 배포 전이라 옛 장치를 남기지 않았습니다(ADR-0089). 받기가 잘 됐는지는 수집 기록과 가져오기 기록으로 봅니다.

다른 선택: 서버 받기 장치를 꺼 둔 채 남겨 두기(예비). 수집기가 안 될 때 다시 켤 수 있지만, 쓰지 않는 코드와 표가 남습니다.
