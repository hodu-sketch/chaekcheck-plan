# 기능 명세: 인기 도서 → 사서추천도서

- 범위: `scope.md` "포함" 1~4와 "이미 정한 것". 결정의 출처(사용자 말)는 `scope.md`·이 문서 표에 적음
- 바탕: 사이클 10 명세 `../10-popular-books/spec.md`(이하 "C10"). **여기 적지 않은 규칙은 C10 그대로**이고, 바뀌는 것만 적음. 지금 만들어진 모양은 `docs/current/`(`popular` 절)와 C10 회고 `../10-popular-books/retro.md`
- 조사: `../../research/popular-books/alternatives.md` 3절(사서추천도서), 3-0절(Open API 받아 봄), 3-1절(우리 목록과 맞는 비율)
- 작성 2026-10-12

## 사용자 이야기

- 읽을 책을 고르는 이용자가 국립중앙도서관 사서가 고른 최근 추천 책을 분야별로 보고 싶다, 무엇을 읽을지 고르기 위해서
- 그중 검색하는 도서관에서 전자책으로 빌릴 수 있는 책을 바로 알고 싶다 (C10과 같음)
- 전자책이 없는 책은 어떻게 하면 되는지 알고 싶다 (C10과 같음)

| 항목 | 내용 | 규칙 | 상태 태그 |
|---|---|---|---|

| 보여 줄 범위 | **가장 최근 추천 12번(2년)**: 추천 연월(`recomYear`·`recomMonth`)이 다른 달 가운데 최근 12개 달의 책 전부 | 2026-10-14 받기 기준 2024.12~2026.10 → 108권(문학·인문·사회·자연 각 18, 테마 36). 처음 정한 "최근 6번"(2026-10-12 기준 52권)을 바꿈 | [확정] (사용자 결정, dev 2026-10-14: "12번(2년)으로 늘리기" — 처음 값은 사용자 "최근 추천 6번 (추천)", 2026-10-12) |

| 검색하는 도서관 | C10과 같음 (검색 화면과 같은 검색 기준) | | [확정] (C10) |

## 동작 규칙

### R1. 받기 (C10 R1을 바꿈)

- R1-1 [확정] (사용자 "승인", 2026-10-12, 인계서 검토) 넉넉한 기간(받는 날부터 거꾸로, 등록일 기준 `start_date`·`end_date`)으로 **요청 1건**(`endRowNumApi` 넉넉히)을 보내고, 받은 것 가운데 추천 연월이 최근인 **12개 달**만 남긴다 [확정] (사용자 결정, dev 2026-10-14: "12번(2년)으로 늘리기" — 처음 6개 달을 바꿈). 2026-10-12 시험: 기간 거르기가 됨(`20251101~20261031` → 52건, `drCode=11` 더하면 10건). 범위 안에 추천 달이 12개 미만이면 받은 것 전부. `end-row` 1000은 설계 값 승인 [확정] (사용자 "이름·값 … 승인", 2026-10-12). 기간: 처음 승인한 2년을 dev가 **3년**으로 바꿈 [안: dev 변경, 사용자 확인 전] [이유 미확인 — 사용자 발언 없음. dev가 적은 이유: 추천이 2달에 한 번이라 12번 = 약 24개월이고 2년이면 받는 날에 따라 12번째 추천의 등록일이 범위 밖으로 빠질 수 있음 (dev `docs/plan-feedback.md` 3783행)]. 2년 범위 1건 = 108건·1.56MB (2026-10-12 시험), 3년 범위 1건 = 163건·2,511,752바이트·771ms, 남긴 것 108권 (2026-10-14 dev 받기 시험)
- R1-2 [확정] (사용자, 2026-10-12, spec 질문 #1: 받기 방식에 "일주일에 한 번"으로 답함) 받는 때: **일주일에 한 번**. 요일·시각은 월요일 05:00 [확정] (사용자 승인, 2026-10-12, spec 질문 #5). 받은 목록이 저장된 것과 같으면 바꾸지 않음. 새 추천이 등록되는 날은 일정하지 않음(2026.10 추천 등록일 2026.09.22~28, 2025.12 추천은 2025.11.27~12.01 — 2026-10-12 API 호출 시험). 월요일에 서버가 꺼져 못 받았으면 따라잡음: 마지막 성공이 7일보다 오래됐으면 서버가 켜질 때·다음 05:00 판단 때 받음 [확정] (사용자: "켜질 때 따라잡기 (추천)", 2026-10-12, 설계 검토)
- R1-3 [확정] (사용자 "승인", 2026-10-12, 인계서 검토) 실패(키 거절·오류 코드·XML 형식 바뀜·받은 책 0권)면 저장하지 않고 화면은 앞에 저장한 목록 그대로. **성공할 때까지 매일 05:00에 다시** [확정] (사용자: "성공할 때까지 매일", 2026-10-12, 인계서 검토 — 처음 안 "다음 날 한 번, 그다음은 다음 주"를 바꿈, ADR-0092). 받기 기록 한 줄 + 서버 오류 기록은 C10 R1-4 그대로
- R1-4 [확정] (C10 R1-4) 자동으로만 받음. 관리자 다시 받기·알림 없음
- R1-5 [확정] (사용자 "승인", 2026-10-12, 인계서 검토) 저장된 목록이 하나도 없으면 서버가 켜질 때 바로 받음 (C10 R1-6과 같은 생각)
- R1-6 [확정] (사용자, 2026-10-12, scope) 출판유통통합전산망(`bnk.kpipa.or.kr`)에는 어떤 요청도 보내지 않는다. 받아 둔 순위·판매 부수·표지·받기 기록은 지운다
- R1-7 [확정] (사용자 "승인", 2026-10-12, 인계서 검토) 인증키는 서버 설정값(비밀값)으로만 두고 화면·로그·문서에 적지 않는다

### R2. 분류 (C10 R2를 바꿈)

- R2-1 [확정] (사용자: "전체·문학·인문·사회·자연·테마 (추천)", 2026-10-12) "전체" + 5분류. 이름: 전체, 문학(`drCode` 11), 인문(6), 사회(5), 자연(4), 테마(425). 순서는 이대로 고정 (판매 부수 순서는 없어짐)
- R2-2 [확정] (사용자 승인, 2026-10-12, spec 질문 #2) 화면 이름은 짧게 "인문·사회·자연"(국립중앙도서관 이름은 인문과학·사회과학·자연과학). 2026-10-12 값(6번): 문학 10, 인문 10, 사회 10, 자연 10, 테마 12, 전체 52. 2026-10-14 값(12번): 문학·인문·사회·자연 각 18, 테마 36, 전체 108 [확정] (사용자 결정, dev 2026-10-14)
- R2-3 [확정] (사용자 승인, 2026-10-12, spec 질문 #2) 범위 안에 책이 0권인 분류는 목록·화면에서 숨김
- R2-4 [확정] (사용자 승인, 2026-10-12, spec 질문 #5) "전체"에는 5분류 책이 모두 나옴. 같은 책이 "전체"와 분야 양쪽에 보이는 것은 C10 R3-3 그대로
- R2-5 [확정] (사용자: "새 분야 오면 그냥 넣는게 어떨까하는데 어때?", 2026-10-12; 넣는 방식은 선호 없음 → 추천안, ADR-0089) 모르는 새 분야 코드가 오면 그 책을 "전체"에 넣고, 분류 목록 맨 뒤(테마 다음, 새 코드끼리는 코드 순)에 API가 준 분야 이름(비면 "기타")으로 새 분류를 붙임. 받기 기록에 새 코드를 남김

### R3. 전자책 있음/없음 (C10 R3을 바꿈)

- R3-1 [확정] (사용자, 2026-10-12) ① 추천 ISBN(978·979로 시작하는 13자리)과 `catalog.book.isbn13`이 같은 우리 책 ② ①이 없으면 본제목이 같고 추천의 첫 저자가 우리 책 저자에 들어 있는 책(본제목·저자 규칙은 `design-delta.md` "모듈" `catalog` 줄에 한 곳으로 둠). 2026-10-12 수집 DB 측정: 최근 1년 52권 중 ① 29권, ①이나 ② 32권(61.5%). ②로만 맞은 책 표본 15권 모두 같은 책 (조사 3-1절)
- R3-2 [확정] (사용자: "가장 많은 도서관이 가진 책 (추천)", 2026-10-12, spec 질문 #4) ②에서 우리 책이 둘 이상 나오면 그 책을 가진 도서관(전체, 검색하는 도서관과 무관)이 가장 많은 책 하나로 맞춤. 같으면 책 번호가 작은 것 [확정] (사용자 승인, 2026-10-12, spec 질문 #5)
- R3-3 [확정] (C10 R3-1 뒷부분) 맞은 책을 가진 도서관이 검색하는 도서관 중 한 곳이라도 있으면 "전자책 있음"
- R3-4 [확정] (사용자: "캐시를 만들 때 맞춤 (추천)", 2026-10-12, ADR-0090) 짝은 저장하지 않고 공용 캐시를 만들 때(시작·10분마다·목록 바뀐 직후) 맞춤

### R4. 격자 (C10 R4를 바꿈)

- R4-1 [확정] (C10 R4-1·R4-2) 분류마다 3×3, ◀ ▶, 아래로 내리면 다음 분류. 분류마다 18권(테마 36권)이라 2쪽(테마 4쪽) [확정] (사용자 결정, dev 2026-10-14 — 12번으로 늘려 처음 "10권 안팎, 1~2쪽"이 바뀜)
- R4-2 [확정] (사용자 승인, 2026-10-12, spec 질문 #2; 방법 변경 승인 2026-10-12 설계 "등록일 기준 정렬 … 승인") 순서: 추천 연월 최근 먼저, 같은 달 안에서는 나중 등록 먼저 = 등록일(`regdate`, 저장 칸 `registered_on`) 늦은 순 → `recomNo` 글자 큰 순. `recomNo`는 옛 추천 1~4자리 수, 최근 추천 20자리 글자라 수로 비교할 수 없음 (2026-10-12 API 호출 시험)
- R4-3 [확정] (사용자: "없애고 표지만 (추천)", 2026-10-12) 표지 왼쪽 위 순위 숫자 없음. 카드는 표지만. 전자책 없는 책은 흐리게(C10 R4-5)
- R4-4 [확정] (사용자: "1로 하되 이전 인기도서처럼 제한걸고 수집하고 크기 좀 줄여", 2026-10-12, ADR-0091) 표지: ① 국립중앙도서관 표지(`recomfilepath`, http → https로 바꿔야 열림) ② 안 열리면 제목 글자 카드(C10 R4-4). **바뀜**: 처음 정한 "우리 전자책 표지 먼저"(사용자: "수집한 거 쓰고 없으면 국립중아도서관 표지 쓰고", scope)는 서비스 DB에 표지가 없어(설계 중 확인) 이번에 빼고 backlog로 보냄. 국립중앙도서관 표지는 API 응답에 그림 주소로 와서 사이트를 따로 긁을 필요 없음, 그림 받기에 인증키 필요 없음 — 2026-10-12 최근 52권 모두 `200`(JPEG 41·PNG 9·BMP 2, 4KB~648KB, 가운데값 56KB)
- R4-5 [확정] (사용자: "받아서 작게 줄여 저장 (추천)", 2026-10-12, ADR-0091) 국립중앙도서관 표지는 새 책 것만 받아 폭 200px JPEG로 줄여 우리 서버가 넘겨줌. 원본 상한 5MB [확정] (사용자: "5MB (추천)", 2026-10-12, 설계 검토 — 사이클 10은 50MB였음)

## 수용 기준

C10의 AC-2(◀ ▶ — 마지막 쪽 권수는 분류마다 다름), AC-3, AC-5, AC-7~AC-10, AC-14, AC-16, AC-18~AC-21은 이름만 바꿔 그대로. 아래는 바뀌거나 새로 생긴 것.

- AC-1: 목록을 받은 뒤 "사서추천도서"를 열면 → "전체" 첫 9권이 3×3 표지로(숫자 없음) 보이고, 출처 줄에 "국립중앙도서관 사서추천도서"와 받은 날이 보인다 (PC·태블릿·폰)
- AC-4: 분류 목록이 → 전체, 문학, 인문, 사회, 자연, 테마 순이다(그 뒤에 새 분야가 올 수 있음, R2-5). 범위 안에 책이 없는 분류는 없다
- AC-4b: 시험 응답에 모르는 분야 코드(예 999, 이름 "새분야")가 섞이면 → 그 책이 "전체"와 맨 뒤 "새분야" 분류에 보이고, 받기 기록에 999가 남는다. 이름이 비면 "기타"
- AC-6: ISBN이 우리 책과 같거나, ISBN이 없거나 안 맞아도 본제목과 첫 저자가 맞는 우리 책이 있고, 검색하는 도서관 중 한 곳이 그 책을 가지면 → 또렷하게, 아니면 → 흐리게 보인다
- AC-11: 받기 시험에서 API가 오류 코드를 주거나 0권을 주면 → 목록은 바뀌지 않고, 받기 기록에 실패와 이유가 한 줄, 서버 기록에 오류가 남는다
- AC-12: 받기 한 번은 국립중앙도서관 목록 요청 1건 + 목록이 바뀌었을 때만 새 표지 요청(`www.nl.go.kr`, 1초 간격)이다. 출판유통통합전산망(`bnk.kpipa.or.kr`)으로 가는 요청은 0건이다 (로그로 확인)
- AC-13b: 마지막 성공이 7일보다 오래된 상태로 서버를 켜면 → 곧바로 받는다
- AC-13: 목록이 없는 상태로 서버를 켜면 → 곧바로 받아 받기 기록에 남긴다
- AC-14b: 국립중앙도서관 표지가 저장된 책은 그 표지(우리 주소), 없거나 안 열리면 제목 글자 카드가 보인다
- AC-15: 머리 링크와 화면 이름이 "사서추천도서"다. "인기 도서" 글자는 어느 화면에도 없다
- AC-17: 전체 범위는 추천 연월이 다른 최근 **12개 달**이다 (2026-10-14 값이면 2024.12~2026.10, 108권) [확정] (사용자 결정, dev 2026-10-14 — 처음 "최근 6개 달, 52권"을 바꿈)
- AC-22: 개발 DB에 출판유통통합전산망 순위·판매 부수·표지가 남아 있지 않다
