1DB를 어떻게 떼어 놓을까

1DB 떼어 놓는 방식 [안]

A안 (추천): docker 프로젝트를 따로 켜고, 지금 DB를 한 번 복사해 씀

  • 새 작업 폴더에서 프로젝트 이름만 바꿔(docker compose -p chaekcheck-c14 …) DB 상자 두 개를 새로 켭니다. DB 주소 번호는 그 폴더의 .env에 따로 적습니다(DB_PORT, TEST_DB_PORT — dev 설정이 이미 이 값을 읽음).
  • 서비스 DB(약 8.5~10GB)를 한 번 복사해 넣습니다. 사이클 11에서 만든 복사 방법(pg_dump 파일 하나)을 그대로 씁니다.
  • 좋은 점: 14를 처음부터 끝까지(옛 표 지우기, 서버 켜기, 진짜 받기 시험, 화면 확인) 지금 다 할 수 있습니다. 12·13이 끝나면 코드만 합치면 됩니다.
  • 드는 것: 디스크 약 10GB 더, 복사하는 시간(측정이 안 도는 때에), 명령마다 -p chaekcheck-c14를 빼먹지 않기(빼먹으면 원래 DB를 건드림).

B안: 시험용 DB(db-test)만 따로, 진짜 DB는 읽기만 — 복사 없이 가볍습니다. 코드와 시험은 지금 다 하고, 1단계 측정은 원래 DB를 읽기만 합니다. 대신 서버 켜기·진짜 받기 시험·화면 확인은 12·13을 합친 뒤로 미뤄야 합니다.

C안: 같은 DB 상자 안에 DB 이름만 따로 (DB_NAME=chaekcheck_c14) — 새 상자는 없지만, 사이클 11이 그 상자의 메모리를 재는 중이라 측정 값이 섞일 수 있습니다. 데이터도 결국 복사해야 합니다.

D안: 따로 떼지 않고 나중에 (앞서 대화에서 낸 "지금은 코드만, DB 일은 합친 뒤") — 준비가 가장 적지만 14의 절반이 12·13을 기다립니다.

3안전장치 [안]

  • 새 폴더에서 docker 명령을 칠 때는 늘 -p chaekcheck-c14를 붙이고, 켜기·끄기 전에 docker compose ls로 어느 프로젝트인지 봅니다. 원래 프로젝트(chaekcheck)는 켜고 끄지 않습니다.
  • 복사는 사이클 11 측정 라운드가 쉬는 때에, 사용자에게 알리고 합니다(원래 DB를 읽기만 함).
  • 새 상자 셋을 더 켜면 PC 메모리를 더 씁니다. 시험 DB는 메모리에 올라가는 방식(tmpfs)이라 다 쓰면 끕니다.

3합치는 순서와 문서 고치기

4합치는 순서 [안]

12·13이 먼저 끝나 기본 브랜치에 들어가면, 14 브랜치를 그 위로 옮기고(rebase) 위 표의 작은 충돌을 풉니다. 13이 새로 만든 설정 파일의 옛 "인기 도서" 줄도 이때 지웁니다. 14가 먼저 끝나면 반대로 13이 그 위로 옮깁니다 — 어느 쪽이든 충돌은 같은 몇 줄입니다.

그러려면 plan 문서 두 곳을 고칩니다: 14 인계서의 시작 조건("12·13 뒤, 작업 폴더 따로 안 만듦" → 이 페이지에서 고른 방식), 13 인계서의 "14는 13 뒤" 문장. dev에 보낼 메시지도 다시 만듭니다.

4근거

  • dev compose.yaml: 맨 위 name: chaekcheck, DB 번호는 ${DB_PORT:-5432}·${TEST_DB_PORT:-5433}, 시험 DB는 tmpfs (2026-10-12 읽음)
  • dev application.yml: 저장소 맨 위 .env를 읽음(optional:file:../.env), DB 주소의 번호는 DB_PORT, 시험은 TEST_DB_PORT. 웹 vite.config.ts: 서버 주소는 API_PROXY_TARGET (2026-10-12 읽음)
  • Docker 공식 문서 "Specify a project name": 이름을 정하는 순서는 -p → COMPOSE_PROJECT_NAME → 파일의 name: → 폴더 이름. 프로젝트 이름으로 환경을 서로 떼어 놓음 (https://docs.docker.com/compose/how-tos/project-name/, 2026-10-12 확인)
  • Docker 공식 문서 "Pre-defined environment variables": 프로젝트 이름이 컨테이너 이름 앞에 붙음 (https://docs.docker.com/compose/how-tos/environment-variables/envvars/, 2026-10-12 확인). .env에 COMPOSE_PROJECT_NAME을 적어도 되는지는 그 문서에 분명한 문장이 없어 확인 못 함 → 그래서 -p를 늘 붙이는 쪽으로 제안
  • 저장 공간(볼륨) 이름에도 프로젝트 이름이 붙어 따로 생기는지는 공식 문서에서 확인 못 함 → 처음 켤 때 docker volume ls로 확인
  • 서비스 DB 크기 약 8.5GiB(dev 측정 2026-10-11, docs/research/deploy/aws-layout.md), 9,812MB(사이클 07 회고)
