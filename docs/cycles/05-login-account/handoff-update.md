- 인계서를 넘긴 뒤(커밋 `6116c3d`) 정해지거나 확인된 것만 모았습니다. 같은 내용이 `docs/current/handoff.md` 끝의 세 절("카카오 앱 등록에서 확인된 것", 네이버 등록 결과, "제공자별로 켜고 끄기")에도 들어 있습니다. 서로 다르면 `docs/current/handoff.md`가 기준입니다.

## 1. 새로 만들 것: 제공자별로 켜고 끄기 [확정] (사용자 승인, 2026-10-04)

네이버와 카카오를 둘 다 만드는 것은 그대로입니다. 설정이 하나 더 생깁니다.

| 항목 | 내용 | 태그 |
|---|---|---|
| 무엇 | 로그인 창에 보일 제공자를 서버 설정으로 고름 | [확정] |
| 설정 이름 | `chaekcheck.auth.providers` | [안] (dev가 정함) |
| 기본값 | 네이버·카카오 둘 다 켬 | [안] (dev가 정함) |
| 뺀 제공자 | 로그인 창에 버튼이 보이지 않음. 그 제공자의 로그인 시작·돌아올 주소가 동작하지 않음(404). 재인증 등록(`naver-reauth`, `kakao-reauth`)도 같음 | [확정] |
| 키 | 뺀 제공자의 키가 없어도 서버가 켜져야 함 | [확정] |
| 남은 제공자 | 로그인·가입·탈퇴가 그대로 동작 | [확정] |
| 웹 | 켜진 제공자를 아는 방법은 "로그인 기능이 켜져 있는지 아는 방법"과 함께 dev가 제안 | [안] |

- 어디에 넣나: 구현 단계 1(`chaekcheck.auth.enabled`를 만드는 단계)에서 함께 만듭니다. 이미 그 단계를 지났으면 그 설정 옆에 더합니다.
- 수용 기준(spec AC-22): 제공자 설정에서 뺀 제공자는 로그인 창에 버튼이 보이지 않고, 그 제공자의 로그인 시작·돌아올 주소는 동작하지 않는다(404). 남은 제공자의 로그인·탈퇴는 그대로 동작한다.
- 확인 방법: 제공자 하나만 켠 컨텍스트 테스트 + 웹 테스트.
- 제약 번호: `design-delta.md` "인계서에 넣을 제약" 38.
- 쓰임: 네이버는 검수를 통과해야 누구나 로그인할 수 있습니다. 검수 전에 공개하면 카카오만 켭니다.
- 이번에 다루지 않는 것 [확인 필요]: 이미 그 제공자로 가입한 계정이 있는데 제공자를 끄는 경우의 동작. 공개 전에 사용자에게 묻습니다.
- 근거: `design-delta.md` "로그인 기능 켜고 끄기", `docs/adr/0046-auth-feature-toggle.md` 덧붙임.

## 2. 풀린 [확인 필요] 항목

인계서 "개발 시작 전 확인"과 "[확인 필요] 항목" 표에서 아래는 답이 나왔습니다. 모두 사용자의 콘솔 화면에서 확인한 것입니다(2026-10-04). 자세한 것은 `research.md` 14절과 그 뒤.

| 항목 | 답 | 구현에 주는 영향 |
|---|---|---|
| 카카오가 돌아올 주소를 둘 이상 받는지 | 받음 | `kakao`, `kakao-reauth` 두 등록을 설계대로 씀 |
| 네이버가 돌아올 주소를 둘 이상 받는지 | 받음(최대 5개) | `naver`, `naver-reauth` 두 등록을 설계대로 씀 |
| 카카오 웹훅의 "대표 어드민 키"와 unlink의 어드민 키가 같은지 | 같음(어드민 키가 하나) | 환경 변수 하나 |
| 카카오 클라이언트 시크릿 | 켜져 있음 | 토큰 요청에 넣어야 함 |
| 네이버에서 제공 정보를 하나도 고르지 않아도 되는지 | 됨. 이용자 식별자는 기본으로 옴 | 동의 고지의 "항목"은 식별자만 |
| 카카오 동의 항목 | 모두 꺼 둠 | 받는 것은 회원번호뿐 |
| localhost 주소 등록 | 네이버·카카오 둘 다 받음 | 개발 중 그대로 시험 가능 |

## 3. 콘솔에 등록된 값

dev가 정한 redirect URI가 아래와 다르면 사용자에게 알려 주세요. 콘솔 값을 고칩니다.

| 제공자 | 등록된 값 |
|---|---|
| 카카오 리다이렉트 URI | `http://localhost:5173/api/v1/auth/login/oauth2/code/kakao`, `http://localhost:5173/api/v1/auth/login/oauth2/code/kakao-reauth` |
| 네이버 서비스 URL | `http://localhost:5173` |
| 네이버 Callback URL | `http://localhost:5173/api/v1/auth/login/oauth2/code/naver`, `http://localhost:5173/api/v1/auth/login/oauth2/code/naver-reauth` |

- 카카오 리다이렉트 URI의 등록 위치는 [앱] > [플랫폼 키] > REST API 키 수정 화면입니다(카카오 로그인 설정 화면이 아님).
- 카카오의 호출 허용 IP 주소는 비워 두었습니다. 비워 두면 모든 IP가 허용되는지는 문서에 문장이 없습니다 [확인 필요]. 첫 로그인 시험에서 `-401`이 나오는지 보고 알려 주세요.

## 4. 시험할 때 알아 둘 것

- 네이버 앱은 "개발 중" 상태입니다. 네이버의 멤버관리 탭에 등록한 아이디만 로그인됩니다. 다른 아이디로 시험해서 실패하면 코드 문제가 아닙니다. 앱을 만든 아이디가 멤버로 자동 등록되는지는 [확인 필요]입니다(사용자가 멤버관리 탭 확인).
- 카카오는 검수 없이 아무 계정으로나 로그인됩니다.
- 네이버 서비스 URL은 도메인만 비교합니다. 값이 실제 사이트와 다르면 로그인 때 "관리자 확인 필요"가 나옵니다.
- 연결 끊김 알림(카카오 연결 해제 웹훅, 네이버 연결 끊기 Callback URL)은 두 콘솔 모두 아직 등록하지 않았습니다. 제공자 서버가 우리 서버로 직접 보내는 요청이라 localhost로는 받을 수 없습니다. 받는 코드(9단계)는 그대로 만들고 직접 만든 요청으로 확인합니다(AC-13, AC-14). 실제 제공자 화면에서 끊어 보는 확인은 공개 주소가 생긴 뒤에 합니다. 인계서의 원래 계획과 같습니다.

## 5. 바뀌지 않은 것

- 구현 단계 1~17의 순서와 내용, 제약 C1~C32, AC-1~AC-21은 그대로입니다. 더해진 것은 위 1절(AC-22, 제약 38)뿐입니다.
- 네이버를 빼고 카카오만 만드는 것이 아닙니다. 둘 다 만듭니다.
