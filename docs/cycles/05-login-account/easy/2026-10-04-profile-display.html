별명과 프로필 사진을 받아 화면에 보여 주려면
앞서 정하신 것 셋이 바뀝니다.

ADR-0039 초안에 남기신 "닉네임과 프로필 사진 정보도 받았으면 하는데..... 화면에서 보여주게"에 대한 답입니다(2026-10-04). 받을 수는 있습니다. 다만 10월 1일에 정하신 것과 반대 방향이라, 무엇이 바뀌는지 먼저 보여 드리고 여쭙니다. 고르실 것은 셋입니다.

가지금까지 정하신 것과 달라지는 점

10월 1일에는 "회원번호만 받고, 화면에는 로그아웃 버튼만 보인다"로 정하셨습니다. 그때 하신 말: "그냥 로그인하면 '로그아웃'버튼이 보이게 한다던가 이런거면 안돼?"
지금 정해진 것별명과 사진을 받으면
네이버·카카오에서 받는 것회원번호만회원번호 + 별명 + 프로필 사진 주소
우리 DB에 저장하는 것계정 번호, 회원번호, 동의 기록여기에 별명과 사진 주소가 더해짐. 네이버·카카오 토큰을 저장하지 않으므로, 로그인할 때 받은 값을 저장해 두어야 화면에 보일 수 있음
가입 동의 화면의 "수집 항목"회원번호회원번호, 별명, 프로필 사진
로그인한 화면"로그아웃" 버튼만별명과 사진 + "로그아웃" 버튼
네이버·카카오 앱 설정제공 항목을 고르지 않음별명과 프로필 사진을 제공 항목으로 켬 (사용자가 하실 일)
화면 쪽 보안 헤더우리 주소의 그림만 허용네이버·카카오의 사진 서버 주소도 허용해야 사진이 보임. 정확한 주소는 확인이 필요함 [확인 못 함]

이미 정한 것 가운데 바뀌지 않는 것: 계정과 로그인 수단의 표 구조(ADR-0039), JWT, 탈퇴, 연결 끊김 알림. 탈퇴하면 별명과 사진 주소도 함께 지워집니다. 액세스 토큰에는 여전히 계정 번호만 넣습니다.

다정해 주실 것 (3가지)

첫째가 가장 큰 결정입니다. 받을지, 받는다면 언제 넣을지입니다.

1별명과 프로필 사진을 이번 사이클(로그인·계정)에 넣음 [안]

하고 싶다고 하신 대로 이번에 넣는 안입니다. 아직 서비스를 열기 전이라 기존 가입자가 없고, 네이버 검수도 받기 전입니다. 지금 넣으면 검수를 한 번만 받으면 되고, 가입 동의 화면과 처리방침도 처음부터 이 항목을 포함해 쓰면 됩니다.

이 안의 부담: 이번 사이클이 커집니다. 표에 칸 둘, 로그인할 때마다 값을 새로 고치는 처리, 화면 위쪽 표시, 동의 문구, 보안 헤더의 사진 주소 허용이 더해집니다. 명세·화면 흐름의 확정 문장 넷(받는 것, 저장하는 것, 로그인 표시, AC-5)을 고쳐야 합니다.

다른 선택 1: 다음 사이클(내 도서관)로 미룸. 이번 사이클은 정한 그대로 끝냅니다. 미루면 나중에 네이버 앱의 제공 항목을 바꾸게 되는데, 그때 검수를 다시 받아야 하는지는 확인하지 못했습니다 [확인 못 함]. 그 사이 가입한 사람은 다음 로그인 때 네이버·카카오가 추가 동의를 묻습니다.

다른 선택 2: 받지 않음(10월 1일 결정 그대로).

2받는 것은 별명과 프로필 사진 둘, 둘 다 "선택" 항목으로 [안]

사용자가 네이버·카카오 화면에서 이 둘의 제공을 거부해도 가입과 로그인은 됩니다. 그 사람에게는 사진과 별명 없이 "로그아웃" 버튼만 보입니다. 화면에 보이는 것 말고는 쓰는 곳이 없으므로 필수로 받을 이유가 없습니다.

다른 선택: 별명만 받음. 저장하는 것이 줄고, 보안 헤더에 다른 회사의 사진 서버 주소를 허용하지 않아도 됩니다. 사진 자리에는 별명 첫 글자를 넣은 동그라미를 보일 수 있습니다.

카카오: 닉네임과 프로필 사진은 "기본 제공" 동의항목. https://developers.kakao.com/docs/ko/kakaologin/utilize · 네이버 프로필 API 응답에 nickname, profile_image 있음: research.md 2절 (2026-10-04). 필요한 최소한을 넘는 정보에 동의하지 않는다는 이유로 서비스 제공을 거부하면 안 된다는 것은 개인정보 보호법 제16조의 내용으로 알고 있으나 이번에 원문을 다시 열어 확인하지 않았습니다.

3별명과 사진 주소는 로그인할 때마다 네이버·카카오의 값으로 새로 고쳐 저장하고, 화면 위 오른쪽에 보임 [안]

사용자가 네이버·카카오에서 별명이나 사진을 바꾸면 다음 로그인 때 우리 쪽에도 반영됩니다. 우리 서비스 안에서 별명을 따로 고치는 기능은 만들지 않습니다. 사진 파일은 우리 서버에 복사하지 않고, 네이버·카카오가 준 주소에서 브라우저가 직접 불러옵니다.

알아 두실 점: 로그인은 30일에 한 번이므로 바꾼 별명이 반영되기까지 최대 30일이 걸릴 수 있습니다. 사진 주소가 그 사이 바뀌거나 지워지면 사진이 안 보일 수 있고, 그때는 빈 동그라미를 보입니다.

다른 선택: 우리 서비스에서 직접 정하는 별명(네이버·카카오에서 받지 않음). 받는 정보가 늘지 않지만 별명을 정하는 화면을 새로 만들어야 합니다.

ADR-0039(로그인 수단 표 구조)는 이 결정과 상관없이 그대로 승인하실 수 있습니다. 넣기로 하시면 그 ADR의 "이메일·이름·제공자 토큰은 저장하지 않는다"에 "별명과 프로필 사진 주소는 저장한다"를 더해 다시 보여 드립니다. 원문: docs/cycles/05-login-account/spec.md "입력과 출력", flow.md S1.
