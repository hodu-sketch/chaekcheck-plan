지금은 배포도 도메인도 필요 없습니다.
앱 등록부터 하시면 됩니다.

네이버·카카오 로그인을 위해 하실 일을 순서대로 적었습니다(2026-10-04). 도메인은 서비스를 실제로 공개하기 직전에 필요해집니다. 등록은 개발자 계정으로 로그인해서 하는 일이라 제가 대신할 수 없습니다.

1배포해서 도메인을 받아야 하나

아니요. 만드는 동안에는 내 컴퓨터 주소(localhost)를 "돌아올 주소"로 등록해 씁니다. 도메인은 공개 준비 때 필요합니다.
무엇도메인 없이 되나근거
카카오: 돌아올 주소를 localhost로 등록됨카카오 공식 개발자 포럼(데브톡)에 http://localhost:8080 같은 주소를 등록해 쓰는 사례가 여럿 있음
네이버: 서비스 주소와 돌아올 주소를 localhost로 등록될 것으로 보임 [공식 문장은 확인 못 함]네이버 가이드에는 localhost에 관한 문장이 없음. 공개된 예제들은 http://localhost:8000으로 등록해 씀. 등록 화면에서 받아 주는지 직접 보셔야 함
네이버·카카오가 우리 서버로 보내는 "연결 끊김" 알림안 됨네이버·카카오의 서버가 내 컴퓨터로는 들어올 수 없음. 그동안은 dev가 직접 만든 요청으로 시험함
네이버 검수서비스를 열기 전이면 기획서로 신청할 수 있음네이버 검수 가이드 (research.md, 2026-10-01 확인)

localhost와 127.0.0.1은 네이버·카카오가 보기에 서로 다른 주소입니다. 둘 중 하나로 정해 그대로 등록해야 합니다.

2네이버에서 하실 일

네이버 개발자센터(developers.naver.com)에서 애플리케이션을 하나 등록합니다. 검수 전에는 등록해 둔 아이디만 로그인됩니다.
순서할 일적을 것, 볼 것
1애플리케이션 등록이름은 chaekcheck(로그인 동의 화면에 보임). 사용 API로 "네이버 로그인"을 고름
2제공 정보 고르기아무것도 고르지 않습니다. 이때 화면을 봐 주세요: 아무것도 안 골라도 등록이 되는지, 회원번호 말고 별명 같은 것이 강제로 붙는지
3환경 추가: PC 웹서비스 URL과 Callback URL(돌아올 주소). Callback URL을 두 줄 넣어 봅니다: 로그인용, 탈퇴 본인 확인용
4키 받기Client ID와 Client Secret
5테스터 등록"멤버 관리"에 시험할 네이버 아이디를 넣음. 검수 전에는 여기 등록한 아이디만 로그인됨

나중에 (공개 준비 때)

할 일설명
실제 주소 더하기서비스 URL과 Callback URL에 도메인 주소를 넣음
연결끊기 Callback URL 등록사용자가 네이버에서 연결을 끊으면 네이버가 알려 주는 주소. API 설정에 있음
검수 신청로그인부터 가입까지의 화면 캡처나 기획서를 냄. 2~3 영업일. 통과해야 누구나 로그인됨

3카카오에서 하실 일

카카오 디벨로퍼스(developers.kakao.com)에서 앱을 하나 만듭니다. 카카오 로그인은 검수가 없고, 사업자 등록도 필요 없습니다.
순서할 일적을 것, 볼 것
1앱 만들기앱 이름 chaekcheck, 회사명 chaekcheck(개인은 서비스 이름을 넣어도 됨. 동의 화면에 보임), 카테고리
2카카오 로그인 켜기[카카오 로그인] 설정에서 상태를 ON으로. 안 켜면 로그인 요청이 오류(KOE004)가 남
3Redirect URI(돌아올 주소) 등록두 줄 넣어 봅니다: 로그인용, 탈퇴 본인 확인용
4동의항목아무것도 켜지 않습니다. 회원번호만 받습니다
5키 받기REST API 키, Client Secret(켜져 있는지 확인), 어드민 키. 어드민 키가 "대표"와 "서비스 앱" 둘로 나뉘어 보이면 같은 값인지 봐 주세요

나중에 (공개 준비 때)

할 일설명
실제 주소 더하기Redirect URI에 도메인 주소를 넣음
연결 해제 웹훅 등록사용자가 카카오에서 연결을 끊으면 카카오가 알려 주는 주소. 등록할 때 방식을 고를 수 있으면 POST로
개인정보 처리방침 주소 등록우리 /privacy 화면의 실제 주소

4돌아올 주소는 무엇을 넣나

정확한 글자는 dev가 만들어 드립니다. 한 글자라도 다르면 로그인이 안 되기 때문입니다.

모양은 이렇습니다. 앞부분(주소와 포트)은 dev가 개발 환경에 맞춰 정합니다.

로그인용탈퇴 본인 확인용
네이버…/api/v1/auth/login/oauth2/code/naver…/api/v1/auth/login/oauth2/code/naver-reauth
카카오…/api/v1/auth/login/oauth2/code/kakao…/api/v1/auth/login/oauth2/code/kakao-reauth

그래서 순서는 둘 중 하나입니다. 먼저 앱을 만들어 키만 받아 두고 돌아올 주소는 dev가 알려 준 뒤에 넣거나, dev에게 주소를 먼저 받은 다음 한 번에 등록합니다. 어느 쪽이든 됩니다.

5키를 다루는 법

키와 시크릿은 dev 프로젝트의 환경 변수 파일에만 넣습니다. 대화창, 코드, 저장소에는 적지 않습니다.
받는 값어디서새면 생기는 일
네이버 Client ID, Client Secret네이버 애플리케이션 정보남이 우리 서비스인 척 로그인을 받을 수 있음
카카오 REST API 키, Client Secret카카오 앱 키 화면같음
카카오 어드민 키카카오 앱 키 화면남이 우리 사용자의 연결을 끊거나 사용자 목록을 볼 수 있음. 가장 조심할 값

dev 프로젝트에는 저장소에 올라가지 않는 환경 변수 파일(.env)을 쓰는 방식이 이미 있습니다. 값을 어디에 어떤 이름으로 넣는지는 dev가 안내합니다. Claude에게 키 값을 대화로 보내지 마세요.

6dev에 알려 주실 것

등록하면서 본 것 셋을 알려 주시면 설계의 "확인 필요"가 풀립니다.
알려 줄 것왜 필요한가
돌아올 주소 두 줄이 네이버와 카카오에서 각각 받아졌는지한 줄만 받는 곳이 있으면 그 제공자는 탈퇴 본인 확인을 다른 방식으로 만듦
네이버에서 제공 정보를 하나도 안 골랐을 때 화면이 어땠는지가입 동의 화면의 "수집 항목" 문구가 이것에 달려 있음
카카오 어드민 키가 하나인지 둘인지둘이면 서버 설정에 값을 둘 넣어야 함
