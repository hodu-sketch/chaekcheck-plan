회원은 "내 도서관"을 서버에 저장하려고 둡니다.
필터는 스위치 하나면 됩니다.

시리즈 5장. 아직 사이클이 아니라 밑그림 [안]입니다. 값과 이름은 /cycle-start 회원에서 정합니다. 보안·개인정보는 앞서 보낸 별도 페이지(근거 signup-security.md)에 있습니다.

1왜 회원인가 (사용자 말)

지금은 브라우저가 지역을 들고 있습니다. 회원은 그것을 서버에 저장하고, 지역과 상관없는 "직접 고른 도서관"을 더하는 것입니다.
  • "회원이 있는 이유는 직장/거주지 지역이라던가 알아서 도서관 매핑해주기 위함이야"
  • "본인 거주지/지역과 상관없이 특정 도서관도 '내 도서관'에 넣는 거 생각 중이야"
  • "'내 도서관' 자료만 찾을 수 있는 거지"

2저장하는 것은 셋뿐입니다

비밀번호·이메일·이름은 받지 않습니다. 적게 받을수록 지켜야 할 것도 줄어듭니다(보안 페이지 카드 4).
무엇값비고
소셜 계정제공자(네이버/카카오) + 그쪽이 준 번호이 둘이 회원의 열쇠. 두 제공자 번호가 같은 사람인지는 알 수 없음
지역 자격거주지·직장 시군구 코드 (여러 줄)지금 브라우저가 들고 있는 값과 같은 모양
내 도서관직접 고른 도서관 id 목록지역과 무관하게 추가

새 모듈 member [안]. 지역 코드와 도서관 id만 저장하고, 도서관 이름·자격은 기존 library 모듈의 공개 API로 읽습니다(모듈끼리 표를 직접 합치지 않음, ADR-0001).

3"내 도서관" = 자동 매핑 + 직접 추가

하나의 목록으로 보이고, 줄마다 "지역으로 자동" / "직접 추가" 표시만 다릅니다. 자동 매핑은 지금 검색이 쓰는 가입 가능 판정(ADR-0013·0027)을 그대로 씁니다.

4검색 필터: 스위치 하나를 추천합니다

사용자 질문: "'내가 가입할 수 있는 도서관' '내가 설정한 도서관' 이렇게 필터링을 해야 할까.. 난 좀 단순했으면 하는데". 답: "내 도서관만 / 전체" 하나만 두면 됩니다.

나쁜 점직접 고른 곳만 보려면 설정 창의 내 도서관 목록에서 봐야 함기존 "방문 없이 가입" 필터까지 세 겹. 직접 고른 곳이 없으면 빈 필터가 생김

안 A에서 로그인 전에는 지금처럼 지역 기준 "가입 가능한 곳", 로그인 후에는 같은 자리가 "내 도서관만"이 됩니다. "방문 없이 가입" 필터는 그대로 둡니다.

5회원 사이클에서 정할 것

밑그림에 남긴 질문입니다. 사이클을 시작할 때 하나씩 묻습니다.
  • 자동 매핑된 도서관을 목록에서 뺄 수 있게 할지
  • 로그인 후 기본 필터를 "내 도서관만"으로 할지
  • 직접 추가한 도서관을 결과 정렬(가입 단계)에서 어디에 둘지
  • 만 14세 미만 정책, 운영자가 소상공인에 해당하는지 (보안 페이지)
  • 네이버·카카오가 PKCE를 지원하는지 → 실제 요청으로 시험

6알림: 세 조각이 필요합니다

"원하는 책이 빌릴 수 있게 되면 알림"에는 관심 책 저장, 상태 변화를 아는 방법, 전달 수단이 필요합니다. 두 번째와 세 번째에 미리 알아 둘 제약이 있습니다.
  • 관심 책 저장회원이 책에 표시해 두면 회원 모듈이 책 번호만 저장합니다 [안].
  • "빌릴 수 있게 됨"을 아는 방법 확인 필요지금은 사용자가 검색할 때만 도서관 페이지를 읽습니다. 알림은 사용자가 없을 때 서버가 스스로 확인해야 합니다. (가) 관심 책이 있는 도서관 페이지를 주기적으로 읽기 → 도서관 사이트 요청 예의(같은 호스트 1초 간격)와 요청 수가 문제. (나) 책 목록 주기 갱신과 합치기 → 갱신은 소장 목록이지 대출 상태가 아닐 수 있음. 또 "새로 들어옴(입고)"과 "반납돼서 빌릴 수 있음"은 다른 신호라 어느 쪽인지 물어야 합니다.
  • 전달 수단 제약이메일·카카오 메시지·웹 푸시 중 무엇을 쓸지 정해야 합니다. 카카오 이메일 동의는 비즈 앱(사업자 정보) 전용이라 개인·비영리는 못 받을 수 있습니다 [확정, 공식 문서]. 연락처를 받으면 수집 항목이 바뀌어 회원에게 다시 동의를 받아야 합니다. 그래서 회원 사이클에서는 연락처를 받지 않는 것이 밑그림입니다.
