책은 "모으고 → 정리하고 → 같은 책끼리 묶는" 세 단계로 다룹니다.

시리즈 4장. 도서관 사이트에서 전자책 목록을 모으는 방법(수집), 제목·저자·출판사를 고르게 만드는 규칙(정리), 여러 도서관의 같은 책을 한 권으로 보는 규칙(묶기)과 그 결정(ADR-0035)을 설명합니다.

1전체 흐름

수집은 plan 문서(수집 세션 관리)와 별도 폴더의 파이썬 도구가, 정리·묶기는 dev의 Java 코드가 합니다. 규칙 문서는 plan에 있고 실제 동작은 dev 코드입니다.

2① 수집: 어떻게 모으나

같은 사이트에는 한 번에 한 건, 1초 넘게 간격을 두고 요청합니다. 소개글은 저장하지 않고 표지 주소만 둡니다. 수량(대출·예약)은 저장하지 않고 사용자가 볼 때 실시간으로 읽습니다.
  • 전체 수집과 신간 수집전체는 주 1회, 신간은 매일이 계획입니다 [확정]. 단, 큰 교보 구독형 16곳은 한 번에 2~3일이 걸려 신간 위주로 하자는 안이 있습니다. 세부는 주기 갱신 사이클에서 정합니다.
  • 어디까지 받았나는 문서에 없습니다python scripts\crawl_catalog.py status로만 알 수 있습니다. 받지 않는 도서관 4곳(국회 44, 전북교육청 135, 군포 261, 김천 269)은 crawl-runbook.md 5-1절.
  • 서비스로 가져올 때 빼는 것오디오북·동영상북, 서비스 도서관 목록에 없는 기관, 빠진 책, 상세 주소가 없거나 다른 호스트인 줄. dry run 기준 읽은 3,773,137줄 중 1,217,651줄을 뺐습니다(대부분 서비스에 없는 기관).

3② 정리: 사이클 04에서 바뀐 두 가지

정리는 원문을 두고 옆에 "정리한 값"을 만드는 것입니다. 검색어에도 같은 규칙을 적용해서 "행동 경제학"과 "행동경제학"이 같이 찾힙니다. 개발 중 저자 규칙과 자료 종류가 바뀌었습니다.
  • 저자 나누기: 쉼표 항목마다 역할을 읽습니다수집한 저자 칸에 "그레타 가드 저자, 김현미 번역, 노고운 번역"처럼 쉼표마다 역할이 붙은 줄이 90,816개 있었습니다. 이제 항목마다 역할을 읽고, 역할이 없는 항목은 뒤 항목의 역할을 받습니다("A, B 공저" → 둘 다 지은이). "역자·번역"은 옮긴이로, "공편·편자·편집"은 엮은이로 읽습니다. 편집부·위원회 같은 단체 이름(79,649줄)은 그냥 저자로 둡니다.
  • 자료 종류: 전자책만이 아니라 넷을 넣습니다처음 안은 전자책(EBOOK)만이었는데, 사용자 결정으로 키즈북(KIDS_BOOK 3,003줄), 종류 미상(UNKNOWN 391줄), 학술논문(PAPER 74줄)도 넣습니다. 소장마다 원래 종류를 적고, 책의 종류는 소장들 중 가장 많은 종류로 합니다.
  • 바뀌지 않은 규칙제목은 NFKC·소문자·공백 제거. 본제목은 첫 " : " 또는 " - " 앞. 출판사는 (주)·주식회사·도서출판 제거. 출판일은 가장 많이 나온 날짜, 같으면 이른 것, 미래 날짜는 오류로 봄.

6ADR-0035: 왜 ④를 넣었고, 무엇을 감수하나

인계서는 "④는 이번에 안 함"이었는데, 같은 작품이 네 권으로 갈라지는 것을 보고 사용자가 넣기로 했습니다. 판 표시가 없는 개정판이 원판과 합쳐지는 것을 감수합니다.
  • 무슨 문제였나「작별하지 않는다」(한강, 문학동네) 소장 98줄이 ①~③ 뒤에도 4권으로 남았습니다. 교보 ISBN 74줄, YES24 번호 22줄, 강남구 1줄, YES24 다른 번호 1줄. 국가서지에 이 책의 판이 여럿이라 ③으로도 못 합쳤습니다.
  • 무엇을 정했나정리한 전체 제목(괄호 속 "(개정판)" 같은 판 표시까지 포함) + 첫 저자 + 정리한 출판사가 같으면 한 권. 사용자: "전체 제목+저자+출판사까지 같으면 합침 (추천) 이걸로 해줘". 그 전에 사용자가 물은 것: "판마다 전자책 내용이 달라질 수 있지 않아?"
  • "전체 제목"에는 부제도 들어갑니다도서관 사이트가 제목 칸에 적은 글자 전부입니다. 본제목, 부제(" : "이나 " - " 뒤), 괄호 속 판 표시, 맨 앞 시리즈 표시, 권 번호가 다 들어가고 떼어내는 것이 없습니다. 비교 전에 하는 정리는 문자 통일·영문 소문자·공백 제거뿐입니다. (2026-10-03 추가, dev 코드로 확인)

  • 다른 선택지는 무엇이었나B: ①~③만(인계서 원안) → 같은 작품이 플랫폼별로 따로 나옴. C: 본제목으로 묶기 → 부제만 다른 해설서·개정판까지 다 합쳐짐. 사용자에게 제시된 선택지가 "전체 제목"이었고, B·C를 고르지 않은 이유는 따로 말하지 않았습니다 [이유 미확인].
  • 감수하는 것두 방향입니다. 덜 합쳐지는 쪽: 같은 책인데 도서관마다 부제나 시리즈 표시를 적은 방식이 다르면 따로 남습니다(번호 체계가 다른 플랫폼 사이에서만, 몇 권인지는 세지 않음). 잘못 합쳐지는 쪽: 제목에 판 표시가 없는 개정판은 원판과 합쳐집니다. 합친 책 중 대표 출판일이 2년 넘게 차이 나는 책이 11,019권인데, 표본 40개는 대부분 등록일 차이였고 「마녀 프레임」「악플 전쟁」「1984년」처럼 판이 다를 수 있는 예도 있습니다 [확인 필요: 표본 조사].
  • 되돌리려면원문이 보관돼 있으니 ④를 끄고 다시 가져오면 됩니다(표를 비우고 다시 채움). 단, 책 번호가 바뀌어 공유한 책 주소(/books/{bookId})가 깨지므로, 주기 갱신 사이클의 번호 유지 장치와 같이 봐야 합니다.
