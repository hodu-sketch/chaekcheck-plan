3다음: 사이클 05 후보

사이클 04에서 "이번에 하지 않는 것"으로 뺀 것들이 가장 가까운 후보입니다. 고르는 것은 회고(/cycle-start) 때 정합니다.
  • 책 목록 주기 갱신 별도 사이클 확정지금 책 목록은 한 번 가져온 것이라 시간이 지나면 도서관 실제 소장과 달라집니다. 주기적으로 다시 모으고, ISBN·서지를 새로 받고, 같은 책 묶기를 다시 계산합니다. 목록이 오래됐다는 경고 기준도 여기서 정합니다.
    • 참고 문서: docs/research/ebook-catalog/catalog-refresh.md
    • 사이클 04에서 정한 "도서관 번호 체계 점검"(카드 4의 3번)도 이 갱신과 같이 돌리기로 했습니다.
  • 정렬 옵션제목 가나다순, 보유 도서관 많은 순, 가입 가능 도서관 책 먼저, 대출 가능 많은 순입니다. 사용자: "정렬은 다른 cycle로 빼자 복잡하다"
  • 수집 목록에만 있는 기관대학·기업·학교 전자도서관, 북큐브 도서관처럼 책 목록에는 있지만 서비스 도서관 목록에는 없는 곳입니다. 읽는 코드가 없는 화면 7종(경남교육청, 서울도서관, 북큐브 등)의 adapter와 이어집니다.
  • 운영에 올리기호스팅을 정하고, 그 호스팅이 pg_bigm의 shared_preload_libraries 설정을 허용하는지 확인합니다. 가져온 책 목록을 운영 DB로 옮기는 방법은 아직 사용자 결정 대기입니다. 저작권법 제93조·부정경쟁방지법 위험은 출시 전 전문가 확인으로 남아 있습니다.
  • 검색 품질오타 보정, "행동하는"으로 "행동" 찾기, 감수·기획·사진 같은 역할 검색, 표지·소개 표시입니다.

제안 가져오기에 실제로 걸린 시간과 책 수를 본 뒤 고르는 편이 낫습니다. 주기 갱신을 얼마나 자주 돌릴 수 있는지가 그 수치에 달려 있습니다.

4곧: plan에서 사이클 04 회고

plan에서 /cycle-start를 실행하면, dev docs/plan-feedback.md의 # 사이클 04 절과 dev 코드를 대조해 retro.md를 쓰고 docs/current/를 실제 코드에 맞춥니다.

docs/current에 반영할 것: dev가 인계서와 다르게 만든 것

  • 1. 가져오는 자료 종류를 넓혔습니다책 종류가 EBOOK만이었는데 KIDS_BOOK(3,003줄), UNKNOWN(391줄), PAPER(74줄)도 넣습니다. 소장마다 원래 종류를 적는 holding.content_type 칸이 새로 생겼습니다. 사용자 결정입니다.
  • 2. 같은 책 묶기에 4단계를 더했습니다제목 전체(괄호 속 판 표시 포함)·첫 저자·출판사가 모두 같으면 한 권으로 합칩니다. 인계서에서는 "이번에 하지 않음"이었습니다. 사용자: "전체 제목+저자+출판사까지 같으면 합침 (추천) 이걸로 해줘"
    • dry run에서 책 수가 784,994권 → 648,267권으로 줄었습니다.
    • 합친 책 중 11,019권은 출판일이 2년 넘게 벌어집니다. 판이 다른 책이 섞였는지는 확인하지 않았습니다 확인 필요
    • 제목에 판 표시가 없는 개정판은 원판과 합쳐집니다(알려진 한계).
  • 3. 어느 도서관끼리 책 번호를 같이 보는지 정했습니다교보·교보 구독형·YES24(V1~V3)는 같은 번호면 같은 책으로 봅니다. 통합 포털과 강남구 번호는 그 도서관 안에서만 씁니다(도서관마다 같은 번호에 다른 책이 붙어 있었음).
    • 사용자: "코드 규칙은 언제든지 달라질 수 있으니 도서관 목록 확인할 때 같이 점검하는 걸로 하면 좋을거 같아"
    • dev의 부탁: 이 기준을 design-delta와 research same-book-isbn.md 5절에 적고, 도서관 목록 점검 절차에 넣기.
    • 비율이 얼마나 바뀌면 기준을 바꿀지는 정하지 않았습니다.
  • 4. 저자 나누는 규칙을 보완했습니다수집 데이터에 "그레타 가드 저자, 김현미 번역, 노고운 번역"처럼 쉼표마다 역할이 붙은 모양이 많았습니다. 이제 쉼표로 나눈 항목마다 역할을 읽고, 역할이 없는 항목은 뒤 항목의 역할을 받습니다. 역자·번역은 옮긴이로, 공편·편자·편집은 엮은이로 읽습니다.
  • 5. dev가 스스로 정한 것
    • 채우지 않은 칸의 완전 일치, 저자 칸이 없을 때의 역할 선택은 오류 없이 무시합니다.
    • 소장 스트림의 첫 이벤트에는 계획 전체가 아니라 그 책을 가진 도서관만 담습니다.
    • 도서관의 수집 완료 시각이 없으면 그 도서관 소장 중 가장 늦게 본 시각으로 "○월 ○일 기준"을 표시합니다.
    • 바로 보기·책 화면에는 도서관 요약 줄이 없습니다(상세 페이지에는 대출률이 없어서).
    • 국가서지 파일은 저장소 안 data/nlk/에 둡니다(git 제외, 사용자 결정).

5지금: dev에서 사이클 04 끝내기

코드는 다 있고, 실제 데이터로 돌리는 세 가지가 남았습니다. 사용자가 "코드까지 만들고 실행은 나중에 알려 줄 때"를 골라서 멈춰 둔 상태입니다.
  • 0. 먼저 확인할 것
    • 전자책 목록 수집 세션이 쉬고 있는지. 가져오기는 수집 SQLite 파일을 읽으므로 수집이 쉴 때 돌립니다.
    • WSL이 켜져 있는지. WSL은 마지막 프로세스가 끝나면 몇 초 뒤 꺼지고, 그러면 DB가 내려갑니다.
  • 1. 실제 가져오기 (인계서 5단계 마지막)dev backend/에서 실행합니다. 
    ./gradlew bootRun --args='--spring.profiles.active=catalog-import --chaekcheck.catalog.import.sqlite-path=../../chaekcheck-data/ebook-catalog.sqlite --chaekcheck.catalog.import.ttl-path=../data/nlk/ttl'
    • 개발 DB의 책 목록을 비우고 새로 채웁니다. 화면 확인용으로 넣어 둔 4권은 지워집니다.
    • 끝나면 요약 로그가 나옵니다: 읽은 줄, 이유별 건너뛴 줄, 묶기 단계별 책 수, 최종 책·소장·저자 수, 걸린 시간, 인덱스 크기.
    • dry run 기준으로 책은 약 648,267권이 나와야 합니다.
  • 2. 검색 속도 재기 (인계서 6단계)EXPLAIN (ANALYZE, BUFFERS)로 검색어 7가지를 잽니다: "행동", "사랑", "행동"+"새폴스키", "사랑"+"문학동네", "사랑" 최신순, 전체 건수 세기, "행동 의"(한 글자 단어가 섞인 경우).
  • 3. AC-1~14 확인 (인계서 14단계)실제 도서관 사이트 요청은 손으로 적게, 1초 간격을 지켜 보냅니다.
    • 검색 결과가 맞는지: AC-2~6 ("행동"+"새폴스키"면 「행동」만, 띄어쓰기, 완전 일치, 옮긴이 켜기, 정렬 순서)
    • 도서관에 보내는 요청이 맞는지: AC-7·8·13 (그 책을 가진 도서관의 상세 페이지만, 화면 종류 7개 읽기, 간격·User-Agent)
    • 화면 동작: AC-1·9·11·12·14 (검색 칸, 0건일 때 직접 찾기, 새로고침 뒤 유지, 지역·범위 반영, 책 먼저 고르기)
    • 데이터: AC-10 (빠진 책·오디오북·동영상북이 없는지)
  • 4. 결과를 dev docs/plan-feedback.md에 적기# 사이클 04 절의 "측정 (아직)" 목록을 채웁니다. 함께 볼 표본: 출판일이 2년 넘게 벌어진 11,019권, 48090…·확인 숫자가 안 맞는 교보 코드 수, 국가서지와 제목이 다른 약 5%, YES24 재수집 뒤 수치. 이 절이 카드 4 회고의 입력이 됩니다.
