비밀번호를 안 받아도
회원을 두면 지켜야 할 것이 생깁니다.

네이버·카카오 로그인만 쓰고, 저장하는 것은 소셜 계정 번호와 거주지·직장 시군구 코드, 내 도서관 목록뿐입니다. 그래도 아래 여섯 가지는 해야 합니다. 모두 공식 문서에서 2026-10-01에 확인한 내용이고, 확인 못 한 것은 따로 표시했습니다.

1해야 할 일은 여섯 가지입니다

비밀번호가 없으니 "비밀번호 암호화" 의무는 없습니다. 대신 로그인 연결, 세션, 동의·처리방침, 탈퇴, 검수, 서버 관리가 남습니다.

2① 로그인 연결: 회원을 어떻게 알아보나

회원의 열쇠는 "제공자 + 제공자가 준 번호" 둘뿐입니다. 이메일로 사람을 알아보지 않습니다.
  • 네이버와 카카오는 앱마다 다른 번호를 줍니다같은 사람이라도 다른 서비스에서는 다른 번호입니다. 그래서 chaekcheck 안에서만 쓰는 번호로 저장하고, 밖으로 보이지 않게 합니다. 네이버 번호와 카카오 번호가 같은 사람인지는 알 수 없습니다. 네이버 profile.md, 카카오 kakaologin/common
  • 이메일은 열쇠로 쓰지 않습니다카카오 공식 문서가 "이메일은 사용자가 바꿀 수 있으니 같은 사람 판단에 쓰지 말라"고 합니다. 이메일 자체를 안 받는 것이 가장 단순합니다. 카카오 kakaologin/utilize
  • 로그인 요청에 state 값을 붙입니다다른 사이트가 사용자 몰래 로그인 요청을 보내는 것(CSRF)을 막는 값입니다. 네이버는 필수, 카카오는 권장입니다. Spring Security의 oauth2Login()이 자동으로 만들고 확인하므로 끄지만 않으면 됩니다. 네이버 devguide.md, 카카오 rest-api, Spring Security 문서
  • PKCE는 시험해 봐야 합니다 확인 필요인터넷 표준(RFC 9700)은 모든 로그인에 PKCE라는 추가 확인을 강력히 권장합니다. 그런데 네이버·카카오 문서에 지원한다는 말이 없습니다. 실제로 요청을 보내 보고, 되면 Spring의 requireProofKey를 켭니다.

3② 세션 쿠키: 로그인 상태를 어떻게 유지하나

서버가 세션을 갖고, 브라우저에는 쿠키 하나만 둡니다. 쿠키에 세 가지 표시를 붙이고, 로그인할 때마다 세션 번호를 새로 만듭니다.
할 것뜻근거
쿠키에 Secure, HttpOnly, SameSiteHTTPS로만 보내고, 페이지 스크립트가 못 읽고, 다른 사이트에서 온 요청에는 안 붙입니다OWASP 세션 관리, NIST 800-63B
로그인하면 세션 번호를 새로 발급로그인 전 번호를 누가 알고 있어도 소용없게 합니다. Spring 기본값(changeSessionId)이 이미 이렇게 합니다OWASP, ASVS 5.0 7.2.4

4③ 동의와 처리방침: 법이 요구하는 최소

시군구 코드도 계정과 묶이면 개인정보로 봅니다. 그래서 가입 때 네 가지를 알리고 동의를 받고, 처리방침을 사이트에 늘 걸어 둡니다.
  • 가입 화면에서 알릴 네 가지목적, 항목, 보유·이용 기간, 거부할 권리와 거부 시 불이익. 이 넷을 적고 동의 표시를 받습니다. 개인정보 보호법 제15조 제2항입니다. 선택 항목을 안 했다고 서비스를 거부하면 안 됩니다(제16조 제3항).
  • 처리방침을 사이트에 상시 게재무엇을 왜 모으고 언제 지우는지, 정보주체의 권리, 책임자 연락처를 적습니다(제30조, 시행령 제31조). 카카오는 앱 설정에 이 페이지 주소를 등록해야 합니다.
  • 꼭 필요한 것만 받습니다"최소한만 받았다"는 것을 증명할 책임이 운영자에게 있습니다(제16조 제1항). 그래서 네이버·카카오에도 이름·이메일 같은 추가 항목을 요청하지 않습니다.
  • 만 14세 미만은 보호자 동의가 필요합니다 정할 것나이를 안 받으면 확인할 방법이 없습니다(제22조의2). "만 14세 이상입니다" 확인란을 둘지는 회원 사이클에서 정합니다.
  • 시군구 코드가 개인정보인지 확인 필요법 제2조는 "다른 정보와 쉽게 결합해 알아볼 수 있는 정보"도 개인정보로 봅니다. 계정과 묶인 시군구 코드는 그렇게 보고 다루는 것이 안전합니다. 다만 개인정보보호위원회의 명시적 해석은 찾지 못했습니다.

5④ 탈퇴: 지우는 순서가 정해져 있습니다

탈퇴하면 카카오·네이버에 "연결 끊기"를 알리고, 회원 정보를 바로 완전히 지우고, 세션을 모두 끊습니다. 카카오 쪽에서 먼저 끊으면 우리 서버가 3초 안에 답해야 합니다.
  • "나중에 복구할 수 있게" 남겨 두지 않습니다개인정보 보호법 제21조는 필요 없어지면 지체 없이, 복구할 수 없게 지우라고 합니다. 카카오 운영정책도 탈퇴 시 모든 개인정보 파기를 요구합니다. 가입을 시작했다가 끝내지 않은 사람의 임시 정보는 24시간 안에 지웁니다. 카카오 운영정책 제1조 제2항(시행 2026-04-20)
  • 카카오가 보내는 "연결 해제" 알림에 3초 안에 답합니다사용자가 카카오 쪽에서 chaekcheck 연결을 끊으면 카카오가 우리 서버 주소로 알립니다. 그 알림을 받는 주소를 만들어 두고, 위 세 단계를 한 뒤 HTTP 200으로 답합니다. 카카오 kakaologin/callback

6⑤ 정식 오픈 전 검수: 알림 사이클에 영향이 큽니다

네이버는 검수를 통과해야 누구나 로그인할 수 있습니다. 카카오는 로그인 자체에 검수나 사업자등록이 필요 없습니다. 이메일을 받으려면 "비즈 앱"이어야 하는데, 개인도 본인인증으로 "개인 개발자 비즈 앱"이 될 수 있습니다(2026-10-03 정정).
  • 네이버 검수검수 전에는 등록한 테스트 계정만 로그인됩니다. 검수 항목은 서비스 내용, 로그인 흐름(가입할 때 비밀번호를 따로 요구하면 안 됨), 받은 정보를 어디에 쓰는지, 로그인 버튼 모양입니다. 네이버 verify.md
  • 카카오 이메일은 비즈 앱에서 전환 뒤 확인이메일 동의 항목은 비즈 앱과 테스트 앱에서만 켤 수 있습니다. 사업자등록번호가 없어도 앱 소유자의 카카오계정 본인인증과 약관 동의로 "개인 개발자 비즈 앱"으로 전환할 수 있습니다(2026-10-03 확인). 다만 그 앱에서 이메일 필수 동의가 켜지는지는 문서에 없어서, 전환한 뒤 동의항목 화면에서 확인해야 합니다. 카카오 app-setting/app, kakaologin/prerequisite
  • 연락처를 받으면 동의를 다시 받습니다이메일이나 카카오 메시지 채널을 나중에 추가하면 수집 항목과 목적이 바뀌므로 회원에게 다시 동의를 받습니다(제15조 제2항). 그래서 회원 사이클에서는 연락처를 받지 않는 것이 밑그림입니다.

7⑥ 서버 관리: 고시가 정한 최소 조치

개인정보의 안전성 확보조치 기준(개인정보보호위원회 고시 제2026-9호, 시행 2026-07-01)이 기준입니다. 1인 운영·1만 명 미만이면 서류(내부 관리계획)는 생략할 수 있지만, 아래 조치는 해야 합니다.

왜 지켜야 하나

  • 유출되면 과징금과 배상이 있습니다매출액의 3% 이하, 매출이 없으면 20억 원 이하 과징금(제64조의2)과 1인당 300만 원 이하 법정손해배상(제39조의2)입니다. 다만 "제29조 안전조치를 다한 경우"는 과징금 대상에서 빠집니다. 위 표를 지켰다는 기록이 곧 방어입니다.
  • 보호책임자는 운영자 본인입니다 확인 필요소상공인이면 따로 지정하지 않아도 대표자가 자동으로 책임자입니다(제31조 제2항). 처리방침에 이름과 연락처를 적습니다. 비영리 1인 운영이 「소상공인기본법」의 소상공인에 해당하는지는 사업자 형태에 달려 있어 확인이 필요합니다.

8확인하지 못한 것

아래는 공식 문서에서 찾지 못했거나 직접 시험해야 알 수 있는 것입니다. 회원 사이클을 시작할 때 처리합니다.
  • 네이버·카카오가 PKCE를 지원하는지 → 실제 요청으로 시험
  • 네이버 refresh token이 얼마나 오래 유효한지 → 문서에 수치 없음, 시험 또는 문의
  • 개인 개발자 비즈 앱에서 이메일 필수 동의가 켜지는지 → 전환한 뒤 동의항목 화면에서 확인 (사업자등록번호 없이 전환되는 것은 2026-10-03에 확인)
  • 시군구 코드가 개인정보인지에 대한 개인정보보호위원회의 명시 해석 → 해석례 원문 또는 문의
  • 운영자가 소상공인에 해당하는지 → 사업자 형태를 알아야 함
  • developers.naver.com 사이트는 도구에서 열리지 않아 네이버 공식 GitHub 문서로 확인했습니다. 사이트 최신본과 같은지 한 번 직접 보는 것이 좋습니다
