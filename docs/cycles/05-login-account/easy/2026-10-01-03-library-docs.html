도서관 목록은 dev 문서 한 권으로
다시 만들 수 있습니다.

시리즈 3장. "도서관 목록을 어디서 얻고, 화면 종류와 가입 자격을 어떻게 나누는가"는 dev docs/library-maintenance.md가 절차 원본입니다. 이 페이지는 그 절차를 풀어 쓴 것입니다.

1도서관 목록은 네 곳에서 모읍니다

공식 전체 목록은 없습니다. 네 출처를 합친 뒤, 사이트가 살아 있는지 도구로 확인해 넣습니다.
  • 결과는 seed 파일에 들어갑니다켜진 도서관 278곳(2026-09-29). 도서관 한 줄 = 전자도서관 사이트 하나(ADR-0017). 꺼 둔 곳은 id 59 대구학생, id 131 서구 통합(2027-01에 재개 확인).
  • robots.txt는 기록만 하고, 막혀도 넣습니다사용자 결정(2026-09-28). plan collection-method.md 2절의 "막히면 검색 안 보냄"은 옛 규칙이라 지금 쓰지 않습니다.

2화면 종류 7가지

도서관 사이트는 화면(HTML 구조)이 7종입니다. 종류마다 읽는 코드(adapter)가 하나씩 있고(ADR-0016), 읽는 코드가 없는 화면은 목록에 넣지 않습니다.
값어떤 사이트알아보는 단서
KYOBO_V1교보 전자도서관주소 모양, 대출 수량 표시 "대출 : 0/5"

판별 절차는 dev library-maintenance.md 1-3·4-6입니다. 인코딩을 먼저 봅니다. 읽는 코드가 없는 화면 7종(경남교육청, 서울도서관, 북큐브 등)은 backlog에 있습니다.

3가입 자격은 원문으로만 정합니다

도서관 사이트의 회원가입 안내 원문을 읽어 판정합니다. 추정하지 않고, 못 찾으면 "자격 미확인"으로 둡니다(ADR-0013).
  • 판정 값 네 가지지역 규칙 있음(REGION) / 누구나(OPEN) / 누구나이지만 주의 문구 있음(OPEN_CAUTION) / 미확인(UNVERIFIED). 2026-09-29 기준 122 / 13 / 1 / 26곳.
  • 방문 가입(visit_required)전자책을 쓰려면 도서관에 가야 하면 true. 판단 순서 4단계는 dev 4-10. 4번 규칙으로 true가 된 18곳은 원문을 다시 볼 후보입니다.
  • 사람이 정한 값이 마지막에 이깁니다dev scripts/library/join_overrides.tsv에 적으면 자동 판정보다 우선합니다. 최신 판정 표는 dev docs/library-research/join-classification-2026-09-29.tsv.
  • 지역 ID 규칙시도 2자리, 시군구 4자리(시도 + 법정동 순서). 세종은 3601 하나. 전남광주통합은 시·도 12로 처리하는데, 옛 광주 거주자가 전남교육청 12곳에 가입 가능으로 나오는 문제가 사용자 확인 대기입니다(dev 14절).

4검색 순서: 가입하기 쉬운 곳부터

지역을 넣으면 내 시군구 → 내 시도 → 누구나 → 방문 가입만 → 확인 필요 순서입니다. 방문 가입 도서관은 같은 무리의 맨 뒤로 갑니다(ADR-0027).

이 순서(joinTier, priorityGroup)는 dev 안내서에는 없고 ADR-0027과 사이클 04 design-delta에만 있습니다. 재조사할 때 ADR-0027을 같이 봐야 합니다.
