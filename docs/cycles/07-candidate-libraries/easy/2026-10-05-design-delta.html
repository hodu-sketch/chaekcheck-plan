설계 문서(design-delta)를 한눈에 보고,
남은 11가지를 정해 주세요.

지금까지 정하신 것(결정 기록 ADR-0052~0058·0060, 로고 7개)을 dev가 만들 수 있는 모양으로 묶은 문서입니다. 남은 것은 세부 규칙·이름과 로고 결정 기록 초안입니다. 다 정해지면 마무리 단계(검토 → 인계서)로 넘어갑니다.

1무엇이 어떻게 이어지나

새 모듈 collection이 가져오기 전부(사본 읽기, 번호 바꾸기, 거르기, 같은 책 묶기, 기록)를 맡고, 다 만든 책을 책 목록 모듈(catalog)에 넘겨 표를 바꿉니다. 제목 다듬기 규칙은 catalog에 두고 빌려 씁니다(ADR-0060). 대출 조회 모듈은 북큐브·알라딘을 새로 읽습니다.

모듈 구성도. 화살표는 "부른다". 로그인·지역 모듈과 조회 서버(fetch-service)는 그대로입니다.

표 관계. 짝 표와 소장은 도서관을 번호로만 가리킵니다(모듈 사이에 외래 키 없음).

1이 설계대로 만듭니다: 새 모듈 collection(가져오기 전부, ADR-0060), 도서관 표 새 칸(가입 조사 상태·교보 소장/구독·로고 둘),
책 표 "가진 도서관 번호", 새 요청 하나(한 번에 옮기기), 북큐브·알라딘 읽기 [안]

그 밖의 서버 요청 모양은 그대로이고, 가입 등급에 "미조사" 값과 로고 주소가 더해집니다. 자세한 칸·요청은 원본 design-delta.md에 있습니다.

다른 선택 고칠 곳을 기타에 적어 주세요.

2주요 흐름

넣기와 가져오기: dev 스크립트가 만든 파일로 도서관·짝·가입 규칙이 들어가고, collection이 사본을 나눠 읽고 묶어 catalog에 넘깁니다.

로그인 전에 직접 넣은 북큐브 도서관으로 검색: 책 목록에서 그 도서관 책이 나오고, 북큐브 XML로 대출 수를 읽습니다. 대여형이면 "구독형 · 바로 대출", 읽기 실패면 "확인 실패".

로그인 직후 옮기기: 계정이 비었을 때만 지역과 도서관을 한 번씩 보냅니다.

3세부 규칙과 이름

2세부 이름(모듈 이름 collection, 칸 이름, 새 요청 주소 /api/v1/me/library-imports, 설정·브라우저 저장 이름, 파일 이름)은
dev가 코드에 맞춰 바꿀 수 있고, 바꾸면 알리기만 합니다 [안]

사이클 06과 같은 방식입니다. 뜻(무엇을 하는 칸·요청인가)은 바꾸지 않습니다.

다른 선택 이름도 이 문서대로 고정. 바꿀 때마다 plan에 묻습니다.

답: "/api/v1/me/library-imports는 뭐 하는 데 쓰는 거야?"

로그인할 때 "이 브라우저에 넣어 둔 도서관들을 계정으로 한 번에 옮기는" 요청입니다. 앞서 "한 번에 옮기는 새 요청을 만들어줘"(ADR-0057)라고 하신 것이 이것입니다.

순서무슨 일
1로그인하지 않은 상태로 내 도서관 화면에서 "강동대학교 (북큐브)", "○○대학교 (알라딘)"을 넣음 → 이 브라우저에만 저장
2로그인함 → 계정에 직접 넣은 도서관이 없으면 "이 브라우저에 저장된 것을 계정에 저장할까요?" 창
3[계정에 저장]을 누르면 화면이 이 요청 하나로 "[281, 1203]"을 서버에 보냄 → 서버가 계정의 직접 추가 목록에 두 곳을 한꺼번에 넣음
4이제 다른 기기에서 로그인해도 두 도서관이 보임

주소 이름 library-imports는 "도서관 옮겨 넣기"라는 뜻입니다. 이 요청은 이때만 쓰고, 평소 도서관 하나를 넣고 빼는 것은 지금 있는 요청 그대로입니다. 이름은 2번(세부 이름은 dev가 바꿀 수 있음)에 들어 있습니다.

답: "이거 collection 담당은 아니지?" 네, 아닙니다. 이 요청은 회원의 내 도서관을 저장하는 mylibrary 모듈이 맡습니다. collection은 수집 DB에서 서비스로 책·도서관을 가져오는 일만 하고, 회원 정보는 다루지 않습니다.

3한 번에 옮기는 요청의 규칙: 계정에 이미 직접 넣은 도서관이 있으면 거절(409),
없는·꺼진 도서관 번호는 건너뜀, 1~20개, 성공하면 옮긴 뒤 전체 목록 [안]

옮기기 창은 계정이 비었을 때만 뜨므로 409는 두 탭에서 동시에 옮기는 경우 같은 드문 때만 일어납니다. 그때 화면은 계정 목록을 다시 읽어 보여 줍니다.

다른 선택 계정에 이미 있어도 합침(20곳까지). 거절이 없지만 계정 목록이 뜻하지 않게 늘 수 있습니다.

4"첫 쪽 1초 안"을 재는 검색어 묶음: "사랑", "소년", "해리", "역사", "김영하", "민음사",
제목+저자 2개, 출판일순 1개 [안]

많이 맞는 짧은 단어, 사람 이름, 출판사, 여러 칸, 정렬을 고루 넣었습니다. dev가 서버에서 재고 결과를 알립니다.

다른 선택 다른 검색어를 기타에 적어 주세요.

5DB 구조 파일은 새 파일로 넣고, 대조가 끝나면 배포 전에 기존 파일에 합칠지 고칩니다.
새 파일 순서: 도서관 → 짝 → 책 목록 [안]

"새 파일을 가지고 비교/대조한 다음에 고치는게 어떨까 해"(사용자, 2026-10-05)를 따른 순서입니다. 합치는 일은 배포 전(PRE_DEPLOYMENT 표시가 있는 동안)에만 할 수 있습니다.

다른 선택 배포 뒤에도 새 파일 그대로 둠(합치지 않음).

답: "기존 것에 있고 새것에 없다면, 기존 것이 정말 살아 있는 사이트인지 검사하고 해야 할 것 같은데"

맞습니다. 합칠 때 "옛 파일에만 있는 도서관"은 지우지 않고, 사이트가 살아 있는지 먼저 확인하는 규칙을 더하겠습니다.

대조 결과할 일
옛 파일과 새 파일 둘 다 있음그대로 합침(주소·이름이 다르면 다른 점을 목록으로 보여 드림)
새 파일에만 있음새로 넣음
옛 파일에만 있음 (예: 이번 사본에서 받지 않은 등록 도서관 4곳 — 국회, 전북교육청, 군포 YES24, 김천시립)지우지 않음. dev가 그 사이트 첫 화면을 한 번 열어 봄(같은 사이트 1건, 로그인 없음). 열리면 그대로 둠. 열리지 않거나 다른 사이트로 바뀌었으면 지우지 않고 "끔"(enabled = false)으로 바꾸자고 목록으로 보여 드리고, 사용자가 정함

지우지 않는 이유: 회원이 내 도서관에 넣어 둔 번호가 사라지지 않게 하기 위함입니다(번호 고정, ADR-0052). 이 규칙으로 5번을 고쳐 적으려면 5번을 승인해 주세요.

6교보 소장형을 가르는 칸(소장·구독·혼합·대여)을 도서관 표에 두고,
값은 수집 세션의 교보 기관 확인 결과(첫 화면 구분)로 채웁니다 [안]

"교보 소장형 고치기"(사용자 승인)를 만드는 방법입니다. 값이 없으면 지금처럼 화면 종류로 판정합니다. 소장형 화면에서 숫자를 어디서 읽는지는 dev가 사이트를 시험해 정합니다.

다른 선택 칸 없이 응답마다 판정(북큐브 대여형처럼). 교보 구독형 화면은 요청 없이 보이던 곳이라 요청이 크게 늘어납니다.

7로고: 줄인 파일은 웹 정적 파일(library-logos/{서비스 번호})로, 서버는 보일 때만 로고 주소를 줌,
브라우저가 오래 보관하도록 캐시 설정 [안]

로고 결정(미리 줄인 파일, DB 값으로 바로 내림, 빈 상자)을 만드는 방법입니다. 로고를 내리면 서버가 주소를 주지 않아 바로 빈 상자가 됩니다.

다른 선택 로고 그림을 DB에 넣음. 파일 관리가 없지만 DB가 그림을 보내야 합니다.

8종류 표에서 "시험용"인 후보 6곳은 서비스에 넣지 않습니다 [안]

이름에 시험·테스트가 붙은 사이트입니다(수집 세션 종류 표). 체험용·운영 중단 4곳을 빼신 것과 같은 이유로 제안합니다.

다른 선택 넣고 "종류 모름"으로 둠.

4로고 결정 기록 초안과 dev 규칙

9ADR-0059 "도서관 로고는 자체 로고가 있는 공공도서관만, 미리 줄인 파일로,
누르면 도서관 메인 페이지, 없으면 빈 상자, DB 값 하나로 바로 내림, 서비스 안내 화면에 고지" 초안대로 기록 [안]

배경: 로고는 저작물·상표·지자체 상징물일 수 있어 위험을 줄이는 장치와 함께 쓰기로 함(library-logos.md 4절, 법령 원문 2026-10-05 확인). 처음에 이번 사이클에서 빼기로 했다가 "이번 사이클에 로고 넣을래 결정 번복이야"로 넣음.

이유(사용자 발언): "그냥 공공도서관? 공개된 도서관만 로고 해주고", "일괄적으로 로고 누르면 해당 도서관 메인 페이지로", "빈 상자 보이도록 근데 이건 실제 화면 보고 나서 언제든 수정 가능", 미리 줄인 파일 "이렇게 해줘", 안내 위치 "'제휴 후원 관계 없음' 이 안내는 뭐 어디 로고 보여주는 화면에는 보이기 싫은데.. 따로 안내에 해야 하나"

하지 않는 것: 이름만 쓰기(위험 0이지만 알아보기 어려움, 채택하지 않음), 허락받은 곳만(시간이 걸림, 채택하지 않음), 회사·대학·업체 기본 로고

다른 선택 고칠 점을 기타에 적어 주세요.

10dev 규칙 "도서관을 넣으면 같은 작업에서 가입 자격을 조사한다"에 대해, 인계서에 "소속 구성원용·종류 모름 후보(약 2,500곳)는
가입 조사 상태 표시로 넣는다(ADR-0053)"는 예외를 적습니다 [안]

앞서 "기다려 이번에 넣을게"라고 하셨고, 후보 공공도서관 120곳 조사는 이번에 넣습니다. 남는 학교·대학·회사·기관은 조사하지 않기로 했으므로(ADR-0053 "소속 구성원용") 이 범위만 예외로 적습니다.

다른 선택 예외 없이 dev에 맡김. dev가 규칙대로 조사를 시작하거나 멈추고 물을 수 있습니다.

11이 설계 문서대로 다음 단계(마무리: 설계 검토 → docs/current/ 갱신 → 인계서)로 갑니다 [안]

마무리에서 검토자(design-reviewer)가 빠진 곳·범위 밖·태그 없는 값을 찾고, 인계서를 만들어 다시 보여 드립니다.

다른 선택 더 볼 곳이 있으면 기타에 적어 주세요.
