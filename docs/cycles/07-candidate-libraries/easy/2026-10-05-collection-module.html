collection 모듈이 맡을 일을
다시 정해 주세요.

질문: "나는 새로 수집된 것을 DB에 추가할 때 용으로도 collection 했는데 뭔가 다르게 된 건가? 왜 카탈로그가 나와?" — 제가 "따로 모듈로 가고 나중에 수집 연결 모듈이 고치라고 해"를 "지금은 짝 표만, 가져오기는 나중에 옮김"으로 좁게 읽었습니다. 말씀하신 뜻대로 가져오기도 collection이 맡도록 다시 제안합니다.

1왜 "카탈로그(catalog)"가 나왔나

catalog는 서비스의 "책 목록" 모듈입니다. 책·사람·소장 표를 가지고 책 검색을 합니다. 지금 가져오기 코드(사이클 04)가 이 모듈 안에 있어서 설계에 나왔습니다.
모듈지금 맡은 일
library 도서관도서관 목록, 가입 규칙, 검색 대상 도서관 고르기
catalog 책 목록책·사람·소장 표, 책 검색. 그리고 지금은 가져오기(수집 DB 읽기 → 정리 → 같은 책 묶기 → 표 채우기)도
availability 대출 조회도서관 사이트에서 대출 수 읽기
collection (새)지금 설계: 짝 표 하나뿐

2가져오기를 collection으로 옮기는 방법

추천안(가): 수집 쪽 일은 collection, 책을 알아보고 묶는 일은 catalog.

1(가) collection이 "수집 DB 읽기 → 서비스 번호로 바꾸기 → 빼는 줄 거르기 → 가져오기 기록"을 맡고,
거른 줄을 catalog의 공개 기능 하나("이 줄들로 책 표를 다시 채워")에 넘깁니다. 정리·같은 책 묶기·표 쓰기는 catalog에 남습니다 [안]

예: 배포 전 가져오기를 실행하면 collection이 사본을 묶음씩 읽어 "수집 100245번 → 서비스 281번"으로 바꾸고, 오디오북·소리 파일 줄을 빼고, 남은 줄을 catalog에 넘깁니다. catalog는 제목·저자를 정리하고 같은 책을 묶어 표를 채웁니다. 나중에 "새로 수집된 것만 더하기(갱신)"를 만들 때도 collection에서 고칩니다.

좋은 점: 수집과 서비스가 코드에서도 갈립니다. 같은 책 묶기 규칙은 책 목록과 함께 있어 검색 쪽과 어긋나지 않습니다. 감수할 점: 지금 가져오기 코드를 두 모듈로 나누는 일이 생기고, catalog에 "대량 쓰기" 공개 기능이 새로 생깁니다.

다른 선택 (나) 정리·같은 책 묶기까지 모두 collection으로: catalog는 표와 검색만. 수집 쪽이 한 곳에 모이지만, 같은 책 묶기 규칙이 검색 모듈과 떨어지고 collection이 책 표 모양을 알아야 합니다. (다) 처음 설계대로 짝 표만 collection, 가져오기는 catalog에 두고 갱신 사이클에서 옮김.

추천: (가).

2이렇게 바꾸면 결정 기록 ADR-0052(새 모듈 collection)에 "가져오기도 맡음"을 덧붙이는 새 결정 기록을 하나 더 씁니다 [안]

이미 Accepted인 기록은 고치지 않는 규칙이라, 범위를 넓히는 기록을 새로 씁니다(번호는 0060).

다른 선택 ADR-0052를 새 기록으로 대체(Superseded).
