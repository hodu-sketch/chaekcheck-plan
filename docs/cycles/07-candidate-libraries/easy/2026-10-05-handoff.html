dev 인계서를 확인해 주세요.
승인하시면 dev 세션이 이 문서로 시작합니다.

인계서(handoff.md)는 18단계로 되어 있습니다. 여기서는 단계 순서, dev가 정하고 알려 줄 것, 사용자가 할 것만 보여 드립니다. 승인하면 docs/current/handoff.md를 이 내용으로 바꾸고(dev가 자동으로 읽음), 사이클 07을 닫습니다.

1dev가 할 순서

단계하는 일
0코드를 바꾸기 전에 지금 결과를 저장(등록 도서관 결과가 그대로인지 나중에 비교하려고)
1seed 스크립트: 사본에서 후보 도서관·짝·가입 규칙 파일을 만듦(도서관 수집의 "넣기")
2DB 구조 새 파일 7개(도서관 칸, 짝 표, 책 "가진 도서관 번호", 로고 칸)
3~5새 모듈 collection으로 가져오기 옮김 → 나눠 읽기·새 제외 규칙·날짜 규칙 → 책 검색을 "가진 도서관 번호"로
6검색 대상 규칙: 소속 구성원용·종류 모름은 직접 넣었을 때만
7북큐브·알라딘 읽기, 북큐브 대여형, 교보 소장형(사이트 시험 먼저)
8로그인 때 한 번에 옮기는 요청
9~13화면: 로그인 전 내 도서관, 옮기기 창, 결과 카드·가입 정보 창, 로고·빈 상자, 서비스 안내, 웹 서버 압축
14~15시험 가져오기(메모리·시간) → 실제 가져오기 → 크기·검색 속도(1초) 재기
16전체 확인(PC·태블릿·폰, 완료 기준 24개)
17배포 전 DB 구조 파일 합치기(옛 파일에만 있는 도서관은 사이트 확인 뒤 사용자에게 "끔" 목록)
18dev 수집 절차 문서를 두 갈래로 정리

1이 순서와 내용으로 dev에 넘깁니다 [안]

dev 규칙의 예외(소속 구성원용·종류 모름 약 2,500곳은 가입 조사 없이 넣음, ADR-0053)도 인계서에 적혀 있습니다. 서버 collection이 도서관 세팅까지 할지는 "다음에 정함"으로 인계서와 backlog에 적었습니다.

다른 선택 고칠 곳을 기타에 적어 주세요.

2설계에 없어서 dev가 정하고 알려 줄 것

무엇왜
가져오기 기록 표를 옮길 때 책 목록 쪽 표의 외래 키를 없애는 방법모듈 사이에는 외래 키를 두지 않는 규칙
화면이 "조사 상태 넷"을 알 수 있는 칸(joinSurvey)가입 등급은 "미조사" 하나라 안내 문구 넷을 가르려면 따로 알려 줘야 함
교보 소장·구독 값(lendingModel)을 대출 조회 쪽에 넘기는 자리대출 조회 모듈이 쓰는 값 묶음이 설계와 달라서
제목 다듬기 규칙을 공개하는 방법(패키지 옮김 등)지금 규칙이 내부 폴더에 있어서
내 도서관 화면 주소가 웹 서버 설정에 빠져 있는 문제dev가 코드를 읽다 찾음. 직접 열면 404일 수 있음

2위 다섯 가지는 dev가 코드에 맞춰 정하고 결과를 알려 주게 합니다 [안]

모두 이미 정하신 규칙(모듈 경계, 조사 상태 넷, 교보 소장형 고치기)을 지키는 방법이라 뜻은 바뀌지 않습니다. 결과는 다음 사이클 회고에서 확인합니다.

다른 선택 하나씩 plan에서 먼저 정함. 인계가 늦어집니다.

3사용자가 할 것

할 일언제
로고 내림 요청용 서비스 전용 이메일 만들어 알려 주기(그 전엔 자리 글)배포 전
소속 전용 후보 공공도서관 2곳(대구학생전자도서관, 세종북자람) 처리 — 규칙으로 못 나타낼 때만1단계 중
교보 소장형 숫자를 못 읽을 때 처리7단계 중
한 번에 옮기는 요청의 오류 코드를 지금 관례(400)에 맞출지 — dev가 물을 때만8단계 전
화면 확인, 북큐브·알라딘 숫자를 사이트와 비교, 로고 끄기 시험16단계
DB 구조 파일 합칠 때 "끔" 목록 승인17단계
사이클 06 뒤 dev에서 따로 한 작업 알려 주기언제든
