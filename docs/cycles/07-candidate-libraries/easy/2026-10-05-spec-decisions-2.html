명세에서 남은 두 가지를
정해 주세요.

앞 페이지 17개 중 15개가 정해졌습니다(승인 14, "주소는 지금처럼 통째로" 1). 남은 것은 로그인하지 않은 사람의 직접 추가(다시 제안)와, 가져오는 동안 검색이 기다리는 문제(질문에 대한 답)입니다.

1로그인하지 않아도
도서관을 직접 넣기

사용자 말: "로그인 하지 않더라도 직접 넣었으면 하는데... 훔.." 그래서 처음 제안("로그인하지 않으면 후보 도서관이 안 보임")을 바꿔, 로그인 없이도 직접 넣을 수 있게 다시 제안합니다.
상황직접 넣은 도서관은 어디에 저장되나검색에 쓰이나
로그인 안 함이 브라우저 (지역과 같은 곳)예. 화면이 검색할 때 도서관 번호를 같이 보냄
로그인함계정(서버). 지금 사이클 06과 같음예
로그인 직후, 계정에 직접 넣은 도서관이 없고 이 브라우저에는 있음"이 브라우저의 도서관도 계정에 저장할까요?"를 한 번 물음. 지역 옮기기 창과 같은 창에 함께답에 따라
로그인 직후 옮기기 창 (위치와 순서만 보이는 그림)
이 브라우저에 저장된 것을 계정에 저장할까요?
거주 서울 마포구 · 직장 서울 중구
직접 넣은 도서관 3곳: 강동대학교 (북큐브), ○○대학교 (알라딘), …
[계정에 저장] [저장하지 않기]

1로그인하지 않아도 내 도서관 화면에서 도서관을 직접 넣을 수 있고(이 브라우저에 저장, 20곳까지),
로그인하면 지역과 함께 계정으로 옮길지 한 번 묻습니다 [안]

예: 로그인하지 않은 사람이 "강동대학교 (북큐브)"를 넣으면, 그 도서관의 책이 이 브라우저의 검색에 나옵니다. 다른 기기에서는 보이지 않습니다. 나중에 로그인하면 옮길지 묻고, 옮기면 어느 기기에서나 보입니다.

서버 쪽은 거의 바뀌지 않습니다. 검색은 이미 "화면이 도서관 번호를 넘기는" 방식이라(사이클 06 결정, ADR-0037), 로그인하지 않은 화면도 같은 값을 넘기면 됩니다. 일은 주로 화면 쪽입니다: 로그인 전 내 도서관 화면, 브라우저 저장, 옮기기 창.

사이클 06에서 정한 "직접 추가는 로그인한 사람이 서버에 저장"을 넓히는 결정입니다.

다른 선택 ① 로그인하지 않아도 넣을 수 있지만, 로그인할 때 옮기지 않음: 더 단순하지만 로그인한 뒤 넣은 도서관이 사라져 보입니다(로그아웃하면 다시 보임). ② 처음 제안대로 로그인한 사람만: 일이 가장 적지만 로그인하지 않은 사람은 후보 도서관을 쓸 수 없습니다.

추천: 이 제안. 지역도 같은 방식(로그인 전 브라우저, 로그인 뒤 옮기기)이라 사용자가 한 가지 규칙만 알면 됩니다.

2"가져오는 동안 왜 기다리나?"에 대한 답

질문하신 대로 배포 전에는 문제가 없습니다. 쓰는 사람이 없기 때문입니다. 기다림이 문제가 되는 것은 서비스를 운영하면서 다시 가져올 때뿐입니다.

왜 기다리나: 가져오기는 책 표를 비우고 다시 채웁니다. 채우는 동안(지난번 약 2분 30초) 표가 잠겨, 그때 들어온 책 검색은 다 채워질 때까지 기다립니다. 배포 전 한 번은 이용자가 없어 상관없습니다. 운영 중 다시 가져올 때 기다리지 않게 하는 방법(새 표에 넣고 한 번에 바꾸기)은 갱신 기능 사이클에서 정합니다.

2가져오는 동안의 기다림은 배포 전이라 문제 없음으로 두고,
운영 중 다시 가져오기는 갱신 기능 사이클에서 정합니다 [안]

이번 사이클에서는 기다림을 없애는 일을 하지 않습니다.

다른 선택 이번에 "새 표에 넣고 한 번에 바꾸기"를 만듦. 배포 뒤 첫 갱신 때 바로 쓸 수 있지만 일이 늘어납니다.
