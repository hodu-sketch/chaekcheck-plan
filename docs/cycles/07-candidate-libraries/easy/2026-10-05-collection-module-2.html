가져오기 전부(읽기 → 정리 → 같은 책 묶기 → 표 채우기)를
collection이 하도록 바꿉니다.

말씀: "가져오기(수집 DB 읽기 → 정리 → 같은 책 묶기 → 표 채우기)도 나는 이걸 컬렉션이 하는게 맞다고 보는데......" 앞 페이지의 (나)안입니다. 모듈 규칙에 맞추려면 두 가지를 같이 정해야 해서, 구체적으로 만든 안을 다시 올립니다.

1나눈 모습

collection이 가져오기 일을 모두 하고, catalog는 자기 표에 쓰는 일과 검색만 합니다.

2모듈 규칙 때문에 같이 정할 두 가지

dev의 모듈 규칙은 "다른 모듈의 표에 직접 쓰지 않는다", "모듈끼리 서로를 부르는 고리를 만들지 않는다"입니다.
문제푸는 방법
책 표는 catalog 것이라 collection이 직접 쓸 수 없음catalog가 공개 기능 하나 "이 책·사람·소장으로 표를 통째로 바꿔"를 내주고, collection이 다 만든 것을 넘김. 실제 쓰기(비우고 채우기, 정리 작업)는 catalog 안에서
검색어도 책 제목과 같은 규칙으로 정리해야 맞게 찾음. 정리 규칙을 collection으로 옮기면 검색이 collection을 불러야 하고, collection은 catalog를 부르므로 서로 부르는 고리가 생김글자 정리 규칙(제목·저자·출판사 정리)은 catalog에 두고 공개해, collection이 그것을 씀. 같은 책 묶기·대표값·날짜 규칙·가진 도서관 번호 계산은 collection으로 옮김

1collection이 가져오기 전부(①~⑥)를 맡고, catalog는 책 표·검색과 글자 정리 규칙을 그대로 가지고
"표 통째로 바꾸기" 공개 기능을 내준다 (글자 정리 규칙은 catalog에 두고 collection이 빌려 씀) [안]

예: 가져오기를 실행하면 collection이 사본을 나눠 읽고, 번호를 바꾸고, 빼는 줄을 거르고, catalog의 정리 규칙으로 제목을 정리하고, 같은 책을 묶어 "책 68만 권·소장 2,100만 줄"을 만든 뒤 catalog에 넘깁니다. catalog는 받은 것으로 표를 통째로 바꾸고 정리 작업(VACUUM)을 합니다. 나중에 갱신 기능은 collection에서 만듭니다.

바뀌는 것: 지금 catalog 안의 가져오기 코드(사본 읽기, 묶기, 대표값, 날짜)를 collection으로 옮김. 모듈 방향: collection → catalog → library, collection → library.

다른 선택 글자 정리 규칙도 collection으로 옮기고 검색은 정리 규칙 사본을 따로 가짐. 고리는 없지만 같은 규칙이 두 곳에 생겨 어긋날 수 있습니다.

답: "글자 정리 규칙, 지금 카탈로그가 뭘 어떻게 하고 있어?"

제목·저자·출판사 글자를 "비교하기 좋은 모양"으로 바꾸는 작은 규칙 묶음입니다. 가져올 때와 검색할 때 똑같이 씁니다. dev 코드 catalog/internal/normalize/CatalogText.java, Contributors.java(읽기만 해서 확인, 2026-10-05).

규칙하는 일예
기본 정리전각·반각 같은 모양 차이를 하나로(NFKC), 영문 소문자로, 띄어쓰기 없앰"해리 포터 Ⅰ" → "해리포터i"
본제목앞의 시리즈 표시(〈…〉, [ … ])와 " : ", " - " 뒤 부제를 뗌"[밀리언셀러] 아몬드 : 손원평 장편소설" → "아몬드"
출판사"(주)", "주식회사" 같은 말과 점·쉼표·띄어쓰기를 뗌"(주)민음사" → "민음사"
저자 나누기"지은이 / 옮긴이" 원문을 사람과 역할로 나눔"손원평 지음 / 홍길동 옮김" → 손원평(저자), 홍길동(옮긴이)

쓰는 곳 둘

  • 가져올 때: 도서관마다 다르게 적힌 제목을 이 규칙으로 바꾼 뒤, 같은 것끼리 같은 책으로 묶음(묶기 ④)
  • 검색할 때: 이용자가 친 "해리 포터"도 같은 규칙으로 "해리포터"로 바꿔 찾음 → 띄어쓰기가 달라도 찾아짐

그래서 제안한 것: 이 규칙이 둘로 갈라지면(가져오기용·검색용) 한쪽만 고쳤을 때 "책은 있는데 검색에 안 걸림"이 생깁니다. 그래서 규칙 자체는 검색과 함께 catalog에 한 벌만 두고, collection이 가져올 때 그것을 불러 씁니다. 묶는 기준(무엇을 같은 책으로 볼지), 대표 제목 고르기, 날짜 규칙처럼 가져오기에서만 쓰는 것은 collection으로 옮깁니다.

답: "글자 정리 규칙은 검색용인데 왜 컬렉션에 둬?"

컬렉션에 두지 않습니다. 말씀대로 검색 쪽(catalog)에 그대로 둡니다. 제 설명이 헷갈리게 쓰였습니다.

어디에 두나누가 쓰나
글자 정리 규칙 (띄어쓰기 없애기, 본제목 떼기, 출판사 다듬기, 저자 나누기)catalog (지금 그대로)catalog 검색 + collection이 가져올 때 빌려 씀
가져오기 일 (사본 읽기, 번호 바꾸기, 거르기, 같은 책 묶기, 대표 제목 고르기, 날짜 규칙, 가진 도서관 번호)collection (옮김)collection
책 표 채우기, 책 검색catalogcatalog

왜 빌려 써야 하나: 같은 책 묶기는 "도서관마다 다르게 적힌 제목을 같은 모양으로 바꾼 뒤 비교"하는 일이라, 그 "같은 모양으로 바꾸기"가 검색 규칙과 똑같아야 합니다. 그래야 묶인 책이 검색에서도 같은 이름으로 찾아집니다. 그래서 규칙은 검색 쪽에 한 벌만 두고, 가져오기가 그것을 부릅니다(규칙을 복사해 두지 않음).

만약 collection이 검색 규칙을 전혀 쓰지 않게 하려면, 같은 책 묶기도 catalog에 남겨야 합니다(앞 페이지의 (가)안: collection은 읽기·번호·거르기·기록만). 1번을 승인하시면 위 표대로, (가)안이 낫다고 보시면 기타에 "(가)"라고 적어 주세요.

답: "같은 책을 묶을 때 그 규칙을 왜 써? 검색용인데"

같은 책인지 알려면 도서관마다 다르게 적힌 제목을 맞춰 봐야 하는데, 그 "맞춰 보기 전 다듬기"가 지금 검색 규칙과 같은 일이라서 같이 쓰고 있습니다.

도서관사이트에 적힌 제목다듬은 뒤
강서구해리 포터와 마법사의 돌 1해리포터와마법사의돌1
고흥군해리포터와 마법사의 돌 1해리포터와마법사의돌1
○○대학교[베스트] 해리 포터와 마법사의 돌 1 : 개정판본제목 해리포터와마법사의돌1

다듬지 않으면 세 줄이 서로 다른 책 셋으로 들어가, 검색 결과에 같은 책이 세 번 나옵니다. 다듬으면 한 책으로 묶여 "도서관 3곳"으로 한 번 나옵니다. 즉 이 규칙은 "검색 전용"이 아니라 "제목 비교용"이고, 검색과 묶기 둘 다 비교를 하기 때문에 같이 씁니다.
