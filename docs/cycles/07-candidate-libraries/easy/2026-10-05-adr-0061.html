1도서관 사이트 보안 연결

세 도서관 사이트의 보안 인증서를 Java가 알아보지 못해 늘 실패했습니다. 그 인증서를 내준 기관 하나를 도서관 사이트 연결에만 믿도록 더했습니다.

1ADR-0061: 도서관 사이트 연결에만 최상위 인증 기관 하나를 더 믿음 (ADR-0022 보완) [안]

배경. 우리 서버는 도서관 사이트에 https로 접속할 때, Java(JDK)에 들어 있는 최상위 인증 기관만 믿기로 했습니다(ADR-0022). 그런데 세계사이버대, 서울신학대, 충북 전자도서관 3곳은 JDK에 없는 기관(OISTE WISeKey Global Root GB CA)의 인증서를 써서 늘 연결에 실패했습니다. 12곳은 사이트가 중간 인증서를 보내지 않아 실패했습니다.

결정. 이 기관 하나를 도서관 사이트 연결에만 더 믿습니다(로그인 등 다른 연결에는 쓰지 않음). 빠진 중간 인증서 3개도 같은 폴더(tls/library-roots/)에 둡니다. 새 기관을 더할 때는 사용자 승인을 받습니다.

이유. 사용자: "이거 신뢰해줘" (2026-10-05, dev 기록)

다른 선택 (가) 그대로 두고 3곳은 "확인 실패"로 보임: 보안 설정은 그대로지만 3곳은 결과가 안 나옴. (나) 3곳을 끔: 검색 대상에서 빠짐. 둘 다 채택하지 않은 이유 [이유 미확인].

함께 바로잡을 기록: 사이클 02에 "Sectigo R46 기관은 JDK에 있음"이라고 적었는데, 지금 쓰는 JDK 25에는 없습니다(dev 확인). 다른 인증서 경로로 풀렸습니다.

다른 결정 기록 초안(책 번호 잇기, 후보 최종 주소, 화면·찾기 규칙)은 사이클 08 범위를 정한 뒤에 보여 드립니다.
