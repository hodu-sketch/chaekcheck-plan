도서관 정보와 도서관–책 정보는
서로 다른 길로 서비스 DB에 들어갑니다.

도서관 정보(이름·주소·가입 방법)는 조사 결과로 seed 파일을 만들어, 서버가 시작할 때 넣습니다. 도서관–책 정보(어느 도서관이 어떤 책을 가졌나)는 수집기가 수집 DB에 모으고, collection 모듈이 가져오기로 서비스 DB에 옮깁니다. 이 페이지는 두 길이 어디서 모으고, 어떻게 다듬고, 어디에 두는지를 보여 드립니다. 정할 것은 없습니다.

1두 길 한눈에

위 줄이 도서관 정보, 아래 줄이 도서관–책 정보입니다. 두 길은 서비스 DB에서 "수집 번호 ↔ 서비스 번호 짝"으로 이어집니다.

도서관 정보는 가져오기를 거치지 않습니다. collection은 아래 줄의 가져오기만 합니다.

2도서관 정보: 모으기 → 다듬기 → 넣기

사람과 확인 스크립트가 조사한 결과를 파일로 남기고, seed 스크립트가 그 파일들로 서비스에 넣을 줄을 만듭니다.

위 줄은 수집 DB에 도서관을 넣는 길, 아래 줄은 서비스 DB에 도서관을 넣는 길입니다.

단계무엇을결과가 남는 곳
후보 찾기교보 공식 기관 목록, 웹러브 북스 기관 목록에서 전자도서관 사이트를 찾음목록 파일 (데이터 폴더)
확인확인 스크립트가 사이트마다 첫 화면을 한 번 열어 열리는지, 화면 종류, 권수, 교보 대출 방식을 봄확인 결과 파일 (데이터 폴더)
수집 DB에 넣기확인된 사이트를 수집 DB 도서관 표에 번호 100001번부터 넣음. 책 수집이 이 표를 보고 돎수집 DB 도서관 표
같은 사이트 거르기이미 있는 도서관과 같은 사이트면 "받지 않음" 표시(지우지 않음)수집 DB 도서관 표의 표시 칸
도서관 정보 조사가입 안내 원문, 도서관 종류, 구독형 마감 공지, 로고. 사람이 읽고 정하는 부분이 있음조사 파일(TSV), 로고 파일 (데이터 폴더)
다듬기 (seed 스크립트)수집 DB와 조사 파일을 읽어 넣을 곳을 거르고, 서비스 번호를 주고(마지막 번호 다음, 한 번 준 번호·이름은 유지), 같은 이름에 화면 종류를 붙이고, 가입 조사 상태·교보 대출 방식·리다이렉트를 따라간 최종 주소를 채움seed 파일(CSV), dev 저장소
넣기서버가 시작할 때 Liquibase가 아직 넣지 않은 seed 파일을 넣음서비스 DB: 도서관 표, 가입 규칙 표, 번호 짝 표

3도서관–책 정보: 수집 DB에 모으기

수집기가 도서관마다 전자책 목록 화면을 처음부터 끝까지 읽어, "이 도서관에 이 책 코드가 있다"는 줄을 수집 DB에 씁니다.

수집기는 계속 돌고, 가져오기는 그중 한 순간을 복사한 사본을 읽습니다.

수집 DB의 표한 줄이 뜻하는 것담는 것
도서관 (library)수집할 도서관 하나번호, 주소, 화면 종류, 받지 않음 표시, 마지막으로 전체 수집에 성공한 시각
소장 (holding)도서관 하나 × 책 코드 하나제목·저자·출판사·출간일 원문, 공급사, 자료 종류(오디오북 등), 상세 페이지 주소, 처음 본 시각, 마지막으로 본 시각, 빠진 날짜
실행 기록 (crawl_run)수집 한 번시작·끝, 상태, 이어 받기 위치, 오류
  • 소개·목차·서평 문장은 저장하지 않고, 표지는 주소만 둡니다. 보유·대출·예약 수는 저장하지 않고 이용자가 볼 때 도서관 사이트에서 바로 읽습니다.
  • 수집기는 계속 돌며 수집 DB를 고칩니다. 그래서 가져오기는 원본이 아니라 날짜를 붙인 사본 파일(지금 ebook-catalog-2026-10-05-0745.sqlite)을 읽습니다.

근거: plan docs/research/collection/2-books.md 2·3절.

5시각이 남는 곳

"언제 모은 정보인가"는 책 쪽은 남고, 도서관 정보 쪽은 조사 파일 이름에만 있습니다.

책 목록의 수집 시각은 수집 DB에서 가져오기를 거쳐 서비스 DB로 옮겨 적힙니다.

시각어디뜻
처음 본·마지막으로 본 시각수집 DB 소장 표그 책 코드를 그 도서관에서 처음·마지막으로 본 때
마지막 전체 수집 성공 시각수집 DB 도서관 표그 도서관 책 목록을 끝까지 받은 마지막 때
도서관별 수집 시각서비스 DB (catalog)가져오기가 위 "마지막 전체 수집 성공 시각"을 옮겨 적음. 없으면 그 도서관에서 마지막으로 본 시각. 검색 결과 기준일에 씀
가져온 시각, 사본 이름서비스 DB 가져오기 기록 (collection)가져오기 한 번마다 한 줄. 사본의 수집 기간은 다음 인계서에서 더함(사용자 결정, 2026-10-05)
넣은 시각·고친 시각서비스 DB 도서관 표DB에 넣은·고친 때. 고친 시각은 지금 믿을 수 없음(회고 질문 페이지 #6)
도서관 정보를 조사한 날조사 파일 이름 (예: public-join-2026-10-05.tsv)서비스 DB에는 없음. 넣을지는 다음에 조사해서 여쭙니다(backlog)

도서관별 수집 시각을 고르는 방법은 dev CollectedCatalog.java(2026-10-05 읽음)에서 확인했습니다.

표·칸 이름으로 보면

수집 DB는 SQLite 파일(chaekcheck-data\ebook-catalog.sqlite, 가져오기는 그 사본)이고, 서비스 DB는 PostgreSQL입니다. 서비스 DB 표 이름의 앞부분(library., catalog., collection.)은 그 표를 가진 모듈입니다.
