후보 도서관 넣기의 동작 규칙,
17가지를 정해 주세요.

명세(spec.md)에서 아직 제안인 것만 모았습니다. 이미 정하신 것(새 번호 + 짝 표, 북큐브·알라딘 코드 만들기, 보이는 규칙)은 그대로 두었습니다. 근거는 오늘 한 두 조사입니다: 배포용 사본의 데이터 모양, 북큐브·알라딘 사이트 시험(요청 25건, 로그인 없음).

1미리 알아 둘 것:
조사에서 나온 숫자

북큐브·알라딘 모두 로그인 없이 보유·대출·예약 수를 읽을 수 있습니다. 사본에는 소장 약 2,151만 줄이 있고, 같은 책 코드가 평균 6.2곳에 있습니다.
무엇값
넣을 후보 도서관 (전체 수집이 끝난 곳)2,412곳
후보 도서관끼리 이름이 같은 곳98묶음 211곳 (예: 강동대학교가 북큐브·교보·YES24 사이트를 따로 둠)
등록 도서관과 이름이 같은 후보 도서관27곳
소장 줄 (같은 사이트 제외)약 2,151만 (등록 499만 + 후보 1,652만)
서로 다른 (제목, 저자, 출판사)약 201만~225만
소장 줄 크기 중 주소(상세·표지)가 차지하는 몫약 70%
서비스 DB 예상 크기 (계산 값, 시험 안 함)8~10GB

2도서관 번호와 이름

1등록 도서관은 지금 번호 그대로 두고,
짝 표에서 같은 번호끼리 짝짓습니다 [안]

예: 등록 도서관 45번은 서비스에서도 45번이고, 짝 표에 "서비스 45 ↔ 수집 DB 45"가 들어갑니다. 지금 회원이 저장한 내 도서관 번호가 바뀌지 않습니다.

다른 선택 등록 도서관도 새 번호를 줌. 번호 규칙이 하나로 같아지지만, 이미 저장된 내 도서관 번호를 모두 고쳐야 합니다.

2다시 가져와도 이미 들어온 후보 도서관의
서비스 번호는 바뀌지 않습니다 [안]

예: 오늘 들어온 "○○대학교 (북큐브)"가 서비스 3001번이면, 다음 주에 다시 가져와도 3001번입니다. 짝 표에서 수집 DB 번호로 찾기 때문입니다. 회원이 내 도서관에 넣어 둔 도서관이 사라지거나 바뀌지 않습니다.

다른 선택 가져올 때마다 새로 번호를 줌. 단순하지만 내 도서관에 저장된 번호가 엉뚱한 도서관을 가리키게 됩니다.

3이름이 겹치면 뒤에 사이트 종류 이름을 붙입니다:
"강동대학교 (북큐브)" [안]

내 도서관 화면 "직접 도서관 추가"에서 "강동"을 친 모습 (위치와 순서만 보이는 그림)
강동대학교 (북큐브)[추가]
강동대학교 (교보)[추가]
강동대학교 (YES24)[추가]
강동구립도서관직접 추가함

서비스 도서관 이름은 서로 달라야 합니다. 같은 기관이 사이트를 여러 개 둔 경우가 대부분이라 사이트 종류(북큐브, 교보, YES24, 알라딘)를 붙이면 구분됩니다. 그래도 겹치면 사이트 주소를 붙입니다(예: "○○학교 (교보, ebook.oo.ac.kr)"). 지금 등록 도서관 이름("(구독)", "(YES24)")과 같은 방식입니다.

다른 선택 ① 이름은 그대로 두고 화면에서 옆에 작은 글씨로 사이트 종류만 보임: 이름이 짧지만 DB의 "이름은 서로 달라야 함" 규칙을 풀어야 합니다. ② 같은 기관의 사이트를 한 줄로 묶어 보임: 보기 좋지만 기관 표가 새로 필요합니다(실물 도서관 사이클에서 다시 볼 일).

4로그인하지 않은 사람에게는
후보 도서관이 보이지 않습니다 [안]

이미 정한 규칙: 가입 조건이 없는 도서관은 내 도서관에 직접 넣은 사람에게만 나옵니다. 그런데 직접 넣기는 로그인해야 됩니다. 그래서 로그인하지 않은 사람의 검색은 지금과 똑같습니다(등록 도서관만).

다른 선택 로그인하지 않아도 브라우저에 직접 넣기를 저장하게 함. 더 많은 사람이 쓰지만, 사이클 06에서 정한 "직접 추가는 로그인 뒤 서버 저장"을 바꾸고 화면 일이 늘어납니다.

3보이는 규칙 (이미 정함)

2026-10-04에 사용자가 정한 규칙을 그림으로 옮긴 것입니다. 이 카드에는 정할 것이 없습니다.

4가져올 때 데이터 고치기

5북큐브의 출판일 "20231015" 같은 값을
날짜로 읽습니다 [안]

북큐브 사이트는 출판일을 숫자 8자리로 줍니다. 지금 가져오기는 이것을 날짜로 읽지 못해 255,783줄이 "출판일 없음"이 됩니다. 읽게 하면 그 책들이 "최신순" 정렬에 제대로 들어갑니다.

다른 선택 지금처럼 둠. 그 책들은 출판일 순 정렬에서 맨 뒤로 갑니다.

6명지대학교 사이트의 1950년 이전 출판일 17,311줄은
"출판일 없음"으로 다룹니다 [안]

1950년 이전 날짜 17,748줄 중 17,311줄이 이 한 도서관에서 나왔습니다. 전자책이 그 시기에 나왔을 리 없어 사이트가 빈칸 대신 넣은 값으로 보입니다(확인은 못 함). 그대로 두면 "오래된 순" 정렬 맨 앞에 이 책들이 섞입니다.

다른 선택 그대로 둠. 또는 모든 도서관의 1950년 이전 날짜를 "없음"으로: 고전 원본 출판일일 수 있는 437줄도 같이 사라집니다.

5북큐브·알라딘 결과 줄

결과 줄 예시 (위치와 순서만 보이는 그림, 실제 모양은 dev 화면을 따릅니다)
울산동부도서관 (북큐브) 직접 추가대출 가능 · 보유 5 · 대출 2 · 예약 0
○○대학교 (알라딘) 직접 추가예약 대기 · 보유 1 · 대출 1 · 예약 0
부산 ○○ (북큐브 구독) 직접 추가구독형 · 바로 대출

7대출 가능 여부는 교보 일반·YES24와 같은 방법으로 정합니다:
대출 수가 보유 수보다 적으면 "대출 가능" [안]

북큐브는 책마다 작은 XML(/xml/productView/?num=)에 보유·대출·예약 수가 있고, 화면 숫자와 같았습니다(2026-10-05, 대출 2/5, 1/1 두 권으로 확인). 알라딘은 상세 화면에 "보유 1, 대출 1, 예약 0"이 그대로 있습니다.

다른 선택 사이트의 버튼 글자("대출하기"/"예약하기")로 정함. 알라딘은 되지만 북큐브 XML에는 그런 값이 확실하지 않습니다.

8북큐브 구독(대여)형은
교보 구독형처럼 "구독형 · 바로 대출"로 보입니다 [안]

이 종류는 보유 수가 늘 0이고, 사이트에 "동시이용제한 없이 이용 가능합니다"라고 적혀 있습니다(부산, 100권 모두 보유 0). 숫자를 그대로 읽으면 모든 책이 "빌릴 수 없음"으로 잘못 보입니다.

다른 선택 숫자 없이 "목록에 있음"만 보임. 틀린 말은 없지만 바로 빌릴 수 있다는 정보가 빠집니다.

9후보 도서관 이름을 누르면 "가입 정보를 아직 조사하지 않았어요.
도서관 사이트에서 확인해 주세요"와 첫 화면 링크가 보입니다 [안]

지금 결과 줄에서 도서관 이름을 누르면 가입 자격·방법이 담긴 창이 열립니다(사이클 06 뒤 dev가 바꾼 것). 후보 도서관은 가입 정보를 조사하지 않았으므로 빈 창 대신 이 안내를 보입니다.

다른 선택 이름을 눌러도 창이 열리지 않게 함. 단순하지만, 왜 열리지 않는지 알 수 없습니다.

6DB와 검색 다듬기

10목표: 정해 둔 검색어 묶음에서
책 검색 첫 쪽 응답이 1초 안 [안]

책이 약 4배로 늘어도 이 안에 들어와야 다 된 것으로 봅니다. dev가 서버에서 잽니다(EXPLAIN 포함). 지난번 "사랑" 첫 검색은 224ms였습니다(소장 495만 줄일 때).

다른 선택 더 빡빡하게 500ms 안, 또는 숫자 없이 "지금보다 크게 느려지지 않음".

11"책을 찾고 → 그 책을 가진 도서관을 펼치는" 지금 구조는 그대로 두고,
표·색인은 설계에서 다시 정합니다 [안]

같은 책 코드가 평균 6.2곳에 있어, 책 단위로 찾는 지금 방식이 늘어난 양에 잘 맞습니다(찾는 대상 약 200만, 펼치는 소장 약 2,100만). 어떤 칸을 어디에 둘지, 찾기용 색인을 어떻게 둘지는 설계(architect 제안)에서 정합니다.

다른 선택 지금 표를 그대로 두고 양만 늘림. 바꿀 것이 없지만 데이터 모양을 보고 다듬자는 사용자 요청과 맞지 않습니다.

12상세·표지 주소를 줄마다 통째로 둘지 줄일지는
설계에서 정합니다 [안]

소장 줄 크기의 약 70%가 주소입니다. 주소는 "도서관 사이트 주소 + 정해진 모양 + 책 코드"로 거의 만들어지므로, 줄이면 DB가 크게 작아질 수 있습니다. 단 교보 상세 주소에는 줄마다 다른 값(sntnAuthCode)이 붙어 그대로 만들 수 없습니다.

다른 선택 지금처럼 통째로 둠. 단순하지만 DB가 더 큽니다.

13가져오는 동안 책 검색이 잠시 기다리는 것은
배포 전 한 번이라 감수합니다 [안]

지난번에는 약 2분 30초 동안 책 검색이 기다렸습니다. 양이 약 4배라 더 길어질 수 있습니다. 배포 전에 한 번 가져오는 것이라 이용자가 거의 없습니다. 운영 중 다시 가져오는 방법은 갱신 기능 사이클에서 정합니다.

다른 선택 이번에 "새 표에 먼저 넣고 한 번에 바꾸기"를 만듦. 기다림이 없어지지만 일이 늘어납니다.

7수집 두 갈래 정리

14plan 문서는 docs/research/collection/ 폴더에
1-libraries.md(도서관 수집), 2-books.md(책 수집) 두 장으로 [안]

각 장에는 받는 것, 내놓는 것, 원칙, 결정, dev 절차 링크를 둡니다. 지금 여섯 장에 흩어진 내용은 이 두 장으로 옮기거나 링크합니다. dev 문서 이름(docs/maintenance/1-libraries.md, 2-crawl.md)과 번호를 맞췄습니다.

다른 선택 지금 문서 이름을 그대로 두고 머리말에 "어느 갈래인지"만 적음. 작지만 흩어진 것은 그대로입니다.

15도서관 수집이 찾은 도서관은 수집 DB에 먼저 들어가고,
가져올 때 짝 표로 서비스에 이어집니다 [안]

흐름: ① 도서관 수집 → 수집 DB 도서관 목록 → ② 책 수집 → 가져오기 때 서비스 도서관 표에 새 번호로 들어가고 짝 표에 기록. 서비스 도서관 표가 "검색에 쓰는 목록"의 원본이 되고, 수집 DB 목록은 "받을 곳 목록"이 됩니다.

다른 선택 서비스 도서관 표에 먼저 넣고 수집 DB가 그것을 받아 감. 원본이 처음부터 하나지만, 수집 세션이 서비스 DB를 읽어야 하고 지금 돌고 있는 수집기를 바꿔야 합니다.

8안 될 때 보이는 것

16도서관 이름 검색 결과가 없으면
"찾는 도서관이 없어요"를 보입니다 [안]

내 도서관 화면에서 친 이름에 맞는 도서관이 없을 때의 문구입니다.

다른 선택 다른 문구를 기타에 적어 주세요.

17북큐브 XML이 그 책을 못 찾거나 모양이 다르면 그 줄은 "실패"로 보이고,
[도서관에서 보기] 링크는 남깁니다 [안]

다른 도서관 사이트가 실패할 때와 같은 모양입니다. 이용자는 링크로 그 사이트에서 직접 확인할 수 있습니다.

다른 선택 실패한 줄을 숨김. 깔끔하지만 그 도서관에 책이 있다는 사실도 사라집니다.
