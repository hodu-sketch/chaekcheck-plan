사이클 07 개발 중에 사용자가 dev와 정한 것 가운데, 이미 있는 결정 기록과 어긋나거나 새 구조를 만든 것을 모았습니다. 인증 기관 추가(ADR-0061)는 이미 기록했습니다. 아래 초안을 승인하시면 docs/adr/에 파일로 씁니다. 결정 자체는 이미 코드에 들어가 있으므로, 여기서는 "기록을 이대로 남길지"를 정합니다.

1가져올 때 책 번호 잇기

다시 가져와도 같은 책은 같은 책 번호를 갖게 되었습니다. 2026-10-04에 정한 규칙(catalog-refresh.md 5.2절)을 dev가 이번에 만들었고, 어디서 하는지를 dev가 정했습니다.

1ADR-0062: 책 번호 잇기는 catalog의 표 바꾸기 안에서 함 [안]

배경. 예전 가져오기는 표를 비우고 책 번호를 1부터 새로 매겨서, 다시 가져오면 책 주소(/books/{번호})가 다른 책을 가리킬 수 있었습니다. 규칙은 2026-10-04에 정했지만(겹침이 가장 많은 옛 번호를 이어 씀, 합쳐지면 가장 작은 번호, 나뉘면 가장 많이 겹치는 쪽, 번호는 다시 쓰지 않음, 안내표 없음), 어느 모듈에서 할지는 정하지 않았습니다.

결정. catalog의 표 바꾸기 기능 안에서 합니다. 새로 받은 책·소장을 임시 표에 넣고, 옛 소장과 (도서관, 책 코드)로 맞대어 번호를 정한 뒤 표를 바꿉니다. 소장 2천만 줄을 서버 메모리에 올리지 않습니다. 가져오기를 맡은 collection은 바뀌지 않습니다. 이어 쓴·새로 준·없어진 번호 수는 가져오기 기록에 남깁니다.

결과. 같은 사본으로 두 번째 가져오기를 하니 1,617,445권 모두 번호가 그대로였습니다. 대신 쓰기 시간이 17분 51초에서 22분 43초(두 번째 26분 55초)로 늘었습니다.

이유. 사용자: "이것도 같이 구현해 줘", 모듈은 "catalog 해줘" (2026-10-05, dev 기록)

다른 선택 collection에서 함: 옛 소장을 읽으려면 catalog의 표를 직접 읽어야 해서 모듈 경계 원칙에 걸림. 채택하지 않은 이유 [이유 미확인].

2후보 도서관 주소

강동대학교 북큐브가 검색되지 않던 원인은, 수집 DB의 http 주소를 그대로 썼는데 사이트가 https로 넘겨서였습니다. 넘겨진 최종 주소를 쓰도록 바꿨습니다.

2ADR-0063: 후보 도서관은 최종 주소를 쓰고, 가져오기는 호스트·경로로 같은 사이트를 확인함 (ADR-0052 보완) [안]

배경. 수집 DB에는 도서관 목록에서 찾은 주소(대개 http)가 있습니다. 우리 서버는 다른 주소로 넘기는 응답(리다이렉트)을 따라가지 않으므로, https로 넘기는 사이트는 늘 실패했습니다. 책 상세 주소도 http라 책 화면의 대출 확인이 실패했습니다.

결정.

  • 후보 도서관의 서비스 주소는 리다이렉트를 따라간 최종 주소로 둡니다(248곳이 https로 바뀜). 등록 도서관에 하던 확인을 후보에도 합니다.
  • 가져오기는 수집 주소와 서비스 주소를 호스트·경로·쿼리로 비교합니다. http/https와 포트 차이는 같은 사이트로 봅니다.
  • 책 상세 주소는 서비스 도서관 주소의 http/https·포트로 옮겨 씁니다.

남은 빈틈. 도서관 411은 넘겨진 곳의 호스트까지 달라(ebook2.ezville.net → gsenc.bookcube.biz) 같은 사이트 확인에 걸려 책 64,461줄이 빠졌습니다. 어떻게 이을지는 사이클 08 후보로 올립니다.

이유. 사용자 보고(강동대학교 북큐브가 "검색해도 안나오고", 2026-10-05, dev 기록). 바꾸는 방법 자체에 대한 사용자 말은 없음 [이유 미확인].

다른 선택 (가) 서비스가 요청할 때마다 리다이렉트를 따라감: 요청이 한 번씩 늘고, 다른 호스트로 넘어가는 것을 막는 안전장치와 부딪힘. (나) 수집 DB 주소를 고침: 수집기가 쓰는 주소가 바뀜. 채택하지 않은 이유 [이유 미확인].

3개발 중에 바꾼 화면·찾기 규칙

ADR-0056(북큐브·알라딘)과 ADR-0059(로고)에 적은 것 중 세 가지가 사용자 요청으로 바뀌었습니다. 확정된 기록은 고칠 수 없으므로 새 기록으로 남깁니다.

3ADR-0064: 알라딘 출판사 검색·북큐브 "더 보기"·로고 자리를 바꿈 (ADR-0056·0059 일부를 바꿈) [안]

예전 기록지금이유
알라딘 "도서관에서 직접 찾기"의 출판사 검색은 그 도서관 실패 (ADR-0056)출판사 검색을 씀 (사이트 시험에서 됨)사용자: "출판사 검색도 씀"
북큐브 직접 찾기는 첫 쪽만 (ADR-0056)다른 사이트처럼 "더 보기" (한 쪽 10권, 쪽 넘기기 시험에서 됨)사용자 결정, 원문 없음 [이유 미확인]
로고는 이름 앞, 없으면 빈 상자 (ADR-0059)로고는 이름 위 줄, 없으면 아무것도 그리지 않음사용자: "실제로 확인해보고 디자인 측면의 안정감때문에"

ADR-0056·0059의 나머지(북큐브·알라딘을 상세 페이지로 읽음, 북큐브 대여형 판정, 자체 로고만 보임, 누르면 메인 페이지 등)는 그대로입니다.

다른 선택 ADR-0056·0059를 통째로 새 기록으로 바꿈: 바뀌지 않은 내용까지 다시 적어야 함.
