## 포함

### A. 후보 도서관 넣기

- 넣을 도서관: 같은 사이트 99곳을 뺀 후보 도서관 중, 가져오는 사본에서 전체 수집이 끝난 곳(지금 사본 2,412곳). 나머지는 수집이 끝나는 대로 다음 가져오기에서 들어옴 [확정] (사용자 승인, 2026-10-05, 캔버스 항목 3). 사용자 덧붙임: "배포가 우선이라서 점차 늘릴거야 그리고 다 세팅한다음에 '갱신'기능을 만들 거야"
- 보이는 규칙 [확정] (사용자, 2026-10-04, `collection-areas.md` 2-1절): 가입 조건이 없는 도서관은 내 도서관에 넣은 사람에게만 검색에 나오고, 그때만 그 사이트로 요청 (설계에서 가입 조사 상태 `join_survey`의 `MEMBERS_ONLY`·`NOT_SURVEYED`로 가름, ADR-0053)
- **북큐브·알라딘 대출 상태를 읽는 코드를 이번에 만듦** [확정] (사용자: "읽는 코드를 이번에 만들었으면 해", "북큐브·알라딘 대출 상태 읽는 코드 이건 여기서 할거야", 2026-10-05, 캔버스 항목 4 미승인·12 기타). 처음 제안("목록에 있음"까지만)은 미승인
- 내 도서관 화면(S10)의 "직접 도서관 추가"에서 후보 도서관을 이름으로 찾음. 방법(목록 통째로 / 서버 이름 검색)은 D에서 재 본 뒤 설계에서 정함 [확정] (사용자 승인, 2026-10-05, 캔버스 항목 8) → 설계에서 목록 통째로 + gzip [확정] (ADR-0058), dev 측정은 확인용. 직접 추가 상한 20곳 그대로 [안]
- 가져오기 범위: 모든 도서관의 책 (사이클 04의 "등록 도서관만"을 넓힘, ADR 필요). dev가 dry run으로 크기·시간을 먼저 잼 [확정] (사용자 승인, 2026-10-05, 캔버스 항목 5)
- **도서관 번호: 서비스에서 새 번호를 주고, 수집 DB 번호와 짝 맞추는 표를 둠** [확정] (사용자: "서비스에서 새 번호를 주고 짝 맞추는 표를 둠", 2026-10-05, 캔버스 항목 6 미승인). 처음 제안(수집 DB 번호 100001~를 그대로)은 미승인
- (2026-10-05 설계 때 더함) 교보 구독형 화면 기관 중 소장형(`library.lending_model = OWNED`)은 "구독형 · 바로 대출" 대신 숫자로 보임 [확정] (사용자 승인, 2026-10-05, 설계 Q3, ADR-0056)
- (2026-10-05 설계 때 더함) 북큐브·알라딘 "도서관에서 직접 찾기" 검색: 쪽 넘기기 시험 전까지 첫 쪽만, 알라딘 출판사 검색은 그 도서관 실패로 보임 [확정] (ADR-0056)

### D. 데이터 형식 파악 → 서비스 DB 형식과 검색 방법 최적화 [확정] (사용자 승인, 2026-10-05, 캔버스 항목 7)

- 수집 DB(`holding` 26칸, `library` 10칸)의 실제 값 모양을 화면 종류별로 파악: 칸마다 비어 있는 비율, 길이, 책 코드 모양, 자료 종류 값, 상세 주소 모양. plan이 사본을 읽기만 해서 셈
- 서비스 DB 형식 최적화: 소장 약 495만 → 약 2,100만 줄(사본 기준, 같은 사이트·빠진 책 제외 전)에 맞게 `catalog`의 책·사람·소장 표와 인덱스를 다시 봄 (pg_bigm, ADR-0032)
- 검색 방법 최적화: 책 검색(`GET /books`)이 늘어난 양에서도 빠르게, 후보 도서관을 이름으로 찾기
- 측정 기준(응답 시간 목표)은 `/feature-spec`에서 정함

### B. 수집 방법 재구성: 두 갈래 (사용자, 2026-10-05: "도서관 수집하는거랑(수집하면서 구독형은 마감 여부 확인하는 거랑) 도서관의 책 수집하는 거 그 두가지야")

- ① 도서관 수집: 어느 전자도서관이 있나(후보 찾기, 확인, 같은 사이트 거르기, 넣기) + 구독형 마감 여부 확인
- ② 도서관의 책 수집: 도서관마다 어떤 책이 있나(전체·신간, 이어 받기, 호출 예의)
- 두 갈래마다 "무엇을 받아 무엇을 내놓나"와 원칙·결정을 한 장씩으로 정리(plan), 도서관 목록 원본을 하나로(서비스 도서관 표), dev 쪽 절차·코드 정리는 인계서로 요청 [확정] (사용자 승인, 2026-10-05, 캔버스 항목 9)
- 돌고 있는 수집기는 멈추지 않음. 수집기를 dev 복사본으로 갈아타기와 코드 구조 정리는 수집이 한 바퀴 끝난 뒤 [확정] (사용자 승인, 2026-10-05, 캔버스 항목 10)

## 영향 받을 모듈 [안]

- `library`: 도서관 표에 후보 도서관 줄 추가(새 번호), 수집 DB 번호와 짝 맞추는 표, 화면 종류 값 둘 추가, 가입 조건 없는 도서관을 검색 계획에서 빼는 규칙(직접 추가면 넣음, ADR-0050과 맞춤), 공개 목록 크기 또는 이름 검색
- `catalog`: 가져오기 범위를 모든 도서관으로(`CollectedCatalog`의 "서비스에 없는 도서관" 제외 규칙, 짝 표로 번호 바꾸기), 표·인덱스 최적화
- `availability`: 북큐브·알라딘 adapter 둘
- `mylibrary`: 바뀌지 않음 (도서관 번호만 받음) → (설계 때 바뀜) 묶음 옮기기 `POST /api/v1/me/library-imports` 추가 (ADR-0057)
- `collection` (새, 설계 때 더함): 수집 번호 ↔ 서비스 번호 짝 표와 가져오기 전부 (ADR-0052, ADR-0060)
- 로고 (E, 설계 때 더함): `library` 표에 로고 칸(`logo_file`·`logo_visible`), 웹 정적 로고 파일, 새 화면 S12 `/about` (ADR-0059)
- 웹: S10 직접 추가에서 후보 도서관 찾기, 결과 줄(새 화면 종류)
- `fetch-service/`: 새 호스트(북큐브·알라딘) 호출 허용 여부 확인
- 수집 도구(dev `scripts/library/`, `scripts/crawl/`)와 문서(dev `docs/maintenance/`): 두 갈래 정리 요청
