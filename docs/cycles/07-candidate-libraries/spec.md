# 기능 명세: 후보 도서관 넣기 (+ 수집 방법 재구성, DB·검색 최적화)

- 작성: 2026-10-05. 범위: `scope.md` 포함 A·D·B·E. 조사: `research.md` 1절(북큐브·알라딘 대출 현황), 2절(수집 데이터 모양, 배포용 사본)
- 이름: **등록 도서관** = 지금 서비스 DB에 있는 278곳, **후보 도서관** = 수집 DB 번호 100001~의 웹러브 북스 기관 [확정] (사용자, 2026-10-04). 이 사이클이 끝나면 둘 다 서비스 도서관 표에 들어가고, 구분은 "가입 조건이 있는 도서관 / 없는 도서관"이 됨 (`collection-areas.md` 2-1절) → 가입 조사 상태 `join_survey`로 가름 (ADR-0053, R1-4)
- 가져올 원본: 배포용 사본 `chaekcheck-data\snapshots\ebook-catalog-2026-10-05-0745.sqlite` (`docs/research/ebook-catalog/snapshot-2026-10-05.md`)

## 사용자 이야기

- 대학·기관 전자도서관을 쓰는 로그인 이용자가, 그 도서관을 이름으로 찾아 내 도서관에 넣고 그 도서관의 책도 검색 결과에서 보고 싶다. 지금은 278곳만 고를 수 있어서.
- 이용자는 책이 많아져도 검색이 지금처럼 빨랐으면 한다.
- 이용자는 북큐브·알라딘 전자도서관에서도 지금 빌릴 수 있는지 보고 싶다.
- 운영자(사용자)는 도서관 수집과 책 수집을 두 갈래로 나눠, 각 갈래가 무엇을 받아 무엇을 내놓는지 한 곳에서 보고 싶다.

## 동작 규칙

### R1. 서비스에 넣는 후보 도서관

1. 가져오는 사본에서 전체 수집이 끝난 후보 도서관을 넣는다. 사본 기준 2,412곳 [확정] (사용자 승인, 2026-10-05). 받는 중 8곳·아직 217곳·실패 2곳은 다음 가져오기에서 [확정]
2. 등록 도서관과 같은 사이트로 표시된 곳(`crawl_skip` "same site as registered library …")은 넣지 않는다 [확정] (사용자, 2026-10-05, `collection-areas.md` 2-2절). 사본에도 99곳 표시됨 [확정] (2026-10-05 사본 조회; `research.md` 2절의 98곳은 셈 방식 차이)
3. 서비스는 새 번호를 주고, 수집 DB 번호와 짝 맞추는 표를 둔다 [확정] (사용자, 2026-10-05). 등록 도서관은 지금 번호 그대로이고 짝 표에서 같은 번호끼리 짝 [확정] (사용자 승인, 2026-10-05)
4. 수집 DB에는 이름·주소·화면 종류만 있다 (`periodic-tasks.md` 5절) [확정]. 그래서 후보 도서관마다 가입 조사 상태 `join_survey`를 둔다 [확정] (ADR-0053): 가입 조건을 조사한 후보 공공도서관은 `SURVEYED`(가입 규칙 줄 있음), 원문을 못 찾은 곳은 `NOT_FOUND`, 학교·대학·회사·기관 등은 `MEMBERS_ONLY`, 종류를 모르는 곳은 `NOT_SURVEYED`. `MEMBERS_ONLY`·`NOT_SURVEYED`는 지역·가입 방법 글·방문 가입 값이 없다
5. 같은 도서관이 다음 가져오기 때 다시 들어와도 번호가 바뀌지 않는다 (짝 표로 찾음) [확정] (사용자 승인, 2026-10-05)
6. 넣지 않는 곳 [확정]: 체험용·운영 중단으로 보이는 4곳(R3-3), 시험용 6곳 (사용자 승인, 2026-10-05, 설계 검토, `design-delta.md` seed 규칙). 이렇게 뺀 뒤 최종 후보 수 [확인 필요: seed 생성 때 셈]

### R2. 도서관 이름

- 서비스 도서관 이름은 서로 달라야 함(`library.name` UNIQUE). 후보 도서관끼리 이름이 같은 곳이 98묶음 211곳, 등록 도서관과 같은 이름이 27곳 (`research.md` 2절). 대부분 같은 기관이 화면 종류마다 사이트를 따로 둔 것(예: 강동대학교 북큐브·교보·YES24)
- 이름이 겹치면 뒤에 화면 종류의 한글 이름을 붙인다: 예) "강동대학교 (북큐브)", "강동대학교 (교보)", "강동대학교 (YES24)". 그래도 겹치면 사이트 주소의 호스트를 붙인다 [확정] (사용자 승인, 2026-10-05)

### R3. 보이는 규칙과 요청 [확정] (사용자, 2026-10-04: "직장/거주 없는 도서관들은 따로 '내 도서관'에서 등록하지 않은 한 기본적으로 안 보였으면 해 요청도 보내지 말고")

1. 가입 조사 상태(`join_survey`, ADR-0053)가 `MEMBERS_ONLY`·`NOT_SURVEYED`인 후보 도서관은, 그 이용자가 내 도서관에 직접 추가한 경우에만 검색 계획에 들어간다. "전체 도서관 | 내 도서관" 스위치와 상관없음. `SURVEYED`·`NOT_FOUND`는 지금 규칙을 따른다(`NOT_FOUND` = 자격 미확인, ADR-0013) [확정] (ADR-0053)
2. 계획에 없는 도서관에는 대출 조회 요청을 보내지 않고, 책 검색 결과에도 그 도서관이 나오지 않는다. 계획 도서관에 없는 책은 결과에서 빠진다(지금 규칙 `GET /books` "계획 도서관이 없는 책은 뺌")
3. 가입 조건이 확인된 후보 공공도서관(수집 세션의 사이클 밖 조사 `docs/research/library-join/candidates.md`)은 가입 규칙 줄을 더해 등록 도서관처럼 지역·직장으로 판정해 검색에 넣는다. 화면은 바뀌지 않고 데이터만 더함. 조사 결과가 인계 전에 오면 이번 가져오기에, 늦으면 다음 가져오기에 [확정] (사용자 승인, 2026-10-05, flow 결정 13). 1차 결과(2026-10-05 10시 무렵, 수집 세션): 후보 2,639곳 종류 = 초·중·고 1,254 / 대학 566 / 회사 332 / 정부·공공기관 231 / 공공도서관 120 / 단체·아파트 93 / 모름 37 / 시험용 6 (`chaekcheck-data\library-join\candidate-kinds-2026-10-05.tsv`). 공공도서관 120곳 조사 끝(2026-10-05, 수집 세션) = 지역 제한 88, 누구나 11, 누구나+주의 1, 소속 전용 2(대구학생전자도서관, 세종북자람), 원문 못 찾음 18. 원문 확인 103곳 중 방문 가입 필요 50, 불필요 52, 모름 18 (`public-join-2026-10-05.tsv`, dev join-classification과 같은 칸). 학교·대학·회사·기관은 미조사로 둠(직접 추가일 때만). 애매한 원문은 사용자가 정함 [확정] (2026-10-05, 표의 `decision` 칸, `docs/research/library-join/candidates.md` 3절): 전주는 전주·완주 + 책이음, 고창(교육청)은 고창군만, 전남교육청 12곳은 통합 시·도·방문 없이, 제천은 거주자만, 익산은 지역 제한. "책이음 회원도 가입 가능"은 2026-09-29 결정대로 지역 규칙 + `extra_condition_text`(9곳). 체험용·운영 중단으로 보이는 4곳(삼각산 북라이브, 대구동구안심 북큐브, 순창 북라이브, 양평 북큐브)은 서비스에 넣지 않음. 원문 못 찾은 곳은 자격 미확인(ADR-0013: 등록 도서관에서 규칙이 없는 곳과 같게 "가입 자격 확인 필요"로 검색에 나옴) [확정] (사용자, 2026-10-05) — `join_survey = NOT_FOUND`로 넣음 [확정] (ADR-0053)
4. 직접 추가한 후보 도서관은 ADR-0050대로 같은 책 안에서 맨 앞, 자격 규칙의 예외
5. 등록 도서관의 계획·순서·결과는 지금과 같다
6. 로그인하지 않은 이용자도 도서관을 직접 추가할 수 있다. 직접 추가는 이 브라우저에 저장하고(최대 20곳), 검색 때 웹이 `libraryIds`로 넘긴다(ADR-0037 그대로). 로그인하면 사이클 06 지역 옮기기(R2)와 같은 방식으로 "이 브라우저의 도서관도 계정에 저장할까요?"를 묻는다 [확정] (사용자 미승인 "로그인 하지 않더라도 직접 넣었으면 하는데... 훔..", 2026-10-05 → 다시 제안 → 승인). 사이클 06 "직접 추가는 로그인 뒤 서버 저장"을 넓힘

### R4. 가져오기 범위와 데이터 정리

1. 모든 서비스 도서관(등록 + R1의 후보)의 책을 가져온다 [확정] (사용자 승인, 2026-10-05). 사이클 04 spec 35행 "등록 도서관만"을 바꿈 → ADR
2. 제외 규칙은 지금 그대로(오디오북·동영상북, 빠진 책, http 아닌 주소, 호스트 불일치, 제목 없음, dev `CollectedCatalog`). 북큐브 `content_kind`의 `book/wma`·`book/vod`·`book/wmv`와 교보 `동영상`은 새 제외 규칙으로 뺀다(그대로 두면 `UNKNOWN`으로 들어옴) [확정] (사용자 승인, 2026-10-05, ADR-0054)
3. 북큐브 출판일 원문 `YYYYMMDD`(255,783줄)를 날짜로 읽는다 [확정] (사용자 승인, 2026-10-05)
4. 1950년 이전 날짜 17,748줄 중 17,311줄이 한 도서관(명지대학교)의 자리 채움 값으로 보임 → 날짜 없음으로 다룬다 [확정] (사용자 승인, 2026-10-05)
5. 같은 책 묶기 ①~④는 지금 규칙 그대로(`same-book-isbn.md` 5절). 기준을 바꾸는 일은 다음 수집 때 (사용자, 2026-10-05)

### R5. 북큐브·알라딘 대출 현황 [확정] 만들기 (사용자: "읽는 코드를 이번에 만들었으면 해", 2026-10-05)

- 북큐브: 책 한 권 XML `{base}/xml/productView/?num={num}`의 `volume`(보유)·`nowLendCount`(대출)·`nowReserveCount`(예약)를 읽음. 화면 숫자와 일치 [확정] (`research.md` 1절, 2026-10-05 호출 시험)
- 알라딘: 상세 화면 "보유현황 보유 N, 대출 N, 예약 N"을 읽음 [확정] (같은 곳)
- 읽은 숫자로 대출 가능 여부를 정하는 방법은 교보 일반·YES24와 같음(ADR-0019) [확정] (사용자 승인, 2026-10-05)
- 북큐브 구독(대여)형(보유 0, "동시이용제한 없이 이용 가능")은 교보 구독형처럼 "구독형 · 바로 대출"로 보인다 [확정] (사용자 승인, 2026-10-05)
- 호출 예의는 지금과 같음(같은 호스트 1건·1초, 캐시 3분) [확정] (사이클 01 spec 5.6)
- 교보 구독형 화면 기관 중 소장형(`library.lending_model = OWNED`)은 "구독형 · 바로 대출" 대신 보유·대출·예약 숫자를 보인다 [확정] (사용자 승인, 2026-10-05, 설계 Q3, ADR-0056). 숫자를 읽는 위치는 [확인 필요: dev 사이트 시험]
- 북큐브·알라딘 "도서관에서 직접 찾기"용 검색도 만든다. 쪽 넘기기를 시험하기 전까지는 첫 쪽만 읽고, 알라딘 출판사 검색은 그 도서관을 실패로 보인다 [확정] (ADR-0056)

### R6. 후보 도서관의 가입 정보 표시

- 결과 줄에서 도서관 이름을 누르면 열리는 창(사이클 06 뒤 dev가 만든 것)에 가입 조사 상태(`join_survey`)에 따라 아래 안내와 도서관 첫 화면 링크를 보인다 [확정] (사용자 승인, 2026-10-05, ADR-0053)
  - `SURVEYED`: 등록 도서관과 같은 가입 정보
  - `NOT_FOUND`: "가입 조건을 찾지 못했어요. 도서관 사이트에서 확인해 주세요"
  - `MEMBERS_ONLY`: "학교·회사 같은 기관의 구성원용으로 보여요. 이용할 수 있는지는 그 기관에 확인해 주세요"
  - `NOT_SURVEYED`: "가입 정보를 아직 조사하지 않았어요"
- 이름 옆 표시는 지금처럼 "직접 추가"

### R7. 데이터 형식과 검색 최적화 (D)

1. 소장 줄이 약 495만 → 약 2,100만 줄(사본, 같은 사이트 제외 뒤 2,151만 줄 중 넣을 몫)이 되어도 책 검색 응답 시간이 목표 안이다. 목표: 정해 둔 검색어 묶음에서 첫 쪽 응답이 1초 안(서버 측정, 지난번 "사랑" 224ms) [확정] (사용자 승인, 2026-10-05)
2. 같은 (플랫폼, 책 코드)가 평균 6.2곳에 있고, 서로 다른 (제목, 저자, 출판사)는 약 201만~225만 개다 (`research.md` 2절). 책 단위로 찾고 도서관 단위로 펼치는 지금 구조(책 → 소장)를 유지하고, 표·인덱스·저장 칸은 설계에서 다시 정한다 [확정] (사용자 승인, 2026-10-05)
3. 소장 줄의 약 70%가 상세 주소·표지 주소다. 주소는 지금처럼 줄마다 통째로 둔다 [확정] (사용자 미승인 뒤 다른 선택 "지금처럼 통째로 둠. 단순하지만 DB가 더 큽니다." 고름, 2026-10-05)
4. 내 도서관 화면의 도서관 찾기: 지금처럼 목록 통째로 받고 응답을 gzip으로 압축한다 [확정] (ADR-0058). dev 측정(목록 크기)은 확인용 (처음 "dev 측정 뒤 설계에서 정함" [확정] 사용자 승인 2026-10-05 → 설계에서 정함)
5. 가져오는 동안 책 검색이 기다리는 시간(지난번 약 2분 30초)이 늘 수 있다. 배포 전 한 번 가져오기라 이용자가 없어 문제 없음 [확정] (사용자 승인, 2026-10-05) (사용자 질문 "왜 기다리는 거야? 어짜피 운영 안되니까 문제 없는 거 아니야?", 2026-10-05 → 답: 맞음. 기다림은 가져오는 동안 표가 잠겨 생기고, 운영 중 다시 가져올 때만 문제)

### R8. 수집 방법 재구성 (B) [확정] (사용자 승인, 2026-10-05)

- 수집을 두 갈래로 정리한다: ① 도서관 수집(후보 찾기·확인·같은 사이트 거르기·넣기, 구독형 마감 여부 확인) ② 도서관의 책 수집. 가져오기는 그 뒤 단계
- plan: 두 갈래마다 "받는 것 / 내놓는 것 / 원칙 / 결정"을 한 장씩 쓰고, 흩어진 문서(`crawl-method.md`, `crawl-runbook.md`, `platforms.md`, `periodic-tasks.md`, `collection-areas.md`, `catalog-refresh.md`)의 해당 부분을 그쪽으로 모으거나 링크한다. 문서 이름·폴더 [확정] (사용자 승인, 2026-10-05): `docs/research/collection/1-libraries.md`, `2-books.md`
- 같은 사이트 거르기 규칙: http/https·포트를 무시한 호스트로 비교하고, 같은 호스트면 책 목록이 겹치는지 본다 [확정] (사용자, 2026-10-05)
- 도서관 목록 원본은 서비스 도서관 표 하나. ① 갈래가 찾은 도서관은 수집 DB에 먼저 들어가고, 가져올 때 짝 표로 서비스에 이어진다 [확정] (사용자 승인, 2026-10-05)
- dev 쪽 절차(`docs/maintenance/`)·코드(`scripts/library/`, `scripts/crawl/`) 정리는 인계서로 요청. 돌고 있는 수집기는 멈추지 않고, 갈아타기·코드 구조 정리는 수집이 한 바퀴 끝난 뒤 [확정] (사용자 승인, 2026-10-05)

### R9. 도서관 로고 [확정] 넣기 (사용자: "이번 사이클에 로고 넣을래 결정 번복이야", 2026-10-05)

1. 로고가 보이는 도서관: 등록 도서관 중 자체 로고가 있는 199곳(`registered-logos-2026-10-05.tsv` `OWN`). 업체 기본 로고·로고 없음·후보 도서관은 로고 자리에 빈 상자 [확정] (사용자: "빈 상자 보이도록 근데 이건 실제 화면 보고 나서 언제든 수정 가능", 2026-10-05, ADR-0059; 대상 구분은 사용자·수집 세션, 2026-10-05)
2. 보여 줄 자리 [확정] (사용자 승인, 2026-10-05): ① 결과 카드(S1·S3)의 도서관 이름 앞 ② 내 도서관 화면(S10)의 도서관 줄(자동 목록, 도서관 찾기 결과, 직접 추가한 도서관)

## 상태별 동작

- 로딩: 도서관 찾기·책 검색 모두 지금과 같음
- 결과 없음: 직접 추가한 후보 도서관에 그 책이 없으면 그 도서관 줄이 없음(지금과 같음). 도서관 이름 검색 결과가 없으면 "찾는 도서관이 없어요" [확정] (사용자 승인, 2026-10-05)
- 외부 사이트 오류·지연: 북큐브·알라딘도 지금 adapter와 같은 실패 표시(시간 초과 5초, fetch-service) [확정] (dev 코드, `research.md` 1절)
- 북큐브 XML에 그 책이 없거나 모양이 다름: 실패로 보이고 카드 링크(그 도서관 책 페이지)는 남김 [확정] (사용자 승인, 2026-10-05)
- 입력 오류: 지금과 같음

## 수용 기준

- AC-1: 로그인 이용자가 내 도서관 화면에서 후보 도서관 이름(예: 대학 이름)을 치면 그 도서관이 나오고, [추가]하면 직접 추가한 도서관 목록에 들어간다.
- AC-2: 이름이 같은 도서관이 여럿이면 찾기 결과에서 화면 종류 이름으로 구분된다(예: "강동대학교 (북큐브)").
- AC-3: 직접 추가한 후보 도서관이 가진 책을 검색하면 그 도서관 줄이 결과에 나온다(같은 책 안에서 맨 앞, "직접 추가").
- AC-4: 내 도서관에 넣지 않은 후보 도서관은 "전체 도서관"에서도 검색 계획(스트림 `targets`)과 결과에 없고, 그 사이트로 요청이 가지 않는다.
- AC-5: 후보 도서관에만 있는 책은 그 도서관을 직접 추가하지 않은 이용자의 책 검색(`GET /books`) 결과에 나오지 않는다.
- AC-6: 등록 도서관만 쓰는 이용자의 같은 검색어 결과(책 목록과 순서)가 이 사이클 전과 같다. (사이클 전 응답과 비교) → 회고(2026-10-05): 검색 대상과 가진 책은 같고, 같은 책 묶음이 합쳐져 생긴 권수·대표 제목·순서 차이는 받아들임 [확정] (사용자 승인, 2026-10-05, `retro.md`)
- AC-7: 북큐브 도서관 줄에 보유·대출·예약 수가 보이고, 그 책의 북큐브 상세 화면 숫자와 같다.
- AC-8: 알라딘 도서관 줄에 보유·대출·예약 수가 보이고, 그 책의 알라딘 상세 화면 숫자와 같다.
- AC-9: 북큐브 구독(대여)형 도서관 줄은 "구독형 · 바로 대출"로 보인다.
- AC-10: 같은 사이트로 표시된 곳은 서비스 도서관 표에 없고, 같은 도서관이 검색 결과에 두 번 나오지 않는다.
- AC-11: 가져오기 요약(`collection.catalog_import`)의 도서관 수가 등록 274 + 후보 R1 수와 맞고, 짝 표로 서비스 번호와 수집 DB 번호가 하나씩 이어진다.
- AC-12: 다시 가져와도 이미 들어온 후보 도서관의 서비스 번호가 바뀌지 않는다(같은 사본으로 두 번 가져와 비교).
- AC-13: 책 검색(`GET /books`) 응답 시간이 목표(첫 쪽 1초) 안이다(정해진 검색어 묶음, `EXPLAIN` 포함 dev 측정).
- AC-14: 후보 도서관 줄의 이름을 누르면 가입 조사 상태(`join_survey`)에 맞는 안내(R6: `NOT_FOUND`·`MEMBERS_ONLY`·`NOT_SURVEYED` 문구, `SURVEYED`는 등록 도서관과 같은 가입 정보)와 도서관 첫 화면 링크가 보인다.
- AC-15: 로그인하지 않고 직접 추가한 도서관도 없는 사람의 검색은 가입 조사를 한 공공도서관(지금 385곳)만 찾는다. 학교·대학·회사·기관처럼 구성원만 쓰는 도서관과 종류를 모르는 도서관은 찾지 않고, 그 사이트에 요청도 보내지 않는다. [확정] (사용자 제안, 2026-10-05, 회고). 처음 문장 "검색 결과는 이 사이클 전과 같다"는 ADR-0053과 함께 지킬 수 없어 바꿈(`retro.md`)
- AC-16: plan에 수집 두 갈래 문서가 있고, 각 문서에 받는 것·내놓는 것·원칙·결정·dev 절차 링크가 있다.
- AC-17: 백엔드 `./gradlew build`(`ModularityTests` 포함), 웹 `npm test`·`build`·`lint` 통과.
- AC-18: 로그인하지 않은 이용자가 내 도서관 화면에서 후보 도서관을 직접 넣으면 이 브라우저의 검색에 그 도서관이 나오고(요청에 `libraryIds`), 서버에는 아무것도 저장되지 않는다. 21번째는 막힌다.
- AC-19: 계정에 직접 넣은 도서관이 없고 브라우저에 있는 상태로 로그인하면 "이 브라우저의 도서관도 계정에 저장할까요?"가 지역 옮기기 창과 함께 한 번 나오고, 저장하면 계정의 직접 추가 목록에 들어간다.
- AC-20: 로고가 있는 등록 도서관은 결과 카드와 내 도서관 화면에서 이름 앞에 원본 그대로 줄인 로고가 보이고, 로고가 없거나(업체 기본 로고·로고 없음) 후보 도서관이면 그 자리에 빈 상자가 보인다. → 바뀜(2026-10-05): 로고는 이름 위 줄, 로고가 없으면 아무것도 그리지 않음 [확정] (사용자: "실제로 확인해보고 디자인 측면의 안정감때문에", 회고)
- AC-21: 모든 화면 바닥글의 "서비스 안내"를 누르면 제휴·후원 관계 없음 문구와 로고 내림 요청 연락 방법이 보인다.
- AC-22: 운영자가 한 도서관의 로고 표시를 끄면 새로고침한 화면에서 그 로고가 보이지 않는다.
- AC-23: 교보 구독형 화면 기관 중 `lending_model = OWNED`인 도서관 줄은 "구독형 · 바로 대출"이 아니라 보유·대출·예약 숫자로 보인다.
- AC-24: 북큐브·알라딘 도서관에서 "도서관에서 직접 찾기"를 하면 그 도서관 검색 첫 쪽 결과가 보이고, 알라딘 출판사 검색은 그 도서관이 실패로 보인다.

## 비목표

- 학교·대학·회사·기관 구성원 자격 조사 (`MEMBERS_ONLY`·`NOT_SURVEYED` 후보 도서관의 가입 자격 판정·필터, 지역·직장으로 자동으로 내 도서관에 넣기 포함) — 이유: 조사하지 않음(scope 제외). 후보 공공도서관 120곳 가입 조사는 포함(R3-3, ADR-0053)
- 같은 기관의 여러 사이트를 한 줄로 묶어 보이기 — [이유 미확인] (Claude 제안, 실물 도서관 사이클의 "운영 기관으로 묶는 테이블"과 같은 문제, backlog)
- 북큐브 `isReservable`·`isMaxLendLimit` 값 쓰기 — 로그인 없이 늘 true라 뜻을 모름 (`research.md` 1절)
- 북큐브 `alt_code`(원래 공급사 코드)로 다른 플랫폼과 같은 책 묶기 — 책 묶기 기준은 다음 수집 때
- 구독형 한도·마감 표시, 수집기 갈아타기, 갱신 기능 — scope 제외
