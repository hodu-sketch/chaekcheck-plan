불러오는 중

AI 책 찾기를 서버 안에서 어떻게 나눠 만들지 설계 제안이 나왔습니다. 정하실 것이 여덟 개입니다.

설계 담당 에이전트가 낸 대안과 추천을 쉬운 말로 옮겼습니다. 원문은 docs/cycles/24-ai-book-search/architect-proposal.md입니다. dev 코드는 이 세션에서 열 수 없어서, 지금 서버 모양은 plan 문서의 기록에 기댔습니다. 각 카드 맨 아래에서 고르고 "저장"을 눌러 주세요.

전체 모양

서버에 "AI 책 찾기" 전용 구역(모듈)을 새로 두고, 추천도서 구역에서 책 목록을 받아 Haiku에게 묻습니다. 찾기용 한 줄은 내 PC에서 파일로 만들어 따로 넣습니다.

flowchart TB
  web["화면: AI 탭 · 대화 화면"] -->|질문 보내기| ais["AI 책 찾기 구역 (새)"]
  web -->|직접 탭| cat["책 검색 구역 (지금 그대로)"]
  ais -->|목록 책 받기| pk["추천도서 구역"]
  ais -->|내 계획 도서관| lib["도서관 구역"]
  ais -->|횟수만 기록| ul["이용 기록 구역"]
  ais -->|질문과 후보| ant["Anthropic Haiku"]
  pc["내 PC: 찾기용 한 줄 만들기"] -.파일.-> col["가져오기 구역"]
  col -->|한 줄 넣기| ais

"구역"은 서버 코드를 나눈 단위(모듈)입니다. 구역끼리는 정해진 창구로만 주고받습니다.

sequenceDiagram
  participant W as 화면
  participant A as AI 책 찾기 구역
  participant H as Haiku
  W->>A: 질문 + 앞 대화 5번 + 내 도서관 조건
  A->>A: 횟수·오늘 비용 확인
  A->>H: 1차: 낱말로 바꿔 줘 (5초)
  H-->>A: 낱말, 제목 같음 여부
  A->>A: 목록 책 2,800권에서 낱말 맞추기 → 30권
  A->>H: 2차: 골라서 글 써 줘 (15초, 조금씩)
  loop 흘러오는 답
    H-->>A: 책 번호
    A->>A: 후보 안인지 확인
    A-->>W: 카드
    H-->>A: 그 책 글 조각
    A-->>W: 글 조각
  end
  A-->>W: 끝

한 질문이 지나가는 길입니다. 번호를 확인한 책만 화면에 나갑니다.

1AI 책 찾기를 어느 구역에 둘까

새 구역 "AI 책 찾기"(코드 이름 aisearch)를 두는 것을 추천합니다. 사이클 23이 지금 추천도서 구역을 크게 고치고 있어서, 같은 곳을 함께 고치면 두 작업을 합칠 때 부딪힙니다. 찾기용 한 줄 표도 이 새 구역이 가집니다.

안좋은 점잃는 것
(가) 새 구역 aisearch, 추천도서 구역에는 "목록 책 읽기" 창구 하나만 더함23과 거의 안 겹침. 나중에 찾는 범위를 넓히기 쉬움구역이 하나 늘어남
(나) 추천도서 구역 안에새 창구가 없음23과 같은 코드를 고쳐 충돌. 추천도서 구역이 외부 AI·요금까지 맡음

[안] #1 (가) 새 구역 aisearch를 두고, 추천도서 구역에는 목록 책을 읽어 가는 창구(ListedBooks) 하나만 더합니다.

2찾기용 한 줄을
운영 DB에 넣는 길

내 PC에서 만든 한 줄 파일을 따로 넣는 짧은 명령을 하나 두는 것을 추천합니다. 사이클 21에서 추천도서 목록을 넣을 때 쓰는 방식과 같아서 익숙하고, 몇 초면 끝납니다.

안좋은 점잃는 것
(가) 따로 넣는 명령 (search-lines)한 줄만 고쳐도 몇 초에 다시 넣음. 23과 안 겹침운영에서 명령을 하나 더 돌림
(나) 책 목록 전체를 반영할 때 함께 싣기할 일이 늘지 않음한 줄만 고쳐도 무거운 전체 반영을 돌려야 함. 23과 파일 형식 번호가 부딪힐 수 있음
(다) 서버 프로그램 안에 파일로 넣기가장 단순함한 줄 바꿀 때마다 다시 배포. "한 줄은 운영 DB로" 결정과 다름

[안] #2 (가) 따로 넣는 명령을 둡니다. 서버는 넣은 뒤 10분 안에 새 줄을 읽습니다.

3낱말 맞추기를 어디서 할까

목록 책은 2,800권뿐이라, 서버가 켜질 때 책 목록과 한 줄을 메모리에 올려 두고 거기서 맞추는 것을 추천합니다. 제목·저자는 추천도서 구역에, 한 줄은 AI 구역에 있어 DB 한 번에 맞추면 구역 경계를 넘기 때문입니다.

안좋은 점잃는 것
(가) 메모리에 올려 두고 맞춤, 10분마다 새로 올림구역 경계를 지킴. 빠를 것으로 봄(dev가 잼)서버 메모리를 조금 씀(2~3MB 추정)
(나) AI 구역 표에 제목·저자도 복사해 DB에서 맞춤메모리를 안 씀복사본이 추천도서와 어긋날 수 있음

[안] #3 (가) 메모리에서 맞춥니다. "과학 책"과 "과학책"은 같게 보고, 한 글자 낱말은 쓰지 않습니다.

4요청 횟수와 하루 비용을
어디에 셀까

같은 IP의 횟수는 서버 메모리에만 세고, 하루 쓴 돈은 DB에 날짜마다 한 줄로 적는 것을 추천합니다. IP를 DB에 남기지 않으면서, 서버를 다시 켜도 하루 $2 상한이 지켜집니다.

안좋은 점잃는 것
(가) IP 횟수는 메모리, 하루 비용은 DBIP가 남지 않음. 재시작해도 상한 유지재시작하면 IP 횟수는 처음부터
(나) 둘 다 메모리표가 없음재시작하면 오늘 비용도 0이 되어 $2를 넘을 수 있음
(다) 둘 다 DB재시작해도 다 남음IP를 DB에 적게 되어 처리방침이 늘어남

[안] #4 (가) IP 횟수는 메모리, 하루 비용은 DB에 날짜마다 한 줄. 하루는 한국 시간 자정에 바뀝니다.

비용 계산: 입력 100만 토큰당 $0.10, 출력 $0.50 (요청 하나가 10만 토큰 이하일 때, https://platform.claude.com/docs/en/about-claude/pricing , 2026-10-24 확인). 상한은 질문을 시작할 때만 보므로, 이미 돌고 있는 질문만큼(몇 센트) 넘을 수 있습니다.

5Haiku를 부르는 방식

서버가 Anthropic에 직접 요청을 보내는 작은 코드를 두는 것을 추천합니다. 지금 서버가 국립중앙도서관 API를 부르는 방식과 같고, 나중에 Ollama나 vast.ai를 같은 모양으로 붙일 수 있습니다.

안좋은 점잃는 것
(가) 직접 요청 (자바에 들어 있는 기능만)새 라이브러리 없음. 로컬 LLM도 같은 모양으로 붙음흘러오는 답을 읽는 코드를 직접 만들고 시험해야 함
(나) Anthropic 공식 자바 라이브러리흘러오는 답 읽기가 이미 있음의존이 늘고, 새 기능(정해진 답 형식)을 따라오는지 확인 필요. 로컬 LLM은 결국 다른 코드

[안] #5 (가) 직접 요청합니다. API 키는 운영 비밀 저장소(사이클 17과 같은 방식)에 넣고, 기록·오류 글에 남기지 않습니다.

Haiku 5.5는 답하기 전에 스스로 생각하는 기능이 기본으로 켜져 있습니다(공식 문서, 2026-10-24 확인). 1차를 5초 안에 끝내려면 끄거나 줄여야 할 수 있어, 시험에서 확인합니다. 노트북 시험에서도 생각하는 시간이 길어 오래 걸렸습니다.

6AI 탭에 책 제목만 넣었을 때

답 맨 위에 "「채식주의자」을(를) 찾으시나요? [직접 찾기에서 보기]" 줄을 붙이고, 그 아래 평소처럼 추천도서 안의 답을 내는 것을 추천합니다. 서버가 전체 책 목록(160만 권)에서 제목을 따로 찾아보지는 않고, 단추를 누르면 화면이 지금 직접 검색을 돌립니다.

안좋은 점잃는 것
(가) 제목 줄 + 평소 답그 책이 추천도서에 있으면 맨 앞에, 비슷한 책도 같이 봄Haiku를 두 번 다 부름
(나) 제목이면 곧장 직접 탭 검색으로바로 그 책을 찾음. 2차 비용이 없음제목처럼 보였지만 사실 질문이었으면 AI 답을 못 봄

단추에 뜨는 제목은 사용자가 쓴 글 안에 있는 말만 씁니다. Haiku가 지어낸 제목이 단추에 뜨지 않게 하려는 것입니다. 단추를 누르면 지금 직접 검색처럼 그 제목이 주소에 들어갑니다. 사용자가 직접 누른 것이라 "질문은 주소에 안 넣음"과 따로 보았습니다.

[안] #6 (가) 답 맨 위에 제목 줄을 붙이고 평소 답도 냅니다. 누르면 직접 탭으로 바뀌고 그 제목으로 검색합니다.

7이용 기록에 남길 칸

질문 글 없이 남기기로 한 것(횟수·걸린 시간·결과·후보 수·고른 책 번호)에 더해, "대화에서 몇 번째 질문인지"와 "쓴 토큰 수"를 남기는 것을 추천합니다. 방문 번호와 회원 번호는 남기지 않습니다.

남김시각, 걸린 시간, 1차 결과(성공·실패·시간 초과), 제목 같음 여부, 2차 결과, 후보 수, 고른 책 번호, 몇 번째 질문인지, 토큰 수
안 남김질문 글, IP, 방문 번호, 회원 번호

[안] #7 위 표대로 남깁니다. 몇 번째 질문인지는 이어서 묻기가 얼마나 쓰이는지, 토큰 수는 비용이 어디서 나는지 보는 데 씁니다.
