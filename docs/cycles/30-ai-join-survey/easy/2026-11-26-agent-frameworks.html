AI가 여러 단계를 거쳐 일하게 만드는 방법 다섯 가지를, 「도서관 한 곳의 가입 조건 알아내기」라는 같은 일에 대 보며 비교합니다.

결정 페이지 7번(어떤 틀로 짤지)에서 「LangGraph나 다른 대안들을 특징·공통점·차이점·실제 예시와 함께 쉽게」 요청하신 답입니다. 맨 끝에 고를 것 하나가 있습니다.

1다섯 가지가 모두 하는 일

다섯 가지 모두 속에서는 같은 일을 되풀이합니다. Claude에게 「쓸 수 있는 도구 목록」과 할 일을 주고, Claude가 도구를 쓰겠다고 하면 그 도구를 실행해 결과를 돌려주고, Claude가 「끝」이라고 할 때까지 반복합니다.

① 할 일 + 도구 목록을 Claude에게
→
② Claude: 「이 페이지를 받아 줘」도구를 쓰겠다는 답
→
③ 프로그램이 페이지를 받아 결과를 돌려줌
→
④ ②~③ 반복, Claude가 「끝, 답은 이것」

이 되풀이를 흔히 「에이전트 반복(agent loop)」이라고 부릅니다. 다섯 가지의 차이는 이 반복을 누가 짜고, 어디서 돌리고, 반복 바깥의 순서를 누가 정하느냐입니다.

또 하나 같은 점: 어느 쪽을 골라도 Claude는 Anthropic API로 부르고, 「승인 전에는 서비스에 넣지 않음」「같은 사이트 1.1초 간격」 같은 우리 규칙은 우리가 코드로 지켜야 합니다. 틀이 대신 지켜 주지 않습니다.

2다섯 가지 한눈에

위로 갈수록 내가 짜는 것이 많고, 아래로 갈수록 남(라이브러리·Anthropic)이 해 주는 것이 많습니다.

방법무엇인가내가 짜는 것어디서 도나
가. Python + Anthropic SDK 직접Anthropic 공식 Python 라이브러리로 Claude를 부르고, 반복과 순서를 내가 다 씀반복, 순서, 끊겼을 때 이어 가기, 승인 대기 전부내 PC
나. SDK의 도구 실행기(tool runner)같은 Anthropic 라이브러리 안의 도우미. 도구 함수만 주면 「도구 쓰기 → 결과 돌려주기」 반복을 라이브러리가 돌림도구 함수, 반복 바깥의 순서내 PC
다. LangGraph여러 단계를 「상자(노드)와 화살표」 그림으로 짜는 Python 라이브러리. 갈라지는 길, 진행 상태 저장, 멈췄다 이어 가기를 줌상자마다 할 일(그 안에서 Claude를 부름), 화살표내 PC
라. Claude Agent SDKClaude Code를 라이브러리로 만든 것. 파일 읽기·쓰기, 명령 실행, 웹 검색 도구와 반복이 처음부터 들어 있음할 일 글(프롬프트)과 허용할 도구내 PC
마. Managed AgentsAnthropic이 반복을 대신 돌려 주는 서비스. 도구는 Anthropic의 클라우드 작업 공간이나 내 PC에서 실행에이전트 설정(할 일, 도구), 결과 받기반복은 Anthropic, 도구는 클라우드 또는 내 PC
방법순서를 누가 정하나끊기면 이어 가기추가 비용배울 수 있는 것
가내 코드직접 만들어야 함없음API 자체, 반복의 원리

다그림(내가 그린 화살표) + 상자 안에서 Claude있음 (상태를 파일에 저장)없음 (오픈소스, MIT)워크플로·에이전트 설계, 상태 관리, 사람 승인 끼우기

3같은 일을 다섯 가지로 하면

할 일: 「광산구통합도서관의 가입 조건을 원문 인용과 함께 알아내고, 지금 값과 다르면 승인을 받는다」. 각 방법에서 무엇을 쓰게 되는지 보입니다.

가. Python + SDK 직접

근거 모으기 스크립트 실행
→
if 근거 있음: Claude 한 번 호출값+인용
→
else: while 반복을 직접 씀페이지 받기 ↔ Claude
→
인용 대조, 보고서 파일

중간에 PC가 꺼지면? 「어디까지 했나」를 적는 파일을 직접 만들어야 합니다. 승인은 보고서를 연 뒤 다시 다른 명령으로 반영합니다.

나. 도구 실행기

근거 모으기 스크립트 실행
→
못 찾은 곳: 도구 함수 「같은 사이트 페이지 받기」만 주고 실행기 호출반복은 라이브러리가
→
인용 대조, 보고서

가와 같지만 while 반복을 안 씁니다. 「최대 5장」은 도구 함수 안에서 세어 막습니다. 이어 가기·승인 대기는 가처럼 직접.

대괄호 하나가 상자(노드) 하나입니다. 상자 안은 보통 Python 함수라 Anthropic SDK를 그대로 부릅니다. 진행 상태가 내 PC의 파일 하나(SQLite)에 저장돼, 400곳 중 200곳에서 끊겨도 201번째부터 이어 갑니다. 「승인 기다림」에서 멈춰 두었다가 승인하면 그 자리에서 이어 갑니다. 주의: 이어 갈 때 그 상자는 처음부터 다시 돌아서, 같은 페이지를 또 받지 않게 짜야 합니다.

라. Claude Agent SDK

할 일 글: 「이 도서관 사이트에서 가입 조건을 찾아 이 칸들로 적어라」
→

→

지금 이 대화의 Claude Code가 하는 방식과 같습니다. 짜는 것은 가장 적지만, 파일 쓰기·명령 실행까지 쥔 AI가 도서관 페이지 글을 읽게 됩니다. 페이지 속에 AI에게 시키는 글이 숨어 있으면 위험이 큽니다(결정 페이지 3번에서 「같은 사이트 페이지 받기 하나만」으로 정한 것과 맞지 않음). 도구를 좁힐 수는 있습니다.

마. Managed Agents

에이전트 설정 한 번 등록
→
도서관마다 「세션」 시작
→
Anthropic이 반복을 돌림, 도구 호출은 클라우드 또는 내 PC 워커가 실행
→
결과를 받아 내 PC에서 보고서

반복을 내 PC에서 돌리지 않아도 됩니다. 도구를 Anthropic 클라우드에서 실행하면 해외에서 도서관 사이트에 접속하게 되어, 국내 접속만 받는 사이트는 막힐 수 있습니다(추론). 내 PC 워커로 돌리면 이 문제는 없지만 그만큼 설정이 늘어납니다. 아직 beta이고, 도는 시간만큼 시간당 $0.08이 붙습니다.

5고를 것: 틀

[안] 세 갈래의 흐름은 LangGraph(다)로 짭니다. 진행 상태는 내 PC의 SQLite 파일 하나에 두고, 상자 안에서는 Anthropic 공식 Python SDK로 Claude를 부릅니다(LangChain의 모델 묶음은 쓰지 않음). 「사이트 찾기」 상자 안의 반복은 SDK로 짜며, 도구는 같은 사이트 페이지 받기 하나만 줍니다. 운영 서버는 바뀌지 않습니다.

다른 선택: 가(SDK 직접) — 가장 단순하지만 이어 가기·승인 대기를 손으로 만듭니다. 라(Agent SDK) — 짜기는 가장 쉽지만 도구가 넓어 도서관 페이지 속 지시문에 약합니다. 마(Managed Agents) — beta·시간 요금, 국내 사이트 접속 때문에 결국 내 PC 워커가 필요합니다.
