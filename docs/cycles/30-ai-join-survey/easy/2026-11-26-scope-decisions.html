도서관 가입 조건을 AI가 다시 읽어 오게 하는 사이클 30의 범위를 정합니다. 8개를 골라 주세요.

원본: docs/cycles/30-ai-join-survey/scope.md. 2026-10-27 조사(docs/research/ai-collection/overview.md)에서 낸 방향 5개는 답이 저장되지 않아, 오늘 확인한 사실을 더해 여기서 다시 묻습니다.

지금은 어떻게 하나

가입 조건은 지금 스크립트가 근거 문장을 모으고, 사람(Claude 세션)이 그 문장을 읽고 값을 정합니다.

  • collect_join_evidence.py(dev에 이미 있음): 도서관 홈페이지에서 시작해 「회원가입」「회원증」 같은 낱말이 든 같은 사이트 링크를 따라가고, 최대 9장을 받아 가입 자격 문장만 남깁니다. 같은 사이트에는 1.1초 간격으로 한 번에 하나만 부릅니다. 스스로 정하는 것은 없습니다.
  • 그 문장을 사람이 읽고 근거(거주·재직·재학·누구나), 범위(시군구·시도), 방문 가입 여부, 가입 방법을 표에 적습니다.
  • 값이 있는 파일: public_join.tsv(사이클 07 이후 넣은 공공도서관 121줄, 원문 인용·출처 주소 포함), join_overrides.tsv(사람이 정한 값 21줄, 마지막에 이김). 마지막 조사 기준일은 2026-10-05입니다.

확인: dev 파일 직접 열어 봄, 2026-11-26. 등록 도서관 나머지 값이 어느 파일에 있는지는 확인 못 함.

바꾸면 이렇게 됩니다

사람이 읽던 단계를 AI가 하고, 사람은 「지금 값과 달라진 곳」만 봅니다.

① 근거 문장 모으기지금 스크립트 그대로
→
② AI가 값과 인용문을 냄새로 만듦
→
③ 인용문이 원문에 있는지 확인스크립트, 새로 만듦
→
④ 지금 값과 다른 곳만 보고서새로 만듦
→
⑤ 사용자가 승인한 줄만 파일에 반영그 뒤는 지금 넣기·반영 절차

파란 상자가 이번에 새로 만드는 것입니다. 초록 상자 전까지는 서비스 화면이 바뀌지 않습니다.

예: 어느 시립도서관이 「관내 재직자도 정회원」을 새로 넣었다면, ②에서 AI가 근거에 「재직」을 더하고 원문 문장을 그대로 인용합니다. ③에서 그 문장이 받은 페이지에 정말 있는지 확인하고, ④ 보고서에 「기존: 거주 / 새로: 거주·재직」 한 줄이 나옵니다. 승인하면 그 도서관 화면의 가입 조건 글이 바뀝니다.

1이번 사이클은 가입 조건만 합니다

[안] 세 갈래(도서관 찾기, 가입 조건, 책 수집) 중 가입 조건만 이 사이클에서 합니다. 나머지 둘은 백로그로 둡니다.

까닭(제안): 사람이 원문을 다 읽던 곳이라 줄어드는 일이 가장 크고, 한 사이클 크기에 맞습니다.

다른 선택: 세 갈래를 한 번에 하면 도서관 찾기(종류 나누기 초안)와 책 수집기 고장 진단까지 들어가서, 시험·승인 화면이 세 벌이 됩니다. 한 사이클보다 큽니다.

2대상은 지금 가입 조건 값이 있는 공공도서관 전부

[안] 지금 서비스에 가입 조건이 들어 있는 공공도서관을 모두 다시 봅니다(약 400곳 어림, 실제 수는 세어 봐야 함). 학교·대학·회사·기관처럼 구성원만 쓰는 곳은 지금처럼 조사하지 않습니다.

다른 선택: public_join.tsv의 121곳만 하면 파일 하나만 다루어 더 작지만, 처음 등록한 도서관들은 2026-10-05 이전 값 그대로 남습니다.

3근거를 못 찾은 곳만 AI가 사이트 안을 찾아갑니다

[안] ①은 지금 스크립트를 그대로 씁니다. 이 스크립트가 가입 자격 문장을 하나도 못 찾은 도서관에서만, AI가 그 사이트 안 링크를 골라 가며 가입 안내 페이지를 찾습니다. 이것이 이번 일 가운데 「에이전트」(다음에 열 페이지를 AI가 고름)인 부분입니다.

  • AI가 쓸 수 있는 것: 같은 사이트 페이지 받기 하나. 도서관마다 최대 5장, 같은 1.1초 간격.
  • 다른 사이트로 나가기, 글쓰기, 파일 쓰기는 주지 않습니다. 도서관 페이지 안에 AI에게 시키는 글이 숨어 있어도 할 수 있는 일이 없게 하려는 것입니다.

다른 선택 1: 못 찾은 곳은 목록으로만 내고 사람이 봅니다. 가장 단순하지만, 못 찾은 곳이 많으면 사람 일이 남습니다.
다른 선택 2: 모든 도서관을 처음부터 AI가 찾아갑니다. 지금 스크립트가 이미 잘 찾는 곳까지 AI 호출이 늘어 비용과 시간이 커집니다.

5먼저 20곳 시험, 90% 같으면 전체로

[안] 공공도서관 20곳으로 AI 값을 2026-10-05 조사값과 견줍니다. 근거·범위·방문 가입 세 칸이 모두 같은 곳이 90% 이상이면 전체를 돌립니다.

다른 곳은 Claude 세션이 원문을 다시 열어 누가 맞는지 확인합니다. 사용자 시간은 쓰지 않습니다(사용자: "이건 내 시간이 안 되는데", 2026-10-27).

다른 선택: 시험 없이 바로 전체. 빠르지만 AI가 어떤 식으로 틀리는지 모른 채 400곳 보고서를 받게 됩니다.
기준을 80%로 낮추면 더 쉽게 넘지만, 보고서에서 사람이 걸러야 할 줄이 늘어납니다.

6승인 전에는 서비스가 바뀌지 않습니다

[안] ③ 인용 확인을 통과하고 지금 값과 다른 줄만 HTML 보고서 한 장에 모읍니다. 줄마다 기존 값, 새 값, 원문 인용, 출처 링크, 승인/미승인 고르기가 있습니다. 승인한 줄만 규칙 파일에 고쳐지고, 그 뒤는 지금 넣기·반영 절차로 들어갑니다.

  • 인용문이 받은 원문에 없으면(AI가 지어냈을 수 있음) 보고서에 「확인 못 함」으로 따로 모읍니다.
  • 값이 같은 곳은 보고서에 넣지 않고, 조사 기준일만 새 날짜가 됩니다.

다른 선택: 인용 확인을 통과한 값은 승인 없이 바로 반영합니다. 사람 일은 줄지만, 잘못 읽은 값이 「가입 가능」으로 바로 보일 수 있습니다.

7내 PC에서, Python + Claude API로

[안] 지금 수집기·가져오기와 같은 내 PC에서 Python 스크립트로 돌립니다. Claude는 Anthropic 공식 Python SDK로 부릅니다. LangGraph나 Anthropic Managed Agents는 쓰지 않습니다. 운영 서버 메모리·연결은 늘지 않습니다.

다른 선택무엇을 주나걸리는 점
LangGraph(Python)여러 단계, 승인 기다렸다 이어 가기이번 흐름은 한 줄로 이어지는 다섯 단계라 필요 없음. 체크포인트 표 관리가 생김
Managed Agents(Anthropic이 돌려 줌)PC 없이 예약 실행베타, 실행 시간도 과금(Anthropic 안내, 공식 페이지 주소 확인 못 함). 해외에서 접속해 국내 접속만 받는 도서관 사이트가 막힐 수 있음(추론)

질문: LangGraph는 왜 안 되나요? (7번에 대한 답)

안 되는 것은 아닙니다. 처음 제안은 「가입 조건만, 한 줄로 이어지는 다섯 단계」여서 틀이 없어도 된다는 뜻이었습니다. 지금은 세 갈래 모두 하기로 하셨고 학습용이라는 목적도 있어서, LangGraph를 쓰는 쪽을 대화에서 다시 여쭙니다.

  • 이번 일에 LangGraph가 맞는 곳: 「근거를 찾았나?」에 따라 갈라지는 길(찾았으면 값 읽기, 못 찾았으면 AI가 사이트 안 찾기), 사용자 승인에서 멈췄다가 이어 가기, 400곳을 돌다 끊겼을 때 이어 가기.
  • 노드는 보통 Python 함수라 Anthropic 공식 SDK를 그대로 부를 수 있습니다. 상태는 내 PC의 파일 하나(SQLite)에 둘 수 있어 운영 서버는 그대로입니다.
  • 걸리는 점: 멈췄다 이어 가면 그 단계가 처음부터 다시 돌아서, 같은 페이지를 또 받거나 AI를 또 부를 수 있습니다. 같은 결과가 나오게 짜야 합니다. 상태 파일도 쌓이므로 다 끝난 실행은 지워야 합니다.

근거: PyPI langgraph 1.2.24 (2026-11-20 배포, MIT, Python 3.10 이상), LangGraph 문서 graph-api·persistence·checkpointers 페이지 (확인 2026-11-26). 자세한 것: research.md 1절.

8이번에는 손으로 한 번 돌립니다

[안] 이번 사이클에서는 사용자나 Claude 세션이 명령으로 한 번 돌립니다. 몇 달마다 저절로 도는 예약 실행은 백로그(「도서관 정보 주기적 재조사」)에 그대로 둡니다.

다른 선택: 이번에 예약까지 넣으면 PC가 꺼져 있을 때, 실패했을 때 알림을 어떻게 할지까지 정해야 해서 범위가 커집니다.

질문: 8번이 무슨 말인가요? (풀어 쓴 답)

「이 조사를 누가, 언제 돌리나」를 정하는 항목입니다.

  • 손으로 돌리기: 다시 조사하고 싶을 때 사용자나 Claude 세션이 내 PC에서 명령 한 줄을 칩니다. 이번 사이클에서는 한 번 돌리고 보고서를 받습니다. 다음 조사는 또 필요할 때 칩니다.
  • 예약 실행: 예를 들어 석 달마다 정해진 날 저절로 돌고, 끝나면 보고서가 생깁니다. 사람이 잊어도 돕니다. 대신 그날 PC가 꺼져 있거나 중간에 실패하면 어떻게 알릴지까지 정해야 합니다.

처음 제안은 이번엔 손으로 돌리고 예약은 나중으로 미루자는 것이었습니다. 이 항목도 대화에서 다시 여쭙니다.
