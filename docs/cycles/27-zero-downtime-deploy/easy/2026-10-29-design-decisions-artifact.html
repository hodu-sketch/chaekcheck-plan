불러오는 중

서버 안에서 파랑·초록 두 자리를 어떻게 두고,
무엇으로 바꿔 끼울지 정합니다.

사이클 27 설계 제안(architect-proposal.md)입니다. dev의 배포 파일을 직접 읽고 썼습니다. 새 모듈·표·API는 없고 배포 파일만 바뀝니다. 정할 것은 6개입니다.

먼저: 바뀐 뒤 서버 모습

칸지금바뀐 뒤
서비스(백엔드)backend 하나backend-blue, backend-green 둘. 평소엔 하나만 떠 있음
nginx화면 파일·설정이 이미지 안에 → 판 바꿀 때마다 다시 만듦고정 판 nginx. 화면 파일·설정은 서버 폴더에서 읽음 → 다시 만들지 않음
어느 자리가 일하나—서버 파일 하나에 적음
배포 명령release.sh 1.21.0같음. 서버에서 새 스크립트가 바꿔 끼움

새로 확인한 것: 화면은 처음에 한 번에 다 받는 구조라(나중에 나눠 받는 조각 없음), 화면 판을 바꿔도 이미 열린 화면은 그대로 돕니다. 계정 삭제 뒤처리는 두 번 돌아도 결과가 같습니다(dev 코드 확인).

처음 한 번: 지금 구조에서 새 구조로 옮기는 첫 배포 때만 짧게 끊깁니다(점검 배포).

1두 자리는
서비스 두 개로

안 #1 배포 설정에 서비스를 backend-blue, backend-green 두 개로 둡니다. 이름이 달라서 nginx가 정확히 한쪽만 가리킬 수 있습니다. 공통 설정은 한 번만 쓰고 둘이 같이 씁니다.

지금 서비스가 잡고 있는 서버 포트 8080은 없앱니다. 운영 스크립트·문서에서 쓰는 곳이 없습니다(PC에서 재는 스크립트만 씀).

다른 선택: 서비스 하나를 둘로 늘리기 — 둘이 같은 이름이라 nginx가 옛 판·새 판에 나눠 보냅니다.

다른 선택: 자리마다 배포 묶음을 따로 — 비밀값·네트워크 설정이 두 벌이 됩니다.

2어느 자리가 일하는지
서버 파일 하나에 적기

안 #2 /srv/chaekcheck/slots.env에 "지금 일하는 자리, 파랑 판 번호, 초록 판 번호, 화면 판 번호"를 적습니다. 배포 설정이 이 파일에서 판 번호를 읽어서, 지금처럼 PC에서 설정 파일을 고쳐 보낼 필요가 없어집니다.

예: ACTIVE_SLOT=blue, BACKEND_BLUE_VERSION=1.20.0, BACKEND_GREEN_VERSION=1.21.0, WEB_VERSION=1.21.0

바꿔 끼우다 중간에 끊겨도, 다음에 서버를 올릴 때 이 파일을 기준으로 nginx가 가리킬 곳을 다시 만듭니다. "일하는 자리"는 nginx 전환이 끝난 뒤에만 바꿉니다.

3화면 판은 폴더 바꾸기로,
nginx는 그대로

안 #3 nginx는 판을 고정한 기본 이미지로 바꾸고, 화면 파일과 nginx 설정은 서버 폴더(/srv/chaekcheck/web, /srv/chaekcheck/nginx)에서 읽게 합니다. 새 화면은 판마다 폴더(releases/1.21.0)에 두고 "지금 판" 표시(current 링크)만 바꾼 뒤 nginx가 다시 읽게 합니다. 되돌리기는 표시를 앞 판으로 돌리는 것입니다.

화면 파일은 지금처럼 이미지로 만들어 보내고, 서버에서 꺼내 폴더에 둡니다. 그래서 만들기·보내기·정리 흐름은 거의 그대로입니다. 폴더는 판 두 개만 남깁니다. 앞 판의 화면 조각도 새 폴더에 같이 두어, 바뀌는 순간에 화면을 막 연 사람이 조각을 못 받는 일을 막습니다.

nginx 프로그램 판을 올릴 때는 컨테이너를 다시 만들어야 해서 점검 배포입니다(DB·Tunnel과 같은 취급).

다른 선택: 화면 이미지를 없애고 파일 묶음을 바로 보내기 — 판 관리·되돌리기 규칙을 새로 짜야 합니다.

다른 선택: 떠 있는 nginx에 파일을 밀어 넣기 — 컨테이너가 다시 만들어지면 옛 화면으로 돌아갑니다.

4준비 확인은 같은 포트,
nginx 컨테이너 안에서 부르기

안 #4 준비 확인 주소는 서비스의 원래 포트(8080)에 둡니다. nginx는 /api/만 서비스로 넘겨서 바깥에서는 이미 404이고, 안전하게 /actuator/를 막는 줄을 하나 더 둡니다. 확인은 nginx 컨테이너 안에서 새 자리를 1초마다 부릅니다(최대 3분). 새 자리가 꺼지거나 다시 시작한 적이 있으면 바로 실패로 봅니다.

nginx 안에서 부르면 nginx가 실제로 쓸 바로 그 길을 확인하게 됩니다. 같은 길로 판 번호(/api/v1/version)도 맞는지 봅니다.

다른 선택: 준비 확인만 다른 포트로 — 연결·스레드가 더 생기고 설정이 늘어납니다.

다른 선택: Docker 건강 검사 기능 — 서비스 이미지에 확인 도구(curl)가 없고, 10초마다 프로세스가 하나 더 뜹니다.

5바꿔 끼우기는
서버의 새 스크립트 하나로

안 #5 서버에 bin/switch.sh를 새로 둡니다. 새벽 시간 검사 → 새 자리 띄우기 → 준비 확인 → nginx 전환 → 2초 기다림 → 옛 자리 내리기 → 결과 한 줄. release.sh는 마지막에 이걸 부릅니다. 되돌리기는 release.sh --switch-only 1.20.0로, 서버에 있는 판이면 만들기·보내기 없이 전환만 합니다.

2초 기다림: nginx가 전환된 직후 옛 자리에 이어져 있던 연결이 새 요청을 거절당하는 짧은 틈을 막습니다. 실제로 충분한지는 완료 확인(1초마다 불러 보기) 때 봅니다.

옛 자리 컨테이너는 내리기만 하고 지우지 않아, 문제가 있으면 로그를 볼 수 있습니다. 새벽 검사는 PC에서도 시작할 때 한 번 해서, 이미지를 다 만든 뒤에야 막히는 일이 없게 합니다.

다른 선택: 지금 있는 up.sh에 덧붙이기 — 비밀값 읽기와 전환이 한 파일에 섞입니다.

아직 재야 하는 것

서버 메모리·스왑, 서비스가 뜨는 시간. 설계 확정(인계) 전에 필요합니다. 서비스 둘이 겹칠 때 메모리가 바닥나면 리눅스가 DB를 끌 수도 있어서, 측정 뒤 스왑 크기를 정합니다.

free -m; swapon --show; docker stats --no-stream; docker logs chaekcheck-backend-1 2>&1 | grep Started

준비 확인이 쿠버네티스 밖에서도 켜지는지와 2초가 충분한지는 dev가 처음 만들 때 확인합니다.
