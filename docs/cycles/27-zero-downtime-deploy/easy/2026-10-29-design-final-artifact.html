nginx는 그대로 떠 있고, active-backend.conf가 가리키는 한 자리로만 /api/를 보냅니다.

그림 2. 서비스(백엔드) 배포

sequenceDiagram
  participant R as release.sh (PC)
  participant S as switch.sh (서버)
  participant G as 새 자리
  participant N as nginx (web)
  participant B as 옛 자리
  R->>R: 03:25~05:10이면 거부
  R->>S: backend X.Y.Z (이미지 전송 뒤)
  S->>S: 03:25~05:10이면 거부, slots.env에 새 자리 판 번호
  S->>G: up -d --no-deps (시작 때 Liquibase)
  loop 1초마다, 최대 60초
    S->>N: exec wget G:8080/actuator/health/readiness
  end
  alt 60초 초과 또는 새 자리 종료·재시작
    S->>G: logs --tail, stop
    S-->>R: 실패 (이유, 옛 판 번호), 종료 코드 1
  else UP
    S->>N: exec wget G:8080/api/v1/version (판 번호 확인)
    S->>N: active-backend.conf 쓰기 → nginx -t → nginx -s reload
    S->>S: 2초 기다림, slots.env ACTIVE_SLOT 변경
    S->>B: stop (Docker 60초, Spring 정상 종료 40초)
    S-->>R: 성공 (새 판 번호)
  end

준비 확인은 1초마다 최대 60초. 안 되면 nginx는 건드리지 않습니다.

그림 3. 화면 배포와 되돌리기

sequenceDiagram
  participant R as release.sh (PC)
  participant S as switch.sh (서버)
  participant N as nginx (web)
  R->>S: web X.Y.Z (web 이미지 전송 뒤)
  S->>S: 이미지에서 dist 꺼내 releases/X 에 둠, 앞 판 assets 함께 복사
  S->>S: current 링크 → releases/X (ln -sfn + mv -T)
  S->>N: nginx -t → nginx -s reload
  S->>S: slots.env WEB_VERSION 변경, releases는 두 판만 남김
  S-->>R: 성공
  Note over R,S: 되돌리기 = release.sh --switch-only 앞판 (서버에 이미지·폴더가 있으면 만들기·전송 없이 같은 전환)

화면은 판 폴더를 만들고 current 링크만 바꿉니다.

그림 4. 자리 하나의 상태

stateDiagram-v2
  [*] --> 쉼
  쉼 --> 뜨는중: switch.sh up
  뜨는중 --> 쉼: 60초 초과·종료 → stop (실패)
  뜨는중 --> 일함: 준비 UP → nginx reload
  일함 --> 내려가는중: 다른 자리가 일함이 됨 → stop
  내려가는중 --> 쉼: 정상 종료 (최대 40초, Docker 60초)

파랑·초록이 이 순서를 번갈아 돕니다.

1ADR-0167
같은 서버 블루·그린

안 #1 백엔드를 backend-blue·backend-green 두 자리로 번갈아 쓰고, slots.env에 기록하고, switch.sh가 전환합니다. 준비 60초, 정상 종료 40초, Docker 60초. 되돌리기는 release.sh --switch-only.

버린 안: 서버 두 대 + 로드밸런서, 끊김 두고 안내 화면, 서비스 하나를 둘로 늘리기, up.sh에 덧붙이기.

2ADR-0168
nginx 고정, 화면은 폴더로

안 #2 nginx는 판을 고정하고 화면 파일·설정은 서버 폴더에서 읽습니다. 화면 판은 releases/판 폴더 + current 링크로 바꿉니다. nginx 판 올리기는 점검 배포.

버린 안: 화면 파일을 묶음으로 바로 보내기, 떠 있는 nginx에 밀어 넣기.

3ADR-0169
준비 확인

안 #3 Actuator health만 열어 같은 포트 8080의 /actuator/health/readiness를 nginx 컨테이너 안에서 부릅니다. 바깥은 /actuator/ 404 줄로 막습니다.

이유: “60초로 줄이고 4번 승인” (2026-10-29). 버린 안: 다른 포트, 자리별 서버 포트, Docker 건강 검사.

4ADR-0170
DB 변경 규칙

안 #4 무중단 배포에는 옛 판이 그대로 돌 수 있는 DB 변경만 싣고, 이름 바꾸기·지우기는 배포 두 번으로 나누고, 못 나누면 점검 배포. 앞으로 모든 사이클에 적용.

버린 안: 나누지 않고 강행.

5ADR-0171
겹칠 때 상태·새벽 배포

안 #5 바뀌는 순간 서버마다 따로 갖는 상태(막힌 길, AI 한도, 캐시, 로그인 중 세션)는 그대로 받아들이고, 03:25~05:10에는 배포를 거절합니다.

버린 안: 같이 쓰는 저장소(Redis), 정해진 일 DB 잠금(ShedLock).

dev에 넘길 때 확인할 것

쿠버네티스 밖에서도 준비 확인 주소가 열리는지, 전환 뒤 2초 기다림으로 실패 0건이 되는지는 dev가 처음 만들 때 확인합니다. 처음 새 구조로 옮기는 배포 한 번은 짧게 끊깁니다.
