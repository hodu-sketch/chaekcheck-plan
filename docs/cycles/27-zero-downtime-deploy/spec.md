## 동작 규칙

1. **한 번에 한 판만 요청을 받음.** nginx는 늘 한 자리(블루 또는 그린)만 바라봄. 전환은 nginx 설정 다시 읽기(reload)로 하고, nginx 컨테이너는 다시 만들지 않음 [확정] (범위 #1·#2)
2. **순서**: 새 판을 빈 자리에 띄움 → 준비 확인 통과 → nginx가 새 자리를 바라보게 reload → 옛 판에 정상 종료 신호 → 옛 판은 받던 요청(스트림 포함)을 끝내고 내려감 [확정] (범위 #1)
3. **겹치는 시간은 옛 판이 받던 요청이 끝날 때까지만.** 이 동안 서버마다 따로 갖는 상태(Webshare 길 간격, 막힌 길, AI IP 한도, 캐시, 로그인 진행 중 세션)는 나뉘거나 새 판에서 처음부터 시작함. 대부분 지금 재시작 배포와 같고, 길 간격만 최대 약 35초 동안 잠깐 2배가 될 수 있음 → 그대로 받아들임 [확정] (사용자 승인, 명세 결정 페이지 2026-10-29) (`research.md` 4-2)
4. **화면(web) 판 바꾸기**: nginx 컨테이너를 다시 만들지 않고 정적 파일만 바꾼 뒤 reload [확정] (범위 #2). 파일을 바꾸는 방법은 설계에서 정함
5. **실패하면 옛 판 그대로**: 새 판이 준비 기다리는 최대 시간 안에 준비되지 않으면 nginx를 건드리지 않고 새 판을 내림 [확정] (범위 #3)
6. **DB 변경**: 새 판이 시작할 때 Liquibase가 돌고, 옛 판은 바뀐 DB에서 계속 돎. 그래서 칸 지우기·이름 바꾸기·함수 본문을 옛 판과 안 맞게 바꾸기는 두 번에 나눔. 지킬 수 없으면 "점검 배포"(짧은 중단을 알리고 지금 방식으로) [확정] (범위 #4)
7. **DB·cloudflared 판 올리기는 지금 방식 그대로** (짧은 중단) [확정] (범위 #5)
8. **메모리**: 백엔드 둘이 겹치는 동안 메모리가 모자라면 서버에 스왑 파일을 둠. 서버 측정 결과로 필요 여부를 정함 [확정] (사용자 승인, 명세 결정 페이지 2026-10-29)

## 수용 기준

- AC-1: 배포하는 동안 다른 창에서 1초마다 `https://chaekcheck.com/api/v1/version`과 첫 화면을 부르면 실패 0건이고, 응답의 판 번호가 옛 판 → 새 판으로 한 번만 바뀐다 (섞여 오가지 않음) [확정] (범위 #6)
- AC-2: 배포 시작 직전에 연 대출 조회 스트림과 AI 책 찾기 답이 배포 중에도 끝까지 온다 [확정] (범위 #6)
- AC-3: 일부러 뜨지 않는 판(예: 시작 때 바로 끝나는 판)을 배포하면 `release.sh`가 0이 아닌 코드로 끝나고 실패 이유를 알리며, AC-1 감시에서 실패 0건, 판 번호는 옛 판 그대로다 [확정] (범위 #6)
- AC-4: 앞 판 번호로 되돌리기를 하면 AC-1과 같은 결과다 [확정] (범위 #6)
- AC-5: web만 배포해도 AC-1과 같고, 첫 화면이 새 화면 파일로 바뀐다 [확정] (사용자 승인, 명세 결정 페이지 2026-10-29)
- AC-6: 배포가 끝난 뒤 `docker ps`에 백엔드가 하나만 돌고, 옛 판의 마지막 로그에 정상 종료가 보인다 (강제 종료 아님) [확정] (사용자 승인, 명세 결정 페이지 2026-10-29)
