사이클 15 · 2026-10-14 · 원본 docs/cycles/15-usage-log/spec.md R1-6 · 사이클 05에서 정한 로그인 쿠키 범위를 바꾸는 일이라 ADR을 새로 씁니다.

0지금과 바뀌는 것

지금 로그인 쿠키(access_token, 15분)는 /api/v1/me로 시작하는 주소에만 브라우저가 실어 보냅니다. 검색 주소에도 실리게 넓히고, 서버는 기록할 때만 그 쿠키를 읽습니다. 검색 자체는 계속 로그인 없이 됩니다.

1쿠키를 어디까지 보낼까

1로그인 쿠키 경로를 /api/v1로 넓힘 (모든 API 주소) [안]

왜 이 범위: 기록할 검색·책 상세·더 보기·사용 알림 주소가 모두 /api/v1/… 아래에 흩어져 있고, 쿠키 경로는 앞부분 하나만 정할 수 있습니다. 화면 파일(HTML·그림) 요청에는 여전히 실리지 않습니다.

안전: 쿠키는 그대로 자바스크립트가 못 읽고(HttpOnly), https에서만(Secure), 다른 사이트에서 시작한 요청에는 대부분 실리지 않습니다(SameSite=Lax). 보내기 요청의 CSRF 검사도 그대로입니다.

다른 선택: 경로를 /로 → 모든 요청에 실리지만, 쿠키 이름 앞에 __Host-를 붙이는 추가 보호를 쓸 수 있게 됩니다(사이클 05에서 경로를 좁혀 이 보호를 포기했었음, ADR-0042). 화면 파일 요청에도 쿠키가 실려 조금 낭비입니다.

추천 /api/v1

2쿠키가 만료됐을 때

로그인 쿠키는 15분짜리라, 로그인한 사람이 한참 검색만 하면 만료된 채로 실려 옵니다. 지금 화면은 내 정보 주소를 부를 때만 새 쿠키를 받아 오기 때문입니다.

2쿠키의 서명이 맞으면 만료됐어도 "로그인함"으로 적고, 서명이 틀리면 "안 함" [안]

이렇게 되면: 우리 서버가 서명한 쿠키인지는 만료와 상관없이 확인할 수 있어, "이 사람은 로그인한 사람"이라는 것을 정확히 적습니다. 이 판단은 기록 칸에만 쓰이고 권한에는 쓰이지 않습니다(내 정보 주소는 지금처럼 만료면 거절).

다른 선택
① 만료면 "모름" → 가장 엄격하지만, 로그인한 사람의 검색 상당수가 "모름"이 될 수 있습니다.
② 화면이 검색 전에 쿠키를 새로 받아 옴 → 늘 정확하지만, 검색할 때 요청이 하나 더 생깁니다.

추천 서명 맞으면 로그인함

3검색에 미치는 영향

3검색·책 상세·사용 알림은 계속 로그인 없이 되고, 쿠키 확인 실패는 오류가 아니라 "안 함"으로만 적음 [안]

이렇게 되면: 쿠키가 없거나 깨졌거나 로그인 기능이 꺼져 있어도 검색 결과는 똑같이 나옵니다. 서버는 검색을 처리하면서 쿠키를 한 번 읽어 기록 칸만 채웁니다. 앞서 정한 "확인 중이면 모름"은 화면이 보내던 값의 규칙이라, 서버 확인으로 바뀌면 없어집니다(서버는 확인 중 상태가 없음).

다른 선택: 깨진 쿠키가 오면 401로 거절 → 엄격하지만 검색이 실패할 수 있어 맞지 않습니다.
