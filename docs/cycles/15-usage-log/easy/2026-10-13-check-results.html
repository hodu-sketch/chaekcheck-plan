1확인 결과 (dev 코드·공식 문서)

설계 방향을 바꿔야 할 문제는 없었습니다. 하나(로그인이 꺼졌을 때 클릭 알림)는 만들 때 조심할 점이 생겼고, 하나(로그인 상태를 확인하는 짧은 순간)는 정해 주셔야 합니다.
확인한 것결과뜻
검색 주소에 "로그인 여부" 값을 더 붙이면 지금 서버가 거절하나거절하지 않고 모르는 값은 무시화면을 먼저 고쳐도 서버가 깨지지 않음
로그인 기능이 꺼졌을 때 화면의 보안 표시 코드표시를 받아 오는 주소가 없어 실패 → 지금 코드를 그대로 쓰면 클릭 알림이 안 나감화면이 "로그인 기능 꺼짐"이면 표시 없이 바로 보내도록 만들어야 함 (설계에 적음)
서버를 끌 때 모아 둔 기록을 DB에 넣을 수 있나보통 종료면 넣을 수 있음. 웹 요청을 다 받은 뒤 멈추도록 순서를 정하면 됨 (Spring 문서)DB 연결이 닫히는 순서는 문서 문장으로 못 찾아 만들 때 시험
묶어 넣을 때 한 번에 보낼 수 있는 값 개수65,535개 (PostgreSQL JDBC)고른 방식(batchUpdate)은 줄마다 따로 보내 걱정 없음
화면이 어느 페이지에서든 로그인 여부를 아나앎. 앱 전체가 첫 화면에서 로그인 상태를 물어 들고 있음"로그인함/안 함"을 보내는 데 문제 없음. 단 아래 한 가지

2로그인 상태를 아직 확인 중일 때 한 검색

화면은 처음 열릴 때 서버에 "로그인했나"를 물어보고, 답이 오기 전 아주 짧은 동안은 모르는 상태입니다. 이때 한 검색은 로그인 여부를 "모름"으로 적는 것을 추천합니다.

1확인 중일 때 한 검색·클릭은 로그인 여부를 "모름"(빈 값)으로 적음 [안]

이렇게 되면: 로그인 여부 칸은 "함 / 안 함 / 모름" 셋 중 하나가 됩니다. 통계에서 "모름"은 따로 세거나 빼고 볼 수 있습니다. 서버 오류로 로그인 상태를 못 받았을 때도 "모름"입니다.

다른 선택
① "안 함"으로 적음 → 칸이 둘로 단순하지만, 실제로는 로그인한 사람이 "안 함"으로 섞일 수 있습니다.
② 답이 올 때까지 검색 기록을 미뤘다가 적음 → 정확하지만 화면 코드가 복잡해집니다.

추천 "모름"으로 적기
