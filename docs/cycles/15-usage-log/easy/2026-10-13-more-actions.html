- 도서관에서 직접 찾기의 도서관별 응답 결과·걸린 시간 — 개인정보 아님(IP 없음), 참고

1더 보기

1"더 보기" 세 종류를 서버가 받는 요청에서 한 줄씩, 검색 기록과 다른 표에 남김 [안]

이렇게 되면: "검색 100번 중 다음 묶음을 누른 건 몇 번", "어느 도서관에서 더 보기를 많이 누르나"를 볼 수 있습니다. 세 요청은 이미 서버로 오므로 화면을 고칠 필요가 없습니다(로그인 여부 값만 같이 붙임). 대출 수 채우기처럼 화면이 사람 손 없이 부르는 요청은 여전히 세지 않습니다.

다른 선택: 검색 기록 표에 "몇 번째 요청" 칸을 더해 같은 표에 남김 → 표는 안 늘지만 "검색 수"를 셀 때마다 첫 요청만 골라야 해서 통계 SQL이 헷갈립니다.

2그 밖의 후보

#2·#3은 서버가 모르는 행동이라 화면이 알림을 보내야 합니다. 도서관 클릭 알림과 같은 주소를 "화면 행동 알림"으로 넓혀 쓰면 새 주소 없이 됩니다(설계에서).

2사서 추천 목록 화면 열기와 추천 책 창 열기도 기록 [안]

이렇게 되면: "사서 추천을 몇 명이 보나, 어떤 분야·책 창을 많이 여나"를 알 수 있습니다. 추천 책 창에서 도서관으로 넘어가는 클릭은 이미 남기므로, 그 앞 단계까지 이어 볼 수 있습니다(같은 IP 30일 안).

다른 선택: 남기지 않음 → 화면 알림이 늘지 않지만, 사서 추천 페이지가 쓰이는지는 클릭으로만 짐작합니다.

추천 기록

3지역 설정 바꾸기, 내 도서관 넣기·빼기도 기록 (무엇을 바꿨는지만) [안]

이렇게 되면: "어느 지역 사람이 많이 쓰나", "어떤 도서관을 내 도서관에 많이 넣나"를 알 수 있습니다. 회원 번호는 남기지 않고 바뀐 지역·도서관 번호와 로그인 여부·IP만 남깁니다. 로그인 전 지역 설정은 브라우저에만 저장되므로 화면이 알림을 보냅니다.

다른 선택: 남기지 않음 → 검색 기록의 지역·도서관 칸으로도 어느 정도 알 수 있습니다(검색할 때의 설정).

추천 기록

4직접 찾기에서 도서관마다 응답했나·실패했나·시간이 얼마나 걸렸나를 기록 [안]

이렇게 되면: "어느 도서관 사이트가 자주 응답하지 않나, 느린가"를 볼 수 있습니다. 서버가 이미 아는 값이라 화면 변화가 없습니다. 사람의 행동이라기보다 운영 기록이지만, 통계 때 "못 찾은 이유"를 나누는 데 씁니다. IP는 붙이지 않습니다.

다른 선택: 남기지 않음 → 지금처럼 서버 로그로만 봅니다.
