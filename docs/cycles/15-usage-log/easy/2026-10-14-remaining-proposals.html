1새로 늘린 기록의 보관 기간

더 보기와 화면 행동(사서 추천 보기, 지역·내 도서관 바꾸기)을 늘릴 때, 보관 기간을 따로 여쭙지 않고 "기존과 같은 규칙"으로 적어 두었습니다.

1더 보기·화면 행동 기록도 IP 30일, 나머지 1년 (검색·클릭과 같은 규칙) [안]

이렇게 되면: 모든 사용 기록이 한 규칙이라 지우기 작업이 단순하고, 처리방침에도 한 줄로 적힙니다(16에 이미 이렇게 전함).

다른 선택: 화면 행동은 90일 → 양이 많지 않아 줄일 이유가 크지 않고, 규칙이 둘이 됩니다.

추천 글자 그대로

3칸의 종류(타입)와 색인

3지역·도서관 목록은 번호 묶음 칸, IP는 IP 전용 칸, 시각 색인은 작은 BRIN 색인 [안]

질문에 대한 답: 시각 색인이 뭔가

색인은 책 뒤의 "찾아보기"처럼, DB가 원하는 줄을 처음부터 다 읽지 않고 바로 찾게 해 주는 목록입니다. 시각 색인은 "언제 받은 기록인지"로 찾을 때 씁니다. 우리 기록은 매일 04:30에 "1년 지난 줄", "30일 지난 IP"를 찾고, 통계 때 "지난주 기록"을 찾으므로 시각으로 찾는 일이 대부분입니다.
색인 종류크기우리 기록에
BRIN (추천)아주 작음 (묶음마다 두 값)시간 순서로만 쌓여 잘 맞음. 4GB 서버 메모리·디스크 부담 작음
보통 색인 (B-tree)줄마다 한 칸 → 표만큼 커짐정확하지만 넣을 때마다 색인도 고쳐 넣기가 조금 느려짐
색인 없음004:30 지우기·통계 때마다 표 전체를 읽음

"크기 수백분의 1"은 어림이며 실제는 개발 때 잽니다. 이해되셨으면 #3 칩에서 골라 주세요.

칸종류왜
지역들·도서관들번호 묶음 (bigint[])한 칸에 여러 번호, 통계 때 풀어서 셈 (unnest)
IPIP 전용 (inet)IP 범위로 찾기·검사가 됨
시각 색인BRIN시간 순서로만 쌓이는 표에 맞고 색인이 아주 작음 (PostgreSQL 문서)

줄마다 붙는 번호(id)를 둘지는 넣기 속도를 재 보고 개발 때 정합니다(측정 기준 10%·50MB에 포함).

다른 선택: 목록을 글자로(예: "1114,1102") → 단순하지만 통계 때 잘라야 합니다. IP를 글자로 → 범위 검사가 안 됩니다.

4이상한 클릭 알림의 "받은 값"은 2KB를 넘으면 잘라서 남김 [안]

다른 선택: 받은 값을 남기지 않고 이유만 → 가장 안전하지만 무엇이 왔는지 볼 수 없습니다.

추천 2KB까지

5로그인 여부는 검색 주소 뒤에 값으로 붙여 보냄 (?loggedIn=true) [안]

질문에 대한 답: 로그인 여부 값은 조작할 수 있지 않나

네, 조작할 수 있습니다. 주소 뒤 값이든 머리글이든 화면이 보내는 값은 사용자가 바꿔 보낼 수 있습니다. 다만 이 값은 통계에만 쓰이고 권한에는 전혀 쓰이지 않아, 바꿔도 "로그인 비율" 숫자가 조금 틀어질 뿐입니다. 서버가 직접 확인하게 하려면 로그인 쿠키를 검색 주소에도 보내도록 바꿔야 합니다.
방법조작드는 것
화면이 값으로 보냄 (지금 제안, #5)가능. 통계 숫자만 틀어짐없음
서버가 로그인 쿠키로 직접 확인불가능 (쿠키는 서버가 서명한 토큰)로그인 쿠키(access_token)가 지금은 /api/v1/me로만 감. 검색 주소(/api/v1 전체)로 넓혀야 하고, 검색마다 토큰을 확인하는 일이 생김. 사이클 05의 쿠키 범위 결정을 바꿈

제 생각: 통계용이라 화면이 보내는 값으로 충분하다고 봅니다. 정확한 로그인 비율이 꼭 필요하면 "서버가 쿠키로 확인"을 고르실 수 있고, 그때는 사이클 05의 쿠키 범위 결정을 다시 여쭙니다. 이대로면 #5 승인, 바꾸시려면 #5 기타에 "서버가 확인"이라고 적어 주세요.

왜: 직접 찾기는 화면이 서버와 연결을 열어 두고 받는 방식(SSE)이라, 이 방식은 머리글을 붙일 수 없습니다. 그래서 주소 뒤 값으로 통일합니다. 지금 서버는 모르는 값을 무시하므로 화면을 먼저 고쳐도 깨지지 않습니다(확인함).

다른 선택: 머리글로 보냄 → 주소가 깔끔하지만 직접 찾기에서는 쓸 수 없습니다.

추천 주소 뒤 값

6기록 모듈은 도서관 모듈만 알도록 제한 [안]

이렇게 되면: 기록 모듈이 다른 모듈 안쪽을 부르면 자동 검사(Spring Modulith)가 막습니다. 도서관 번호 확인에만 도서관 모듈을 씁니다. 검색 쪽(catalog·availability)이 기록 모듈을 부르는 것은 허용됩니다.

다른 선택: 제한을 두지 않음 → 지금 catalog·availability처럼 열어 두지만, 나중에 의존이 늘어도 막히지 않습니다.
