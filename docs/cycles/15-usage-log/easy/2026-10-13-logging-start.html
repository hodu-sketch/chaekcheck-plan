★사이클 17에 전달할 글 (요청하신 것)

아래 글을 그대로 복사해 사이클 17 세션에 붙여 넣으시면 됩니다. 같은 글이 docs/cycles/15-usage-log/to-cycle-17.md에 있습니다. 4번(기록 켜기 시점)은 아래에서 정하시면 고쳐 다시 드립니다.
사이클 17 세션에 전달합니다. 사이클 15(사용자 행동 기록)가 배포 설정에 기대는 것입니다.

1. 사용자 IP (가장 중요)
   - 15 서비스는 IP를 nginx가 넘기는 `X-Real-IP` 머리글에서 읽음 (dev `deploy/nginx/chaekcheck-locations.conf:17`, 값은 nginx의 `$remote_addr`). 서비스 쪽 forwarded 설정은 쓰지 않음
   - 그래서 17의 nginx가 `CF-Connecting-IP`를 사용자 주소로 읽게 하는 설정(`real_ip_header CF-Connecting-IP`, `set_real_ip_from` = cloudflared가 nginx에 붙는 주소)이 들어가야 `$remote_addr`·`X-Real-IP`가 실제 사용자 IP가 됨. `ngx_http_realip_module`은 기본 빌드에 없을 수 있음(https://nginx.org/en/docs/http/ngx_http_realip_module.html) → 쓰는 nginx 이미지에 있는지 확인 부탁
   - 이 설정이 없으면: 15 기록의 IP가 모두 cloudflared 주소 하나가 되고, 지금 있는 "도서관에서 직접 찾기" IP당 1분 30번 제한과 15의 클릭 알림 IP당 1분 60번 제한이 모든 사용자를 한 사람으로 세어 함께 막음
   - 터널을 거쳐도 `CF-Connecting-IP`가 붙는지 배포 때 시험 결과를 15에 알려 주세요

2. 15가 dev에 더할 nginx 설정 (15 인계서로 들어감, 17 설정과 겹치지 않게)
   - `location = /api/v1/library-clicks` (POST, 클릭 알림): IP당 1분 60번, 넘치면 기록하지 않고 204
   - 직접 찾기·대출 조회 location에서 User-Agent에 bot·crawler·spider가 든 요청은 403
   - 웹 `public/robots.txt`: `/api/` 크롤러 금지
   - 17이 Cloudflare 무료 요청 한도 규칙을 쓰기로 하면 이 nginx 한도들과 어떻게 나눌지 알려 주세요 (Cloudflare 규칙도 IP 기준)

3. nginx 접속 기록 보관 기간 (17 범위)
   - nginx 기본 접속 기록에는 IP와 검색어가 든 요청 주소가 함께 남음. 15의 검색 기록(IP 30일)과 따로 노는 기록이라, 기간이 정해지면 15·16에 알려 주세요. 검색어가 든 쿼리 문자열을 접속 기록에서 뺄지도 같이 봐 주시면 좋음 (15의 제안, 결정 아님)

4. 기록 켜기 시점 (15에서 정하는 중)
   - 15 기록은 서버 설정 값 하나로 켜고 끄며, 첫 배포 때는 꺼 두고 처리방침 공개일에 켜는 안 [안] — 정해지면 다시 알림. 정해지면 배포 설정(환경 변수)에 이 값이 들어감

5. 4GB 서버 몫
   - 15가 더하는 것: 서비스 메모리에 기록 버퍼 최대 1만 줄(약 5MB), DB 연결 추가 없음, 디스크 1년 1~2GB(어림)
   - 15의 AC-16(기록 켜기 전후 검색 응답 시간 10% 안, 메모리 50MB 안)은 Prometheus·Grafana·node_exporter를 켠 상태로 재고 그 메모리도 함께 적을 예정

6. 매일 새벽 작업 시각
   - 15는 매일 04:30(서울)에 기록 지우기(IP 30일 비우기, 1년 지난 줄 지우기)를 돌림. 지금 04:00 회원 정리, 05:00 사서 추천 받기 사이. 17의 백업·점검 작업 시각과 겹치면 알려 주세요

처리방침 시행일 = 모르는 사람에게도 공개하는 날(공개일). 첫 배포 뒤 지인에게만 여는 동안은 공개일 전아래에서 기록 시작 시점을 정함
Cloudflare = 처리 위탁 + 국외 이전, AWS = 처리 위탁15의 IP도 Cloudflare를 지나므로 이 기재에 들어감 (명세에 적음)
처리방침은 로그인 기능과 상관없이 늘 공개15 기록이 로그인 꺼짐에서도 IP를 남기는 것과 맞음
Cloudflare Tunnel, nginx가 CF-Connecting-IP를 사용자 주소로이미 반영: 서비스는 X-Real-IP를 읽음 (설계 #7)
Lightsail, WAF 제외, 모니터링 같은 서버, 나가는 IP마다 따로 셈이미 반영 (명세 R1-8, AC-16)

1기록 시작 시점

처리방침이 효력을 갖는 날(공개일)부터 기록을 켜는 것을 추천합니다. 서버 설정 값 하나로 켜고 끄게 만들어, 첫 배포 때는 꺼 두고 공개일에 켭니다.

1기록은 서버 설정 값으로 켜고 끄며, 공개일(처리방침 시행일)부터 켬 [안]

질문에 대한 답: 그래도 시험은 하나? (유의미한 결과는 외부 공개 뒤)

네, 시험은 세 번 합니다. 통계로 쓸 기록은 말씀대로 공개일부터 쌓고, 그 전에는 "제대로 남는지"만 확인한 뒤 시험 기록을 지웁니다.
언제무엇을 보나
① 개발 중 (dev)확인 기준 AC-1~AC-20 자동 시험. 로그인 기능 켬·끔 둘 다
② 첫 배포 뒤 지인 기간에 잠깐 켬실제 서버에서만 볼 수 있는 것: 터널을 거친 IP가 진짜 사용자 IP인지, 검색 응답 시간·메모리 차이(10%·50MB), 광고 차단으로 빠지는 클릭. 끝나면 그 기록을 지우고 다시 끔
③ 공개일설정 값을 켜서 정식으로 쌓기 시작

②에서 조심할 것: 처리방침 시행 전이라 시험에 참여하는 지인에게 "잠깐 기록을 켜서 시험한다"고 미리 알리고, 끝나면 그 기간 기록(IP 포함)을 지웁니다. 이렇게 하면 아래 칩의 "공개일부터 켬"과 함께 갈 수 있습니다. 이 방식으로 가시려면 칩에서 승인하고 기타 메모에 "시험은 지인 기간에 잠깐"이라고 적어 주셔도 되고, 그냥 승인하셔도 명세에 이 시험 순서를 같이 적겠습니다.

이렇게 되면: 첫 배포 때는 기록 기능이 들어 있지만 꺼져 있어, 지인에게만 여는 동안 IP를 포함한 기록이 남지 않습니다. 공개일에 설정 값만 바꾸면 켜집니다. 개인정보 보호법은 처리방침을 정해 공개하도록 하므로(제30조, 국가법령정보센터), 처리방침이 시행되기 전에 IP를 남기는 일을 피합니다. 지인 기간에 기록을 보며 시험하고 싶으면 그때만 잠깐 켤 수 있습니다.

다른 선택
① 첫 배포부터 켬 → 지인 기간 기록도 통계에 쓰지만, 처리방침 시행 전에 IP를 남기게 됩니다.
② 첫 배포부터 켜되 IP만 공개일부터 → 지인 기간에도 검색 통계는 남지만, 설정이 두 개가 됩니다.

이 설정 값은 사용자가 고르는 "기록 끄기"가 아니라 운영자가 서버에서 바꾸는 값입니다. 사용자 끄기 설정은 두지 않기로 이미 정했습니다.
