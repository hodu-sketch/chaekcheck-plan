# 사이클 15: 사용자 행동 기록

시작: 2026-10-12. 다른 사이클과 나란히 미리 하는 plan입니다 (아래 "나란히 도는 사이클과 겹치는 곳").
문서: [spec.md](spec.md) · [flow.md](flow.md) · [architect-proposal.md](architect-proposal.md) · [design-delta.md](design-delta.md) (초안) · [to-cycle-16.md](to-cycle-16.md) · [to-cycle-17.md](to-cycle-17.md) · 쉬운 설명 [easy/README.md](easy/README.md)

## 목표 (한 문장)

사용자가 검색하고, 책을 보고, 결과에서 도서관으로 넘어가는 행동을 한 줄씩 DB에 남겨, 다음 사이클에서 통계를 낼 수 있게 합니다.

- 사용자: "사용자가 검색을 하거나 도서관 페이지를 클릭할 때 정보를 기록해서 나중에 통계에 쓸까 해", "통계는 다음이고 지금은 기록이야" (2026-10-12), "이거 했으면 좋겠어 어지간한면 기록하고 싶어" (2026-10-13)

## 포함

저장 장소 조사와 첫 결정: [storage.md](../../research/usage-log/storage.md) 6절 ([결정 페이지](../../research/usage-log/easy/2026-10-12-storage-decisions.html)). 범위 결정: [easy/2026-10-12-scope-decisions.html](easy/2026-10-12-scope-decisions.html). 자세한 규칙은 [spec.md](spec.md).

1. **저장할 곳**: 같은 PostgreSQL에 새 schema(`usagelog`)의 기록 칸 [확정] (사용자 승인, 2026-10-12, [ADR-0096](../../adr/0096-usage-log-storage-and-fields.md))
2. **검색 기록**: 사람이 한 검색의 처음 요청만 한 줄. 수집 목록 검색과 도서관에서 직접 찾기 둘 다. 검색 조건·결과 수·거주/직장 지역·고른 도서관·범위를 같은 줄에 [확정] (사용자 승인, 2026-10-12; 사용자: "검색 요청을 한 사용자의 정보도 남겼으면 해 지역(직장/거주) 도서관 .. 이런거라던가")
3. **도서관 클릭 기록**: 링크는 지금처럼 새 탭으로 바로 열고, 화면이 "이 도서관을 눌렀음"을 따로 알림. 누르는 곳 여섯 [확정] (사용자 승인, 2026-10-12). 보내는 방법은 `fetch` keepalive, 주소 `POST /api/v1/usage-events` (spec R2-1)
4. **남기지 않는 것**: 회원 번호, 쿠키 값, User-Agent [확정]. IP는 남김(30일, 포함 8) — 처음(2026-10-12)에는 IP도 남기지 않기로 했다가 2026-10-13에 바뀜 (spec 바뀐 이력)
5. **보관**: 사용 기록 1년(IP 칸은 30일), 서버가 매일 자동으로 지움 [확정] (사용자 승인, 2026-10-12~14)
6. **쓰는 방식**: 검색 응답과 떨어져서, 5초마다 묶어 한 트랜잭션, 기록 트랜잭션만 비동기 커밋, Spring Modulith 이벤트는 쓰지 않음 [확정] (사용자 승인, 2026-10-12, [storage.md](../../research/usage-log/storage.md) 2.7절, [ADR-0097](../../adr/0097-usagelog-module-and-write-path.md))
7. **더 남기는 행동**: 책 상세 열기, 더 보기 세 종류, 사서 추천 목록·책 창 열기, 지역·내 도서관 바꾸기, 도서관 응답 하루 요약(직접 찾기·대출 수 채우기) [확정] (사용자: "이거 했으면 좋겠어 어지간한면 기록하고 싶어", 2026-10-13, [easy/2026-10-13-more-actions.html](easy/2026-10-13-more-actions.html); spec R5·R6)
8. **IP·로그인 여부·이상한 알림**: 모든 사용 기록에 IP(30일)와 로그인 여부(서버가 쿠키로 판별, 로그인함/안 함/로그인 기능 꺼짐), 이상한 알림은 IP와 함께 30일 [확정] (spec R1-6·R2-3·R5-2, [ADR-0102](../../adr/0102-access-cookie-api-v1-and-login-status-reader.md))
9. **운영 장치**: 기록 켜기 설정(첫 배포 때 꺼 둠, 공개일에 켬), 검색 로봇 거르기(robots.txt, nginx가 이름 밝힌 로봇 거절), 사용 알림 nginx 한도(IP당 1분 60번) [확정] (spec R1-5·R1-7·R1-8·R2-5·R3-6)

## 제외 (backlog.md로 보낸 항목)

- 통계(집계, 그래프, 운영자 화면) — 다음 사이클 (사용자, 2026-10-12)
- 회원 번호·쿠키로 같은 사람의 행동 잇기, 검색과 클릭을 잇는 칸 (spec R2-6). IP로 30일 안에서 이어 보기는 허용 [확정] (사용자 승인, 2026-10-14, [검증 결정](easy/2026-10-14-verify-decisions.html) #1)
- 화면 머문 시간, 스크롤, 그 밖의 버튼 (포함 7 밖의 행동)
- 분석 전용 저장소(ClickHouse 등)로 옮기기 — 통계가 느려질 때 ([storage.md](../../research/usage-log/storage.md) 2.8절)
- 이름을 속이는 로봇까지 막는 장치(WAF, Cloudflare 요청 한도 규칙) — 사이클 17이 정함 (backlog)
- 개인정보 처리방침 문구 — 사이클 16이 씀. 이 사이클은 무엇을 모으는지만 넘김 ([to-cycle-16.md](to-cycle-16.md))

## 완료 기준 (사용자가 확인할 수 있는 것)

기록은 화면에 보이지 않으므로, 화면에서 한 행동이 DB에 남는지로 확인합니다. 자세한 기준은 [spec.md](spec.md) 수용 기준.

- 검색을 한 번 하면 검색 기록에 한 줄이 생기고, "더 보기"·다음 쪽을 누르면 검색 기록은 늘지 않고 더 보기 기록에 한 줄씩 생긴다
- 검색 기록에 검색어, 결과 수, 거주·직장 지역, 고른 도서관, 로그인 여부, IP가 들어 있다
- 결과 카드를 누르면 전자도서관 새 탭이 지금처럼 바로 열리고, 클릭 기록에 누른 도서관과 누른 곳이 한 줄 생긴다 (여섯 곳 모두)
- 책 페이지, 사서 추천 목록·책 창, 지역·내 도서관 바꾸기도 각각 한 줄씩 남는다
- 기록 칸에 회원 번호·쿠키 값·User-Agent 칸이 없다. 31일 된 기록은 IP 칸이 비어 있다
- 1년이 지난 기록이 지워진다 (테스트)
- 기록을 켜기 전과 후의 검색 응답 시간 차이 10% 안, 서비스·DB 메모리 차이 각각 50MB 안 [확정] (사용자 승인, 2026-10-12·13)
- 로그인 기능 켬·끔 두 경우 모두 위가 통과한다
- 기록을 보는 방법: SQL 또는 Claude 명령 (운영자 화면 없음) [확정] (사용자 승인, 2026-10-12)
