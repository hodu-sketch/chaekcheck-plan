# 기능 명세: 내 도서관 (지역·직장 저장과 검색 연결)

- 작성: 2026-10-04. 범위: `scope.md`. 근거: `docs/research/member-and-alerts/outline.md`(2절), `integration-plan.md`(3절, 5절), `optional-profile-data-law.md`(개인정보 보호법 조문 원문, 국가법령정보센터 확인 2026-10-04), 사이클 05 `spec.md`
- 태그: `[확정]` 사용자가 정했거나 공식 문서 확인 / `[안]` 제안(결정 페이지 `easy/2026-10-04-spec-decisions.html`에서 하나씩 정함) / `[확인 필요]`
- 이 명세는 **서버에 저장하는 일**만 다룹니다. 검색이 도서관을 고르는 규칙(가입 가능 판정, 정렬 단계)은 사이클 01~04 그대로입니다.

## 사용자 이야기

- 로그인한 이용자는 거주지·직장 지역을 한 번 저장하면, 다른 브라우저나 기기에서 로그인해도 다시 고르지 않고 싶다. 사용자: "회원이 있는 이유는 직장/거주지 지역이라던가 알아서 도서관 매핑해주기 위함이야" (2026-10-01)
- 이용자는 지역과 상관없이 쓰고 싶은 도서관을 직접 추가하고 싶다. 사용자: "본인 거주지/지역과 상관없이 특정 도서관도 '내 도서관'에 넣는 거 생각 중이야", "'내 도서관' 자료만 찾을 수 있는 거지" (2026-10-01)
- 이용자는 검색 화면에서 스위치 하나로 "내 도서관" 결과만 보고 싶다. 사용자: "단순했으면 하는데" (2026-10-01, `outline.md` 2.3)
- 로그인하지 않은 이용자는 지금처럼 쓴다(지역은 이 브라우저에만 저장).
- 이용자는 저장한 지역·도서관을 언제든 고치고 지우고, 탈퇴하면 함께 지워지기를 바란다.

## 동작 규칙

### R1. 지역 저장과 읽기

- 로그인한 이용자가 거주지·직장 지역을 고르면 서버에 저장하고, 다른 브라우저에서 로그인해도 그 값을 읽어 씁니다. 저장은 "통째로 바꾸기"입니다(여러 곳을 한 번에).
- 로그인한 동안 화면은 서버 값만 씁니다. 이 브라우저의 로컬 저장 값은 건드리지 않고(지우지도 덮어쓰지도 않음), 로그아웃하면 다시 그 값을 씁니다 [확정] (사용자 승인, 2026-10-04).
- 로그인하지 않으면 지금과 같습니다. 서버에 보내지 않습니다(AC-6, 사이클 01).
- 지역 선택의 화면은 지금 지역 고르기 창을 그대로 씁니다. 바뀌는 것은 저장 위치뿐입니다.

### R2. 처음 로그인했을 때 브라우저 지역 옮기기 [확정] (사용자 승인, 2026-10-04)

- 로그인 직후 서버에 저장된 값이 없고 이 브라우저에 지역이 있으면, 한 번만 "이 지역을 계정에 저장할까요?"를 묻습니다. 저장하면 서버로 옮기고, 저장하지 않으면 서버 값이 빈 채로 시작합니다(브라우저 값은 그대로 남아 로그아웃 뒤에 씀).
- 서버에 이미 저장된 값이 있으면 묻지 않고 서버 값을 씁니다(브라우저 값은 그대로).
- [계정에 저장]이든 [저장하지 않기]든 한 번 답하면 그 브라우저에서 그 계정에는 다시 묻지 않음. 답하지 않고 닫거나 새로고침하면 다음 로그인 때 다시 물음. 옮기기 전에 `/api/v1/regions/resolutions`로 해석해 바뀐 지역은 새 지역으로 고쳐 저장하고(창에 "행정구역이 바뀌어 △△로 저장돼요"), 나뉘었거나 모르는 지역은 빼고 저장한 뒤 "다시 골라 주세요" 안내 [확정] (사용자 승인, 2026-10-04, 마무리 검토).

### R3. 직접 추가한 도서관

- 이용자는 서비스 도서관(꺼진 도서관 제외)을 내 도서관에 최대 20곳까지 추가하고 뺄 수 있습니다 [확정] (사용자: "상한 20까지 하라고", 2026-10-04). 꺼진 도서관도 뺄 때까지 20곳에 셉니다 [확정] (사용자 승인, 2026-10-04).
- 거주·직장 지역은 고른 순서대로 저장하고 보입니다 [확정] (사용자 승인, 2026-10-04).
- 검색 결과에서 직접 추가한 도서관은 가입 가능한 도서관보다 앞에 둡니다 [확정] (사용자 승인, 2026-10-04).
- 직접 추가한 도서관은 자격 판정과 상관없이 내 도서관에 들어갑니다.
- **직접 추가한 도서관은 자격 규칙의 예외입니다**: 이용자가 이미 가입해서 넣은 도서관으로 봅니다. 검색 결과와 내 도서관 화면에서 가입 자격 배지("가입 자격 확인 필요" 등)를 보이지 않고, 대신 "직접 추가" 표시 하나만 간단히 보입니다 [확정] (사용자 제안, 2026-10-04: "직접 추가한 도서관은 예외임. \"가입 자격 확인 필요\" 필요없음", "이미 가입된 도서관이라서 넣는다 이거 간단하게 표시하고 넣어줘"). 표시 글자 "직접 추가"는 [안] (내 도서관 화면 구역 이름과 같게).
- "방문 없이 가입"(`visit=none`)을 켜도 직접 추가한 도서관은 빼지 않습니다(이미 가입한 곳이므로) [확정] (사용자 제안, 2026-10-04, 같은 말). 스위치가 "전체 도서관"일 때도 직접 추가한 도서관은 결과 맨 앞에 둡니다 [확정] (사용자 승인, 2026-10-04).
- 지역으로 자동 들어온 도서관·누구나 가입하는 도서관도 직접 추가할 수 있습니다. 이미 직접 추가한 도서관을 다시 추가하면(20곳이 찼어도) 오류 없이 그대로입니다 [확정] (사용자 승인, 2026-10-04, 마무리 검토).
- 직접 추가한 도서관은 가입 주의 문구(이용 제한 원문)도 숨깁니다 [확정] (사용자 승인, 2026-10-04, 마무리 검토).
- 꺼진(`enabled=false`) 도서관이 저장돼 있으면 읽을 때 거르고 목록에서 안내합니다 [확정] (사용자 승인, 2026-10-04, 항목 7에 함께 적음).

### R4. 자동으로 들어온 도서관

- 지역으로 자동 들어온 도서관은 내 도서관 목록에 "지역으로 자동"으로 보입니다.
- 목록에서 하나씩 뺄 수 없고, 지역을 바꿔서 조절합니다 [확정] (사용자 승인, 2026-10-04).

### R5. "내 도서관만" 스위치

- 로그인한 상태에서 스위치를 켜면 검색의 계획 도서관은 내 도서관입니다: 거주지·직장 지역으로 가입 가능한 곳 + 누구나 가입하는 곳 + 직접 추가한 곳. 끄면 전체 도서관이고, 직접 추가한 도서관은 그때도 맨 앞입니다(R3).
- 지역과 직접 추가한 도서관이 모두 없으면 "누구나 가입하는 곳"만 남습니다(지금 지역이 없을 때의 `scope=joinable`과 같음).
- 로그인하고 내 도서관이 있으면 처음부터 "내 도서관만"이 켜져 있습니다. 사용자가 바꾼 값은 새로고침해도 유지됩니다 [확정] (사용자 승인, 2026-10-04).
- 로그인하지 않은 상태에서는 지금의 "가입할 수 있는 도서관만"(`scope=joinable`) 스위치 그대로입니다.
- 이 스위치는 두 검색(도서관에서 직접 찾기, 수집 목록 책 검색)과 책 화면에 모두 같은 규칙으로 적용됩니다(지금 `scope`가 적용되는 곳과 같음).

### R6. 폐지·바뀐 지역과 꺼진 도서관

- 저장된 지역이 나중에 폐지·통합·분할되면 지금 브라우저 값에 하는 것과 같은 규칙을 서버 값에도 합니다(AC-20, ADR-0003): 읽을 때 `/api/v1/regions/resolutions`로 해석해 대체된 곳은 새 지역으로 바꿔 쓰고 안내, 나뉘거나 모르는 곳은 빼고 "다시 골라 주세요" 안내. 서버 저장 값은 이용자가 다시 저장할 때 고쳐집니다 [확정] (사용자 승인, 2026-10-04).

### R7. 개인정보 동의 (새 수집 항목)

- 지역·직접 추가 도서관을 저장하는 것은 가입 동의에 없던 **새 수집 항목**입니다. 법 제15조②는 수집 항목을 알리고 동의를 받게 하고, 항목을 바꾸는 경우에도 알리고 동의를 받게 합니다(`optional-profile-data-law.md` 2절 원문).
- **가입 때의 필수 동의(개인정보 수집·이용) 문서에 항목을 더합니다** [확정] (사용자 제안, 2026-10-04: 처음 제안한 선택 동의를 미승인하고 "① 가입 때의 필수 동의 문서에 항목을 더하고 버전을 올림 … 이렇게 해줘"). 더하는 항목: 거주지 지역(시군구), 직장 지역(시군구), 직접 추가한 도서관. 목적: 거주·직장 지역은 "내 지역에서 가입할 수 있는 도서관을 찾아 검색에 쓰기", 직접 추가한 도서관은 "직접 고른 도서관을 검색 결과에서 먼저 보여 주기" [확정] (사용자 승인, 2026-10-04, 마무리 검토). 보유 기간: 지금 문구 그대로(탈퇴 때까지). 개인정보 처리방침의 처리 항목에도 더합니다(법 제30조). 문구는 `/design-delta`에서 쓰고 사용자가 검토합니다.
- 필수로 받는 근거: 회원 기능의 목적이 지역에 맞춰 도서관을 찾는 것입니다(사용자: "회원이 있는 이유는 직장/거주지 지역이라던가 알아서 도서관 매핑해주기 위함이야", 2026-10-01). 지역을 고르지 않는 회원은 이 항목이 수집되지 않습니다.
- **문서 버전은 올리지 않습니다** [확정] (사용자, 2026-10-04: "아직 배포 전이라서 뭐 버전 올릴 것도 없어"). 지금 버전 값(`2026-10-04`, 사이클 05에서 임시)의 문구를 고치고, 시행 날짜는 배포 전에 사용자가 정합니다(사이클 05 retro "사용자가 할 일"). 그래서 이미 가입한 계정에 다시 동의를 받는 화면은 만들지 않습니다. 지금 가입된 계정은 사용자 본인 하나뿐입니다 [확정] (사용자: "아직 나 혼자만 가입되어 있어", 2026-10-04).
- 저장한 지역·도서관은 내 도서관 화면(S10)에서 언제든 비우거나 지울 수 있고, 탈퇴하면 모두 지웁니다(R8).

### R8. 탈퇴·계정 삭제

- 탈퇴하거나 제공자 쪽에서 연결이 끊겨 계정이 지워지면 저장한 지역과 직접 추가한 도서관도 함께 지웁니다. `auth`가 `AccountDeleted(accountId)`를 발행하고 `mylibrary`가 받아 지웁니다(ADR-0041, ADR-0048). 같은 이벤트가 두 번 와도 결과가 같아야 합니다.
- 계정이 지워진 뒤 액세스 토큰이 남은 15분 동안에도 `mylibrary`는 지워진 계정의 줄을 새로 만들지 않아야 합니다(`retro.md` 새로 알게 된 제약, ADR-0038). 저장할 때 계정 줄을 잠그고 확인합니다 [확정] (ADR-0051).

### R8-1. 저장을 맡는 모듈과 API

- 지역·직접 추가 도서관의 저장은 **도서관과 사용자를 잇는 일만 맡는 새 모듈**이 맡습니다 [확정] (사용자 제안, 2026-10-04: "매핑 전용 모듈로"). ADR-0036의 둘째 모듈(`member`: 지역, 내 도서관, 나중에 관심 책)을 이 모듈로 바꾸고, 관심 책은 알림 사이클에서 따로 둡니다. 계정 모듈 `auth`와 나눈 결정은 그대로입니다. 모듈 이름은 `mylibrary` [확정] (ADR-0048, ADR-0036을 대체).
- 저장 API는 로그인 정보(`GET /api/v1/me`, `auth`)와 따로 둡니다 [확정] (사용자, 2026-10-04: 항목 6을 "매핑 전용 모듈로"로 답함 — API를 따로 두는 부분은 그대로). 주소는 `/api/v1/me/regions`, `/api/v1/me/libraries/{libraryId}` [확정] (ADR-0049).

### R8-2. 사이클 05 보완 (`scope.md`)

- 첫 가입을 마친 직후에만 화면 위 안내 줄에 "가입했어요" 한 줄을 보입니다. 다시 로그인할 때는 보이지 않습니다 [확정] (사용자 승인, 2026-10-04). 결과 코드 이름 `signup_success` [확정] (사용자 승인).
- 탈퇴 재인증에서 돌아온 요청이 만료되었으면 `withdraw_request_expired`("본인 확인 시간이 지났어요. 탈퇴를 다시 눌러 주세요"), 확인 값(`state`)이 맞지 않으면 `withdraw_state_mismatch`("안전하지 않은 요청이라 멈췄어요. 탈퇴를 다시 눌러 주세요")를 씁니다. 지금 쓰는 로그인용 코드(`login_expired`, `login_state_mismatch`)를 바꿉니다 [확정] (사용자 승인, 2026-10-04).

### R9. 비회원과 기존 기능

- 로그인하지 않은 이용자의 모든 기능은 사이클 05까지와 같습니다. 기존 검색·조회 API는 `libraryIds` 한 칸이 더해지는 것 외에 바뀌지 않습니다(ADR-0037).

## 상태별 동작

- 다 불러온 뒤에는 이미 하던 검색을 "내 도서관" 기준으로 한 번 다시 합니다 [확정] (사용자 승인, 2026-10-04, 마무리 검토).
- 로딩: 로그인 직후 서버 값을 읽는 동안 지역·스위치 칸은 "불러오는 중"으로 두고 검색은 막지 않습니다(읽기가 끝나기 전에는 지금처럼 브라우저 값 없이 전체 기준) [확정] (사용자 승인, 2026-10-04, `flow.md` S1).
- 저장 실패(서버 오류·연결 끊김): "저장하지 못했어요. 잠시 뒤 다시 해 주세요". 화면의 값은 바꾸지 않고 다시 시도할 수 있게 둡니다.
- 로그인이 풀린 채 저장 요청(401): 로그인이 풀렸다는 안내 후 로그인 전 상태(브라우저 값)로 돌아갑니다. 사이클 05의 갱신 규칙(15분마다 자동 갱신)이 먼저 적용됩니다.
- 도서관 20곳 초과 추가: 더 넣을 수 없다고 알리고 하나를 빼면 추가할 수 있습니다.
- 내 도서관이 비어 있음(지역·직접 추가 없음): 스위치를 켜도 누구나 가입하는 곳만 보임. 목록 화면은 "지역을 고르거나 도서관을 추가하세요" 안내 [안].
- "이 지역을 계정에 저장할까요?"에 저장하지 않음: 서버 값이 빈 채로 시작하고, 내 도서관 화면(S10)에서 언제든 지역을 고를 수 있음.

## 수용 기준

- AC-1: 로그인하고 동의한 이용자가 거주지·직장 지역을 고르면, 다른 브라우저에서 로그인해도 같은 지역이 선택된 채로 검색된다. (`GET` 응답과 화면)
- AC-2: 로그인하지 않은 상태에서 지역을 고르면 서버로 지역을 보내는 요청이 없다(지금과 같음). (네트워크 확인)
- AC-3: 로그인 직후 서버에 저장 값이 없고 브라우저에 지역이 있으면 "이 지역을 계정에 저장할까요?"가 한 번 나오고, 저장하면 서버로 옮겨지고, 저장하지 않으면 서버에 아무것도 저장되지 않는다.
- AC-4: 직장 지역을 "서울 중구"로 저장하면, 서울 재직자가 가입할 수 있는 도서관이 내 도서관 목록에 "지역으로 자동"으로 나온다.
- AC-5: 도서관을 직접 추가하면 S10의 "직접 추가한 도서관"에 나오고, 지역과 상관없이 검색 계획에 들어가며 결과 맨 앞에 가입 자격 배지 없이 "직접 추가" 표시로 나온다. 빼면 사라진다.
- AC-6: "내 도서관만"을 켜면 계획 도서관이 내 도서관(자동 ∪ 직접 추가)과 일치하고, 끄면 전체 도서관이 되며 직접 추가한 도서관은 그때도 맨 앞이다. (스트림 `targets` 확인)
- AC-7: 내 도서관이 비어 있으면 "내 도서관만"을 켜도 누구나 가입하는 도서관만 나온다.
- AC-8: 21번째 도서관을 추가하려 하면 막고 이유를 알린다.
- AC-9: 서버에 저장된 지역이 나중에 폐지·대체되면, 읽을 때 대체 지역으로 바뀌어 보이고 안내가 나온다. 나뉘거나 모르는 지역은 빠지고 다시 고르라는 안내가 나온다. (시험용 폐지 데이터 9001·9002 사용)
- AC-10: 꺼진 도서관이 저장돼 있으면 검색 계획에 들어가지 않고 목록에서 안내된다.
- AC-11: 탈퇴하면 그 계정의 지역·직접 추가 도서관 행이 DB에 없다(발행 저장소의 완료 기록도 없음).
- AC-12: 지워진 계정의 액세스 토큰(남은 15분)으로 저장을 시도하면 줄이 생기지 않는다.
- AC-13: 내 도서관 화면(S10)에서 지역과 직접 추가 도서관을 모두 비우면 서버의 해당 행이 없다.
- AC-14: 로그인하지 않은 상태의 검색·지역 선택·"가입할 수 있는 도서관만" 스위치는 사이클 05까지와 같다.
- AC-15: 가입 동의 화면의 수집·이용 고지 표에 거주지·직장 지역과 직접 추가한 도서관이 항목으로 보이고, 개인정보 처리방침 화면에도 같은 항목이 있다.
- AC-16: 로그인하고 내 도서관이 있으면 검색 화면이 "내 도서관만"이 켜진 채 열리고, 사용자가 끈 값은 새로고침해도 유지된다.
- AC-17: 처음 가입을 마치면 화면 위에 "가입했어요"가 한 번 보이고, 같은 계정으로 다시 로그인하면 보이지 않는다.
- AC-18: 탈퇴 재인증에서 돌아온 요청이 만료되었으면 "본인 확인 시간이 지났어요. 탈퇴를 다시 눌러 주세요", `state`가 다르면 "안전하지 않은 요청이라 멈췄어요. 탈퇴를 다시 눌러 주세요"가 보이고 계정은 지워지지 않는다(결과 코드 `withdraw_request_expired`, `withdraw_state_mismatch`).

## 비목표

- 대학·회사 등 소속 기관의 전자도서관 자격 입력과 판정 — 기관 목록·가입 자격 조사가 먼저 필요함(backlog "웹러브 북스 기관을 서비스 도서관으로 넣기")
- 관심 책과 알림, 책을 저장하는 모든 기능 — 책 번호 유지가 먼저(`scope.md` 순서)
- 이메일·전화 등 연락처, 별명·프로필 사진 수집
- 지역 자동 감지(위치 권한, IP) — 이용자가 직접 고름
- 여러 프로필·가족 계정, 다른 사람과 내 도서관 공유
- 직접 추가한 도서관별 메모·정렬 직접 지정(위치는 규칙 하나로)
- 로그인하지 않은 상태에서 서버에 저장하는 것
