- 시작: 2026-10-04. 사이클 05 회고: `../05-login-account/retro.md`
- 폴더 이름 `my-libraries`는 임시 [안] (사용자가 따로 정하지 않음)
- 밑그림·근거: `docs/research/member-and-alerts/outline.md`(2절 내 도서관), `integration-plan.md`(3절 구조, 5절 05b 줄), `docs/reference-index.md` 5절. 결정 페이지: `easy/2026-10-04-cycle-start-decisions.html`
- 번호 대응: integration-plan의 "05b" = 이 사이클. 사이클 05 `scope.md`가 "06 알림 = 사이클 07"이라고 적은 것은 아래 "순서"로 바뀜

## 목표 (한 문장)

로그인한 사람의 거주지·직장 지역과 직접 고른 도서관이 서버에 저장되고, 검색 화면의 "내 도서관만" 스위치로 바로 쓰인다.

## 포함 [확정] (사용자 승인, 2026-10-04, 캔버스 항목 2)

- 거주지·직장 지역을 서버에 저장 (지금은 브라우저에만 저장됨). 직장 기준으로 가입 가능한 도서관이 내 도서관에 자동으로 들어옴. 가입 가능 판정은 지금 검색이 쓰는 판정을 그대로 씀(`joinable()`, ADR-0013·0027)
- 지역과 상관없이 도서관을 직접 추가
- 검색 화면의 "내 도서관만" 스위치, 설정 창 "내 도서관" 절
- 새 모듈: 도서관-사용자 매핑 전용 모듈(이름은 설계에서, ADR-0036의 `member`를 바꿈 — 사용자 제안 2026-10-04 "매핑 전용 모듈로"), 검색은 회원을 모르고 웹이 `libraryIds`로 넘김(ADR-0037)
- `AccountDeleted` 처리: 새 매핑 모듈이 첫 실제 소비자
- 사이클 05 보완(아래)

## 제외 (backlog.md로 보낸 항목)

- **책 번호 유지** → 별개의 사이클 [확정] (사용자, 2026-10-04: "책 번호 유지는 별개의 사이클로 해줘.. 그것은 수집기를 update가능한 형태로 바꿔야 하는 거니까"). 06은 책을 저장하지 않으므로 먼저 필요하지 않음. 책을 저장하는 알림보다는 먼저
- 관심 책·알림. 알림은 책 번호 유지 뒤
- 소속 기관(대학·회사) 전자도서관 자격: 기관 목록과 가입 자격 조사, 서비스에 없는 기관 넣기가 먼저 필요(`docs/backlog.md` "웹러브 북스 기관을 서비스 도서관으로 넣기")
- 책 묶기 안내, 책검색 화면, 정렬, 이상한 곳 수정 → "검색 화면 다듬기" 후보
- 이메일·전화 등 연락처 수집, 별명·프로필 사진(backlog), 이용자 간 기능
- 배포: 사이클 밖에서 병행(`docs/research/deploy/aws-layout.md`)

## 완료 기준 (사용자가 화면에서 확인할 수 있는 것) [안]

`/feature-spec`에서 확정합니다. 초안:

- [ ] 로그인한 뒤 거주지·직장 지역을 고르면 다른 브라우저에서 로그인해도 같은 지역이 보인다
- [ ] 직장 지역을 저장하면 그 지역에서 가입 가능한 도서관이 내 도서관에 자동으로 들어온다
- [ ] 지역과 상관없이 도서관을 직접 추가·삭제할 수 있다
- [ ] "내 도서관만" 스위치를 켜면 내 도서관의 결과만 보인다
- [ ] 탈퇴하면 저장한 지역·내 도서관도 함께 지워진다
- [ ] 로그인하지 않은 사람은 지금처럼 쓴다(지역은 브라우저에만 저장)
- [ ] `ModularityTests`(새 매핑 모듈), 백엔드 빌드, 웹 테스트·빌드·lint 통과

## 슬라이스 선택 기록

- ICE 점수는 매기지 않음. 사이클은 사용자가 정함.
- 사용자 목적(2026-10-01): "회원이 있는 이유는 직장/거주지 지역이라던가 알아서 도서관 매핑해주기 위함이야", "본인 거주지/지역과 상관없이 특정 도서관도 '내 도서관'에 넣는 거 생각 중이야".
- 사용자 순서(2026-10-04): ① 책 묶기 알려주기 → ② 책검색, 직장/지역 UI → ③ 직장별 도서관 매핑 → ④ 내 도서관 → ⑤ 정렬·UI 수정 → ⑥ 배포(카카오 로그인만). 이 사이클은 ②의 지역 UI 저장, ③, ④. 나머지는 위 "순서".
- 사이클 번호와 범위는 사용자가 캔버스에서 승인(2026-10-04, 항목 1·2). 이유는 [이유 미확인] (승인만 있음).

## 영향 받을 모듈 [안]

- 새 매핑 전용 모듈(이름은 설계에서, 스키마: 지역, 내 도서관). `auth`의 공개 `AccountId`·`AccountDeleted`를 받음. `library`는 `LibraryCatalog` 공개 API로 읽음(모듈 간 JOIN 금지)
- `library`·`catalog`·`availability`: 검색에 `libraryIds` 파라미터를 받는 칸 하나(ADR-0037)
- 웹: 지역 저장 위치(브라우저 → 서버), "내 도서관" 설정 절, "내 도서관만" 스위치
- 바뀌지 않는 것: `auth`의 로그인 동작, `fetch-service/`, `region`의 판정 규칙
