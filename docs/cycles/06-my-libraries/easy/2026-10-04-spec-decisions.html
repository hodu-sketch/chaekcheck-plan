내 도서관 기능이 어떻게 동작할지
일곱 가지를 정해 주세요.

명세 spec.md를 쉬운 말로 풀었습니다. 항목마다 승인 · 미승인 · 기타 중 하나를 고르시면 됩니다. 이 기능은 로그인한 사람의 지역과 도서관을 서버에 저장하는 일이라, 개인정보 동의 문제가 가장 먼저 나옵니다.

1내 도서관이란 (이미 정한 것)

내 도서관 = 지역으로 자동 들어온 도서관 + 직접 추가한 도서관입니다. 검색 화면의 "내 도서관만" 스위치를 켜면 이 범위만 찾습니다. 이 정의는 2026-10-01에 정하고 이번에 범위로 승인하셨습니다.

이 사이클에서 하지 않는 것: 회사·대학 같은 소속 기관의 전자도서관, 관심 책과 알림, 지역 자동 감지, 연락처 수집.

2저장해도 되나: 개인정보 동의

지역과 직접 추가한 도서관을 서버에 저장하는 것은 가입할 때 받은 동의에 없던 "새로 모으는 개인정보"입니다. 그래서 저장 전에 알리고 동의를 받아야 합니다.

근거: 개인정보 보호법 제15조②는 개인정보를 모을 때 목적, 항목, 보유 기간, 동의를 거부할 권리를 알리고 동의를 받게 하며, 항목을 바꿀 때도 알리고 동의를 받게 합니다. 제22조⑤는 선택 사항에 동의하지 않았다는 이유로 서비스 제공을 거부하지 못하게 합니다. 조문 원문은 조사 문서 optional-profile-data-law.md 2절에 있고, 국가법령정보센터에서 2026-10-04에 확인한 것입니다(이 세션에서 다시 열지는 않았습니다). 법률 자문이 아니고, 아래 제안은 이 서비스에 대어 본 제 해석입니다.

1지역·내 도서관 저장은 가입 동의와 따로, 선택 동의로 받음 [안]

예: 로그인한 사람이 설정의 "내 도서관"에서 "계정에 저장하기"를 누르면 "거주지 지역, 직장 지역, 직접 추가한 도서관을 탈퇴할 때까지 저장합니다. 동의하지 않아도 모든 기능을 쓸 수 있고, 지역은 이 브라우저에만 저장됩니다"를 보여 주고 동의하면 서버에 저장합니다. 설정에서 "저장 끄기"를 누르면 서버에 저장된 지역과 도서관이 지워지고 동의 기록도 거둬집니다. 개인정보 처리방침의 처리 항목에도 더합니다. 동의 문구와 문서 버전은 설계 단계에서 쓰고 사용자가 검토합니다.

적용함: 미승인하고 "필수 동의 문서에 항목을 더함, 배포 전이라 버전은 올리지 않음"으로 정하셔서 명세에 그대로 적었습니다(R7). 회원 기능의 목적이 지역에 맞춰 도서관을 찾는 것이라는 사용자 말(2026-10-01)을 필수로 받는 근거로 함께 적었습니다. 다시 동의를 받는 화면은 만들지 않습니다.

다른 선택 ① 가입 때의 필수 동의 문서에 항목을 더하고 버전을 올림. 이미 가입한 모든 회원이 다시 동의해야 하고, 동의하지 않으면 가입이나 이용이 막힙니다. 지역 저장은 서비스에 꼭 필요한 기능이 아니라서 필수로 받기 어렵다고 봅니다. ② 동의 없이 서버에 저장. 위 법 조문상 할 수 없습니다.

2로그인 직후 이 브라우저에 저장된 지역이 있으면 "이 지역을 계정에 저장할까요?"를 한 번 묻고, 로그인한 동안은 서버 값만 씀 [안]

예: 로그인하기 전에 "서울 마포구"를 골라 둔 사람이 처음 로그인하면, 저장할지 한 번 묻습니다. 저장하면 서버로 옮겨지고(위 동의를 같은 화면에서 받음), 저장하지 않으면 계속 이 브라우저에서만 씁니다. 서버에 이미 저장된 값이 있으면 묻지 않고 서버 값을 씁니다. 로그인한 동안 이 브라우저의 값은 지우지도 덮어쓰지도 않고, 로그아웃하면 다시 그 값을 씁니다.

다른 선택 ① 묻지 않고 자동으로 옮김. 위 동의 없이 서버에 저장하게 되어 항목 1과 맞지 않습니다. ② 옮기지 않고 새로 고르게 함. 이미 고른 것을 다시 골라야 합니다.

참고: 아직 운영 전이라 이미 가입한 회원은 시험 계정뿐인 것으로 알고 있습니다. 실제 회원이 있다면 알려 주세요(동의를 받는 방법이 달라집니다).

3검색 화면에서 어떻게 보이나

로그인하면 지금의 "가입할 수 있는 도서관만" 스위치 자리가 "내 도서관만"이 됩니다. 로그인하지 않은 사람의 화면은 그대로입니다.

3직접 추가한 도서관은 결과에서 가입 가능한 도서관보다 앞에 두고, 최대 20곳까지 [안]

예: 가입 자격이 없어도 내가 직접 넣은 "서울도서관"이 있으면, 그 도서관의 결과가 가입 가능한 도서관의 결과보다 위에 나옵니다. 가입 자격 배지("가입 자격 확인 필요" 등)는 지금처럼 보입니다. 20곳은 지역 칸이 칸당 20곳까지인 것과 같은 값이고, 값이 커지면 검색 요청 주소가 길어집니다.

메모가 잘렸습니다: 항목 3을 "승인하되 최대"로 보내셨는데 뒤 글이 오지 않았습니다. 앞에 두는 것은 확정으로 적었고, 상한은 비워 두었습니다. 항목 3을 다시 눌러 기타에 상한(예: "최대 30곳")을 적어 주세요.

다른 선택 ① 자동으로 들어온 도서관과 같은 순서에 섞음. 직접 고른 곳이 뒤로 밀려 안 보일 수 있습니다. ② 상한을 10곳 또는 50곳으로 함. 10곳은 작아서 불편할 수 있고, 50곳은 요청 주소가 길어집니다. 값은 근거 없이 정한 제안입니다 [이유 미확인].

4지역으로 자동 들어온 도서관은 목록에서 뺄 수 없고, 지역을 바꿔서 조절함 [안]

예: 직장을 "서울 중구"로 저장해서 자동으로 들어온 도서관이 마음에 들지 않으면, 그 도서관만 뺄 수는 없고 직장 지역을 바꿔야 합니다. 가장 단순하고, "내 도서관만"을 켰을 때 누구나 가입하는 곳은 항상 들어 있습니다.

다른 선택 자동 도서관마다 "제외"를 누를 수 있게 함. 제외한 도서관 목록을 서버에 하나 더 저장해야 하고(저장하는 개인정보가 늘어 동의 항목도 늘어남), 지역을 바꿀 때 제외 목록을 어떻게 할지 정해야 합니다.

5로그인하고 내 도서관이 있으면 처음부터 "내 도서관만"이 켜져 있음 [안]

예: 로그인한 사람이 검색 화면에 들어오면 "내 도서관만"이 이미 켜져 있고, 끄면 전체가 보입니다. 사용자가 바꾼 값은 새로고침해도 유지됩니다(지금 설정 저장 방식 그대로). 이 기본값은 2026-10-01 밑그림에서 추천했던 것이고, 지금까지 사용자가 따로 확정한 적은 없습니다.

다른 선택 항상 "전체"로 시작. 내 도서관을 설정한 이유가 사라질 수 있지만, 처음 보는 결과가 지금과 같아 놀랄 일이 없습니다.

4서버 모양과 바뀐 지역

여기는 화면에 직접 보이는 것이 적습니다. 구조는 이미 정한 것(회원 저장 모듈 member를 따로 둠, 검색은 회원을 모름)을 그대로 따릅니다.

6지역·도서관 저장 API는 로그인 정보(/api/v1/me)와 따로 두고, 새 모듈 member가 맡음 [안]

예: 로그인했는지·약관에 동의했는지는 지금처럼 /api/v1/me가 주고, 저장한 지역과 직접 추가한 도서관은 /api/v1/me/regions, /api/v1/me/libraries(읽기와 통째로 바꾸기)가 줍니다. 로그인 정보 모듈(auth)이 지역과 도서관을 모르게 하려는 구조 결정(ADR-0036)을 지키는 방법입니다. 주소 이름은 제안이고 설계 단계에서 확정합니다.

다른 선택 /api/v1/me에 지역과 도서관을 합쳐서 한 번에 줌. 화면이 한 번만 부르면 되지만 auth가 member를 알아야 해서 모듈 경계(ADR-0001)에 어긋납니다.

질문: member 말고 도서관과 사용자를 잇는 일만 맡는 모듈은 어떤가요?

됩니다. 이번에 저장하는 것(거주지·직장 지역, 직접 추가한 도서관)은 모두 "이 사람의 내 도서관이 어디인가"를 정하는 데만 쓰여서, 그 일만 맡는 모듈 하나에 그대로 들어갑니다. member와 다른 점은 이름, 그리고 나중에 생길 다른 회원 자료(알림의 관심 책)를 어디에 두느냐입니다.

member (ADR-0036 그대로)매핑 전용 모듈 (이름 예: mylibrary)library 모듈 안에
맡는 것지역, 직접 추가 도서관, 나중에 관심 책지역, 직접 추가 도서관만. 관심 책은 알림 사이클에서 따로같은 내용을 도서관 목록 모듈이
좋은 점회원 자료가 한 곳에 모임이름이 하는 일과 맞음. 모듈이 작고, 알림 사이클이 이 모듈을 건드리지 않음모듈 수가 늘지 않음
나쁜 점관심 책까지 들어가면 "회원 자료면 아무거나" 모듈이 되기 쉬움회원 자료 모듈이 알림 때 하나 더 생김. ADR-0036에 이름을 바꾸는 덧붙임이 필요여러 검색이 함께 쓰는 도서관 모듈이 계정을 알게 됨. "검색은 회원을 모른다"(ADR-0037)와 섞여서 권하지 않음

제 추천은 매핑 전용 모듈입니다. 이번 사이클이 저장하는 것과 정확히 맞고, 알림 밑그림(integration-plan.md 4절)도 이미 관심 책 판단을 새 모듈 notification에 두려 했기 때문입니다. 계정 모듈 auth와 나눈 결정(ADR-0036)은 그대로이고, 바뀌는 것은 둘째 모듈의 이름과 맡는 범위입니다. 이름은 설계 단계에서 정합니다.

이렇게 가시려면 위 항목 6을 다시 눌러 기타에 "매핑 전용 모듈로"라고 적어 주세요. member로 두시려면 승인을 누르시면 됩니다.

7저장된 지역이 나중에 없어지거나 바뀌면, 지금 브라우저 값에 하는 규칙을 서버 값에도 똑같이 적용함 [안]

예: 저장해 둔 지역이 다른 지역으로 통합되면 읽을 때 새 지역으로 바꿔 쓰고 "행정구역 변경으로 지역이 바뀌었습니다"를 안내합니다. 여러 지역으로 나뉘었거나 알 수 없으면 그 지역을 빼고 "내 지역을 다시 골라 주세요"를 안내합니다. 서버에 저장된 값은 이용자가 다시 저장할 때 고쳐집니다. 꺼진 도서관이 저장돼 있으면 검색 계획에서 빼고 목록에서 안내합니다.

다른 선택 지역이 바뀔 때마다 서버가 저장 값을 직접 고침. 읽을 때마다 해석하는 지금 방식보다 저장 값을 바꾸는 코드와 이력이 늘어납니다.
