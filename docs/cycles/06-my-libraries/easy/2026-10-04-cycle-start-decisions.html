1사이클 번호: 06은 내 도서관, 그 뒤 검색 화면 다듬기(07), 책 번호 유지, 알림 [안]

06에서는 지역·직장·내 도서관만 저장하고 책은 저장하지 않습니다. 그래서 책 번호 유지는 06 뒤로 미뤄도 되고, 책을 저장하는 알림보다 앞에만 오면 됩니다(사용자 결정, 2026-10-04: 책 번호 유지는 회원이 책을 저장하는 기능보다 먼저). 책 번호 유지와 알림의 번호는 그때 정합니다.

옛 문서가 다르게 적은 곳이 있습니다. 회원 밑그림(integration-plan.md)은 06을 알림으로 적었는데, 그 뒤 outline.md가 06을 내 도서관, 알림을 07로 바꿨고, 이번 안은 07을 검색 화면 다듬기로 바꿉니다.

다른 선택 ① 알림을 07로 두고 검색 화면 다듬기는 그 뒤로 미룸. 알림은 책 번호 유지가 먼저 필요해서 순서가 꼬입니다. ② 06과 07을 한 사이클로 합침. 문서가 한 벌이지만 인계서가 커지고 하나가 막히면 전부 늦어집니다.

206에서 만들 것의 범위

06은 "로그인하면 내 도서관이 서버에 저장되고, 검색에 바로 쓰이는" 사이클로 정리하는 것을 권합니다.

2내 도서관만 만들기: 지역·직장 저장, 직장 기준 자동 포함, 직접 추가, "내 도서관만" 스위치 [안]

예: 직장을 "서울 중구"로 저장하면, 서울 재직자가 가입할 수 있는 도서관이 내 도서관에 자동으로 들어옵니다. 가입 가능 여부는 지금 검색이 쓰는 판정을 그대로 씁니다. 새로 만드는 것은 로그인한 사람의 거주지·직장 지역을 서버에 저장하는 것(지금은 브라우저에만 저장됨), 지역과 상관없이 고른 도서관을 저장하는 것, 검색 화면의 "내 도서관만" 스위치입니다. 회사·대학이 직원에게 주는 전자도서관(소속 자격)은 넣지 않습니다. 기관 목록과 가입 자격 조사가 먼저 필요하기 때문입니다.

다른 선택 ① 위 내용에 "책 묶기 안내"까지 넣음. 사이클이 커져 10월 6일이 빠듯해집니다. ② 위 내용에서 "도서관 직접 추가"를 뺌. 가장 작지만, 지역과 상관없이 도서관을 넣고 싶다는 사용자 요구(2026-10-01)는 다음으로 밀립니다.

3사이클 05에서 dev가 정해 달라고 넘긴 것

dev가 구현하다가 설계 표에 없는 경우를 만났고, 일단 임시로 정해 두었습니다. 추천대로 확정해도 코드는 바뀌지 않거나 조금만 바뀝니다.

3첫 가입을 마친 직후에만 "가입했어요" 안내 줄 한 줄을 보임 [안]

지금은 가입을 마쳐도 아무 안내 없이 보던 화면으로 돌아가서 허전합니다(사용자 의견, 2026-10-04: "로그인 되었는데 로그인되었다는 알람이 없어서 허전한데"). 첫 가입 뒤에만 화면 위 안내 줄에 "가입했어요"가 나오고, 다시 로그인할 때는 지금처럼 안내가 없습니다.

근거: dev가 공개 페이지로 조사한 결과, 다시 로그인할 때 "로그인되었습니다"를 띄운다는 근거는 조사한 서비스에서 찾지 못했고, 첫 가입 뒤에는 가입 완료 화면을 따로 보여 주는 서비스가 많았습니다(예: 예스24 가입완료 단계). 이 세션에서 다시 확인하지는 않았습니다.

다른 선택 ① 안내를 두지 않음(지금 그대로). ② 다시 로그인할 때도 "로그인했어요"를 보임. 매번 뜨는 안내가 되어 방해가 될 수 있습니다.

4결과 코드 표에 오류 응답 세 가지를 더함 [안]

dev가 임시로 만든 응답 세 가지를 설계의 결과 코드 표에 정식으로 적습니다.

상황응답
로그인 확인 중 우리 DB에 오류가 남500 internal_error. 401로 응답하면 화면이 로그인을 버리기 때문에 일부러 500으로 함
CSRF 검사가 아닌 다른 이유로 403403 forbidden. 지금은 권한 구분이 없어서 나올 일은 없음
네이버·카카오 로그인은 성공했는데 우리 서버 쪽 오류가 남지금은 돌아오는 주소에서 500. 화면에 보여 줄 전용 문구가 없음

다른 선택 세 번째 상황에 "우리 서버 오류" 결과 코드를 새로 만들어 화면에 안내 문구를 보임. 문구 하나와 코드 하나가 늘고, 제공자 탓으로 읽히는 login_provider_error는 쓰지 않습니다.

5탈퇴 재인증에서 돌아온 요청이 만료·불일치일 때 로그인과 같은 코드(login_expired, login_state_mismatch)를 씀 [안]

탈퇴하려고 제공자에서 다시 로그인하고 돌아왔는데 시간이 지났거나 요청 값이 맞지 않으면, 화면은 로그인 때와 같은 안내를 보여 줍니다. 탈퇴용 코드는 따로 두지 않습니다. dev가 이미 이렇게 구현했습니다.

다른 선택 탈퇴 전용 코드(withdraw_login_expired 같은 것)를 새로 만들어 문구를 구분함. 코드와 문구가 늘어납니다.

6하루 한 번 작업에서 카카오 연결 목록이 비어 있으면 아무것도 지우지 않고 경고만 남김 [안]

설계에는 없던 안전장치로 dev가 더했습니다. 매일 새벽 4시에 카카오의 연결 목록과 우리 계정을 맞춰 보고, 목록에 없는 계정을 지웁니다. 어드민 키나 앱 설정이 잘못되어 빈 목록이 오면 모든 카카오 계정이 지워질 수 있으므로, 빈 목록이면 지우지 않고 경고만 남깁니다. 진짜로 모두 연결을 끊었다면 연결 해제 알림과 1년 정리로 지워집니다.

다른 선택 안전장치를 뺌. 빈 목록도 그대로 믿고 지움. 한 번 지워진 계정은 되돌릴 수 없습니다.

4직접 써 보고 확인해 주세요

dev가 카카오로 실제 확인을 하고 나서 사용자에게 다시 물어 달라고 남긴 세 가지입니다. 자동 테스트는 통과했지만 실제 화면에서 본 결과가 없습니다. 맞으면 승인, 달랐으면 미승인이나 기타에 적어 주세요.

7가입 화면에서 세 칸을 모두 체크해야 가입 버튼이 눌렸다고 기록함 [안]

세 칸은 이용약관 동의, 개인정보 수집·이용 동의, 만 14세 이상 확인입니다. 하나라도 비어 있으면 가입 버튼이 눌리지 않아야 합니다. 승인 = 그렇게 동작했음.

8다시 로그인하면 검색어가 붙은 보던 주소로 돌아왔다고 기록함 [안]

예: 검색어를 넣고 결과를 보다가 로그인하면, 로그인 뒤 같은 검색 결과 화면으로 돌아와야 합니다. 승인 = 그렇게 동작했음.

9로그인한 상태에서 검색해도 로그인 전과 똑같이 동작했다고 기록함 [안]

결과 목록, 대출 현황이 뜨는 방식, 속도에 이상이 없었으면 승인입니다.

참고: 실제 브라우저에서 15분 뒤 자동 갱신이 되는지는 사용자가 나중에 알려주기로 해서 이번에는 묻지 않고 보류로 적습니다. 네이버 실제 확인은 키를 받은 뒤에 합니다.
