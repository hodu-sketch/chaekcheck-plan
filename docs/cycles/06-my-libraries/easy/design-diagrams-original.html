1. 모듈 구성도 (누가 누구를 부르나)

  • 화살표 방향 = 의존 방향. mylibrary → auth, library, region만 새로 생기고 순환은 없습니다. catalog·availability는 회원을 모릅니다(ADR-0037).
  • 로그인·가입·로그아웃·탈퇴는 사이클 05 그대로 화면이 auth와 직접 주고받습니다. mylibrary는 로그인을 하지 않고, 로그인된 뒤 "지금 누구인지"(AccountId)를 auth에게서 받아 그 사람의 지역·도서관만 저장합니다.

2. 클래스 그림 (설계 수준, 이름은 예시)

2.1 mylibrary 모듈 안

  • 저장소(…Store)는 사이클 05 auth처럼 JdbcClient로 SQL을 씁니다. JPA 엔티티는 없습니다.
  • MyLibraryService의 모든 쓰기는 @Transactional이고, 처음에 AccountPresence.lockIfExists를 부릅니다(2.2).

2.2 다른 모듈과 맞닿는 공개 타입

  • AccountIdArgumentResolver는 auth 안에 있고 앱 전체에 등록됩니다. 그래서 mylibrary 컨트롤러는 JWT를 몰라도 AccountId를 인자로 받습니다.
  • catalog의 JoinTier에 첫 값 CHOSEN이 더해지고, availability의 스트림 두 곳이 libraryIds를 받아 PlanOptions에 넣습니다.

3. 표 관계 (ERD)

  • 점선 = 다른 모듈의 표를 번호로만 가리킴(외래 키 없음, ADR-0001). 모듈끼리 JOIN하지 않습니다.
  • 한 계정: 거주 0~20줄, 직장 0~20줄, 직접 추가 0~20줄.
