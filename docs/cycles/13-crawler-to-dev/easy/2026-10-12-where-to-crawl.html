수집은 plan이 아니라 dev에서 하는 게 맞을까?

마무리 페이지에서 하신 질문의 답이에요. 마무리 페이지(커밋·푸시)는 그대로 열려 있어요.

1짧은 답: 네, 이제는 dev 쪽이 맞아요

  • 코드가 dev로 갔어요. 수집기는 dev scripts/crawl/로 갈아타기로 정했고(ADR-0088), 새 도서관 넣기는 dev 백엔드의 명령(ADR-0084)이에요. 둘 다 dev 코드예요.
  • plan은 dev에 쓰지 않는 규칙이에요. 이 프로젝트에는 "dev는 읽기만"이라는 막는 장치(.claude/hooks/guard.mjs)가 있어요. 넣기 명령을 돌리면 dev 폴더 안에 빌드 결과가 생기고, 수집기 로그도 dev 쪽에 쌓이게 돼요. plan에서 돌리면 이 규칙과 부딪혀요.
  • 절차의 원본도 dev예요. 수집 절차는 이미 dev docs/maintenance/가 원본이고, plan은 원칙·조사·결정을 맡기로 했어요(ADR-0047).
  • 지금까지 plan 세션이 수집을 돌린 건, 수집기가 아직 데이터 폴더에 있어서였어요. 사이클 13 뒤에는 그 이유가 없어져요.

2정할 것

[안] 사이클 13 개발이 끝난 뒤부터 수집·도서관 넣기는 dev 쪽 별도 "수집" 세션에서 돌리고, plan은 조사·원칙·결정만 해요. 수집 진행 기록(plan crawl-runbook.md의 상태·진행 표)은 dev docs/maintenance/로 옮기고, plan에는 결정 기록만 남겨요. 인계서에 이 한 줄을 더해요.

안좋은 점드는 것
dev 별도 수집 세션 (추천)규칙과 맞음. 개발 세션과 섞이지 않음(수집은 며칠씩 돎)세션 하나 더. 개발 중인 코드와 같은 폴더를 쓰면 수집 도중 코드가 바뀔 수 있어, 개발이 쉬는 때 돌리거나 따로 작업 폴더를 씀
사이클 개발 세션이 겸함세션이 하나개발 중 코드가 수집을 깨뜨릴 수 있고, 긴 수집이 개발을 막음
지금처럼 plan 세션익숙함dev는 읽기만 규칙을 풀어야 함
