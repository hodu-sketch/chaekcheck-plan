사이클 13을 시작하기 전에
미리 정해 두면 좋은 것 여덟 가지

"도서관 넣기를 collection 모듈이 재시작 없이"를 하려고 dev 코드를 읽어 봤습니다. 정할 것을 항목마다 골라 주세요. 여기서 정한 것은 사이클 13의 범위(scope)와 명세(spec)에 그대로 들어갑니다.

1조사해서 알게 된 것

재시작 없이 넣는 것은 가능합니다. 서비스는 도서관 표를 요청마다 읽고 캐시가 없어서, DB에 줄이 들어가면 바로 보입니다. 다만 지금 Java 코드에는 도서관을 "넣는" 기능이 아예 없습니다. 지금까지는 Liquibase(앱 시작 때 도는 seed)만 넣었습니다.
지금
수집 DB 사본 + 사람이 정한 표들→ Python 스크립트→ seed CSV 3개 (git)→ 앱 재시작 때 Liquibase가 넣음
▼ 사이클 13
바꾸면 (제안)
수집 DB 사본 + 사람이 정한 표들→ collection 모듈의 "도서관 넣기" 명령 (따로 돌고 끝남)→ library 모듈의 새 "도서관 더하기" 기능으로 도서관·가입 규칙→ collection이 짝 표→ 서비스는 재시작 없이 바로 봄
알게 된 것뜻
도서관 표의 주인은 library 모듈이고, 모듈끼리는 공개 기능으로만 서로 씀 (dev 규칙)collection이 도서관 표에 직접 쓰면 규칙 위반. library에 "도서관 더하기"를 새로 만들어야 함
스크립트 안에 사람이 정한 값이 많음이름 바꾸기 295줄, 같은 사이트 8, 체험용 4, 같은 호스트지만 남김 22, 가입 범위 덮어쓰기 8, 그리고 가입 조사·종류·교보 probe·북큐브 권수 파일. 명령이 이것들을 어디서 읽을지 정해야 함
지금 스크립트는 "앞서 만든 seed 파일"을 읽어 번호·이름을 이어 감명령으로 바꾸면 서비스 DB를 읽어 이어 가야 함
사이클 11은 운영에 반영할 때 두 DB의 도서관·짝 표가 같은지 봄명령으로 넣은 도서관이 두 DB에 똑같이 있어야 반영이 됨
지금 남은 오류: 서비스 1215 한화S&amp;C (HTML 글자가 이름에 남음)이번에 함께 고칠 것 (아래 8번)

자세한 기록: docs/cycles/13-crawler-to-dev/research.md

2도서관 넣기 명령

1library 모듈에 "도서관 더하기" 공개 기능을 새로 만들고, collection 명령이 그것을 부른다 (추천) [안]

도서관·가입 규칙 줄은 library가 넣고, 짝 표만 collection이 넣습니다. 둘을 한 번에(같은 트랜잭션) 처리합니다.

다른 선택: collection이 SQL로 도서관 표에 직접 씀(모듈 규칙 위반) / 이벤트로 알림(새 번호를 돌려받기 어려워 이 일에 맞지 않음).

2지금까지 seed로 들어간 2,600여 곳은 그대로 두고, 앞으로 더하는 곳만 명령으로 넣는다 (추천) [안]

이미 들어간 도서관은 건드리지 않습니다. 대신 앞으로는 seed로 도서관 번호를 넣지 않습니다(명령으로 넣은 번호와 부딪히기 때문). 로컬 DB를 처음부터 다시 만들 때는 seed 뒤에 명령을 한 번 더 돌리면 같은 상태가 됩니다(명령은 몇 번 돌려도 같은 결과가 나오게).

다른 선택: 있는 seed도 지우고 모두 명령으로 다시 넣음(테스트·seed를 크게 고침) / 명령이 DB에 넣으면서 seed 파일도 함께 씀(같은 줄이 두 번 들어가는 문제를 따로 막아야 함).

답: "어차피 비교해서 해야 하는 거 아니야? 도서관에 변동이 있을 수 있잖아" (2026-10-12)

맞습니다. 명령은 매번 전체를 비교합니다. 2번에서 "그대로 둔다"는 것은 이미 들어간 도서관을 명령이 고쳐 쓰지 않는다는 뜻이지, 비교에서 뺀다는 뜻이 아닙니다.

  • 비교는 지금 스크립트처럼 "앞서 만든 seed 파일"이 아니라 서비스 DB를 기준으로 합니다. 그래서 seed로 들어간 곳과 명령으로 들어간 곳을 똑같이 봅니다.
  • 바뀐 곳의 예: 사이트 주소가 옮겨짐, 공식 이름이 바뀜(사이클 09처럼), 북큐브가 구독으로 바뀜, 수집에서 "받지 않음"이 됨.
  • 이런 변화를 명령이 자동으로 고치지 않는 것은 5번(이번에는 더하기만)을 승인하셨기 때문입니다. 보고서를 보고 지금처럼 SQL·changeset으로 고칩니다. 나중에 "바뀐 곳도 명령이 고치기"로 넓힐 수 있습니다.
  • 그래서 2번은 "seed로 들어간 곳은 지우지 않고 그대로 두되, 비교에는 모두 넣는다"로 읽으시면 됩니다.

이 설명으로 2번을 골라 주세요. "바뀐 곳도 이번에 명령이 고친다"를 원하시면 기타에 적어 주세요(그러면 5번과 함께 다시 정합니다).

3사람이 정한 값은 git 안의 파일로 두고 명령이 읽는다 (추천) [안]

값지금제안
이름 바꾸기, 같은 사이트, 체험용, 같은 호스트 남김, 가입 범위 덮어쓰기스크립트 안 상수 + name_overrides.tsvdev scripts/library/(또는 resources)의 TSV 파일들. 바뀐 내역이 git에 남고 리뷰할 수 있음
공공도서관 가입 조사, 도서관 종류, 교보 probe, 북큐브 권수데이터 폴더 TSV(git 밖)같은 git 파일로 옮김 (공개된 기관 정보뿐)

다른 선택: 수집 DB에 표로 넣음(수집 세션이 관리) / 서비스 DB에 표로 넣음(운영 화면 없이 SQL로 고쳐야 함).

4명령은 먼저 "넣을 것 보고서"만 내고, 사람이 확인한 뒤 실제로 넣는다 (추천) [안]

지금 스크립트는 같은 호스트가 의심되거나 순번 2가 생기면 멈춥니다(파일은 이미 쓴 뒤). DB에 넣은 것은 파일보다 되돌리기 어려우니, 명령을 두 단계로 둡니다: ① 미리 보기(아무것도 안 씀, 넣을 도서관·이름·순번·의심 목록) → ② 넣기. 의심이 남아 있으면 ②가 멈춥니다.

다른 선택: 한 번에 넣고 의심은 보고만 함.

5이번에는 "새 도서관 더하기"만. 이름 바꾸기·끄기는 지금처럼 따로 [안]

있는 도서관의 이름 바꾸기·끄기(enabled)는 지금처럼 SQL이나 changeset으로 합니다. 명령이 하는 일을 작게 둡니다.

다른 선택: 이름 바꾸기·끄기도 명령이 함(일이 커짐).

3사이클 11과 맞추기

6도서관 넣기는 내 PC에서 하고, 운영에는 사이클 11의 반영 파일에 함께 실어 보낸다 (추천) [안]

사이클 11에서는 내 PC에서 가져오기를 하고 파일로 운영에 반영합니다. 반영할 때 두 DB의 도서관·짝 표가 같은지 보고, 다르면 멈춥니다. 그래서 새 도서관도 같은 파일에 실어 "도서관 → 짝 표 → 책" 순서로 한 번에 넣으면, 운영에서는 도서관과 그 책이 함께 나타나고 멈출 일도 없습니다.

다른 선택: 운영에서도 같은 명령을 따로 돌림(순서를 사람이 지켜야 하고, 그 사이 반영이 mismatch로 멈춤).

사이클 11이 지금 진행 중이라, 사이클 11 설계에 자리만 비워 둘지는 사이클 11 세션에 알려야 합니다(결정되면 메시지를 만들어 드림).

4수집기 쪽

7수집기는 Python 그대로 dev로 옮긴다 (Java로 다시 쓰지 않음) (추천) [안]

수집기(1,305줄)는 이번 사이클에서 위치만 옮기고, 언어는 그대로 둡니다. 도서관 넣기 명령(Java)은 수집 DB 사본만 읽으면 되므로 수집기 언어와 상관없습니다.

다른 선택: backend(Java)로 다시 씀(아주 큰 일).

8이름 속 HTML 글자(&amp; 등)는 명령이 넣을 때 풀고, 남은 한 곳(1215 한화S&amp;C)도 이번에 고친다 (추천) [안]

수집 DB 이름은 사이트에서 읽은 그대로라 &amp; 같은 글자가 남을 수 있습니다. 명령이 넣을 때 보통 글자로 바꾸고, 수집 DB에서도 같은 곳을 고칩니다.
