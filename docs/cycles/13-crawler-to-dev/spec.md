# 기능 명세: 사이클 13 수집기 (dev로 갈아타기 + 도서관 넣기 명령)

- 작성 2026-10-12. 범위: `scope.md` (사전 결정 8, 도서관 날짜 3, 완료 기준 7)
- 조사: `research.md` (1~7절)
- 이 대화의 질문과 답 (2026-10-12, 묻기 창). 명세의 [안]도 묻기 창에서 모두 정함("모두 추천대로", 의심 범위·옛 스크립트·여주대 각 추천):
  - 보고서는 파일로 남김
  - 보고서는 Claude(수집 세션)가 보고 의심·바뀐 곳만 사용자에게 물음
  - "바뀐 도서관"은 주소·이름·화면 종류·대출 방식·받지 않음
  - 넣기는 보고서와 같을 때만
  - 공지는 서비스 안내 페이지

## 사용자 이야기

- 운영자(사용자)는 수집을 dev 코드로 돌리고 싶다. 수집기 코드가 두 벌이라 헷갈리지 않게.
- 운영자는 새로 찾은 도서관을 앱을 다시 켜지 않고 서비스에 넣고 싶다. 그리고 넣기 전에 무엇이 들어가는지 알고 싶다.
- 운영자는 확인을 Claude에게 맡기고, 의심스럽거나 바뀐 곳만 직접 보고 싶다.
- 서비스 이용자는 학교·회사 같은 새 도서관도 "내 도서관 → 직접 추가"에서 찾고 싶다.
- 서비스 이용자는 가입 조건 정보가 언제 조사된 것인지 알 수 있어야 한다.

## 상태별 동작

| 상황 | 동작 |
|---|---|
| 미리 보기: 새로 넣을 곳 0 | "넣을 도서관 없음" 보고서, 넣기 할 일 없음 |
| 미리 보기: 의심 있음 | 보고서에 표시. Claude가 사용자에게 물음. 남아 있으면 넣기가 멈춤(종료 코드로 구분) |
| 미리 보기: 규칙 파일에 없는 종류·알 수 없는 업체·지역 이름을 못 읽음 | 보고서를 만들지 않고 멈춤, 이유를 보여 줌(지금 스크립트와 같음) |
| 넣기: 보고서 번호가 없거나 내용이 달라짐 | 넣지 않고 멈춤, 무엇이 다른지 보여 줌 |
| 넣기: DB 제약 위반(주소 중복, 분류 겹침) | 한 트랜잭션이라 아무것도 들어가지 않음, 실패 기록 |
| 넣기 뒤 서비스 | 재시작 없이 다음 요청부터 보임(서비스가 도서관 표를 요청마다 읽음, `research.md` 2절) |
| 넣은 도서관의 책 | 다음 가져오기 때 들어옴. 그 사이에는 책 0권 |
| 수집: 사이트가 막음(403·시간 초과가 이어짐) | 그 도서관만 받지 않음 표시(R1-7) |
| 수집: 갈아탄 수집기가 옛 수집기가 돌고 있는 것을 봄 | 시작하지 않음(dev `resume.cmd`의 두 벌 실행 검사) |

## 수용 기준

- AC-1: dev 수집기로 여주대(102084) 빈 곳 채우기를 돌리면 끝까지 돌고, 수집 DB의 여주대 줄 수가 돌리기 전보다 늘거나 같으며, 기록에 "refill done"이 남는다
- AC-2: 옛 코드가 보관 폴더에 있고, 데이터 폴더에서 옛 `resume.cmd`를 찾을 수 없다. dev `resume.cmd`만 수집을 시작한다
- AC-3: 2026-10-12 사본으로 미리 보기를 돌리면 보고서 파일이 생기고 아래가 나온다
  - 새로 넣을 도서관 6곳: 여주대 100584·102084, 한국선원복지고용센터 102029, 김천대 102092, 경운대 102101, 천상중 102171
  - 사라진 곳 0
  - 의심 0. 여주대 두 곳(같은 호스트, 교보 쪽 책 코드 2,199개 중 2,198개가 YES24 쪽에도 있음)은 사용자가 "둘 다 넣음"으로 정해 '같은 호스트지만 남김' 파일에 들어가므로 의심에서 빠짐
  - 순번 2 이상 0
- AC-4: 넣기를 보고서 번호와 함께 돌리면 6곳이 서비스에 들어간다. 앱을 다시 켜지 않고 "내 도서관 → 직접 추가"에서 "여주대학교"를 찾으면 두 곳(교보·YES24)이 나온다
- AC-5: 미리 보기 뒤 규칙 파일을 하나 바꾸고 같은 보고서 번호로 넣기를 하면, 아무것도 넣지 않고 무엇이 다른지 보여 준다
- AC-6: 같은 사본으로 옛 스크립트와 새 명령을 돌리면 새로 넣을 도서관의 번호·이름·업체·대출 방식·순번·가입 조사 상태·가입 규칙·짝 줄이 같다. 다른 점은 HTML 글자 풀기와 같은 호스트 범위(R2-7)뿐이다
- AC-7: 넣기 뒤 내 PC에서 가져오기·내보내기를 하고 운영 역할 DB에 반영하면, 반영이 `mismatch` 없이 끝난다. 운영 역할 DB에 6곳과 그 책이 함께 있다
- AC-8: 넣기 명령을 같은 사본으로 한 번 더 돌리면 새로 넣을 곳 0이다
- AC-9: 도서관 1215 이름이 화면에서 "한화S&C"로 보인다
- AC-10: 서비스 안내 페이지에 "가입 조건은 2026년 10월에 조사한 내용입니다"가 보인다
- AC-11: dev 코드·절차 문서에서 "candidate"·"후보"를 찾으면 이미 적용된 Liquibase 파일 이름과 지난 기록 말고는 나오지 않는다
- AC-12: 넣기 실행 기록에 실행 시각·사본·넣은 수·보고서 번호·가입 조건 조사 기준일이 한 줄로 남는다

## 비목표

- 있는 도서관의 이름 바꾸기·끄기·주소 고치기를 명령이 하기 — 사전 결정 5
- 보고서를 화면(웹)에서 보기 — 파일과 명령 창으로 충분 [이유 미확인]
- 도서관마다 조사·수집 날짜를 화면에 보이기 — 사용자: "굳이 보여줄 필요는 없어. 어디 공지로 하자.."
- 수집기 코드를 갈래별·화면별로 나누기 — 사전 결정(갈아타기 4), backlog
- 넣기를 정해진 때마다 자동으로 — 자동 갱신은 사이클 11처럼 밖에 둠
- 교보 구독형 서버 다시 수집 — ADR-0067, 우리 IP가 막혀 있음
