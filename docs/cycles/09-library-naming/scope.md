## 목표 (한 문장)

모든 도서관 이름에서 업체·대출 방식 괄호를 떼고, 이름 옆에 "교보 · 소장"처럼 분류를 보여 주며, 겹침은 (이름, 업체, 대출 방식, 순번) 조합으로 막는다 [확정] (인계 문서 1절, 사용자 승인 2026-10-11)

## 포함

1. ADR: 인계 문서 7절 초안에 번호를 붙여 씀. ADR-0017 "감수하는 점"과 사이클 07 seed 규칙 "이름" 줄을 대체 [확정 방향] (결정 6)
2. 이름: 서비스 seed의 분류 괄호(277곳, `research.md` 3절)를 뗌. 기관 이름의 일부인 괄호는 남김 (결정 1). 사이클 08이 붙인 434·456 "(북큐브)"도 뗌. 이름 고침 묶음에 977 "국립경국대학교"(spec R1-9)와 이름이 바뀐 학교 6곳(spec R1-10)도 넣음 [확정] (사용자 승인, 2026-10-11, `../08-polish-swap-memory/easy/2026-10-11-midpoint-decisions.html`, `…/2026-10-11-final-decisions.html`)
3. 분류: 모든 도서관에 업체와 대출 방식(`lending_model`)을 채움 (결정 2)
4. 겹침 규칙: `name` UNIQUE를 (이름, 업체, 대출 방식, 순번) UNIQUE로 바꿈 (결정 3, 순번은 spec R4-4)
4a. 덤: 1149 이름의 HTML 이스케이프 오류 고침(spec R1-8), 76·64 이름 정리(R1-3), 386 "대여형" 뗌(R1-11), 수집 DB 이름도 같게(R1-7), dev 도구 `check_front_page_names.py`의 괄호 떼기 지움(design-delta) [확정] (사용자 승인, 2026-10-11)
5. 남은 겹침: 부산 339 구독, 양산 두 곳 정식 이름, 1575 "완주동상초등학교", 제주한라 140 구독 (결정 4, spec R4-3)
6. 화면: 이름 옆 작은 분류 표시. 보이는 곳은 flow에서 정함 (결정 5, 인계 문서 5절)
   - 양산 93 "양산시립도서관"(근거: https://lib.yangsan.go.kr/ 머리 로고·저작권 줄, 2026-10-11 확인), 100747 "경상남도교육청 양산도서관" [확정] (사용자 승인, 2026-10-11, `easy/2026-10-11-scope-decisions.html`). 100747의 교육청 쪽 정식 이름은 확인 못 함 → dev가 이름을 고칠 때 출처 다시 확인
7. dev 이름 생성 규칙 고치기: `build_candidate_seed.py`의 괄호 규칙(`name_candidates()`, `LABELS`), dev 문서 `library-maintenance.md` 1-1·4-5절 (인계 문서 6절 6·7)

## 정한 규칙

- 이름 유지: 이번 괄호 떼기는 한 번만 하는 예외. 그 뒤에는 "한 번 정한 이름은 바꾸지 않음"을 지키고, 예외는 사이클 08에서 정한 공식 개명·틀린 이름(`name_overrides.tsv`)뿐 [확정] (사용자 승인, 2026-10-11: "이렇게 해줘")
- 통합 포털 7곳(`ELIB_PORTAL_V1`)은 대출 방식을 비워 둠(NULL). 화면에는 "통합 포털"만 보임 [확정] (사용자 승인, 2026-10-11). 그래서 UNIQUE는 NULL을 같은 값으로 봄(NULLS NOT DISTINCT) [확정] (사용자 승인, 2026-10-11, `easy/2026-10-11-spec-flow-decisions.html`)

## 완료 기준 (사용자가 화면에서 확인할 수 있는 것)

- 자세한 기준은 `spec.md` AC-1~8
