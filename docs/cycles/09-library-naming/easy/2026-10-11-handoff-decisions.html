사이클 09 인계서입니다.
dev가 이 순서로 만듭니다.

인계서(handoff.md)는 dev가 그대로 따라 만드는 작업 순서입니다. 정하신 것만 담았고, 새로 고르실 것은 작은 것 5개와 마지막 "넘김" 하나입니다. 승인하시면 docs/current/handoff.md로 옮겨 dev 세션이 자동으로 읽습니다.

1만드는 순서 (0~7단계)

색: 파랑 = 재기·확인, 주황 = 보통, 빨강 = 위험 높음, 초록 = 문서. 점선은 dev 밖의 일입니다.

dev가 지킬 것 중 이번에 새로 더한 것: 이미 적용된 seed·변경 파일은 고치지 않음(정하신 seed 방식), 교보 구독형 서버에는 요청하지 않음(막혀 있음), 검색 결과의 대출 가능 판정이 바뀌면 멈추고 보고.

2도중에 여쭐 것

dev가 만들다가 아래를 보여 드리고 답을 받습니다.

  • 공식 이름이 명세와 다른 곳(학교 6곳, 977, 양산·마산 교육청 도서관): 출처 원문과 제안
  • 북큐브 구독 번호가 339·380·386·705가 아니면
  • 순번 2 이상이 나오면(지금은 없을 것으로 봄): 사이트 이름 확인
  • 실제로 이름을 바꿀 줄 수와 목록: 변경 파일을 커밋하기 전
  • 도서관 목록 응답이 얼마나 커졌는지, 화면 확인

3고르실 것

인계서에서 처음 나온 작은 제안들입니다. 정하신 큰 틀은 바뀌지 않습니다.

결과 카드 순서: 이름 → 분류 → 폰 안내 [안]

YES24 폰 안내("폰에서는 사이트가 다른 화면을…")가 있는 13곳은 카드에 줄이 셋이 됩니다. 이름 다음에 "YES24 · 소장", 그 아래에 폰 안내를 둡니다.

다른 선택 — 이름 → 폰 안내 → 분류: 안내가 이름에 더 가깝지만, 분류가 이름과 떨어져 보입니다.

추천: 이름 → 분류 → 폰 안내.

[추가]·[빼기] 버튼의 화면 읽기용 이름에 분류를 넣음 [안]

화면 읽기 프로그램을 쓰는 사람에게 버튼이 "동대문구립도서관 추가"로만 읽히면 같은 이름 두 줄을 구분할 수 없습니다. "동대문구립도서관 YES24 소장 추가"처럼 읽히게 합니다. 화면에 보이는 글자는 그대로입니다.

추천: 넣음.

질문: 무슨 상황인지 그림으로

앞이 잘 안 보여 화면을 소리로 듣는 사람이 내 도서관 화면에서 [추가] 버튼을 고를 때의 일입니다. 폰의 VoiceOver(아이폰)·TalkBack(안드로이드) 같은 화면 읽기 기능은 손가락이 닿은 버튼의 "읽기용 이름"을 소리로 읽어 줍니다. 이 이름은 화면에 보이지 않고, 웹 코드에 따로 적어 둡니다(aria-label).

눈으로 보는 화면은 바뀌지 않습니다. 소리로 읽히는 말에만 분류가 더해집니다. [빼기] 버튼과 직접 추가한 도서관 목록도 같습니다.

dev 웹 코드는 지금도 버튼마다 읽기용 이름을 "○○ 추가", "○○ 빼기"로 적어 두고 있습니다(MyLibrariesPage.tsx, 2026-10-11 읽음). 이번 제안은 그 말에 분류를 끼워 넣는 것뿐입니다. 위 버튼으로 골라 주세요.

이름 찾기에서 띄어쓰기 없이 친 검색어도 지금처럼 찾힘 [안]

새 규칙은 검색어를 띄어쓰기로 나눠 낱말마다 봅니다. 여기에 "검색어 전체(띄어쓰기를 지운 것)가 이름에 들어 있어도 맞음"을 남겨, 지금 찾히던 것이 새 규칙 때문에 안 찾히는 일이 없게 합니다. 예: "창원대학교거창"으로 "국립창원대학교 거창캠퍼스"가 찾힘.

추천: 남김.

이름 고침 목록의 표시: "(sam)"·"대여형"도 괄호 떼기와 같은 표시, 메리츠는 오타 표시 [안]

이름 고침 목록(name_overrides.tsv)에는 고친 까닭을 짧게 적습니다. 괄호 떼기는 label-removed로 정하셨습니다. 서대문 "(sam)"과 진천군립 "대여형"도 같은 표시로, 메리츠의 깨진 글자는 사이클 08에서 오타를 고칠 때 쓴 typo로 적습니다. 출처 칸에는 괄호 떼기의 경우 "ADR-0071"을 적습니다.

추천: 이대로.

DB 변경 파일 014는 한 덩어리로 실행 [안]

이름 고침부터 새 겹침 규칙까지 일곱 단계를 한 번에 실행합니다. 중간에 겹침이 나오면 일곱 단계 전부가 취소되고 배포가 멈춥니다. 반쯤 바뀐 상태로 남지 않습니다(PostgreSQL은 표 구조 변경도 한꺼번에 되돌림).

다른 선택 — 단계마다 나눔: 어디서 멈췄는지 더 잘 보이지만, 반쯤 바뀐 상태가 남을 수 있습니다.

추천: 한 덩어리.
