1무엇을 만드나

새 모듈·새 표·새 이벤트는 없습니다. 도서관 표에 칸 둘을 더하고, 이름을 고치고, 서버와 화면이 분류를 보이게 합니다.

어디바뀌는 것
도서관 표 (DB)이름 겹침 규칙을 지우고 → 이름 약 293곳 고침 → 업체 칸 더해 채움 → 대출 방식 채움 → 순번 칸 더함 → 확인 규칙 셋 → 새 겹침 규칙(이름·업체·대출 방식·순번)
서버도서관 목록과 검색 스트림에 vendor·lendingModel·orderNo
화면결과 카드는 이름 다음 줄에 "교보 · 소장", 내 도서관은 이름 옆(폰은 아래 줄), 이름 찾기가 분류 글자도 찾음
seed 생성 스크립트괄호 규칙을 지우고 업체 대응표·대출 방식 규칙·순번 세기. 배포 뒤에는 바뀐 것만 변경 파일로
수집 DB같은 이름으로 바꿈(수집 세션이 함)

고치는 이름의 내역: 괄호 떼기 277곳, 사이클 08이 붙인 "(북큐브)" 2곳, 따로 정한 7곳(서대문, 마산, 양산 둘, 완주동상초, 메리츠, 진천군립), 977 국립경국대학교, 이름이 바뀐 학교 6곳.

검색 결과의 "대출 가능" 판정은 바뀌지 않습니다. 대출 방식으로 동작이 갈리는 곳(교보 구독형이 "소장"인지)에 새로 "소장"이 들어가는 도서관이 없기 때문입니다(dev 코드 확인, 2026-10-11).

2업체 칸의 확인 규칙

업체는 도서관 수집이 정하고(정하신 것), DB는 허용 값인지 확인합니다. 그 확인 규칙의 이름과 "비어 있어도 되는 때"를 정합니다.

업체는 6값 중 하나, 전자도서관이면 반드시 있어야 함 [안]

DB 확인 규칙 library_vendor_check: 업체 값은 KYOBO·YES24·BOOKCUBE·ALADIN·PORTAL·IN_HOUSE 중 하나. 그리고 지금 "전자도서관이면 화면 종류와 주소가 있어야 함" 규칙처럼, 전자도서관이면 업체도 있어야 합니다. 나중에 실물 도서관이 들어오면 업체가 비어 있어도 됩니다.

다른 선택 — 업체를 늘 필수로: 단순하지만, 실물 도서관 사이클에서 규칙을 다시 고쳐야 합니다.

추천: 전자도서관이면 필수. 지금 표의 규칙과 같은 모양입니다.

3dev 도구 하나 정리

사이트 제목과 이름을 비교하는 도구의 "괄호 떼기"를 지움 [안]

dev 도구 check_front_page_names.py는 사이트 첫 화면 제목과 우리 이름을 비교할 때, 우리 이름에서 "(교보)", "(구독)" 같은 괄호를 먼저 뗍니다. 이번에 이름에서 괄호가 모두 없어지므로 이 단계가 필요 없습니다.

다른 선택 — 그대로 둠: 해는 없지만, 읽는 사람이 왜 있는지 헷갈립니다.

추천: 지움.

4남은 확인 (개발 때 dev가 함)

정하실 것은 아니고, dev가 개발하며 확인하고 다르면 여쭙는 것들입니다.

  • 북큐브 구독 4곳의 서비스 번호(339·380·386·705)를 수집 번호와 다시 맞춤
  • 이름이 바뀐 학교 6곳, 977, 양산·마산 교육청 도서관의 공식 이름을 출처로 다시 확인
  • 도서관 목록 응답이 얼마나 커지는지(압축 뒤)
  • 변경 파일 번호(지금 마지막이 013이라 014로 봄)
  • 수집 DB 이름을 바꾸는 방법·때(수집 세션)

이 설계 문서대로 인계서로 넘어감 [안]

승인하시면 설계 검토(design-reviewer)를 돌리고, ADR-0071을 Accepted로 바꾸고, dev가 따라 만들 인계서를 써서 보여 드립니다.
