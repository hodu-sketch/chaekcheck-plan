## 목표 (한 문장)

사이클 07에서 정한 작은 수정과 화면 수정을 끝내고, 가져오는 동안에도 책 검색이 멈추지 않게 표를 바꿔 끼우며, DB·캐시·Java 메모리를 속도를 잃지 않는 선에서 줄인다 [확정] (사용자: "B랑 C같이 하고 싶은데", "캐시 줄이는 방향으로도 추가로 가자 DB메모리도 어떻게 해야 최적인가(너무 메모리에 맞춰서 줄였다가 느려지면 또 그건 별로니까) 찾아보자", 2026-10-05).

### 메모리 줄이기 (속도를 잃지 않는 선)

12. 먼저 잼: 서비스 Java 메모리, 두 캐시(도서관 검색 쪽 `SearchPageCache`, 책 상세 판정 `DetailVerdictCache`, 지금 3분·최대 1,000개)의 실제 크기와 적중률, DB가 책 화면·검색에서 읽는 쪽 수
13. 캐시 메모리 줄이기: 개수 대신 크기로 상한을 두거나, 담는 값을 필요한 칸만 남김. 줄이는 것은 [확정], 방법은 [안] (사용자: "캐시 줄이는 방향으로도 추가로 가자", "물론 DB메모리도 줄이고 캐시 메모리도 줄이고", 2026-10-05)
   - 설계에서 정함: 두 캐시 통계를 켜고 캐시마다 상한 설정을 나눈 뒤 잰 값으로 상한을 정함 [확정] (ADR-0066)
13a. 검색 계획(`planSearch`)은 들어갈 수 있는 도서관(가입 조사됨·안내 못 찾음 + 직접 추가)만 SQL로 읽음. 켜짐 여부는 요청마다(ADR-0004 그대로) [확정] (사용자 승인, 2026-10-11, 설계 검토; ADR-0066)
13b. 도서관 응답 본문 복사 줄이기: `BodyLimit`는 `Content-Length`로 처음 크기를 정하고, 조회 서버 경로는 `byte[]`로 받음. 줄이는 것은 [확정] (사용자: "비효율적이고 고칠 수 있으면 지금 고치는게 나아", 2026-10-11; ADR-0066), 방법은 [안] (`design-delta.md` 모듈 표 `availability`)
14. 서비스 Java 메모리 상한을 정함 [안]
15. DB 메모리 줄이기: 메모리 설정(`shared_buffers`, `effective_cache_size`, `work_mem` 등)을 어디까지 줄여도 빠른지 **이번 사이클에서** 찾음(줄이는 정도와 응답 시간을 함께 잼). 줄이는 것과 최적점 찾기는 [확정] (사용자: "DB메모리도 어떻게 해야 최적인가(너무 메모리에 맞춰서 줄였다가 느려지면 또 그건 별로니까) 찾아보자", "이거 지금하겠다고 했어", 2026-10-05). 책 화면이 계획한 도서관 줄만 읽기(DB 메모리 안 3)는 [확정] (ADR-0066)
16. 가져오기가 더 작은 Java 메모리로 되는지 잼 (지금 8GB에서 끝남)

## 완료 기준 (사용자가 화면에서 확인할 수 있는 것) [안]

- 정렬·완전 일치·역할은 새로 열면 기본값으로 돌아가고, 범위·방문 없이 가입·지금 빌릴 수 있는 책만·보기 방식·직접 찾기는 남아 있다
- 너무 자주 검색하면 "검색을 너무 자주 했어요…" 문구가, 서버가 바쁘면 "지금 찾는 사람이 많아요…" 문구가 보인다
- 폰에서 YES24 13곳의 링크 옆에 PC 안내가 보인다
- 가져오기를 돌리는 동안 첫 화면에서 책을 검색하면 결과가 나온다
- 메모리 측정표(줄이기 전 / 뒤)와 응답 시간표(첫 쪽, 책 화면)를 보고, 메모리를 줄여도 검색 첫 쪽이 1초 안(사이클 07 기준)이다
- 화면 질문 여섯의 결과가 PC·태블릿·폰에서 보인다

## 먼저 조사할 것 [확인 필요]

| 항목 | 확인 방법 |
|---|---|
| PostgreSQL 메모리 설정(`shared_buffers`, `effective_cache_size`, `work_mem`)의 공식 권장과 재는 법 | 공식 문서 확인 (PostgreSQL 18 문서) |
| DB가 메모리에 올린 쪽을 표별로 보는 방법(`pg_buffercache`), 쿼리마다 읽은 쪽(`EXPLAIN (ANALYZE, BUFFERS)`) | 공식 문서 확인, 프로토타입 |

| 같은 책 소장 줄 붙여 저장: 정렬해 쓰기와 `CLUSTER`의 차이, 다시 흩어지는지 | 공식 문서 확인, 프로토타입 (`db-memory.md` 4절) |
| Caffeine 크기 상한(`maximumWeight` + `weigher`) | 공식 문서 확인 |
| Java 메모리 상한과 실제 사용량 재는 법(Spring Boot Actuator 등) | 공식 문서 확인, 프로토타입 |
| 트리거로 `updated_at` 자동 기록 | 공식 문서 확인 (PostgreSQL PL/pgSQL 트리거, 2026-10-05 확인함: 예 41.3) |
| 글꼴 서브셋 방법과 라이선스(나눔바른고딕) | 공식 문서 확인 |

- ICE 점수는 매기지 않음. 사용자가 후보 다섯(A 배포 준비, B 다듬기, C 주기 갱신 + DB 메모리, D 구독형 한도, E 알림) 가운데 B·C를 고름. A·D·E는 "나중"

## 영향 받을 모듈 [안]

- `catalog`: 표 바꿔 끼우기, 소장 줄 순서, 책 화면 소장 읽기(안 3)
- `collection`: 가져오기 기록에 수집 기간, 바꿔 끼우기 호출
- `availability`: 캐시 크기 상한, 429·503(`Retry-After: 5`), 응답 본문 복사 줄이기
- `library`: YES24 안내 표시 칸, 이름 고치기 seed(이름 고침 목록), `updated_at` 트리거, `planSearch` 읽는 도서관 줄이기
- `region`: `updated_at` 트리거
- 웹: 검색 조건 기억, 오류 문구, YES24 안내, 화면 질문 여섯, 글꼴
- nginx·운영 설정: 바뀌지 않음(배포 보류)
