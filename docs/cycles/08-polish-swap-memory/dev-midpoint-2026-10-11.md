## 설계와 달라진 점 (plan이 회고 때 확인)

1. 국가서지 원문: ISBN이 여럿인 기록은 ISBN마다 한 줄(`isbn13` 13자리 유지). 결과는 같음
2. `step_seconds` 키: 인계서 키에 더해 `group`, `same_text`, `books_copy`, `holdings_read`, `holdings_copy`, `load`(전체), 옛 방식의 `move`·`vacuum`
3. 실패 기록 칸: `catalog_import.status`(SUCCEEDED | FAILED), `failure_reason`, `failure_detail`
4. 넓은 줄은 임시 표와 `catalog_next`에 두 번 씀(`book_id` 순 정렬). 쓰기 시간이 이미 줄어 바꾸지 않음
5. S10 이름 찾기가 가운뎃점(·)도 무시 [안]
6. 폰 직접 찾기 "정렬 없음 ⓘ"은 검색 줄(폰의 정렬 자리)에 둠
7. 캐시 상한은 두 캐시 모두 1,000 그대로(1,000칸이 차도 10MB 안팎). ADR-0006 값 변경 없음
8. 이름 고침은 seed CSV를 다시 만들지 않고 changeset 013(번호 + 옛 이름 조건 UPDATE). seed 스크립트도 목록을 읽음. 다음에 seed를 다시 만들면 CSV에 새 이름이 들어가 `loadData` checksum이 바뀜 → 배포 뒤 seed 갱신 방식을 정해야 함
9. 수집 DB 230곳 표시는 `status --skip`이 1곳에 약 50초라 같은 UPDATE를 한 번에 실행
