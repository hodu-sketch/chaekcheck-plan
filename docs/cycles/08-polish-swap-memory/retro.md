## 계획대로 된 것

- 가져오기 바꿔 끼우기: 새 표(`catalog_next`)에 색인 없이 쓰고, 짧은 잠금으로 바꿔 끼움. 검색이 기다린 시간 9분 37초(#1 지금 방식) → 0.33초(#2). 가져오기 전체 약 47분 → 약 41분, 쓰기 23분 30초 → 16분 50초 (AC-8b)
- 가져오는 동안 검색 p95 560ms, 1,705번 요청에 5xx 0, 바꿔 끼우는 순간도 200 (AC-8)
- 책·소장 번호 잇기: kept 1,615,125 / new 0 / dropped 0 (AC-10). 바꿔 끼우기 전에 받은 소장 번호로 다음 묶음도 정상 (AC-8c, ADR-0070)
- 줄 붙이기(같은 책의 소장을 책 번호 순으로): `holding.book_id` 상관도 0.0116 → 1.0, 책 3권 소장 읽기 1,169쪽·78ms → 77쪽·1.4ms. 첫 쪽 응답 p50·p95 143·406ms → 97·320ms
- 준비 문장(AC-21): 바꿔 끼우기 전에 만든 풀 연결로 계속 검색해도 오류 없음. 잠금 줄 서기는 한 번에 최대 `lock_timeout` 2초, 2초·10초·5번은 바꾸지 않음
- 국가서지 원문 저장과 정리 규칙을 바꿀 때 다시 가져오는 순서 (ADR-0069, `3-import.md` 12절)
- `updated_at` DB 트리거 (ADR-0068), 가져오기 기록의 수집 기간(AC-7)
- 검색 조건 기억 범위, 429·503 문구, 503 `Retry-After: 5`, YES24 폰 안내 13곳(`mobile_site_differs`), 화면 질문 여섯
- 글꼴 woff2 합 2,997,692 → 629,272바이트(−79%), 드문 음절이 있을 때만 원래 파일 (AC-13)
- 교보 대여·혼합 11곳 seed에서 지움(ADR-0067): 소장 −2,669,217, 책 −2,320(사이클 07 2회차 대비). 수집 DB 230곳 받지 않음 표시
- 이름 고침 8곳(changeset 013, `name_overrides.tsv`), 흡수된 학교 7곳은 보고만
- 메모리: DB `shared_buffers` 64MB, `effective_cache_size` 768MB, `work_mem` 4MB, 컨테이너 상한 권장 1GB, 서비스 힙 512MB (모두 로컬 PC 기준)
- 디스크 최대 19.1GiB(바꿔 끼우는 동안, 시작 8.5GiB)
- Modulith `components.puml`의 관계가 `docs/current/module-map.md`와 같음: Collection→Catalog·Library, Catalog→Library, Library→Region, Availability→Library·Catalog, Mylibrary→Auth·Library·Region. 이번 사이클에 모듈 관계 변화 없음

- 교보 구독형 서버(103.182.126.192, `*.dkyobobook.co.kr`)는 이 집 IP에서 10-07부터 막혀 있고 10-11에도 응답 없음. 바깥(WebFetch)에서는 연결 거부 (`docs/research/ebook-catalog/crawl-runbook.md` 8-2-1절). 이 서버의 소장형 1,187곳 책 화면 대출 현황과 "도서관에서 직접 찾기"는 이 PC에서 실패할 수 있음 [확인 필요: dev 화면에서]

- 교보 사이트 첫 화면 제목("전자도서관", "Insert title here")은 스크립트로 넘기는 빈 화면이라 이름 판단에 못 씀. `/elibrary-front/main.ink`의 `<title>`과 화면 아래 "도서관명 :"을 봐야 함 (dev `library-maintenance.md` 4-12-2)
- seed CSV를 다시 만들면 `loadData` checksum이 바뀜 (dev 설명. Liquibase는 적용된 changeset이 바뀌면 checksum 오류, https://docs.liquibase.com/concepts/changelogs/attributes/runonchange.html 확인 2026-10-11)
