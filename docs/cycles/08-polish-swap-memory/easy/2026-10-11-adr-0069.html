국가서지 결과를 남기는 방식이 바뀐 것을
결정 기록 ADR-0069로 남깁니다.

ADR-0065(가져오기는 새 표에 쓰고 바꿔 끼운다)에는 "국가서지 결과를 파일 지문·정리 규칙 판과 함께 남긴다"고 적었습니다. 그 뒤 질문을 거쳐 "원문을 남기고 판 번호는 두지 않는다", "정리 규칙을 바꿀 때 상황별 할 일"로 정하셨습니다. 확정된 기록은 고칠 수 없어 새 기록으로 남깁니다.

1ADR-0069 초안

1ADR-0069: 국가서지는 원문을 남기고, 정리 규칙을 바꿀 때는 상황별로 다시 가져온다 (ADR-0065 일부를 바꿈) [안]

결정.

  • 국가서지 TTL에서 뽑은 원문(ISBN·제목·저자·출판사)과 파일 지문만 남긴다. 지문이 같으면 원문을 다시 쓰고, 가져올 때마다 지금 정리 규칙으로 다듬는다. 정리 규칙 판 번호는 두지 않는다
  • 새 사본으로 갱신하거나 묶기·대표값·날짜 규칙만 고쳤으면: 가져오기 → 바꿔 끼우기. 서비스는 그대로
  • 검색어 다듬기 규칙을 고쳤으면: 옛 서비스를 켜 둔 채 새 코드로 가져오기 → 바꿔 끼우자마자 서비스를 새 코드로 다시 켬
  • 표 교체는 한 트랜잭션에서 이름 자리만 바꾸므로 켜진 서비스는 다음 검색부터 새 표를 읽는다(PostgreSQL 18 PREPARE: 쓰는 표가 바뀌면 다시 계획, 확인 2026-10-11). 연결 풀에서의 확인은 만들 때

이유. 사용자: "규칙을 db에 남겨야 하나? 어짜피 새 규칙으로 db가 새로 만들어 져야 하는 거 아니야?", "테이블만 바꿔끼우는 거면 굳이 '규칙을 고치고 VERSION 3→4'이것을 할 필요가 없지 않나?", "그냥 트랜잭션 걸려 있어서 테이블만 교체하면 알아서 되는 거 아니야? 검색어를 다듬는 규칙이 달라지는 경우에만 서비스 다시 키면 되는 거 아니야?", 상황별 표에 "이렇게 해줘" (2026-10-11).

검토한 대안 다듬은 키 + 손으로 올리는 판 번호 + 잊지 않게 하는 테스트(처음 제안), 자동 지문(테스트 벡터 해시), 배포 번호를 판으로.
