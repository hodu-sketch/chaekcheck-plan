4정할 것

1수집 기간 칸과 폰 사이트 다름 표시는 따로 결정 기록(ADR)을 남기지 않음 [안]

둘 다 범위·요구 문서에 사용자 말씀과 날짜로 이미 적혀 있고, 칸 하나씩 더하는 작은 변경이라 구조를 바꾸는 결정이 아닙니다. 승인하시면 지금처럼 범위(scope.md 3·7번) 기록으로 둡니다.

다른 선택 ADR 두 개를 새로 씀: 나중에 찾기는 쉬워지지만 결정 기록이 작은 칸 추가로 늘어남.

2이름 고침 목록은 후보 도서관 seed 스크립트(build_candidate_seed.py)가 적용 [안]

고칠 곳이 모두 후보로 들어온 도서관(번호 281 이상)이라, 그 seed를 만드는 스크립트가 목록을 읽게 합니다. 다음에 seed를 다시 만들어도 고친 이름이 유지됩니다.

다른 선택 등록 도서관 스크립트(build_seed.py)까지 둘 다 읽음: 나중에 등록 도서관 이름이 바뀌어도 같은 목록을 쓸 수 있지만 지금은 대상이 없음.

답: 구체적으로 어떻게 되나요?
도서관 목록은 손으로 쓰지 않고 스크립트가 만든 파일(seed CSV)로 DB에 들어갑니다. 스크립트가 둘 있습니다.

스크립트만드는 것대상
build_seed.py처음 등록한 도서관 파일(library/004 등)번호 1~280쯤, 교보 사이트 점검으로 넣은 곳. 이미 다 만들어져 다시 돌리지 않음
build_candidate_seed.pylibrary/008-library-candidates.csv, collection/002-collection-link.csv번호 281 이상, 수집 DB에서 온 후보 도서관. 새 사본이 오거나 규칙이 바뀌면 다시 돌림(이번 교보 11곳 빼기도 이걸로)

왜 목록 파일이 필요한가: 이 스크립트는 다시 돌릴 때 "이미 있는 후보는 번호와 이름을 그대로 둔다"는 규칙이 있어(dev build_candidate_seed.py 21행), 이름을 한 번 손으로 고쳐도 근거가 남지 않고, 수집 DB 이름으로 새로 만들 때 옛 이름이 돌아올 수 있습니다. 목록이 있으면 스크립트가 매번 목록대로 덮어써서 고친 이름이 유지되고, 출처와 확인일도 함께 남습니다. 고칠 곳(434, 456, 1016, 1079, 2161, 2264, 2563, 2611)이 모두 281 이상이라 후보 스크립트 하나만 읽으면 됩니다.

덧붙임: 아직 배포 전이라(PRE_DEPLOYMENT 표시, dev CLAUDE.md 47행) 교보 11곳처럼 CSV를 다시 만들고 로컬 DB를 초기화하는 방식이 됩니다. 그러면 설계에 적은 별도 이름 고침 UPDATE 파일(library/013)은 없어도 됩니다. 원하시면 다음 페이지에서 따로 여쭙겠습니다.
