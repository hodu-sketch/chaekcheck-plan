사이클 08에서 정할 것을
한 페이지에 모았습니다.

주무시는 동안 스펙(spec.md), 화면 흐름(flow.md), 메모리·가져오기 조사(research.md), 구조 안(architect-proposal.md)을 만들었습니다. 각 칩은 추천안입니다. 다 고르시면 이 결과로 설계(design-delta.md)를 씁니다. 자세한 설명은 앞서 보낸 페이지 셋(메모리 쓰임, 메모리 구조 안, 가져오기 시간 안)에 있습니다.

1가져오기·교체 시간

지금 36~41분, 그중 쓰기 끝부분 동안 검색이 멈춥니다. 여덟 방향 중 셋을 묶는 것을 추천합니다.

1새 표에 색인 없이 쓰고 → 색인을 나중에 만든 뒤 → 이름 바꿔 끼우기 + 국가서지 푼 결과 남기기 [안]

검색은 이름을 바꾸는 순간만 잠깐 기다립니다. 국가서지(6.5~9분)를 매번 다시 풀지 않습니다. 새 표에 같은 책 줄을 붙여 써서 DB 메모리 줄이기도 함께 됩니다.

다른 선택 바뀐 줄만 고치기(빠르지만 옛 줄이 쌓임, 9월 30일에 피하자고 하신 것), 도서관별로 표 나누기(책 화면이 느려질 위험), 지금 흐름에서 색인만 나중에(검색은 여전히 멈춤).

2먼저 쓰기 27분을 단계별로 잰 뒤, 가장 느린 곳을 더 고칠지 정함 [안]

두 번째 읽기, 임시 표, 맞대기, 옮겨 쓰기 중 어디가 느린지 아직 모릅니다. dev가 시간 기록을 넣고 같은 사본으로 한 번 더 돌립니다.

3소장 번호를 "지난번 최대 번호 다음"부터 매김 [안]

지금은 가져올 때마다 1부터 다시 매겨서, 가져오기 직전에 열어 둔 책 화면의 "더 보기"가 다른 도서관 줄을 가리킬 수 있습니다. 이어 매기면 옛 번호는 "없음"으로 실패할 뿐 다른 줄을 가리키지 않습니다.

다른 선택 지금처럼 1부터(가져오는 동안 검색이 되면 이 빈틈이 드러남).

4바꿔 끼운 뒤 옛 표는 바로 지움 [안]

디스크를 빨리 돌려받습니다. 되돌리려면 다시 가져와야 합니다.

다른 선택 다음 가져오기까지 한 벌 남김(되돌리기 쉬움, 디스크 약 10GB 더).

2메모리 구조

5검색할 때 도서관 2,700곳을 다 읽지 않고, 들어갈 약 390곳만 DB에서 읽음 [안]

예전 결정("도서관 켜짐 여부는 요청마다 읽음", ADR-0004)을 그대로 지킵니다.

다른 선택 30초 동안 메모리에 기억(DB 읽기는 거의 없어지지만 끈 도서관이 최대 30초 늦게 반영, 예전 결정을 바꿔야 함).

6책 화면은 찾을 도서관 줄만 DB에서 읽음. 가져오기용 색인과 원문 칸은 남김 [안]

다른 선택 가져오기용 색인(1,075MB)을 없앰: 약 1GB 줄지만 같은 책 코드 중복을 DB가 막지 않음.

7캐시 둘은 개수 상한을 두고 통계를 켜서 잰 뒤 캐시마다 상한을 따로 정함 [안]

코드로 센 추정으로는 가득 차도 약 15MB라 작습니다. 캐시 상한 결정(ADR-0006)을 고칠 수 있습니다.

다른 선택 크기(무게)로 상한, 담는 값 줄이기.

8재는 도구는 따로 더하지 않고 Java 명령과 캐시 통계 로그로 잼 [안]

다른 선택 측정 때만 Actuator(앱 상태 도구)를 내 PC에서만 열리게 켬.

9DB 메모리 값은 Docker 실행 설정에 두고 재시작만으로 바꿈. 가져오는 동안만 DB 정렬·색인 메모리를 올림 [안]

10최적점 기준: 검색 첫 쪽이 1초 안이고, 줄이기 전보다 20% 넘게 느려지기 직전 단계 [안]

메모리를 단계로 줄이며(예: 4GB → 2GB → 1GB → 512MB → 256MB) 같은 검색을 반복합니다. 20%와 단계 값을 바꾸고 싶으면 기타에 적어 주세요.

다른 선택 결과 카드에는 빼고(책 상세 링크는 폰에서도 맞으므로) 첫 화면 링크 옆에만.

고르셨던 시안(D안)이 이 모양이었습니다. 내용과 순서는 그대로입니다.

15폰 "도서관에서 직접 찾기"일 때 정렬 자리에 흐린 "정렬 없음", 누르면 이유 [안]

16남은 상태 칸("대출 중 · 예약", "확인 실패" 등) 색을 보유 칸과 같은 연보라로 [안]

17카드 전체 링크는 그대로 (글자 선택 문제는 생기면 다시) [안]

18글꼴을 자주 쓰는 한글만 담은 작은 파일로 줄임 (약 3MB → 줄어듦, 라이선스 확인 뒤) [안]

19약관·처리방침 화면 맨 위에 "← 돌아가기" (이전 화면, 없으면 첫 화면) [안]

20도서관 이름을 고친 뒤 예전 이름으로는 찾지 않음 [안]

다른 선택 예전 이름도 찾게 함(이름 칸이 하나 더 필요).

21작은 구조 항목은 추천 모양 그대로 [안]

고친 시각: 도서관·지역 모듈마다 "고칠 때 시각 적기" 장치. YES24 표시: 도서관 표에 칸 하나. 이름 고치기: 새 DB 변경 파일 + seed 스크립트의 "이름 고침 목록". 수집 기간: 가져오기 기록에 시작·끝 두 칸.
