1ADR-0065: 가져오기는 새 표에 쓰고 바꿔 끼운다

가져오는 동안 검색이 멈추지 않게 하고, 매번 하던 일을 덜 하도록 가져오기 방식을 바꿉니다.

1ADR-0065 초안 [안]

결정. 가져오기는 기존 책·소장 표를 그대로 둔 채 새 표에 색인 없이 책 번호 순으로 쓰고, 색인·제약·통계를 만든 뒤 짧은 순간에 이름을 바꿔 끼운다. 옛 표는 바로 지운다. 소장 번호는 지난번 최대 번호 다음부터 매긴다. 국가서지 파일을 푼 결과는 파일과 정리 규칙이 같으면 다시 쓴다(collection 안). 표 바꾸기는 catalog 안에서 하고 공개 기능 모양은 그대로다. 먼저 쓰기 단계 안의 시간을 나눠 잰 뒤 가장 느린 곳만 더 고친다. catalog-refresh.md 5.1 "표 통째로 바꾸기"(2026-09-30 사용자 방향)를 구현 방식으로 정하고, ADR-0062(책 번호 잇기)는 그대로 둔다.

이유. 사용자: "기존 테이블을 냅두고 TEMP 테이블 두었다가 다 되면 TEMP랑 기존이랑 바꿔치기 하는 식으로"(2026-10-05), "이거 꼭 이 방향이 아니고 db가져오기? 교체? 시간을 줄이기 위한 것이거든"(2026-10-06), "업데이트도 생각했지만 데드 튜플 쌓이는게 싫어서"(2026-09-30). 여덟 방향 비교 뒤 묶음 추천안 → 승인(2026-10-10).

검토한 대안 바뀐 줄만 고치기(옛 줄이 쌓임), 도서관별 표 나누기(책 화면이 모든 조각을 뒤짐), 지금 흐름에서 색인만 나중에(검색 멈춤 그대로), 다른 DB에서 가져와 옮기기(지금 규모에 지나침). 근거 research.md 10절.

2ADR-0066: 메모리를 줄이는 구조

먼저 재고 그다음 줄이며, 읽지도 않을 것을 읽는 곳부터 고칩니다.

2ADR-0066 초안 [안]

결정.

  • 검색 계획은 검색에 들어갈 수 있는 도서관(가입 조사됨·안내 못 찾음 + 직접 추가)만 DB에서 읽는다. 도서관 켜짐 여부는 지금처럼 요청마다 읽는다(ADR-0004 그대로)
  • 책 화면의 소장 읽기는 계획에 든 도서관 줄만 DB에서 읽는다. 가져오기용 색인과 원문 칸은 남긴다
  • 캐시 둘은 통계(맞힌 비율·밀려난 수)를 켜고, 잰 뒤 캐시마다 상한을 정한다. 상한이 1,000건(ADR-0006)에서 바뀌면 그때 새 기록을 남긴다
  • 재는 도구는 따로 더하지 않고 Java 명령(jcmd)과 캐시 통계 로그로 잰다(Actuator 없음)
  • DB 메모리 값은 Docker 실행 설정에 두고, 가져오는 동안에만 DB 정렬·색인 메모리를 올린다. Java 힙 상한은 실행 설정에 둔다
  • 도서관 응답 본문을 두세 벌 복사하는 것을 이번에 줄인다
  • 최적점: 검색 첫 쪽 1초 안, 줄이기 전보다 20% 넘게 느려지기 직전 단계(스펙 승인)

이유. 사용자: "DB메모리도 어떻게 해야 최적인가(너무 메모리에 맞춰서 줄였다가 느려지면 또 그건 별로니까) 찾아보자", "물론 DB메모리도 줄이고 캐시 메모리도 줄이고"(2026-10-05), 응답 복사: "비효율적이고 고칠 수 있으면 지금 고치는게 나아"(2026-10-11). 나머지는 추천안 → 승인(2026-10-10~11).

검토한 대안 도서관 목록을 30초 메모리에 기억(ADR-0004를 바꿔야 함), 캐시를 크기(무게)로 상한, 측정 때만 Actuator, DB 설정을 이미지 파일에. 근거 architect-proposal.md, research.md 1~9절.

3ADR-0067: 교보 대여·혼합 도서관은 받지도 넣지도 않는다

3ADR-0067 초안 [안]

배경. 교보 구독형 플랫폼 서버 하나에 공공도서관 구독 21곳, 소장형 1,182곳, 대여·혼합 230곳이 있습니다. 대여·혼합은 회사·공공기관 직원용이 87%이고, 큰 대여 목록(약 26만 권) 중 계약한 만큼을 보여 도서관마다 달라 하나씩 받아야 합니다. 이 서버가 10월 6~7일 우리 IP를 막아 202곳을 못 받았습니다(crawl-runbook.md 8-2-1절).

결정. 대여·혼합 230곳은 수집하지 않고(수집 DB에 받지 않음 표시, 지우지 않음) 서비스에도 넣지 않는다. 이미 넣은 11곳(2664~2674)은 배포 전이라 seed에서 빼 DB에서 지운다. seed 규칙에 "교보 대여·혼합은 넣지 않음"을 더한다. 공공도서관 구독 21곳과 소장형은 그대로다.

이유. 사용자: "나는 \"교보 구독형 플랫폼 – 대여·혼합\"이걸 아예 제외하려고 해", "이거 다른 사용자들에게 배포 안 되었어. 그냥 DB에서 삭제"(2026-10-10). 범위는 제안 → 승인.

검토한 대안 공공도서관 구독 21곳도 함께 뺌(지역 주민 결과에서 구독 전자책이 사라짐), 11곳을 지우지 않고 끔.

4ADR-0068: 고친 시각은 DB가 적는다

4ADR-0068 초안 [안]

결정. 고친 시각(updated_at) 칸을 두는 표는 줄을 고칠 때마다 DB가 시각을 적는 장치(트리거)를 함께 둔다. 장치는 모듈마다 자기 스키마에 두고 공용으로 나눠 쓰지 않는다. 값을 그대로 두고 고쳐도 시각이 바뀐다. 지금 대상: library.library, region.region. dev 규칙 문서(postgres-patterns)에 같은 지침을 더한다.

이유. 사용자: "왜 updated_at이 지금 정상적으로 안 되는 거야? 이거 좀 dev가 잘 넣도록 지침이라던가 해줘 이거 기본 아니야?"(2026-10-05). 모듈마다 두는 것은 제안 → 승인(2026-10-10).

검토한 대안 서버 코드에서만 적기(DB 변경 파일·직접 명령으로 고칠 때를 놓침), "고칠 때 적는다" 규칙만(지금 빠뜨린 방식 그대로). 근거: PostgreSQL 18 PL/pgSQL 트리거 문서 예 41.3(확인 2026-10-05).
