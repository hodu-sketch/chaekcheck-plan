1무엇이 어디서 바뀌나

가져오기 방식은 catalog와 collection 안에서, 메모리 줄이기는 library·availability·catalog 안에서 바뀝니다. 화면은 웹만 바뀝니다.

모듈 구성도. 각 칸에 이번에 바뀌는 것만 적었습니다.

2가져오기: 새 표에 쓰고 바꿔 끼우기

새 표에 다 쓰는 동안 검색은 옛 표를 읽고, 마지막에 이름만 바꿔 끼웁니다. 국가서지는 파일이 같으면 남긴 결과를 다시 씁니다. 바꿔 끼우기 전에 실패하면 옛 표가 그대로 남습니다.

가져오기 흐름. 가져오기 기록에 수집 시작·끝과 단계별 시간이 남습니다.

3검색 계획과 책 화면: 필요한 줄만 읽기

도서관은 들어갈 약 385곳 + 직접 추가만, 소장은 계획에 든 도서관 줄만 DB에서 읽습니다.

4막혔을 때

429는 웹 서버(nginx)가 이미 Retry-After: 2를 붙이고 있었습니다(dev deploy/nginx 확인). 503에만 새로 붙입니다.

질문: isbn13이 뭔가요? 왜 13인가요?

ISBN은 책마다 붙는 국제 표준 번호(International Standard Book Number)이고, 2007년 1월 1일부터 13자리로 바뀌어서 13입니다. 그 전에는 10자리였습니다. 칸 이름 isbn13은 "13자리 ISBN을 담는 칸"이라는 뜻입니다.

출처: International ISBN Agency "What is an ISBN?" — 2006년 12월 말까지 10자리, 2007년 1월 1일부터 늘 13자리, 맨 앞 978 또는 979 세 자리, 마지막은 검사 숫자 (isbn-international.org, 확인 2026-10-11). 예시 번호는 docs/research/ebook-catalog/same-book-isbn.md 5절.

우리 DB에서 쓰는 곳: 책 표 catalog.book.isbn13에 그 책 묶음의 대표 ISBN 하나를 둡니다(없을 수 있음). 값은 978·979로 시작하는 13자리 숫자만 들어가게 DB가 검사하고(CHECK), 같은 값은 한 책에만(고유). 가져오기의 같은 책 묶기 ②(교보식 코드에서 계산한 ISBN)·③(국가서지 파일)에서 이 번호로 다른 도서관의 같은 책을 묶습니다. 이번 사이클에는 이 칸이 바뀌지 않습니다.

질문: source_fingerprint, normalize_version은 뭐고, 새 칸들은 각각 무슨 일을 하나요?

두 칸은 "남겨 둔 국가서지 결과를 그대로 다시 써도 되는가"를 판단하는 표시입니다. 결과는 두 가지로 정해지기 때문입니다: ① 어떤 국가서지 파일을 풀었나, ② 제목·저자·출판사를 어떤 규칙으로 다듬어 키를 만들었나. 둘 중 하나라도 바뀌면 결과도 달라지므로 다시 만들어야 합니다.

모양 고침: 처음 초안은 두 표시를 결과 줄마다 적었는데, 수백만 줄에 같은 값이 반복됩니다. 그래서 표시는 따로 한 줄짜리 작은 표에 한 번만 두고, 결과 표는 키와 ISBN만 갖는 모양으로 고쳤습니다(아래 6번의 #1 제안에 반영).

질문: 정리 규칙이 바뀌면 어떻게 하기로 했나요?

정해 둔 것은 "규칙 코드는 한 벌만 두고, 검색어와 저장값을 같은 코드로 다듬는다"(ADR-0031·0060)까지입니다. 규칙을 바꿨을 때의 순서는 아직 정한 적이 없습니다. 지금 구조에서 실제로 일어나는 일은 이렇습니다.

근거: ADR-0031 "검색어와 저장값은 같은 정리 규칙으로 정리해야 검색이 맞는다", dev catalog/001의 *_norm 칸 설명(같은 코드가 검색어를 다듬음).

이 빈틈을 막는 규칙을 하나 정해 두길 권합니다. 이 페이지에는 칩을 더할 수 없어서 짧은 후속 페이지(정할 것 1개)로 따로 열겠습니다: "정리 규칙을 바꾸면 판 번호를 올리고, 그 코드를 올릴 때 반드시 같은 사본으로 다시 가져온다". 바꿔 끼우기(ADR-0065) 덕분에 다시 가져오는 동안에도 검색은 멈추지 않습니다.

바꿔 끼울 때 함께 옮기는 것

무엇몇 개어떻게
catalog 표4개 (책, 사람, 소장, 도서관별 수집 시각)준비 스키마(catalog_next)에 새로 만들고 다 채운 뒤 옮김
색인12개 (책 8: 제목·출판사 글자 찾기 2, 완전 일치 3, 출판일 2, 가진 도서관 번호 1 / 사람 3 / 소장 1)다 쓴 뒤 한 번에 만듦. 정의는 지금 운영 표에서 읽어 같은 이름으로
제약기본 키 4, 외래 키 2(사람→책, 소장→책), 고유 2(책 ISBN, 소장의 도서관·책 코드), 값 검사(CHECK) 몇 개같은 방법으로 다시 만듦
번호 시작값책·사람·소장책·소장은 옛 최대 다음부터(다시 쓰지 않음)

다른 모듈 표가 catalog 표를 외래 키로 가리키는 곳은 지금 없습니다(점선만 있음). 그래서 바꿔 끼워도 다른 모듈은 영향을 받지 않습니다. 회원이 책 번호를 저장하는 기능이 생기면 그때 함께 봐야 합니다.

6남은 제안

1국가서지 푼 결과는 collection이 가진 DB 표에 남김 [안]

파일로 두는 것보다 PC가 바뀌어도 같이 옮겨지고, 판(파일 지문·정리 규칙 판)을 함께 적기 쉽습니다. 모양(질문 뒤 고침): TTL에서 뽑은 원문 표(ISBN·제목·저자·출판사)와 파일 지문을 한 번만 적는 한 줄짜리 표(지문, 만든 시각) 둘. 다듬기는 가져올 때마다 지금 규칙으로 해서 정리 규칙 판 번호는 두지 않음. 크기와 다시 읽는 시간은 만들어 보고 잽니다.

다른 선택 데이터 폴더에 파일로(DB가 조금 덜 커짐, 다른 PC로 옮길 때 따로 챙겨야 함).

2503 "지금 찾는 사람이 많아요"에 "5초 뒤 다시"(Retry-After 5)를 붙임 [안]

dev 규칙 문서(api-design 스킬)도 503에는 Retry-After를 붙이라고 적고 있습니다. 화면 문구는 정하신 대로입니다.

3DB 컨테이너 메모리 상한(mem_limit)과 공유 메모리(shm_size 128MB)는 측정할 때만 설정에 둠 [안]

상한을 너무 낮추면 느려지는 게 아니라 DB가 꺼질 수 있어서(Docker 공식 문서), 평소 설정에는 넣지 않고 재는 단계에서만 씁니다.

4흡수돼 없어진 학교 6~7곳(경남도립거창대 등)은 이름을 고치지 않고, 사이트를 한 번씩 확인한 뒤 "주소 바꿈 / 끄기" 목록으로 따로 여쭘 [안]

5이 설계대로 사이클 마무리(검토 → 인계서) 단계로 넘어감 [안]

결정 기록 초안 넷(ADR-0065~0068)은 다른 페이지에서 고르시면 됩니다.
