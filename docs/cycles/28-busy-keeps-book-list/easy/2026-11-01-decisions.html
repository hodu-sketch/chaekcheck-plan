먼저: 지금은 무엇이 보이나

책 목록은 이미 받았는데도, 대출 조회가 거절되면 결과 자리 전체가 "지금 찾는 사람이 많아요. 잠시 뒤에 다시 해 주세요." 한 줄로 바뀝니다. 책 목록도, 다시 시도 단추도 없습니다.

「바로 보기」 검색은 요청이 둘입니다(ADR-0030). ① 책 목록은 우리 DB에서 바로 옵니다(/api/v1/books, 자리를 쓰지 않음). ② 그 책을 가진 도서관마다 대출 가능 여부를 묻는 "대출 조회 스트림"은 서버 전체 60개 자리 가운데 하나를 써야 열립니다. 자리가 없으면 서버는 줄을 세우지 않고 바로 503(server_busy)으로 거절합니다(dev SearchSlots.java 51~59행, AvailabilityErrors.java 86~93행, 2026-11-01 확인).

1이 사이클이 하는 일 하나:
자리가 없어도 책 목록은 보이고 대출 정보만 "알 수 없음"

[안] 「바로 보기」 첫 대출 조회가 자리를 못 얻었을 때, 책 목록은 그대로 보이고 도서관별 대출 가능 여부만 빼고 "지금 알 수 없다"고 알립니다. 자리 수 60, 줄 세우기, 직접 찾기·AI 책 찾기의 503, 새 모듈·표는 건드리지 않습니다.

예: 점심시간에 여러 사람이 동시에 검색해 자리가 꽉 찼을 때 "아몬드"를 검색하면, 지금은 안내문 한 줄만 보이지만, 바뀐 뒤에는 "아몬드 · 손원평 · 창비 · 보유 도서관 12곳" 같은 책 줄이 보이고 그 위에 "대출 정보는 알 수 없어요" 안내가 붙습니다.

완료 기준(사용자가 확인하는 것): 시험용으로 자리를 1개로 낮추고 다른 창에서 조회 하나를 열어 둔 뒤 검색하면 ① 책 줄이 보이고 ② 안내 줄과 다시 확인 단추가 보이고 ③ 자리가 비면 단추로 대출 정보가 채워지고 ④ 직접 찾기는 지금처럼 안내 줄, ⑤ 1분 요약 로그 거절 수와 조회 상태 신호 빨강은 지금처럼 남습니다.

다른 선택: 직접 찾기의 503도 함께 손보기 — 직접 찾기는 목록이 도서관 사이트에서 오므로 자리가 없으면 보여 줄 것이 없습니다. 바꿀 것이 없어 넣지 않았습니다.

사용자 말(2026-11-01): "넘으면 바로 503이 아니라 그냥 대출 결과만 제외하고 알려주려고 … 그냥 목록만… 대출 정보는 알 수 없다고만 하고."

2방식: 서버는 그대로 두고
화면만 고친다 (다안)

[안] 서버는 지금처럼 503으로 거절하고, 화면이 503을 받으면 이미 받아 둔 책 목록을 그리는 쪽을 택합니다. API·스트림 이벤트·오류 코드가 하나도 바뀌지 않고, 고치는 곳은 화면 파일 3~4개입니다.

왜 이게 되나: 문제가 생기는 곳이 첫 조회 한 곳(InstantResults.tsx 134~141행)뿐이고, 그때 책 목록은 화면이 이미 손에 들고 있습니다. 서버가 더 보낼 것이 없습니다. 「결과 더 보기」의 거절은 지금도 결과가 남고 다시 물을 수 있어 그대로 둡니다.

가안: 스트림을 열고 소장마다 "자리 없음" 실패 보내기나안: 스트림을 열고 새 이벤트 한 번다안: 화면만 (추천)
서버 응답200 스트림, 소장(책·도서관 쌍) 최대 10개마다 holding-failed(server_busy), 새 끝 이유 SERVER_BUSY200 스트림, 새 이벤트 lookups-unavailable 한 번503 그대로
첫 조회 때 보이는 것도서관별 줄 10개 "지금 알 수 없음" + 도서관 책 페이지 링크화면이 자리표 줄을 스스로 만들거나 책 목록만(결국 다안과 같아짐)책 줄 목록 + 안내 줄 + 다시 확인 단추
고치는 곳서버 4~5 + 화면 4~5 파일, 서버 통합 테스트(사이클 08 AC-18) 기대값 바뀜서버 3~4 + 화면 5~6 파일, 스트림 약속 하나 늘어남화면 3~4 파일, 서버 테스트 변화 없음
옛 화면 판 + 새 서버 판이 잠깐 섞일 때(블루·그린 전환, ADR-0170)옛 화면은 10줄을 "확인하지 못했어요"로 보이고 다시 못 물음옛 화면은 안내 없이 단추만섞일 것이 없음
잃는 것——첫 조회 거절 때 도서관별 줄·도서관 책 페이지 링크는 안 보임(책 줄만)

아키텍트 비교표를 줄인 것입니다. 전체는 architect-proposal.md.

다른 선택 가안: 도서관별 줄과 링크가 보이는 대신 서버·화면 둘을 고치고 테스트와 문서(api.md, ADR)가 늘어납니다. 도서관별 줄이 꼭 필요하면 이쪽입니다.

다른 선택 나안: 서버를 바꾸지만 화면이 그릴 수 있는 것은 다안과 같아서 바꾸는 이득이 작습니다.

추천 이유: 개인 서비스, 서버 한 대, 자리 60개라 거절은 드물고 짧습니다(서버가 "5초 뒤 다시"를 붙임). 단추 하나로 다시 여는 것으로 충분하고, 사용자가 "아주 간단하게"를 요청했습니다.

5다시 확인은 단추를 누를 때만

[안] 안내 줄에 「대출 정보 다시 확인」 단추를 둡니다. 누르면 같은 책들로 대출 조회를 다시 열고, 성공하면 보통 결과 화면(도서관별 줄, ①②③ 묶음)으로 바뀌며 책 줄·안내 줄은 사라집니다. 또 거절되면 같은 화면이 그대로 남고 단추를 다시 누를 수 있습니다. 자동으로 몇 초 뒤 다시 묻지는 않습니다.

책 줄 목록안내 줄 + 단추→ 누름 →대출 정보 확인 중…단추 잠김→보통 결과 화면
·→·→ 또 거절 →책 줄 목록 그대로단추 다시 가능

단추를 누른 뒤 답을 기다리는 동안 안내 줄은 "대출 정보 확인 중…"으로 바뀌고 단추는 잠깁니다.

다른 선택 1: 서버가 보낸 "5초 뒤 다시"(Retry-After)를 받아 5초 동안 단추를 잠그기 — 자리는 1초 뒤에도 빌 수 있어 기다리게 할 이유가 약합니다.

다른 선택 2: 5초마다 자동으로 다시 묻기 — 사용자 규칙(2026-10-18 "체크와 검색이 따로, 0.7초 기다리지 마라": 실행은 단추로)과 어긋나고, 바쁜 서버에 요청을 더 보냅니다.

[안] 「바로 보기」 아래쪽 「다음 책 N권 보기」로 새 책들을 받은 직후의 조회가 거절되면, 지금처럼 앞서 받은 결과는 남고 위에 안내 줄이 붙되, 안내 줄에 「대출 정보 다시 확인」 단추를 더해 새 책들의 조회를 다시 열 수 있게 합니다. 새 책들의 책 줄은 이 경우에는 그리지 않습니다.

왜 책 줄을 안 그리나: 이때 결과 자리에는 이미 도서관별 줄(①②③ 묶음)이 있어서, 그 아래에 모양이 다른 책 줄을 섞어 그리면 두 종류 줄이 한 목록에 들어갑니다. 드문 경우라 단추로 다시 묻는 것만 둡니다.

다른 선택 1: 새 책들을 책 줄로 목록 아래에 더하기 — 한 목록에 두 모양이 섞이고, 다시 확인 뒤 지우는 처리가 더 필요합니다.

다른 선택 2: 지금 그대로(단추 없음) — 「다음 책 N권 보기」를 다시 눌러야 하는데, 그러면 그다음 페이지를 받아 옵니다. 거절된 책들은 다시 묻지 못합니다.

8"너무 자주 했어요"(429)는 지금 그대로

[안] nginx가 한 주소에서 너무 잦은 요청을 막는 429는 지금처럼 결과 자리를 "검색을 너무 자주 했어요. 1분쯤 뒤에 다시 해 주세요."로 바꿉니다. 책 줄 목록으로 바꾸지 않습니다.

이유: 429는 서버가 바쁜 것이 아니라 그 사람이 1분 안에 너무 많이 요청한 경우입니다(nginx 한도, 사이클 07·08). 1분을 기다려야 하므로 다시 확인 단추를 두면 바로 또 429가 납니다.

다른 선택: 429도 책 줄 목록 + 안내 줄(단추 없이) — 책 목록은 보이지만, 한도에 걸린 사람이 책 화면으로 들어가도 거기서도 429가 납니다.

그대로 두는 것

9다음 묶음·추천도서 책 창 문구와
거절 세는 법은 지금 그대로

[안] ① 「결과 더 보기」 거절 안내 "지금 찾는 사람이 많아요. 잠시 뒤에 다시 해 주세요."와 다시 「결과 더 보기」로 묻는 동작 ② 추천도서 책 창의 "대출 정보를 확인하지 못했어요. 잠시 뒤 다시 시도해 주세요." ③ 거절 1건마다 1분 요약 로그 거절 수 +1, 조회 상태 신호 빨강 10초 — 모두 그대로입니다. 이용 기록(usagelog)에 새 표·새 칸은 두지 않습니다.

서버를 바꾸지 않는 방식(2번)이라 ③은 자연히 그대로입니다. ②는 책 머리가 이미 보이고 문구 뜻도 맞아 손대지 않습니다. ①은 지금 동작이 이미 "받은 것은 남고 다시 물을 수 있음"입니다.

다른 선택: 세 문구를 "대출 정보는 알 수 없어요" 말투로 통일 — 세 파일을 더 고치고 테스트가 늘어나는 데 비해 얻는 것이 적습니다.

결정 기록

10ADR 초안(쓴 번호 ADR-0173):
자리 거절 때 책 목록은 화면이 지킨다 (서버 503 그대로)

[안] 결정: "동시 검색 자리가 없을 때 대출 조회 스트림은 지금처럼 503 server_busy로 거절한다. 「바로 보기」 첫 조회가 거절되면 화면이 이미 받은 책 목록을 책 줄로 그리고 안내 줄과 「대출 정보 다시 확인」 단추를 둔다. 서버·API·스트림 이벤트는 바꾸지 않는다." 이 항목을 승인하면 ADR 파일을 쓰고(Status: Accepted), 2번의 선택 이유로 사용자가 적은 말을 넣습니다.

항목내용
배경자리 60개가 다 차면 503으로 거절하고 화면이 결과 자리를 안내문으로 바꿔, DB에서 이미 받은 책 목록이 버려짐. 사용자가 "503 대신 목록은 보이고 대출 정보만 알 수 없다고" 요청(2026-11-01)

이유사용자가 2번에 적는 말. 없으면 [이유 미확인]과 아키텍트 추천 근거(문제가 첫 조회 한 곳, 개인 서비스 규모, 아주 작은 사이클)
결과좋아지는 점: API 변경 없음, 블루·그린 전환에 호환 걱정 없음. 감수하는 점: 첫 조회 거절 때 도서관별 줄·링크는 안 보임. 나중에 도서관별 줄이 필요하면 가안으로 바꿈(backlog)

다른 선택: ADR을 쓰지 않기 — 화면만 바꾸는 일이지만 "서버는 503 그대로"라는 선택은 나중에 가안으로 가야 할 때 근거가 되므로 한 건은 남기는 쪽을 권합니다.
