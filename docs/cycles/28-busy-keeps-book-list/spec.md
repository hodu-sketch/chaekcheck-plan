# 기능 명세: 자리가 다 차도 책 목록은 보여 주기 (사이클 28, 번외)

범위: `scope.md`. 지금 동작은 그 문서의 "지금 동작" 표와 `architect-proposal.md` "코드에서 확인한 것"(dev 코드, 2026-11-01). 새 화면은 없고, 「바로 보기」 결과 화면·책 화면이 **자리가 없을 때** 보이는 것만 바뀝니다. 결정은 `easy/2026-11-01-decisions.html` 한 장에서.

용어: **자리** = 서버 전체에서 동시에 돌 수 있는 도서관 조회 60개(`SearchSlots`). **대출 조회 스트림** = 책을 가진 도서관마다 상세 페이지를 읽어 대출 가능 여부를 보내는 요청(`/api/v1/book-availabilities/stream`, 다음 묶음 `…/batches/stream`). **첫 스트림** = 검색(또는 「다음 책 N권 보기」)으로 받은 책들의 첫 조회. **다음 묶음** = 「결과 더 보기」.

## 사용자 이야기

- 검색한 사람은 서버가 바쁜 순간에도 **어떤 책이 있고 몇 곳이 가지고 있는지**는 바로 보고 싶다, 대출 가능 여부는 조금 뒤에 확인해도 되니까 (사용자: "그냥 대출 결과만 제외하고 알려주려고 … 그냥 목록만… 대출 정보는 알 수 없다고만 하고", 2026-11-01)
- 검색한 사람은 자리가 생기면 **한 번 눌러** 대출 정보를 채우고 싶다, 검색을 처음부터 다시 하지 않고 [확정] (사용자 승인, 결정 페이지 2026-11-07)

## 동작 규칙

1. **책 목록은 자리와 무관하게 보인다.** `GET /api/v1/books`는 DB 조회라 자리를 쓰지 않는다(ADR-0030) [확정] (dev `BookAvailabilityStreamController.java` 주석, `catalog` 모듈). 화면은 책 목록을 받은 뒤 대출 조회 스트림을 연다(지금과 같음)
2. **첫 스트림이 503이면 대출 조회만 빠진다.** 결과 자리에는 책 줄(제목·저자·출판사·보유 도서관 N곳)과 안내 줄·단추가 보인다. 지금처럼 결과 자리를 안내문으로 바꾸지 않는다 [확정] (사용자 승인, 결정 페이지 2026-11-07)
3. **다시 확인은 사람이 누를 때만.** 자동으로 몇 초 뒤 다시 묻지 않는다(사용자 규칙 2026-10-18 "체크와 검색이 따로, 0.7초 기다리지 마라"와 같은 뜻) [확정] (사용자 승인, 결정 페이지 2026-11-07)
4. **다시 확인이 성공하면** 보통 결과 화면(도서관별 줄, 묶음 ①②③)으로 바뀌고 책 줄·안내 줄은 사라진다. 또 503이면 책 줄·안내 줄 그대로, 단추 다시 가능 [확정] (사용자 승인, 결정 페이지 2026-11-07)
5. **다음 묶음·「다음 책 N권 보기」의 거절은 지금 동작 그대로.** 받은 결과는 남고 위에 안내 줄, 「결과 더 보기」가 다시 묻는다. 「다음 책 N권 보기」 뒤 첫 스트림이 거절되면 지금 동작(새 책 안 보임, 안내 줄)에 「대출 정보 다시 확인」 단추만 더함(그 페이지 책들만 다시 묻기, 앞 페이지 책은 그대로) [확정] (사용자 승인, 결정 페이지 2026-11-07)
6. **거절은 지금처럼 센다.** 서버 코드를 바꾸지 않으므로 `RefusalRecord`(빨강 10초)·`LookupOpsCounters.refused()`(1분 요약 로그)는 그대로 [확정] (사용자 승인, 결정 페이지 2026-11-07)
7. **다른 요청은 그대로.** 직접 찾기·그 다음 묶음·도서관별 더 보기·AI 책 찾기는 지금처럼 503과 지금 문구 [확정] (사용자 승인, 결정 페이지 2026-11-07)

## 상태별 동작

| 상황 | 「바로 보기」 결과 | 책 화면 | 추천도서 책 창 |
|---|---|---|---|
| 첫 스트림 503 | 책 줄 목록 + 위에 안내 줄 + 「대출 정보 다시 확인」 (지금: 안내문만) | 책 머리 + 안내 줄 + 단추 (지금: 안내 줄 + "모두 조회했습니다") | 지금 그대로 |
| 다시 확인 → 자리 있음 | 보통 결과 화면("대출 정보 조회 중" → 결과) | 같음 | — |
| 다시 확인 → 또 503 | 그대로, 단추 다시 가능 | 같음 | — |
| 「결과 더 보기」 묶음 503 | 지금 그대로(결과 남음 + 안내 줄, 다시 「결과 더 보기」) | 같음 | — |
| 429 | 지금 그대로 | 지금 그대로 | 지금 그대로 |
| 직접 찾기 503 | 지금 그대로 | — | — |

## 수용 기준

- AC-1: 자리가 하나도 없는 상태(시험: `max-concurrent-searches=1`로 띄우고 다른 창에서 대출 조회 하나를 열어 둠)에서 「바로 보기」로 검색하면, 책마다 한 줄(제목·저자·출판사·보유 도서관 N곳)이 `/books` 순서대로 보이고, 목록 위에 안내 줄과 「대출 정보 다시 확인」이 보인다. 책 줄을 누르면 책 화면으로 간다 [확정] (사용자 승인, 결정 페이지 2026-11-07)
- AC-2: 자리가 생긴 뒤 「대출 정보 다시 확인」을 누르면 보통 결과 화면이 되고 책 줄·안내 줄이 사라진다. 도서관 요청은 다시 확인 때 처음 보낸다(그 전에는 0건, 서버 로그) [확정] (사용자 승인, 결정 페이지 2026-11-07)
- AC-3: 자리가 없는 채로 단추를 누르면 같은 화면이 유지되고 단추를 다시 누를 수 있다 [확정] (사용자 승인, 결정 페이지 2026-11-07)
- AC-4: 같은 상태에서 책 화면은 책 머리 + 안내 줄 + 단추를 보이고 "이 책을 가진 도서관을 모두 조회했습니다"는 보이지 않는다 [확정] (사용자 승인, 결정 페이지 2026-11-07)
- AC-5: 같은 상태에서 직접 찾기와 「결과 더 보기」는 지금 동작·문구 그대로다 [확정] (사용자 승인, 결정 페이지 2026-11-07)
- AC-6: 거절 1건마다 1분 요약 로그 거절 수가 1 오르고 `/api/v1/lookup-status`가 10초 동안 `RED`다(지금과 같음) [확정] (사용자 승인, 결정 페이지 2026-11-07)
- AC-7: 서버 코드·API는 바뀌지 않는다(백엔드 테스트 변경 0, `api.md` 변경 없음) [확정] (사용자 승인, 결정 페이지 2026-11-07)
