## 사용자 이야기

- 이용자는 서비스 소식(도서관 추가, 점검, 바뀐 점)을 **공지사항**에서 날짜순으로 보고 싶다, 무엇이 바뀌었는지 알려고
- 이용자는 서비스 안내·약관·처리방침·공지가 **예전에 어땠는지** 볼 수 있으면 좋겠다 (사용자: "서비스 안내 공지 모두 이전 기록이 보였으면 하는데 ..", 2026-10-12)
- 운영자(사용자, 실제 실행은 Claude)는 공지를 올리거나 안내·약관을 고칠 때 **배포 없이** DB에 넣기만 하고 싶다
- 가입하는 사람은 지금 시행 중인 약관·동의문에 동의하고, 그 버전이 기록되어야 한다

## 동작 규칙

### R1 글
- R1-1 가입 화면의 개인정보 수집·이용 동의문(4항목 표와 전문)도 같은 방식으로 DB에 두고 버전을 남김. 가입 동의 기록이 버전을 가리키는 글은 이용약관과 이 동의문 둘이기 때문 [확정] (사용자 승인, 2026-10-12)
- R1-2 본문은 제한된 마크다운(제목, 문단, 목록, 굵게, 링크). `react-markdown`으로 그리고 HTML은 그리지 않음(기본 동작, [research.md](research.md) 1절). C22를 지킴 [확정] (사용자 승인, 2026-10-12)
- R1-3 연락처 `chaekcheck9104@gmail.com`: 서비스 안내 글 안(문의, 로고 내림 요청), 처리방침의 보호책임자 연락처. 바닥글에는 두지 않음 [확정] (값: 사용자, 2026-10-12 / 바닥글 제외: 사용자 제안, 2026-10-13 "서비스 안내 안에 이메일을 넣자 너무 길어")

### R2 버전
- R2-1 네 글 모두 고칠 때마다 새 버전을 넣고 옛 버전은 지우지 않음 [확정] (사용자 승인, 2026-10-12)
- R2-2 **버전은 글마다 1부터 붙는 순번**(주소 `?version=2`). 같은 글을 하루에 여러 번 고쳐도 됨 [확정] (사용자 제안, 2026-10-13: "하루에 여러 공지가 날 수 있는데 이상한데 그냥 그 자체의 순번으로 하면 안돼?"; 처음 제안 "버전 이름 = 시행일, 같은 날 두 버전 없음"은 바뀜). 버전마다 시행일(공지·안내는 게시일)을 따로 가짐. "지금 버전" = 시행일이 오늘(Asia/Seoul) 이전인 것 중 순번이 가장 큰 것. 시행일을 앞날로 넣어 두면 그날부터 바뀜(미리 넣어 두기) [확정] (사용자 승인, 2026-10-12·13). 가입 동의 기록에는 판 순번 글자(`"1"`)를 남김 [확정] (사용자 승인, 2026-10-13, [ADR-0099](../../adr/0099-signup-document-version-from-sitecontent.md))
- R2-3 처음 넣는 버전
  - 개발 DB: 지금 웹 코드의 글을 첫 버전으로 넣음(약관·동의문 시행일 `2026-10-04`). 서비스 안내는 사이클 13·14가 더한 문장까지 들어간 dev 코드에서 가져옴(dev main `AboutPage.tsx`, 2026-10-14 확인) [확정] (사용자 승인, 2026-10-12)
  - 운영 DB: 검토한 글([drafts/](drafts/))부터 시작하고, 첫 판의 시행일은 **모르는 사람에게도 공개하는 날**(첫 배포일이 아님). 네 글과 동의문 모두 [확정] (사용자: "그냥 내가 외부 내가 모르는 사람들에게도 공개할 때 그 날짜로 다 맞춰줘 이것말고도 전부", 2026-10-13; 앞선 조건 "나중에 진짜로 도메인 사서 배포할 때 그 날짜로 바꿔야 해", 2026-10-12를 바꿈. 설계 결정 6·7)
  - 지금 가입자는 테스트 한 명뿐이라 옛 동의를 따로 챙길 필요는 없음 (사용자, 2026-10-12)

### R3 이전 버전 보기
- R3-1 **제목 아래 날짜 고르기 칸**에서 옛 버전을 고르면 그 버전 글이 열림 [확정] (사용자 제안, 2026-10-13: "제목 아래 날짜 고르기 칸"; 처음 제안 "글 화면 아래 이전 버전 목록"은 바뀜). 이전 기록을 보이게 하는 것 자체는 [확정] (사용자 승인, 2026-10-12)
- R3-2 날짜 고르기 칸의 항목마다 적용 기간("2026-10-04 ~ 2026-10-19 적용")을 보임. 이전 버전을 열면 제목 옆에 작은 "이전 버전" 표시, 지금 버전으로는 같은 칸에서 돌아감(큰 안내 띠 없음). 이전 버전은 주소로 바로 열 수 있음. 버전이 하나뿐이면 칸을 숨김 [확정] (적용 기간·하나면 숨김: 사용자 승인 2026-10-12 / 작은 표시: 사용자 제안 2026-10-13 "작은 표시"). 근거: 작성지침 83쪽 "각 버전의 적용 기간을 확인할 수 있게" ([research.md](research.md) 2.2)
- R3-3 이용약관·동의문·처리방침 버전에는 "바뀐 점" 글(사람이 쓰는 짧은 요약 또는 바뀌기 전·후 표)을 함께 넣고, 제목 아래 접힌 한 줄 "바뀐 점 보기"로 둠(누르면 펼침). 자동 비교(바뀐 줄 표시)는 하지 않음 [확정] (사용자 승인, 2026-10-12 / 접힌 한 줄·노랑 없음: 사용자 제안 2026-10-13 "접힌 한 줄로 노랑은 이 테마에 안 맞아"). 근거: 작성지침 83쪽 "중대한 변경은 대조표 등으로 따로 안내", 13쪽 "변경 전후 비교 공개 권장"

### R4 공지사항
- R4-1 목록은 게시일 최신순, 운영자가 고정으로 넣은 공지는 1쪽 맨 위. 분류(안내·점검 등)는 두지 않음. 공지를 내릴 때는 지우지 않고 "숨김"으로 바꾸며, 숨긴 공지는 목록·주소 모두 안 보임 [확정] (사용자 승인, 2026-10-12·13 / 고정을 빼는 안 미승인 "보기 어려워", 숨김을 빼는 안 미승인 "이전에 기록을 봤으면 해"). 고친 공지는 목록에는 표시하지 않고, 공지 글 화면에서 언제 고쳤는지 보임 [확정] (사용자 제안, 2026-10-13: "고침은 보여주지 말자 고침은 글 클릭하면 언제 고쳤는지 보이게 해주자")
- R4-2 10개씩 숫자 페이지, 고정 공지는 1쪽 위에만(10개 셈에 안 넣음), 없는 쪽은 마지막 쪽, 공지 글은 따로 화면 + "목록으로" [확정] (사용자 승인, 2026-10-13, [flow.md](flow.md))

### R6 바닥글과 보이는 조건
- R6-1 "공지사항 · 서비스 안내 · 이용약관 · 개인정보 처리방침" 한 줄 [확정] (scope 포함 6). 순서·모양은 [flow.md](flow.md)
- R6-2 **개인정보 처리방침은 로그인 기능과 상관없이 늘 보임**(링크와 `/privacy`). 이용약관은 지금처럼 로그인 기능이 꺼져 있으면 안 보임 [확정] (사용자 승인, 2026-10-12, [ADR-0100](../../adr/0100-privacy-policy-public-regardless-of-login.md)). 앞서 정한 "둘 다 로그인 기능을 따름"(사이클 05 제약 35, scope 포함 7)을 바꿈. 근거: 작성지침 17쪽 "로그인 여부와 상관없이 확인할 수 있어야", 로그인이 꺼져도 접속 기록·사이클 15 이용 기록에 IP가 남음(지침 24~25쪽 생성되는 개인정보 기재, IP가 늘 개인정보라는 공식 해석은 확인 못 함, [research.md](research.md) 2.3·5절)
- R6-3 바닥글의 "문의: 준비 중"은 없애고, 연락처는 서비스 안내 글 안에 둠 [확정] (사용자 제안, 2026-10-13). 앞서 정한 "바닥글에 문의 주소, 그 주소도 DB에"는 이 결정으로 바뀜(주소는 서비스 안내 글과 함께 DB에 있음)

### R7 약관·처리방침을 바꿀 때
- R7-1 바꿀 때는 공지사항에 알리고, 새 버전의 시행일을 앞날로 넣어 둠(R2-2). "공지 뒤 반대하지 않으면 동의한 것으로 봄" 같은 조항은 쓰지 않음 [확정]. 처음 제안 "이미 가입한 사람에게 다시 동의를 받지 않음"은 사용자 질문("이거 되는거 확실한거야?", 2026-10-12) 뒤 조사에서 근거가 약하다고 나와 R7-2·R7-3으로 바뀜 ([research.md](research.md) 4절: 대법원 2011다69053, 무반응은 동의 아님; 약관규제법 제12조제1호; 처리방침은 동의 대상이 아님, 지침 13쪽; 약관 사전 공지 기간을 정한 법 조문 없음, 2.4절)
- R7-2 가벼운 변경(오탈자, 회원에게 유리한 변경, 처리방침)은 공지 + 시행일. 중요하거나 불리한 변경, 동의로 모으는 항목·목적이 바뀌는 동의문 변경(개인정보 보호법 제15조②)은 **다음 로그인 때 다시 동의**를 받음. 다시 동의하지 않으면 탈퇴할 수 있고, 로그인하지 않는 회원에게는 옛 약관이 적용됨 [확정] (사용자 승인, 2026-10-12, [ADR-0101](../../adr/0101-terms-change-notice-or-reconsent.md))
- R7-3 다시 동의 화면과 "다시 동의 필요" 표시 칸은 backlog(첫 실제 중요 변경 전까지). 그 전에는 다시 동의가 필요한 변경을 넣지 않음 [확정] (사용자 승인, 2026-10-12·13: "아직 기능이 다시 동의 필요가 없지 않나?")

## 상태별 동작

- 로딩은 글 자리에 회색 줄, 공지가 하나도 없으면 "아직 공지가 없어요", 없는 공지·없는 버전 주소는 "찾을 수 없어요" + 목록(또는 지금 버전)으로 가는 링크, 서버 오류·지연은 "글을 불러오지 못했어요" + 다시 시도 [확정] (사용자 승인, 2026-10-12)
- 서비스 안내·약관·동의문·처리방침은 첫 버전을 넣고 시작하므로 "글 없음" 상태가 없음
- 로그인 기능이 꺼져 있을 때 `/terms`: 지금처럼 없는 경로로 처리 [확정] (사이클 05 제약 35). 이용약관 서버 창구(`/api/v1/documents/terms-of-service`)는 열어 둠 [확정] (사용자 승인, 2026-10-13, 설계 결정 5). `/privacy`는 R6-2를 따름

## 수용 기준

- AC-1: DB에 공지를 하나 넣고 공지사항 화면을 새로고침하면, 배포 없이 그 공지가 목록 맨 위(고정 공지 다음)에 보인다
- AC-2: 서비스 안내 글의 새 버전을 넣으면 `/about`에 새 글이 보이고, 제목 아래 날짜 고르기 칸에 옛 버전의 적용 기간이 보이며 고르면 옛 글과 "이전 버전" 표시가 보인다
- AC-3: 이용약관 새 버전을 시행일 오늘로 넣은 뒤 가입하면 `auth.account_consent`에 새 버전이 남는다 (API 호출 시험)
- AC-4: 시행일을 앞날로 넣은 버전은 그날 전까지 화면과 가입 API에 나오지 않는다
- AC-5: 공지를 숨김으로 바꾸면 목록에서 사라지고, 그 공지 주소는 "찾을 수 없어요"를 보인다
- AC-6: 본문에 `<script>` 같은 HTML이나 `javascript:` 링크를 넣어도 실행되지 않는다
- AC-7: 바닥글에 공지사항·서비스 안내·이용약관·개인정보 처리방침이 보이고 "문의: 준비 중"은 없다. 로그인 기능이 꺼져 있으면 이용약관만 빠진다
- AC-8: 이용약관·처리방침 화면에 "검토 전 문구" 표시가 없다
- AC-9: 없는 버전 주소는 "찾을 수 없어요"를 보인다
- AC-10: 서비스 안내에 사이클 13의 기준일 한 줄이 DB 글 아래에 보인다
- AC-11: 약관·처리방침에 "바뀐 점"이 있는 버전은 제목 아래 "바뀐 점 보기"를 눌러 그 내용을 볼 수 있다
- AC-12: 서비스 안내에 문의 이메일 `chaekcheck9104@gmail.com`이 보이고 누르면 메일 쓰기가 열린다
- AC-13: 공지 목록에는 고친 날이 없고, 고친 공지를 열면 언제 고쳤는지 보인다
