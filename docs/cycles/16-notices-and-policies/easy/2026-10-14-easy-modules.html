공지와 안내·약관 글은
새 모듈 sitecontent 한 곳이 맡습니다

사이클 16이 docs/current/module-map.md에 더한 것을 쉽게 옮긴 페이지입니다. 모듈은 서버 코드를 일 단위로 나눈 묶음이고, 각 모듈은 자기 표만 만집니다. (2026-10-14, 설계됨·아직 만들지 않음)

1누가 누구를 부르나

글을 읽는 쪽은 둘(웹 화면, 가입을 맡은 auth), 글을 넣는 쪽은 하나(Claude의 SQL)입니다. sitecontent는 다른 모듈을 부르지 않습니다.

2sitecontent가 맡는 일

글을 고칠 때마다 배포하지 않고, 옛 판도 남겨 볼 수 있게 하는 것이 이 모듈의 일입니다.

맡는 것예
공지"점검 안내"를 올리고, 고치면 고친 판이 하나 더 생김
문서 넷서비스 안내, 이용약관, 개인정보 처리방침, 가입 동의문
지금 판 고르기시행일이 오늘(한국 날짜)이 된 판 중 가장 새 판을 보여 줌. 12월 1일 시행 판은 11월에는 안 보임
읽는 주소 셋/api/v1/notices(공지 목록), /api/v1/notices/{번호}(공지 글), /api/v1/documents/{문서}(about, terms-of-service, privacy-policy, privacy-collection)

글을 쓰는 화면(운영자 화면)은 없습니다. 사용자가 "점검 공지 올려 줘"라고 하면 Claude가 글을 보여 드리고, 확인을 받은 뒤 SQL로 넣습니다.

결정이유 (사용자 말)
DB 표 + 읽기 주소, 운영자 화면 없음"B. DB 표 + 읽기 API 이걸로 해주고" (2026-10-12)
안내·약관·처리방침도 DB로"1. 셋 다 DB로" (2026-10-12)
옛 판을 남겨 보이기"서비스 안내 공지 모두 이전 기록이 보였으면 하는데 .." (2026-10-12)
모듈 이름 sitecontent제안 → 승인 (이유 미확인)

3가입(auth)에서 바뀌는 것

auth가 처음으로 다른 모듈을 부르게 됩니다. 가입 화면이 "어느 판에 동의하는지"를 sitecontent에 묻기 때문입니다.

지금약관 버전이 서버 설정 파일에 날짜 2026-10-04로 적혀 있음. 동의 기록에도 그 날짜가 남음
바뀐 뒤auth가 sitecontent에 지금 판 번호를 물음(예: 1). 동의 기록에는 1이 남음. 테스트 계정 기록도 2026-10-04 → 1

반대 방향(sitecontent가 auth를 부르는 일)은 없습니다. 그래서 로그인 기능을 꺼도 약관 글을 읽는 주소는 열려 있고, 웹이 /terms 화면만 숨깁니다. 처리방침은 로그인 기능과 상관없이 늘 보입니다.

dev의 모듈 시험(ModularityTests)은 지금 "auth는 다른 모듈을 쓰지 않는다"를 검사합니다. 이 줄을 "auth는 sitecontent만 쓴다"로 바꿉니다.
