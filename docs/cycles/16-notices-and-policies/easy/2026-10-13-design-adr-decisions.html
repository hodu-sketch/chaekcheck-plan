사이클 16 설계 정리와
결정 기록(ADR) 초안 4개

지금까지 정하신 것을 design-delta.md로 묶었습니다. 그림으로 한 번 훑어보시고, 아래 ADR 초안 4개와 마지막 "이대로 다음 단계" 칩을 골라 주세요. ADR은 승인하시면 파일로 쓰고 상태를 "Accepted"로 둡니다. 설계 확정은 범위에서 정한 대로 사이클 12·13·14 회고 뒤에 dev 코드와 맞춰 봅니다.

1무엇이 생기고 무엇과 이어지나

새 모듈 sitecontent 하나가 공지와 네 문서를 맡습니다. 웹은 로그인 없이 읽고, 가입(auth)은 판 번호만 물어봅니다.

그림: 새 연결은 "auth → sitecontent" 하나. 사이클 13의 가입 조사 기준일(collection)은 그대로입니다.

2DB 표

공지 표 둘(공지, 공지 판)과 문서 판 표 하나. 숨김·고정은 공지 표에, 제목·본문·날짜는 판 표에 있습니다. "다시 동의 필요" 칸은 이번에 만들지 않습니다.

그림: 공지 1개 : 판 여러 개. 문서 판 표는 따로이고, auth의 동의 기록은 판 번호 값만 기억합니다(표끼리 연결 없음).

3가입과 글 넣기 흐름

가입 화면은 지금처럼 동작하고, 버전 번호만 서버 설정이 아니라 sitecontent에서 옵니다. 글은 Claude가 확인받고 SQL로 넣습니다.

그림: 가입. 그사이 새 판이 시행되면 지금처럼 "약관이 바뀌었어요"가 뜹니다.

그림: 운영자(사용자 → Claude)가 글을 넣는 길. 배포 없이 시행일부터 보입니다.

공지 목록·공지 글, 문서 읽기 흐름 그림은 design-delta-original.html에 있습니다.

4결정 기록(ADR) 초안

큰 결정 네 가지를 ADR로 남깁니다. 번호는 파일을 쓸 때 마지막 번호(지금 0097)를 다시 확인해 붙입니다. 다른 세션도 ADR을 쓰기 때문입니다.

1ADR: 공지·서비스 안내·약관 글을 새 모듈 sitecontent가 DB에 판으로 둔다 [안]

칸초안
배경공지사항 페이지가 필요하고, 서비스 안내·이용약관·처리방침 글이 웹 코드에 있어 고칠 때마다 배포해야 했음
결정새 모듈 sitecontent(스키마 같은 이름)가 공지(공지·공지 판 표)와 네 문서(문서 판 표)의 모든 판을 가짐. 로그인 없이 읽는 REST만 두고, 쓰기는 SQL(Claude). 운영자 화면 없음. 고정 공지는 1쪽 위, 숨긴 공지는 DB에 남김
이유 (사용자 말)"B. DB 표 + 읽기 API 이걸로 해주고", "1. 셋 다 DB로", 숨김: "이전에 기록을 봤으면 해", 고정: (빼기 안에) "보기 어려워"
대안웹 코드에 글(배포 필요) / DB + 운영자 화면(일이 큼) / 표를 "문서 + 문서 판" 하나로 합치기(공지 번호 5부터, 규칙을 DB가 못 막음) — 이유 미확인

질문: "DB에 INSERT하면 적용 날짜랑 상관없이 다 보이는 거야?"

아니요. 넣어도 적용 날짜(시행일·게시일)가 오늘 이후면 그날 전까지는 어디에도 보이지 않습니다. 서버가 글을 읽을 때마다 "오늘(한국 시간) 이전에 시행된 판"만 고르기 때문입니다(설계 결정 8, 승인됨).

10월 25일에 넣은 것10월 31일까지11월 1일부터
이용약관 2판, 시행일 11월 1일화면·가입 모두 1판. 날짜 고르기 칸에도 2판 없음화면·가입 모두 2판. 1판은 날짜 고르기 칸에 "~ 10-31 적용"
공지 "점검 안내", 게시일 11월 1일목록에 없음, 주소로 열어도 "찾을 수 없어요"목록 맨 위(최신)에 나타남
공지 "도서관 추가", 게시일 10월 25일(오늘)넣은 즉시 보임(새로고침)

그래서 약관을 바꿀 때 "미리 넣어 두고 시행일에 저절로 바뀌게" 할 수 있습니다. 날짜가 바뀌는 순간 서버를 다시 켜거나 배포할 필요는 없습니다(다음 요청부터 바로 적용, 서버가 글을 기억해 두지 않음 — 명세 R8-2).

2ADR: 가입 문서 버전의 원본을 서버 설정에서 sitecontent로 옮기고, 동의 기록에는 판 순번을 남긴다 (auth → sitecontent) [안]

칸초안
배경지금 이용약관·동의문 버전은 서버 설정 날짜(2026-10-04)이고, 웹 파일과 같은지 테스트로 확인함(사이클 05 제약 27). 글을 DB 판으로 옮기면 버전도 DB가 원본이어야 함
결정가입 화면이 쓰는 지금 판 번호를 auth가 sitecontent의 Java 창구로 물음. 동의 기록에는 판 순번 글자("1")를 남기고, 테스트 계정의 "2026-10-04"는 "1"로 바꿈. 제약 27 폐기. auth가 처음으로 다른 모듈에 의존(AC-18 변경). 409 동작 그대로
이유 (사용자 말)DB로 옮김: 제안 → 승인(2026-10-12). 순번: "하루에 여러 공지가 날 수 있는데 이상한데 그냥 그 자체의 순번으로 하면 안돼?" (화면 흐름), 동의 기록 = 순번: 제안 → 승인(2026-10-13)
대안시행일을 그대로 남김(같은 날 두 판을 구분 못 함) / 표 내부 번호(환경마다 다름) — 이유 미확인

3ADR: 개인정보 처리방침은 로그인 기능과 상관없이 공개한다 (사이클 05 제약 35 일부 변경) [안]

칸초안
배경사이클 05에서 로그인 기능이 꺼지면 약관·처리방침을 숨기기로 함. 그런데 로그인이 꺼져도 이용 기록(사이클 15)·접속 기록에 IP가 남음
결정/privacy와 바닥글 링크는 늘 보임. 이용약관(/terms)은 지금처럼 로그인 기능을 따름(서버 창구는 열어 둠)
근거개인정보위 처리방침 작성지침(2026.4.) 17쪽 "로그인 여부와 상관없이 확인할 수 있어야", 개인정보 보호법 제30조②·시행령 제31조② (research.md 2.2·2.3)
이유 (사용자 말)제안 → 승인(2026-10-12). 처음에는 "로그인 방침에 따라서 다르게 보여야 하는 거 아니야?"라고 하셨고, 지침 확인 뒤 바꿈
대안둘 다 로그인 기능을 따름(지침과 맞지 않음)

4ADR: 약관이 바뀔 때 — 가벼우면 공지 + 시행일, 중요하거나 동의 항목이 바뀌면 다음 로그인 때 다시 동의 (화면은 나중) [안]

칸초안
배경"공지와 시행일만으로 알리기"를 제안했다가, 질문("이거 되는거 확실한거야?") 뒤 조사에서 근거가 약하다고 나옴
결정오탈자·유리한 변경·처리방침은 공지 + 시행일. 중요하거나 불리한 이용약관 변경, 동의문의 항목·목적·기간 변경은 다음 로그인 때 다시 동의(동의 안 하면 탈퇴 가능). 다시 동의 화면과 표시 칸은 나중 할 일 목록 — 그 전에는 그런 변경을 넣지 않음
근거대법원 2013. 2. 15. 선고 2011다69053(반대하지 않은 것은 동의가 아님), 약관규제법 제12조제1호, 개인정보 보호법 제15조② (research.md 4절)
이유 (사용자 말)제안 → 승인(2026-10-12). 칸을 빼는 것: "아직 기능이 다시 동의 필요가 없지 않나?" (2026-10-13)
대안공지 + 동의 간주 조항(온라인게임 표준약관 방식) / 늘 다시 동의 — 이유 미확인
