# 사이클 16: 공지사항과 안내·약관 페이지를 DB로

시작: 2026-10-12. 다른 사이클과 나란히 미리 하는 plan입니다 (아래 "나란히 도는 사이클과 겹치는 곳"). 이어지는 문서: [spec.md](spec.md) · [flow.md](flow.md) · [design-delta.md](design-delta.md) · [research.md](research.md) · [privacy-inputs.md](privacy-inputs.md) · [drafts/](drafts/) · 결정 페이지 목록 [easy/README.md](easy/README.md)

## 목표 (한 문장)

공지사항 페이지를 새로 만들고, 공지사항·서비스 안내·이용약관·개인정보 처리방침의 글을 DB에 두어 배포 없이 고칠 수 있게 합니다.

## 포함

1. **공지사항 페이지** 신설 — 목록과 글 보기 모양은 [flow.md](flow.md)에서 정함 [확정] (2026-10-13). 공개일에 올릴 첫 공지 한 건 "책첵을 시작했어요"([drafts/notice-first.md](drafts/notice-first.md), 사용자 승인 2026-10-13)
2. **네 가지 글을 DB에 두고 읽기 API로 보여 주기** [확정] (사용자: "B. DB 표 + 읽기 API 이걸로 해주고", "1. 셋 다 DB로", 2026-10-12)
   - 공지사항, 서비스 안내(`/about`), 이용약관(`/terms`), 개인정보 처리방침(`/privacy`)
   - 이용약관·처리방침은 **버전마다 글을 남김**: 가입 동의 기록이 버전을 가리키므로 옛 버전 글을 지우지 않음 [확정] (사용자 승인, 2026-10-12). 동의 기록에 남는 값은 지금 `2026-10-04`이고, 설계에서 판 순번 `"1"`로 바뀜 ([ADR-0099](../../adr/0099-signup-document-version-from-sitecontent.md)). 덧붙임: 지금 가입한 사람은 테스트 사용자 한 명뿐이라 지금 버전(검토 전 문구) 동의를 옛 버전으로 따로 챙길 필요 없음 (사용자: "아직 실제로 테스트 인원 이외에 뭐 된 거 없어서 괜찮아 나만 가입했어", 2026-10-12)
   - 가입 화면이 받는 문서 버전(`GET /api/v1/auth/signup`)을 서버 설정(`application.yml`의 `terms-of-service-version`, `privacy-collection-version`)에서 DB의 "지금 버전"으로 옮김 [확정] (사용자 승인, 2026-10-12)
   - 서비스 안내·공지도 이전 기록이 남아 보여야 함 (사용자: "서비스 안내 공지 모두 이전 기록이 보였으면 하는데 ..", 2026-10-12. 제안 "버전 없이 고쳐 씀"은 미승인). 방법: 네 글 모두 버전을 남기고 옛 글을 볼 수 있게 함 [확정] (사용자 승인, 2026-10-12, [easy/2026-10-12-history-decisions.html](easy/2026-10-12-history-decisions.html)). 고르는 자리는 화면 흐름에서 "페이지 아래 목록" → "제목 아래 날짜 고르기 칸"으로 바뀜 (사용자 제안, 2026-10-13). 화면 모양은 결정 페이지의 그림과 다르게, 잘 알려진 서비스의 공지사항 게시판(PC·태블릿·폰)을 조사해 정함 (사용자: "디자인은 저 예시랑 달라야 해 다른 공지사항들 게시판든 사이트 검색해봐 폰이랑 pc랑 태브릿 유명한거 그거 보고 화면 안 좀 줘", 2026-10-12) → [research.md](research.md) 3절, [flow.md](flow.md)
3. **글 넣기·고치기는 SQL 또는 Claude 명령** — 운영자 페이지 없음 [확정] (사용자, 2026-10-12, B안 선택)
4. **연락처 채우기** [확정] 포함 (사용자: "이거 다 할거긴 해", 2026-10-12). 값 `chaekcheck9104@gmail.com` [확정] (사용자, 2026-10-12)
   - 바닥글 "문의: 준비 중"은 없애고, 연락처는 서비스 안내 글 안에 둠 [확정] (사용자 제안, 2026-10-13, [easy/2026-10-13-flow-pc.html](easy/2026-10-13-flow-pc.html))
   - 서비스 안내의 로고 내림 요청 연락처와 같은 주소 하나 [확정] (사용자 승인, 2026-10-12)
5. **이용약관·처리방침 문구 확정** ("검토 전 문구" 표시 떼기) [확정] 포함 (같은 발언). Claude가 법정 항목을 공식 자료로 확인해 초안, 사용자가 검토 [확정] (사용자 승인, 2026-10-12). 처리방침 확정은 사이클 15가 기록할 것이 정해진 뒤, 그 전에는 초안까지 [확정] (사용자 승인, 2026-10-12) → 초안 [drafts/](drafts/) 승인 (2026-10-13)
6. **바닥글 링크 한 줄 정리**: "공지사항 · 서비스 안내 · 이용약관 · 개인정보 처리방침" [확정] 포함 (같은 발언). 순서·모양은 [flow.md](flow.md)
7. 이용약관·처리방침 링크와 페이지는 로그인 기능 설정을 따름(로그인 기능이 꺼져 있으면 보이지 않음, [사이클 05 design-delta](../05-login-account/design-delta.md) 제약 35) — 처음엔 그대로 둠 [확정] (사용자: "로그인 방침에 따라서 다르게 보여야 하는 거 아니야?", 2026-10-12). → **바뀜**: 조사(개인정보위 작성지침 17쪽 "로그인 여부와 상관없이") 뒤 처리방침은 로그인 기능과 상관없이 늘 보이고, 이용약관만 로그인 기능을 따름 [확정] (사용자 승인, 2026-10-12, [spec.md](spec.md) R6-2, [ADR-0100](../../adr/0100-privacy-policy-public-regardless-of-login.md))

## 완료 기준 (사용자가 화면에서 확인할 수 있는 것)

- 바닥글에 "공지사항 · 서비스 안내 · 이용약관 · 개인정보 처리방침"이 한 줄로 보이고(이용약관은 로그인 기능이 켜져 있을 때만), 각각 눌러 열린다
- 공지사항 페이지에 DB에 넣은 공지가 보이고, SQL(또는 Claude 명령)로 공지를 넣으면 **배포 없이** 새로고침만으로 보인다
- 서비스 안내·이용약관·처리방침의 글을 DB에서 고치면 배포 없이 바뀐 글이 보인다
- 이용약관·처리방침에 "검토 전 문구" 표시가 없다
- 서비스 안내에 연락처가 보이고, 바닥글에 "준비 중"이 없다 (사용자 제안, 2026-10-13)
- 새 약관 버전을 넣은 뒤 가입하면 동의 기록에 새 버전이 남는다 (테스트로 확인)

- ICE 점수는 매기지 않음. 사용자가 슬라이스를 직접 정함: "나는 공지사항 페이지를 넣으려고 해", "기존의 서비스 안내 이용약관 개인정보 처리방침 이것도 좀 정리하고 싶어" (2026-10-12)
- 저장 방식 선택: 세 안(A 웹 코드에 글 / B DB 표 + 읽기 API / C B + 운영자 페이지) 중 B, 세 페이지는 "셋 다 DB로"(나머지 안: 서비스 안내만 DB, 셋 다 코드에 두고 내용만 정리). 고른 이유 [이유 미확인]
- 지금 상태 (dev 코드 확인, 2026-10-12): 세 페이지의 글은 모두 웹 코드 안에 있음 (`web/src/features/about/AboutPage.tsx`, `web/src/features/auth/legalText.ts`), 약관 버전 날짜만 서버 설정(`application.yml`). 운영자 권한·관리 화면은 없음
