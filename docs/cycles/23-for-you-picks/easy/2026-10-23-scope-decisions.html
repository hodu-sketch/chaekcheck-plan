불러오는 중

「나에게 맞는 책」 탭 사이클을 시작하기 전에
다섯 가지를 골라 주세요.

탭 자리·화면 짜임·신호 점수·고르기·보유 조건·기본 목록 출처는 이미 정해졌습니다(2026-10-23·24). 여기 다섯 가지는 범위를 쓰면서 남은 질문입니다. 각 항목에서 승인·미승인·기타를 고르고 "저장"을 누르면 이 대화의 Claude가 읽습니다.

1꼬리표 사전은 이번 사이클에서 빼고 다음으로

안 #1 이번 사이클은 탭·기본 목록·비슷한 책·개인 신호만 만들고, 꼬리표(분위기·주제·독자 같은 태그) 사전과 Haiku로 꼬리표 붙이기는 다음 사이클로 미룹니다. 탭은 꼬리표 없이도 동작합니다.

꼬리표가 무엇인가. 2026-10-23에 정한 방식은 Thema 1.6 한국어판(출판 업계 주제 분류)을 뼈대로 분야·주제·독자 100~150개와 느낌 15~20개를 사람이 정한 뒤, Haiku가 책마다 그 사전 안에서 번호만 고르는 것입니다(docs/research/ai-recommend/tag-vocabulary.md 3절). 표본 500권을 먼저 해 봅니다.

앞서 정한 것과 다릅니다: tag-vocabulary.md 3절은 꼬리표를 "AI 추천(맞춤 탭)을 맡은 사이클에서 함"이라고 적었습니다. 이번 범위 질문(2026-10-23)에는 꼬리표가 들어 있지 않아서, 미루는 안을 냅니다.

다른 선택: 이번에 함께 — 사전 150개를 사람이 확정하는 일과 표본 500권 검토가 더해져 사이클이 길어집니다. 대신 탭 카드에 "잔잔함 · 가족" 같은 꼬리표를 바로 보일 수 있습니다.

2로그인하지 않은 사람의 "최근 본 책"은
그 브라우저가 들고 있게

안 #2 로그인한 사람은 서버 사용 기록(회원 번호가 붙은 기록)으로 최근 30일 기준 책 3권을 고릅니다. 로그인하지 않은 사람은 브라우저가 자기 저장소에 최근 본 책 번호와 점수를 30일 동안 들고 있다가, 탭을 열 때 상위 3권 번호만 서버에 보냅니다. 서버는 그 번호로 이웃 책을 돌려줄 뿐 새로 저장하지 않습니다.

로그인한 사람서버 기록의 회원 번호→서버가 30일 점수 계산→기준 책 3권
로그인 안 한 사람브라우저 저장소→브라우저가 30일 점수 계산→기준 책 3권 번호만 보냄

두 길 모두 끝에서 같은 "기준 책 3권 → 이웃 책 고르기"로 이어집니다.

왜 이 질문이 생겼나. 지금 기록의 방문 번호(visit_key, ADR-0134)는 탭 하나에만 살아서 탭을 닫으면 끊깁니다. 그래서 로그인하지 않은 사람의 "최근 30일"은 서버 기록만으로는 이어 붙일 수 없습니다.

예: 로그인하지 않고 오늘 「아몬드」 창을 15초 보고, 사흘 뒤 같은 브라우저로 다시 오면 탭 맨 위에 「아몬드」와 비슷한 책이 나옵니다. 다른 기기나 브라우저 저장소를 지운 뒤에는 나오지 않습니다.

다른 선택 ① 로그인한 사람만 개인 추천, 로그인하지 않은 사람은 기본 목록만 — 가장 단순하지만 지금 대부분이 로그인하지 않으면 개인 추천을 볼 사람이 거의 없습니다. ② 방문 번호를 브라우저에 오래 남겨 서버 기록끼리 잇기 — ADR-0134("탭 단위, 쿠키 아님")를 바꾸고 처리방침을 고쳐야 하며, law.md에 적힌 맞춤형 광고 가이드라인 확인이 필요합니다(확인 못 함).

이 안에서도 법적 고지가 따로 필요한지는 확인 못 함입니다(브라우저 저장소에 본 책 번호만 두고 서버는 저장하지 않음). 명세 단계에서 law.md와 공식 문서로 확인합니다.

3탭 추천 글은 내 PC에 모은 전자도서관 소개 원문과
서지로 Haiku가 씀

안 #3 「나에게 맞는 책」 카드의 글은 지금 추천목록 책 창의 AI 요약과 따로 만듭니다. 입력은 제목·저자·출판사와, 내 PC 수집 DB에 모으고 있는 전자도서관 목록 화면의 책 소개 원문(intro_raw)입니다. 원문은 PC에만 있고 서비스로 나가는 것은 Haiku가 쓴 글뿐입니다. 소개 원문이 없는 책은 서지만으로 쓰고, 모르면 쓰지 않습니다. 사람이 표본을 확인합니다.

입력지금 상태판정
서지만(제목·저자·출판사)모든 책에 있음안전하지만 덜 알려진 책은 글을 못 씀
수집 DB 소개 원문 intro_raw2026-10-23부터 모으는 중. 교보 500자에서 잘림, YES24 "…"로 줄임, 북큐브·강남 전체, 알라딘·포털·서울도서관 없음원문은 PC에만 두기로 이미 정함(2026-10-23 결정 #1)
카카오 책 검색 소개(지금 추천목록 요약이 쓴 것)카카오는 저장 제약 때문에 표지에서 이미 뺀 곳약관 확인 못 함

앞서 정한 것과 다릅니다: overview.md 결정 #6은 "AI 소개 문구 입력은 서지만, 책 소개 원문을 넣지 않음"이었습니다. tag-vocabulary.md 3절 끝에서 "소개 원문을 문구 입력으로 쓸지는 그 사이클에서 따로 물음"으로 남겨 두었고, 이번에 묻습니다.

다른 선택: overview 결정 #6 그대로 서지만 — 가장 안전하지만 글이 비는 책이 많아질 수 있습니다. 카카오 소개 — 약관을 먼저 확인해야 합니다.

4북튜버 채널 후보는 Claude가 찾아 다음 페이지에 올리고
사용자가 고름

안 #4 기본 목록의 유튜브 출처는 정해 둔 채널 10~30곳의 새 영상만 봅니다. 채널 후보(이름, 주소, 구독자 수, 최근 올린 횟수, 책을 영상 제목이나 설명에 적는지)를 Claude가 조사해 다음 결정 페이지에 올리고, 사용자가 고릅니다. 영상 제목·설명은 저장하지 않고 책 이름과 영상 링크만 남깁니다(사이클 21 이동진 추천도서와 같은 방식, ADR-0128).

YouTube Data API의 하루 한도와 호출 비용은 이 클라우드 세션에서 구글 개발자 문서가 열리지 않아 확인 못 함입니다. 사이클 21 수집기는 같은 API를 쓰고 있어(28단위), 그 기록과 공식 문서로 다시 확인합니다.

다른 선택: 사용자가 채널을 직접 적어 주기 — 기타에 채널 이름을 적어 주시면 그대로 씁니다. 채널을 정하지 않고 "책 추천" 검색 결과를 쓰기 — 검색은 호출 비용이 크고 광고·협찬 영상이 섞입니다(비용 수치는 확인 못 함).

5개발은 세 단계로 나눠 차례로

안 #5 한 번에 만들기에는 커서(수집기 둘, PC 임베딩, 서버 표와 응답, 웹 탭, 사용 알림) 세 단계로 나눕니다. 단계마다 운영에 올려 보고 다음으로 갑니다.

1단계탭 + 기본 목록(추천목록 + 교보 인기순) + 카드 + AI 표시 줄→2단계비슷한 책 표(PC 임베딩) + 머묾 알림 + 기준 책 3권→3단계북튜버 출처를 기본 목록에 더함

실선 칸이 먼저 할 일, 점선 칸이 뒤에 할 일입니다. 1단계만으로도 탭이 보이고, 2단계에서 개인 추천이 붙습니다.

탭 추천 글(#3)은 1단계에 나오는 책부터 씁니다. 교보 인기순이 약관이나 시험 결과로 막히면 1단계는 추천목록만으로 갑니다.

다른 선택: 한 번에 — 개발 기간이 길고 중간 확인이 없습니다. 북튜버를 1단계로 — 채널 목록과 API 확인이 먼저 끝나야 해서 탭이 늦게 보입니다.
