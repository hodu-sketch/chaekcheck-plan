B. 묶는 방식

  • 인터페이스 BookGrouper(지금 CatalogImporter가 부르는 모양: add, groupByCodes, bibliographyKeys, attachBibliography, mergeSameText, forEachBook, bookOf), 이름 [안]
  • compact [확정 방향: 스펙 R-B2, 설계 #9]: 제목·저자·출판사·공급자 필드별 같은 글자 합치기, Votes 6개 대신 묶음 안의 칸(첫 값 + int 개수, ISBN long, 날짜 epochDay, 종류 byte, 두 번째 값부터만 작은 맵), 도서관 int[], 묶음 열쇠 128비트(64비트 해시 둘) 원시 배열 해시표
  • sql [확정 방향: 스펙 R-B3·B4·B5, 설계 #10]: Java가 줄마다 정리값(title_norm, main_title_norm, publisher_norm, first_author, 교보식 ISBN, 출판일)과 읽은 순번 seq를 가져오기 연결의 TEMPORARY 표에 COPY → 묶음 번호 row_number() OVER (ORDER BY min(seq)) → 사슬 잇기는 바뀐 줄이 0이 될 때까지 label := min 반복(상한 둠) → 대표값은 개수 큰 순 + COLLATE "C" → ③ 국가서지·④ 같은 글 한 번씩 → 책을 label 순으로 흘려 Java가 씀 → 둘째 읽기는 seq 순으로 흘려 짝지음(매 줄 (도서관, 책 코드) 확인)
    • temp_buffers 기본 8MB [확정] (https://www.postgresql.org/docs/18/runtime-config-resource.html , 확인 2026-10-12, research.md 11절)라 임시 표는 대부분 디스크로 감 → temp_bytes·pg_database_size로 잼
  • 결과 비교 [확정] (설계 #11): dry run이 books.tsv(책 순번·제목·저자·출판사·출판일·ISBN·종류·도서관 목록)·rows.tsv((도서관, 책 코드) → 책 순번) gzip을 남기고 scripts/catalog/compare_grouping.py가 비교. 번호는 방식마다 export → 앱 밖 compare_grouping.py가 psql로 catalog_next의 book·holding 번호를 뽑음(앱 코드에 넣지 않음, collection이 catalog 표를 읽지 않게) [확정] (사용자 승인, 2026-10-12, 검토 결정 #2) → discard
  • 측정 [확정: 스펙 R-B6]: bootRun에 -PbootRunJvmArgs(이름 [안])로 -XX:+UseStringDeduplication, -XX:+UseCompactObjectHeaders, -Xlog:gc*:file=…. 힙 최고(GC 기록 + noteHeap), step_seconds, pg_stat_database.temp_bytes 전후 차이, pg_database_size 최대, Java CPU(getProcessCpuTime)와 DB 컨테이너 cgroup cpu.stat, 가져오는 동안 probe_during_import.py. 방식마다 두 번, 힙은 6→4→3→2→1GB로 끝까지 되는 값까지
  • 시험 사본 [확정: 점검 #2]: 새 사본(411 새 주소 포함) + 비교용 옛 사본(ebook-catalog-2026-10-05-0745.sqlite) 한 번
