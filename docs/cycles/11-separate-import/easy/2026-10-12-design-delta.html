2운영자가 돌리는 순서

3dev가 먼저 시험할 것과 잴 것

본 개발 전에 작은 시험 넷으로 방식이 되는지 봅니다. 안 되면 설계 안에서 대안(파일을 파이프 대신 폴더로 주고받기 등)으로 바꿉니다.

먼저 시험안 될 때
덤프·복원 뒤 책·소장 번호 시퀀스 값이 같은지복원 뒤 번호 값을 따로 맞춤
WSL·Docker 파이프로 파일이 깨지지 않는지파일을 공유 폴더로 주고받음
컨테이너 안 도구가 암호 없이 붙는지접속 설정 추가
Java가 죽어도 컨테이너 안 복원이 계속 도는지다음 실행이 확인하고 멈춤

잴 것: 덤프 파일 크기, 복원 시간, 상한 1GB에서 색인 시간, 운영 디스크 최대, 그리고 세 방식 × 여섯 관점 × 두 번(+ Java 옵션 두 경우). 결과는 dev가 plan-feedback.md로 넘깁니다.
