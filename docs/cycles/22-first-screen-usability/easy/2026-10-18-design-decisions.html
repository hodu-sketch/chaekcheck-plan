1[어디 살든 가입] 말풍선에서 "울산에" 같은 시도 이름을 빼기

[안] 말풍선 문구를 "그 지역에 살지 않아도 온라인으로 가입할 수 있어요 · 가입 방법 보기"로 씁니다. 도서관이 어느 시도에 있는지가 서버 `library` 표에도, 결과 데이터(targets)에도 없기 때문입니다(2026-10-18 dev `Library.java`·표 정의 확인). 서버·데이터 변경 없음.

예시: 울산동부도서관 줄의 [어디 살든 가입]을 누르면 "그 지역에 살지 않아도 온라인으로 가입할 수 있어요 · 가입 방법 보기".

제안: 승인. 범위 결정 2-1의 "○○에 살지 않아도"가 "그 지역에 살지 않아도"로 바뀌는 것뿐입니다.

다른 선택 ①: 서버 `library` 표에 시도 칸을 더하고 2,663곳을 채우기 — 정확하지만 이 사이클의 "서버 변경 없음"을 벗어나고 도서관 넣기(사이클 13)까지 손댑니다.
다른 선택 ②: 도서관 이름 앞머리("울산동부…")로 시도를 짐작 — 공짜지만 "군산시립도서관"처럼 안 맞는 곳이 있고 이름 규칙에 기대는 논리가 생깁니다.

2[내 지역] 말풍선은 "사는 곳이나 일하는 곳으로 가입할 수 있어요"

[안] [내 지역] 말풍선은 사용자가 고른 쪽에 맞춰 씁니다: 사는 곳만 있으면 "사는 곳으로 가입할 수 있어요", 일하는 곳만 있으면 "일하는 곳으로", 둘 다 있으면 "사는 곳이나 일하는 곳으로 가입할 수 있어요". 그 도서관이 둘 중 어느 쪽 덕분에 가입되는지는 결과 데이터에 없습니다(설계가 새로 찾은 빈틈). 서버 변경 없음.

제안: 승인.

다른 선택: 결과 데이터(targets)에 "거주/직장 중 무엇으로 맞았는지" 칸을 더하기 — 정확하지만 서버 변경입니다. 백로그에 둡니다.

3[결과 더 보기]로 온 줄은 묶음 안 "소절"의 끝에 (거름이 "전체"일 때)

[안] 묶음 안은 "지금 빌릴 수 있어요" 소절 → "예약하고 기다려요" 소절 → "조회 중" 순이고, [결과 더 보기]로 온 줄은 자기 소절의 끝에 붙습니다. 기본 거름("지금 빌릴 수 있는 책만")에서는 소절이 하나라 묶음 끝과 같고(명세 결정 #6 그대로), 거름을 "전체"로 했을 때만 차이가 납니다.

내 도서관에 있어요 (5)
● 지금 빌릴 수 있어요: 배치1 a, b · 배치2 d
● 예약하고 기다려요: 배치1 c · 배치2 e

(제안) 소절 끝에: 소절 제목은 한 번씩, 배치2의 빌림 줄 d가 배치1의 예약 줄 c보다 위에.

내 도서관에 있어요 (5)
● 지금 빌릴 수 있어요: a, b
● 예약하고 기다려요: c
● 지금 빌릴 수 있어요: d
● 예약하고 기다려요: e

(다른 선택) 묶음 끝에 덩어리로: 보던 줄이 전혀 안 움직이지만 소절 제목이 되풀이됩니다.

함께 정하는 세부: 배치마다 나오던 "지금까지 N곳에서 찾지 못했습니다" 글은 목록 맨 아래 [결과 더 보기] 바로 위 한 줄로 옮기고, "내 도서관에는 없어요 (0)"은 지역이나 직접 추가가 있는 사람에게 첫 배치가 끝난 뒤에만 보입니다.

제안: 승인. 명세 R5-2(소절 제목은 묶음마다 한 번)와 맞습니다.

다른 선택: 묶음 끝에 배치 덩어리로 — 보던 줄이 안 밀리지만 소절 제목이 여러 번 나와 R5-2와 어긋납니다.

4펼친 상자의 "직접 추가 N곳" 이름은 상자를 열 때 도서관 목록을 받아 보임

[안] 직접 추가가 1곳 이상인 사람이 펼친 상자를 열면 그때 도서관 전체 목록(`GET /api/v1/libraries`, 압축 약 62KB)을 한 번 받아 이름을 보이고, 그 페이지에 있는 동안 기억합니다. 상세검색 "도서관" 줄의 이름 찾기도 어차피 이 목록이 필요하므로 같은 것을 같이 씁니다. 직접 추가가 0인 대다수에게는 요청이 없습니다.

왜: 직접 추가 목록은 브라우저·계정 모두 도서관 번호만 있고 이름이 없습니다. 이름을 보이려면 목록이 필요합니다. 명세 결정 #4(첫 화면에서 수 하나 때문에 목록을 받지 않기)와 어긋나지 않습니다: 그때는 모든 사람, 지금은 직접 추가가 있는 사람이 상자를 연 때만입니다.

제안: 승인.

다른 선택 ①: 수만 보이기("직접 추가 2곳") — 요청 0이지만 흐름의 "이름 두어 개"를 뺍니다.
다른 선택 ②: 마지막 검색 결과의 계획에서 이름 가져오기 — 요청 0이지만 검색 전에는 수만 보이고, 바꾼 뒤 다음 검색까지 안 맞습니다.

5곳 수 기억과 "저장 안내 닫음"은 지금 검색 설정 저장 칸에 같이 둠

[안] 접힌 줄의 "N곳"(명세 결정 #4)과 저장 안내를 ×로 닫은 표시(명세 결정 #10)는 지금 있는 브라우저 저장 `chaekcheck.searchSettings.v1`에 칸을 더해 둡니다. 같은 변경에서 더는 쓰지 않는 스위치 값(`guestScope`·`myScope`)을 지웁니다.

세부: 곳 수는 "어떤 조건의 수인지"(지역·직접 추가·방문 빼기·로그인 여부)를 함께 적어, 조건이 같을 때만 보입니다. 그래서 지역을 바꾸면 따로 지우지 않아도 수가 숨겨져 다음 검색까지 수 없이 보입니다. 전국 링크 검색의 수는 저장하지 않습니다.

제안: 승인. 저장을 읽고 쓰는 코드가 이미 있어 그대로 씁니다.

다른 선택: 새 저장 칸을 하나 더 만들기 — 성격은 깔끔하지만 같은 일을 하는 코드가 하나 더 생깁니다.

다시 검색·기록은 마지막 체크 뒤 0.7초에 한 번

[안] 체크하면 바로 저장합니다(로그인 전 브라우저, 뒤 계정에 PUT — 한 번에 하나씩 보내고, 보내는 중에 또 바뀌면 마지막 값만 다음에). 무거운 일(다시 검색, 마이페이지 "자동 N곳" 목록 다시 받기, 이용 기록 `region_change`)은 마지막 체크 뒤 0.7초(제안값) 기다렸다가 한 번만 합니다. 저장에 실패하면 꼬리표를 마지막 저장값으로 되돌리고 사이클 06 문구를 보입니다.

서버 자원 쪽: 체크마다 처리하면 세 번 체크에 검색 3번·도서관 목록(870KB) 3번·PUT 3번(응답 순서가 바뀌면 앞 값으로 되돌아갈 위험)·기록 3줄입니다. 제안대로면 각각 1번입니다. 0.7초는 웹 값이라 서버 설정 표에는 넣지 않고 설계 문서에만 적습니다.

제안: 승인(0.7초 포함).

다른 선택 ①: 체크마다 모두 바로 — 가장 단순하지만 위의 낭비.
다른 선택 ②: 다시 검색은 상자를 닫을 때 — 명세 R10-2 "바꾸는 즉시 다시 검색"(확정)과 어긋납니다.

7로그인한 사람은 계정의 지역을 읽을 때까지 검색이 잠깐 기다림

[안] 로그인한 사람이 검색하면 계정의 지역·직접 추가를 읽을 때까지(서버에서 두 번 읽기, 보통 0.1초 안) 검색을 시작하지 않습니다. 읽기에 실패하면 지역 없이 "빌릴 수 있는 곳"으로 찾고 접힌 줄에 "내 도서관을 불러오지 못했어요 [다시 시도]"를 보입니다. 지금 규칙(사이클 06: 읽는 동안·실패하면 "전체 도서관")을 바꾸는 것이라 결정이 필요합니다.

왜 바꾸나: 스위치가 없어지면 "전체"로 시작할 이유가 없고, 지금처럼 하면 약 376곳 계획으로 검색을 시작했다가 곧 내 도서관으로 다시 시작해 외부 도서관 조회를 버립니다. 친구분이 놀란 전국 화면도 잠깐 보입니다.

제안: 승인. 사이클 06 flow S1의 "읽는 동안 전체" 결정을 바꿉니다.

다른 선택: 지금처럼 읽는 동안 전국 — 첫 검색이 0.1초쯤 빠르지만 조회를 버리고 전국 화면이 번쩍입니다.

8방문 가입을 뺀 뒤의 문구는 수 없이 "방문 가입 도서관을 뺐어요 · [다시 넣기]"

[안] [그 N곳 빼기]를 누르면 다시 검색되는데, 그때는 뺀 도서관이 계획(targets)에 아예 없어 몇 곳을 뺐는지 화면이 알 수 없습니다. 그래서 명세 R8-2의 "방문 가입 {N}곳을 뺐어요"를 흐름의 문구 "방문 가입 도서관을 뺐어요 · [다시 넣기]"로 맞춥니다.

제안: 승인(문구 하나).

다른 선택: 누르기 전의 N을 기억해 두었다가 쓰기 — 다음 배치가 오면 맞지 않는 수가 됩니다.

9책 화면과 추천도서 창은 묶음·꼬리표 없이, 가입 정보 창의 말만 바뀜

[안] 결과 목록 부품(ResultList·ResultRow)은 책 화면(`/books/…`, 책 먼저 고르기 뒤)과 추천도서 책 창도 같이 씁니다. 그 둘에는 묶음·꼬리표를 켜지 않습니다(범위 결정 #2). 단, 도서관 이름을 눌러 열리는 가입 정보 창의 자격 요약 "누구나 가입" → "어디 살든 온라인 가입"(흐름 #6)은 부품이 같아 그 두 화면에서도 바뀝니다 — 수용 기준 AC-17 "변경 전과 같다"의 예외로 둡니다. 또 범위 스위치 저장값이 없어져 추천도서·책 화면도 늘 "빌릴 수 있는 곳"으로 찾습니다(전에 "전체 도서관"을 저장해 둔 사람은 바뀜).

제안: 승인.

다른 선택: 가입 정보 창 문구를 화면마다 다르게 — 같은 창에서 말이 둘이 됩니다.

설계에서 확인한 것 (결정 아님)

  • 서버 변경 없음. API(`/api/v1/regions`, `/api/v1/me/regions`, `/api/v1/me/libraries/**`, `/api/v1/libraries`, 검색 스트림 셋)와 표(`library`, `region`, 계정 지역·도서관, 이용 기록) 모두 그대로. `scope`는 `joinable`, 전국 링크 때만 `all`. 이용 기록에 새 이벤트 없음(전국 링크는 `scope='all'`로, 방문 빼기는 `visit`로 이미 남음).
  • 문서 어긋남 6곳을 고쳤습니다(설계가 찾음): 첫 화면 작은 글 "안 고르면 전국에서" → "안 고르면 어디 살든 가입되는 도서관에서"(스위치가 없어져 전국이 아니므로), 녹색 줄 문구도 같은 뜻으로, R7-1의 "스위치가 내 도서관이고" 삭제, AC-4 [지역 고르기] → [사는 곳 고르기], R5-4 "전국으로 바꾸면" → [전국에서 찾기] 링크, "두 단계 고르기" → 격자.
