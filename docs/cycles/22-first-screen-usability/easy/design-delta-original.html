웹 규칙 (설계 결정)

#규칙근거
D1[어디 살든 가입] 말풍선은 "그 지역에 살지 않아도 온라인으로 가입할 수 있어요 · 가입 방법 보기" (도서관 시도는 library 표·targets에 없음)설계 결정 #1 [확정]
D2[내 지역] 말풍선은 사용자가 고른 쪽으로: 사는 곳만/일하는 곳만/"사는 곳이나 일하는 곳으로"설계 결정 #2 [확정]
D3묶음 단계는 resultGroups.groupBatches(views, libraryById): 배치 순서대로 ①②③에 넣고, 묶음 안은 sortBatch 결과를 소절(빌릴 수 있어요 → 예약 → 조회 중)마다 이어 붙임. [더 보기] 줄은 자기 소절 끝. 배치마다 있던 "더 찾은 결과" 구분 줄·"N곳에서 찾지 못했습니다" 글은 없애고 후자는 목록 맨 아래 한 줄로. "내 도서관에는 없어요 (0)"은 지역·직접 추가가 있고 첫 배치가 끝난 뒤만설계 결정 #3 [확정]
D3'libraryGroup(target): chosen ∨ priorityGroup∈{MY_SIGUNGU, MY_SIDO} ∨ eligibility=ELIGIBLE → MINE; eligibility=OPEN → OPEN; 그 밖 → OTHER; 실패·UNKNOWN 판정 줄은 sortBatch.unchecked → UNCHECKED(사이클 20 그대로)spec R5-1 [확정]
D4펼친 상자의 직접 추가 이름과 상세검색 도서관 이름 찾기는 GET /api/v1/libraries(지역 없이)를 필요할 때 한 번 받아 페이지 안에서 캐시(React Query key ['libraries','',''], staleTime 5분). 직접 추가 0이고 이름 찾기를 안 쓰면 요청 없음설계 결정 #4 [확정]
D5브라우저 저장 chaekcheck.searchSettings.v1에 planCount {key, count}, openCount, saveHintClosed 추가; guestScope·myScope는 DROPPED_PREFS로 지움. planCount.key = `sourceresidenceworklibraryIdsvisit 지문 — 같을 때만 수를 보임(바뀌면 자연히 숨김). scope=all` 검색의 수는 저장 안 함설계 결정 #5 [확정]
D6격자 체크 = 저장만(로그인 전 localStorage, 뒤 PUT을 한 번에 하나씩 — 보내는 중 또 바뀌면 마지막 값만 다음에; 실패 시 마지막 저장값으로 되돌리고 사이클 06 문구, 422는 해석 안내). 검색은 [검색] 단추로만. 자동 재검색·debounce 없음. region_change 기록은 저장마다(지금과 같음). 마이페이지 "자동 N곳" 목록은 격자 체크 뒤 다시 받음(지금과 같음)설계 결정 #6 [확정] (사용자 규칙)
D7로그인한 사람: RegionContext.ready=false 동안 검색을 시작하지 않음(bookQuery=null). 계정 읽기 실패: 지역 없이 joinable, 접힌 줄에 "내 도서관을 불러오지 못했어요 [다시 시도]", 녹색 안내 줄 숨김설계 결정 #7 [확정] (사이클 06 flow S1 "읽는 동안 all" 대체)
D8방문 가입을 뺀 뒤 제목 자리 "방문 가입 도서관을 뺐어요 · [다시 넣기]" (수 없음)설계 결정 #8 [확정]
D9BookPage는 ResultList grouped=false, PicksBookDialog는 ResultRow tags=false. 가입 정보 창의 "누구나 가입" → "어디 살든 온라인 가입"은 공통이라 그 화면들에서도 바뀜(AC-17 예외). 추천도서·책 화면의 범위는 늘 joinable(주소 scope=all일 때만 전국)설계 결정 #9 [확정]
D10범위 읽기 readScope(params): 주소 scope=all이면 all, 아니면 joinable. search()는 새 주소에 scope를 싣지 않음. 책 링크(bookLinkSearch)는 주소에 있던 scope=all을 이어서 실음흐름 후속 #2 [확정] / 책 링크 [안]
D11RegionGrid 크기: 글자 16px 이상, 체크 칸 높이 40px 이상, 너비 100%(PC 상자 최대 약 640px, 시군구 4칸 → 좁으면 3·2칸), 폰은 화면 너비 전체spec R12-1 [확정]

세 관점 자체 점검 (2026-10-18)

관점본 것결과
사용자결과 화면에서 지역을 바꾼 뒤 [검색]을 안 누르면 결과와 접힌 줄이 어긋남접힌 줄은 저장값을, 결과는 검색 당시 값을 보이므로 "· N곳"은 지문이 달라 숨겨짐(D5). 상자를 닫을 때 지역이 바뀌어 있으면 검색창 아래 한 줄 "지역이 바뀌었어요 · [검색]을 눌러 다시 찾기" [안]
사용자전국 링크 검색 중에 [결과 더 보기]를 누르면?같은 주소(scope=all)의 다음 배치 → 전국 그대로. 새 검색만 joinable로 돌아감 [확정] (D10)
사용자로그인 직후 가져오기 창(S11)과 새 저장 안내가 겹침S11은 그대로, 저장 안내는 로그인한 사람에게 안 보임(R9-2)이라 겹치지 않음
서버 자원체크마다 검색이 사라져 외부 조회 낭비 없음(D6). 전체 목록 870KB는 직접 추가 있는 사람이 상자를 열 때·이름 찾기 때만(D4). 전국 링크는 사용자가 누른 그 검색만(계획 약 376곳, 첫 배치는 똑같이 10곳)지금보다 늘어나는 요청 없음. 계정 PUT이 체크 수만큼 늘지만 DB 쓰기 한 줄
보안·안정성주소 scope=all은 지금도 받는 값(검증 그대로). 브라우저 저장 칸 셋은 숫자·불리언·문자열이고 읽을 때 기본값으로 떨어짐(loadPrefs 방식). PUT 순서 보장으로 되돌아감 방지새 공격면 없음. 격자가 받는 지역 ID는 지금처럼 resolutions로 해석
