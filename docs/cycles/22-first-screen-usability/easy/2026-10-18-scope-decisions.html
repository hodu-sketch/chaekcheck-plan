질문에 답 (2026-10-18)

스위치 모양: "내 도서관 / 전국"은 지금처럼 한 네모 안에 두 칸이 붙은 스위치입니다(위 그림을 그렇게 고쳤습니다). 따로 떨어진 단추 두 개가 아닙니다. 사용자 말: "실사용에서는 둘이 합쳐진 네모 안에 속해야 하는 거 잊지 마" → 명세·화면 문서에 그대로 적습니다.
방문 가입 설정: 접힌 줄을 펼친 안에 "☐ 직접 가야 가입되는 도서관은 빼기" 칸을 넣었습니다(위 그림 셋째 줄). 그래서 켜고 끄는 곳은 셋이 됩니다: 펼친 줄 안, 결과 묶음 아래 [그 N곳 빼기], ⚙ 설정. 값은 하나라 어디서 켜도 같이 켜집니다.

제안: 승인. 사이클 07의 "[내 도서관 관리] 단추(사이클 06 S1)"와 2026-09-29의 [방문 없이 가입] 단추 자리를 바꾸는 것이고, 기능은 모두 접힌 줄 안과 ⚙ 설정에 남습니다.

다른 선택: [내 도서관 관리 ⌄]는 남기고 지역 줄만 더하기 — 같은 값을 여는 입구가 한 줄에 둘이라 "이게 뭐가 다르지"가 됩니다.

다시 생각한 것 (2026-10-18): 접힌 줄에 어디까지 보여 줄까

사용자 말: "니가 더 다른 시각에서 생각해봐… 어떤 것이 좋은가 어디까지 정보를 줘야 하나." 다른 시각으로 보면, 이 줄의 할 일은 "지금 어느 도서관을 찾는지"를 한 번에 읽히게 하고, 결과가 왜 이런지 설명해 주는 것입니다. 그러니 기준은 하나입니다: 결과를 바꾸는 값만 보이고, 기본값과 같은 것은 숨깁니다. 그래서 접힌 줄은 아래 "중간" 수준으로 고칩니다.

적게"내 도서관: 서울 강남구 ▾"
짧지만 68곳인지 39곳인지, 일하는 곳이 있는지 모릅니다.
중간 (제안)"내 도서관: 서울 강남구 · 68곳 ▾"
일하는 곳이 있으면 "· 일하는 곳 성남시", 방문 가입을 뺐을 때만 "· 방문 가입 뺌", 직접 추가가 있을 때만 "· 직접 추가 2"
결과를 바꾸는 것만 보이고, 기본값이면 안 보입니다.
많이"내 도서관: 사는 곳 서울 강남구 · 일하는 곳 없음 · 방문 가입 포함 · 직접 추가 0 · 68곳 ▾"
처음 온 사람에게 "없음·포함·0"은 읽을 거리만 늘립니다. 폰에서는 두 줄이 됩니다.

왜 "곳 수"를 넣나: 친구분이 놀란 것은 "전국 결과"였습니다. "68곳"이 보이면 "전국"을 누르기 전에 지금 범위가 좁다는 것을 알고, 지역이 없을 때 "누구나 가입 39곳"이 보이면 왜 울산이 나오는지 압니다. 수는 지금 마이페이지가 이미 세고 있는 값(자동 29곳 + 누구나 가입 39곳)이라 새 계산이 없습니다.

왜 "방문 가입 포함"은 숨기나: 기본값이라 결과를 바꾸지 않습니다. 반대로 뺐을 때는 결과에서 도서관이 사라지므로 "방문 가입 뺌"을 꼭 보입니다(안 그러면 "왜 그 도서관이 안 나오지"가 됩니다).

2꼬리표와 묶음은 검색 결과 화면까지만

[안] 묶음 세 개와 [내 지역]·[누구나 가입]·[방문 가입] 꼬리표는 검색 결과(바로 보기, 도서관에서 직접 찾기)에만 넣습니다. "책 먼저 고르기" 화면(책 줄 → 도서관별)과 추천도서 책 창의 대출 줄(최대 3곳)은 이번 사이클에서 손대지 않습니다.

왜: 친구분이 본 화면은 기본 보기(바로 보기)의 결과입니다. 책 먼저 고르기 화면은 책 한 권 아래 도서관이 나열되는 다른 모양이라 묶음 규칙을 따로 정해야 하고, 추천도서 책 창은 3곳만 보여 묶음이 의미가 없습니다.

제안: 승인. 두 화면은 백로그에 "꼬리표 넣기"로 두고, 이 사이클이 끝난 뒤 같은 꼬리표 부품을 그대로 옮겨 쓰면 됩니다.

다른 선택: 세 화면 모두 이번에 — 사이클이 커지고, 책 먼저 고르기 화면의 묶음 규칙을 새로 정해야 합니다.

실제 화면으로: "꼬리표"와 "묶음"이 무엇인가 (2026-10-18)

묶음 = 결과 목록을 나누는 큰 제목 줄입니다. 지금은 "지금 빌릴 수 있어요"와 "확인하지 못한 도서관" 두 제목뿐인데, 바뀐 뒤에는 "내 도서관에 있어요 / 누구나 가입 도서관에 있어요 / 확인하지 못한 도서관" 세 제목이 됩니다. 꼬리표 = 각 결과 줄의 도서관 이름 옆에 붙는 작은 알약 글자입니다(예: 내 지역 누구나 가입 방문 가입). 아래는 2026-10-18에 강남구를 고르고 "데미안"을 찾은 실제 결과를 바탕으로, 지금 모양과 바뀐 모양을 실제 크기로 그린 것입니다.

3스위치를 "전국"으로 두었을 때의 결과 묶음은 넷

4로그인한 사람의 첫 화면 줄도 같은 모양,
바꾸면 계정에 바로 저장

[안] 로그인한 사람에게도 첫 화면 지역 줄은 같은 모양이고, 값은 계정의 거주·직장 지역입니다. 거기서 지역을 바꾸면 지금 마이페이지에서 바꿀 때와 같이 계정에 바로 저장됩니다(서버 PUT /api/v1/me/regions, 사이클 06에 이미 있음).

예시: 로그인한 사람이 첫 화면에서 [일하는 곳도 더하기] → 경기 성남시를 고르면, 다른 기기에서 로그인해도 성남시가 들어 있습니다. 로그인 전 사람은 이 브라우저에만 남고, 저장 순간 안내 한 줄(개선안 8)이 뜹니다.

제안: 승인. 새 API 없이 지금 저장 길을 그대로 씁니다.

다른 선택: 로그인한 사람은 첫 화면에서 지역을 못 바꾸고 마이페이지로 보내기 — 첫 사용자에게만 쉬운 화면이 되고, 친구분이 지적한 "순서" 문제가 로그인 뒤에 다시 생깁니다.

5"누구나 가입 39곳"은 사이트 수로 셈

[안] 안내 줄과 접힌 줄의 "누구나 가입 39곳"은 지금 마이페이지와 같이 사이트 수입니다. 국립세종도서관(사이트 3개)·군산시립도서관(3개)처럼 한 도서관이 여러 사이트를 쓰면 각각 셉니다.

왜 묻나: 사람 눈에는 도서관 수(이름이 같은 것을 하나로)가 더 자연스럽지만, 결과 줄은 사이트마다 한 줄이고 마이페이지도 사이트 수로 "39곳"이라고 써 왔습니다. 두 곳의 수가 다르면 더 헷갈립니다.
