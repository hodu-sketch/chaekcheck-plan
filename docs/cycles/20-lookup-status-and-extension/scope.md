## 목표 (한 문장) [안]

조회가 몰려 503 `server_busy`가 나기 전에 사용자가 머리말에서 "지금 조회가 원활한지"를 보고, 원하면 크롬 확장을 설치해 도서관 조회를 자기 브라우저에서 직접 하게 하여 우리 서버의 조회 한도에 묶이지 않게 한다.

## 지금 상태 (dev 코드 확인, 2026-10-15)

- 대기열은 없음. 동시 검색 슬롯 `SearchSlots`(Semaphore, 기다리지 않음) `chaekcheck.availability.max-concurrent-searches: 20` [안], 꽉 차면 바로 503 `server_busy`, `Retry-After: 5`. 슬롯을 쓰는 곳: 검색 묶음·소장 묶음·도서관별 더 보기 (`backend/.../availability/internal/search/SearchSlots.java`, `BatchRunner.java:152,211`, `LibraryEbookController.java:80`)
- 호스트별 제한 `InMemoryHostThrottle`: 호스트마다 동시 1건·최소 간격 1초, 마감(8초)까지 기다렸다 시간 초과 → SSE `library-failed`
- 웹: 503이면 노란 안내 "지금 찾는 사람이 많아요. 잠시 뒤에 다시 해 주세요." (`web/src/features/search/blocked.ts`). 사전에 알려 주는 표시는 없음
- 남은 슬롯 수를 밖으로 내는 엔드포인트 없음(`SearchSlots.available()`은 테스트·로그용). Actuator·`/health` 없음(사이클 17이 Actuator 지표를 붙이기로 함)
- 도서관 요청은 모두 GET, 쿠키 없음, `User-Agent: chaekcheck/0.0.1`(사이클 17 ADR-0095로 일반 브라우저 값으로 바뀜). 일부 사이트는 `http://`, EUC-KR, 중간 인증서 빠짐
- 조회 서버 경유 모드(`fetch-service`, ADR-0011·0015): 조회 서버는 URL을 GET으로 받아 상태 코드와 원본 바이트만 돌려줌. 해석(adapter)은 본 서비스
- 우리 쪽 CORS 설정 없음(웹과 `/api`가 한 origin). 도서관 사이트의 CORS 헤더는 확인한 기록 없음

## 포함 [안]

### A. 조회 상태 신호 (머리말)

1. 머리말에 조회 상태 표시: **세 단계** 초록 / 노랑(동시 검색 자리 20개 중 10개 이상 사용) / 빨강(자리 모두 참 또는 최근 10초 안 503) [확정] (사용자: 다른 선택 ① 세 단계를 고름, 2026-10-15, 범위 결정 #2). 기준은 동시 검색 슬롯 사용량. **특정 도서관에 몰리는 경우**: 머리말이 아니라 그 도서관의 결과 줄에 표시. 서버가 상태 응답에 "지금 줄이 선 도서관" 목록(기다리는 요청이 있거나 최근 시간 초과가 난 호스트)을 주고, 화면은 그 도서관 줄 이름 옆에 "지금 이 도서관 조회가 밀려요" [확정] (사용자 승인, 2026-10-15, 범위 결정 #8). **호스트별 1건·1초 카운팅은 조회 서버(나가는 IP)마다 따로** [확정] (사용자: "조회 서버마다 1초 카운팅 다르게 하는거 잊지 마", 2026-10-15; ADR-0094·0095와 같음) → 줄이 선 판정도 나가는 길마다 셈. 판정 값(기다리는 수, 최근 몇 분)은 명세에서
2. 상태를 주는 API `GET /api/v1/availability/status` (자리 수·사용 중 수·단계, 줄이 선 도서관 목록). 캐시 가능, 도서관을 부르지 않음, nginx 도서관 호출 한도 밖 [확정] (사용자 승인, 2026-10-15, 범위 결정 #3; 주소 이름은 설계에서)
3. 웹이 검색 화면(첫 화면·검색 결과·책 화면)이 열려 있는 동안 **10초마다** 묻고, 검색 중 503을 받으면 바로 빨강. 탭이 보이지 않으면 묻지 않음 [확정] (사용자 승인, 2026-10-15, 범위 결정 #3). **SSE 대신 묻기를 고른 이유** (사용자: "자원 비교해서 이 서비스는 메모리 점유가 더 문제라고 판단했다", 2026-10-15): SSE는 보는 사람 수만큼 연결·메모리를 붙들고(nginx `worker_connections` 기본 512, 프록시 연결 포함), 묻기는 요청 뒤 서버에 남는 것이 없음 — 비교는 `research.md` 7절
3-1. ~~(화면 흐름 #4·#7로 뺌: 안내 줄·카드 글 없음, 대신 확인하지 못한 도서관 묶음)~~ 빨강(혼잡)일 때 결과 줄의 "도서관에서 보기" 링크(`detailUrl`, 없으면 도서관 검색 페이지)를 앞세우고 한 줄 안내("지금 찾는 사람이 많아요. 도서관 사이트에서 직접 확인할 수 있어요" [안] 문구) — 설치 없이 폰도 됨 [확정] (사용자 승인, 2026-10-15, 방법 비교 #4)

### B. 크롬 확장으로 사용자 브라우저에서 조회

4. 크롬 확장(Manifest V3) 설치 시 도서관 사이트 요청을 사용자의 브라우저가 보냄. 확장은 "사용자 쪽 조회 서버": 서버가 볼 주소를 주고, 확장이 원본 바이트(상태 코드 포함)를 올리면 서버 adapter가 해석(ADR-0015 조회 서버 약속과 같은 모양) [확정] (사용자 승인, 2026-10-15, 범위 결정 #5)
5. 확장이 있으면 우리 서버의 조회 슬롯을 쓰지 않음(묶음 계획·판정은 서버가 그대로) [확정] (사용자 승인, 2026-10-15, 범위 결정 #5)
5-1. 확장도 도서관 한 곳에 동시 1건·요청 사이 1초를 사용자 브라우저 안에서 지킴(사용자 IP 보호) [확정] (사용자 승인, 2026-10-15, 범위 결정 #7)
5-2. 확장의 사이트 권한은 모든 http·https 사이트(`http://*/*`, `https://*/*`); 책첵 주소에서 온 요청만 받음(`externally_connectable`) [확정] (사용자 승인, 2026-10-15, 범위 결정 #6). 나중에 웹스토어 심사 요청을 쓸 때 「Library Extension」 선례(`research.md` 3절 A)를 권한 사유에 씀 (사용자: "이걸 승인 요청 문서를 보낼 때 쓰면 될 것 같기도 하다", 2026-10-15)
6. **이 사이클은 확장을 동작하게 만드는 데까지**: 개발자 모드(압축 해제 확장 로드)로 설치해 확인. Chrome Web Store 등록·심사는 나중에 따로 [확정] (사용자: "크롬 확장은 돌아가게만 만들고 승인은 나중에 받을거야", 2026-10-15, 캔버스). 그때 배포는 Chrome Web Store, **크롬만 먼저** [확정] (사용자: "크롬만 먼저 하자.", 2026-10-15, 방법 비교 #1 미승인 → 엣지 동시 배포 안 함) (등록비 1회, 심사 며칠~몇 주)

## 외부 확인 (2026-10-15)

- 확장 안(service worker·확장 페이지)은 `host_permissions`가 있으면 다른 origin에 요청 가능. content script는 host_permissions가 있어도 CORS 적용 — https://developer.chrome.com/docs/extensions/develop/concepts/network-requests (확인 2026-10-15)
- 일반 웹 페이지 → 확장 메시지: 확장 manifest `externally_connectable`에 사이트를 적고 페이지가 `runtime.sendMessage(확장 ID, …)`; 확장 → 페이지 방향은 불가 — https://developer.chrome.com/docs/extensions/develop/concepts/messaging (확인 2026-10-15)
- `host_permissions` 패턴을 더하거나 바꾸면 설치·갱신 경고 — https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions (확인 2026-10-15)
- 웹스토어 심사 "대부분 며칠, 길면 몇 주", 넓은 host 권한은 심사가 길어질 수 있음 — https://developer.chrome.com/docs/webstore/review-process (확인 2026-10-15); 등록은 1회 등록비 — https://developer.chrome.com/docs/webstore/register (확인 2026-10-15, 금액은 페이지에 없음)

## 영향 받을 모듈 [안]

- `availability`: 상태 API, 확장 모드(받은 바이트를 해석하는 입구, 슬롯을 쓰지 않는 길)
- 웹(`web/`): 머리말 신호, 확장 감지와 메시지 주고받기
- 새 폴더 `extension/` (크롬 확장, dev 저장소 맨 위, 빌드 없음) [확정] (설계 결정 #11 사용자 승인 2026-10-16, ADR-0120)
