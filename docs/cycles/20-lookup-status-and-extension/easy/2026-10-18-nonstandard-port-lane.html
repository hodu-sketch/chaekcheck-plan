포트가 붙은 도서관 주소는 어느 길로 부를까 (2026-10-18)

dev 사이클 20 세션이 나가는 길(Webshare 한국 IP 20개)을 다 만들어 dev main에 넣었고(d5341a6), 실제 Webshare로도 확인했습니다. 그런데 주소에 비표준 포트가 붙은 도서관은 Webshare 길로는 열리지 않고 서버 자기 IP로만 열렸습니다. 이 도서관들을 어느 길로 부를지 정해 주세요.

1비표준 포트 도서관은 처음부터 직접 길만

Webshare가 비표준 포트를 막는다는 공식 문서는 찾지 못했습니다(Webshare 도움말 검색, 2026-10-18). 관찰값만 있어 [확인 필요]로 둡니다. 켜진 도서관 중 비표준 포트를 쓰는 곳이 몇 곳인지는 dev가 세어 알립니다.

[안] 주소 포트가 80·443이 아닌 도서관은 Webshare 길을 쓰지 않고 서버 자기 IP(직접 길)로만 부릅니다. 목록 없이 포트로 자동으로 가르고, 설정 하나로 끌 수 있게 합니다. 「프록시만」 설정일 때 이 도서관들은 「확인하지 못한 도서관」입니다.

다른 선택: (가) 지금대로 둠(막힌 길 규칙이 알아서 처리) / (나) 포트 대신 호스트 목록을 설정에 적어 관리.

물으신 것: 따로 어떻게 관리하나, DB에 두나

따로 관리하지 않습니다. 새 표·칸도 만들지 않습니다.

  • 도서관 주소는 이미 DB에 있습니다. 도서관마다 검색 주소(예: https://libebook.jejusi.go.kr:442/...)가 library 정보에 저장돼 있고, 서버가 도서관을 부를 때 이 주소를 씁니다.
  • 길을 고르는 순간 주소의 포트만 봅니다. 서버가 도서관을 부르려고 길을 고를 때 주소에 :442처럼 80·443이 아닌 포트가 있으면 Webshare 길을 빼고 서버 자기 IP로 보냅니다. 코드 한 곳의 규칙이라 도서관이 새로 들어오거나 주소가 바뀌어도 사람이 고칠 것이 없습니다.
  • 켜고 끄는 것만 설정 하나(운영 prod.env의 환경 변수, 이름은 dev가 정함)입니다. 나중에 Webshare가 이런 포트를 열면 이 설정만 끄면 됩니다. 설정 위치는 docs/settings-index.md에 적습니다.
  • 나중에 "포트는 표준인데 프록시로 안 열리는 사이트"가 생기면 그때 호스트 목록 설정을 따로 검토합니다(지금은 만들지 않음).

물으신 것: 코드 안에 도서관이 박혀 있게 되나

아닙니다. 코드에는 도서관 이름이나 번호가 하나도 들어가지 않습니다.

  • 코드에 들어가는 것은 일반 규칙 한 줄입니다: "부를 주소의 포트가 80·443이 아니면 Webshare 길을 고르지 않는다".
  • 어느 도서관이 해당하는지는 실행할 때 DB의 도서관 주소를 보고 그때그때 정해집니다. 제주시·의정부는 예시일 뿐 코드에 적히지 않습니다.
  • 예: 내일 새로 넣은 도서관 주소가 :8443이면 아무것도 고치지 않아도 직접 길로 갑니다. 반대로 제주시가 주소를 443으로 바꾸면 자동으로 Webshare 길도 씁니다.

물으신 것: 80·443이어도 프록시가 빠를 수 있지 않나

맞습니다. 그래서 80·443 도서관은 이 규칙에 걸리지 않고 지금처럼 Webshare 길 21개를 모두 씁니다.

  • 이 규칙이 바꾸는 것은 주소에 :442·:8088처럼 다른 포트가 붙은 도서관뿐입니다. 이 도서관들은 Webshare 길로는 느린 것이 아니라 아예 연결이 안 됩니다(5초 기다린 뒤 실패, dev 실측). 그래서 빠르기를 비교할 대상이 없습니다.
  • 80·443 도서관은 그대로 서버 자기 IP 1개 + Webshare 20개 중에서 고르고, 길·도서관마다 1건·1초로 여러 길이 나눠 맡습니다. 그 가운데 어느 길이 막히면 막힌 길 규칙(그 길만 10분부터 쉼)이 처리합니다.
