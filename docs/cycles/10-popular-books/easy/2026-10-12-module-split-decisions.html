인기 도서를 "모으기" 모듈과 "보여 주기" 모듈로 나눌 때 정할 것 4가지입니다.

정하신 것: 같은 서버 안에서 모듈만 둘로 (2026-10-12). 승인된 ADR-0073("popular 한 모듈")을 새 ADR로 바꾸고, 설계·인계서·현재 설계 문서를 고친 뒤 dev를 시작합니다.

1나눈 모양

모으기 모듈이 받기·예약·표 5개·표지를 맡고, 보여 주기 모듈이 공용 캐시와 API를 맡습니다. 보여 주기는 모으기의 "읽기용 창구"로만 데이터를 읽고, 새 달을 저장하면 모으기가 알림을 보냅니다.

실선은 "부른다", 점선은 "알린다(이벤트)". 보여 주기는 모으기의 표를 직접 읽지 않습니다.

2정할 것

1모듈 이름: 모으기 popularfetch, 보여 주기 popular [안]

예: 패키지 com.chaekcheck.popularfetch와 com.chaekcheck.popular. Java 패키지 이름에는 붙임표(-)를 쓸 수 없어 붙여 씁니다. 화면용 API 주소(/api/v1/popular-books)는 그대로입니다.

다른 선택 popularcollect·bestseller 등: 원하시는 이름이 있으면 "기타"에 적어 주세요.

추천: popularfetch + popular.

2표 5개는 모으기가 가지고, DB 칸 묶음(스키마) 이름은 popular 그대로 [안]

예: fetch_run·ranking_month·ranking_category·ranking_entry·cover는 popularfetch만 쓰고 읽습니다. 스키마 이름까지 바꾸면 이미 정한 표 이름 규칙과 설계 문서를 더 많이 고쳐야 합니다.

다른 선택 스키마도 popularfetch로: 모듈 = 스키마로 맞춰지지만 이름이 길어집니다.

추천: 스키마 popular 그대로.

3잇는 방법: 보여 주기는 모으기의 읽기 창구(공개 Java API)로 읽고, 모으기는 새 달·표지 저장이 끝나면 알림(이벤트)을 보냄 [안]

예: 모으기에 공개 인터페이스 PopularRankings [안 이름] — "최근 달 순위 한 벌 주기", "표지 그림 주기". 새 달을 저장하거나 표지 받기가 끝나면 PopularRankingsUpdated [안 이름] 이벤트를 보내고, 보여 주기가 받아 공용 캐시를 바로 새로 고칩니다. 10분마다 새로 고치는 것은 그대로입니다(책 목록 가져오기 반영용).

다른 선택 알림 없이 10분마다만: 새 달이 최대 10분 늦게 보이지만 이벤트가 필요 없습니다.

추천: 읽기 창구 + 알림. 같은 서버 안의 알림이라 지금 서비스의 이벤트 방식(AccountDeleted와 같은 꼴)을 그대로 씁니다.

4ADR-0078 "인기 도서는 모으기·보여 주기 두 모듈로" 를 쓰고 ADR-0073을 대체로 표시 [안]

예: ADR-0073의 상태를 "Superseded by 0078"로 바꾸고, 새 ADR에 위 1~3과 의존 방향(popular → popularfetch·catalog·library, popularfetch는 다른 모듈에 기대지 않음)을 적습니다. 이유는 "같은 서버 안에서 모듈만 둘로"(2026-10-12)를 옮기고, 까닭은 [이유 미확인]으로 둡니다.

추천: 씀(승인 = Accepted로 기록). 승인되면 설계·인계서·현재 설계 문서를 고쳐 커밋하고, 그다음 dev를 시작하시면 됩니다.
