3같은 날 사이클 밖에서 고친 것

plan이 요청한 검색 설정 창의 ⓧ는 끝났고, dev가 폰 로그인 창까지 같이 바꿨습니다.
  • 폰의 아래 창 여섯(검색 설정, 로그인, 인기 도서 넷)이 모두 같은 방식으로 닫힘: 손잡이 끌어내리기, ⓧ, 바깥 누르기, 뒤로 가기(창만 닫힘). 폰 로그인 창의 [닫기] 글자 버튼은 ⓧ와 겹쳐서 뺐습니다.
  • 폰 상세검색에서 "완전 일치"가 칸 밖으로 나가던 것을 고침(삼성 인터넷에서만 보였음)
  • 앱 전체 아이콘: 글자 아이콘(▾ ✓ × ☰)을 그림으로 바꾸고, ⓧ 자리를 맞추고, 폰에서 누르는 자리를 44px로 넓힘

4정할 것

셋 다 이번 디자인에서 나온 것이 앞으로 다른 화면에도 영향을 주는지에 대한 질문입니다.

[안] 옅은 그림자가 있는 둥근 카드는 인기 도서 화면에서만 씁니다

2026-09-27에 정한 화면 취향은 "평평한 카드, 그림자 없음"입니다(dev global.css 주석). 인기 도서 화면만 이 취향의 예외로 두고, 검색 결과·책 화면·내 도서관은 지금처럼 평평한 카드로 둡니다.

다른 선택: 앱 전체 카드를 인기 도서와 같은 둥근 카드로 맞춥니다. 화면 모양이 하나로 통일되지만, 다른 화면 여러 곳을 다시 손봐야 해서 사이클 하나가 필요합니다.

추천: 인기 도서 화면에서만. 앱 전체로 바꾸고 싶어지면 그때 백로그에서 꺼냅니다.

[안] "터치 화면은 pointer: coarse 하나로 판정"을 dev의 화면 규칙에 적어 달라고 요청합니다

삼성 인터넷은 폰인데도 "마우스를 올릴 수 있다"(hover: hover)고 답했습니다. 그래서 처음 만든 판정으로는 폰에서 "한 번 밀면 한 분류"가 꺼져 있었습니다. 다음에 다른 화면에서 터치 동작을 만들 때 같은 실수를 하지 않도록, dev가 늘 읽는 화면 규칙 파일에 한 줄 넣어 달라고 합니다. plan은 요청 글을 만들어 드립니다.

다른 선택: 회고에만 남깁니다. 다음 dev 세션이 회고를 읽지 않으면 같은 실수를 다시 할 수 있습니다.

추천: dev 규칙에 넣기.

[안] 폰 화면이 바뀌는 사이클의 인계서 확인 목록에 "실제 폰(삼성 인터넷)으로 확인"을 넣습니다

이번에 상세검색 칸 넘침은 크롬의 폰 흉내로는 보이지 않고 실제 삼성 인터넷에서만 보였습니다. 터치 판정 문제도 실제 폰에서야 드러났습니다. 앞으로 화면을 바꾸는 사이클은 끝내기 전에 사용자 폰으로 한 번 확인하는 줄을 확인 목록에 넣습니다. 방법은 dev의 web-lan-5174(같은 와이파이에서 폰으로 여는 웹 서버)입니다.

다른 선택: 사이클마다 그때 정합니다. 빠뜨리면 이번처럼 끝난 뒤에 고치게 됩니다.

추천: 확인 목록에 넣기. 사이클 11은 화면이 거의 바뀌지 않아 해당이 없습니다.

5남은 확인과 알려 드릴 것

  • 공용 캐시 메모리는 재 두었습니다: 한 벌 약 0.4MB. 새로 고침 한 번에 걸리는 시간은 아직 안 쟀고, 배포 사이클의 메모리 다시 재기 때 함께 잽니다(백로그).
  • "받기를 켠 채 다시 켜면 요청 0건"은 이번에도 단위 테스트로만 확인했습니다.
  • 사이클 11 인계서의 "사이클 10 디자인 다듬기가 아직 진행 중"을 "끝남"으로 고쳤습니다. 작업 폴더에 다른 세션의 수정 파일이 남아 있으면 시작할 때 사용자에게 묻도록 적었습니다.
  • dev 백엔드(8080)와 폰 확인용 웹 서버(5174)는 plan에서 쓰지 않습니다. 끌지는 dev 세션에 직접 말씀해 주세요.
