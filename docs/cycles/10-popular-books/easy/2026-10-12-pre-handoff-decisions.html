사이클 10을 인계하기 전에 설계 검토에서 나온 것 가운데 정할 것 8가지입니다.

설계 검토 에이전트가 문서를 읽고 고칠 곳을 짚었습니다. 옛 숫자(21분류, 1,050권), 남아 있던 "고정 자리", 상태 줄 같은 것은 이미 고쳤습니다. 여기에는 정하셔야 하는 것만 있습니다. 앞의 네 개는 설계, 뒤의 네 개는 사이클 09와 따로 병렬로 개발하는 방법입니다.

1설계에서 고칠 것

받기 기록을 쓰는 순서가 표 규칙과 맞지 않는 곳 하나, 분류 빼기를 기록할 ADR 하나, 검수 기준(AC) 추가, 가운데 창의 빠진 상태를 정합니다.

1받기 기록은 순위를 저장하는 같은 순간에 "성공"으로 완성하고, 표지 수 두 칸만 나중에 채움 [안]

문제: 지금 설계는 순위(달·분류·책)를 먼저 넣고, 표지 받기(약 28분)가 끝난 뒤에 받기 기록을 넣습니다. 그런데 "달" 표는 받기 기록 번호가 꼭 있어야 해서 이 순서로는 저장이 안 됩니다.

예: 3일 05:01에 순위 17개를 다 받으면, 한 번에 받기 기록(성공, 끝난 시각 05:01)과 순위를 함께 저장합니다. 이어서 표지를 받고, 05:29에 그 기록의 "새로 받은 표지 수·실패 수"만 채웁니다. 표지 받는 중에 서버가 꺼져도 순위는 이미 저장돼 있습니다.

다른 선택 받기 기록을 맨 먼저 "진행 중"으로 넣고 끝날 때 고치기: 진행 중 상태와 "끝난 시각 비어 있음"을 더해야 하고, 꺼졌을 때 진행 중으로 남는 줄을 치울 규칙이 필요합니다.

추천: 순위와 함께 완성.

2ADR-0077 "인기 도서는 전자책이 거의 없는 다섯 분류를 받지 않음" 새로 씀 [안]

예: ADR-0072에는 "21분류 + 전체를 받는다"로 남아 있습니다. 승인된 ADR은 고치지 않는 규칙이라, 새 ADR이 이를 "16분류 + 전체"로 바꾼다고 적습니다. 같은 ADR에 바뀐 숫자(한 달 요청 35건 이하, 표지 첫 달 최대 850장·약 28분, 두 달 약 90MB, ISBN 최대 850개)도 적어 ADR-0074·0075의 옛 숫자를 바로잡습니다.

  • 결정: 만화·어린이·청소년·기타·의학·스포츠는 받지도 보이지도 않음. "전체" 목록에는 섞여 나옴. 고정 자리 없음
  • 이유: 9월 기준 ISBN으로 맞춘 책이 0~3권. 사용자가 만화·어린이·청소년을 빼자고 제안("'만화'랑 '어린이 청소년' 카테고리는 너무 없어서 그냥 제외하는게 어떨가 하는데"), 나머지 셋은 제안 → 승인
  • 번호: 다른 세션이 0076까지 씀. 사이클 11도 ADR을 쓸 수 있어 쓰기 직전에 번호를 다시 확인

추천: 씀(승인 = 이 초안대로 Accepted로 기록).

3검수 기준(AC)에 빠진 것 추가 [안]

dev가 "다 됐다"를 확인하는 목록에 아래가 없어서 더합니다.

  • 머리에 "인기 도서" 링크가 있고(약관·개인정보 화면 제외), "전자도서관 대출 가능 확인" 설명 글이 없다
  • 로그인하지 않아도 인기 도서를 볼 수 있다
  • 순위를 받은 뒤 그달 새 표지를 받아 저장하고, 몇 장이 실패해도 순위는 성공이며 그 책은 제목 글자로 보인다. 지운 표지를 부르면 "없음"(404)
  • 폰 아래 창 네 개는 손잡이 끌어내리기·ⓧ·바깥으로 닫히고, 폰 뒤로 가기는 창만 닫는다. PC는 Esc로도 닫힌다
  • 폰·태블릿에서 3×3을 좌우로 밀면 넘어간다
  • 책 화면에 갔다가 뒤로 오면 보던 분류·쪽·스크롤 자리다

추천: 추가.

4가운데 창: 책 정보를 못 불러오면 책 화면과 같은 오류 문구, 표지는 격자에서 쓰던 표지 [안]

예: 가운데 창을 열 때 서버가 응답하지 않으면 창 안에 책 화면이 쓰는 오류 문구가 보입니다(빠진 책은 이미 정한 "책을 찾을 수 없어요"). 창의 표지는 격자에서 누른 그 표지(우리 서버가 넘겨주는 출처 표지)를 그대로 써서 두 화면의 그림이 같습니다.

다른 선택 창 표지를 우리 전자책 표지로: 격자와 창의 그림이 다를 수 있습니다.

추천: 위대로.

2사이클 09와 병렬로 개발하는 방법

dev는 사이클 10 전용 작업 폴더(worktree)와 가지(branch)에서 개발하고, 인계서·기록·DB·포트를 09와 나눕니다. 합치는 순서는 09 먼저입니다.

dev 사이클 08은 이미 커밋돼 있어(2026-10-11 dev 기록 확인) 두 가지 모두 08 코드 위에서 시작합니다.

5인계 문서를 따로: plan은 docs/cycles/10-popular-books/handoff.md만, dev 기록은 docs/plan-feedback-cycle10.md [안]

예: dev가 자동으로 읽는 docs/current/handoff.md는 사이클 09 그대로 둡니다. 사이클 10 dev 세션은 시작할 때 "사이클 10 인계서 파일을 따르고, 자동으로 불러온 09 인계서는 따르지 않음"으로 시작합니다(dev 설명서는 고치지 않음). 다른 점과 이유는 plan-feedback.md가 아닌 새 파일 docs/plan-feedback-cycle10.md에 적어 09 기록과 겹치지 않게 합니다.

다른 선택 dev 기록을 plan-feedback.md의 새 절로: 두 가지에서 같은 파일 끝에 덧붙여 합칠 때 겹칩니다.

추천: 따로 (말씀하신 "겹치지 않게 따로").

6로컬 DB와 포트를 09와 나누고, 개발·시험 중에는 사이트에서 받기를 꺼 둠 [안]

예: 사이클 10 작업 폴더는 다른 DB 이름(또는 다른 DB 컨테이너)과 다른 서버·웹 포트를 씁니다. 같은 DB를 쓰면 09의 도서관 표 변경과 10의 새 표가 한 DB에 섞여 서로의 시험을 흔듭니다. 출판유통통합전산망 받기는 기본으로 꺼 두고(chaekcheck.popular.fetch.enabled=false), 받기를 시험할 때만 켭니다. 서버를 켤 때마다 사이트를 부르지 않게 하려는 것입니다.

추천: 나눔.

질문: DB와 포트는 지금 어디서 돌고 있나

DB는 이 PC의 WSL(Ubuntu) 안 Docker에서, 서버는 Spring Boot 8080, 화면 개발 서버는 Vite가 돌립니다. dev 파일을 읽어 확인했습니다(2026-10-12).

무엇지금근거
개발용 DBDocker 묶음 chaekcheck의 db 컨테이너(PostgreSQL 18 + pg_bigm), 포트 5432, DB 이름은 .env의 DB_NAME. 데이터는 볼륨 db-data에 남음dev compose.yaml 10~43행, .env.example
시험용 DB같은 묶음의 db-test 컨테이너, 포트 5433, 메모리에만 저장(./gradlew test가 씀)compose.yaml 45~62행
서버(Spring Boot)8080(따로 정하지 않아 기본값). .env를 읽어 localhost:5432의 DB에 붙음application.yml 6·8행, vite.config.ts 6행 주석
화면 개발 서버(Vite)포트를 따로 적지 않아 Vite 기본값(5173으로 앎, 설정 파일에는 없음). /api 요청을 8080으로 넘김(API_PROXY_TARGET로 바꿀 수 있음)vite.config.ts 7·12~15행

주의: Docker 묶음 이름이 chaekcheck로 고정돼 있어, 10 worktree에서 docker compose up을 하면 새 컨테이너가 아니라 같은 컨테이너를 씁니다. 그래서 컨테이너를 새로 만들기보다 같은 컨테이너 안에 10용 DB 이름을 하나 더 두는 것이 가장 간단합니다. 시험용 DB도 두 쪽이 동시에 시험을 돌리면 서로 지우므로 이름을 나눕니다. 포트 번호(예: 서버 8081, 화면 5174)는 dev가 정하게 둡니다.

6번 제안은 이 방식(같은 컨테이너, DB 이름만 따로, 서버·화면 포트 따로, 받기 기본 꺼짐)을 뜻합니다.

질문: chaekcheck.popular.fetch.enabled=false는 무엇이고 어느 서비스와 관련 있나

우리 서버(Spring Boot) 설정 파일에 새로 둘 켜고 끄는 스위치 하나입니다. "출판유통통합전산망에서 순위를 받아 올지"를 정합니다.

어디서스위치까닭
운영 서버켜짐 (기본값)매달 3일에 순위를 받아야 함
개발 중 내 PC (10 worktree)꺼짐개발하며 서버를 자주 껐다 켜는데, 순위가 비어 있으면 켤 때마다 사이트에 요청 35건 + 표지 수백 건을 보냄. 공공기관 사이트에 불필요한 요청을 막음
자동 시험(./gradlew test)꺼짐시험이 바깥 사이트에 기대지 않게. 받기 시험은 미리 저장한 응답으로
가져오기 프로그램(collection-import)꺼짐같은 서버 코드로 따로 뜨는 프로그램이라, 켜져 있으면 가져올 때마다 사이트를 부름

이름은 지금 서비스 설정 이름 방식(chaekcheck.availability.max-concurrent-searches 같은 꼴)을 따른 것이고, 설계 결정 #12에서 승인하셨습니다. 받기 자체를 시험할 때만 개발자가 잠깐 켭니다.
