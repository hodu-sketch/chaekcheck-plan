인기 도서 설계 문서(design-delta)를 한 장으로 보여 드리고, 남은 작은 값 다섯 가지를 여쭙니다.

큰 결정은 앞 페이지와 ADR-0072~0075에서 끝났습니다. 이 문서는 그 결정을 개발자가 만들 모양(모듈, 표, API, 흐름)으로 옮긴 것입니다. 그림이 모두 들어간 원본은 easy/design-delta-original.html에 따로 있습니다.

1무엇을 만드나

서버에 새 모듈 하나, 책 검색 모듈에 함수 하나, 웹에 새 화면 하나와 머리 링크를 만듭니다. 도서관 대출 조회는 지금 것을 그대로 씁니다.
어디만드는 것
새 모듈 popular매일 05:00과 켜질 때 받을지 따짐 → 순위·판매 부수 45건 + 새 표지 받기 → 우리 DB 저장 → 공용 캐시 → 화면용 API 두 개(인기 도서 목록, 표지 그림)
책 검색 모듈 catalog"ISBN으로 책 찾기" 하나 (ISBN → 우리 책 번호와 그 책을 가진 도서관 목록)
웹/popular 화면(3×3, 세모, 분류 목록, ⓘ), 가운데 창(지금 책 화면 API 재사용), 신청 안내 창, 머리 "인기 도서" 링크, 설명 글 지움
바꾸지 않는 것대출 조회, 책 화면, 도서관, 보안 설정(CSP), 새 이벤트 없음

2무엇을 저장하나

표 다섯 개입니다. 순위는 달마다 쌓이고, 표지는 최근 두 달 것만 남습니다.

점선은 표끼리 묶지 않고 값(그림 경로, ISBN)으로만 잇는 곳입니다. 노란 칸 "표지"가 이번 결정(서버가 넘겨주기)으로 생긴 표입니다.

3남은 작은 값

개발자가 그대로 써도 되는 제안입니다. 바꾸고 싶은 것만 "기타"에 적어 주세요.

1사이트 연결 시간 제한: 연결 5초, 응답 읽기 10초 [안]

예: 사이트가 10초 넘게 답하지 않으면 그 요청은 실패로 보고 그달 받기를 실패로 기록합니다(다음 날 다시). 개발 때 실제 걸리는 시간을 보고 바꿀 수 있습니다.

추천: 5초·10초.

2표지 표와 받기 기록에 더하는 칸 이름: cover(id, source_path, content_type, image, byte_size, fetched_at), fetch_run의 cover_fetched_count·cover_failed_count [안]

예: 받기 기록에 "이번에 새로 받은 표지 312장, 실패 3장"이 남습니다. 앞서 승인하신 이름 짓기 방식과 같습니다.

추천: 위 이름.

3표지 그림 응답은 브라우저가 30일 저장, 없는 표지는 "없음"(404 cover_not_found) [안]

예: 한 번 본 표지는 30일 동안 다시 받지 않아 화면이 빠릅니다. 같은 번호의 그림은 바뀌지 않으므로 안전합니다. 두 달이 지나 지운 표지를 누가 부르면 "없음"이 가고 화면은 제목 글자를 보입니다.

추천: 30일, 404.

4코드 안쪽 위치와 파일 이름(패키지 나눔, Liquibase 파일 경로, 화면 컴포넌트 이름)은 dev가 정함 [안]

예: internal/fetch, db/changelog/popular/001-popular-schema.yaml, PopularPage는 제안일 뿐이고, dev가 지금 코드 관례에 맞춰 바꿔도 됩니다. 화면에는 보이지 않습니다.

추천: dev에 맡김.

5이 설계대로 마무리 단계(cycle-close: 검토, 현재 설계 문서 반영, 인계서)로 감 [안]

예: 설계 검토 에이전트가 빠진 곳을 살피고, docs/current/에 반영할 내용과 dev에 넘길 인계서를 만듭니다. 다만 지금은 사이클 08 개발이 진행 중이고 09가 먼저라, 인계서는 "09 다음"으로 표시하고 docs/current/handoff.md(dev가 읽는 파일)는 바꾸지 않는 것을 제안합니다.

다른 선택 여기서 멈추고 사이클 08 개발이 끝난 뒤 마무리: 앞 사이클 회고(retro)를 먼저 할 수 있지만 그만큼 늦어집니다.

추천: 마무리까지 하되 dev가 읽는 인계 파일은 그대로.
