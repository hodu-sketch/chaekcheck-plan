사이클 18 인계서:
dev가 할 일을 세 묶음으로 나눴습니다

인계서를 만들면서 dev 코드를 다시 읽었고, 설계 문서에 없던 것 몇 가지가 나왔습니다. 인계서에서 새로 정한 것 5가지와 "이대로 넘김" 하나를 확인해 주세요. 이름(클래스·파일 번호 등)은 앞서 정한 대로 dev가 바꿀 수 있습니다. (2026-10-14)

2인계서에서 새로 정한 것

1조회 서버 방식에서는 밑줄 주소 길을 만들지 않음 (오류만 막음)

[안] dev 코드에는 대출 조회를 별도 "조회 서버"(fetch-service)로 보내는 방식도 있습니다. 설계 문서는 이 방식을 다루지 않았습니다. 사이클 17은 첫 배포에서 조회 서버를 꺼 두고 본 서비스가 직접 조회합니다. 그래서 밑줄 주소 길은 직접 조회 방식에만 넣고, 조회 서버 방식에서는 현대제철 줄만 실패하도록(오류로 멈추지 않게) 합니다.

다른 선택: 조회 서버에도 같은 길을 넣음 → 별도 앱 하나를 더 고치고 시험해야 하는데, 지금은 쓰지 않는 방식입니다.

추천: 직접 조회에만.

반영: 조회 서버도 같이 → 그렇게 적었습니다

사용자 말 "같이 해 굳이 왜 나눠서 해 조회 서버도 같이 해"대로, 조회 서버 앱에도 같은 밑줄 주소 길을 넣도록 인계서(A2의 7번)와 설계 문서에 적었습니다.

  • 조회 서버의 주소 검사(UrlGuard)는 지금 밑줄 주소를 거절합니다. 밑줄 주소도 받게 하되, 이 검사가 하는 "내부망 주소로는 요청하지 않기" 보호는 그대로 둡니다
  • 요청 라이브러리는 본 서비스와 같은 것을 씁니다(조건 넷 그대로)
  • 조회 서버는 첫 배포에서 꺼 두므로, 실제 확인은 내 PC에서 조회 서버를 켜고 한 번 해 봅니다(사용자 승인 뒤)

2"전자책 0권" 검사를 규칙 파일 검사보다 앞에 둘지는 dev가 정하고 보고

[안] 넣기 명령은 새 도서관에 "최종 주소 파일 줄"·"도서관 종류 줄"이 없으면 규칙 오류로 멈춥니다. "전자책 0권" 검사를 그 앞에 두면, 책이 없는 곳 때문에 규칙 파일을 채우느라 멈추는 일이 없어집니다. 어느 쪽이 코드에 맞는지는 dev가 보고 정해 알려 주게 합니다.

다른 선택: 지금 "앞에"로 정함 → 코드 구조를 보지 않고 정하게 됩니다.

추천: dev가 정하고 보고.

3"켜진 0권 도서관 0곳" 확인 SQL

[안] 명세는 "사이클 12 분포 검사와 같은 SQL"이라고만 적었습니다. 그 SQL이 dev 쪽 분석 폴더(git 밖)에 남아 있으면 그것을, 없으면 "켜져 있고 소장 줄이 하나도 없는 도서관"을 세는 한 줄 SQL을 씁니다.

추천: 이대로.

422곳 밖에서 0권 도서관이 새로 나오면 dev가 끄지 않고 멈춰서 알림

[안] 사이클 13으로 새로 들어온 6곳 등이 나중에 0권으로 나올 수 있습니다. 그런 곳은 dev가 스스로 끄지 않고 멈추고 보고합니다. 끄는 결정은 사용자가 합니다.

다른 선택: 같은 규칙(오디오북 전용 등)이면 dev가 끔 → 빠르지만 사용자가 모르는 사이 도서관이 빠집니다.

추천: 멈추고 보고.

질문: "끈다"는 게 무엇인가요?

도서관 표에서 그 도서관의 "켜짐" 칸을 꺼짐으로 바꾸는 것입니다. 도서관을 지우는 것이 아니라 서비스에 안 보이게 하는 것이고, 다시 켤 수 있습니다.

꺼진 도서관은어떻게 되나
도서관 고르기 목록 ("내 도서관 관리", 검색 범위)나오지 않음
책 검색 결과그 도서관 줄이 나오지 않음 (이번 22곳은 원래 책이 0권이라 달라지는 것 없음)
이미 "내 도서관"에 넣어 둔 사람"쓸 수 없는 도서관"으로 보이고, 지울 수 있음
도서관 정보(이름·주소 등)DB에 그대로 남음. 지우지 않음
다시 켜기DB 변경 파일 하나로 다시 켬 (교보 구독형 4곳은 나중에 책이 생기면 그렇게 함)

지금도 이렇게 꺼 둔 도서관이 있습니다(사이클 07에서 끈 135 전라북도교육청통합도서관 등 5곳). 이번 22곳도 같은 방식입니다.

그래서 4번은 "22곳 말고 0권 도서관이 새로 보이면, dev가 그 도서관을 꺼짐으로 바꾸지 않고 사용자에게 먼저 알린다"는 뜻입니다.

5A1·A2는 각각 main에 합치고, B는 19 뒤 새 브랜치에서

[안] 묶음마다 때가 달라서, 끝나는 대로 따로 합치게 합니다. 작업 폴더는 다른 사이클처럼 따로(git worktree, docker 프로젝트 이름 따로) 두고, 원래 서비스 DB는 읽기만 합니다.

다른 선택: 셋을 한 브랜치에서 모아 한 번에 → 19를 기다리는 동안 A1·A2가 묶여 있습니다.

추천: 따로 합침.
