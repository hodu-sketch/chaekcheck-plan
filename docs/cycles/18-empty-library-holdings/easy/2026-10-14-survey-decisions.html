2오디오북만 있는 곳과 빈 곳

범위를 정할 때 승인한 규칙("오디오북 전용이면 끄고 이유를 적음")을 그대로 대는 안입니다.

1오디오북만 있는 14곳과 느티나무도서관을 끔

[안] 위 표의 15곳을 서비스에서 끄고, dev library-site-issues.md에 사이트 첫 화면의 분류 메뉴(원문)와 함께 "오디오북 전용" 또는 "책 0종"으로 적습니다. 범위 결정에서 끄기로 한 국회·김천·군포 3곳을 더하면 이 사이클에서 끄는 도서관은 18곳입니다.

다른 선택: 켜 두고 기록만 → 이용자가 골라도 책이 계속 안 나옵니다. / 오디오북도 가져오기 → 우리는 오디오북을 다루지 않기로 했으므로(가져오기에서 뺌) 서비스 전체 규칙이 바뀝니다.

추천: 끔.

2다시 생기지 않게: 새 도서관을 넣을 때 전자책이 0권인 곳은 넣지 않음

[안] 이 15곳은 사이클 07에서 수집으로 찾은 도서관을 넣을 때 "수집 성공"만 보고 들어왔습니다. 앞으로 새 도서관 넣기 명령(사이클 13에서 만든 것)이 미리 보기 보고서를 만들 때, 모은 책이 모두 오디오북이거나 0권인 곳은 "넣지 않음"으로 빼게 합니다. 예: 다음에 오디오북만 있는 학교 사이트를 찾으면 보고서에 "전자책 0권으로 뺌"으로 나오고 서비스에는 안 들어갑니다.

다른 선택: 이번에는 끄기만 하고 넣기 규칙은 backlog → 이번 사이클이 작아지지만, 다음 넣기 때 같은 일이 생길 수 있습니다.

추천: 이번에 포함. 넣기 명령에 거름 하나를 더하는 일입니다.

3현대제철: 우리 쪽 문제

사이트 주소에 밑줄(_)이 들어 있어, 우리 가져오기 코드가 책 주소를 "읽을 수 없는 주소"로 보고 241권을 모두 건너뛰었습니다.

우리 가져오기는 Java의 주소 읽기 기능을 씁니다. 이 기능은 호스트 이름에 영문·숫자·-만 받고, 밑줄이 있으면 호스트가 없는 주소로 봅니다.

근거: Java 21 java.net.URI 공식 문서, getHost() 절 "Each label consists of alphanum characters as well as hyphen characters", https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/net/URI.html (확인 2026-10-14). 우리 코드 dev CollectedCatalog.httpHostOf

3가져오기 코드를 고쳐 현대제철 241권을 넣음

[안] 가져오기가 밑줄이 있는 호스트도 읽게 고치고, 다음 가져오기 때 현대제철 책이 들어가게 합니다. 수집은 다시 하지 않아도 됩니다(이미 모아 둠). 서비스의 대출 조회와 "도서관에서 직접 찾기"도 이 주소에서 같은 문제가 있는지는 설계 때 코드로 확인합니다(확인 못 함).

다른 선택: 현대제철도 끔 → 코드 변경이 없지만, 책이 있는 도서관을 우리 문제로 빼게 됩니다.

추천: 고침.
