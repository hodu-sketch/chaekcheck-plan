## 지금 코드에서 알게 된 것

- ④는 세 방식 모두 `BookGrouper.key(titleNorm(title), firstAuthor, publisherNorm)` — 전체 제목. ISBN은 안 보고, 합치면 ISBN 하나만 남김
- `BookGrouper.key`·`firstAuthor`는 ③(국가서지, `NationalBibliography` 188~191행)과 공유 → ④만 바꾸려면 이 둘은 그대로 두고 ④ 전용 키를 새로 만듦
- ②·③ 뒤에는 같은 ISBN 묶음이 하나뿐 → ④ 버킷 안에서 ISBN으로 나누기가 쉬움
- 저자·출판사 "."는 지금도 정리 뒤 빈 값이라 ④ 키가 없음 → 새로 막을 것은 "기타"·"unknown"(저자·출판사)과 "미상"(출판사)
- spec R7-2(이어 씀·새·사라짐 수)는 **이미 기록됨**: `collection.catalog_import`의 `kept_book_id_count`·`new_book_id_count`·`dropped_book_id_count`·`book_count`, 따로 하기 경로도 `ImportTransfer`가 옮김
- 비교 도구 `DryRunDump`, `scripts/catalog/compare_grouping.py`(`dryrun`·`ids`·`ids-compare`)는 두 방식 같음 비교(R8-2)에 그대로 씀. 합쳐짐·나뉨 목록 뽑기 기능은 없음

## 결정 1: 새 ④ 규칙을 어디에 두나

- A안: `catalog.normalize`(공개)에 — 검색이 안 쓰는 묶기 전용 규칙이 공개 API로 늘고, ADR-0069 "검색 규칙 바뀜 → 재시작"과 헷갈림
- **B안 (추천) [안]**: `collection.internal.importer` 안 패키지 내부 클래스 `SameTextKey` + `BookGrouper.sameTextKey(title, authorRaw, publisherRaw)`. `compact`·`sql`이 같은 Java 함수를 부름. 키 = 본제목 + 권 표시 + 첫 저자 + 출판사, 하나라도 없으면 합치지 않음. 목록은 코드 상수

## 결정 2: 판이 다른 책(R1·R1-3)을 어떻게 나누나

- **A안 (추천) [안]**: 같은 키로 모은 뒤(버킷) 버킷 안 ISBN 수를 보고 나눔 — 0~1개면 모두 한 책, 2개 이상이면 ISBN 있는 묶음은 각자 한 책, ISBN 없는 묶음은 어느 판에도 붙이지 않음(R1-3). 순서와 상관없음. `sql`은 집계 쿼리 하나 추가
- B안: 합칠 때 두 쪽 ISBN이 다르면 건너뜀 — 처리 순서에 따라 ISBN 없는 책이 먼저 만난 판에 붙어 **R1-3([확정])을 어김**

## 결정 3: 이용 안내 꼬리(R3-3)를 비교 제목에서도 뗄까

- 지금 본제목(`mainTitleNorm`)은 뒤 괄호를 남김 → spec 문구대로면 「제목(PC만 열람 가능)」과 「제목」은 계속 따로
- A안: 꼬리 목록은 권 표시에서만 뗌 (spec 문구 그대로)
- **B안 (추천) [안]**: 목록에 든 꼬리만 비교 제목 끝에서도 뗌 (spec R3-1 문구를 넓힘)
- C안: 뒤 괄호를 모두 뗌 — "(영문판)" 같은 다른 판이 합쳐짐

## 결정 4: 비교 도구

- 4-1 "새로 넣은 도서관을 뺀" dry run: **A안 (추천) [안]** dry run에서만 켜는 설정(수집 번호 100001 이상 = 사이클 07 도서관을 뺌, 진짜 가져오기에서 켜면 시작 안 함) / B안 수집 사본을 복사해 줄을 지우는 스크립트(수 GB 복사)
- 4-2 합쳐짐·나뉨 목록: **A안 (추천) [안]** `compare_grouping.py regroup <A> <B>` — (도서관, 책 코드)로 맞대어 "여러 책 → 한 책"(합쳐짐)과 "한 책 → 여러 책"(나뉨)을 목록으로. R5(뺀 것 vs 넣은 것)와 R7-3(지금 서비스 DB vs 새 규칙)에 같이 씀 / B안 DB에 넣어 SQL로 비교

## 결정 5: `current`를 지운 뒤 "출판일 2년 차이" 표본 순서

- **A안 (추천) [안]**: 표본 순서를 "합친 책의 첫 묶음 순"으로 단순화하고 `current` 흉내 코드를 지움 / B안: 흉내 유지(해시 두 벌)

## 꼬리 목록(R3-3)을 데이터로 정하는 절차 [안]
