# 사이클 순서와 상태 (먼저 읽을 것)

사이클 번호는 **plan을 시작한 차례**이고, dev가 만드는 차례와 다릅니다. 여러 사이클을 미리 계획해 두고 dev가 병렬이나 다른 순서로 만들었기 때문입니다. 다른 AI 세션은 사이클 문서를 읽기 전에 이 표로 지금 무엇이 어디까지 왔는지 먼저 확인합니다. 사이클을 시작·인계·회고하거나 순서를 바꾸면 이 파일을 같이 고칩니다 (사용자: "문서에 이렇게 순서 뒤틀린 것도 좀 다른 ai라 파악하기 좋게 넣어주라", 2026-10-17).

- `docs/current/handoff.md`는 열린 사이클 한 줄 목록 + 교차 규칙(ADR-0170)입니다 (2026-11-05 줄임)
- 사이클별 인계서는 각 사이클 폴더 `handoff.md`에 있습니다

## 2. 순서가 뒤틀린 곳

번호 차례대로 읽으면 헷갈리는 곳만 적습니다.

1. **20이 17보다 먼저 만들어졌습니다.** 17(첫 배포)은 2026-10-13에 계획을 시작했지만, 사용자가 "사이클 20을 먼저 개발하고, 그다음 17 배포로 해"(2026-10-16)라고 정했습니다. 그래서 20 1단계 → 17 배포 → 20 2단계 순서였습니다.
2. **나가는 길(webshare 작업)은 사이클 번호가 없습니다.** 처음에 "사이클 22"로 불렸지만 사이클 20 안에서 끝났습니다. 옛 문서에 남은 "사이클 22"·"17/22"는 이 일을 가리킵니다.
3. **19와 21은 dev에서 병렬로 만들었습니다.** 21은 19가 dev main에 들어간 뒤 그 위에서 시작했습니다.
4. **12·13·14와 15·16도 미리 인계했습니다.** dev 순서는 11 → 12 → 13, 14는 자기 워크트리, 16은 15와 병렬.
5. **18은 일부만 했습니다.** A1·A2·B는 dev main, C(운영 반영)는 백로그로 갔다가 2026-11-05 완료 확인.
6. **세션 이름의 번호 = 사이클 번호**이지만, 23처럼 plan 폴더가 없는 세션도 있습니다. 찾을 때는 `docs/reference-index.md`와 백로그를 봅니다.
