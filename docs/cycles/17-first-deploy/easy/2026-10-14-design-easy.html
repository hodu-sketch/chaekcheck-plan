사이클 17 첫 배포 설계,
한눈에

책첵을 집 PC 밖에서 누구나 쓸 수 있게 AWS 서버 한 대에 올리는 설계입니다. 서비스 화면·기능·데이터는 바뀌지 않고, 서버를 어떻게 세우고 지키는지만 정했습니다. 이 글은 이미 정한 것을 쉬운 말로 다시 적은 것입니다. (2026-10-14)

1사용자가 들어오는 길

사용자는 chaekcheck.com으로 들어오고, Cloudflare가 그 요청을 받아 우리 서버로 넘깁니다. 우리 서버는 바깥에 어떤 문도 열지 않습니다.

터널은 서버 쪽 cloudflared가 먼저 Cloudflare로 연결을 걸어 두는 방식입니다. 그래서 서버에 들어오는 포트를 열지 않아도 됩니다.

  • 서버: AWS Lightsail 서울 한 대(2주), 그 뒤 본가 노트북으로 옮김
  • 도메인: chaekcheck.com(Cloudflare에서 삼), 로그인은 카카오만
  • http로 오면 https로 옮김. 서버가 멈추면 사용자는 Cloudflare 오류 화면을 봄(우리 안내 화면은 안 만듦)

2서버 한 대 안에 무엇이 도나

작은 프로그램 여러 개를 Docker로 함께 띄웁니다. 바깥 요청을 받는 무리와 안에서만 쓰는 무리로 나눠서, 안쪽 것은 바깥에서 아예 못 봅니다.

같은 그림을 쓰는 네 프로그램(prometheus·node_exporter·cAdvisor·접속 기록 읽기)은 모두 서버 상태 숫자를 모으는 일을 합니다. 자세한 건 4번 카드.

  • 이렇게 나누는 이유: nginx가 "진짜 사용자 IP"를 믿을 범위를 edge 무리로 좁히려는 것입니다. 그래야 누가 가짜 IP를 붙여 보내도 속지 않습니다.
  • 조회 서버는 지금 서비스가 도서관에 직접 묻는 방식이라 쓰지 않습니다. 그래서 넣어 두되 꺼 둡니다.

3비밀 값을 넣는 방법

카카오 키·DB 비밀번호 같은 비밀 값은 서버 파일에 적어 두지 않고 AWS Parameter Store에 둡니다. 서버를 띄울 때 스크립트가 받아 옵니다.

서버에는 비밀 값을 읽을 수 있는 AWS 접근 키 한 쌍만 둡니다. 값을 못 받으면 멈추고, 돌던 프로그램은 그대로 둡니다.

  • 넣는 값: DB 비밀번호, 로그인 서명 키, 카카오 키 3개, 터널 토큰, Grafana 비밀번호. 이름 끝이 그대로 설정 이름이 됩니다(/chaekcheck/prod/DB_PASSWORD → DB_PASSWORD).
  • 노트북으로 옮길 때: 같은 스크립트를 쓰거나, 받은 값을 .env 파일로 두고 그 파일로 띄워도 됩니다.

4서버가 버티는지 보기 (모니터링)

서버 상태를 숫자로 모아 Grafana 그래프 화면에서 봅니다. 숫자를 모으는 프로그램이 넷인데, 보는 곳이 서로 달라 함께 씁니다.

프로그램무엇을 봄
node_exporter서버 전체: CPU, 메모리, 디스크 남은 양
cAdvisor프로그램 하나하나의 메모리(DB가 얼마, backend가 얼마)
backend 자신서비스 응답 시간, 오류 수, 도서관 호출을 차례 못 받아 포기한 횟수
접속 기록 읽기요청 한도를 넘어 거절된 횟수(429). 이건 nginx가 돌려줘서 서비스가 모름
  • Grafana는 grafana.chaekcheck.com으로 들어가 로그인해야 봅니다. 숫자를 내보내는 주소는 바깥에 열지 않습니다.
  • "포기한 횟수"는 같은 도서관에 사람이 몰리거나 도서관이 느려지면 늘어납니다. 이 숫자를 보려고 backend 코드를 조금 고칩니다(지금 로그에 안 남는 경우가 하나 있어 더함).

5망가져도 되살리기 (백업)

매일 새벽 3시에 서버가 DB를 통째로 파일로 뽑아 두고, 내 PC가 그 파일을 받아 옵니다.

  • 백업에 넣는 것: 회원·내 도서관·이용 기록처럼 운영 중에만 생기는 것. 수집한 책 목록은 내 PC에 원본이 있어 매일 백업에서 뺍니다.
  • 몇 개 두나: 서버에 2일치, 내 PC에 7일치. 더 오래된 것은 지웁니다.
  • 받아 오는 길: 집 IP가 바뀔 수 있어서, 서버 포트를 여는 대신 Cloudflare 터널로 SSH를 겁니다.
  • 처리방침에 쓸 보관 기간은 7일입니다.

6과한 요청 막기

한 사람(IP)이 너무 자주 부르면 그때그때 잠깐 막습니다. 계속 막아 두는 목록은 없습니다.

대상한도
도서관을 부르는 요청(검색·대출 현황·더 보기)이미 있음: IP마다 2초에 1번, 몰아서 20번
그 밖의 요청(책 목록 검색·도서관 목록·로그인)새로: IP마다 1초에 5번, 몰아서 30번
클릭·행동 알림(/api/v1/usage-events)사이클 15가 둠: IP마다 1분에 60번

한도를 넘긴 요청만 "잠시 뒤 다시"(429)를 받고, 다른 사람은 그대로 씁니다. 진짜 사용자 IP로 세려면 nginx가 Cloudflare가 알려 주는 IP를 읽게 해야 합니다.

7프록시로 대출 조회 (이번 배포에 포함)

도서관 대출 현황을 물을 때 나가는 길을 여러 개 두는 설계입니다(ADR-0095). 이번 첫 배포에 넣습니다. 켜기 전에 아래 네 가지를 먼저 확인해야 합니다.

  • 나가는 길 셋: 서버가 직접 / 직접 + 업체 프록시 여러 곳 / 조회 서버를 거침. 설정으로 고릅니다.
  • 도서관 한 곳에 보내는 양은 나가는 IP마다 따로 셉니다. 한 IP가 막히면 그 IP만 그 사이트에서 멈추고 다른 IP로 계속합니다.
  • 먼저 확인할 것: 한국 고정 IP를 파는 업체, 그 업체가 공공도서관(go.kr) 접속을 막는지, 약관에 걸리는지, Java에서 프록시를 쓰는 방법.
  • 이 부분은 사용자가 직접 정하고 명세에 적었습니다(spec R13).
