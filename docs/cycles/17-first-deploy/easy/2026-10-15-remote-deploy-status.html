1정할 것: AWS에서 Cloudflare Tunnel 유지?

AWS에 계속 둘 거라 "터널이 꼭 필요한가"가 생긴 질문입니다. 아래 중 하나를 눌러 주세요. 추천은 ① 유지입니다(열린 포트 0개 + 집 이전 때 재작업 없음).

2당신이 콘솔에서 할 일 보기용

로그인·결제·계정 설정은 제가 못 하는 5가지입니다. 정확한 값(보안그룹·권한 범위·Redirect URI)은 각 단계에서 제가 드립니다.

  • AWS 안에서 (순서대로)
    • ① Budgets 예산 1개 — 크레딧 알림 + 적립 활동 하나
    • ② EC2 서버 — 서울(ap-northeast-2) · t4g.medium(4GB) · Ubuntu, 키 페어 받기
    • ③ IAM 역할 — Parameter Store 읽기 권한만, ②서버에 연결
  • AWS 밖에서 (아무 때나)
    • ④ chaekcheck.com 도메인 Cloudflare에서 사기
    • ⑤ 카카오 개발자 콘솔에 운영 주소·Redirect URI(https://chaekcheck.com) 등록

3배포 직전 확인할 것 보기용

대부분 제가/개발이 배포 때 확인합니다. 당신은 공개일과 데이터 판만 알아 두시면 됩니다.

  • 공개일 = 2026-10-18(모르는 사람에게 여는 날). 이 날 사용 기록 켜고 첫 공지 올림.
  • 첫 배포 데이터에 도서관 22곳 끄기(016)·현대제철 2624 전자책 241권이 들어갈지 — 사이클 19 반영 뒤 목록 기준으로 배포 전 확인.
  • 처리방침·약관 글(sitecontent) seed를 검토본·공개일로 고치는 일을 DB 비우기 전에 함.
  • 터널로 들어온 IP가 실제 사용자 IP로 찍히는지(CF-Connecting-IP), Cloudflare "Remove visitor IP headers" 꺼짐 — 배포 때 시험.
  • EC2 4GB에 서비스·DB·모니터링이 다 들어가는지 — 서버에서 측정.

✓이미 정해진 것 참고

  • 호스트 = AWS EC2 t4g.medium(4GB·서울), 무료 크레딧으로 최대 6개월
  • 비밀값 = EC2 IAM 역할(접근 키 없이)
  • 조회 = 프록시 안 쓰고 본 서버 직접(집 이전은 나중에)
