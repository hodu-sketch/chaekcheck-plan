AWS에서 계속 쓸 거면
Cloudflare Tunnel이 필요한가

배포를 "2주"가 아니라 "6개월까지 AWS"로 바꾸면서 생긴 질문입니다. 결론: Cloudflare 전체가 아니라 그중 Tunnel이 선택이 됩니다. (2026-10-14)

먼저: 무엇이 바뀌고 무엇은 그대로인가

cloudflared 터널을 넣은 가장 큰 이유는 집 노트북이었습니다. 집 노트북은 고정 공인 IP가 없고 공유기 뒤에 있어 바깥에서 들어올 길이 없기 때문입니다. 그런데 AWS EC2는 고정 공인 IP(Elastic IP)가 있어, DNS를 그 IP로 가리키고 443 포트를 열면 터널 없이도 서비스됩니다. 그래서 터널은 "필수"에서 "선택"이 됩니다.

그대로 필요한 것: 도메인(chaekcheck.com, 어디선가는 사야 함), https 인증서(터널 없어도 Cloudflare 프록시나 서버의 Let's Encrypt로 받음), 원하면 DDoS·과도요청 막이. 이건 터널과 별개입니다.

EC2에서도 Cloudflare Tunnel을 유지함 [안]

EC2에서도 지금 설계대로 cloudflared 터널로 들어오게 합니다. 서버에 바깥으로 열린 포트가 하나도 없고(ADR-0103이 그 이유로 고른 구조), 나중에 집 노트북으로 옮길 때 같은 설정을 그대로 써서 재작업이 없습니다. "6개월 AWS"는 집 이전을 없앤 게 아니라 미룬 것뿐입니다.

방식열린 포트집 이전 때보호
① 터널 유지(이 안)없음재작업 없음SSL·DDoS
② 터널 빼고 Cloudflare 프록시443을 Cloudflare에 열기터널 다시 도입SSL·DDoS
③ Cloudflare 최소(DNS만)+서버 직접 TLS443 전체 공개터널 도입없음(IP 노출)

②·③은 지금은 조금 단순하지만, 집 노트북으로 옮길 때 터널을 다시 넣어야 합니다(재작업). ①은 지금 손이 한 겹 더 들지만 그 뒤가 매끄럽습니다.

다른 선택이 끌리면: "지금 6개월은 단순하게" 원하면 ②(프록시)로, "Cloudflare 보호도 빼고 가장 단순" 원하면 ③으로 — 기타에 적어 주세요.

추천: ① 터널 유지. 단 터널의 스트리밍 응답 제한(기록해 둔 125초 확인 항목)만 배포 때 점검.

계속 AWS에 둘 거면: AWS 자체 기능으로 세팅하는 건? (궁금증 답)

됩니다. 집 이전을 안 하고 AWS에 계속 둘 거면, Cloudflare가 해 주던 일(https 인증서·DDoS 막이·CDN·origin IP 숨김)을 AWS 자체 서비스로 대체할 수 있습니다. 거의 무료로 되는 길도 있고, 그게 더 'AWS다운' 구성이라 운영 관점에서도 보여줄 거리가 됩니다.

Cloudflare 역할을 AWS로 바꾸면: 도메인 DNS = Route 53(월 $0.50), https 인증서 = ACM(ALB·CloudFront에 쓰면 무료), CDN+인증서+DDoS = CloudFront(월 1TB·요청 1천만까지 항상 무료, EC2에서 가져오는 트래픽 무료), 기본 DDoS 막이 = Shield Standard(모든 계정 기본 무료). 즉 Route 53 + ACM + CloudFront면 우리 규모에선 월 $0.50 수준입니다.

방식월 비용(크레딧)열린 포트AWS 네이티브
① Cloudflare Tunnel$0없음(가장 안전)아니오
④ Route 53 + ACM + CloudFront약 $0.5443을 CloudFront IP에 열기예 (거의 무료)
⑤ Route 53 + ACM + ALB약 $22/월443을 ALB에 열기예 (과함)

④가 Cloudflare 프록시(②)와 거의 같은 일을 AWS 안에서 합니다. ⑤(ALB)는 서버 한 대엔 과하고 크레딧을 빨리 씁니다. 다만 ④·⑤ 모두 origin(EC2) 포트를 그 서비스 IP에만 여는 설정이 필요해, "열린 포트 0개"는 터널(①)만의 장점입니다.

정리하면 — "AWS면 Cloudflare 무의미"가 아니라, Cloudflare 무료 기능이 AWS 유료 기능(특히 ALB)보다 싼 경우가 많습니다. 반대로 AWS 기술을 보여주는 게 목적이면 ④(CloudFront)로 가는 값어치가 있습니다. 집 이전을 정말 안 할 거라면 ④도 진지한 후보입니다.

지금 결정은 위 제안(터널 유지)만 정하면 됩니다. "AWS 네이티브(④)로 가고 싶다"면 기타에 적어 주세요 — 그러면 ④ 기준으로 설계를 다시 그립니다.
