사이클 17 첫 배포:
무엇을 이번에 하고, 무엇을 다음으로 미룰지

이틀 동안 배포 조사에서 정한 것을 사이클 17의 범위로 옮겼습니다. 하나의 사이클로 보기에는 커서, 이번에는 "공개 주소에서 서비스가 돌아가는 것"까지만 하고 대출 조회 프록시와 노트북 이전은 다음으로 미루는 안입니다. 6가지를 정해 주세요. (2026-10-13)

1이번 사이클이 끝나면 생기는 것

휴대폰으로 내 도메인 주소를 열면 지금 집 PC에서 보던 서비스가 그대로 뜨고, 카카오 로그인까지 됩니다. 서버는 Lightsail 서울 한 대이고, 2주 동안 공개합니다.

점선이 없는 그림이 이번 사이클입니다. 업체 프록시와 노트북은 그리지 않았습니다.

2이번에 할 것

아홉 가지를 세 묶음으로 나눴습니다. 서버를 세우는 것, 서비스를 운영 상태로 만드는 것, 운영을 지켜보는 것입니다.

서버 세우기

  • Lightsail 서울 4GB 한 대에 nginx·서비스·조회 서버·PostgreSQL을 Docker로 띄움 (정해짐)
  • 도메인 + Cloudflare Tunnel 연결, 인증서는 Cloudflare (정해짐)
  • nginx가 진짜 사용자 IP를 읽게 하고(정해짐), 책 검색 목록 같은 나머지 API에도 IP별 한도를 둠

서비스를 운영 상태로

  • 운영 DB 채우기: 첫 배포 직전에 seed를 다시 만들고, 그 뒤로는 DB 변경을 새 파일로만 함. 책 목록은 내 PC에서 가져와 운영 서버에 반영
  • 비밀 값(카카오 키, DB 비밀번호, 조회 서버 토큰) 둘 곳, 카카오 콘솔에 운영 주소 등록, 약관·처리방침 시행일(사이클 16과 맞춤)
  • 서비스 주소를 User-Agent와 화면에 채우기, 운영 메모리 값 다시 재기

운영 지켜보기

  • Prometheus·Grafana·node_exporter를 서버에 직접 (정해짐), 서비스가 숫자를 내보내게 Spring 설정 더하기
  • 하루 한 번 DB 백업을 서버 밖에 둠
  • nginx 접속 기록 보관 기간 정하기 (사이클 15·16에서 넘어온 것)

1이번 사이클에 위 아홉 가지를 넣음 [안]

대부분 서버와 설정 일이고, 코드는 지표 내보내기·IP별 한도·서비스 주소 정도만 바뀝니다. 표와 API는 바뀌지 않을 것으로 봅니다.

모니터링을 빼고 더 작게: 빨리 끝납니다. 대신 2주 동안 서버가 버티는지 숫자로 볼 수 없습니다.
백업을 빼기: 2주 체험이라 잃어도 다시 가져올 수 있다고 볼 수 있습니다. 대신 그동안 생긴 회원·내 도서관 기록은 되살릴 수 없습니다.

추천: 아홉 가지 모두.

3다음으로 미룰 것

오늘 정하신 대출 조회 프록시(ADR-0095)는 개발할 것이 많아 사이클 18로 따로 떼는 안입니다. 이번에는 서버 자기 고정 IP로만 조회합니다.

미룰 것이유어디로
대출 조회 나가는 길 세 가지, 업체 프록시, IP마다 따로 세기, 일반 브라우저 User-Agent본 서비스와 조회 서버 양쪽에 프록시 거쳐 보내기를 새로 만들어야 하고, 업체 선택·약관 확인이 남음사이클 18 후보
교보 구독형 서버 다시 받기·조회 (ADR-0094)집이 아닌 IP가 생긴 뒤에 함. 프록시와 함께 하는 것이 자연스러움사이클 18과 함께
노트북으로 옮기기2주 뒤의 일이고, 노트북 사양을 아직 모름2주 뒤 따로
AWS WAF 봇 막기Lightsail 앞에는 바로 붙이지 않음. Cloudflare 규칙으로 대신할지 사이클 15와 함께 다시 봄backlog
DB 크기 줄이기, S3·CloudFront·RDS2주 체험에는 필요 없음backlog

2대출 조회 프록시(ADR-0095)와 교보 서버 다시 받기(ADR-0094)는 사이클 18로 미룸 [안]

이번 2주 동안 교보 구독형 서버 쪽 대출 현황은 Lightsail 고정 IP로 조회됩니다. 집 IP가 아니므로 막히지 않을 수 있지만, 사이트가 데이터센터 IP를 받아 주는지는 아직 시험하지 않았습니다.

이번 사이클에 함께: 공개하자마자 프록시를 씁니다. 대신 개발 범위가 두 배 가까이 되고, 업체 가입·결제·약관 확인을 먼저 해야 합니다.

추천: 사이클 18로.

4끝났다고 보는 기준

사용자가 휴대폰으로 직접 확인할 수 있는 다섯 가지입니다.

  • 휴대폰 데이터망에서 https://내도메인을 열면 검색 결과와 대출 현황이 나온다
  • 카카오로 로그인하고 내 도서관을 저장할 수 있다
  • 같은 IP에서 검색을 한도보다 많이 보내면 "잠시 뒤 다시"가 나오고, 다른 사람의 검색은 영향받지 않는다
  • Grafana에서 서버 CPU·메모리·응답 시간·"차례를 못 받아 포기한 횟수"를 볼 수 있다
  • 서버 밖에 전날 DB 백업 파일이 있다

3위 다섯 가지를 완료 기준으로 함 [안]

더 줄이기(앞의 두 가지만): 공개만 확인합니다. 한도·모니터링·백업은 확인하지 않고 끝날 수 있습니다.

추천: 다섯 가지.

5먼저 정해야 하는 것

개발 전에 사용자가 정하거나 직접 해야 하는 것이 셋 있습니다.

4도메인은 chaekcheck.com을 Cloudflare에서 삼 [안]

`.com`으로 사기로 한 것은 2026-10-05에 정했습니다. 이름과 살 곳은 아직 정하지 않았습니다. Cloudflare에서 사면 바로 터널에 붙고, 첫해와 다음 해 값이 같습니다(외부 정리 기준 약 $10.46, 결제 화면에서 확인). 이름을 쓸 수 있는지는 확인하지 않았습니다.

다른 이름: 기타에 적어 주세요.
국내 업체에서 삼: 첫해가 조금 싸고(가비아 19,800원), 네임서버를 Cloudflare로 바꾸는 단계가 하나 더 있습니다.

추천: chaekcheck.com, Cloudflare.

5비밀 값은 서버의 .env 파일(본인만 읽을 수 있게)에 둠 [안]

카카오 키, DB 비밀번호, 조회 서버 토큰을 서버 한 곳의 파일에 두고, 그 파일은 서버 사용자만 읽게 합니다. 지금 코드는 환경 변수 이름만 읽으므로 바꿀 것이 없습니다(dev 기록 2026-10-04).

AWS Parameter Store·Secrets Manager: 서버 밖에 안전하게 둡니다. 대신 설정이 늘고, 노트북으로 옮기면 다시 바꿔야 합니다.

추천: .env 파일. 2주 뒤 노트북에서도 같은 방식.

6DB 백업은 하루 한 번 내 PC로 내려받음 [안]

서버가 밤에 DB 덤프 파일을 만들고, 내 PC가 받아 둡니다. 책 목록은 내 PC에 원본이 있으므로, 실제로 지켜야 하는 것은 회원·내 도서관·이용 기록입니다.

S3에 둠: PC가 꺼져 있어도 쌓입니다. 대신 AWS 요금과 설정이 조금 늡니다(금액은 확인 못 함).

추천: 내 PC로.
