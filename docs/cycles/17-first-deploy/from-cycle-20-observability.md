# 사이클 20 → 사이클 17: 운영 감시와 메모리 보호 (인계에 넣을 것)

- 쓴 날: 2026-10-17, 사이클 20 세션. 결정 페이지 `docs/cycles/20-lookup-status-and-extension/easy/2026-10-17-overall-review.html` #4·#5 [확정] (사용자 승인, 2026-10-17)
- 왜 17에: 운영 서버·compose·CloudWatch 설정은 사이클 17(배포) 몫. 사이클 20은 앱 쪽 1분 요약 로그만 넣음(사이클 20 1단계)
- 지금 상태(사이클 17 research 17절): CloudWatch 경보는 `chaekcheck-server-down`(상태 검사 실패)·`chaekcheck-disk-high`(디스크 90%) 둘뿐. 앱 프로세스가 죽거나, Cloudflare 터널이 끊기거나, 힙이 차거나, 503이 몰려도 메일이 오지 않음. dev에는 Actuator가 없음

## 넣을 것 [확정] (사용자 승인, 2026-10-17, 전반 점검 #5)

1. **1분 요약 로그 → 경보 3개**: 앱(사이클 20이 만듦)이 1분마다 운영 요약 로그 한 줄을 남김(검색 자리 사용 수, 503 수, 힙 사용량, 멈춘 길, 계획 무게, 장부 크기, 확장/서버 요청 수). CloudWatch 에이전트가 그 로그를 보내고, 로그 지표 필터로 경보 3개: ① 요약 줄이 5분 동안 없음(앱 죽음) ② 힙 85% 넘음 ③ 503 급증(기준값 [안]: dev가 정함). SNS `chaekcheck-alerts` 메일로. 무료 경보 10개 안 (지금 2개 사용). 로그 수집 비용 [확인 필요: AWS 요금 페이지]
2. **2GB 서버 전체 보호**: 메모리 사용률 90% 경보, 스왑 파일 1~2GB [안: 크기는 17이 디스크 여유 보고 정함], PostgreSQL 컨테이너 `mem_limit` 1GB → 약 512MB [안: 17이 배포 뒤 측정으로 맞춤]
3. **배포·끊김 대비**: 서비스 `server.shutdown: graceful`(지금은 fetch-service에만 있음), cloudflared `restart: unless-stopped`

## 넣을 것 [확정] (전반 점검 #4)

4. **메모리가 바닥나면 앱을 끝내고 다시 켜기**: JVM `-XX:+ExitOnOutOfMemoryError` + 서비스 컨테이너 `restart: unless-stopped`. 해석 자리 상한(서버·확장 함께 8)은 사이클 20이 앱에 넣음
