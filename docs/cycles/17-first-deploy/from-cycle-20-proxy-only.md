# 사이클 20 → 사이클 17·22: 나가는 길 설정에 "프록시만" (인계에 넣을 것)

- (2026-10-17) 길 목록·막힌 길 처리는 사이클 20 dev로 옮김 — 사용자 결정, 20 handoff 1-15. 업체 데이터 세기·업체 오류 멈춤·경보는 17에 남음.

- 쓴 날: 2026-10-16, 사이클 20 세션. 사용자 요청(사이클 20 세 관점 검토 캔버스): "옵션 설정하는 거 있잖아, 프록시만 하면 프록시만 하고 자체 서버 IP에서 수집하는 것을 안 하도록 했으면 해"
- 결정 페이지: `docs/cycles/20-lookup-status-and-extension/easy/2026-10-16-review-decisions.html` #24
- 왜 17·22에: 대출 조회 나가는 길과 그 설정은 ADR-0130(사이클 22 조사, 사이클 17 인계 `from-research-lookup-egress.md`)의 몫. 사이클 20은 상태 불만 이 설정을 따름

## 결정 [확정] (사용자 승인, 2026-10-16, 사이클 20 세 관점 검토 #24)

1. 대출 조회 나가는 길 설정에 값 셋: `모두`(기본, 시드니 EC2 자기 IP 1 + Webshare 한국 정적 20 = 21개) / `프록시만`(Webshare 한국 20개만) / `직접만`(EC2 자기 IP 1개만). 바꾸면 서비스 다시 켜기만. 설정 이름·값 철자는 dev가 ADR-0130 설정 자리에 맞춰 정함 [안]
2. `프록시만`이면 시드니 EC2 자기 IP로는 도서관에 요청을 보내지 않음(막힌 길 다시 시험 요청 포함)
3. `프록시만`에서 Webshare 길 20개가 모두 멈추면(업체 오류 407·429·계정 문제, 또는 데이터 90% — ADR-0130·사이클 22 8절 #3·#4) **EC2로 자동으로 넘어가지 않음**: 서버 모드 조회 멈춤 → 모든 도서관 「확인하지 못한 도서관」, 운영자에게는 사이클 22의 "업체 길 멈춤" 메일 그대로. 다시 가려면 운영자가 설정을 `모두`로 바꿈
4. 적용 범위: 서비스 대출 조회의 나가는 길에만. 책 목록 수집기의 길은 따로(사용자가 따로 원하면 다시 정함)

## 사이클 20 쪽 (상태 불)

- `프록시만`이고 Webshare 길이 모두 멈춘 동안: 머리말 빨강, 둘째 줄 "지금은 도서관 조회를 할 수 없어요". 확장 모드(파란 불)는 사용자 브라우저로 가므로 그대로 동작 [확정] (같은 결정). `모두`일 때의 #21(최소 노랑)과 다름
- 사이클 20은 "길 설정 값"과 "업체 길 멈춤" 값을 읽기만 함
