## 결정 기록

- 1번(책 표 세기): 1분 확인을 없애고 **AI 검색 책 목록은 서비스 서버가 켜질 때 한 번만 읽는다**. 가져오기 뒤 다시 띄우기가 알림 역할 [확정] (사용자 결정, 2026-11-08: 이벤트 방식을 고른 뒤 "listen, notify 구조면 연결 하나가 너무 아깝지 않아?" → (나)). 다시 띄우기를 잊지 않게 하는 방법은 `easy/2026-11-08-reload-options.html`에서 정함
- 1번 고침 (2026-11-08): 위 「켜질 때만 읽기」에 더해, **백엔드에 「책 목록 다시 읽기」 REST 요청을 하나 두고, 가져오기가 끝나면 그 요청을 보내 새 판을 적용**한다. 다시 띄우지 않고, 1분 확인도 없다 [확정] (사용자 결정: "그냥 백엔드에 rest api받는거 하나 주고 그거 응답 받으면 새 버전을 적용하는 거 하면 되는 거 아니야?"). 「가져오기 뒤 다시 읽기」 페이지의 가·나·다는 이 결정으로 대신함
- 세부 [안]: 주소는 nginx·터널로 열지 않는 내부 경로, 서버 안에서 지금 손님을 받는 자리(블루·그린)에 보냄. 다시 읽는 동안에는 옛 목록으로 계속 답하고, 다 읽으면 한 번에 바꿈. 다시 읽는 데 걸리는 시간은 [확인 필요: 고친 뒤 시작 로그 `ai search books read`로 잼]
- 결정 페이지 `easy/2026-11-09-decisions.html` (2026-11-08 KST 밤 전송): 1 `book-texts` 넣기를 새 표 바꿔 끼우기로 [확정] (사용자 승인) / 2 미승인 → "가져오기를 표 교체로 바꾼 다음에 db 미리 데우기도 테스트 해서 해" [확정] (사용자 제안) / 3 연결 유지 설정 안 함 [확정] / 4 「찾는 중」 이른 신호는 백로그 [확정] / 5 고친 뒤 같은 10건 다시 재기 [확정] / 6 ADR-0174 [확정] (모두 사용자 승인)
