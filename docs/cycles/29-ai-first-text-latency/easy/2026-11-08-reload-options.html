AI 검색의 책 목록은 서버가 켜질 때 한 번만 읽고, 1분마다 세는 일은 없앱니다(정하신 (나)).
남은 것: 가져오기 뒤 서버를 다시 띄우는 일을 어떻게 잊지 않게 할까.

결정 페이지 1번에 대한 이어지는 질문입니다. 하나만 골라 주세요(나머지는 미승인).

먼저: 가져오기는 지금 어떻게 하나

책 한 줄 넣기(book-texts)는 운영 서버에서 백엔드 이미지를 한 번 따로 띄워 실행합니다(비밀값을 PC로 가져오지 않음, dev docs/maintenance/6-aisearch.md 53~61행). 끝나면 서비스 서버를 bin/switch.sh backend <지금 판>으로 다시 띄웁니다(같은 문서 70행).

이미 같은 방식인 것: 책 프로필(catalog.book_profile)은 v1.22.1부터 켜질 때만 읽고 넣은 뒤 다시 띄우라고 적혀 있습니다(31행). 이번 결정으로 AI 검색 책 목록도 같은 규칙이 됩니다.

가져오기 실행서버에서 한 번 띄움→서비스 서버 다시 띄우기switch.sh→켜지며 새 목록 읽음
질문 답: 서비스 서버를 다시 띄운다 = 백엔드를 다시 띄운다는 것인가, 낭비 아닌가
네, 백엔드(자바 서버)를 새로 하나 띄워 바꿔 끼우는 것입니다. 책 목록 하나 다시 읽자고 하기엔 큽니다: 새 백엔드가 뜨는 1~2분 동안 2GB 서버에 자바가 둘 떠서 메모리를 더 쓰고(이미 스왑 633MB), 시작할 때 모델 파일·벡터도 다시 읽습니다 [확인 필요: 걸리는 시간은 재지 않음].
다만 카탈로그 전체를 다시 가져올 때는 벡터·이웃 파일도 새 번호로 바꿔야 해서 어차피 다시 띄웁니다(dev 6-aisearch.md 70행). 낭비가 되는 것은 한 줄 넣기(book-texts)만 할 때입니다.
다시 띄우지 않는 가벼운 길도 있습니다: ① 가져오기가 끝날 때 작은 표에 「몇 번째 판」 한 줄을 적고, 서버는 1분마다 그 한 줄만 읽기(1ms 안팎, 표 전체를 세지 않음) ② 가져오기가 서버 안에서 백엔드에 「다시 읽어」 요청 한 번 보내기(밖에서는 닿지 않는 주소). 이 둘로 다시 고를지 대화창에서 여쭙니다.

1가: 절차 문서에만 적기 (지금 그대로)

[안] 코드는 「켜질 때 읽기」만 바꾸고, 다시 띄우라는 것은 운영 문서의 절차 줄로만 둡니다.

예: 사용자가 가져오기를 돌리고 문서를 따라 switch.sh를 칩니다. 잊으면 다음 배포 때까지 새 책이 AI 검색에 안 나옵니다.

비용: 새로 만들 것 0. 잊을 위험은 지금 책 프로필과 같음.

2나: 가져오기 스크립트가 끝에 다시 띄우기까지 (추천)

[안] 가져오기를 감싸는 스크립트 하나(예: bin/import.sh book-texts <파일>)를 두고, 가져오기가 성공하면 이어서 switch.sh backend <지금 판>을 자동으로 부릅니다. 가져오기가 실패하면 다시 띄우지 않습니다. 책 프로필 넣기도 같은 스크립트로 묶습니다.

예: 명령 한 줄로 「넣기 → 블루·그린 바꿔 다시 띄우기」가 끝납니다. 무중단 배포(사이클 27)라 다시 띄우는 동안에도 손님은 끊기지 않습니다.

비용: 스크립트 하나. 다시 띄우는 동안 서버에 백엔드가 둘 떠서 잠깐 메모리를 더 씀(지금 배포 때와 같음).

3다: 가져오기 끝에 안내만 찍기

[안] 가져오기가 끝날 때 마지막 줄에 "AI 검색에 반영하려면 switch.sh backend <판>으로 다시 띄우세요"를 찍고, 서비스 서버가 켜질 때 읽은 책 수와 가져온 시각을 로그에 남깁니다. 다시 띄우는 것은 사람이 합니다.

비용: 로그 두 줄. 잊을 위험은 줄지만 남음.

어느 쪽이든 1분마다 세는 일과 붙잡아 두는 DB 연결은 없습니다.
