# 사이클 01: 도서 제목 검색 → 전자도서관 대출 가능 여부

## 목표 (한 문장)

로그인 없이 책 제목으로 검색하면 시범 전자도서관들의 보유·대출·예약 현황을 보여 주고, 사용자가 거주·직장 지역을 고르면 가입해서 빌릴 수 있는 도서관만 보여 준다. [확정] (2026-09-27)

## 포함

세부 규칙은 `spec.md`에 있습니다. 여기서는 범위만 적습니다.

- 도서 제목 검색 (로그인 없음) [확정]
- 시범 도서관 2곳, 플랫폼 2종: 서울 강서구 전자도서관(YES24, 자격 필요), 고흥군립도서관 전자도서관(교보, 누구나 가입). 플랫폼마다 adapter 하나 [확정]
- 도서관 가입 조건 두 종류(누구나 가입 / 자격 필요)와 자격 규칙(근거 × 범위) [확정]
- 내 지역 입력: 거주·직장 지역, 시군구 단위, 여러 개, 브라우저에만 저장 [확정]
- 지역을 고르면 빌릴 수 있는 도서관만 표시, 고르지 않으면 전부 표시하고 가입 조건 종류를 붙임 [확정]
- 실시간 조회와 도서관별 "더 보기", 먼저 응답한 도서관부터 표시 [확정]
- 결과 순서: 재고 그룹(지금 빌릴 수 있어요 / 예약하고 기다려요) → 가입 가능한 도서관 먼저 → 빌릴 수 있는 그룹은 재고 많은 순 → 도서관 대출률 낮은 순, 예약 그룹은 예약 적은 순 → 보유 많은 순 [확정]
- 크롤링 예의: 캐시 3분, 같은 도서관 동시 1건·1초 간격, User-Agent 식별, 원문 미저장 [확정]
- 도서관별 사용 여부 (운영용) [확정]
- 지역 목록: 내부 ID, 시도 → 시군구 계층, 행정구역 변경 시 폐지 표시와 자동 대체 [확정]
- 비영리 공개, 페이지 바닥에 데이터 출처와 연락처 [확정]
- 재학·소속 기관 자격을 나중에 담을 수 있는 구조 (입력은 제외) [확정]

## 제외 (backlog.md로 보낸 항목)

- 회원가입, 소셜 로그인(카카오·네이버), 서버에 자격 정보 저장
- 학교 지역·소속 기관(대학·회사) 입력과 그 시범 도서관 → 다음 사이클 후보
- 인기 도서 사전 수집 → 2사이클 [확정]
- 같은 책 묶기
- 시범 외 도서관·플랫폼 확대
- 실물 도서관, 구독 서비스, 구매 가격

## 완료 기준 (사용자가 화면에서 확인할 수 있는 것)

`spec.md` 7장의 AC-1~AC-20을 모두 통과하는 것입니다. 핵심은 다음과 같습니다.

1. 제목을 입력하면 두 시범 도서관의 결과가 도서관별로 나오고, 수량이 도서관 사이트와 같다.
2. 거주·직장 지역을 고르면 빌릴 수 있는 도서관만 보인다 (예: 서울 마포구 거주 → 강서구 + 고흥군, 부산 해운대구 거주 → 고흥군만).
3. 결과가 "지금 빌릴 수 있어요 / 예약하고 기다려요" 두 그룹과 정해진 순서를 따르고, 먼저 응답한 도서관 결과부터 보인다.
4. 도서관 하나가 실패해도 나머지 결과가 나온다.

## 슬라이스 선택 기록

- ICE 점수는 매기지 않았습니다. backlog의 "1사이클 후보"를 그대로 골랐습니다. [확정]
- 사용자 선택 (2026-09-27): "검색만, 거주지는 선택 입력". 처음에는 회원가입과 거주지 확인을 1단계로 말했지만, 크롤링이 가장 불확실하므로 먼저 검증하자는 제안을 받아들였습니다. 사용자가 직접 밝힌 이유는 [이유 미확인]
- 시범 도서관은 사용자가 골랐습니다: "서울 강서구, 고흥군 전자도서관으로. 둘이 종류가 달랐을 거야 교보랑 yes24로" (2026-09-27)

## 영향 받을 모듈 [확정] (ADR-0001, 상세는 design-delta.md)

- `library`: 전자도서관 목록, 플랫폼 종류, 가입 조건과 자격 규칙, 사용 여부. "이 지역들로 빌릴 수 있는 도서관"을 공개 API로 제공
- `availability`: 플랫폼별 adapter, 검색 스트림(SSE)과 더 보기, 캐시, 호출 간격 제어, 정렬에 쓰는 값 계산 (정렬은 프론트). `library`의 공개 API로 대상 도서관을 받음
- `region`: 시도·시군구 목록, 폐지·대체 연결, 옛 ID 해석 (별도 모듈로 확정)
