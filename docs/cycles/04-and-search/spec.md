# 기능 명세: 사이클 04 AND 검색 (제목·저자·출판사 여러 조건)

- 작성: 2026-09-30. 범위는 `scope.md`. 사전 조사는 `docs/research/ebook-catalog/` (`search-and-normalization.md`, `same-book-isbn.md`, `catalog-refresh.md`)
- 입력 방식, 저자 역할, 보완 검색, 기본 순서는 사용자가 Claude 추천안 또는 직접 쓴 답으로 정했습니다(2026-09-30). 고른 이유는 따로 말하지 않은 것은 [이유 미확인]입니다.

## 1. 사용자 이야기

- 전자책을 찾는 사람이 제목과 저자(또는 출판사)를 함께 넣어, 조건에 모두 맞는 책만 보고 싶다. 제목이 흔한 책("행동")도 원하는 책까지 "더 보기"를 수십 번 누르지 않기 위해서다. (사용자: "로버트 m. 새폴스키의 \"행동\" 검색하면서 너무 힘들었어")
- 그 책을 가진 도서관에서 지금 빌리거나 예약할 수 있는지 바로 보고 싶다. (서비스 목적)
- 수집 목록에 없는 책은 지금처럼 도서관 사이트에서 직접 찾고 싶다.

## 2. 입력과 출력

## 3. 동작 규칙

### 3.1 찾는 대상

- 수집한 책 목록(`chaekcheck-data`에서 한 번 가져온 것, 같은 책끼리 묶은 것)에서 찾습니다 [확정] (scope)
- **서비스에 등록된 도서관(지금 켜진 278곳)** 의 소장만 봅니다 [확정] (scope, 사용자 승인). 수집 목록의 도서관은 id·주소로 서비스 도서관과 이어집니다(276곳 id·주소 같음, 나머지 2곳은 꺼진 도서관 59·131번, 2026-09-30 대조)
- **도서관이 서비스하지 않는 책은 뺍니다** [확정]. 판단: 최근 성공한 수집에서 빠진 책(빠진 날짜가 있음)은 뺌 [안]. 그 밖에 상세 페이지에서 서비스 종료를 알아보는 방법은 [확인 필요]
- 자료 종류가 오디오북·동영상북인 것은 넣지 않습니다 [안] (사이클 02 backlog "포털 검색에 오디오북이 섞여 나옴 → 전자책만 보일지"와 같은 문제. 수집 DB가 종류를 구분함)

### 3.2 AND와 띄어쓰기

- 채운 칸끼리 AND: 모든 칸의 조건을 만족하는 책만 [확정]
- 칸 안: 검색어를 띄어쓰기로 나눈 단어가 **모두** 그 필드에 들어 있으면 일치. 비교는 정리한 값(공백 제거, NFKC, 영문 소문자)끼리 [안]. 그래서 "행동 경제학"과 "행동경제학"이 서로 찾아짐. 단어 순서는 보지 않음
- 정리 규칙은 `docs/research/ebook-catalog/search-and-normalization.md` 4절 [안]:
  - 제목: 전체 제목으로 부분 일치
  - 저자: 이름·역할로 나눈 사람 이름에서 찾음, 괄호 속 별명도 찾음
  - 출판사: `(주)`·`주식회사`·`도서출판` 등을 뗀 값

### 3.3 완전 일치

- 제목: **본제목**(첫 ` : ` 또는 ` - ` 앞) 또는 전체 제목이 검색어와 같으면 일치 [확정]
- 저자: 그 책의 사람 이름 **하나**가 검색어와 같으면 일치. 공백·마침표는 무시("로버트 M. 새폴스키" = "로버트M새폴스키") [확정 방향, 무시 규칙 안]
- 출판사: 정리한 출판사 이름이 같으면 일치 [확정]
- 예: 제목 "행동" 완전 일치 → 수집 데이터(2026-09-30)에서 제목에 "행동"이 든 책 코드 1,662개 중 새폴스키 「행동」만

### 3.4 저자 역할

- 기본: 지은이 + 역할 모름 [확정]
- 옮긴이·그림·엮은이는 따로 켜면 포함 [확정]. 역할 이름 사전은 `search-and-normalization.md` 4.1절 (저·글·지음·공저 → 지은이, 역·옮김·공역 → 옮긴이, 그림 → 그림, 글그림 → 지은이+그림, 편·엮음·편저·편역 → 엮은이) [안]

### 3.5 순서

- **기본 순서** [확정] (사용자: "추천안으로 가되 출판일 정렬도 마지막 조건으로 넣어주랑", "가입 가능 도서관 책 먼저가 최우선이야.. 당연히 누구나 가입이 더 최우선이고", 2026-09-30)
  1. **가입할 수 있는 도서관에 있는 책 먼저.** 책마다 그 책을 가진 계획 도서관 중 가장 앞 단계로 셈
     - 지역 있음: 내 시군구(방문 없음) → 내 시도(방문 없음) → 누구나(방문 없음) → 방문 가입만 → 가입 자격 확인 필요만 [확정] (사용자: "지역이 있을 때 책도 내 지역 먼저", 2026-09-30). 한 책 안 도서관 순서(ADR-0027)와 기준이 같음
     - 지역 없음: 누구나(방문 없음) → 방문 가입만 → 가입 자격 확인 필요만 [확정] (사용자: "당연히 누구나 가입이 더 최우선이고")
  2. 완전 일치 먼저 (칸마다 완전 일치를 켜지 않았어도, 검색어와 본제목이 같은 책을 앞에)
  3. 보유 도서관이 많은 책 먼저 (서비스 도서관 기준, 조회 범위·방문 가입 설정을 반영한 수 [안])
  4. 출판일 최신 먼저
- **출판일 최신순 / 오래된순**: 출판일만으로 줄 세움. 같으면 기본 순서 [안]
- 출판일: 같은 책을 가진 도서관들의 날짜 중 가장 많이 나온 날짜, 같으면 이른 날짜 [안]. 미래 날짜는 오류로 보고 다른 도서관 날짜로 대체, 없으면 비움 [확정]. 날짜를 모르는 책은 어느 정렬에서나 맨 뒤 [안]
- 한 책 안에서 도서관 순서와, 줄 단위 정렬(대출 가능 먼저 등)은 사이클 02·03 규칙 그대로 [확정]
- 그 밖의 정렬(제목 가나다순, 보유 도서관 많은 순, 가입 가능 먼저, 대출 가능 많은 순 등)은 **별도 사이클** [확정] (사용자: "정렬은 다른 cycle로 빼자 복잡하다", 2026-09-30) → backlog

### 3.6 실시간 조회

- 결과 순서대로 책을 가져와, **그 책을 가진 도서관에만** 조회합니다 [확정]
- 조회는 **그 책의 상세 페이지(수집해 둔 주소)** 를 읽어 대출·예약 수를 얻습니다 [확정] (사용자: "나. 상세 페이지 읽기 이걸로해줘"). 화면 종류별 확인 (2026-09-30, 종류마다 1건, 요청 간격 1.5초):

| 화면 종류 | 상세 페이지에 나오는 것 | 상태 |
|---|---|---|
| `KYOBO_V1` | "대출 : 0/5 예약 : 0" (대출 중/보유, 예약) | 확인 (경북도서관) |
| `KYOBO_SUBSCRIPTION_V1` | 수량 없음 | 확인 (동해). 사이클 02와 같이 구독형 판정(`SUBSCRIPTION`) |
| `YES24_V1` | "보유 2 , 대출 0 , 예약 0 , 누적대출 33 …" | 확인 (국립세종) |
| `YES24_V2` | "보유 1 대출 0 예약 0 누적대출 2" | 확인 (춘천) |
| `YES24_V3` | "보유 2 대출 0 예약 0 누적대출 2" | 확인 (경주) |
| `GANGNAM_V1` | "보유 20 대출 0 예약 0". 같은 화면에 다른 책(연관 도서)의 수량도 여러 개 나옴 | 확인 (강남구). 본 책 수량을 가려 읽는 방법 [확인 필요] |
| `ELIB_PORTAL_V1` | 사이클 02부터 상세 페이지로 "대출 가능·예약 가능"을 읽고 있음 | 대구는 일반 TLS 설정으로 연결 실패(ADR-0022의 RSA 키 교환 문제와 같음). 서비스의 기존 연결 설정으로 읽을 수 있음 |

- 호출 예의·묶음 규칙은 사이클 01·02 그대로 [확정]: 캐시 3분, 같은 호스트 동시 1건·1초, User-Agent, 묶음 20줄, "더 보기"
- 한 묶음에 넣을 책·도서관 수와 순서는 design-delta [안]

### 3.7 도서관에서 직접 찾기 (보완)

- 사이클 01~03의 방식(도서관 사이트 검색 화면에 검색어를 넣어 결과 목록을 읽음)을 그대로 씁니다 [확정]
- 부르는 방법 두 가지 [확정] (사용자)
  1. 수집 목록에서 결과가 0건이면 "도서관에서 직접 찾기" 버튼
  2. 설정(켜고 끔)으로 언제든 이 방식으로 검색
- 이 방식의 한계 [확정 사실, 사이클 03 조사]:
  - 조건 하나만: 채운 칸 중 첫 칸(제목 → 저자 → 출판사 순) [안]. 여러 칸 AND 불가
  - 완전 일치·출판일 정렬·저자 역할 선택 불가
  - 도서관마다 부분 일치·정확히 일치가 다름 (통합 포털 저자·출판사는 정확히 일치, ADR-0026)
  - 제목이 비슷한 다른 책이 섞이고, 도서관마다 차례로 조회해 느림
- **한계를 알리는 방법** [안] (사용자: "도서관에서 직접 찾기는 기능이 제한적인데 이걸 어떻게 알리지". screen-flow에서 확정)
  - 설정을 켜면 쓸 수 없는 입력(여러 조건 칸, 완전 일치, 역할, 출판일 정렬)을 흐리게 하고 짧은 이유를 붙임
  - 결과 위에 한 줄: "도서관 사이트에서 직접 찾은 결과예요. 한 가지 조건(제목)만 쓰고, 비슷한 제목의 다른 책이 섞일 수 있어요."
  - 0건 버튼 옆에도 같은 뜻의 짧은 설명

### 3.8 보기 방식: 책 먼저 고르기

- 설정으로 켜고 끕니다 [확정]
- 켜면: 검색 결과가 **책 목록**으로 나옵니다. 이 단계에서는 도서관에 실시간 조회를 하지 않습니다 [안]. 책마다 보유 도서관 수와 목록 기준일을 보입니다 [안]
- 책을 고르면: 그 책을 가진 서비스 도서관에만 상세 페이지로 대출·예약 수를 묻고, **도서관별로** 보여 줍니다 [확정]. 도서관 순서는 지금 계획 순서(ADR-0027)와 필터(결과 필터, 조회 범위, 방문 없이 가입, 지역) 그대로 [안]
- 책 목록 순서는 3.5절 기본 순서·출판일 정렬과 같음 [안]
- 도서관에서 직접 찾기(3.7)를 켜면 이 설정은 쓸 수 없음 (사이트 검색 결과는 책 단위로 묶여 있지 않음) [안]
- 설정을 어디에 저장할지: 주소(공유 가능) 또는 브라우저(다음 방문에도 유지) [확인 필요: 사용자에게 질문]. 회원 기능은 없음

| 로딩 | 목록 찾기는 빠르고, 대출 상황은 도서관마다 도착하는 대로 채움 (사이클 02와 같은 스트림 방식 [안]) |
| 결과 없음 | "조건에 맞는 책이 수집 목록에 없어요" + "도서관에서 직접 찾기" 버튼 + 목록 기준일 [안 문구] |
| 도서관 오류·지연 | 그 도서관 줄만 "확인 실패"(사이클 02와 같음). 상세 페이지가 없어진 책(404 등)은 그 줄만 실패로 표시 [안] |
| 입력 오류 | 채운 칸이 하나도 없거나, 채운 칸이 2자 미만·50자 초과면 검색하지 않고 그 칸에 안내 (사이클 03과 같은 규칙) |
| 목록이 오래됨 | 기준일을 늘 보여 줌. 경고 기준은 주기 갱신 사이클에서 |

## 5. 수용 기준

- AC-1: 첫 화면에는 제목 칸 하나만 있다. "여러 조건"을 누르면 저자·출판사 칸이 나타난다. 조건 드롭다운은 없다. (화면)
- AC-2: 제목 "행동" + 저자 "새폴스키"로 찾으면 새폴스키의 「행동」만 나오고, 그 책을 가진 서비스 도서관의 대출·예약 상황이 줄마다 보인다. (화면)
- AC-3: 제목 "행동경제학"(붙여 씀)의 결과 책은 모두 "행동 경제학"(띄어 씀)의 결과에도 있다. 띄어 쓴 쪽은 단어 순서가 다른 제목(예: 「경제학으로 본 행동」)도 찾는다. (API) — 사용자 선택 "단어별 AND"(2026-09-30)로 문구를 고침
- AC-4: 제목 완전 일치를 켜고 "행동"으로 찾으면 본제목이 정확히 "행동"인 책만 나온다. (화면)
- AC-5: 저자 칸에 옮긴이 이름(예: "양병찬")을 넣으면 기본으로는 찾지 않고, "옮긴이"를 켜면 그 사람이 옮긴 책이 나온다. 그림·엮은이도 같다. (화면)
- AC-6: 기본 순서에서 지역이 없으면 누구나 가입 도서관에 있는 책이, 지역이 있으면 내 시군구 → 내 시도 → 누구나 가입 도서관에 있는 책 순으로 앞에 온다. 같은 무리 안에서는 본제목이 검색어와 같은 책, 그다음 보유 도서관이 많은 책이 앞이다. 출판일 최신순·오래된순으로 바꿀 수 있고, 출판일을 모르는 책은 맨 뒤다. 미래 출판일(예: 2045-12-08)은 목록에 그대로 보이지 않는다. (화면·API)
- AC-7: 실시간 조회 요청은 결과 책을 가진 서비스 도서관의 상세 페이지로만 간다. 요청 로그에 다른 도서관·검색 화면 요청이 없다. (서버 로그)
- AC-8: 화면 종류 7개 각각에서 상세 페이지로 읽은 대출·예약 상황이 사이트 화면과 같다 (종류마다 1건 이상). (화면 대조)
- AC-9: 수집 목록에서 0건이면 "도서관에서 직접 찾기" 버튼이 보이고, 누르면 첫 칸 조건으로 사이클 03 방식 검색 결과가 나온다. 설정으로 켜도 같은 방식으로 검색되고, 쓸 수 없는 입력이 흐려지며 한계 안내가 보인다. (화면)
- AC-10: 최근 수집에서 빠진 책과 오디오북·동영상북은 결과에 없다. (API)
- AC-11: 조건과 설정이 주소에 남아 새로고침해도 같은 결과가 나온다. (화면)
- AC-12: 결과 필터·조회 범위·방문 없이 가입·지역이 사이클 02·03처럼 결과에 반영된다. (화면)
- AC-13: 호출 예의(캐시 3분, 같은 호스트 동시 1건·1초, User-Agent)가 지켜진다. (서버 로그)
- AC-14: 보기 방식을 "책 먼저 고르기"로 바꾸면 결과가 책 목록으로 나오고 이때는 도서관 요청이 없다. 책을 고르면 그 책을 가진 서비스 도서관별 대출·예약 상황이 나온다. 바로 보기로 돌리면 사이클 04 기본 흐름으로 보인다. (화면·서버 로그)

## 6. 비목표

- 오타 보정, 형태소 검색("행동하는"으로 "행동") — scope 제외
- 감수·기획·사진·원작·해설·낭독 역할 검색 — [이유 미확인] (Claude 안, 사용자가 그림·엮은이만 선택으로 넣음)
- 기본 순서·출판일 외의 정렬 — 사용자: "정렬은 다른 cycle로 빼자 복잡하다" → backlog (별도 사이클)
- 검색 결과에 책 표지·소개 표시 — 소개글은 저장하지 않음, 표지는 주소만 저장 [확정] (`crawl-method.md`). 표지 표시는 [이유 미확인]으로 이번에 하지 않음 [안]
- 서비스에 없는 기관(대학·기업 등)의 조회 — scope 제외
- 목록을 새로 수집·갱신하는 일 — 주기 갱신 사이클
