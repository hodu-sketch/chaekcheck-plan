# 사이클 04: AND 검색 (제목·저자·출판사 여러 조건)

## 목표 (한 문장)

제목·저자·출판사를 함께 넣어 조건을 모두 만족하는 전자책만 찾고, 그 책을 가진 도서관의 지금 대출·예약 상황을 결과 목록에 보여 준다. [안] (문장은 Claude 정리. 흐름은 사용자 확인 2026-09-30)

## 포함

세부 규칙은 `spec.md`에서 정합니다. 여기서는 범위만 적습니다.

- **흐름** [확정] (사용자 확인, 2026-09-30)
  1. 조건 입력
  2. 수집한 책 목록에서 AND에 맞는 책과, 그 책을 가진 도서관을 찾음
  3. 그 도서관에만 기존 실시간 조회
  4. 지금처럼 결과 목록에 대출·예약 표시. **사용자가 책을 고르는 단계는 없음** (사용자: "내가 사용자가 책을 '고르는'건 없을 거라고 했는데", "실시간 대출 조회는 이미 되는거 아니야?")
- **입력** [확정] (사용자: "여러칸 입력은 따로 버튼 눌러야하고 기본적으로 제목만")
  - 기본 화면은 제목 한 칸
  - 버튼을 누르면 저자·출판사 칸이 나타남
- **AND 검색**
  - 칸끼리 AND (칸마다 그 필드에서만 찾음) [확정] (backlog, 사이클 03 제외 항목)
  - 칸 안에서는 띄어쓰기를 무시하고, 나눈 단어가 모두 들어 있으면 찾음 [안] (사용자 지적: "띄어쓰기 잘못했다고 검색 못하는 경우 생기자나")
- **완전 일치**: 제목·저자·출판사 칸마다 켤 수 있음 [확정] (사용자 선택, 2026-09-30. 계기: "로버트 m. 새폴스키의 \"행동\" 검색하면서 너무 힘들었어")
- **출판일 정렬**: 최신순·오래된순 [확정] (사용자 선택)
  - 미래 출판일은 날짜 오류로 보고 다른 도서관 날짜로 대체 [확정]
  - 날짜를 모르는 책은 맨 뒤 [안]
- **옮긴이 포함 선택**: 저자 칸 기본은 역할 모름 + 지은이, 켜면 옮긴이도 [확정] (사용자 선택)
- **수집한 책 목록을 서비스 DB에 한 번 가져오기** [확정] (사용자 선택 "국가서지 ISBN까지")
  - 원천: `chaekcheck-data/ebook-catalog.sqlite`
  - 정리 규칙 적용 (`docs/research/ebook-catalog/search-and-normalization.md` 4절)
  - 같은 책 묶기: 같은 플랫폼 코드, 교보식 코드 ISBN, **국가서지 일반도서 파일 ISBN**까지 (`docs/research/ebook-catalog/same-book-isbn.md`)
- **서비스하지 않는 책은 결과에서 뺌** [확정] (사용자, 2026-09-30)
- **기존 검색(도서관 사이트 실시간 검색)은 보완용으로 남김** [확정] (사용자 선택)
  - 수집 목록에 없는 책은 지금 방식으로 찾음
  - 화면에서 어떻게 부를지는 spec에서 정함
- 호출 예의와 묶음 규칙은 사이클 01·02 그대로 (캐시 3분, 같은 호스트 동시 1건·1초, User-Agent, 20줄 묶음)

## 제외 (backlog.md로 보낸 항목)

- **주기 갱신**: 소장 목록 주기 수집을 서비스로 옮기기, ISBN·서지 주기 갱신, 정리·묶기 다시 계산. 별도 사이클 [확정] (사용자, 2026-09-30). 참고 문서 `docs/research/ebook-catalog/catalog-refresh.md`
- **ISBN 서지정보 API 연동**: 인증키 발급 대기. 신간 보충은 주기 갱신 사이클에서
- 사용자가 책을 골라 따로 조회하는 화면 (사용자: 고르는 단계 없음)
- 수집 목록에만 있고 서비스 도서관 목록(`library`)에 없는 기관(대학·기업·학교 등)의 조회: 가입 자격 조사가 필요한 도서관 확대 작업이라 이번에는 서비스에 등록된 도서관만 [안]
- 오타 보정, 형태소 검색(예: "행동하는"으로 "행동" 찾기)
- 회원, 읽는 코드가 없는 화면 7종, 느리거나 실패하는 도서관 기억하기 (backlog 그대로)

## 완료 기준 (사용자가 화면에서 확인할 수 있는 것)

세부 AC는 `spec.md`에서 정합니다. 핵심은 다음과 같습니다. [안]

1. 첫 화면은 제목 한 칸이고, 버튼을 누르면 저자·출판사 칸이 나타난다.
2. 제목 "행동" + 저자 "새폴스키"로 찾으면 「행동」만 나오고, 그 책을 가진 도서관의 대출·예약 상황이 보인다.
3. "행동 경제학"과 "행동경제학"으로 찾은 결과가 같다.
4. 제목 완전 일치를 켜고 "행동"으로 찾으면 제목이 정확히 "행동"인 책만 나온다.
5. "옮긴이 포함"을 켜면 옮긴이 이름으로도 찾아진다.
6. 출판일 최신순·오래된순으로 바꿀 수 있고, 날짜를 모르는 책은 맨 뒤에 있다.
7. 수집 목록에 없는 책은 기존 방식(도서관 사이트 검색)으로 찾을 수 있다.
8. 실시간 조회는 그 책을 가진 도서관에만 가고, 사이클 01·02의 호출 예의가 지켜진다.

## 먼저 조사할 것 [확인 필요]

| 항목 | 확인 방법 |

| PostgreSQL + `pg_bigm`의 2배 규모(책 약 350만) 응답 시간: 2글자, AND, 출판일 정렬, "사랑" | 프로토타입 (로컬 PostgreSQL) |

| 기존 실시간 조회로 "특정 책"의 대출 상황을 얻는 방법: 사이트 검색 결과에서 책 코드로 맞추기 vs 상세 페이지 조회 (화면 종류별) | 호출 시험, dev 코드 확인 |

## 영향 받을 모듈 [안]

- **새 모듈 (이름은 design-delta에서)**
  - 수집한 책 목록(책·소장·정리값·묶음)을 소유
  - AND 검색 제공
  - 새 스키마와 Liquibase changeset
- **`availability`**: 실시간 조회 계획을 "그 책을 가진 도서관"으로 좁힘. 조건 파라미터를 여러 개로 넓힘 (ADR-0025가 `?title=…&author=…` 모양을 미리 열어 둠)
- **`library`**: 수집 목록의 도서관을 서비스 도서관과 잇는 방법에 따라 바뀔 수 있음
- **`region`**, 조회 서비스: 바뀌지 않을 것으로 봄
- **웹**: 검색 영역(제목 한 칸 + 여러 조건 버튼, 완전 일치, 옮긴이 포함, 출판일 정렬), 목록에 없을 때 기존 검색으로 가기
- **한 번 가져오기 도구**: SQLite → PostgreSQL, 정리·묶기, 국가서지 대조. 어디에 둘지는 design-delta에서
