백로그에서 앞으로 할 일

기준: docs/backlog.md, 사이클 09·10·11·13 문서, dev plan-feedback.md (2026-10-12 오전에 한 번 더 맞춤)
사이클 11은 dev에 넘어갔고, 12는 "책 묶기 기준 다시 보기", 13은 "수집기를 dev로 옮기기"로 잡혔습니다.
배포·알림·통계는 사용자가 "나중"으로 미뤄 두었습니다.

1지금 어디까지 왔나

09와 10은 개발과 회고까지 끝났습니다. 11은 인계서가 승인되어 dev 차례입니다. 12와 13은 주제만 정해졌습니다.
  • 10: 인기 도서 화면과 매달 순위 받기가 들어갔고 회고도 썼습니다.dev가 사용자 요청("전체적으로 디자인 심심한데")으로 인기 도서 화면 디자인만 따로 다듬고 있습니다.
  • 11: 가져오기를 내 PC에서 하고 결과 표만 운영 DB로 옮기기, 가져오기 메모리 줄이기시험은 새 수집 사본(도서관 411의 새 주소 포함)으로 합니다. 그래서 "새 사본으로 다시 가져오기"는 11에서 함께 됩니다.
  • 12: 책 묶기 기준 다시 보기책 번호 유지는 사이클 07에 이미 구현돼 있어 빠집니다(2026-10-12 바로잡음). 사용자: "이 세션 cycle 12가 될 예정이고 … 이거 할거야" (2026-10-12). 알려진 문제(same-book-isbn.md 5.3절)의 표본 조사는 사이클 밖에서 plan이 미리 하기로 했습니다.
  • 13: 수집기를 dev로 옮기고, 도서관 넣기를 서버 collection 모듈이 재시작 없이 하게 하기

2책 목록 갱신에 딸린 큰 일

(2026-10-12 바로잡음) 책 번호 유지는 사이클 07에서 이미 구현됐습니다(ADR-0062). 처음 이 페이지에 할 일로 적은 것은 틀렸습니다. 자동 갱신은 아직 어느 사이클에도 없습니다.
  • 책 번호 유지다시 가져와도 /books/{bookId} 주소가 같은 책을 가리키게 합니다. 규칙은 이미 정했습니다(도서관 책 코드가 가장 많이 겹치는 옛 책의 번호를 이어 씀). 이미 구현됨(사이클 07, ADR-0062). 남은 것은 판이 합쳐지거나 나뉠 때 실제 데이터로 확인하는 것과, 회원이 책 번호를 저장하게 되면 옛 번호를 새 번호로 고쳐 쓰는 것입니다.
  • 정해진 때마다 자동 갱신사이클 11 결정: 가져오기를 내 PC에서 하면, 자동 갱신은 내 PC가 켜져 있을 때 돌리고 결과 파일을 운영에 올리는 모양이 됩니다.

3작게 끝나는 정리 일

두 개는 dev에서 이미 끝났거나 다른 사이클에 들어갔습니다. 남은 것은 아래 셋입니다.

남은 것

  • 폰 "검색 설정" 아래 창에 ⓧ 닫기 버튼사이클 10에서 폰 아래 창을 공용 부품으로 묶으면서 ⓧ와 "폰 뒤로 가기로 창만 닫기"가 생겼습니다. 검색 설정 창도 이 부품을 쓰지만, 인계서대로 ⓧ를 꺼 두었습니다. 이제 켜기만 하면 됩니다.
  • plan이 조사하고 다시 물을 것: 607 원광보건대학 이름, 다른 기관으로 보이는 도서관 10곳, 도서관마다 "언제 조사·수집했는지" 날짜를 남길지.

끝난 것

  • 가져오기 도중 죽으면 남는 빈 표 지우기 → 사이클 11의 discard 명령에 들어갔습니다.
  • dev 도구 build_candidate_seed.py가 도서관 업체 정보를 수집 DB에서 읽게 하기 → dev가 끝냈습니다(커밋 406465d).

4다음 책 목록 수집 때 같이 볼 것

수집을 다시 돌릴 때만 확인할 수 있는 일입니다. 수집 세션에 넘깁니다.
  • 북큐브에서 책이 0종이거나 응답이 없던 5곳: 대출 방식이 지금 "소장"으로 들어가 있는데 맞는지 봅니다.
  • 새로 들어온 북큐브 도서관의 권수 파일을 만들고, 새 도서관 이름은 정식 이름만 씁니다.
  • 교보 구독형 서버가 다시 열리면 1016·1079·2161의 사이트 제목을 확인합니다.
  • 여주대: 10-08에 중간에 멈춘 빠진 책 채우기를 다시 할지 수집 세션이 사용자에게 묻습니다.

5운영 서버에 올릴 때 다시 볼 것

사용자가 운영 서버 배포는 미뤄 두었습니다: "로컬 클라우드플레어로도 일단 충족되었다고 생각해 그래서 배포는 넣어둬". 그때 꺼낼 목록입니다.
  • 메모리 값 다시 재기사이클 08에서 정한 DB·서비스 메모리 값은 내 PC 기준입니다. 운영 서버에서 다시 재고, 서비스 힙 512MB와 가져오기용 DB 작업 메모리 1GB가 맞는지 봅니다.
  • 첫 배포 직전에 도서관 seed를 한 번 다시 만들고 DB를 새로 만듭니다.그동안 쌓인 이름 고침(013, 014)을 합칩니다. 배포 뒤에는 seed를 고정하고 바뀐 것만 더합니다.
  • 서버 크기: EC2 t4g.medium(4GiB), 디스크 40GiB 제안이 있습니다(aws-layout.md 6절).
  • 도메인: .com을 사기로 했습니다. 정확한 이름과 살 곳은 아직 안 정했습니다.

6"나중"으로 미뤄 둔 큰 기능

각각 한 사이클 이상 걸리는 일입니다. 사용자가 2026-10-05에 "나중"으로 미뤘습니다.
  • 알림: 원하는 책을 빌릴 수 있게 되면 알려 주기회원이 책을 저장하므로, 저장한 책 번호를 다시 가져온 뒤 새 번호로 고쳐 쓰는 일이 함께 필요합니다(책 번호 유지 자체는 사이클 07에 구현됨).
  • 구독형 도서관의 그달 예산이 다 찼다고 알려 주기도서관 사이트 공지에서 마감을 읽어 표시하기로 했습니다. 사이트에서 정말 보이는지는 월말에 시험해야 합니다.
  • 검색 결과 정렬 늘리기제목 가나다순, 가진 도서관 많은 순, 가입할 수 있는 도서관 책 먼저 등. 사용자: "정렬은 다른 cycle로 빼자 복잡하다"
  • 통계: 많이 검색된 책, 지역·직장별 인기, 성별·연령대성별·연령대는 나중에 카카오 동의항목(선택)으로 받기로 했습니다. 그 전에 앱 아이콘 등록, 본인인증, 비즈 앱 전환 신청이 필요합니다.
  • 회원 부가 기능별명·프로필 사진 보이기(염두에만), 만 14세 미만 가입, 이메일·비밀번호 직접 가입, 네이버·카카오 계정 한 계정에 묶기, 폰 앱 로그인.

7인기 도서(사이클 10)에서 빼 둔 것

사이클 10을 개발해서 써 본 뒤 고르면 됩니다.
  • "전자책 없음"일 때 그 도서관의 희망도서 신청 페이지로 바로 가는 링크
  • 지난달 순위 다시 보기 (받은 값은 이미 남겨 둠)
  • 제목과 저자로 전자책을 더 많이 찾기순위 목록에는 저자가 없어서 국가서지에서 ISBN으로 저자를 찾아야 합니다.
  • 매달 순위 받기가 실패하면 메일 등으로 알려 주기
  • 서버가 여러 대가 되면 매달 받기가 두 번 돌지 않게 막기
