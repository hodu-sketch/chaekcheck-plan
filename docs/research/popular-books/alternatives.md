## 1. 도서관 정보나루 인기대출도서 [확정] (2026-10-12 확인)

- API 목록: https://www.data4library.kr/apiUtilization — "인기대출도서 조회"(`loanItemSrch`) 있음. 회원가입 뒤 인증키 신청, 승인 후 사용
- 데이터 화면: https://data4library.kr/loanDataL
  - 이용허락조건: "저작자표시(BY)" — 출처를 밝히면 상업적 이용도 허용되는 조건으로 읽음 [안: 해석. 공공누리·CC 문구가 페이지에 따로 없음]
  - 갱신: 일간
  - 거르는 조건: 기간(금년·금월·금주·기간설정), 성별, 연령, 지역(광역시도·세부지역), 주제(KDC), 도서구분(전체·큰글씨·국외), ISBN 부가기호
  - 결과 건수 옵션 200·500·1000
  - 전자책이 들어 있는지 설명 없음. 사이클 01 기록은 "실물 도서관만" (`docs/backlog.md`) [확인 필요: API 호출 시험]
- 호출 제한: 2023-11-20부터 1일 30,000건 (https://www.data4library.kr/noticeV?cn=194, 2023-11-10 공지)
- 개인도 키를 받을 수 있는지: 신청 화면에 사용 목적을 적는다는 개인 블로그 글만 있음 [확인 필요: 사용자가 가입·신청]
- **쓰지 않음** [확정] (사용자, 2026-10-12: "아동 도서가 20대 30대 무슨 필터를 걸어도 너무 많아서 쓸 수가 없어"). 2026-10-11 결정 "알라딘/정보나루 안 할 거야"와 같음

## 2. 전자도서관 사이트의 인기순 목록 [확인 필요: API 호출 시험]

- 교보 구독형·교보 기관 목록: `{base}/content/contentList.ink?cttsDvsnCode=001&contentAll=Y&ctgrId=&orderByKey=loanNmvl&pageIndex=1&recordCount=20` — 정렬 값 `loanNmvl`(인기순)은 2026-09-30 조사에 있음 (`../ebook-catalog/platforms.md` 3절). 줄마다 "대출 : X/Y 예약 : Z"
- 교보 일반: 정렬 값이 구독형과 같다고 적혀 있음 (같은 문서 2절)
- YES24: 검색 `sort=lending` (같은 문서 4절). 검색어 없이 전체 목록을 대출순으로 받을 수 있는지 모름
- 북큐브·알라딘 전자도서관: 인기순 정렬 조사 안 함
- 2026-10-12 세종 구독(`sejonglib.dkyobobook.co.kr`)에 1건 호출을 시도했으나 이 세션에서 연결 실패. 이 사이트는 옛 TLS 설정이 필요한데(같은 문서 0절) 이 세션에서는 그 설정으로 호출할 권한이 없었음. 수집 PC(`chaekcheck-data`)에서 시험해야 함
- 생각할 점 [안]
  - 순위가 도서관마다 따로임. 구독형(대여)은 같은 교보 구독 목록을 여러 도서관이 함께 쓰므로, 구독 사이트 한두 곳의 인기순이 사실상 "교보 구독 전자책 인기 순위"일 수 있음 [확인 필요: API 호출 시험 — 두 구독 사이트의 1쪽 비교]
  - "인기순"이 누적 대출 수인지 최근 기간인지 모름 [확인 필요: API 호출 시험 — 신간이 위에 오는지]
  - 사이트 이용 조건은 지금 목록 수집과 같은 처지. robots.txt 기록 방침은 사이클 13에서 정함
