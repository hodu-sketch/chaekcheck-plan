## 7. ADR 초안 (다음 사이클이 번호를 붙여 씀)

```
# ADR-NNNN: 도서관 이름에는 기관 이름만, 업체·대출 방식은 분류 칸으로

Status: Proposed
Date: 2026-10-11
Supersedes: ADR-0017의 "이름이 겹치지 않게 '(구독)' 등을 붙임", 사이클 07 design-delta seed 규칙의 "이름" 줄

## 배경
같은 기관이 사이트를 둘 이상 운영하면 두 번째 사이트 이름에만 괄호가 붙었다. 붙는 말이 업체((YES24) 30곳), 대출 방식((구독) 13곳), 그 밖의 것((교육청산하), (sam) 등)으로 제각각이고, 사이클 07에서는 (교보, 호스트)까지 붙었다. 괄호 없는 쪽이 어느 업체인지는 넣은 순서로 정해져 화면에서 알 수 없었다. 서비스 DB에는 이미 화면 종류(platform_type)와 대출 방식(lending_model) 칸이 있다.

## 결정
- 이름에는 기관 정식 이름만 둔다. 업체·대출 방식을 뜻하는 괄호 표시는 뗀다(기관 이름의 일부인 괄호는 남긴다).
- 모든 도서관에 업체(교보·YES24·북큐브·알라딘·통합 포털·자체)와 대출 방식(소장·구독·대여·혼합)을 채운다.
- 겹치면 안 되는 것은 (이름, 업체, 대출 방식) 조합이다.
- 그래도 겹치면 다른 기관은 정식 이름으로 나누고, 같은 사이트는 받지 않음으로 표시한다.
- 화면에서는 이름 옆에 분류를 작게 붙인다.

## 이유 (사용자 발언)
- "이름을 ( ) 하지 말고 따로 분류 칸을 만들어서 이름 + 분류 조합으로 unique하게 하는게 어떨까 해" (2026-10-11)
- "각 전자도서관마다 분류를 꼭 했으면 해 어떤 것만 따로 분류 ( ) 안에 붙는게 이상해서" (2026-10-11)

## 검토한 대안
### A안: 이름 + 업체·대출 방식 분류 칸, 조합 UNIQUE (채택)
- 장점: 모든 도서관이 같은 방식으로 분류됨, 화면에서 업체·방식이 늘 보임, 이미 있는 칸을 씀
- 단점: 이름 약 279줄을 고침, 대출 방식이 없는 도서관을 채워야 함, 통합 포털의 대출 방식을 정해야 함
### B안: 글로 적는 "분류" 칸 하나 (예 "교보 구독")
- 장점: 단순함
- 단점: 적는 방식이 다시 제각각이 될 수 있음
- 채택하지 않은 이유: [이유 미확인] (사용자가 A안을 승인)
### C안: 지금 괄호 규칙 유지, 앞으로만 새 규칙
- 단점: 화면에 두 방식이 섞임
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 서비스 seed의 이름과 UNIQUE 제약이 바뀐다. 도서관 번호는 그대로다.
- 겹침 시험(2026-10-11, 2,917곳)에서 남은 4묶음은 정식 이름·받지 않음·대출 방식 값으로 푼다.
```
