수집 일을 셋으로 나누고,
섞여 있던 도서관 정보 도구를
"도서관 정보" 쪽으로 옮깁니다.

정할 것은 다섯 가지입니다. 원본은 docs/research/maintenance/collection-areas.md입니다.

1지금 무엇이 섞여 있나

"어느 도서관이 있나"를 찾는 일과 "구독형이 마감됐나"를 보는 일이, 책 목록 수집기 폴더(chaekcheck-data, git 밖)에 함께 들어 있습니다.

그 결과 도서관 목록도 둘이 됐습니다. 서비스 도서관 278곳(dev seed)과, 웹러브 북스에서 찾아 수집 DB에만 있는 기관 2,738곳(번호 100001~)입니다. 두 번째 목록은 다 받아도 서비스 검색에 나오지 않습니다.

2정할 것

나눔, 옮길 곳, 이름, 문서 정리, 알릴 것입니다.

1수집 일을 셋으로 나눔: ① 도서관 정보, ② 도서관-책, ③ 가져오기 [안]

dev docs/maintenance/의 1-libraries.md, 2-crawl.md, 3-import.md와 같은 나눔입니다. 구독 규칙과 마감 확인은 책이 아니라 도서관에 대한 정보라 ①에 넣습니다.

다른 선택: 마감 확인을 ④로 따로 둠(일이 하나 늘고, 구독 규칙과 따로 놀게 됨).

2웹러브 북스 기관 찾기와 마감 확인 스크립트는 dev scripts/library/로 옮김 [안]

책 수집기를 dev로 옮길 때(전체 수집이 끝난 뒤) 함께 옮깁니다. 절차는 dev 1-libraries.md에 "수집 전용 기관 찾기", "구독 규칙·마감 확인" 절로 넣습니다. 조사 기록과 결정은 plan에 남습니다(library-limits/research.md, crawl-runbook.md 8절).

다른 선택: 책 수집기와 함께 scripts/crawl/로(코드가 한곳이지만 ①·② 구분이 흐려짐).

3도서관 목록 둘을 "서비스 도서관"과 "수집 전용 기관"으로 부름 [안]

문서마다 이 두 이름을 씁니다. "수집 전용 기관"을 서비스로 넣는 일은 backlog의 다음 사이클 후보 그대로입니다.

다른 선택: 지금처럼 "웹러브 북스 기관"(출처 이름이라 나중에 다른 출처가 생기면 맞지 않음).

4plan 문서와 링크를 이 나눔에 맞춰 고침 [안]

plan reference-index.md의 절을 ①②③에 맞춥니다. periodic-tasks.md, crawl-runbook.md, library-limits/research.md, catalog-refresh.md 머리말에 dev 위치를 링크합니다. 오늘 바뀐 상태(흐름 6·7 구현, 첫 가져오기, 교보 대여·혼합 수집 등)로 낡은 표시를 고칩니다. dev 문서는 plan이 쓸 수 없으니 요청서로 넘깁니다.

다른 선택: dev가 옮기기를 마친 뒤 한 번에(그동안 문서끼리 어긋남).

5알릴 것은 둘: dev 요청서 하나와 다음 plan 세션용 메시지 하나 [안]

dev: ADR-0047 요청서에 "C. 도서관 정보 도구 옮기기"와 "오늘 바뀐 수집기 기능 목록"(IP 줄 세우기, 서버별 동시 요청 수, 이어 받기, 알라딘·북큐브 고친 것 등)을 더하고, 붙여 넣을 메시지를 새로 만듭니다. plan: 오늘 정한 것(책 번호 유지, 구독형 한도, 수집 나눔, 교보 대여·혼합 수집, 도서관-책 매핑이 중요하다는 원칙)을 한 장으로 묶은 메시지를 만듭니다. 사용자가 각 세션에 붙여 넣습니다.

다른 선택: 주제마다 메시지를 따로(책 번호 유지 메시지는 이미 있음. 붙여 넣을 것이 많아짐).
