2. **웹러브 북스 기관 찾기와 마감 확인은 ①로** [확정] (사용자 승인, 2026-10-04): 스크립트는 dev `scripts/library/`로 옮기고(책 수집기와 함께 B 때), 절차는 dev `1-libraries.md`에 "후보 도서관 찾기", "구독 규칙·마감 확인" 절로 넣음. 조사 기록과 결정은 plan(`docs/research/library-limits/`, `crawl-runbook.md` 8절)에 남음
3. **도서관 목록이 둘임을 이름으로 구분** [확정] (사용자 승인, 2026-10-04, 후보 4개 중 1번): **"등록 도서관"**(서비스 DB `library`, dev seed, 278곳, 검색에 나옴) / **"후보 도서관"**(수집 DB `library` 번호 100001~, 2,738곳, 책은 모으지만 아직 검색에 안 나옴). 이전 경과: 처음 제안 "서비스 도서관" / "수집 전용 기관"은 미승인 (사용자: "무슨 뜻인지 이름이 직관적이지 않아 뭘 말하고 싶은 거야? 적합한 여러 이름 후보좀", 2026-10-04). 이름 후보는 `easy/2026-10-04-library-list-names-decisions.html`에서 다시 정함. 구분할 두 목록: 서비스 DB `library`(dev seed, 278곳, 검색에 나옴) / 수집 DB `library` 번호 100001~(웹러브 북스에서 찾음, 2,738곳, 책은 모으지만 검색에 안 나옴). 두 목록을 잇는 일(후보 도서관을 등록 도서관으로 옮기기)은 backlog 다음 사이클 후보 그대로
4. **문서·링크 정리** [확정] (사용자 승인, 2026-10-04): plan 쪽은 `reference-index.md`에 ①②③ 절을 맞추고, `periodic-tasks.md`·`crawl-runbook.md`·`library-limits/research.md`·`catalog-refresh.md` 머리말에 dev 위치를 링크. 낡은 표시를 고침. dev 쪽 고칠 것은 요청서로

## 2-1. 서비스에서 두 목록을 담는 방향 (2026-10-04)

계기: 사이클 06(내 도서관)에서 사용자가 도서관을 직접 골라 넣을 수 있게 됨 → 사용자: "가져오기는 그러면 이제 서비스 db도서관 표에 있는 도서관의 책만 옮기지 않고 다 옮겨야 하지 않나 어짜피 지금 내 도서관으로 도서관 선택해서 넣을 수 있게 되었는데", "테이블을 분리해서 넣으면 되는 거 아니야? 지역/직장 조건 있는 도서관이랑 아닌 도서관" (2026-10-04)

- **방향 [확정]** (사용자: "'나'로 하도록 하고 직장/거주 없는 도서관들은 따로 '내 도서관'에서 등록하지 않은 한 기본적으로 안 보였으면 해 요청도 보내지 말고", 2026-10-04): 도서관은 **한 표**(모든 전자도서관 사이트: 이름·주소·화면 종류·켜짐)에 두고, **가입 조건(지역·직장·누구나·방문 가입)은 따로 떼어** 조사한 도서관만 줄을 둠. 구독 규칙도 따로(`docs/research/library-limits/research.md` 4절과 같은 생각). 소장·대출 조회·가져오기는 도서관 표만 봄
- **보이는 규칙 [확정]** (같은 말): 가입 조건 줄이 **없는** 도서관은 그 사용자가 **내 도서관에 넣지 않았으면 검색 결과에 나오지 않고, 그 도서관 사이트로 요청도 보내지 않음.** 가입 조건 줄이 있는 도서관(지금 등록 도서관 278곳, "누구나 가입" 포함)은 지금처럼 지역·직장으로 판정해 검색에 넣음
- 그러면 가져오기는 모든 도서관의 책을 옮김(지금은 서비스 DB 도서관 표에 있는 278곳만). 크기를 먼저 재야 함: 서비스 DB 소장 지금 약 495만 줄 → 후보 도서관 포함 약 1,900만 줄 이상, 교보 대여·혼합형을 다 받으면 약 6,000만 줄(대여형은 같은 책 목록이라 책 수는 거의 그대로) [확인 필요: 프로토타입]
- 내 도서관에서 고르는 목록이 278곳 → 약 3,000곳이 되어 서버 이름 검색이 필요(ADR-0049 "감수하는 점"이 예상한 일)
- 북큐브·알라딘(약 480곳)은 대출 상태를 실시간으로 읽는 코드가 없음 → 그 코드를 만들거나 "목록에 있음"까지만 보여 줌 [확인 필요: 사이클에서 결정]
- 표 이름·칸·API는 그 사이클의 `design-delta.md`와 ADR에서 정함(사이클 06 ADR-0049 등과 맞춤)
- "등록 도서관 / 후보 도서관"은 지금 상태(서비스 DB에 있나)를 부르는 이름. 이 방향으로 만들고 나면 둘 다 서비스 도서관 표에 들어가고, 구분은 "가입 조건이 있는 도서관 / 없는 도서관"이 됨
