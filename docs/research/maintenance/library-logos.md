# 도서관 로고 수집 (2026-10-05 시작)

- 사용자 요청: "도서관 로고도 같이 수집했으면 해... 이거 모은 도서관 이름이랑 도서관이랑 같이 좀 매핑하고 수집하고 다른 PLAN에게 알려줄 말 만들어줘" (2026-10-05)
- 성격: ① 도서관 정보 수집(`collection-areas.md`). 서비스에서 어떻게 보여 줄지(화면·표)는 사이클에서 정함
- 도구: `chaekcheck-data/scripts/probe_logos.py` (git 밖. dev로 옮길 때 `scripts/library/`, 요청서 C와 같은 자리)
- 결과: `chaekcheck-data/logos/<library_id>.<확장자>` 그림 파일과 `chaekcheck-data/logos/logos.tsv` 매핑 표

## 1. 매핑 표 `logos.tsv`

| 칸 | 뜻 |
|---|---|
| `library_id` | 수집 DB `library.id` (등록 도서관 1~280 = 서비스 도서관 번호와 같음, 후보 도서관 100001~) |
| `name`, `platform_type`, `base_url` | 수집 DB의 도서관 이름·화면 종류·주소 |
| `logo_url` | 로고를 받은 주소 |
| `file` | 저장한 파일 이름 (`<library_id>.png` 등). 비어 있으면 못 받음 |
| `bytes`, `sha256`, `content_type` | 파일 크기, 같은 그림을 찾는 지문, 형식 |
| `note` | 못 받은 이유, 또는 "footer logo (no header img)"(머리말 그림이 없어 바닥글 로고를 받음) |
| `checked_at` | 받은 시각 |

다시 돌리면 로고를 못 받은 도서관만 다시 시도함(그 도서관의 가장 최근 줄이 유효).

## 2. 로고가 있는 곳 (2026-10-05 표본 확인)

| 화면 종류 | 로고 위치 |
|---|---|
| 교보 구독형·소장형·대여형 (`KYOBO_SUBSCRIPTION_V1`) | `{주소}/main/headerLogo.json`의 `upendLogo1Path`·`upendLogo1Name` → `{주소}/util/imageDisplay.ink?libraryCode=&target=toplogo&imagePath=` |
| 교보 일반 (`KYOBO_V1`) | `{주소}/elibrary-front/main/headerLogo.json` → `{주소}/elibrary-front/util/imageDisplay.ink?…` |
| YES24·북큐브·알라딘·통합 포털·강남구 | 첫 화면의 머리말 그림(그림 주소·대체 글·class나 부모에 "logo"가 들어간 것, 바닥글 제외). 머리말을 CSS로 그리는 곳(부산 포털 등)은 바닥글 로고를 받고 note에 적음 |

예의: 수집기와 같이 IP 하나에 한 줄, 한 번에 1건, 요청 사이 2초. 도서관마다 요청 1~2건. 수집기와 동시에 돌아서 같은 서버에 잠깐 요청이 하나 더 갈 수 있음(교보 대여·혼합형 서버는 수집 4건 + 로고 1건).

## 3. 알게 된 것 (표본 50곳쯤, 2026-10-05 08:30)

- **업체 기본 로고**: 교보 일반 화면 중 일부(경기과천교육도서관, 부산대표도서관, 군산시립, 경상남도대표도서관, 서울시교육청, 경남교육청 등)는 도서관 로고 대신 "KYOBO 교보문고" 기본 로고를 걸어 둠. 같은 그림(sha256 앞 8자리 `fb770784`)이 여러 도서관에 나옴 → 수집이 끝나면 여러 도서관이 같은 그림이면 "업체 기본 로고"로 따로 표시하고 도서관 로고로 쓰지 않음 [안]
- 교보 일반 화면 중 일부는 `headerLogo.json`에 로고가 없거나(김포시립, 경기도서관, 성동구립 등) 빈 파일(계양, 고창공공, 무주공공, 고성)을 줌 → 그 사이트에는 로고가 없음
- 실패: 사이트 주소가 없어진 곳(404), 응답 없는 곳(경기도교육청 포털 시간 초과) — 다시 돌릴 때 다시 시도

|---|---|---|
| `OWN` | 199 | 그 도서관 로고가 있음. 전자도서관 머리말에서 187곳, 본 홈페이지에서 12곳 |
| `VENDOR_DEFAULT` | 43 | 전자도서관에 업체 기본 로고만 있음(교보 "KYOBO 교보문고" 등. 같은 그림이 3곳 이상) |

`NONE`의 이유:
- 사이트가 로고 칸을 비워 둠
- 화면이 가리키는 로고 파일이 서버에 없음(404)
- 책 수집에서 빠진 4곳
- 본 홈페이지에서 받은 것이 도서관 로고가 아님
  - 영도구·창녕군·연제구: 구·군 상징
  - 인천시 통합전자도서관: 다른 도서관 로고
  - 이 넷은 상징물 조례 대상이고 "공공도서관 로고만"에도 맞지 않아 뺌

본 홈페이지에서 받는 방법(`chaekcheck-data/scripts/probe_home_logos.py`):
- 본 홈페이지 주소는 dev 도서관 seed의 `join_url`(가입 안내 주소)에서 가져옴. 전자도서관 화면에는 본 홈페이지 링크가 없음
- 그 홈페이지 머리말 그림을 받고, 받은 그림은 눈으로 확인함
- 아직 못 받은 곳:
  - 교육청 통합 홈페이지(전북·경기·인천·경남): 로고를 그림 파일이 아닌 방식으로 그림
  - `join_url`이 없는 18곳
  - 받는 방법은 아직 정하지 않음 [확인 필요]

`VENDOR_DEFAULT` 판단 기준:
- 같은 그림이 3곳 이상이면 업체 기본 로고로 봄 [안]
- 수집이 끝난 뒤 사용자에게 물을 예정이었으나, 등록 도서관만 받기로 해서 지금 값으로 둠

## 4. 로고를 서비스 화면에 써도 되는지 (조사 2026-10-05, 법률 자문 아님)

  - 웹사이트에 공개돼 있다는 것은 저작권법상 "공표"이지 "이용 허락"이 아님

## 5. 확인 필요

| 항목 | 방법 |
|---|---|
| 공공도서관인지 아닌지 (로고를 보여 줄 범위) | 도서관 종류 분류 (`docs/research/library-join/`의 후보 도서관 조사, 사이클에서 확정) |
