# 회원 → 알림 밑그림 (사이클 시작 전 메모)

작성 2026-10-01. 설계 문서가 아닙니다. 2026-10-01 사이클 05 `docs/cycles/05-login-account`(로그인·계정)가 시작됨. 이 문서의 "회원 사이클"은 사이클 05(계정)와 06(내 도서관)으로 나뉘었고, "알림"은 사이클 07입니다 (`integration-plan.md`). 사용자가 말한 목적과 그것을 받치는 최소 구조를 [안]으로 적어 두고, 사이클을 시작할 때(`/cycle-start 회원`) 이 문서에서 범위를 잘라 냅니다. 큰 틀만 잡고 세부는 사이클에서 정합니다 (사용자: "큰 틀을 먼저 잡고 디테일한 부분은 나중에 하려고 해", 2026-10-01).

## 1. 왜 회원인가 (사용자 말, 2026-10-01)

- "회원이 있는 이유는 직장/거주지 지역이라던가 알아서 도서관 매핑해주기 위함이야"
- "본인 거주지/지역과 상관없이 특정 도서관도 '내 도서관'에 넣는 거 생각 중이야"
- "'내 도서관' 자료만 찾을 수 있는 거지"
- 다음 사이클: "'알림' 기능 원하는 책이 입고되어서 빌릴 수 있게 되면 알리는 기능"

지금(사이클 04까지)은 회원 없이 브라우저가 지역(`residenceRegionIds`, `workRegionIds`)을 주소와 브라우저 저장소에 들고 있습니다. 회원은 이것을 서버에 저장하고, 거기에 "직접 고른 도서관"을 더하는 것입니다.

## 2. 회원 사이클 밑그림 [안]

### 2.1 저장하는 것 (최소)

| 무엇 | 값 | 비고 |
|---|---|---|
| 소셜 계정 | 제공자(`NAVER`/`KAKAO`) + 제공자 쪽 사용자 식별자 | 비밀번호 없음. 이메일·이름 등 프로필은 **받지 않거나 저장하지 않음** [안] (최소 수집, `signup-security.md`) |
| 지역 자격 | 거주지·직장 시군구 코드 (여러 줄) | backlog "회원" 절의 `member_region(member_id, kind, region_code)` [안]. 지역 ID는 `region` 모듈 ID (ADR-0003) |
| 내 도서관 | 직접 고른 `library.id` 목록 | 지역과 무관하게 추가. 자동 매핑된 도서관을 빼는 것도 여기서 [안, 확인 필요: 뺄 수 있게 할지] |

- 모듈은 `auth`(계정·로그인·세션·탈퇴, 05a)와 `member`(지역·내 도서관, 05b) 둘 [확정: 사용자 선택 2026-10-01, `integration-plan.md` 3.1]. 지역 코드와 도서관 ID만 저장하고, 도서관 정보는 `LibraryCatalog` 공개 API로 읽습니다 (모듈 간 JOIN 금지, backlog "회원" 절, ADR-0001).
- 대학·회사 소속 자격(`institution`)은 이번에 넣지 않음 [안]. backlog "회원" 절의 별도 항목.

### 2.2 "내 도서관"의 정의 [안]

**내 도서관 = 자동 매핑(거주지·직장 지역으로 가입 가능한 도서관) ∪ 직접 추가한 도서관.** 하나의 목록으로 보이고, 줄마다 "지역으로 자동" / "직접 추가" 표시만 다릅니다.

- 자동 매핑은 지금 `planSearch`가 하는 판정(`joinable()` = `OPEN`/`ELIGIBLE`, ADR-0013·0027)을 그대로 씁니다. 새 판정 규칙을 만들지 않습니다.
- 지역을 바꾸면 자동 매핑 부분이 따라 바뀌고, 직접 추가한 것은 남습니다.

### 2.3 검색 필터: 단순하게 하나만 [안, 추천]

사용자 질문: "'내가 가입할 수 있는 도서관' '내가 설정한 도서관' 이렇게 필터링을 해야 할까.. 난 좀 단순했으면 하는데"

| | 안 A (추천) | 안 B |
|---|---|---|
| 필터 | **"내 도서관만" / "전체"** 스위치 하나 | "가입 가능한 곳" / "직접 고른 곳" / "전체" 세 가지 |
| 내 도서관 뜻 | 자동 매핑 ∪ 직접 추가 (2.2) | 둘을 따로 봄 |
| 장점 | 고를 것이 하나. 지금의 `scope=JOINABLE`("가입 가능한 곳") 자리에 그대로 들어감. 직접 추가한 곳이 "가입 가능한 곳"과 다른 필터에 숨지 않음 | 직접 고른 곳만 따로 볼 수 있음 |
| 단점 | 직접 고른 곳만 따로 보려면 목록 화면(설정)에서 봐야 함 | 필터 셋 + 기존 `visit`(방문 없이 가입) 필터까지 겹쳐 복잡함. "직접 고른 곳"이 비어 있으면 빈 필터가 하나 생김 |

- 안 A에서 기존 필터와의 관계 [안]: 로그인 전 `scope=JOINABLE`(지역 기준 가입 가능) → 로그인 후 같은 자리가 "내 도서관만"이 됨. `visit=none`(방문 없이 가입)은 그대로 둠. 기본값은 로그인하면 "내 도서관만" [안, 확인 필요: 사용자에게 질문].
- 직접 추가한 도서관은 자격 판정과 무관하게 "내 도서관"이므로, 결과 정렬의 가입 단계(`joinTier`)에서 어디에 두는지 정해야 함 [확인 필요: 사이클에서 결정. 후보: 자동 매핑과 같은 단계 / 맨 앞].

### 2.4 화면 (큰 틀)

- 로그인(네이버·카카오 버튼) → 처음이면 지역 입력(지금 화면 재사용) → 검색 화면. 설정 창에 "내 도서관" 목록(자동/직접 표시, 추가·삭제)과 계정(연결 끊기·탈퇴).
- 로그인 없이도 지금처럼 쓸 수 있음 [안]. 회원은 "저장"만 더해 줌.

### 2.5 회원 사이클에서 정할 것 (확인 필요)

- 자동 매핑된 도서관을 목록에서 뺄 수 있게 할지 → 사용자에게 질문
- 로그인 후 기본 필터 → 사용자에게 질문
- 직접 추가 도서관의 정렬 위치 → 사용자에게 질문
- 탈퇴 시 삭제 범위·시점, 소셜 연결 끊기 처리 → `signup-security.md` 3절 5·6번 근거로 사이클에서 결정
- 세션 방식(서버 세션 쿠키 vs 토큰)과 만료 → `signup-security.md` 3절 8번 근거로 사이클에서 결정 (제안: 서버 세션)
- 만 14세 미만 정책 ("만 14세 이상만 가입" 확인란 [안]) → 사용자에게 질문 (`signup-security.md` 3절 14번)
- 운영자가 「소상공인기본법」상 소상공인인지(보호책임자 지정 방식이 달라짐) → 사용자에게 질문 (`signup-security.md` 3절 13번)
- 네이버·카카오 PKCE 지원 여부 → 프로토타입 호출 시험

## 3. 알림 사이클 밑그림 [안]

목적: "원하는 책이 입고되어서 빌릴 수 있게 되면 알리는 기능".

### 3.1 필요한 조각

1. **관심 책 저장** — 회원이 책(`catalog.book`)을 표시해 둠. 회원 모듈이 `book_id`만 저장 [안].
2. **"빌릴 수 있게 됨"을 아는 방법** — 지금은 사용자가 검색할 때만 도서관 상세 페이지를 읽습니다(ADR-0029). 알림은 사용자가 없을 때 서버가 스스로 확인해야 합니다. 두 갈래 [안]:
   - (가) 관심 책이 있는 도서관의 상세 페이지를 주기적으로 읽음 — 호출 예의(같은 호스트 1초 간격, ADR-0010)와 요청 수가 문제. 관심 책 수 × 도서관 수만큼 요청이 생김 [확인 필요: 규모 추정]
   - (나) 책 목록 주기 갱신(backlog, 별도 사이클 확정)과 합침 — 갱신할 때 얻는 정보로 판단. 단, 갱신은 소장 목록이지 대출 상태가 아닐 수 있음 [확인 필요: `catalog-refresh.md`에서 무엇을 갱신하는지]
   - "입고"(새로 소장됨)와 "반납되어 대출 가능"은 다른 신호. 사용자가 어느 쪽을 뜻하는지 [확인 필요: 사용자에게 질문]
3. **전달 수단** — 이메일, 카카오 메시지, 웹 푸시 중 무엇을 쓸지 [확인 필요: 공식 문서 확인 — 각 수단의 발송 조건·비용·검수]. 수단마다 저장해야 하는 연락처(이메일 주소, 카카오 동의 항목)가 생기고, 이것은 개인정보 수집 범위를 넓혀 재동의가 필요함 (`signup-security.md` 3절 15번). 카카오 이메일 동의항목은 비즈 앱에서 설정함. 처음에는 "사업자 정보가 있어야 해서 개인은 못 받을 수 있다"고 적었으나 **틀린 추정이었음**: 개인도 본인인증만으로 "개인 개발자 비즈 앱"으로 전환할 수 있음(사업자등록번호 불필요). 2026-10-03 확인, `docs/cycles/05-login-account/research.md` 7절. 개인 개발자 비즈 앱에서도 이메일 필수 동의가 되는지는 [확인 필요: 전환 뒤 동의항목 화면].
4. **중복·해제** — 한 번 알린 뒤 다시 알릴지, 알림 끄기.

### 3.2 회원 사이클이 알림을 위해 미리 열어 둘 것 [안]

- 회원 모듈이 "회원이 표시한 것"(도서관, 책)을 같은 모양으로 저장할 수 있게 표 이름과 키를 정할 때 책도 염두에 둠. 단, 알림 표는 알림 사이클에서 만듦(스코프 가드).
- 연락처는 회원 사이클에서 받지 않음 [안]. 알림 사이클에서 필요한 수단이 정해진 뒤 동의와 함께 받음.
