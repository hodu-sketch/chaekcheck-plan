# 전자책 목록 DB 사전 수집 — 조사

- 작성: 2026-09-30
- 성격: 사이클 밖 사전 준비 자료입니다. 이 문서로 모듈·테이블·API를 정하지 않습니다. 실제 설계는 이 기능을 다루는 사이클의 `design-delta.md`에서 합니다 (`.claude/rules/scope-guard.md`).
- 요청 (사용자, 2026-09-30): "복합 검색을 하려고 하는데 (책이름, 저자, 출판사) 전자책 데이터베이스는 어디를 봐도 없어", "크롤링한 데이터베이스를 미리 가지고 있는게 어떨까 해 조사해서 알려주고", "수집하되 수집된 날짜(실시간성)을 기록해줘", "대부분의 항목들을 일정하게 구조화해서 수집하면 좋겠는데"
- 크롤링 방법은 따로 `crawl-method.md`에 적었습니다. 이 조사의 결정은 ADR-0034(목록 저장)·ADR-0028(catalog 모듈)에 기록했고, 실제 설계는 `docs/cycles/04-and-search/design-delta.md`입니다. 문서 색인: `docs/reference-index.md` 3절 (2026-10-01)

## 3. 법적 쟁점 — 전체 목록을 모으면 달라지는 점

사이클 01은 "검색할 때 수량만 읽고 쌓아 두지 않음"으로 저작권법 제93조를 피했습니다(사이클 01 spec 10장). 전체 목록 수집은 정확히 "반복적·체계적 복제"에 해당하므로 다시 판단해야 합니다.

| 근거 | 내용 | 확인 |
|---|---|---|
| 저작권법 제93조 (데이터베이스제작자의 권리) | 전부 또는 상당한 부분의 복제 금지. 상당하지 않은 부분도 반복적·체계적으로 복제해 통상적 이용과 충돌하면 상당한 부분으로 봄 | 사이클 01 spec 10장 |
| 대법원 2022. 5. 12. 선고 2021도1533 (야놀자 v. 여기어때, 형사) | 크롤링에 대해 정보통신망침해·DB제작자 권리 침해·업무방해 모두 무죄. 이유: API 주소를 쉽게 알 수 있었고 보호 조치가 없었음, 복제한 부분이 양·질적으로 상당하지 않음 | https://klep.or.kr/board/weeklys/article/133699, https://www.lawtimes.co.kr/news/articleView.html?idxno=182087 (확인 2026-09-30) |
| 서울중앙지법 2021. 8. 19. 선고 2018가합508729 (같은 당사자, 민사) | 경쟁사 DB를 약 9개월간 체계적으로 가져간 행위를 부정경쟁방지법 제2조 제1호 카목(성과 도용)으로 보고 10억 원 배상. DB 권리 판단은 따로 하지 않음 | https://www.law.go.kr/LSW/precInfoP.do?precSeq=226943 (확인 2026-09-30). 상급심 결과는 확인하지 않음 [확인 필요] |

chaekcheck에 맞춰 본 점 [안] (법률 판단이 아님. 출시 전 전문가 확인 [확인 필요]):

- 도서관·플랫폼과 경쟁 관계가 아니고 이용자를 도서관으로 보내는 서비스라는 점은 유리한 쪽
- 전체 목록을 주기적으로 모으는 것은 "상당한 부분"에 해당할 가능성이 큼 → 위험을 줄이는 방법:
  - 사실 정보(제목·저자·출판사·출간일·소장 여부)만 저장하고, 책 소개글·저자 소개·목차·서평 같은 창작 문장은 저장하지 않음
  - 표지 이미지는 파일로 받지 않고 주소만 저장 (보여 줄지는 사용자 결정)
  - 책마다 원래 도서관 상세 페이지로 링크
  - 비영리 공개 (사이클 01 결정 유지)
- 웹러브 북스처럼 **남이 모은 DB를 가져오는 것**은 그 운영자의 DB 제작자 권리와 성과 도용 문제가 겹침 → 하지 않음 [안]
