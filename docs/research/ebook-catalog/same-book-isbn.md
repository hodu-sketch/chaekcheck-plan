## 3. 수집 데이터의 교보식 코드 → 종이책 ISBN

- 규칙 [안]: 교보식 코드 `480` + 9자리(t) + 확인 숫자. t가 `89`로 시작하면 `978`+t, `11`로 시작하면 `979`+t를 붙이고 ISBN-13 확인 숫자를 다시 계산함. 교보 코드의 마지막 숫자는 항상 `978`+t 기준 확인 숫자라서 `979` 책은 한 자리가 다름
- 확인한 예 (검색 결과 기준 2건 + 국가서지 표본 대조 10건, 4.1절): 「작별하지 않는다」 `4808954682152` → `9788954682152` (https://isbnsearch.org/isbn/9788954682152), 「미국은 왜 전쟁을 멈추지 못하는가」 `4801175780096` → `9791175780095` (종이책 ISBN, 검색 요약). 둘 다 종이책 ISBN
- 처음에 "978·979 중 확인 숫자가 맞는 쪽"으로 셌다가 979 책에서 틀린 것을 발견해 위 규칙으로 고침
- 적용 결과 (`removed_at IS NULL`, 284.3만 줄, 2026-09-30): 90.0만 줄(약 32%), 서로 다른 코드 20.3만 개 → 서로 다른 ISBN 17.2만 개. 북큐브 줄은 `alt_code`(교보식 코드)로 계산
- 한국 ISBN이 아닌 교보 코드: `48090…` 3.8만 줄(1.0만 코드, 예 「리멤버. 1」 디키스토리), 교보 확인 숫자가 안 맞는 `480` 코드 4.3천 줄 [확인 필요: 전자책 전용 코드인지]. 재수집 뒤 dry run(2026-09-30 17:58) 수치: 37,678줄 / 5,352줄 (5.1절)
- 나머지 약 68%(YES24 번호, 북큐브 번호, 포털 `AAA:99` 코드 등)는 코드에서 ISBN이 나오지 않음
- 수집 세션이 알려 준 추가 단서 (2026-09-30 10시경, `removed_at IS NULL`) [확인 필요]
  - YES24 사이트에서 교보가 공급한 책은 `goods_id`가 교보식 코드(`480…`) → 25,571줄. `480D231030630`처럼 영문이 섞인 코드는 ISBN 계산 대상이 아님 (교보 구독형 코드에도 `480D…`가 많음)
  - 통합 포털 표지 파일 이름이 ISBN-13인 줄 10,213줄 (예 `…/DRMCon/images/9791194267676.jpg`). 표지 주소에서 나온 값이라 종이책·전자책 ISBN 중 무엇인지 모름
  - 강남구 `book_num`이 `978`·`979`로 시작하는 13자리 96줄
  - 강서(YES24) 10줄, 영주·경산 각 1줄은 예전 파서로 받은 채 남아 `goods_id`가 잘렸을 수 있음
- 규칙 검증: 국가서지 일반도서 전체와 대조해 978·979 모두 약 95% 제목 일치 (4.2절)
- YES24 재수집 전 수치가 섞였을 수 있음 (`search-and-normalization.md` 머리말 주의)

### 4.1 국가서지 LOD 표본 확인 (2026-09-30)

사용자 허락을 받아 표본 두 개만 받았습니다 (`Online_sample.ttl` 6.5MB, `book_sample.ttl` 1.4MB, 각 1,000건, scratchpad에만 저장).

- 온라인자료 표본 1,000건은 모두 장르 "보이스브레일도서"(시각장애인 대체자료, 형식 `application/vbf`, 소장 국립중앙도서관)이고 논문 691·단행본 306건입니다. 도서관 플랫폼의 상업 전자책은 표본에 없습니다. ISBN(`bibo:isbn`)은 309건에 있고 `"89-20-90635-193350"`처럼 ISBN-10과 부가기호가 붙은 글자라 정리가 필요합니다
- 일반도서 표본 1,000건 중 ISBN이 있는 것은 115건이고, `"7500004087 (34)"`처럼 해외 ISBN이 섞여 있습니다. 필드: `dcterms:title`, `nlon:remainderOfTitle`(부제), `dc:creator`, `dc:publisher`, `nlon:datePublished`, `nlon:kdc`, `bibo:isbn`, `nlon:titleOfSeries`, `bibo:volume`
- **교보식 코드 → ISBN 규칙 대조**: 표본 ISBN을 ISBN-13으로 정리(ISBN-10·부가기호 포함 글자 처리)하니 354개였고, 수집 데이터에서 계산한 ISBN 17.3만 개와 **10개가 겹쳤으며 10개 모두 제목·출판사가 같은 책**이었습니다 (예: 「순수이성 비판 서문」 책세상 `9788970133010`, 「전쟁론1」/「전쟁론 1」 갈무리 `9788986114843`, 「바람의 딸 걸어서 지구 세 바퀴 반 1권」/「… 반. 1」 푸른숲 `9788971847473`). 겹친 ISBN은 모두 온라인자료 표본(대체자료가 원본 종이책 ISBN을 적음)에서 나왔고 모두 `978-89`라서, `979-11` 쪽 규칙은 아직 이 방법으로 확인하지 못했습니다
- 표본은 파일 앞부분 일부라 전체를 대표하는지 알 수 없습니다. 지금으로서는 **ISBN 매핑의 기본은 ISBN 서지정보 API**로 두고, 국가서지 파일은 종이책 ISBN 대조가 더 필요할 때 일반도서 전체 파일로 다시 시험합니다 [안]

### 4.3 ISBN 서지정보 API 형식 (공식 안내 페이지, 2026-09-30)

- 요청: `https://www.nl.go.kr/seoji/SearchApi.do` (출판 예정 자료는 `deposit_yn=N`)
- 필수: `cert_key`, `result_style`(json·xml), `page_no`(1부터), `page_size`(최대값 미공개, 초과 시 오류 013)
- 검색: `isbn`·`set_isbn`(앞부분 일치), `title`·`author`·`publisher`·`series_title`(형태소 + n-gram), `start_publish_date`·`end_publish_date`(yyyymmdd), `ebook_yn`, `cip_yn`, `deposit_yn`, `form`(종이책·혼합자료·전자책·오디오북·기타 전자출판물), `sort`(PUBLISH_PREDATE·INPUT_DATE·INDEX_TITLE·INDEX_PUBLISHER), `order_by`
- 응답: `TOTAL_COUNT`, `PAGE_NO`, `TITLE`, `VOL`, `SERIES_TITLE`, `SERIES_NO`, `AUTHOR`, `EA_ISBN`, `EA_ADD_CODE`, `SET_ISBN`, `SET_ADD_CODE`, `SET_EXPRESSION`, `PUBLISHER`, `EDITION_STMT`, `PRE_PRICE`, `KDC`, `DDC`, `PAGE`, `BOOK_SIZE`, `FORM`, `FORM_DETAIL`, `PUBLISH_PREDATE`, `SUBJECT`, `EBOOK_YN`, `CIP_YN`, `CONTROL_NO`, `DEPOSIT_YN`, `BIB_YN`, `RELATED_ISBN`, `TITLE_URL`, `BOOK_TB_CNT_URL`, `BOOK_INTRODUCTION_URL`, `BOOK_SUMMARY_URL`, `PUBLISHER_URL`, `INPUT_DATE`, `UPDATE_DATE`
- 오류: 000 시스템, 010 키 없음, 011 키 틀림, 012 필수 파라미터 없음, 013 쪽당 건수 초과
- 응답 값의 실제 모양(ISBN 하이픈 여부, 날짜 형식, `RELATED_ISBN` 내용)은 인증키 발급 후 확인 [확인 필요]

## 5. 묶기 절차 (사이클 04 구현 기준, 2026-10-01 갱신)

아래는 dev에 구현된 규칙입니다 (`catalog/internal/importer/BookGrouping.java`, dev `docs/plan-feedback.md` `# 사이클 04` 절, 2026-09-30). 앞 단계에서 묶이지 않은 책만 다음 단계로 넘깁니다. 2026-09-30 이전의 [안]은 ①~③만이었고 ④는 "이번에 하지 않음"이었습니다. 개발 중 사용자 결정으로 ④가 들어갔습니다.

1. **같은 플랫폼 코드** [확정: 구현]. 어느 화면 종류끼리 번호를 같이 보는지("번호 체계")는 다음과 같습니다.
   - 한 번호 체계로 묶음: 교보(`KYOBO_V1`), 교보 구독형(`KYOBO_SUBSCRIPTION_V1`), YES24 V1·V2·V3. 다른 도서관이라도 번호가 같으면 같은 책.
   - 그 도서관 안에서만 묶음: 통합 포털 `book_idx`, 강남구 `book_num`. 도서관마다 같은 번호에 다른 책이 붙어 있어 사이트별 번호로 봄.
   - 근거 (2026-09-30 수집 SQLite 대조, 같은 코드끼리 정리한 제목 앞 8글자 비교, 같음/다름): 교보↔교보 구독형 42,714/197, 교보↔YES24 V1 67,038/468, 교보↔YES24 V2 49,328/881, YES24 V1↔V2 30,093/492, YES24 V1↔V3 6,102/602. 포털은 여러 도서관에 있는 `book_idx` 32,449개가 모두 도서관마다 제목이 달랐음. YES24는 같은 화면 종류 안에서도 8.6%(V1·V2)가 제목이 달랐지만 묶음. "다름"은 부제·시리즈 표기 차이가 대부분으로 보임 [확인 필요: 표본은 보지 않음].
   - **점검**: 이 기준은 도서관 목록을 확인할 때마다 같이 점검함 [확정] (사용자: "코드 규칙은 언제든지 달라질 수 있으니 도서관 목록 확인할 때 같이 점검하는 걸로 하면 좋을거 같아 그리고 나중에 반영하고", 2026-09-30). 절차와 기준값 표는 dev `docs/library-maintenance.md` 4-11, 도구는 dev `scripts/library/check_code_spaces.py`. 비율이 얼마나 바뀌면 기준을 바꿀지는 정하지 않음 [확인 필요: 그때 사용자에게 질문].
2. **교보식 코드에서 계산한 종이책 ISBN**이 같으면 플랫폼이 달라도 묶음 [확정: 구현]. 묶음의 ISBN은 가장 많이 나온 값. 지금은 교보식 코드와 계산 ISBN이 1:1이라 ①에서 이미 같은 묶음이고 **②가 새로 합친 책은 없음**(dry run 2026-09-30). 북큐브(`alt_code`)가 들어오면 ②가 일을 하게 됨.
3. **국가서지 일반도서 파일**(4.2절)로 ISBN 붙이기 [확정: 구현]. 키 = 앞 괄호 관제를 뗀 본제목 + 첫 저자 `name_exact` + 끝 `#`을 뗀 출판사(`dc:creator`의 `;`는 `/`로 봄). 키가 국가서지 레코드 하나와만 맞고 그 레코드의 ISBN이 하나일 때만 붙임. 레코드가 여럿이거나 ISBN이 여럿이면 "모호"로 두고 붙이지 않음.
   - 한계: 인기 책은 판마다 ISBN이 달라(예 「작별하지 않는다」 `9788954682152`, `9788954687799`, `9791141601607`) 모호가 되어 ③으로는 ISBN이 안 붙고 ②로만 얻음 (dev plan-feedback 779행).
   - ISBN 서지정보 API(4.3절)는 아직 쓰지 않음(인증키 대기).
4. **정리한 글자로 묶기** [확정] (사용자: "전체 제목+저자+출판사까지 같으면 합침 (추천) 이걸로 해줘", 2026-09-30. 사용자가 먼저 물은 것: "판마다 전자책 내용이 달라질 수 있지 않아?"). ①~③ 뒤에 **정리한 전체 제목**(`title_norm`, 본제목이 아니라 괄호 속 판 표시까지 포함) + 대표 저자(첫 지은이·역할 모름의 `name_exact`) + 정리한 출판사가 같으면 한 권. 저자나 출판사가 없으면 합치지 않음(OCLC 원칙). 합친 책의 ISBN이 여럿이면 하나만 남김.
   - 이유: 같은 작품이 교보·YES24 번호가 달라 여러 권으로 나옴. 예 「작별하지 않는다」(한강, 문학동네) 서비스 소장 98줄이 ①~③ 뒤 4권으로 나뉨(교보 ISBN 74줄, YES24 `103915489` 22줄, 강남구 1줄, YES24 `9788954682237` 1줄).
   - 알려진 한계: 제목에 판 표시가 있으면(「이기적 유전자(40주년 기념판)」, 「…(개정판)」) 따로 남고, 판 표시가 없는 개정판은 원판과 합쳐짐.
