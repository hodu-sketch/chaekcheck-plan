## 3. 수집 데이터의 교보식 코드 → 종이책 ISBN

- 규칙 [안]: 교보식 코드 `480` + 9자리(t) + 확인 숫자. t가 `89`로 시작하면 `978`+t, `11`로 시작하면 `979`+t를 붙이고 ISBN-13 확인 숫자를 다시 계산함. 교보 코드의 마지막 숫자는 항상 `978`+t 기준 확인 숫자라서 `979` 책은 한 자리가 다름
- 확인한 예 (검색 결과 기준, 2건): 「작별하지 않는다」 `4808954682152` → `9788954682152` (https://isbnsearch.org/isbn/9788954682152), 「미국은 왜 전쟁을 멈추지 못하는가」 `4801175780096` → `9791175780095` (종이책 ISBN, 검색 요약). 둘 다 종이책 ISBN
- 처음에 "978·979 중 확인 숫자가 맞는 쪽"으로 셌다가 979 책에서 틀린 것을 발견해 위 규칙으로 고침
- 적용 결과 (`removed_at IS NULL`, 284.3만 줄, 2026-09-30): 90.0만 줄(약 32%), 서로 다른 코드 20.3만 개 → 서로 다른 ISBN 17.2만 개. 북큐브 줄은 `alt_code`(교보식 코드)로 계산
- 한국 ISBN이 아닌 교보 코드: `48090…` 3.8만 줄(1.0만 코드, 예 「리멤버. 1」 디키스토리), 교보 확인 숫자가 안 맞는 `480` 코드 4.3천 줄 [확인 필요: 전자책 전용 코드인지]
- 나머지 약 68%(YES24 번호, 북큐브 번호, 포털 `AAA:99` 코드 등)는 코드에서 ISBN이 나오지 않음
- 규칙 전체 검증: ISBN 서지정보와 표본 대조 [확인 필요: API 호출 시험]
- YES24 재수집 전 수치가 섞였을 수 있음 (`search-and-normalization.md` 머리말 주의)

## 5. 묶기 절차 [안]

앞 단계에서 묶이지 않은 책만 다음 단계로 넘깁니다.

1. 같은 플랫폼 코드: 여러 도서관의 같은 교보 코드·YES24 번호는 같은 책 (284만 줄 → 약 122만 코드)
2. 코드에서 계산한 종이책 ISBN이 같으면 플랫폼이 달라도 묶음
3. 국립중앙도서관 ISBN 서지정보에서 정리한 본제목·저자·출판사로 종이책 ISBN 검색. 결과가 하나로 맞을 때만 붙이고 저장. 새로 들어온 책만 검색
4. 남은 책: 정리한 본제목 + 대표 저자 + 정리한 출판사가 같으면 묶음. 저자가 없거나 애매하면 합치지 않음 (OCLC 원칙). 부제만 다른 해설서·요약본을 합치지 않도록 주의 (Open Library 규칙)

## 6. 인증키 신청 사유 초안

사용자가 신청 화면에 붙여 넣을 문안입니다. 신청 양식의 항목 이름과 글자 수 제한은 확인하지 못했습니다 [확인 필요]. 서비스 이름·운영 형태는 지금까지 정한 것(비영리, 사이클 01 결정)만 적었습니다.

> **활용 목적:** 공공도서관 전자책 대출 가능 여부를 한곳에서 찾아 주는 비영리 서비스 "chaekcheck"를 개발하고 있습니다. 전국 공공 전자도서관에 흩어져 있는 같은 책을 하나로 묶어 이용자가 원하는 책을 정확히 찾도록 하기 위해, 각 도서의 서명·저자·출판사로 ISBN 서지정보를 조회하여 종이책·전자책 ISBN을 확인하고자 합니다.
>
> **활용 방법:** 새로 확인된 도서에 한해 서명·저자·출판사로 검색하고, 조회한 ISBN과 발행형태(종이책·전자책) 정보를 서비스 내부의 도서 식별에 사용합니다. 조회 결과를 다시 배포하거나 판매하지 않으며, 화면에 서지정보를 보일 때는 출처(국립중앙도서관)를 표시합니다. 호출은 기관의 이용 기준을 지켜 필요한 만큼만 합니다.
>
> **기대 효과:** 이용자가 공공도서관 전자책을 쉽게 찾아 빌리게 되어 공공도서관 전자책 이용이 늘어납니다.
