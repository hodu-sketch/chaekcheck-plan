## 1. 무엇을 주기적으로 갱신하나

| 대상 | 내용 | 주기 | 출처 | 태그 |
|---|---|---|---|---|
| 도서관 목록·정보 | 전자도서관 주소, 플랫폼, 가입 자격, 켜기·끄기 | 정해지지 않음 | 도서관 사이트, dev `docs/library-maintenance.md` | backlog "도서관 정보 주기적 재조사" |
| 도서관 × 도서 소장 | 어느 도서관에 어떤 책이 있나, 새로 들어온 책, 빠진 책 | 주 1회 전체 + 매일 신간 | 도서관 사이트 목록 수집 | [확정] (`crawl-method.md` 2절) |
| 도서 서지·ISBN | 종이책 ISBN, 대표 제목·저자·출판사·출판일 | 국가서지 파일은 공개될 때마다(최근 2026-08-07), 신간은 매일 API | 국가서지 LOD 일반도서 파일, ISBN 서지정보 API | [안] |
| 정리·묶기 재계산 | 정리 규칙 적용, 같은 책 묶기 | 소장·서지가 바뀐 책만, 규칙을 바꾸면 전체 | 원문 + 위 서지 | [안] |
| 보유·대출·예약 수 | 저장하지 않음. 사용자가 책을 고를 때 실시간 조회 | — | 도서관 상세 페이지 | [확정] (`crawl-method.md` 2절) |

## 2. 순서 [안]

1. 도서관 목록 확인 (켜진 도서관, 바뀐 주소)
2. 소장 수집: 전체(주 1회) 또는 신간(매일). 도서관 한 곳 결과를 임시 테이블에 넣고 바뀐 것만 반영 (`search-and-normalization.md` 3.3절)
3. 새로 생기거나 바뀐 책만 정리 규칙 적용 (`search-and-normalization.md` 4절)
4. 같은 책 묶기: 같은 플랫폼 코드 → 교보식 코드 ISBN → 국가서지 파일 → ISBN 서지정보 API → 정리한 글자 (`same-book-isbn.md` 5절)
5. 대표 서지 정하기: ISBN이 있으면 공공 서지, 없으면 가장 많이 나온 원문
6. 실행 기록과 이상 알림 (사이트 총 건수와 다름, 반 이상 줄어듦, 화면 모양 바뀜)

## 3. 출처별 특성 (확인한 것)

| 출처 | 특성 | 근거 |
|---|---|---|
| 도서관 사이트 목록 | 원문이 제각각. 교보는 한 쪽 500줄, YES24는 10줄 고정. 같은 호스트 1건·1초. 한 줄 오류로 전체 실패하지 않게 할 것 | `crawl-method.md`, `crawl-runbook.md`(수집 세션), `research.md` |
| 교보식 코드 (`480`…) | 수집 줄의 약 32%에서 종이책 ISBN 계산. 국가서지와 978·979 모두 약 95% 제목 일치 | `same-book-isbn.md` 3·4.2절 |
| 국가서지 일반도서 파일 | 3,936,503건, ISBN 3,165,282건, CC0. 앞 괄호 관제·`(The)`·출판사 끝 `#` 같은 표기 | `same-book-isbn.md` 4.2절 |
| ISBN 서지정보 API | 인증키·담당자 승인 필요(사용자 신청 예정). 제목·저자·출판사 형태소+n-gram 검색, `EBOOK_YN`, `RELATED_ISBN` | `same-book-isbn.md` 4.3·6절 |
| 도서관 상세 페이지 | 교보는 "대출 : 0/5 예약 : 0" 표시. 다른 화면 종류 미확인 | `search-and-normalization.md` 5절 |

## 5. 정해지지 않은 것 (갱신 사이클에서 정함)

- 수집을 어디서 돌리나: 지금은 `chaekcheck-data`(수집 세션의 파이썬 도구). 서비스 안의 예약 작업으로 옮길지, 조회 서버를 같이 쓸지 (`crawl-method.md` 7절 [안])
- 전체 수집 주기가 기관 수 증가(웹러브 북스 수준) 뒤에도 주 1회로 가능한지
- 국가서지 파일을 어떻게 받아 갱신할지 (다운로드 전 이용 설문이 있음)
