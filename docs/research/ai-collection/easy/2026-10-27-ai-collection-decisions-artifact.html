불러오는 중

AI는 "사람이 원문을 읽고 판단하던 곳"에만 넣고,
책 목록 수집은 지금 수집기를 그대로 두는 쪽을 제안합니다.

"랭그래프 같은 걸 활용해서 ai agent로 수집하는 것(도서관, 도서관-책 정보, 도서관 가입정보)을 자동화하는 것에 대해서 고민 중이야" (2026-10-27)에 대한 방향 5개입니다. 사이클 23·24 dev가 끝난 뒤 사이클로 할 일이라, 지금은 큰 틀만 정합니다. 항목마다 승인·미승인·기타를 골라 주세요.

먼저: 지금 수집에서 사람이 판단하는 곳

세 갈래 중 판단이 가장 많이 드는 곳은 가입 정보입니다. 책 목록 수집은 이미 스크립트가 정해진 주소를 돌며 받고 있어서 AI가 대신할 일이 적습니다.

갈래지금 하는 방법사람(또는 Claude 세션)이 판단하는 곳
도서관 찾기교보·웹러브 북스 기관 목록 → 확인 스크립트 → 같은 사이트 거르기 → 넣기 명령학교·회사·공공도서관 종류 나누기(이름만으로 확실하지 않은 곳 250곳), 같은 사이트인지 읽어 보기
도서관-책플랫폼별 수집기가 목록 화면을 쪽마다 받음 (같은 서버에 한 번에 1건, 1초 간격)수집기가 깨졌을 때 원인 찾기, 새 플랫폼 붙이기
가입 정보Claude 세션이 도서관 가입 안내 페이지를 열어 읽고 표에 적음. 사람이 고친 값 목록(join_overrides.tsv)이 마지막에 이김원문 해석 전부 ("원문 우선, 추정 금지")

근거: plan docs/research/collection/1-libraries.md, 2-books.md, library-join/candidates.md. dev는 이미 Python 스크립트에서 Claude Haiku 5.5를 부르고 있습니다(scripts/aisearch/prototype_haiku.py, 2026-10-27 확인).

LangGraph가 무엇을 해 주나

LangGraph는 AI 작업을 여러 단계로 잇고, 중간에 사람 승인을 기다리며 멈췄다가 이어 가게 해 주는 Python 도구입니다. 한 페이지를 읽고 값을 뽑는 한 단계 일에는 필요하지 않습니다.

항목공식 자료 (확인 2026-10-27)
정의오래 도는, 상태를 가진 에이전트를 만들고 돌리는 "low-level orchestration framework and runtime" (docs.langchain.com LangGraph overview)
버전·라이선스1.2.18 (2026-10-26), MIT (pypi.org/project/langgraph)
언어Python. 우리 백엔드(Java Spring)용은 공식이 아닌 LangGraph4j만 있음
멈췄다 이어 가기interrupt()로 멈추고 같은 작업 번호로 다시 부르면 이어 감. 멈춘 상태를 저장할 곳(체크포인터)이 꼭 있어야 함 (docs.langchain.com interrupts)

1AI를 쓰는 곳: 가입 정보 먼저,
도서관 찾기는 초안만, 책 수집은 지금 그대로

안 #1 가입 정보는 AI가 가입 안내 원문을 읽고 자격(거주·재직·재학·누구나)과 그 근거 문장을 냅니다. 도서관 찾기에서는 AI가 종류 나누기·같은 사이트 판단의 초안만 냅니다. 책 목록 수집은 지금 수집기 그대로 두고, AI는 수집기가 실패했을 때 "어느 화면이 어떻게 바뀌었는지" 보고만 합니다.

예시: 어느 시립도서관이 "관내 거주자"에서 "관내 거주·직장인"으로 가입 조건을 바꾸면, 다음 재조사 때 AI가 바뀐 문장을 찾아 "재직 자격 추가" 후보로 올립니다.

책 수집에 AI를 넣지 않는 이유: 책 목록은 도서관마다 수천~수만 권이고 화면 모양이 플랫폼마다 정해져 있어, 스크립트가 더 빠르고 매번 같은 결과를 냅니다. AI가 목록을 읽으면 같은 책을 매번 다르게 읽을 수 있고 비용이 책 수만큼 늡니다.

다른 선택: (가) 세 갈래 모두 AI 에이전트로 — 수집기가 깨져도 스스로 고쳐 받을 수 있지만, 결과가 매번 달라질 수 있고 도서관 서버에 보내는 요청 수를 지금처럼 정확히 묶기 어렵습니다. (나) 가입 정보만 — 가장 단순하지만 도서관 찾기의 종류 나누기는 계속 사람이 합니다.

2도구: 처음엔 LangGraph 없이 스크립트 + Claude API,
단계가 늘면 LangGraph로

안 #2 처음에는 Python 스크립트가 페이지를 받아 Claude Haiku 5.5에 한 번 묻고, 정해진 칸(자격, 범위, 근거 문장, 출처 주소)으로 답을 받습니다. dev가 이미 쓰는 방식(prototype_haiku.py)과 같습니다. "못 찾으면 다른 페이지로 가서 다시 찾기", "승인을 기다렸다가 이어 가기"처럼 단계가 여러 개로 늘어나면 그때 LangGraph로 옮깁니다.

가입 안내 페이지스크립트가 받음→Haiku 5.5정해진 칸으로 답→결과 표도서관마다 한 줄

처음 모양: 단계 하나라 LangGraph 같은 틀이 없어도 됩니다.

모델입력 / 출력 (100만 토큰당)공공도서관 약 400곳 한 번 [추론]
Haiku 5.5$0.10 / $0.50약 $0.6 (약 900원)
Sonnet 5.5$2 / $10약 $12

가격: platform.claude.com pricing (확인 2026-10-27). 어림 가정: 도서관마다 페이지 3장 × 약 4,000토큰 입력, 600토큰 출력. 한국어라 1.5~2배가 될 수 있습니다. 400곳은 등록 도서관 278 + 조사한 후보 공공도서관 120으로 잡은 수입니다.

다른 선택: (가) 처음부터 LangGraph — 나중에 단계가 늘 때 옮기는 일이 없지만, 멈춘 상태를 저장할 곳과 배울 것이 먼저 늡니다. (나) Claude Code를 정해진 시간에 돌려 지금 세션처럼 dev 절차 문서를 따라 하게 하기 — 새 코드가 거의 없지만, 매번 하는 일이 조금씩 달라 결과를 비교하기 어렵습니다.

3AI가 낸 값은 승인한 뒤에만
서비스에 들어감

안 #3 AI 값은 바로 서비스에 들어가지 않습니다. 스크립트가 먼저 AI가 낸 근거 문장이 받아 온 원문에 글자 그대로 있는지 확인하고, 지금 값과 다른 도서관만 목록으로 만듭니다. 사용자가 그 목록에서 승인한 것만 사람이 고친 값 목록(join_overrides.tsv)이나 넣기 명령으로 들어갑니다.

AI 값 + 근거 문장→근거 문장이 원문에 있나없으면 버림→지금 값과 다른가같으면 끝→바뀐 곳 목록→사용자 승인그 뒤 서비스 반영

AI가 지어낸 문장은 원문 대조에서 걸리고, 승인 전에는 이용자 화면이 바뀌지 않습니다.

안 정하면: AI가 "누구나 가입"으로 잘못 읽은 도서관이 이용자에게 가입 가능으로 보일 수 있습니다.

다른 선택: 근거 문장 대조를 통과하면 자동 반영 — 손이 덜 가지만, 문장은 맞는데 해석이 틀린 경우(예: 회원증만 지역 제한인데 "지역 제한"으로 읽음)를 거르지 못합니다.
