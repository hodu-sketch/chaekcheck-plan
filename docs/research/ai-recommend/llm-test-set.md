## 2. 후보 책 [확인 필요: dev 수집 DB에서 뽑기]

- 질문마다 후보 10권. 임베딩(KURE-v1)은 아직 없으므로 시험에서는 수집 DB에서 낱말·분야로 뽑습니다. 뽑는 일은 PC의 수집 DB가 있는 dev 쪽에서 합니다(이 저장소에서는 DB를 쓰지 않음)
- 후보 한 권에 넣는 칸: 번호, 제목, 저자, 꼬리표, 소개. **소개 칸만 바꿔 두 번 돌림**: (가) 소개 원문, (나) 내용 메모(원문에서 뽑은 주제 낱말과 짧은 사실 문장)
- 내용 메모를 만드는 방법은 아직 정하지 않음 [확인 필요: 사용자에게 질문]

## 3. 지시문과 JSON 형식 초안 [안]

같은 지시문을 Haiku와 Ollama에 넣습니다.

**system**

```
너는 도서 추천 도우미다.
- 반드시 아래 후보 목록의 번호 중에서만 고른다. 목록에 없는 책을 말하지 않는다.
- 질문에 맞는 책을 0~8권 고른다. 맞는 책이 없으면 빈 목록을 돌려준다.
- 고른 책마다 질문에 맞춘 글을 한국어 2~3문장으로 쓴다. 왜 이 질문에 맞는지가 드러나게 쓴다.
- 후보에 적힌 내용만 근거로 쓴다. 적혀 있지 않은 줄거리·수상·저자 정보를 지어내지 않는다.
- 소개 글의 문장을 그대로 옮기지 않는다. 자기 말로 다시 쓴다.
- 정해진 JSON 형식으로만 답한다.
```

**user**

```
질문: {질문}
후보:
1. 제목: … / 저자: … / 꼬리표: … / 소개: …
2. …
```

**JSON 형식** (Ollama는 `response_format` `json_schema`, Haiku 5.5는 `output_config.format` `json_schema` [확정] https://platform.claude.com/docs/en/build-with-claude/structured-outputs (지원 모델에 Haiku 5.5, 2026-10-24 확인). `maxItems`를 두 쪽이 다 지키는지는 [확인 필요: 시험])

```json
{
  "type": "object",
  "properties": {
    "picks": {
      "type": "array",
      "maxItems": 8,
      "items": {
        "type": "object",
        "properties": {
          "no": { "type": "integer" },
          "text": { "type": "string" }
        },
        "required": ["no", "text"]
      }
    }
  },
  "required": ["picks"]
}
```

## 4. 채점표 [안]

모델 × 소개 종류(원문/메모)마다 질문 20개를 돌리고, 질문 하나에 한 줄씩 적습니다.

| 칸 | 어떻게 보나 | 누가 |
|---|---|---|
| JSON 지킴 | 형식대로 읽히면 ○ | 자동 |
| 후보 밖 번호 | 목록에 없는 번호 수 (0이어야 함) | 자동 |
| 베낀 문장 | 소개 원문과 연속 15자 이상 같은 부분이 있으면 표시 | 자동 |
| 지어낸 내용 | 후보 칸에 없는 사실(수상, 줄거리 등)이 있으면 표시 | 사람 |
| 질문에 맞음 | 1(안 맞음) · 2(보통) · 3(잘 맞음) | 사람(사용자) |
| 글 자연스러움 | 1 · 2 · 3 | 사람(사용자) |
| 걸린 시간 | 요청부터 응답까지 초 | 자동 |
| 18~20번 | 억지로 골랐는지 | 사람 |

- "연속 15자"는 이 문서에서 정한 시험용 기준입니다 [안]
- 원문 대 메모 결정: "질문에 맞음"과 "자연스러움" 평균 차이, "베낀 문장" 수를 나란히 보고 사용자가 정함
