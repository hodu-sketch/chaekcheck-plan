불러오는 중

2차에서 두 가지가 정해졌고, 세 가지에 질문을 남기셨습니다. 이 페이지에는 정해진 것 정리, 로컬 컴퓨터에서 LLM을 처음 돌려 보는 순서, 남은 질문 두 개에 대한 답이 있습니다.

고를 것은 세 개입니다: 로컬 시작 순서(2번), 소개 원문과 내용 메모 중 무엇을 쓸지(3번), 첫 화면 배치(4번). 각 카드 맨 아래에서 고르고 "저장"을 눌러 주세요.

정해진 것

카드 글은 질문에 맞춘 글 한 덩어리를 실시간으로 씁니다. 소개와 이유를 나누지 않고, LLM이 질문에 맞춰 2~3문장을 그때그때 씁니다. (2차 페이지에서 "(나) 질문에 맞춘 글 한 덩어리를 실시간" 선택, 2026-10-23)
우리 서버는 Haiku와 내 LLM을 둘 다 부를 수 있게 만들고, Haiku로 먼저 시작합니다. 적으신 말: "일단 둘 다 되도록 해주고, haiku로 먼저 하고 병렬적으로 llm 다루는 것 좀 알려줘 vast.ai이전에 먼저 내 로컬 컴퓨터에 간단한 모델 돌려보고 싶어" (2026-10-23)

"둘 다 되도록"이 뜻하는 것: 우리 서버에 LLM을 부르는 방법을 두 가지 둡니다. 설정 값 하나로 어느 쪽을 쓸지 바꿉니다.

부르는 방법부르는 곳
Anthropic 방식 (Messages API)Claude Haiku 5.5
OpenAI 호환 방식 (/v1/chat/completions)내 PC의 Ollama, 나중에 vast.ai의 vLLM. 둘 다 같은 방식이라 주소만 바꾸면 됩니다

Haiku를 OpenAI 호환 방식으로 부르는 길도 있지만, Anthropic 문서가 "주로 시험·비교용이며 오래 쓰거나 운영에 쓸 방법은 아니다"라고 적고 있어 두 방법을 따로 둡니다 (https://platform.claude.com/docs/en/api/openai-sdk, 2026-10-23 확인).

1번 결정으로 바뀌는 점: LLM이 쓰는 글이 길어져 응답이 느려질 수 있습니다(얼마나 느린지는 재 보지 않음). "나에게 맞는 책" 탭의 미리 만든 소개 글은 그 탭에서 그대로 씁니다.

2내 컴퓨터에서 LLM을
처음 돌려 보는 순서

Haiku로 서비스를 만드는 동안, 따로 내 Windows PC에 Ollama를 깔아 작은 모델을 돌려 봅니다. Ollama는 vLLM과 같은 OpenAI 호환 주소를 열어 주므로, PC에서 시험한 요청을 나중에 vast.ai에서 그대로 쓸 수 있습니다.

1. Ollama 설치
Windows용 프로그램으로 설치하고, NVIDIA와 AMD 그래픽카드를 씁니다. Windows 10 22H2 이상, NVIDIA는 드라이버 551.61 이상이 필요합니다. 프로그램만 4GB 이상, 모델마다 공간이 더 듭니다.
2. 작은 모델 받기
상업 이용이 되는 Qwen3(0.6B~32B 여러 크기) 가운데 PC에 맞는 작은 크기부터 받습니다. 어느 크기가 돌아갈지는 그래픽카드 메모리에 달려 있는데, 사양을 몰라 아직 정하지 못했습니다. 아래 칸에 적어 주세요.
3. 요청 보내 보기
Ollama는 켜 두면 내 PC 안에서만 http://localhost:11434/v1/chat/completions 주소로 요청을 받습니다. 여기에 질문과 후보 책 몇 권을 넣고, JSON 형식(response_format)으로 답하게 해 봅니다.
4. Haiku와 나란히 비교
같은 질문 20개를 Haiku와 내 모델에 넣고 카드 글을 비교합니다. 3번 카드의 "원문 대 내용 메모" 비교도 이 단계에서 함께 합니다. 소개 원문이 PC에 있기 때문입니다.
5. vast.ai로 옮기기
더 큰 모델이 필요해지면 vast.ai에 vLLM을 띄웁니다. vLLM은 Windows에서 바로 돌지 않고 Linux(Windows에서는 WSL)가 필요한데, vast.ai 장비는 Linux라 상관없습니다.
6. 튜닝은 그다음
4단계에서 고친 좋은 예시가 쌓이면 LoRA로 튜닝합니다. vLLM은 LoRA 덧붙임을 붙여 돌릴 수 있습니다.

근거 (2026-10-23 확인, ollama.com과 docs.vllm.ai는 이 환경에서 열리지 않아 GitHub의 같은 문서로 봄): Ollama Windows https://github.com/ollama/ollama/blob/main/docs/windows.mdx , Ollama OpenAI 호환 https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx , 기본 주소 127.0.0.1:11434 https://github.com/ollama/ollama/blob/main/docs/faq.mdx , vLLM 설치 "vLLM does not support Windows natively" https://github.com/vllm-project/vllm/blob/main/docs/getting_started/installation/README.md , Qwen3 크기와 라이선스는 infra-cost.md 3절. Ollama에서 쓰는 모델 이름(예: 어떤 크기 표기)은 Ollama 모델 목록이 열리지 않아 확인 못 함.

[안] #2 위 1~6 순서로 시작합니다. 덧붙일 말 칸에 PC 사양(그래픽카드 이름, 그래픽카드 메모리, 컴퓨터 메모리)을 적어 주시면 2단계 모델 크기를 정해 드립니다.

3품질은 어느 쪽이 나은가:
소개 원문 그대로 / 내용 메모

적으신 말: "퀄리티 측면에서 어떤 게 나아? 소개글을 메모로 만들어서 올린다 vs llm이 다 한다"

정보가 많은 쪽은 원문입니다. 1번에서 질문에 맞춘 글을 실시간으로 쓰기로 하셨으니 원문이 있을 때 글이 더 구체적일 가능성이 큽니다. 하지만 메모를 잘 만들면 차이가 작을 수도 있고, 실제로 얼마나 다른지는 재 보지 않았습니다. 원문이 PC에 있으니 PC에서 직접 비교해 보고 정하는 것을 추천합니다.

원문을 LLM에 그대로내용 메모
글 품질분위기, 줄거리의 작은 부분까지 반영할 수 있음메모에 없는 부분은 쓸 수 없음. 메모를 얼마나 자세히 만드느냐에 달림
베끼기질문에 맞춰 실시간으로 쓰므로 원문 문장이 섞여 나올 위험이 더 큼. 화면에 보내기 전에 검사해야 함원문 문장이 나올 길이 좁음
운영 서버출판사 글 사본이 운영 DB에 쌓임. 2026-10-23 결정 "원문은 PC에만"을 바꿈결정을 바꾸지 않음
속도입력이 길어 조금 느림입력이 짧음

비교 시험 (2번의 4단계에서 함께 함)

같은 질문 20개→원문을 넣어 글쓰기메모를 넣어 글쓰기→사용자님이 나란히 보고 고름

시험은 PC에서만 합니다. Haiku로 시험하면 원문이 시험 동안 Anthropic API로 갑니다. 서비스에 원문을 저장하는 일은 아닙니다.

[안] #3 PC에서 같은 질문 20개로 원문과 내용 메모를 비교해 보고 정합니다. 그동안 서비스는 미리 만든 소개와 꼬리표로 만듭니다.

다른 선택: 지금 원문으로 정하기(2026-10-23 결정이 바뀌고 저작권 검토가 필요), 지금 메모로 정하기(품질 차이를 모른 채 정함).
