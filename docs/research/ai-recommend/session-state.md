## 1. 확정된 것 [확정]

### 1-1. 전체 구성 (2026-10-17/18 승인, overview.md 7절)
- 세 단계: ① 후보(책당 비슷한 책 20권) ② 순위(규칙 계산) ③ AI 소개 문구. **모델은 운영 서버 밖**(PC나 잠깐 빌린 GPU)에서 미리 계산하고 결과 표만 운영 DB에 반영(사이클 11 방식)
- 임베딩: `nlpai-lab/KURE-v1`(1024차원, MIT), PC에서, 입력은 제목·저자·출판사(·출판일)
- 같이 본 책: 모델 없이 SQL 공출현(Amazon식 인기 보정), 기록이 쌓이면 Python `implicit`
- 소개 문구: Claude Haiku 5.5 Message Batches, 입력은 서지만, 책 소개 원문(출판사 글) 넣지 않음
- Jev(TypeSafe AI)는 나중에 순위 점수용으로만 검토(글을 만들지 않음, early access)
- vast.ai는 on-demand로 빌려 일괄 작업 뒤 바로 destroy, 서지만 올림. 서버가 실시간 REST로 부르지 않음
- 1단계 범위: 서지 임베딩 "비슷한 책" + AI 소개 문구, 비로그인 포함
- 정보나루 "함께 대출된 도서"·국립중앙도서관 책 소개는 처음엔 쓰지 않음

### 1-2. 로깅 (ADR-0134, 2026-10-18 승인, **dev main에 구현됨** 6b40067, 2026-10-23 보고)
- `usagelog.book_view`·`library_click`·`screen_event`에 `visit_key`(탭 단위 난수, `sessionStorage`, 쿠키 아님)·`account_id`(로그인 회원) 칸. `search_event`·`search_more`는 제외
- `auth` `LoginStatusReader.read` → `LoginState(status, accountId)`, 탈퇴 때 `UsageLogAccountDeletedCleanup`이 `account_id`만 NULL
- 처리방침 1절 짧은 판: "서비스 이용 기록(로그인한 경우 회원 번호 포함)", 목적에 "책 추천", "회원 번호는 탈퇴하면 바로 지움"
- 남은 감수 1건 [확인 필요]: 탈퇴 뒤 만료 토큰이 남은 브라우저가 책을 열면 그 번호가 다시 기록될 수 있음 → 3단계 "맞춤 추천 끄기" 설계 때

### 1-3. 약관·AI 표시
- 회원 맞춤 추천은 약관에 서비스 내용으로 적고 처리방침 공개 → 별도 동의 없이(개인정보위 FAQ, 제15조①4호). 거부 방법 = 설정 "맞춤 추천 끄기"(3단계)
- AI 소개 글 표시: **카드마다가 아니라 탭 맨 위 한 줄** "책 소개 글은 AI가 썼어요" (2026-10-23, 사용자 "AI 각각 붙여서 너무 많지 않아? 간단하게 통으로"). 서비스 안내·약관의 사전 고지 한 줄은 유지

### 1-4. "나에게 맞는 책" 탭 (2026-10-23/24 승인, overview.md 6-1절)
- 화면 짜임: **맨 위 한 권(가장 좋아할 책)은 한 줄 전체·큰 표지·큰 제목·소개 글 전부**, 그 아래 **한 줄에 두 권**, 소개 글은 어디서도 자르지 않음. PC·태블릿·폰 같은 짜임. 그림 [easy/2026-10-23-for-you-tab-screens.html](easy/2026-10-23-for-you-tab-screens.html)
- 탭 자리: **추천도서 탭 줄 맨 앞** (사용자 "더하되 맨 첫번째로 하자"). dev 현재 탭: KAIST · 국립중앙도서관 · 서울대 · 노벨연구소(이동진은 탭에서 빠지고 주소로만, dev `web/src/features/picks/picksLists.ts`)
- 신호 점수: 책 창 열기 1 + 10초 넘게 열어 둠 2 + 그 책에서 도서관 클릭 3, 최근 30일, 상위 3권이 기준 책. "머묾"은 사용 알림 하나 추가 필요(`screen_event` 종류 `book_dwell`, 이름은 사이클에서)
- 고르기: 기준 3권의 이웃 20권씩 → 본 책·기준 책 빼고 → 내 계획 도서관에 있는 것만 → 소장 도서관 수 많은 순 20권씩, 같은 저자 연속 2권까지
- 보유 조건: 내 계획 도서관 중 한 곳이라도 가진 책(`book.library_ids` ∩ 계획 도서관), 카드에 "내 도서관 N곳", 대출 가능 여부는 탭에서 안 봄
- 처음 온 사람 안내("아직 본 책이 없어요…")는 **없음**. 누구에게나 **기본 목록(트렌드)** 을 보여 주고, 본 책이 생기면 그 기반 추천을 위에 더함(맨 위 한 권·두 권 줄 앞쪽), 겹치면 한 번만
- 트렌드는 **바깥 출처에서** (사용자 "지금은 사용자가 없고 … 외부에서 트랜드 도서를 가져오자")

## 5. 이 세션에서 배운 작업 방식 (메모리에도 있음)

- 결정은 캔버스 결정 페이지로, 질문 답은 받은 페이지에 먼저
- 쓰지 않기로 한 출처는 새 근거가 나와도 다시 추천하지 않음
- DB 구조·흐름·바꿀 곳은 dev에 전하기 전에 결정 페이지로 먼저 승인받음 (2026-10-18 "db구조 이런거 나한테 먼저 승인받아야지")
- 화면 예시는 그림으로, 사용자와 정한 짜임·dev의 현재 이름(탭 이름 등)과 맞춰서
- dev에 전달할 때는 인계서에 쓰고 dev 세션(예: `chaekcheck-dev-cycle-20-1`)에 메시지로 알림
