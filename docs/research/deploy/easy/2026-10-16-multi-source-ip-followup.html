첫 배포부터 프록시를 쓸 때:
무엇을 사고, 어떻게 나눠 쓸지

앞 페이지(2026-10-16-multi-source-ip.html)에서 두 제안이 미승인되었습니다. "정적 주거용만 더하고 바뀌는 주거용은 뺌"에는 "요청마다 ip가 바귀는 주거용도 같이 했으면 해 정적 주거용이랑 같이", "첫 배포는 프록시 없이"에는 "지금 프록시가 없으면 1초 제한에 걸려서 사용자가 거의의미가없어; 실제로 지인 몇 명에게 부탁했는데 로딩 이야기가 있어서 그래서 프록시를 같이 가야해"라고 하셨습니다(2026-10-16). 그래서 생기는 다섯 가지를 정합니다.

1두 종류 프록시가
어떻게 다른가

정적 주거용은 IP 20개를 사서 한 달 내내 같은 IP를 씁니다. 바뀌는 주거용은 접속 주소 하나로 보내면 요청마다 다른 한국 가정 IP로 나가고, 쓴 데이터(GB)만큼 돈을 냅니다.

초록 실선은 IP가 늘 같은 길, 노란 점선은 요청마다 IP가 바뀌는 길입니다. 도서관 사이트에는 맨 끝 IP만 보입니다.

  • 이전 결정이 바뀌는 점: ADR-0095는 "주거용·IP 바꿔 가는 프록시는 길로 넣지 않음"(G안 기각)이었습니다. 이번 말씀으로 둘 다 넣습니다. ADR-0095의 "감수하는 점"(사이트가 막아도 다른 IP로 계속 들어가는 모양)은 바뀌는 주거용에서 더 뚜렷해집니다.

2첫 배포 때 무엇을 사나

EC2 자기 IP 1개 + Webshare 한국 정적 주거용 20개 + Webshare 한국 바뀌는 주거용 1GB를 제안합니다. 한 달 약 $9.50입니다.

#1첫 배포 길 묶음:
EC2 1개 + 정적 20개 + 바뀌는 1GB

[안] 첫 배포부터 나가는 길을 세 가지로 둡니다: EC2 자기 IP 1개, Webshare 한국 정적 주거용 공유 20개(한 달 $6), Webshare 한국 바뀌는 주거용 1GB(한 달 $3.50). 모두 설정 목록에 넣고, 업체 주소·비밀번호는 서버 비밀 값으로 둡니다.

그러면: 도서관 사이트 하나에 고정 IP 21개가 각자 1초에 1건씩, 합쳐 1초에 최대 21건을 보낼 수 있습니다(지금은 1건). 바뀌는 주거용은 그 위에 더해집니다(3번 카드).

다른 선택: 정적을 Private(다른 고객 0~2명)으로 → 20개 $18.52, 남과 같이 쓰다 막힐 일이 줄어듦. / 바뀌는 주거용을 3GB로 → $9.00. / 바뀌는 주거용 없이 정적만 → $6, 말씀과 다름.

추천: 이 묶음으로 시작하고, 조회 기록에서 막힘과 GB 사용량을 본 뒤 늘립니다.

Webshare 정적 주거용이 실제로 한국 통신사 IP인지, 강동구립도서관이 받아 주는지는 사서 확인합니다(앞 페이지의 시험 명령 두 줄). 아니면 결제 뒤 48시간 안·1GB 미만일 때 환불(https://help.webshare.io/en/articles/8370527-requesting-a-refund).

3어느 길부터 쓰고,
바뀌는 주거용은 어떻게 세나

고정 IP 21개를 먼저 쓰고, 그 사이트에서 21개가 모두 바쁘거나 막혔을 때만 바뀌는 주거용을 씁니다. 바뀌는 주거용은 IP마다 셀 수 없으니 "접속 주소 하나 = 길 하나"로 보고 동시 건수로만 셉니다.

#2고정 IP 먼저,
바뀌는 주거용은 넘칠 때만

[안] 도서관 사이트마다 고정 IP 21개(EC2 1 + 정적 20) 중 지금 그 사이트에 보낼 수 있는 IP를 먼저 고릅니다(IP마다 동시 1건·1초, 교보 구독형 서버는 IP마다 동시 3건 그대로). 21개가 모두 그 사이트에서 바쁘거나 막혔을 때만 바뀌는 주거용으로 보냅니다.

그러면: 평소에는 GB가 거의 안 들고, 한꺼번에 몰릴 때와 고정 IP가 막혔을 때만 바뀌는 주거용 GB를 씁니다.

다른 선택: 처음부터 세 길을 고르게 섞음 → 빨라지지만 1GB가 빨리 닳음(조회 약 16,000번 추정). / 바뀌는 주거용을 맨 먼저 → 가장 빠르지만 GB 값이 가장 큼.

추천: 고정 IP 먼저.

#3바뀌는 주거용은 사이트마다
동시 5건, 1초 간격 없음

[안] 바뀌는 주거용 접속 주소 하나를 나가는 길 하나로 보고, 도서관 사이트마다 동시 5건까지 보냅니다(설정으로 바꿈). 요청마다 IP가 달라서 1초 간격은 두지 않습니다.

그러면: 고정 IP 21개가 모두 찼을 때 한 사이트에 5건이 더 나갑니다. 사이트에는 서로 다른 한국 가정 IP 5개에서 동시에 온 요청으로 보입니다.

다른 선택: 동시 상한 없음 → 몰리면 한 사이트에 수십 건이 한꺼번에 감. / 1초 간격 둠 → 고정 IP 하나 더 있는 것과 같아져 바뀌는 주거용을 쓰는 뜻이 작아짐. / 동시 3건·10건 → 숫자만 다름.

추천: 동시 5건, 설정으로. 5는 근거 있는 값이 아니라 제가 고른 시작 숫자이며, 조회 기록을 보고 바꿉니다.

4바뀌는 주거용이
막히거나 GB를 다 쓰면

한 번 막혀도 다음 요청은 새 IP로 가므로 바로 멈추지 않습니다. 같은 사이트에서 연달아 막힐 때와 GB를 거의 다 썼을 때만 바뀌는 주거용 길을 멈춥니다.

#4연달아 5번 막히면
그 사이트에서만 쉼

[안] 바뀌는 주거용으로 보낸 요청이 어느 사이트에서 막힌 응답을 받아도 길을 멈추지 않습니다. 같은 사이트에서 연달아 5번 막히면 그 사이트로만 이 길을 쉬고, 사이클 17에 넘긴 규칙대로 10분 뒤 시험 요청 1건 → 또 막히면 20분 → 40분 … 최대 7일로 다시 봅니다(docs/cycles/17-first-deploy/from-cycle-20-blocked-ip-resume.md).

그러면: 우연히 나쁜 IP 하나에 걸린 것은 무시하고, 사이트가 가정 IP 전체를 막는 경우에만 멈춥니다.

다른 선택: 한 번 막히면 바로 쉼 → 우연한 실패에도 멈춤. / 멈추지 않음 → 사이트가 막아도 계속 보내 GB와 법적 부담이 커짐.

추천: 연달아 5번, 숫자는 설정으로.

#5한 달 GB의 90%를 쓰면
바뀌는 주거용만 멈춤

[안] 바뀌는 주거용으로 받은 데이터 양을 우리 서버가 세고, 그 달 산 양(처음 1GB)의 90%를 넘으면 이 길만 멈춥니다. 고정 IP 21개는 계속 씁니다. 멈춘 사실과 쓴 양은 조회 기록에 남깁니다.

그러면: GB가 바닥나서 업체가 끊을 때 생기는 실패를 미리 피하고, 한 달 값이 $3.50을 넘지 않습니다.

다른 선택: 세지 않고 업체 한도에 맡김 → 다 쓰면 업체 쪽에서 실패가 납니다(업체가 어떻게 끊는지는 확인 못 함). / 자동으로 GB를 더 삼 → 값이 늘어남.

추천: 90%에서 멈춤, 비율과 그 달 양은 설정으로.
