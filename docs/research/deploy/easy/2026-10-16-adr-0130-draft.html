ADR-0130 초안과 사이클 17 인계:
오늘 정한 것을 기록하고 넘기기

사용자 말씀(2026-10-16): "ADR-0095 바꾸는 ADR 초안이랑 사이클 17 인계 파일 만들어서 캔버스로 보여줘". 오늘 정한 대출 조회 나가는 길·한도·알림을 ADR-0130 하나로 묶어 ADR-0095를 대신하게 하고, dev에 넘길 것은 사이클 17 폴더에 파일로 둡니다. 정할 것은 두 가지입니다.

1오늘 정한 것이 서비스에서 어떻게 돌아가나

사용자가 책을 검색하면 우리 서버(시드니 EC2)가 도서관 사이트마다 고정 IP 21개 중 비어 있는 IP를 골라 대출 현황을 묻습니다. 한도에 가까워지거나 막히면 그 길만 멈추고 메일이 옵니다.

초록은 첫 배포에 쓰는 길(한 사이트에 1초 최대 21건), 점선은 나중에 더할 길, 노랑은 알림입니다.

정한 것어디서 정함
업체 프록시와 서버 공인 IP 여러 개를 둘 다 지원첫 페이지 #2 승인
첫 배포: EC2 IP 1개 + Webshare 한국 정적 20개, 고정 IP 먼저첫 배포 프록시 #1·#2 승인 → "정적 20개 먼저, 동적은 나중"
바뀌는 주거용 허용(동시 5건·연달아 5번 쉼·90% 멈춤), 단 나중에첫 배포 프록시 #3~#5 승인, backlog
CloudWatch 메일, 알릴 일 다섯, 정적 90% 멈춤, 업체 오류면 업체 길 전체 멈춤한도와 알림 #1~#4 승인
Webshare 20개 모두 멈추면 상태 불 최소 노랑사이클 20 #21 승인

2ADR-0130 초안

ADR-0095의 내용(세 길, IP마다 따로 셈, 막힌 IP만 멈춤, 일반 브라우저 User-Agent)을 이어받고, 오늘 정한 것을 더해 ADR-0095를 대신합니다. 승인하면 ADR-0095는 "Superseded by 0130"이 됩니다.

  • 이전 결정이 바뀌는 점: ADR-0095 G안 "주거용·IP 바꾸는 프록시는 넣지 않음"을 뒤집습니다. 사이클 17의 "알림은 두지 않음"도 바꿉니다.
  • 이유: 모두 오늘 하신 말씀을 그대로 옮겼습니다(예: "지금 프록시가 없으면 1초 제한에 걸려서 사용자가 거의의미가없어 …"). 제가 고른 숫자(동시 5건, 연달아 5번, 80·90%)는 "제안 → 승인"으로 적었습니다.
  • 검토한 대안 여섯: 채택(A), 첫 배포는 프록시 없이(B, 미승인), 정적만(C, 미승인), 서버 IP만(D), 알림 없음(E), .go.kr은 바뀌는 주거용 빼기(F, 미룸).
  • 감수하는 점: 막힌 뒤 다른 IP로 계속 들어가는 모양(대법원 2021도1533)이 주거용 IP로 더 뚜렷해짐, Webshare 공유 IP라 남 때문에 막힐 수 있음, Webshare 계정이 멈추면 EC2 IP 하나로 돌아감.

#1ADR-0130 초안대로 기록

[안] 초안(docs/research/deploy/drafts/0130-lookup-egress-webshare-kr-static-and-alerts.md)을 docs/adr/0130-…로 쓰고 Status: Proposed로 둡니다. ADR-0095는 "Superseded by 0130"으로 바꾸고 ADR 목록에 한 줄 더합니다.

다른 선택: ADR-0095를 두고 바뀐 부분만 담은 ADR을 따로 → 두 ADR을 함께 읽어야 함. / 사이클 17이 설계할 때 ADR로 → 오늘 정한 것이 그때까지 조사 문서에만 있음.

3사이클 17 인계 파일

사이클 17이 dev에 넘기는 대출 조회 부분(spec R13)을 이 파일 기준으로 맞추도록, 넘길 것 아홉 줄을 docs/cycles/17-first-deploy/from-research-lookup-egress.md에 적었습니다. 사이클 20이 17에 넘긴 파일과 같은 방식입니다.

#dev에 넘길 것
1나가는 길에 "서버 공인 IP 여러 개" 더하기, 업체 프록시와 둘 다 지원
2첫 배포 길: EC2 IP 1개 + Webshare 한국 20개(주소:포트, IP 등록이라 비밀번호 없음)
3고정 IP 먼저, IP마다 1건·1초(교보 구독형 3건)
4막힌 길: ADR-0095 + 사이클 20 규칙(10분부터 두 배, 7일 상한)
5업체 데이터 세기: 우리가 센 양과 Webshare 사용량 API 중 큰 값, 80% 경고·90% 멈춤, 확장 모드 응답은 빼기
6Webshare 407·429·계정 확인이면 Webshare 길 전체 즉시 멈춤
7CloudWatch → SNS 메일, 알릴 일 다섯, 1시간에 한 번
8상태 불: 20개 모두 멈추면 최소 노랑(사이클 20이 읽음)
9나간 길·업체를 조회 기록에(그대로)
  • 배포 때 직접 하실 일: Webshare API 키 만들기, AWS가 보내는 SNS 구독 확인 메일 누르기.
  • 17 세션에 알림: 승인하시면 사이클 17 세션에 파일 위치만 메시지로 보냅니다(요약 왕복 없이).
