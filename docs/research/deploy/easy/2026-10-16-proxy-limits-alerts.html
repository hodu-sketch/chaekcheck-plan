프록시 한도에 닿기 전에 멈추고,
멈추면 메일로 바로 알려 드리기

사용자 말씀(2026-10-16): "이런데 나한테 알려주기가 잘 되어야 해", "고정 IP 21개도 용량 제한이 있지 않아? 이것도 막히기 전에 그만 하고 나한테 잘 알려줘야 해 이런 것에 대한 고려가 더 필요한 것 같아 너가 꼼꼼히 지금 설계/개발 안에서 고려해봐". 길마다 한도를 찾아보고, 정할 것을 다섯 가지로 나눴습니다.

1길마다 어떤 한도가 있나

EC2 자기 IP에는 데이터 한도가 없습니다. Webshare는 정적·바뀌는 주거용 모두 산 데이터를 넘기면 프록시가 멈추고, 동시 연결이 많거나 정부 사이트에 많이 보내면 계정 확인(KYC) 때문에 계정 전체가 멈출 수 있습니다.

길한도넘으면
EC2 자기 IP 1개데이터 한도 없음. 사용자에게 보내는 데이터는 AWS 전체에서 매달 100GB까지 무료값이 늘어남 → 이미 있는 AWS 예산 메일(지출 $0.01 넘으면)로 알 수 있음
Webshare 정적 주거용 20개플랜 전체 데이터 250GB/달(20개가 나눠 씀)"프록시가 작동을 멈춤", 남은 양은 다음 달로 안 넘어감
Webshare 바뀌는 주거용산 양 1GB/달같음 (이미 정한 #5: 90%에서 우리가 먼저 멈춤)
Webshare 공통: 동시 연결기본값 숫자는 확인 못 함429 client_connect_high_concurrency(동시에 너무 많이 보냄)
Webshare 공통: 정부 사이트"Government Websites"는 사용량 기준이 있는 분야, 바뀌는 주거용에서는 제한 분야본인 확인(KYC) 절차·계정 제한·정지 가능, 확인 중에는 프록시 접속이 멈출 수 있음
  • Webshare 사용량은 API로 읽을 수 있습니다: GET https://proxy.webshare.io/api/v2/stats/aggregate/가 쓴 데이터(bandwidth_total), 성공·실패 요청 수, 실패 이유를 돌려줍니다. Webshare API 키가 필요합니다(서버 비밀 값).
  • Webshare가 한도 메일을 보내는지는 확인 못 함: 도움말에는 "대시보드에서 사용량을 자주 보라"고만 적혀 있습니다.
  • 지금 설계의 알림: 사이클 17은 모니터링에 "알림은 두지 않음"으로 정했고, 지금은 CloudWatch로 메모리·디스크만 봅니다. 막힌 길은 서버 로그와 지표로만 남깁니다(from-cycle-20-blocked-ip-resume.md). 그래서 지금 설계로는 길이 멈춰도 메일이 오지 않습니다.

2어떻게 알려 드리나

이미 쓰는 CloudWatch에 경보를 걸고, 경보가 울리면 AWS가 메일을 보냅니다. 메일 주소는 AWS 예산 메일과 같은 <알림 메일>입니다.

#1CloudWatch 경보 → 메일

사이클 17의 "알림은 두지 않음"을 바꿉니다.

[안] 서버가 길 멈춤·풀림·사용량을 CloudWatch에 기록하고, CloudWatch 경보가 AWS SNS로 <알림 메일>에 메일을 보냅니다. 같은 일에 대한 메일은 1시간에 한 번까지만 보냅니다.

그러면: 폰 Gmail 앱 알림으로 받습니다. 새 서비스나 새 비밀 값이 늘지 않습니다. CloudWatch 경보는 한 달 10개까지 무료이고 그 뒤 하나에 $0.10입니다. SNS 메일 값은 확인 못 함.

다른 선택: 텔레그램 봇 → 폰에 바로 뜨지만 봇을 만들고 토큰을 비밀 값으로 둬야 함. / 서버가 Gmail로 직접 메일 → 메일 비밀번호를 서버에 둬야 함.

추천: CloudWatch 경보 → 메일.

근거: CloudWatch 값 https://aws.amazon.com/cloudwatch/pricing/ (2026-10-16 확인)

3무엇을 알려 드리나

길이 멈추거나 풀릴 때, 사이트가 모든 길에서 막힐 때, 데이터를 80%·90% 썼을 때, 업체 계정에 문제가 생길 때 메일이 옵니다.

#2메일을 보내는 일 다섯 가지

[안] 아래 다섯 가지에 메일을 보냅니다.

일메일 예
어떤 길이 어떤 사이트에서 쉬기 시작함 / 7일 상한에 닿음 / 다시 풀림"Webshare 바뀌는 주거용이 www.gdlibrary.or.kr에서 연달아 5번 막혀 쉼. 다음 시험 10분 뒤"
어떤 사이트가 모든 길에서 막혀 화면에 "확인 불가"로 나옴"ebook.○○.go.kr: 21개 IP와 바뀌는 주거용 모두 막힘"
업체 데이터를 80% 씀(경고), 90% 씀(그 길 멈춤)"Webshare 정적 주거용 250GB 중 201GB 사용(80%)"
업체 계정 문제로 그 업체 길 전체가 멈춤(4번 카드 #4)"Webshare 인증 실패(407), Webshare 길 모두 멈춤. EC2 IP로만 조회 중"
매일 아침 요약 1통길마다 어제 요청 수·실패 수·쓴 데이터, 쉬고 있는 길 목록

다른 선택: 매일 요약 빼기 → 메일이 줄지만 조용히 나빠지는 것(실패가 조금씩 늘어남)을 놓칠 수 있음. / 길이 멈출 때만 → 데이터 경고를 놓침.

추천: 다섯 가지 모두.

4정적 20개 데이터와
업체 계정 문제 막기

바뀌는 주거용에 정한 "90%에서 멈춤"을 정적 20개에도 똑같이 겁니다. 업체 쪽 오류가 오면 사이트별로 기다리지 않고 그 업체 길 전체를 바로 멈춥니다.

#3정적 20개도 250GB의 90%에서 멈춤,
Webshare 사용량 API로 맞춰 봄

[안] 정적 주거용 20개가 함께 쓰는 250GB도 우리 서버가 받은 데이터를 세어 80%에 경고, 90%에 정적 길만 멈춥니다(EC2 IP와 바뀌는 주거용은 계속). 1시간마다 Webshare 사용량 API(bandwidth_total)를 읽어 우리가 센 값과 비교하고, 둘 중 큰 값을 씁니다. 바뀌는 주거용 1GB도 같은 방식으로 맞춰 봅니다.

그러면: 우리 서버가 세는 양과 Webshare가 세는 양이 다르더라도(요청·응답 머리, 실패한 연결 등) Webshare가 멈추기 전에 우리가 먼저 멈춥니다. 다음 달이 시작되면 다시 켭니다.

다른 선택: 우리가 센 값만 → API 키가 필요 없지만 Webshare 쪽 값과 어긋날 수 있음. / API 값만 → 1시간 사이에 한도를 넘을 수 있음.

추천: 둘 다 보고 큰 값.

#4업체 쪽 오류면 그 업체 길 전체를
바로 멈추고 메일

[안] Webshare가 돌려주는 오류 중 업체 쪽 문제인 것(인증 실패 407, 동시 연결 초과 429 client_connect_high_concurrency, 계정 확인·정지)이 오면, 사이트별 "연달아 5번" 규칙을 기다리지 않고 Webshare 길(정적·바뀌는 주거용) 전체를 멈추고 메일을 보냅니다. EC2 IP로는 계속 조회합니다. 다시 켜는 것은 설정으로 합니다.

그러면: 계정 확인(KYC)으로 Webshare가 멈췄을 때 모든 요청이 실패하며 사이트별 쉼이 줄줄이 생기는 일을 막습니다. 동시 연결 초과면 메일을 보고 Webshare 동시 연결 기능을 더 사거나 우리 동시 건수를 줄입니다.

다른 선택: 사이트별 규칙만 → 업체 문제인데 사이트가 막힌 것처럼 기록되고 메일이 사이트 수만큼 옴.

추천: 업체 쪽 오류는 업체 단위로.

5정부 사이트 도서관은
바뀌는 주거용으로 보내지 않음

Webshare는 바뀌는 주거용에서 정부 사이트를 제한 분야로 적어 두었고, 많이 보내면 계정 확인을 요구할 수 있습니다. .go.kr 도서관은 고정 IP(EC2·정적 20개)로만 보냅니다.

#5.go.kr 주소는 고정 IP로만

[안] 주소가 .go.kr로 끝나는 도서관 사이트에는 바뀌는 주거용을 쓰지 않고, EC2 IP와 정적 20개만 씁니다(IP마다 1건·1초 그대로). .or.kr(강동구립 gdlibrary.or.kr 등)은 정부 사이트로 볼지 Webshare 기준을 확인 못 해 일반 사이트로 둡니다.

그러면: 정부 사이트 때문에 Webshare 계정 전체가 멈출 위험을 줄입니다. 대신 .go.kr 도서관은 몰릴 때 바뀌는 주거용 5건이 더해지지 않습니다. AWS IP를 막는 .go.kr(부산 등)은 정적 20개에 기대게 됩니다.

다른 선택: 구분 없이 씀 → 더 빠르지만 계정 확인 위험. / 사서 시험해 보고 정함 → 시험 중 계정이 확인 절차에 걸릴 수 있음. / Webshare에 미리 문의 → 확실하지만 답을 기다려야 함.

추천: .go.kr은 고정 IP로만, 주소 끝 목록은 설정으로.

정해지면 이 페이지와 앞 페이지(첫 배포 프록시)의 결정을 사이클 17 인계에 넣을 파일로 정리하고, ADR-0095를 바꾸는 ADR 초안을 따로 보여 드립니다. 이 글은 요약이며 근거는 docs/research/deploy/multi-source-ip.md 8절에 있습니다.
