## 2. 사이클 15가 기대는 것 (나가는 IP가 하나일 때)

- 도서관 사이트마다 동시 1건·앞 응답 끝난 뒤 1초(`host-max-concurrency: 1`, `host-min-interval: 1s`)는 그대로 두는 방향 [안] (결정 페이지 `docs/research/deploy/easy/2026-10-12-hosting-options.html` #7, 아직 칩 미결정). 나가는 IP가 하나일 때는 follow-up #1의 "봇이 몰려도 도서관 사이트 하나는 1초에 한 번"이 성립. IP가 여러 개면 3절대로 "IP 수만큼"
- 예외: 교보 구독형 서버(`*.dkyobobook.co.kr`)는 서비스 조회를 1초 간격 없이 동시 3건(설정으로 조절), 느려지면 1건, 막힘 신호면 멈추고 화면에 "확인 불가" (ADR-0094, 제안됨). 봇이 몰리면 이 서버는 나가는 IP마다 동시 3건까지 받음(3절)

## 3. 그 뒤 정해진 것 (2026-10-13, ADR-0095 제안됨)

- 서비스 대출 조회는 나가는 길 세 가지(본 서비스 직접 / 직접 + 업체 고정 IP 프록시 여러 곳 / 조회 서버, 조회 서버마다 업체 프록시)를 설정으로 고름
- 도서관 한 곳에 보내는 양은 **나가는 IP마다 따로** 셈 → 2절의 "봇이 몰려도 도서관 사이트 하나는 1초에 한 번"은 "나가는 IP 수만큼 1초에 한 번"이 됨. follow-up #1의 분석을 이에 맞춰 다시 볼 것
- 한 IP가 막히면 그 IP만 그 사이트에서 멈추고 다른 IP로 계속
- 서비스 대출 조회의 User-Agent는 일반 브라우저와 같은 값(우리 이름 없음). 수집기는 그대로

## 3-1. (이전 기록) 그때 정하는 중이던 것

- 서비스 대출 조회를 **업체 고정 IP 프록시 여러 곳**을 돌아가며 거쳐 보낼지 (사용자 방향: "하나의 서버에서 하되 여러 업체 프록시를 쓰도록", 결정 페이지 `docs/research/deploy/easy/2026-10-13-lookup-proxy-decisions.html`). 정해지면 도서관 사이트 쪽에서 보이는 IP가 여러 개가 됨. 도서관 한 곳이 받는 양은 서버 한 곳에서 합쳐 세는 안 [안]
- 프록시를 쓰더라도 User-Agent는 우리 이름 그대로 두는 안 [안] → R1-5의 "이름 밝힌 봇 거르기"와는 방향이 같음(우리도 이름을 밝힘)

## 5. 사이클 15에 전한 글 (2차, 2026-10-13)

### 사이클 16에서 확인한 것

- 이용 기록(IP 포함)에 사용자가 끄는 설정을 법으로 두어야 한다는 근거는 찾지 못함. 법 제30조①7호·개인정보위 처리방침 작성지침(2026.4.) 항목 14(p.54–55)의 "자동 수집 장치"는 웹·앱에 설치하는 쿠키 등이고, 서버가 남기는 IP·이용 기록은 항목 3(p.24–25) "처리하는 개인정보 항목"에 적는 대상. 개인정보위 명시 해석례는 확인 못 함(추론). 15는 끄기 설정 없이 가도 됨으로 보임. 처리방침의 항목·목적·보유 기간·법적 근거는 16이 적음. 근거: 사이클 16 `research.md` 5절

### 사이클 17(첫 배포)에서 정한 것 중 15에 닿는 것

1. 서버 앞에 Cloudflare Tunnel [확정]. 설정이 없으면 nginx와 서비스가 모든 요청의 IP를 `cloudflared` 주소 하나로 봄. 배포 때 nginx가 `CF-Connecting-IP`를 사용자 주소로 읽게 함 [확정]. 15가 남기는 IP가 실제 사용자 IP가 되려면 서비스가 nginx가 넘긴 주소(`X-Real-IP`/`X-Forwarded-For`)를 믿도록 설정해야 함 → 15 설계에서 서비스가 어느 값을 IP로 쓰는지 확인 [확인 필요]. 이 설정이 없으면 R2-5 클릭 알림 IP당 1분 60번 제한도 모든 사용자에게 하나로 걸림
2. 처음 2주 운영 서버는 Lightsail 서울 4GB [확정]. 15 결정 페이지의 "AWS WAF는 배포 사이클에서"는 Lightsail 앞에 바로 붙지 않을 수 있음. 17은 AWS WAF를 범위에서 뺐고, Cloudflare 무료 요청 한도 규칙(1개, IP 기준, 10초 단위)으로 대신할지 다시 봄
3. nginx 접속 기록 보관 기간은 17 범위에서 정함. 정해지면 15·16에 알림
4. 모니터링은 Prometheus·Grafana·node_exporter를 서버에 직접 [확정]. 4GB 메모리를 함께 쓰므로 15의 AC-16(기록 켜기 전후 메모리 차이) 잴 때 함께 보면 좋음
5. 대출 조회 나가는 길(ADR-0095, 제안됨): 도서관 사이트에 보내는 양을 나가는 IP마다 따로 셈 → "봇이 몰려도 도서관 사이트 하나는 1초에 한 번"은 나가는 IP가 하나일 때만 맞고, 여러 개면 "IP 수만큼"(3절)
