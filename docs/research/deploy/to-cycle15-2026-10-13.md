# 사이클 15 세션에 전달 (배포 조사 세션, 2026-10-13)

배포 조사 세션(사이클 밖, `docs/research/deploy/hosting-options.md`)에서 2026-10-12~13에 정한 것 가운데, 사이클 15(사용자 행동 기록) 명세와 결정 페이지 `easy/2026-10-13-spec-followup-decisions.html`에 닿는 것만 적었습니다. 사이클 15 문서는 이 세션에서 고치지 않았습니다.

## 1. 정해진 것 (사용자 승인, 2026-10-13)

| 정한 것 | 사이클 15에 닿는 곳 |
|---|---|
| 처음 2주 운영 서버는 **AWS Lightsail 서울 4GB 묶음**(EC2 아님). 그 뒤 본가 노트북으로 옮김 | follow-up #1의 "AWS WAF는 배포 사이클에서 봄": Lightsail 앞에는 WAF를 바로 붙일 수 없을 수 있음(follow-up 페이지에 적힌 대로 WAF는 CloudFront·로드밸런서 앞에 둠). Lightsail에서 쓸 수 있는지는 확인 안 함 |
| 클라우드 서버와 노트북 모두 **Cloudflare Tunnel**로 연결. 모든 요청이 Cloudflare를 거침 | 봇 막기 후보에 Cloudflare 무료 요청 한도 규칙(1개, IP 기준, 10초 단위, https://developers.cloudflare.com/waf/rate-limiting-rules/ , 확인 2026-10-12)을 더해 볼 수 있음 |
| 배포 때 nginx가 Cloudflare가 붙이는 **`CF-Connecting-IP`를 사용자 주소로 읽게** 설정. 터널에서도 이 헤더가 붙는지는 배포 때 시험 [확인 필요] | 이 설정이 없으면 nginx는 모든 사용자를 `cloudflared` 주소 하나로 봄 → R2-5(클릭 알림 IP별 한도)와 기존 IP별 한도가 모든 사용자에게 하나로 걸리고, follow-up #3·#4의 "nginx 접속 기록의 IP"도 모두 같은 값이 됨 |
| 모니터링은 **Prometheus·Grafana·node_exporter를 서버에 직접** 띄움(2주 Lightsail, 노트북 모두) | 이용 기록(사이클 15)과는 다른 것(서버 상태 숫자). 4GB 서버에서 메모리를 함께 씀 → AC-16(기록 켜기 전후 메모리 차이) 잴 때 함께 보면 좋음 |
| 화면은 지금처럼 nginx가 내려 주고 앞의 Cloudflare 캐시만 씀 | 없음 |

## 2. 사이클 15가 기대는 것 (나가는 IP가 하나일 때)

- 도서관 사이트마다 동시 1건·앞 응답 끝난 뒤 1초(`host-max-concurrency: 1`, `host-min-interval: 1s`)는 그대로 두는 방향 [안] (결정 페이지 `docs/research/deploy/easy/2026-10-12-hosting-options.html` #7, 아직 칩 미결정). 나가는 IP가 하나일 때는 follow-up #1의 "봇이 몰려도 도서관 사이트 하나는 1초에 한 번"이 성립. IP가 여러 개면 3절대로 "IP 수만큼"
- 예외: 교보 구독형 서버(`*.dkyobobook.co.kr`)는 서비스 조회를 1초 간격 없이 동시 3건(설정으로 조절), 느려지면 1건, 막힘 신호면 멈추고 화면에 "확인 불가" (ADR-0094, 제안됨). 봇이 몰리면 이 서버는 나가는 IP마다 동시 3건까지 받음(3절)

## 3. 그 뒤 정해진 것 (2026-10-13, ADR-0095 제안됨)

- 서비스 대출 조회는 나가는 길 세 가지(본 서비스 직접 / 직접 + 업체 고정 IP 프록시 여러 곳 / 조회 서버, 조회 서버마다 업체 프록시)를 설정으로 고름
- 도서관 한 곳에 보내는 양은 **나가는 IP마다 따로** 셈 → 2절의 "봇이 몰려도 도서관 사이트 하나는 1초에 한 번"은 "나가는 IP 수만큼 1초에 한 번"이 됨. follow-up #1의 분석을 이에 맞춰 다시 볼 것
- 한 IP가 막히면 그 IP만 그 사이트에서 멈추고 다른 IP로 계속
- 서비스 대출 조회의 User-Agent는 일반 브라우저와 같은 값(우리 이름 없음). 수집기는 그대로

## 3-1. (이전 기록) 그때 정하는 중이던 것

- 서비스 대출 조회를 **업체 고정 IP 프록시 여러 곳**을 돌아가며 거쳐 보낼지 (사용자 방향: "하나의 서버에서 하되 여러 업체 프록시를 쓰도록", 결정 페이지 `docs/research/deploy/easy/2026-10-13-lookup-proxy-decisions.html`). 정해지면 도서관 사이트 쪽에서 보이는 IP가 여러 개가 됨. 도서관 한 곳이 받는 양은 서버 한 곳에서 합쳐 세는 안 [안]
- 프록시를 쓰더라도 User-Agent는 우리 이름 그대로 두는 안 [안] → R1-5의 "이름 밝힌 봇 거르기"와는 방향이 같음(우리도 이름을 밝힘)

## 4. 사이클 15에서 보면 좋을 것 (제안)

- follow-up #1의 AWS WAF 전제를 "Lightsail + Cloudflare Tunnel"에 맞춰 다시 볼지
- R2-5 IP별 한도와 follow-up #3·#4가 `CF-Connecting-IP` 설정(배포 사이클)에 기대고 있다는 점을 명세에 적을지
