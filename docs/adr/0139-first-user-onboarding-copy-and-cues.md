# ADR-0139: 첫 사용자 안내 — 첫 화면 머리글은 이득·불편 순서, 지역 줄에서 "조건·설정" 말 빼기, "우리 동네만?" 오해는 그림으로, 고른 직후 내 숫자, 꼬리표는 가입 근거로, 뺀 도서관은 맨 아래 한 줄, 탈퇴는 계정 칸 안

Status: Accepted
Date: 2026-10-20
Cycle: 22-first-screen-usability (덧붙임 5-A단계)
Supersedes: 없음 (부분 대체: 사이클 22 문구표의 지역 줄·꼬리표 이름, 사용자 2026-10-19 "탈퇴하기는 아주 아래로"·"[전국에서 더 찾기] 빼자", 첫 화면 재설계 문구(2026-10-19))

## 배경

- 2026-10-20 친구분 두 분의 피드백(카카오톡): "대체 왜 사는 곳과 일하는 곳을 골라야 하는지", "재직증명서 내야 함?", "어필 포인트가 없다 — 서비스를 왜 사용하는가", "구글 검색 메인창 fork 느낌", "처음 접속하면 소개가 나오는 식은?", "로그인 유저 대상?".
- 사용자 방향: "도서관 가입을 위한 정보 제공이 핵심. 왜 필요한지 납득하게. 기존 전자도서관의 '가입 조건이 자기 멋대로'를 알려야 하고 멘트도 자연스럽게." "서울 강서구에 거주하면 강서구만 되는 줄 아는데 강동구나 송파구도 되거든 … 문장만 있으면 안 읽으니까 읽게끔." "강서구는 예시야."
- 검토: `docs/research/screen-feedback/first-user-retention.md`, 결정 페이지 `easy/2026-10-20-first-user-retention.html`(결정 11개, 2026-10-20 저장).

## 결정

1. **첫 화면 머리글은 이득 → 불편 → 책첵이 하는 일** 순서. 불편은 "도서관마다 가입 조건이 달라요 — 거주, 재직, 또는 상관없이" 한 줄. 세 갈래 이름은 **"거주 · 재직 · 상관없이"**로 모든 화면에서 통일 [확정] (사용자 승인 + 낱말 제시, 2026-10-20). 문구는 메인 화면 (나)로 확정 (사용자, 2026-10-20, `easy/2026-10-20-main-screen-options.html`): 제목 "우리 동네 도서관만 될까요? 아니요.", 본문 첫 줄에 예시 "강서구에 살아도 강동구·송파구 전자도서관에 가입할 수 있어요."(예시를 문구에 넣는 것은 됨 — 사용자 "강서구 살아도 강동구 책 빌릴 수 있다 이런 것을 녹이고 싶어"). 폰 순서 머리글 → 검색창 → 지역 줄 → 카드 [확정].
2. **"우리 동네 도서관만 될까?"라는 오해는 글이 아니라 알약 그림**으로 푼다(PC 첫 화면 카드, 폰도). 카드는 "예: 서울 강서구에 살면" 거주/재직/상관없이 세 줄 알약(강서구·강동구·송파구·마포구 +27 / 일하는 곳 / 고흥·목포·군산 +35)으로, 예시 지역을 문구로 씀 [확정] ((나) 선택 2026-10-20; 3차 판의 "특정 지역 없는 자리말" 그림은 사용자가 미승인·(나)로 대체). 3단계 카드("이렇게 이용해 보세요")는 이 그림이 대신한다.
3. **지역 줄에서 "조건·설정"이라는 말을 뺀다**: "사는 곳을 알려 주시면 가입할 수 있는 도서관을 골라 드려요 [사는 곳 고르기]" / "서울 강남구에 살아요 [바꾸기]". 펼친 상자 맨 위 "왜 묻나요? 도서관마다 가입 조건이 달라서요." 한 줄만 [확정] (사용자: 저장·증명 문장은 빼기).
4. **시군구를 체크한 직후 상자 안에 그 사람의 숫자 그림**("서울 강서구 → 가입할 수 있는 도서관 70곳: 강서구 1 · 서울 다른 구 31 · 어디 살든 38 · 가야 하는 곳 9 [이름 보기]"). 숫자는 `GET /api/v1/libraries?residenceRegionIds=…`를 **체크 직후 한 번** 보내 세고 5분 재사용(ADR-0138 "도서관 목록은 필요할 때만"과 같은 캐시). 자기 시군구/시도를 응답으로 가를 수 없으면 합쳐 "서울 거주로 32곳" [확정].
5. **결과 꼬리표 [내 지역 가입]을 가입 근거로**: `priorityGroup` MY_SIGUNGU → [{시군구} 거주 가입], MY_SIDO → [{시도 짧은 이름} 거주 가입], 일하는 곳만 골랐으면 "재직", 둘 다면 "거주·재직" [확정].
6. **검색에서 뺀 도서관은 결과 맨 아래 한 줄**: "가입 조건이 맞지 않는 도서관은 찾지 않았어요 · [전국에서 찾기]"(지역·직접 추가가 있는 검색에서만, 수 없음; 누르면 그 검색만 `scope=all`). 2026-10-19의 "[전국에서 더 찾기] 빼자"를 글 한 줄로 되살림 [확정].
7. **로그인 창 설명** "로그인하면 거주·재직 지역과 직접 추가한 도서관이 계정에 저장돼 폰과 PC에서 똑같이 보여요. 로그인하지 않아도 모든 기능을 쓸 수 있어요." 회원가입 유도는 하지 않음 [확정].
8. **처음 한 번 뜨는 소개 창·애니메이션은 두지 않음** [확정].
9. **탈퇴는 마이페이지 "계정" 칸 안 맨 아래 회색 글자 링크**, 계정 칸에 [로그아웃]도 함께. 빈 공간 뒤 단추(2026-10-19)는 없앰 [확정].
10. 모두 웹 화면만. 서버 API·표 변경 없음. 사이클 22 인계서 5-A단계로 넘김 [확정] (사용자: "현재 사이클 22 진행 중인데 넣어줘라").

## 이유 (사용자 발언)

- "지금 도서관 가입을 위한 정보 제공이 핵심인데 이것을 어디에 둘 것인지 사용자가 이게 왜 필요한지 납득하게 할 것인지가 우선이야. 그러기 위해서는 기존 전자도서관의 거지같은 점 '가입 조건이 자기 멋대로' 이걸 알려야 하고 멘트 같은 것도 좀 더 자연스러워야 해" (2026-10-20)
- "문장만 있으면 길고 안 읽으니까 어떻게 읽게끔 안 되나" / "아니 강서구는 예시야 예시" (2026-10-20)
- 안 3 기타: "고르는 데만 쓰고 이 브라우저에만 저장돼요. 증명은 도서관이 가입할 때 확인해요. 이거 빼고 해"; 안 5: "거주, 재직, 직접추가로"; 안 8: "현재 사이클 22 진행 중인데 넣어줘라"; 안 9: "문구 좀 더 짧고 간단하게" (결정 페이지, 2026-10-20)

## 검토한 대안

- 처음 한 번 소개 창(친구분 제안) — 닫으면 끝, 건너뛰는 사람에게 효과 없음 → 머리글·그림이 매번 대신.
- 한 지역(서울 강서구)을 예로 든 실제 이름 그림 — 다른 지역 사람에게 남의 예 → 자리말 그림 + 고른 뒤 내 숫자.
- 회원가입 유도(친구분 제안) — 사용자 거절("거부감").
- 탈퇴를 별도 계정 화면으로 — 로그아웃·탈퇴뿐이라 과함.
- 뺀 도서관 줄 없이 지금처럼(①이 빌 때만 [전국에서 찾기]) — "다른 데는 없나"가 궁금한 사람이 갈 곳 없음.
