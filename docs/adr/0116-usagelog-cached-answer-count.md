# ADR-0116: 사용 기록에 도서관별 "캐시 답" 수를 남긴다

Status: Accepted
Date: 2026-10-15
Cycle: 19-author-angle-brackets
Supersedes: 없음 (ADR-0097 쓰기 방식 그대로)

## 배경
사이클 15 사용 기록은 도서관에 실제로 보낸 요청만 응답 수로 세고, 3분 캐시에서 꺼낸 답은 어디에도 남기지 않는다(dev `BatchRunner.java` 334~338행). 사이클 15 회고에서 이것을 확인했고, 기록은 첫 배포 날부터 쌓이므로 배포 전에 넣으면 첫날부터 캐시 답 수를 알 수 있다.

## 결정
`usagelog.library_response_daily`에 `cached_count`(정수, 0 이상, 기본 0)를 더한다(새 변경 파일 `usagelog/002`). 공개 결과 값에 `CACHED`를 더해, 캐시에서 답을 꺼내는 두 곳(직접 찾기 묶음, 도서관별 더 보기)이 이 값으로 알리면 하루 줄의 `cached_count`가 1 는다. 응답 시간·성공/실패 수와 서버 로그 줄에는 넣지 않는다. 사이클 19 인계서의 "따로 하는 작은 일"로 한다.

## 이유 (사용자 발언)
- "도서관별 하루 표에 \"캐시 답\" 칸을 하나 더하자" (2026-10-15, 사이클 15 회고 결정 #3)
- 모양·때(사이클 19에 끼움): 승인 (회고 이어서 #2), 칸 이름: 승인 (명세 결정 #10)
- `CACHED` 값, 새 변경 파일: 제안 → 승인 (설계 결정 #8·#9, 2026-10-15)

## 검토한 대안
### A안: 결과 값에 `CACHED` 하나 더함 (채택)
- 장점: 공개 API가 값 하나만 늘어남, 빠진 처리가 있으면 컴파일이 알려 줌
- 단점: 그 경우 응답 시간 인자는 무시됨
### B안: 새 공개 함수 `recordCachedAnswer`
- 단점: 공개 함수가 늘어남
- 채택하지 않은 이유: [이유 미확인]
### C안: 기존 함수에 "캐시냐" 인자
- 단점: 부르는 곳이 모두 바뀌고 어긋난 조합이 생김
- 채택하지 않은 이유: [이유 미확인]
### D안: 첫 배포 뒤 통계 사이클에서
- 단점: 배포 첫날부터의 캐시 답 수가 남지 않음
- 채택하지 않은 이유: [이유 미확인] (사이클 19에 끼우는 안을 승인)

## 결과
- 상수 기본값이라 칸을 더해도 표를 다시 쓰지 않음 (PostgreSQL 18 ALTER TABLE Notes, https://www.postgresql.org/docs/current/sql-altertable.html, 확인 2026-10-15)
- 기존 `usagelog/001`은 고치지 않음

## 나중에 분리할 때
- `usagelog` 안에서 끝남
