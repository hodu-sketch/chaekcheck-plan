# ADR-0037: 검색 모듈은 회원을 모르고, 웹이 "내 도서관"을 파라미터로 넘김

Status: Accepted
Date: 2026-10-01
Cycle: 05-login-account
Supersedes: 없음

## 배경

회원이 생기면 "내 도서관 = 지역으로 가입 가능한 곳 ∪ 직접 추가한 곳"(`docs/research/member-and-alerts/outline.md` 2.2)만 검색하는 필터가 필요합니다. 이 필터를 `catalog`·`availability`에 어떻게 전달할지 정해야 했습니다 (`integration-plan.md` 3.2). 지금 검색은 브라우저가 지역 ID를 파라미터로 보내고 계획을 브라우저가 가집니다 (ADR-0014). 구현은 사이클 06(내 도서관·검색 연결)에서 하지만, 사이클 05의 `auth` API 모양에 영향을 주므로 지금 기록합니다.

## 결정

웹이 `/api/v1/me` 쪽 API로 지역과 직접 추가 도서관을 받아, 기존 `residenceRegionIds`·`workRegionIds`·`scope=joinable`에 새 칸 `libraryIds`(직접 추가, 자격과 무관하게 포함)를 더해 검색 API로 보냅니다. `catalog`·`availability`는 `auth`·`member`에 의존하지 않습니다. `library.planSearch`에 "이 도서관들은 자격과 상관없이 포함" 옵션만 더합니다.

## 이유 (사용자 발언)

- [이유 미확인] (사용자가 선택지 중 "안 1: 웹이 파라미터로"를 고름, 2026-10-01)
- 필터를 하나로 두자는 방향은 사용자: "난 좀 단순했으면 하는데" (2026-10-01)

## 검토한 대안

### 안 1: 웹이 파라미터로 (채택)
- 장점: 검색 모듈이 회원을 모름. 주소를 공유해도 비회원이 같은 결과를 봄. 지금 구조(ADR-0014)와 같음
- 단점: 직접 추가 도서관이 많으면 주소가 길어짐 → 상한 필요 [안: 20, 사이클 06에서 확정]. 사용자가 주소를 고쳐 다른 도서관을 넣을 수 있음(공개 자료라 해가 없음)

### 안 2: 서버가 세션으로 (`scope=mine`)
- 장점: 주소가 짧음. 웹이 회원 정보를 매번 붙이지 않아도 됨
- 단점: `catalog → member`, `availability → member` 의존이 새로 생김. 세션 있는 요청과 없는 요청을 둘 다 처리. 캐시 키에 회원이 섞일 위험
- 채택하지 않은 이유: [이유 미확인]

## 결과

- 좋아지는 점: 검색 API가 계속 인증 없는 GET으로 남음. 회원 기능을 더해도 검색 모듈의 의존 방향이 바뀌지 않음
- 감수하는 점: 웹이 로그인 뒤 회원 정보를 먼저 받아야 검색 주소를 만들 수 있음. `libraryIds` 상한과 검증 순서를 새로 정해야 함(사이클 06)
- 나중에 분리할 때: 검색 서비스가 회원 서비스를 부르지 않음. 안 2로 바꾸려면 검색 모듈에 회원 의존을 추가하고 캐시 키를 다시 설계해야 함
