# ADR-0168: nginx는 고정 판으로 두고 화면 파일·설정은 서버 폴더에서 바꿈

Status: Accepted
Date: 2026-10-29
Cycle: 27-zero-downtime-deploy
Supersedes: 없음

## 배경
지금 web 이미지(`deploy/prod/web.Dockerfile`)에 nginx 설정 4개와 React 빌드(`web/dist`)가 같이 들어 있어, 화면만 바꿔도 nginx 컨테이너가 다시 만들어지고 Cloudflare Tunnel이 붙은 nginx가 잠깐 사라진다. 범위 #2 "화면 판 바꾸기도 끊김 없이"를 지키려면 nginx 컨테이너를 다시 만들지 않고 파일만 바꿔야 한다.

## 결정
`web` 서비스는 판을 고정한 nginx 기본 이미지로 바꾸고, 설정은 `/srv/chaekcheck/nginx/`, 화면 파일은 `/srv/chaekcheck/web/`를 폴더째 읽기 전용으로 붙인다. 화면은 지금처럼 `chaekcheck/web:X` 이미지로 만들어 보내되 서버에서 꺼내 `releases/X`에 두고(앞 판 assets도 함께), `current` 링크를 바꾼 뒤 reload한다. 되돌리기는 링크를 앞 판으로 돌리는 것이고, 폴더는 두 판만 남긴다. nginx 이미지 판 올리기는 점검 배포다.

## 이유 (사용자 발언)
- 설계 결정 #3 승인 (2026-10-29). 이유는 말하지 않음 [이유 미확인]

## 검토한 대안
### A안: 고정 nginx + 서버 폴더 + 판 폴더 링크 (채택)
- 장점: 이미지 만들기·보내기·정리 흐름 그대로, 되돌리기가 링크 하나
- 단점: 서버 폴더 둘이 늘고, `release.sh`가 nginx 설정도 보내야 함
### B안: web 이미지 없이 dist를 묶음 파일로 바로 보냄
- 단점: 판 관리·되돌리기 규칙을 새로 짜야 함
- 채택하지 않은 이유: [이유 미확인]
### C안: 떠 있는 nginx에 `docker cp`로 넣기
- 단점: 컨테이너가 다시 만들어지면 이미지 안의 옛 화면으로 돌아감
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 화면 배포·되돌리기 때 nginx·Tunnel 연결이 끊기지 않음, React 코드는 그대로
- 감수하는 점: 파일 하나만 mount하면 바꿔도 옛 파일을 보므로 반드시 폴더째, nginx 판 올리기는 점검 배포
- 나중에 되돌리거나 서비스로 분리할 때의 비용: 낮음. 화면을 CDN(S3 등)으로 옮길 때도 판 폴더 방식이 그대로 맞음
