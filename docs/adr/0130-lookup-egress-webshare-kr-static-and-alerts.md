# ADR-0130: 서비스 대출 조회는 첫 배포부터 서버 자기 IP와 Webshare 한국 정적 주거용 20개로 나가고, 업체 프록시와 서버 공인 IP 여러 개를 모두 지원하며, 한도에 닿기 전에 멈추고 메일로 알린다

Status: Accepted
Date: 2026-10-16
Cycle: 사이클 밖 (배포 조사, `docs/research/deploy/multi-source-ip.md`)
Supersedes: 0095

## 배경
ADR-0095(2026-10-13)는 대출 조회 나가는 길을 셋(직접·업체 고정 IP 프록시·조회 서버)으로 두고, IP마다 따로 세고, 막힌 IP만 멈추고, 일반 브라우저 User-Agent로 보내기로 했다. 업체 프록시는 고정 IP 상품만 넣고 주거용·IP가 바뀌는 상품은 뺐다(G안 기각). 2026-10-16 조사에서 (1) 서버 한 대에 공인 IP를 여러 개 붙이는 길, (2) Webshare 한국 정적 주거용(20개 월 $6, 한국 759개 재고)을 살폈다. 운영 EC2는 무료 플랜 제약으로 서울이 아니라 시드니(<서버 IP>)라 한국 IP는 업체에서만 얻는다. 사용자가 20개를 사서 시험했고, 20개 모두 KT(AS4766) 한국 IP, 강동 전자도서관 응답은 시드니 EC2→프록시 약 1.7초였다.

## 결정
- ADR-0095의 내용(세 길을 설정으로 고름, 나가는 IP마다 따로 셈, 막힌 IP만 그 사이트에서 멈춤, 일반 브라우저 User-Agent, 수집은 대상 아님)은 그대로 이어받는다.
- 나가는 길 종류에 "서버 자기 공인 IP 여러 개"를 더한다. 업체 프록시와 서버 공인 IP 여러 개를 둘 다 되게 만들고, 설정을 따로 두어야 하면 따로 둔다. 본 서비스 서버가 직접 조회하는 길과 따로 둔 조회 서버로 조회하는 길 **둘 다 개발**하고, 두 길 모두 같은 나가는 길 설정을 쓴다.
- 업체 프록시에 정적 주거용(IP 고정)과 요청마다 IP가 바뀌는 주거용을 모두 허용한다(ADR-0095 G안을 뒤집음). 첫 배포는 EC2 자기 IP 1개 + Webshare 한국 정적 주거용(공유) 20개로 나가고, 바뀌는 주거용은 나중에 더한다.
- 고정 IP 21개 중 그 사이트에 보낼 수 있는 IP를 먼저 쓴다(IP마다 동시 1건·1초, 교보 구독형 서버는 IP마다 동시 3건). 바뀌는 주거용을 더하면 21개가 모두 바쁘거나 막혔을 때만 쓰고, 접속 주소 하나를 길 하나로 보고 사이트마다 동시 5건(설정), 1초 간격 없음, 같은 사이트에서 연달아 5번 막히면 그 사이트에서만 쉰다.
- 업체 데이터는 우리 서버가 센 양과 Webshare 사용량 API 값 중 큰 값으로 보고 80%에 경고, 90%에 그 업체 길만 멈춘다(확장 모드 응답은 세지 않음). Webshare 업체 쪽 오류(407·429 동시 연결 초과·계정 확인)면 Webshare 길 전체를 바로 멈추고 EC2 IP로 계속한다.
- CloudWatch 경보 → AWS SNS 메일로 알린다(같은 일 1시간에 한 번): 길 쉼 시작·7일 상한·풀림, 모든 길 막힘("확인 불가"), 업체 데이터 80%·90%, 업체 계정 문제로 업체 길 전체 멈춤, 매일 아침 요약. 사이클 17의 "알림은 두지 않음"을 바꾼다.

## 이유 (사용자 발언)
- "조회 서버에서 여러 출처 아이피를 설정으로 하는 것도 고려 중이야 (조회 서버 따로 두지 않고 자체 서버에서 할 때도)" (2026-10-16)
- "프록시랑 공인 아이피 여러개 다 되도록 구현 했으면 해 분리가 필요해서 각각 설정 따로 해야 하면 따로 하고" (2026-10-16)
- "이거 자체 서버에서 조회하는거랑 따로 조회서버 두는거랑 둘 다 개발되어야 해" (2026-10-16, 이 ADR 초안 승인 때)
- "정적 주거용도 괜찮은 것 같아", "요청마다 ip가 바귀는 주거용도 같이 했으면 해 정적 주거용이랑 같이" (2026-10-16)
- "아니 가격이 webshare가 훨씬 매력적이라서이러는거자나" (2026-10-16)
- "지금 프록시가 없으면 1초 제한에 걸려서 사용자가 거의의미가없어; 실제로 지인 몇 명에게 부탁했는데 로딩 이야기가 있어서 그래서 프록시를 같이 가야해" (2026-10-16)
- "Webshare 정적 20개 이거먼저 할거고 동적은 좀 더 나중에 고민해도 될 것 같아" (2026-10-16)
- "이런데 나한테 알려주기가 잘 되어야 해", "고정 IP 21개도 용량 제한이 있지 않아? 이것도 막히기 전에 그만 하고 나한테 잘 알려줘야 해" (2026-10-16)
- 고정 IP 먼저·바뀌는 주거용 동시 5건·연달아 5번·90% 멈춤·CloudWatch 메일·알릴 일 다섯 가지·업체 오류면 업체 길 전체 멈춤: 제안 → 승인 (2026-10-16)

## 검토한 대안
### A안: 서버 자기 IP + Webshare 한국 정적 20개로 첫 배포, 두 방식 모두 지원, 한도 전 멈춤·메일 (채택)
- 장점: 첫날부터 한 사이트에 1초 최대 21건, 한국 IP로 나감, 월 $6
- 단점: 업체 약관(정부 사이트 사용량 기준·KYC)에 묶임, 시드니에서 한국 프록시를 거쳐 왕복이 한 번 늚
### B안: 첫 배포는 프록시 없이, 막히면 EC2 IP 추가, 그다음 업체
- 채택하지 않은 이유: "지금 프록시가 없으면 1초 제한에 걸려서 사용자가 거의의미가없어 …" (2026-10-16)
### C안: 업체 프록시에 정적 주거용만 넣고 바뀌는 주거용은 계속 뺌
- 채택하지 않은 이유: "요청마다 ip가 바귀는 주거용도 같이 했으면 해 정적 주거용이랑 같이" (2026-10-16)
### D안: 서버 공인 IP 여러 개만 (EC2에 IP 추가, 개당 월 약 $3.65)
- 단점: 시드니 EC2라 붙이는 IP도 호주 IP
- 채택하지 않은 이유: "가격이 webshare가 훨씬 매력적이라서" (2026-10-16), 그리고 둘 다 되게 하라는 말씀
### E안: 알림 없이 로그·지표만 (사이클 17 그대로)
- 채택하지 않은 이유: "이것도 막히기 전에 그만 하고 나한테 잘 알려줘야 해" (2026-10-16)
### F안: `.go.kr` 도서관은 바뀌는 주거용으로 보내지 않음
- 미룸: "이건 잘 모르겠어. 근데 이건 나중으로 미뤄도 될 것 같아 일단 고정ip먼저 할거거든....." (2026-10-16)

## 결과
- 좋아지는 점: 첫 배포부터 한국 IP 20개로 대출 조회를 나눠 보냄(강동 전자도서관 시드니→프록시 약 1.7초), 집 IP를 막은 교보 구독형 서버도 열림, 한도에 닿기 전에 멈추고 메일이 옴
- 감수하는 점: ADR-0095 "감수하는 점"(막힌 뒤 다른 IP로 계속 들어가는 모양, 대법원 2021도1533) 그대로이고 주거용 IP로 더 뚜렷해짐. Webshare 공유 IP라 다른 사용자 때문에 막힐 수 있음. Webshare IP Authorization이 1개라 EC2 IP만 등록(집 PC에서는 못 씀). Webshare 계정이 확인 절차로 멈추면 EC2 IP 하나로 돌아감. 도서관 한 곳이 받는 양이 IP 수만큼(최대 21건/초) 늘어남
- 나중에 되돌릴 때: 설정에서 Webshare 길을 빼면 EC2 직접만 남음. 바뀌는 주거용은 설정으로 더함(`docs/backlog.md`)
- 나중에 서비스로 분리할 때: 조회 서버가 이미 따로 배포되는 단위라 길 설정을 그대로 가져감
