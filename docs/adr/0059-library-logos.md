# ADR-0059: 도서관 로고는 자체 로고가 있는 공공도서관만, 미리 줄인 파일로 보이고 바로 내릴 수 있게 한다

Status: Accepted
Date: 2026-10-05
Cycle: 07-candidate-libraries
Supersedes: 없음

## 배경
수집 세션이 등록 도서관 로고를 모았다(`chaekcheck-data\logos\registered-logos-2026-10-05.tsv`: 자체 로고 199곳, 업체 기본 로고 43곳, 없음 36곳). 로고는 저작물·상표·지자체 상징물일 수 있어, 웹에 공개됐다는 것만으로 이용 허락이 되지 않는다(`docs/research/maintenance/library-logos.md` 4절, 저작권법·상표법·부정경쟁방지법·지자체 조례 원문 2026-10-05 확인). 처음에는 이번 사이클에서 빼기로 했다가 사용자가 넣기로 바꿨다.

## 결정
로고는 등록 도서관 중 자체 로고가 있는 곳(공공도서관)만 보인다. 업체 기본 로고·회사·대학·후보 도서관은 이름만. 보이는 자리는 결과 카드(검색·책 화면)와 내 도서관 화면의 도서관 이름 앞. 파일은 원본을 자르거나 바꾸지 않고 표시 높이의 2배로 미리 줄여 웹 정적 파일로 두고, 브라우저가 오래 보관하게 한다. 로고를 누르면 어디서든 그 도서관 메인 페이지가 새 창으로 열린다. 로고가 없거나 못 불러오면 빈 상자. 운영자가 DB 값 하나(`logo_visible`)를 끄면 바로 내려간다. "각 도서관의 로고와 이름은 그 기관의 것이며 책첵은 제휴·후원 관계가 없습니다" 안내와 로고 내림 요청 연락처(서비스 전용 이메일)는 새 "서비스 안내" 화면(`/about`)에 두고 모든 화면 바닥글에 링크한다.

## 이유 (사용자 발언)
- "이번 사이클에 로고 넣을래 결정 번복이야" (2026-10-05)
- "그냥 공공도서관? 공개된 도서관만 로고 해주고" (2026-10-05)
- "'제휴 후원 관계 없음' 이 안내는 뭐 어디 로고 보여주는 화면에는 보이기 싫은데.. 따로 안내에 해야 하나" (2026-10-05)
- "일괄적으로 로고 누르면 해당 도서관 메인 페이지로" (2026-10-05)
- "빈 상자 보이도록 근데 이건 실제 화면 보고 나서 언제든 수정 가능" (2026-10-05)
- 미리 줄인 파일: 질문 "이미 줄인 상태로 브라우저에 이미지가 저장되도록 하는 건?"에 대한 답을 보고 "이렇게 해줘" (2026-10-05)

## 검토한 대안
### A안: 위험을 줄이는 장치와 함께 로고를 씀 (채택)
- 장점: 도서관을 빨리 알아봄
- 단점: 위험이 0은 아님(요청 시 즉시 내림으로 줄임)
### B안: 이름만 씀
- 장점: 위험 없음(비슷한 서비스 2곳의 방식)
- 단점: 알아보기 어려움
- 채택하지 않은 이유: [이유 미확인] (로고를 쓰기로 고름)
### C안: 허락받은 곳만
- 장점: 위험이 가장 낮음
- 단점: 허락받는 데 시간이 걸림
- 채택하지 않은 이유: [이유 미확인]
### D안: 결과 카드에서는 로고가 카드 링크(책 페이지)를 따름
- 채택하지 않은 이유: "일괄적으로 로고 누르면 해당 도서관 메인 페이지로"
### E안: 로고가 없으면 이름만
- 채택하지 않은 이유: "빈 상자 보이도록"

## 결과
- 좋아지는 점: 결과와 내 도서관에서 도서관을 빨리 알아봄, 내림 요청에 배포 없이 응함
- 감수하는 점: 로고 파일을 미리 줄이는 단계와 새 화면 하나, 로고 내림 연락처(서비스 전용 이메일)를 만들어야 함
- 나중에 분리할 때: 로고 파일은 S3 + CloudFront로 옮길 수 있음(배포 결정의 "나중에")
