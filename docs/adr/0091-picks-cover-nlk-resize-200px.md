# ADR-0091: 사서추천 표지는 국립중앙도서관 표지를 받아 폭 200px JPEG로 줄여 우리 서버가 넘겨줌 (우리 전자책 표지는 이번에 쓰지 않음)

Status: Accepted
Date: 2026-10-12
Cycle: 14-librarian-picks
Supersedes: 0081

## 배경
사용자는 "수집한 표지를 먼저, 없으면 국립중앙도서관 표지"를 원했으나, 서비스 DB(`catalog`)에는 표지 칸이 없고 가져오기도 표지 주소를 옮기지 않는다. 표지 주소는 수집 DB에만 있다(architect가 dev 코드 확인, 2026-10-12). 국립중앙도서관 API는 책마다 표지 주소(`recomfilepath`)를 주고, http를 https로 바꾸면 최근 52권이 모두 열렸다(JPEG 41·PNG 9·BMP 2, 4KB~648KB, 2026-10-12). ADR-0081(출판유통통합전산망 표지를 200px JPEG로 줄여 저장)의 방식이 있다.

## 결정
- 이번 사이클 표지 순서: 국립중앙도서관 표지 → 제목 글자. 우리 전자책 표지를 서비스 DB로 가져오는 일은 backlog
- 국립중앙도서관 표지는 목록이 바뀔 때 아직 없는 것만 받아 폭 200px JPEG로 줄여 `picks.cover`에 저장하고 `/api/v1/picks/covers/{coverId}`로 넘겨줌. 지금 목록이 쓰지 않는 표지는 받기 성공 뒤 지움
- 제한(사이클 10 값): 요청 사이 1초, 원본 상한 5MB, 1,600만 화소 상한. http → https로 바꾼 뒤 호스트 `www.nl.go.kr`, 경로 `/afile/`만 받고, 다른 곳으로 넘기는 응답은 따르지 않음
- CSP는 바꾸지 않음(`img-src 'self'`)

## 이유 (사용자 발언)
- "1로 하되 이전 인기도서처럼 제한걸고 수집하고 크기 좀 줄여" (2026-10-12, "이번엔 국립중앙도서관 표지만"을 고르며)
- "받아서 작게 줄여 저장 (추천)" (2026-10-12)
- "사이클 10 값 그대로 (추천)" (2026-10-12)

## 검토한 대안
### A안: 국립중앙도서관 표지만, 받아서 줄여 저장 (채택)
- 장점: CSP 그대로, 폰 데이터 작음, 국립중앙도서관 사이트 상태와 상관없이 화면이 같음, BMP도 JPEG로
- 단점: 표지 사본을 저장하므로 이용 조건 확인이 중요(배포 전)
### B안: 이번에 우리 전자책 표지도 서비스 DB로 가져옴
- 단점: `catalog` 표·가져오기 파일 형식·160만 권 다시 가져오기, 사이클 11·12·13과 같은 코드, 도서관 사이트 표지 주소가 여러 호스트·http
- 채택하지 않은 이유: [이유 미확인]
### C안: 국립중앙도서관 표지 주소를 그대로 걺
- 장점: 코드가 가장 적음
- 단점: CSP를 넓힘, 폰에서 한 쪽 수백 KB, 이용자 브라우저가 국립중앙도서관에 직접 요청
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 사이클 10의 표지 코드(`CoverResizer` 등)를 그대로 씀
- 감수하는 점: 사용자가 원한 "우리 표지 먼저"는 나중으로 미룸. 국립중앙도서관 표지 이용 조건은 배포 전 확인 [확인 필요]
- 나중에 서비스로 분리할 때: 표지는 `picks` 서비스 안에 둠
