# ADR-0053: 가입 정보를 조사하지 않은 도서관은 직접 추가했을 때만 검색에 넣는다

Status: Accepted
Date: 2026-10-05
Cycle: 07-candidate-libraries
Supersedes: 없음

## 배경
후보 도서관 대부분(학교·대학·회사·기관 약 2,500곳)은 가입 조건을 조사하지 않았다. 사용자는 이런 도서관을 내 도서관에 넣지 않으면 보이지 않고 요청도 가지 않게 정했다(2026-10-04). 그런데 지금 코드는 가입 규칙이 0개인 등록 도서관도 "자격 미확인"으로 전체 검색에 넣는다(ADR-0013). 그래서 "규칙이 없으면 숨김"으로는 등록 도서관 동작이 바뀐다. 또 사용자는 "조사했지만 원문을 못 찾은 곳"과 "회사·대학처럼 일부러 조사하지 않은 곳"을 가르기를 원했다.

## 결정
도서관 표에 가입 조사 상태 칸(`library.join_survey`, 기본 `SURVEYED`)을 두고 값 넷을 쓴다.

| 값 | 어떤 곳 | 검색에 | 도서관 이름을 누르면 |
|---|---|---|---|
| `SURVEYED` 조사함 | 등록 도서관 278곳, 원문이 확인된 후보 공공도서관 | 지금처럼 지역·직장으로 판정 | 가입 자격·방법 |
| `NOT_FOUND` 조사했지만 원문 없음 | 후보 공공도서관 중 원문을 못 찾은 곳(18곳) | 등록 도서관의 "자격 미확인"과 같이 "가입 자격 확인 필요"로 보임(ADR-0013) | "가입 조건을 찾지 못했어요. 도서관 사이트에서 확인해 주세요" |
| `MEMBERS_ONLY` 조사하지 않음(소속 구성원용) | 초·중·고, 대학, 회사, 정부·공공기관, 단체·아파트(수집 세션 종류 표 `candidate-kinds-2026-10-05.tsv`) | 내 도서관에 직접 넣었을 때만 | "학교·회사 같은 기관의 구성원용으로 보여요. 이용할 수 있는지는 그 기관에 확인해 주세요" |
| `NOT_SURVEYED` 조사하지 않음(종류 모름) | 종류 "모름" | 직접 넣었을 때만 | "가입 정보를 아직 조사하지 않았어요" |

`MEMBERS_ONLY`·`NOT_SURVEYED`이면서 이용자가 직접 추가하지 않은 도서관은 검색 계획에서 빼고 그 사이트로 요청하지 않는다. API는 이 두 값을 가입 등급 `eligibility: UNSURVEYED` 하나로 내보내고, 안내 문구는 조사 상태로 가른다. ADR-0013·ADR-0050을 보완한다. 값 이름은 [안] (dev가 바꿀 수 있음).

## 이유 (사용자 발언)
- "'나'로 하도록 하고 직장/거주 없는 도서관들은 따로 '내 도서관'에서 등록하지 않은 한 기본적으로 안 보였으면 해 요청도 보내지 말고" (2026-10-04)
- 등급 값으로 내보냄: "가입 등급에 '미조사' 값을 새로 더함 … 이걸로 해줘" (2026-10-05)
- 값 넷으로 가름: "회사나 대학교 도서관은 일부러 가입 조건을 조사 안 하는 것도 있단 말이야... 음... 이런 것들을 어떻게 하지? 진짜 조사해서 안 나오는 것들이랑 조사 그냥 안 하는 것들" → 값 넷 안을 보고 "이렇게 해줘" (2026-10-05)
- 원문 못 찾은 곳은 자격 미확인: "원문 못 찾은 곳은 자격 미확인" (2026-10-05, 수집 세션에서 사용자 결정)

## 검토한 대안
### A안: 조사 상태 칸 값 넷 + 등급 `UNSURVEYED` (채택)
- 장점: 등록 도서관 278곳 동작이 그대로, 일부러 조사하지 않은 곳은 이유를 보여 줌, 조사가 끝나면 데이터만 고침
- 단점: 등급을 쓰는 웹 분기와 안내 문구를 고침
### B안: 예/아니요 칸 하나 (`join_surveyed`)
- 장점: 단순함
- 단점: 조사했지만 못 찾은 곳과 일부러 조사하지 않은 곳을 가르지 못함
- 채택하지 않은 이유: "진짜 조사해서 안 나오는 것들이랑 조사 그냥 안 하는 것들"을 가르기 원함
### C안: "등록/후보" 구분 칸 + "후보이고 규칙 0개면 직접 추가일 때만"
- 장점: 규칙만 넣으면 보임
- 단점: 학교·회사(규칙이 계속 없음)와 미조사를 가르지 못함
- 채택하지 않은 이유: [이유 미확인]
### D안: API에 별도 `joinSurveyed` 값
- 장점: 기존 웹 분기를 건드리지 않음
- 단점: 같은 뜻을 두 값으로 봄
- 채택하지 않은 이유: 사용자가 등급 값을 고름 [이유 미확인]

## 결과
- 좋아지는 점: 미조사 도서관에 요청이 가지 않음, 이용자가 왜 가입 정보가 없는지 앎, 조사 결과를 코드 변경 없이 넣음
- 감수하는 점: 직접 추가하지 않은 이용자에게는 소속 구성원용·종류 모름 도서관이 보이지 않음. 종류는 이름으로 본 것이라 틀릴 수 있음
- 나중에 분리할 때: 도서관 서비스의 계획 규칙과 칸 하나
