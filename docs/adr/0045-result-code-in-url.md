# ADR-0045: 로그인·탈퇴 결과는 주소 뒤의 코드로 화면에 알리고, 돌아갈 주소는 화면이 기억함

Status: Accepted
Date: 2026-10-04
Cycle: 05-login-account
Supersedes: 없음

## 배경
네이버·카카오에서 돌아오는 요청은 브라우저의 주소 이동이라 서버가 화면에 JSON으로 답할 수 없다. 로그인이 왜 실패했는지(취소, 제공자 오류, 시간 지남, 확인 값 다름)와 탈퇴 본인 확인 결과를 화면에 알릴 방법, 그리고 로그인 뒤 보던 화면으로 돌아가는 방법이 필요했다.

## 결정
서버는 고정된 웹 주소 `/auth/complete?result=<code>`로 보낸다(처음 온 계정은 `/signup`). 화면은 목록에 있는 코드만 정해진 문구로 바꿔 보이고 주소에서 코드를 지운다. 돌아갈 주소는 화면이 로그인 버튼을 누를 때 `sessionStorage`에 적어 두었다가 꺼내 쓰고, 서버는 돌아갈 주소를 받지 않는다. 규칙 넷: 코드에 민감한 값을 넣지 않음, 목록에 있는 코드만 문구로, 서버는 코드로 판단하지 않음, 돌아갈 주소는 사이트 안 경로만.

## 이유 (사용자 발언)
- "이렇게 해도 보안 상 안전한거니? 안전하면 이렇게 해줘" (2026-10-04)

## 검토한 대안
### A안: 로그인·탈퇴 결과는 주소 뒤의 코드로 화면에 알리고, 돌아갈 주소는 화면이 기억함 (채택)
- 장점 / 단점: "결과" 절 참고
### B안: 결과를 짧은 쿠키에 담고 화면이 읽음
- 장점: 주소에 코드가 보이지 않음
- 채택하지 않은 이유: [이유 미확인] (화면이 쿠키를 읽게 됨)
### C안: 서버 임시 저장소에 두고 화면이 한 번 더 요청해 가져옴
- 장점: 주소에 코드가 보이지 않음
- 채택하지 않은 이유: [이유 미확인] (요청과 임시 저장소가 늘어남)

## 결과
- 좋아지는 점: 가장 단순함. 서버가 돌아갈 주소를 받지 않아 엉뚱한 사이트로 보내는 공격이 통하지 않음
- 감수하는 점: 주소창과 브라우저 기록에 코드가 잠깐 보임. 누가 가짜 코드가 붙은 주소를 보내면 그 문구가 보일 수 있음(로그인이나 탈퇴는 되지 않음)
- 되돌리는 비용: 웹과 서버의 전달 부분만 고침
