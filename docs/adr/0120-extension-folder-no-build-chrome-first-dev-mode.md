# ADR-0120: 크롬 확장은 dev 저장소 `extension/` 폴더에 빌드 없이 두고, 크롬만 먼저, 이번에는 개발자 모드까지

Status: Proposed
Date: 2026-10-16
Cycle: 20-lookup-status-and-extension
Supersedes: 없음

## 배경
확장이 도서관 페이지를 받아오려면 브라우저 확장이어야 한다(웹 페이지만으로는 CORS·혼합 콘텐츠로 불가, 사이클 20 research 1절 호출 시험). 폰 크롬·사파리는 확장을 지원하지 않고, 엣지는 같은 파일을 올릴 수 있으며, 웹스토어 심사는 며칠~몇 주이고 넓은 사이트 권한은 심사가 길어질 수 있다(공식 문서, 2026-10-15). 같은 구조의 선례 「Library Extension」(사용자 10만 명). dev `CLAUDE.md`는 "backend/는 Spring Boot 앱 하나"이고 조회 서버는 `fetch-service/`로 따로 있다(ADR-0015).

## 결정
- 크롬 확장(Manifest V3)은 dev 저장소 맨 위 `extension/` 폴더에 **빌드 도구 없이** 둔다: `manifest.json`(ID 고정 `key`, `host_permissions` http·https 전체, `externally_connectable`에 책첵 운영·개발 주소만), `background.js`(service worker), 호스트 간격 모듈. 시험은 Node 내장 테스트.
- 확장은 호스트마다 동시 1건·앞 요청 끝 1초 뒤, 묶음 안 동시 5, 응답 머리까지 10초·본문은 묶음 마감까지, 리다이렉트 안 따름, 쿠키 안 보냄.
- 이번 사이클은 개발자 모드(압축 해제 확장 로드)로 동작 확인까지. Chrome Web Store 등록·심사는 나중에 따로, 그때도 **크롬만 먼저**. 심사 요청의 권한 사유에는 「Library Extension」 선례를 쓴다.
- dev `CLAUDE.md`에 `fetch-service/`처럼 "`extension/` — 크롬 확장, Spring 앱 아님, Gradle 없음" 한 줄을 더한다. "backend/는 Spring Boot 앱 하나"는 그대로.

## 이유 (사용자 발언)
- "크롬만 먼저 하자." (2026-10-15, 방법 비교 #1 미승인)
- "크롬 확장은 돌아가게만 만들고 승인은 나중에 받을거야" (2026-10-15)
- 권한: "이걸 승인 요청 문서를 보낼 때 쓰면 될 것 같기도 하다. 아무튼 그렇게 하자" (2026-10-15)
- 간격: "근데 요청 시간 1초 간격 지켜" (2026-10-15)
- 빌드 없음·동시 5·머리 10초: 제안 → 승인 [이유 미확인]

## 검토한 대안
### A안: `extension/` 빌드 없음, 크롬만, 모든 사이트 권한 (채택)
- 장점: 압축만 풀어 바로 로드, 파일이 적음, 도서관이 늘어도 재심사 없음
- 단점: 타입 검사 없음, 설치 때 "모든 사이트" 경고
### B안: Vite·TypeScript 빌드
- 장점: 타입 검사
- 단점: 빌드 결과물을 로드해야 하고 설정이 늘어남
- 채택하지 않은 이유: [이유 미확인] (제안 → 승인)
### C안: 크롬·엣지 동시 배포
- 장점: 엣지 사용자도 바로
- 단점: 올리는 곳 둘
- 채택하지 않은 이유: "크롬만 먼저 하자."
### D안: 도서관 호스트 2,794개를 권한에 나열
- 장점: 설치 경고가 좁음
- 단점: 도서관이 바뀔 때마다 재심사, 심사자에게는 넓은 권한과 다르지 않음
- 채택하지 않은 이유: [이유 미확인] (제안 → 승인)
### E안: 사용자 스크립트(Tampermonkey류) · 로컬 도우미 프로그램 · 폰 앱
- 장점: 각각 심사 없음 / PC 전체 / 폰
- 단점: 설치 3단계 / 폰 불가·서명 비용·크롬 사설망 접근 제한 / 앱 두 벌·스토어 계정
- 채택하지 않은 이유: "사용자 스크립트 이건 백로그에도 쓰지 마 이 사이클에 조사했다고만 기록해"(도우미도 같은 말), 폰 앱은 "Google Play 폰 앱 만드는 것을 백로그에 해줘" (2026-10-15)

## 결과
- 좋아지는 점: 파일 몇 개로 바로 시험. 확장이 우리 API를 모르므로(ADR-0119) 웹스토어 뒤에도 서버 변경 때 재배포가 드묾
- 감수하는 점: 폰 사용자는 못 씀(서버 조회 + 신호로 감). 웹스토어 뒤 확장 자체 변경은 심사. 사용자 집 IP가 도서관에 막힐 수 있어 1건·1초를 지킴
- 나중에 되돌리거나 서비스로 분리할 때: 엣지·파이어폭스는 같은 WebExtension 규격이라 손질이 작음(파이어폭스 안드로이드는 MV2 권장·service worker 미지원). 확장은 이미 본 서비스 밖 폴더라 분리 비용 없음
