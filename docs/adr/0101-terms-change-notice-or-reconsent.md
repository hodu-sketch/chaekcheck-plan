# ADR-0101: 약관이 바뀔 때 — 가벼우면 공지와 시행일, 중요하면 다음 로그인 때 다시 동의 (화면은 나중)

Status: Proposed
Date: 2026-10-13
Cycle: 16-notices-and-policies
Supersedes: 없음

## 배경
"이미 가입한 사람에게 다시 동의를 받지 않고 공지와 시행일로 알린다"를 제안했으나, 사용자 질문("이거 되는거 확실한거야?") 뒤 조사에서 근거가 약하다고 나왔다. 반대하지 않은 것만으로는 동의로 볼 수 없다는 판례가 있다. 지금 가입자는 테스트 한 명이고 정식 공개 전이다.

## 결정
오탈자·회원에게 유리한 변경·처리방침 변경은 공지사항에 알리고 새 판의 시행일을 앞날로 넣는다. 중요하거나 불리한 이용약관 변경, 동의문의 항목·목적·보유 기간 변경은 다음 로그인 때 다시 동의를 받는다(동의하지 않으면 탈퇴 가능, 로그인하지 않는 회원에게는 옛 약관). "공지 뒤 반대하지 않으면 동의한 것으로 봄" 조항은 쓰지 않는다. 다시 동의 화면과 표시 칸은 나중 할 일 목록에 두고, 그 전에는 다시 동의가 필요한 변경을 넣지 않는다.

## 근거
- 대법원 2013. 2. 15. 선고 2011다69053: 이의를 제기하지 않은 것만으로 동의로 볼 수 없음
- 약관의 규제에 관한 법률 제12조제1호(의사표시 의제 조항의 무효와 단서), 개인정보 보호법 제15조②(동의 항목 변경 시 다시 동의)
- 개인정보 처리방침 작성지침(2026.4.) 13쪽: 처리방침은 동의 대상이 아님
- 출처와 확인일: `docs/cycles/16-notices-and-policies/research.md` 4절 (2026-10-12). 법률 자문이 아니라 공개 자료를 읽고 정리한 것

## 이유 (사용자 발언)
- 규칙: 제안 → 승인 (2026-10-12)
- 화면·칸을 나중으로: 제안 → 승인 (2026-10-12), "아직 기능이 다시 동의 필요가 없지 않나?" (2026-10-13)

## 검토한 대안
### A안: 가벼우면 공지, 중요하면 다시 동의 (채택)
- 장점: 실제 동의로 근거가 확실, 오탈자에는 동의 화면이 뜨지 않음
- 단점: 다시 동의 화면이 필요(나중)
### B안: 공지 + 동의 간주 조항 + 거부 시 탈퇴 (온라인게임 표준약관 방식)
- 단점: 따로 알리는 수단이 필요하고, 중요한 내용이면 효력을 부정당할 수 있음
- 채택하지 않은 이유: [이유 미확인]
### C안: 늘 다시 동의
- 단점: 오탈자 하나에도 모든 회원에게 동의 화면
- 채택하지 않은 이유: [이유 미확인]
### D안: 공지 + 시행일만 (처음 제안)
- 단점: 기존 회원에게 새 약관이 적용된다는 근거가 약함
- 채택하지 않은 이유: 조사 결과(위 판례), 사용자 질문 "이거 되는거 확실한거야?"
