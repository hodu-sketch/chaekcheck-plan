# ADR-0033: 웹 주소에 여러 검색 조건을 담음 (ADR-0025의 웹 주소 규칙 변경)

Status: Accepted
Date: 2026-09-30
Cycle: 04-and-search
Supersedes: 없음

## 배경
ADR-0025는 검색 조건을 `title`/`author`/`publisher` 이름 있는 파라미터 하나로 받고, 웹 주소에 조건이 둘 이상이면 하나만 쓰기로 했다. 사이클 04는 여러 조건 AND 검색을 한다.

## 결정
웹 주소(`/search`)에 여러 조건과 설정(`exact`, `roles`, `sort`, `view`, `direct`)을 함께 담는다. 도서관에서 직접 찾기일 때만 첫 칸(title → author → publisher) 하나를 쓴다. 기존 사이트 검색 API의 "조건 하나" 규칙(ADR-0025)은 그대로 둔다. `view`, `direct`는 웹에만 있고 브라우저에도 저장한다.

## 이유 (사용자 발언)
- "나중에 and검색에 저 여러개있는거 쓸꺼 생각중" (사이클 03, 2026-09-29)
- 설정 저장 위치는 선택지 "설정 메뉴 + 브라우저 저장" (2026-09-30)

## 검토한 대안
### 여러 조건을 주소에 (채택)
- 장점: 새로고침·공유해도 AND 조건이 유지됨
- 단점: ADR-0025의 웹 주소 규칙과 달라짐
### 주소에는 조건 하나만
- 장점: ADR-0025 그대로
- 단점: AND 검색을 공유할 수 없음
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: AND 검색 결과를 주소로 공유. 감수하는 점: 웹 주소 규칙과 사이트 검색 API 규칙이 달라져 직접 찾기에서 조건 하나를 고르는 처리가 필요.
