# ADR-0137: 지역 고르기는 내 지역 창 대신 격자 공통 부품으로, 체크는 저장만 하고 검색은 [검색] 단추로

Status: Accepted
Date: 2026-10-18
Cycle: 22-first-screen-usability
Supersedes: 없음

## 배경
친구분 QA(2026-10-18): "지역 선택 창 너무 작음". 지금 내 지역 창(사이클 06 S2)은 너비 약 830px·작은 글자로 고정돼 있다(dev `RegionModal.module.css`, 2026-10-18 확인). 사이클 22에서 지역 고르기가 첫 화면 접힌 줄의 상자·상세검색·폰 설정 시트·마이페이지 네 자리에 들어간다. 지금은 지역을 바꾸면 결과 화면이 자동으로 다시 검색한다(사이클 06).

## 결정
내 지역 창을 없애고, 그 안의 격자(왼쪽 시도 목록 + 오른쪽 시군구 체크 칸)를 공통 부품 `RegionGrid`로 떼어 네 자리에 둔다(글자 16px 이상, 체크 칸 높이 40px 이상, 너비 100%). 체크하는 즉시 저장만 한다(로그인 전 브라우저, 뒤 계정 `PUT /api/v1/me/regions`를 한 번에 하나씩, 실패하면 마지막 저장값으로 되돌림). 검색은 사용자가 [검색] 단추를 누를 때 그때의 지역으로 한다. 지역을 바꾸면 자동으로 다시 찾던 동작은 없애고, 기다리는 시간(debounce)도 두지 않는다. 결과 안의 [전국에서 찾기]·[그 N곳 빼기] 같은 단추는 누르는 것이 곧 검색이라 바로 다시 찾는다. 지역·직접 추가 값은 한 곳에 저장되고 입구만 셋이다.

## 이유 (사용자 발언)
- "그냥 기존 것대로 프론트만 잘 하면 작은 노트북 화면에서도 잘 보이는 거 아니야?", "(A) 기존 격자를 그대로, 크기만 키워 상자 안에" (2026-10-18)
- "지역 체크랑 검색이랑 별개인데 왜 0.7초 기다려??"
- "체크와 검색이 따로. 기다리는 시간도, 체크마다 검색도 없습니다. 무슨 0.7초 기다리지 마라"
- 창 없이: 범위 결정 #5 승인 "(나) 창 없이"

## 검토한 대안
### A안: 기존 격자를 창 없이 공통 부품으로, 체크는 저장만 (채택)
- 장점: 부품 하나, 창 없음, 체크마다 검색 낭비 없음.
- 단점: 결과 화면에서 지역을 바꾼 뒤 [검색]을 다시 눌러야 반영.
### B안: 브라우저 기본 고르기 두 단계([시도 ▾][시군구 ▾])
- 장점: 짧고 기본 부품.
- 단점: 구 여러 개를 한눈에 못 고름.
- 채택하지 않은 이유: "그냥 기존 것대로 … 잘 보이는 거 아니야?"
### C안: 창은 두고 크기만 키움
- 채택하지 않은 이유: [이유 미확인] (창 없이 안을 승인함)
### D안: 체크마다 바로 다시 검색 / 마지막 체크 뒤 0.7초에 한 번
- 채택하지 않은 이유: "지역 체크랑 검색이랑 별개인데 왜 0.7초 기다려??", "체크마다 검색도 없습니다"

## 결과
- 좋아지는 점: 작은 화면·TV에서도 읽히고, 어느 입구에서 바꿔도 같은 값.
- 감수하는 점: 결과 화면에서 바꾼 지역은 [검색]을 눌러야 반영(접힌 줄의 곳 수는 그동안 숨김).
- 나중 비용: 낮음(웹만).
