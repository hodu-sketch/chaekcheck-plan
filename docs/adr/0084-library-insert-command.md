# ADR-0084: 새 도서관은 `collection` 명령으로 넣는다 (미리 보기 → 보고서 → 넣기), seed로 번호를 넣지 않는다

Status: Accepted
Date: 2026-10-12
Cycle: 13-crawler-to-dev
Supersedes: 없음 (ADR-0052의 "seed로 넣음" 부분을 바꿈. 짝 표 `collection_link`는 그대로)

> **미리 정함**: 사이클 13은 사이클 12(책 묶기 기준)가 끝나기 전에 나란히 진행해 정한 결정이다. dev에는 사이클 12 handoff 뒤에 넘긴다.

## 배경
지금까지 새 도서관은 Python 스크립트가 만든 Liquibase seed로 들어갔다(ADR-0052). seed는 처음 만든 묶음과만 비교해서, 서비스에 이미 있는 곳이 바뀌거나 사라져도 알 수 없고, 넣으려면 앱을 다시 켜야 했다. 사이클 13 조사에서 2026-10-12 사본 기준 새로 넣을 곳 6곳(여주대 두 곳 등)이 나왔다(`docs/cycles/13-crawler-to-dev/research.md` 7절).

## 결정
- `collection`에 넣기 명령을 둔다(따로 돌고 끝남, 가져오기 명령과 같은 꼴) [안: 프로필 `library-insert`, 설정 `chaekcheck.collection.library-insert.*`]
  - ① 미리 보기: DB에 쓰지 않고 보고서 파일을 만든다. 보고서 번호 = 정규화 JSON의 SHA-256 앞 12자리
  - ② 넣기: 보고서 번호를 받아 다시 계산한 내용이 보고서와 같을 때만, 한 트랜잭션에서 잠금 → `LibraryRegistry.add`(ADR-0083) → `collection_link` → 실행 기록 줄
- 비교 대상은 서비스 DB 전체(seed로 들어간 곳 포함)와 수집 DB 사본. 네 목록: 새로 넣을 곳, 바뀐 곳, 사라진 곳, 의심(같은 호스트, 순번 2 이상)
- 넣는 것은 새로 생긴 곳만. 바뀐 곳·사라진 곳은 보고만 하고 고치기는 지금처럼 SQL·changeset
- 보고서는 Claude(수집 세션)가 먼저 보고, 의심·바뀐 곳·사라진 곳이 있을 때만 사용자에게 묻는다. 의심이 남아 있으면 넣기가 멈춘다
- 실행마다 `collection.library_insert_run`에 한 줄을 남긴다(성공·실패) [안: 표·칸 이름]
- 앞으로 seed로 도서관 번호를 넣지 않는다. 로컬 DB를 새로 만들 때는 seed 뒤 명령을 다시 돌린다. 지금까지 seed로 들어간 곳은 그대로 둔다

## 이유 (사용자 발언)
- "나는 재시작 없이 하고 싶어 나. collection 모듈이 넣음으로 해줘" (2026-10-12)
- 서비스 DB 전체와 비교: "어짜피 비교해서 해야 하는 거 아니야? 도서관에 변동이 있을 수 있자나" (2026-10-12) → 답한 뒤 승인 "아니 승인 이미 했잖아"
- 보고서를 파일로, 보고서와 같을 때만 넣기, "Claude가 보고, 의심·바뀐 곳만 내게": 사용자 선택 (2026-10-12, spec). 고른 이유는 [이유 미확인]

## 검토한 대안
### A안: `collection` 명령, 서비스 DB 전체와 비교 (채택)
- 장점: 앱 재시작 없음, seed로 들어간 곳의 변화도 보임, 몇 번 돌려도 같은 결과
- 단점: 로컬 DB를 새로 만들 때 명령을 한 번 더 돌려야 함
### B안: 지금처럼 Python이 seed changeset을 만듦
- 장점: 새 코드가 적음
- 단점: 앱 재시작 필요, 처음 묶음과만 비교
- 채택하지 않은 이유: "나는 재시작 없이 하고 싶어 나"
### C안: 미리 보기 없이 바로 넣기
- 장점: 단계가 하나
- 단점: 무엇이 들어가는지 넣은 뒤에야 앎
- 채택하지 않은 이유: [이유 미확인] (사전 결정 4에서 두 단계를 승인)

## 결과
- 좋아지는 점: 새 도서관을 넣기 전에 보고서로 확인, 넣은 뒤 바로 "직접 추가"에서 보임, 실행 기록이 남음
- 감수하는 점: 고르기·값 정하기 규칙(지금 Python 스크립트)을 Java로 옮겨야 하고, 옛 스크립트와 결과가 같은지 시험해야 함(AC-6)
- 나중에 되돌리거나 서비스로 분리할 때의 비용: 중간. 나중에 분리할 때 명령은 `collection` 쪽에 남고 `library` 쓰기 API만 원격 호출로 바뀜
