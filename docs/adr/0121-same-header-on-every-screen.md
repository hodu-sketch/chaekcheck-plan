# ADR-0121: 공통 머리말은 약관·처리방침을 포함한 모든 화면에서 같다

Status: Accepted (2026-10-17, 사용자 승인 — 사이클 20 마무리 확인)
Date: 2026-10-16
Cycle: 20-lookup-status-and-extension
Supersedes: 없음

## 배경
사이클 05 화면 흐름(2026-10-04)은 "S8·S9(약관·처리방침)에는 로그인·로그아웃 버튼을 두지 않음"으로 정했고(이유는 문서에 없음), 사이클 10의 「인기 도서」·14의 「사서추천도서」 링크도 "로그인 버튼처럼 빼고"로 그 예외를 따랐다(dev `AppLayout.tsx`의 `legal` 분기). 사이클 20 화면 흐름 검토에서 사용자가 두 화면의 머리말이 다른 것을 지적했다. 사이클 21이 머리말을 정보나루식 큰 메뉴(「추천도서」·「마이페이지」, 폰 ☰)로 바꾸고 먼저 개발한다.

## 결정
공통 머리말(사이클 21 메뉴 기준: 「책첵」·큰 메뉴·조회 상태 점·「로그인/로그아웃」, 폰은 ☰ 대신 머리말 줄 누르기 + 작은 ▾ — 사이클 21 검토 #7·#9, 2026-10-17)은 `/terms`·`/privacy`를 포함한 **모든 화면에서 같다**. 사이클 05·10·14의 예외를 없애고 dev `AppLayout.tsx`의 `legal` 분기를 지운다. 사이클 21이 머리말을 만들 때 이 규칙대로 만들고, 사이클 20은 그 위에 조회 상태 점만 얹는다.

## 이유 (사용자 발언)
- "왜 이용약관이랑 개인정보처리방침은 왜 머릿말이 달라? 그것들도 같아야지", "이렇게 가자" (2026-10-15)

## 검토한 대안
### A안: 모든 화면 같은 머리말 (채택)
- 장점: 일관됨, 코드 분기 하나가 줄어듦, 신호·메뉴가 어느 화면에서나 보임
- 단점: 사이클 05 결정을 바꿈
### B안: 지금대로 약관·처리방침만 다르게
- 장점: 바꿀 것 없음
- 단점: 사용자가 이상하다고 느낌
- 채택하지 않은 이유: "그것들도 같아야지"

## 결과
- 좋아지는 점: 어느 화면에서나 같은 머리말
- 감수하는 점: 가입 중 약관을 볼 때도 로그인 버튼이 보임(사이클 05가 이를 피하려 했는지는 [이유 미확인])
- 나중에 되돌릴 때: 분기 하나를 되살리면 됨
