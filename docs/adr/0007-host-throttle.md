# ADR-0007: 도서관 호출 간격 제어: 직접 구현

Status: Superseded by 0010
Date: 2026-09-27
Cycle: 01-ebook-availability-search
Supersedes: 없음

## 배경
같은 도서관에는 동시에 1건, 요청 사이 1초 이상이어야 한다 (spec 5.6, AC-17).

## 결정
호스트(host:port)마다 공정한 세마포어 1개와 마지막 요청 종료 시각을 둔다. 차례를 받으면 "이전 요청 종료 + 1초"까지 기다린 뒤 요청한다. 기다리는 시간도 8초 제한에 포함하고, 넘으면 504로 끝낸다.

## 이유 (사용자 발언)
- [이유 미확인] (추천안 채택)

## 검토한 대안
### A안: 직접 구현 (채택)
- 장점: "간격 1초 이상"을 정확히 지키고 코드가 작음
- 단점: 직접 테스트해야 함
### B안: Resilience4j RateLimiter + Bulkhead
- 장점: 이미 있는 라이브러리, metrics
- 단점: 주기가 시작될 때 허가를 다시 채우므로 주기 경계에서 두 요청이 1초 안에 나갈 수 있음 (https://resilience4j.readme.io/docs/ratelimiter, 2026-09-27 확인)
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 두 도서관이 같은 호스트를 써도 보호됨
- 감수하는 점: 서버 1대 전제. 여러 대가 되면 공유 방식 필요 (ADR-0006과 함께 Redis 검토)
- 나중에 서비스로 분리할 때: 조회 서비스 안에 그대로 둠
