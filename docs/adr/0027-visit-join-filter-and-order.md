# ADR-0027: 방문 가입 도서관은 필터로 뺄 수 있고, 가입 가능한 도서관 중 맨 뒤에 조회

Status: Accepted
Date: 2026-09-30
Cycle: 03-search-conditions
Supersedes: 없음

## 배경
방문 가입 표시(`visit_required`)가 가입 방법 글과 어긋나는 도서관이 있었다(목포 등, dev plan-feedback C3-U-1). 방문 가입 도서관을 검색에서 빼거나 뒤로 미룰 방법도 없었다. 사이클 03 개발 중(2026-09-29~30) "무리 안에서 방문 가입을 맨 뒤로"로 구현했으나, 회고(2026-09-30)에서 지역이 있을 때의 순서를 사용자가 다시 정했다.

## 결정
- 가입 절차에 방문 단계만 있고 원문이 전자책 회원 등급을 따로 말하지 않으면 방문 가입(`visit_required = true`)으로 본다.
- 첫 묶음 API에 `visit=any|none`(없으면 `any`)을 둔다. `none`이면 방문 가입 도서관을 조회 계획에서 빼고 요청하지 않는다.
- 조회 순서(지역 있음): 내 시군구(방문 없음) → 내 시도(방문 없음) → 누구나(방문 없음) → 내 시군구(방문) → 내 시도(방문) → 누구나(방문) → 확인 필요. 지역 없음: 누구나(방문 없음) → 누구나(방문) → 자격 필요 → 확인 필요. 자격 필요·확인 필요 무리 안에서는 방문 가입이 뒤 [안]. `priorityGroup` 값은 바꾸지 않는다.
- 결과 정렬(같은 책 안): 가입 가능 → 가입 가능(주의) → 가입 가능(방문) → 가입 자격 확인 필요.

## 이유 (사용자 발언)
- "방문 가입도 태그로서 검색 조건에 활용하거나 필요한 것 같아"
- "방문 가입 조건이 붙은 도서관은 누구나 도서관보다 좀 후순위에 해줘"
- 개발 때 구현된 순서 설명을 보고 "이거 좀 이상한데" → 위 순서를 직접 지정 (2026-09-30)

## 검토한 대안
### A안: 방문 없는 가입 가능 도서관을 모두 먼저, 그다음 방문 가입 (채택)
- 장점: 방문 없이 가입할 수 있는 곳을 먼저 조회함. 무리 값이 그대로라 웹 표시 코드가 바뀌지 않음
- 단점: 방문 가입인 내 동네 도서관이 멀리 있는 누구나 도서관보다 뒤로 감
### B안: 무리 안에서만 방문 가입을 뒤로 (개발 때 구현)
- 장점: 가까운 도서관이 먼저
- 단점: 지역이 있으면 방문 가입 도서관이 누구나(방문 없음) 도서관보다 앞에 옴
- 채택하지 않은 이유: "이거 좀 이상한데"
### C안: 새 무리 값 `OPEN_VISIT`을 따로 둠
- 장점: 무리 값만 보고 방문 가입 무리를 알 수 있음
- 단점: `priorityGroup`을 쓰는 웹 코드와 테스트를 바꿔야 함
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 방문 없이 가입할 수 있는 곳을 먼저 조회함. 방문이 어려운 사용자는 필터로 요청 자체를 줄임
- 감수하는 점: 방문 가입인 내 동네 도서관이 멀리 있는 누구나 도서관보다 뒤로 감
- 방문 가입 판단 규칙(dev `library-maintenance.md` 4-10 5번)을 정기 재조사 때도 지켜야 함
- dev 반영: 지역 있음 순서 변경은 인계서 "사이클 03 후속"으로 전달 (2026-09-30)
