# ADR-0138: 첫 화면의 "찾을 도서관" 줄 하나로 합치고 처음 온 사람에게 지역부터 묻기; 방문 가입 빼기는 값 하나에 입구 셋; 브라우저 저장 칸 셋; 도서관 목록은 필요할 때만

Status: Accepted
Date: 2026-10-18
Cycle: 22-first-screen-usability
Supersedes: 없음 (부분 대체: ADR-0049 3항 "전체/내 도서관 스위치 값을 브라우저에 적어 둠"과 ADR-0050의 "스위치가 전체 도서관이어도" 문구는 ADR-0135로 뜻을 잃음; 사이클 06·07 flow S1의 [내 도서관 관리]·[내 지역 설정] 단추와 S2 창은 이 ADR과 ADR-0137로 없어짐)

## 배경
친구분 QA(2026-10-18): 지역 설정이 마이페이지 안쪽 일곱 단계에 있고, 첫 화면 필터 줄의 세 부품([내 도서관 설정] 링크, [내 도서관 관리 ⌄] 드롭다운, [방문 없이 가입] 단추)이 무엇인지 처음 온 사람은 모른다. 설계에서 확인한 것: 접힌 줄의 곳 수를 정확히 세려면 전체 도서관 목록 API(약 870KB, gzip 62KB)를 불러야 하고, 직접 추가 목록은 브라우저·계정 모두 번호만 있어 이름을 보이려면 같은 목록이 필요하다.

## 결정
- 첫 화면·결과 화면의 필터 줄은 부품 하나(`LibraryScopeLine`)로 합친다: 지역·직접 추가가 없으면 단추 [사는 곳·일하는 곳 고르기]만(앞에 물음 글 없음)과 작은 글, 있으면 접힌 줄 "내 도서관: 서울 강남구 · N곳 ▾"(기본값과 다른 것만 덧붙임). 누르면 검색창 아래에 떠 있는 상자(사는 곳·일하는 곳 격자, 직접 추가 N곳, 방문 가입 빼기, 어디 살든 가입 안내, [마이페이지에서 전체 보기]). 폰은 칩 하나 → ⚙ 시트의 "찾을 도서관" 칸. 세 부품은 지운다.
- 방문 가입 빼기는 값 하나(`visit`)에 입구 셋(펼친 상자, 결과 묶음 ②의 [그 N곳 빼기], ⚙ 설정 "직접 가야 가입되는 도서관은 빼기"). 결과 안 단추만 바로 다시 검색한다.
- 브라우저 저장 `chaekcheck.searchSettings.v1`에 `planCount {key, count}`(마지막 검색의 계획 길이와 조건 지문), `openCount`, `saveHintClosed`를 더하고 `guestScope`·`myScope`는 지운다. 곳 수는 조건 지문이 같을 때만 보인다.
- 전체 도서관 목록 `GET /api/v1/libraries`(지역 없이)는 직접 추가 이름·상세검색 이름 찾기에 필요할 때 한 번 받아 페이지 안에서 캐시한다(직접 추가가 0이면 요청 없음). 첫 화면에서 수 하나 때문에 부르지 않는다.
- 로그인 전 저장 직후 "이 브라우저에만 저장됐어요. 로그인하면 다른 기기에서도 그대로예요 [카카오 로그인] ×"를 보이고, ×로 닫으면 다시 보이지 않는다.

## 이유 (사용자 발언)
- 범위 결정 #1 승인(부품 셋 합치기), "니가 더 다른 시각에서 생각해봐… 어디까지 정보를 줘야 하나" → 중간 수준 승인 (2026-10-18)
- "메인에 '어디서 빌리실건가요' 이거 빼줘" (2026-10-18)
- 방문 가입 표시: "이것도 보여주는 건 어때? 방문 꽤 큰데", "방문 가입은 또 설정으로 뺄 수 있는 거지?" (2026-10-18)
- 곳 수 출처·저장 칸·목록 캐시: 명세 결정 #4·#10, 설계 결정 #4·#5 승인 (2026-10-18)

## 검토한 대안
### 첫 화면: 처음 한 번 안내 창, 또는 [내 도서관 관리 ⌄] 유지 + 지역 줄 추가
- 채택하지 않은 이유: 친구분 "알려주는 것보다 애초에 사용하기 쉽게"; 입구가 한 줄에 둘이면 "뭐가 다르지" — [이유 미확인] (제안을 승인함)
### 곳 수: 첫 화면에서 전체 목록 API 호출 / 수만 주는 새 API
- 채택하지 않은 이유: [이유 미확인] (계획 길이 안을 승인함; 새 API는 백로그)
### 직접 추가 이름: 수만 보이기 / 마지막 검색의 계획에서
- 채택하지 않은 이유: [이유 미확인] (필요할 때 목록을 받는 안을 승인함)
### 저장 칸: 새 저장 키
- 채택하지 않은 이유: [이유 미확인] (지금 키에 칸을 더하는 안을 승인함)

## 결과
- 좋아지는 점: 첫 화면 줄이 하나, 처음 온 사람은 지역부터, 방문 가입은 어디서 켜도 같은 값.
- 감수하는 점: 첫 화면의 곳 수는 검색한 뒤에야 보임; 직접 추가가 있는 사람은 상자를 열 때 62KB를 받음.
- 나중 비용: 웹만이라 낮음. 서버에 "수만 주는" API를 더하면 첫 화면에서도 수를 보일 수 있음(백로그).
