# ADR-0062: 책 번호 잇기는 `catalog`의 표 바꾸기 안에서 한다

Status: Accepted
Date: 2026-10-05
Cycle: 07-candidate-libraries
Supersedes: 없음

## 배경
예전 가져오기는 표를 비우고 책 번호를 1부터 새로 매겨서, 다시 가져오면 책 주소(`/books/{bookId}`)가 다른 책을 가리킬 수 있었다. 규칙은 2026-10-04에 정했다(소장이 가장 많이 겹치는 옛 번호를 이어 씀, 합쳐지면 가장 작은 번호, 나뉘면 가장 많이 겹치는 쪽, 번호는 다시 쓰지 않음, 안내표 없음 — `docs/research/ebook-catalog/catalog-refresh.md` 5.2). 어느 모듈에서 할지는 정하지 않았고, 사이클 07 개발 중 사용자 요청으로 dev가 만들었다(dev `docs/plan-feedback.md` "handoff 밖 추가 작업 B"). 기록은 사이클 07 회고에서 남긴다.

## 결정
`catalog`의 공개 기능 `CatalogLoad.replaceAll` 안에서 한다. 새로 받은 책·소장을 임시 표에 넣고, 옛 `catalog.holding`과 `(library_id, item_key)`로 맞대어 번호를 정한 뒤 표를 바꾼다. 소장 2천만 줄을 서버 메모리에 올리지 않고 SQL로 한다. 가져오기를 맡은 `collection`은 바뀌지 않는다(`addBook`이 돌려주는 번호는 "이번 가져오기 안에서만 쓰는 번호"). 이어 쓴·새로 준·없어진 번호 수는 `collection.catalog_import`에 남긴다.

## 이유 (사용자 발언)
- "이것도 같이 구현해 줘", 모듈은 "catalog 해줘" (2026-10-05, dev 기록)
- 기록: 사이클 07 회고 결정 기록 초안 승인 (2026-10-05)

## 검토한 대안
### A안: `catalog`의 표 바꾸기 안에서 (채택)
- 장점: 옛 소장을 읽는 일이 표 주인 모듈 안에 머묾. `collection`은 바뀌지 않음
- 단점: 쓰기 시간이 늘어남(17분 51초 → 22분 43초, 2회차 26분 55초)
### B안: `collection`에서 번호를 정함
- 장점: 가져오기 일이 한 모듈에 모임
- 단점: 옛 소장을 읽으려면 `catalog` 표를 직접 읽어야 해서 모듈 경계 원칙에 걸림
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 같은 사본 2회차: kept 1,617,445, new 0, dropped 0, 도서관 2,646곳의 (책 코드 → 책 번호)가 모두 같음 (dev 확인 2026-10-05)
- 합쳐짐·나뉨은 실데이터로 못 봄(같은 사본). 다음 사본 가져오기 로그로 확인
- 회원이 책 번호를 저장하는 기능이 생기면 옛 → 새 번호 고쳐 쓰기를 그 사이클에서 함
