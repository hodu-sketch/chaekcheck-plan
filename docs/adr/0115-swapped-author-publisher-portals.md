# ADR-0115: 저자·출판사가 뒤바뀐 세 포털은 가져올 때 규칙 파일로 바꿔 읽고, 수집기도 고치며, 규칙은 다음에 다시 검증하고 지운다

Status: Accepted
Date: 2026-10-15
Cycle: 19-author-angle-brackets
Supersedes: 없음

## 배경
수집 DB 실험에서 경기도교육청·대구·전북특별자치도교육청 전자도서관(수집 번호 12·11·15)의 거의 모든 줄이 저자와 출판사가 뒤바뀌어 있었다(63,660·27,251·12,768줄). 사이트를 열어 보니 같은 통합 포털 화면인데 이 세 곳은 목록에 출판사 → 저자 순서로 이름표 없이 보이고, 수집기 `parse_portal`은 첫 칸을 언제나 저자로 읽는다(부산·강원·인천·경북은 저자가 먼저).

## 결정
가져오기가 수집 줄을 읽는 순간(`CollectedCatalog.scan`) dev 규칙 파일 `author_publisher_swapped.tsv`(수집 번호 11·12·15)에 적힌 도서관의 두 칸을 바꿔 읽어, 묶기·책 표·소장 줄까지 바른 값이 되게 한다. 규칙 폴더는 가져오기 설정 `rules-dir`로 읽고 파일이 없으면 멈춘다. 수집기에는 "출판사가 먼저인 포털" 상수(세 호스트)를 두어 다음 수집부터 바르게 받는다. 고친 수집기 뒤 사본이면 가져오기가 멈추고, 그 사본으로 저자·출판사 비율 검사를 **검증 스크립트**(dev `scripts/library/check_author_publisher_swap.py` [안: 이름], 도서관마다 "바름 / 뒤바뀜 / 판단 못 함")로 다시 돌려 바르게 들어왔을 때만 규칙 줄을 지운다. Claude 세션은 "바름"이면 줄을 지우고 다시 가져오고, 그 밖이면 사용자에게 묻는다. 포털 칸 순서는 수집 전 점검 목록에서 확인한다.

## 이유 (사용자 발언)
- "같이하자 어짜피 cycle19가 내용이 그렇게 안 많아" (2026-10-14), 규칙 파일 + 수집기 고침: 승인 (세 원인 #5, 2026-10-14)
- "잊지 않게 막되 다음에도 이 규칙이 맞는가 검증은 해야 해 지금이 뜻하는 데이터 가공 방향으로" (2026-10-15)
- "이거 md에서 기록해놔서 다음에 수집할 때 고려가 되어야하는지 잘 체크하게 해줘" (2026-10-15)
- 줄 읽을 때 바꾸기, 규칙 파일 자리, 수집기 상수: 제안 → 승인 (설계 결정 #3·#4·#10, 2026-10-15)
- 검증 스크립트: "이거 수집기 클로드나 너와 같음 ai랑 같이 잘 돌도록 구성되어 있는거지?" → 승인 "다만 \"다시 검증\"을 사람 손 SQL이 아니라 스크립트 하나로 만들면 AI가 더 확실하게 돌립니다 — 이것을 더하기를 추천" (2026-10-15)

## 검토한 대안
### A안: 줄 읽을 때 바꿈 + 규칙 파일 + 수집기 상수 (채택)
- 장점: 책 화면 도서관 줄의 저자·출판사까지 바름, 세 묶는 방식이 따로 할 일 없음
- 단점: 세 도서관의 소장 줄은 "수집 원문 그대로"가 아님 → 데이터 모델에 적음
### B안: 묶기·책 만들기에서만 바꿈
- 단점: 고칠 곳이 늘고 소장 줄 저자·출판사는 계속 뒤바뀜
- 채택하지 않은 이유: [이유 미확인] (추천하지 않은 안)
### C안: 규칙을 코드 안 자료로, 잊음 장치 없음
- 단점: 사람이 정하는 규칙이 두 곳으로 나뉨, 잊으면 바르게 받은 줄을 다시 뒤바꿈
- 채택하지 않은 이유: 사용자 "잊지 않게 막되 … 검증은 해야 해"

## 결과
- 이번 사이클에는 다시 수집하지 않음. 다음 수집부터 고친 수집기로 받음
- dev 가져오기·수집 문서에 검증 절차와 점검 한 줄
- 사람이 정한 규칙(`author_publisher_swapped.tsv`, `PUBLISHER_FIRST_PORTAL_HOSTS`)은 dev 규칙 목록 문서(`docs/maintenance/rules-index.md` [안: 이름])에 한 줄씩 적는다: 어디에(파일·상수) / 뜻 / 데이터로 확인하는 법 / 바꾸는 법과 그 뒤 할 일. 코드 상수마다 그 줄을 가리키는 주석, 수집·가져오기 문서의 시작 점검이 확인 칸을 돌림 (방향 지침은 ADR-0117)

## 나중에 분리할 때
- 가져오기 규칙은 `collection`, 수집기는 수집 쪽과 함께 감
