# ADR-0001: 모듈 경계: region, library, availability

Status: Accepted
Date: 2026-09-27
Cycle: 01-ebook-availability-search
Supersedes: 없음

## 배경
첫 사이클에 전자도서관 목록·자격 규칙, 실시간 조회, 행정구역 목록이 필요하다. 행정구역은 행정안전부 공지에 따라 반년 정도마다 바뀌어 도서관과 수명 주기가 다르다. Spring Modulith 규칙상 모듈은 공개 API로만 서로 호출한다.

## 결정
`region`(시도·시군구 목록, 폐지·대체), `library`(전자도서관, 자격 규칙, 사용 여부, 대상 도서관 판정), `availability`(플랫폼 adapter, 실시간 조회, 캐시, 호출 간격 제어, 정렬용 값 계산) 세 모듈을 둔다. 의존 방향은 `availability → library → region`이다.

## 이유 (사용자 발언)
- [이유 미확인] (architect 추천안을 사용자가 채택, 2026-09-27)

## 검토한 대안
### A안: region 모듈 분리 (채택)
- 장점: 참조 데이터와 도서관 도메인이 분리되고 의존이 한 방향. Liquibase 변경분도 모듈별로 나뉨
- 단점: 모듈 하나 추가, 자격 판정 때 모듈 경계를 넘는 호출 한 번
### B안: 지역을 library 안에 둠
- 장점: 모듈 2개, 경계를 넘는 호출 없음
- 단점: 나중에 다른 모듈이 지역을 쓰면 library에 의존하게 됨
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 지역 규칙(폐지, 대체, 코드 갱신)이 한 모듈에 모임
- 감수하는 점: `region`을 공통 유틸 모듈로 키우지 않도록 관리해야 함
- 나중에 서비스로 분리할 때: 지역은 거의 읽기만 하는 참조 데이터라 복제하거나 따로 떼기 쉬움
