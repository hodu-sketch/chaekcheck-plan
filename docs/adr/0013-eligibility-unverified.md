# ADR-0013: 자격 모델 확장: 규칙이 없으면 자격 미확인

Status: Accepted
Date: 2026-09-28
Cycle: 02-library-expansion
Supersedes: 0004

## 배경
ADR-0004는 가입 조건 종류를 규칙 유무로 계산하고 "규칙 없음 = 누구나 가입"으로 봤다. 사이클 02는 자격을 찾지 못한 도서관도 넣고 "가입 자격 확인 필요"로 표시해야 하며, 추정값을 붙이지 않는다 (scope.md, eligibility.md). 책이음 회원·학생·시각장애인처럼 거주·직장 지역으로 판정할 수 없는 자격과, 방문 가입만 되는 도서관도 있다.

## 결정
- ADR-0004의 규칙 구조(근거 × 범위, nullable 기관 참조, `library.enabled`)는 그대로 둔다.
- 범위 종류에 `NATIONWIDE`를 더한다. 누구나 가입은 `RESIDENCE × NATIONWIDE` 한 줄로 저장한다. **규칙이 없으면 자격 미확인**이다.
- 판정 불가 자격은 규칙으로 저장하지 않고 도서관의 문구(`extra_condition_text`)로 보여 주기만 한다.
- 지역 규칙과 판정 불가 문구가 함께 있으면, 내 지역이 규칙과 맞을 때 가입 가능으로, 안 맞을 때 "가입 자격 확인 필요" + 문구로 보여 준다.
- 방문 가입만 되는 도서관은 `visit_required`로 표시한다.
- 인접 지역(천안 등)은 지역 규칙 여러 줄로 저장한다.

## 이유 (사용자 발언)
- 규칙 없음 = 미확인, 판정 불가는 문구만: [이유 미확인] (추천안 선택, 2026-09-28)
- 지역 규칙이 맞으면 가입 가능: [이유 미확인] (추천안 선택, 2026-09-28)
- 방문 가입 표시: [이유 미확인] (추천안 선택, 2026-09-28)

## 검토한 대안
### A안: 누구나도 규칙으로, 규칙 없으면 미확인 (채택)
- 장점: ADR-0004의 "종류는 규칙에서 계산" 원칙 유지. seed에서 규칙을 빠뜨리면 "누구나"가 아니라 "확인 필요"로 보임
- 단점: "규칙 없음"의 뜻이 사이클 01과 반대. 고흥에 NATIONWIDE 규칙을 더하는 마이그레이션과 코드가 같은 배포에 들어가야 함
### B안: 도서관에 가입 조건 종류 컬럼
- 장점: 읽기 쉬움
- 단점: 같은 사실이 두 곳에 저장되어 어긋날 수 있음
- 채택하지 않은 이유: [이유 미확인]
### C안: A안 + 판정 불가 자격도 규칙 종류로 구조화
- 장점: 나중에 책이음 회원 입력을 넣을 때 스키마 변경 없음
- 단점: 이번에 판정하지 않는 값을 미리 구조화함
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 수백 곳의 미확인 도서관을 규칙 0줄로 넣을 수 있음
- 감수하는 점: 기존 데이터 마이그레이션. 판정 불가 자격은 사용자별 입력이 생길 때까지 판정하지 않음 (backlog "사용자별 도서관 직접 추가")
- 되돌리는 비용: 중간 (뜻을 한 번 더 뒤집어야 함)
