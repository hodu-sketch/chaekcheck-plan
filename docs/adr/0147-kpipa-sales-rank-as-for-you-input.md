# ADR-0147: 출판유통통합전산망 판매 순위를 「나에게 맞는 책」 기본 목록의 재료로 씀 (이용 승인 거절을 알고 위험 감수)

Status: Accepted
Date: 2026-10-24
Cycle: 23-for-you-picks
Supersedes: 없음 (사이클 10 이후 "출판유통통합전산망 쓰지 않음" 흐름을 이 탭에 한해 바꿈)

## 배경
- 「나에게 맞는 책」 기본 목록에 "요즘 많이 팔리는·빌리는 책"이 필요함. 서점 베스트셀러는 교보문고·YES24·알라딘·리디·북큐브·인터파크가 약관이나 robots.txt로 막혀 있음 (`docs/research/popular-books/alternatives.md` 5-2절)
- 출판유통통합전산망의 공개 판매 순위 화면은 서버 호출로 받을 수 있음을 확인함 (`docs/research/popular-books/kpipa.md` 2절, 2026-10-11)
- 그러나 2026-10-12 출판데이터팀 회신: "이용약관에 따라 문의하신 내용은 승인이 어려움". 근거는 이용약관 제10조①(판매통계 정보는 판매 분석·통계자료 작성 용도로만) (`kpipa.md` 5절)
- 출판진흥원 「화제의 책 200선」(월간 200권)도 출판유통통합전산망 집계라 같은 처지임 (`alternatives.md` 6절, 검색 요약 기준 [확인 필요: 사용자 PC에서 원문 확인])

## 결정
- 출판유통통합전산망 판매 순위(일·주·월 Top100)와 「화제의 책 200선」을 기본 목록 인기 점수의 재료로 씀. 교보·YES24 전자도서관 인기, KLWAVE(보조), 추천목록과 섞음 (spec.md R2-1·R2-3)
- 위 거절 회신과 약관 제10조①을 알고 위험을 감수한다는 사용자 결정임
- 표지는 쓰지 않음 (표지도 승인되지 않은 것으로 읽음)
- 카드에 출처를 적지 않음. 출처 꼬리말은 추천목록에 있는 책에만 붙임 (spec.md R3-2)

## 이유 (사용자 발언)
- "출판유통통합전산망도 괜찮은데 왜냐면 여러 추천도서리스트랑 섞어서 할 거니까" (2026-10-24)
- "나. 그래도 쓰기. 그 경우 위 위험을 감수한다는 결정으로 ADR에 남기겠습니다." (2026-10-24, 제안 문구를 사용자가 골라 답함)
- 꼬리말: "추천목록에 있음 이외에는 보여주지 말자" (2026-10-24)
- 초안·「화제의 책 200선」·KLWAVE: "모두 YES" (2026-10-24)

## 검토한 대안
### A안: 쓰기 (채택)
- 장점: 실제 판매 기준의 인기 신호. 서버 호출로 받는 방법도 확인됨
- 단점: 운영 주체가 승인을 거절함. 약관 위반으로 볼 소지가 있고, 운영 주체가 요청하면 내려야 함
### B안: 쓰지 않음
- 장점: 약관 위험 없음
- 단점: 판매 기준 인기 신호가 없음. 교보·YES24 전자도서관 인기와 KLWAVE(분기)만 남음
- 채택하지 않은 이유: "여러 추천도서리스트랑 섞어서 할 거니까"
### C안: 다시 문의 ("섞어 쓰는 경우"를 출판데이터팀에 다시 물음)
- 장점: 승인되면 위험이 없어짐
- 단점: 회신을 기다리는 동안 출처가 없음. 사이클 10에서도 같은 기다림 끝에 거절됨
- 채택하지 않은 이유: 사용자 "서면동의요청빼고하고" (2026-10-24)
### 꼬리말 가안("서점 베스트셀러")·나안("출판유통통합전산망 판매 순위")
- 채택하지 않은 이유: "추천목록에 있음 이외에는 보여주지 말자" (2026-10-24)

## 결과
- 좋아지는 점: 기본 목록에 판매 기준 인기가 들어감
- 감수하는 점:
  - 약관 제10조① 위반으로 볼 소지 (법률 판단이 아닌 추론)
  - 내림 요청이 오면 바로 빼야 함 → 수집과 점수 계산을 다른 출처와 떼어 이 출처만 끌 수 있게 설계함 (설계 단계에서 design-delta.md에 반영)
  - 사이클 10에서 승인을 기다리다 「사서추천도서」로 바꾼 것과 다른 방향
- 되돌리는 비용: 이 출처를 끄면 인기 점수에서 빠질 뿐, 화면과 표 구조는 그대로
- 나중에 분리할 때: 수집 출처 하나일 뿐이라 영향 없음
