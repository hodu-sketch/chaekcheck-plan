# ADR-0085: 사람이 정한 도서관 규칙은 dev git의 TSV 파일로 두고, 지역은 번호로 미리 풀어 둔다

Status: Accepted
Date: 2026-10-12
Cycle: 13-crawler-to-dev
Supersedes: 없음

> **미리 정함**: 사이클 13은 사이클 12(책 묶기 기준)가 끝나기 전에 나란히 진행해 정한 결정이다. dev에는 사이클 12 handoff 뒤에 넘긴다.

## 배경
지금 seed 스크립트는 사람이 정한 값(이름 바꾸기, 같은 사이트, 체험용·운영 중단, 같은 호스트지만 남김, 가입 범위 덮어쓰기)과 가입 조사·도서관 종류·교보 probe·북큐브 권수를 여러 파일·코드 속 표에서 읽는다. 넣기 명령(ADR-0084)이 이 값을 읽어야 하고, 옛 스크립트와 결과가 같은지 비교해야 한다(AC-6). 가입 조사 결과의 지역은 이름으로 적혀 있어 같은 이름의 지역(중구 등)을 푸는 규칙이 필요하다.

## 결정
- dev git `scripts/library/rules/`에 규칙마다 TSV 파일 하나를 둔다 [안: 폴더·파일 이름]
  - `name_overrides`, `same_site`, `demo_or_closed`, `same_host_kept`, `scope_overrides`, `public_join`, `library_kinds`, `kyobo_probe`, `bookcube_volume`, `final_origins`
  - 순번 2 이상을 허용하는 곳은 허용 목록 파일로 둔다
  - 가입 조사 기준일은 한 줄짜리 날짜 파일 `join_surveyed_on.txt` (ADR-0087)
- `public_join`의 지역은 번호로 미리 풀어 적는다(새 줄은 Python 도우미로 채움). `collection`은 `region` 모듈에 의존하지 않는다
- 넣기 명령은 설정(`rules-dir`)으로 폴더를 받는다

## 이유 (사용자 발언)
- 규칙을 dev git 파일로 둠: 사전 결정 3 승인 (2026-10-12)
- 여러 TSV·지역 번호(A안), 순번 2 허용 목록, 날짜 한 줄 파일: 추천안을 고름 (2026-10-12, 설계 결정 2). 고른 이유는 [이유 미확인]

## 검토한 대안
### A안: 규칙마다 TSV, 지역은 번호 (채택)
- 장점: 옛 스크립트와 새 명령이 같은 파일을 읽어 비교가 정확, 모듈 의존이 늘지 않음, 고쳐도 다시 빌드 안 함
- 단점: 새 가입 조사 줄의 지역 번호를 도우미로 채워야 함
### B안: `backend/src/main/resources`에 YAML 하나
- 장점: 파일 하나
- 단점: Python 비교 도구가 읽기 어렵고 고칠 때마다 다시 빌드
- 채택하지 않은 이유: [이유 미확인]
### C안: A처럼 두되 지역은 이름 그대로, Java가 이름을 풂
- 장점: 사람이 읽기 쉬움
- 단점: 같은 이름 지역을 푸는 규칙을 Java로 옮겨야 하고 결과가 달라질 위험, `collection → region` 의존이 생김
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 규칙이 git 기록에 남고 한 곳에 모임
- 감수하는 점: 파일이 10개 넘음, 지역 번호를 손으로 쓰지 않도록 도우미가 필요
- 나중에 되돌리거나 서비스로 분리할 때의 비용: 낮음. 파일 꼴만 지키면 읽는 쪽을 바꾸기 쉬움
