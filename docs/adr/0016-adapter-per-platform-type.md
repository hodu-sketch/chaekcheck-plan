# ADR-0016: 화면 종류마다 adapter 하나

Status: Accepted
Date: 2026-09-28
Cycle: 02-library-expansion
Supersedes: 없음

## 배경
사이클 01은 교보·YES24 adapter 2개였다. 사이클 02는 교보 구독형, YES24 한 세대 전(EUC-KR), 통합 전자도서관 포털, 강남구 자체 시스템을 더한다 (research.md "플랫폼 유형 정리"). 화면마다 경로, 문자셋, 수량 표기, 대출 가능 여부 표기가 다르다.

## 결정
- 플랫폼 유형 6개(`KYOBO`, `KYOBO_SUBSCRIPTION`, `YES24`, `YES24_LEGACY`, `ELIB_PORTAL`, `GANGNAM`, 이름은 [안])마다 adapter 하나를 둔다. 교보 두 종류, YES24 두 종류의 공통 부분은 함께 쓴다.
- adapter는 검색어 문자셋을 정하고, 응답을 바이트로 받아 해석하며, 줄마다 사이트 판정과 (필요하면) 상세 페이지 주소를 돌려준다. 수량은 없을 수 있다.

## 검토한 대안
### A안: 화면 종류마다 adapter (채택)
- 장점: 차이가 값이 아니라 구조라서 코드와 HTML 고정 파일 테스트로 다룸
- 단점: 클래스 6개
### B안: 적은 adapter + 사이트별 설정을 DB에
- 장점: 배포 없이 변형 추가
- 단점: 파싱 지식이 데이터로 흩어져 테스트가 어렵고, 운영 중 선택자 변경으로 조용히 못 읽게 될 수 있음
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 화면이 바뀌면 해당 adapter와 테스트만 고침
- 감수하는 점: 새 화면 종류는 코드 배포가 필요함 (북큐브·알라딘·다산은 backlog)
