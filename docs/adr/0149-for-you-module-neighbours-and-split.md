# ADR-0149: 「나에게 맞는 책」 모듈 `foryou`, 비슷한 책 표와 넣는 길, 개인 추천 나누기

Status: Accepted
Date: 2026-10-24
Cycle: 23-for-you-picks
Supersedes: 없음

## 배경
「나에게 맞는 책」은 기본 목록, 비슷한 책(PC에서 KURE-v1로 134만 권 × 20권 계산), 탭 추천 글·꼬리표(PC Haiku 배치)를 쓴다. 운영 서버는 메모리 4GB다. 꼬리표는 추천목록 책에만 붙고 사이클 24 AI 책 찾기도 쓴다. 본 책 기록은 브라우저에만 두기로 했다(spec R5-1).

## 결정
1. 새 모듈 `foryou`가 기본 목록·점수·비슷한 책·탭 글·표지 연결·API 둘을 맡는다. 꼬리표와 꼬리표 사전은 `picks`가 갖고 `ListedBooks`(24)로 내보낸다. 꼬리표 사전은 DB 표 `picks.tag_dictionary`, 넣기 모드 `tag-dictionary`.
2. 비슷한 책 표 `foryou.book_neighbour`는 책마다 한 줄, 이웃 번호는 4바이트 정수 배열(최대 20)이다. 넣기는 `collection`의 새 모드 `neighbours`(full은 바꿔 끼우기, add는 upsert, catalog `export_id`가 다르면 멈춤). 처음 한 번 뒤 새 책만 계산하고 반년에 한 번쯤 전체를 다시 계산한다.
3. 탭 추천 글·꼬리표·표지 연결은 24의 `book-texts` 명령에 kind(`for_you_blurb`·`tags`·`cover_file`)로 넣는다. PC Haiku 배치는 책 한 권당 한 번 호출로 탭 글·꼬리표·찾기용 한 줄(24)을 함께 만들고, 대상 책 목록을 입력으로 받아 새 책만 더 돌린다.
4. 개인 추천: 브라우저가 기준 책 ≤3과 다시 보여 줄 본 책 후보 ≤6 번호만 보내고, 서버가 이웃 모으기·계획 도서관 거르기·정렬(인기 점수 있는 책 먼저, 그다음 계획 도서관 수)을 한다. 본 책(≤200) 빼기·같은 저자 2권·20권씩·다시 섞기는 브라우저가 한다.
5. 같은 책의 다른 판은 "같은 책" 규칙(본제목 정리값 같음 + 저자 공유, 사이클 21 규칙)으로 모아 점수를 더하고 소장 많은 판 하나만 보인다.

## 검토한 대안
### 모듈 B안: 모두 `picks` 안
- 단점: `picks`가 목록·인기 수집·이웃·글을 다 떠안고 `availability`에도 의존
- 채택하지 않은 이유: [이유 미확인] (A안 승인)
### 이웃 B안: 짝마다 한 줄 (약 2,680만 줄, 약 2GB)
- 채택하지 않은 이유: [이유 미확인] (가안 승인)
### 이웃 C안: 임베딩 벡터를 운영에 두고 그때그때 찾기 (벡터만 약 5.5GB)
- 채택하지 않은 이유: "일단 (가)로 하고 나중에 … 고려하자" (backlog)
### 개인 추천 B안: 본 책 200권을 서버로
- 단점: 행태 정보가 서버로 감, "3권만"을 크게 바꿈
- 채택하지 않은 이유: [이유 미확인] (A안 승인)
### 배치 B안: 23·24 따로
- 채택하지 않은 이유: [이유 미확인] (같이 만들기 승인)
### 사전 A안: 서버와 함께 배포되는 파일
- 채택하지 않은 이유: 사용자 미승인, "DB 표"
### 판 A안: 책 번호만
- 채택하지 않은 이유: [이유 미확인] (B안 승인)

## 결과
- 좋아지는 점: 이웃 표 약 0.2GB, 기준 책 3권이면 세 줄만 읽음. 본 책 목록은 서버에 남지 않음. 23·24 글을 한 파일·한 명령으로 넣음
- 감수하는 점: 모듈 하나·공개 API 몇 개 늘어남(`ForYouTransfer`, `BookTagTransfer`, `RankedListings`, `BookLookup` 카드 칸·`workKeys`). 순서 규칙 일부가 웹 코드에 있음. 23·24 중 먼저 개발하는 쪽이 `book-texts`·`ListedBooks`를 만듦. 책 번호가 21억을 넘으면 배열 타입을 바꿔야 함
- 되돌리는 비용: 이웃 표 모양은 넣기 모드와 표 하나, 개인 추천 나누기는 응답 모양이 같아 웹 코드만 바뀜
- 나중에 분리할 때: `foryou`는 추천 서비스(`foryou` 스키마)로 떼고, 넣기 모드는 그 서비스의 가져오기 끝점으로 감
