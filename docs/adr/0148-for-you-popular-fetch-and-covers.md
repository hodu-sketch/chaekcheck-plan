# ADR-0148: 「나에게 맞는 책」 인기 목록은 운영 서버가 새벽에 받고, 표지는 PC 표지를 옮김

Status: Accepted
Date: 2026-10-24
Cycle: 23-for-you-picks
Supersedes: 없음

## 배경
「나에게 맞는 책」 기본 목록은 매일 새벽에 만들고 실패하면 전날 목록을 쓴다(spec R2-5, 사용자 승인 2026-10-24). 인기 재료는 교보 일반 전자도서관 4곳·YES24 V1 2곳의 인기순 앞 100권(대출 중·예약 수), 출판유통 판매 순위·「화제의 책 200선」(ADR-0147), KLWAVE다. 탭에는 추천목록 밖 책(인기 책, 비슷한 책)도 나오는데 서비스 `catalog`에는 표지 칸이 없다. PC `fetch-covers`가 서비스 책마다 표지를 받고 있다(dev 2026-10-23~).

## 결정
- 인기 목록은 운영 서버의 새 모듈 `foryou`가 매일 새벽 직접 받는다. 도서관 사이트는 `availability`의 새 공개 API(`RankedListings`)로, 조회와 같은 호스트 줄(호스트당 1건·1초)과 나가는 길 설정을 그대로 쓴다. `*.dkyobobook.co.kr`에는 보내지 않는다. 출처마다 따로 끌 수 있다.
- 책 수집 때마다 인기 목록 받기가 아직 맞는지 검증한다(`docs/cycles/23-for-you-picks/to-dev-popular-list-check.md`).
- 표지는 PC `fetch-covers` 결과 가운데 탭 글 범위(추천목록 책 + 보유 많은 3만 권 + 기본 목록 후보)를 운영 `/covers/`(ADR-0144와 같은 nginx 규칙)로 옮기고, 책 번호 연결은 `book-texts` kind `cover_file`로 넣는다. 그 밖은 제목 글자 표지.

## 이유 (사용자 발언)
- 인기 목록: 설계 결정 #1 승인 (2026-10-24). 검증: "주기적으로 수집하면서 이거 추천 도서 목록 찾는것도 바뀔 수 있을 것 같은데.... 이것도 책 수집할 때 인기 도서 찾는거 검증하라고 따로 써줘"
- 표지: "아니아니 어짜피 보여야 하는 거면 수집하자 수집 세션에게 하라고 시켜" (2026-10-24)

## 검토한 대안
### A안: 운영 서버가 새벽에 받음 (채택)
- 장점: 사람 손 없이 매일, 실패하면 전날 목록. 책 번호가 늘 운영 기준. 조회와 같은 줄
- 단점: 인기순 화면 파싱을 서버에 새로 짬. 프록시 길이 dev에 있어야 함
### B안: 내 PC 수집기 → 파일 넣기
- 장점: 파서가 이미 있음, 운영 나가는 길을 건드리지 않음
- 단점: 매일 PC가 켜져 있어야 하고 반영이 사람 손을 탐
- 채택하지 않은 이유: [이유 미확인] (A안 승인)
### 표지 B안: 이번에는 추천목록 밖 책은 글자 표지, 넓히기는 다음에
- 채택하지 않은 이유: "어짜피 보여야 하는 거면 수집하자"
### 표지 C안: 서버가 새 인기 책 표지만 YES24에서 받음
- 단점: 서점 이미지 서버 요청, 이용 조건 확인 필요
- 채택하지 않은 이유: [이유 미확인] (backlog 후보)

## 결과
- 좋아지는 점: 기본 목록이 매일 자동, 카드 대부분에 표지
- 감수하는 점: 교보문고 약관 제11조⑨ 범위 [확인 필요]. 오늘 새로 든 인기 책은 다음 PC 반영까지 글자 표지. 표지 출처별 이용 조건은 공개 배포 전 확인
- 되돌리는 비용: 인기 수집을 PC 파일로 바꾸면 `foryou`의 작업 하나를 넣기 모드로 바꿈, 표·화면 그대로
- 나중에 분리할 때: 수집 작업은 추천 서비스 안, `availability` 호출은 내부 HTTP 하나로
