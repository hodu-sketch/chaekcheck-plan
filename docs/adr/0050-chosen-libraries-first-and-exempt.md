# ADR-0050: 직접 추가한 도서관은 검색에서 맨 앞, 자격 규칙의 예외

Status: Accepted
Date: 2026-10-04
Cycle: 06-my-libraries
Supersedes: 없음

## 배경

사이클 06에서 로그인한 사람은 지역과 상관없이 도서관을 "내 도서관"에 직접 추가할 수 있습니다(최대 20곳). 검색은 회원을 모르고 화면이 `libraryIds`로 넘깁니다(ADR-0037). 정할 것은 검색 계획과 결과에서 이 도서관을 어떻게 다룰지(순서, 가입 자격 배지, "방문 없이 가입" 거르기)였습니다. 방문 가입 순서는 ADR-0027이 정했습니다.

## 결정

검색 요청의 `libraryIds`에 있는 켜진 도서관은 자격과 상관없이 계획에 넣고 "직접 추가" 표시(`chosen`)를 붙여 결과 맨 앞에 둡니다. 스위치가 "전체 도서관"이어도 같습니다. 원래 무리(`priorityGroup`: 내 시군구, 누구나 가입 등)는 그대로 둡니다. 직접 추가한 도서관은 이미 가입해서 넣은 곳으로 보고 가입 자격 배지 대신 "직접 추가" 표시 하나만 보이며, "방문 없이 가입"을 켜도 빼지 않습니다.

## 이유 (사용자 발언)

- "직접 추가한 도서관은 예외임. \"가입 자격 확인 필요\" 필요없음" (2026-10-04)
- "이미 가입된 도서관이라서 넣는다 이거 간단하게 표시하고 넣어줘" (2026-10-04)
- 맨 앞에 두는 것, "전체"에서도 앞에 두는 것, 표시 방식은 제안 → 승인(2026-10-04)

## 검토한 대안

### A안: "직접 추가" 표시 칸을 더하고 원래 무리는 그대로 (채택)
- 장점: 무리와 배지 뜻이 바뀌지 않음. 화면의 무리 코드가 그대로
- 단점: 응답 칸 하나(`chosen`)와 정렬 값 하나(`JoinTier.CHOSEN`)가 늘어남(호환됨)

### B안: 새 무리 값 "직접 추가"
- 장점: 칸이 늘지 않음
- 단점: 원래 무리를 잃고 화면 코드·시험을 더 고쳐야 함. ADR-0027도 같은 이유로 새 무리 값을 고르지 않음
- 채택하지 않은 이유: [이유 미확인]

### C안: 스위치가 "전체"일 때는 앞에 두지 않음
- 장점: "전체"의 결과가 로그인 전과 완전히 같음
- 채택하지 않은 이유: [이유 미확인] (사용자가 "전체에서도 앞" 제안을 승인)

### D안: 가입 자격 배지를 그대로 보이고, "방문 없이 가입"이면 뺌
- 장점: 자격 판정이 모든 도서관에 같게 적용됨
- 채택하지 않은 이유: 위 사용자 발언(직접 추가는 예외, 이미 가입한 곳)

## 결과

- 좋아지는 점: 이용자가 직접 고른 도서관이 늘 먼저 보이고, 쓸데없는 경고가 붙지 않음
- 감수하는 점: 이용자가 실제로 가입하지 않은 도서관을 넣어도 경고가 없음. 계획 순서, `/api/v1/books` 정렬, 화면 `sortBatch` 세 곳에 같은 규칙을 둬야 함
- 나중에 분리할 때: 검색 서비스의 요청 파라미터 하나와 응답 칸 하나. 회원 서비스를 부르지 않음(ADR-0037 그대로)
