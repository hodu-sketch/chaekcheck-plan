# ADR-0049: 내 도서관 화면이 쓰는 목록과 저장 방법

Status: Accepted
Date: 2026-10-04
Cycle: 06-my-libraries
Supersedes: 없음

## 배경

사이클 06의 내 도서관 화면(S10)은 여섯 구역(거주 지역 선택, 거주 지역으로 자동, 직장 지역 선택, 직장 지역으로 자동, 직접 도서관 추가, 직접 추가한 도서관)과 맨 위 "누구나 가입" 줄, 이름 검색을 보입니다(`docs/cycles/06-my-libraries/flow.md`). 추가·빼기는 누르면 바로 저장합니다. 바뀐 지역은 화면이 `/api/v1/regions/resolutions`로 해석하고(spec R6), 검색 모듈은 회원을 모릅니다(ADR-0037). 지금은 도서관 목록을 주는 REST가 없습니다.

## 결정

1. `library` 모듈이 로그인 없이 쓰는 공개 목록 `GET /api/v1/libraries?residenceRegionIds=&workRegionIds=`를 둡니다. 켜진 도서관 전체에 줄마다 가입 표시(누구나 가입 / 거주로 됨 / 직장으로 됨)를 붙여 주고, 화면이 이것으로 여섯 구역·누구나 가입 줄·이름 검색(화면 안에서 거름)을 만듭니다.
2. 저장은 `mylibrary`가 맡고 주소는 `/api/v1/me/` 아래에 둡니다(로그인 확인·계정 확인·CSRF를 `auth` 수정 없이 그대로 씀, ADR-0044). 지역은 `PUT /api/v1/me/regions`로 통째로 바꾸고 본문에 거주·직장이 다른 칸(`residenceRegionIds`, `workRegionIds`)으로 들어갑니다. 직접 추가 도서관은 `PUT`/`DELETE /api/v1/me/libraries/{libraryId}`로 하나씩 넣고 뺍니다.
3. 지역 옮기기 창에서 [저장하지 않기]를 누른 것과 "전체 / 내 도서관" 스위치 값은 그 브라우저 안에 적어 두고 서버에 보내지 않습니다.

## 이유 (사용자 발언)

- [이유 미확인] (제안 → 승인, 2026-10-04). 사용자는 "이렇게 하면 거주/직장 구분은 어떻게 해?", "이거 post인데 안에 직장/거주 구분이 있는거야?"라고 물었고, 본문에 칸이 따로 있다는 답을 본 뒤 승인함

## 검토한 대안

### A안: 도서관 공개 목록 하나 + 지역 통째로·도서관 하나씩 (채택)
- 장점: 화면이 쓰는 API가 적음. 자격 판정은 `library`에만. 다른 탭에서 바꾼 도서관을 덮어쓰지 않음. 20곳 초과·꺼진 도서관을 409/404로 정확히 알림
- 단점: 278곳 전체를 내려받음(크기 [확인 필요: dev 측정]). 두 탭에서 동시에 지역을 바꾸면 나중 저장이 이김

### B안: `mylibrary`가 서버에서 다 계산해 줌
- 장점: 화면 요청이 하나
- 단점: 바뀐 지역 해석이 서버·화면 두 곳에 생기고, 매핑 전용 모듈이 자격 판정을 다룸. 이름 검색은 따로 필요
- 채택하지 않은 이유: [이유 미확인]

### C안: `library`가 세 목록으로 나눠 줌
- 장점: 응답이 작음
- 단점: 직접 추가 줄의 이름과 이름 검색에 API가 하나 더 필요
- 채택하지 않은 이유: [이유 미확인]

### D안: 직접 추가 목록도 통째로, 또는 지역·도서관을 한 묶음으로 저장
- 장점: 서버가 단순하거나 요청이 하나
- 단점: 다른 탭에서 바꾼 것을 덮어씀
- 채택하지 않은 이유: [이유 미확인]

### E안: 거주와 직장을 주소부터 따로 저장
- 장점: 화면 구역과 딱 맞고 두 탭에서 거주·직장을 동시에 바꿔도 덮어쓰지 않음
- 단점: 주소가 둘로 늘어남
- 채택하지 않은 이유: [이유 미확인] (답을 본 뒤 A안을 승인함)

## 결과

- 좋아지는 점: 공개 목록은 회원을 모르므로 ADR-0037을 그대로 지킴. 저장 API에 사이클 05의 보안 설정이 그대로 적용됨
- 감수하는 점: 도서관이 수천 곳이 되면 서버에서 이름으로 거르는 방식으로 바꿔야 함. 다른 기기에서는 [저장하지 않기] 답과 스위치 값을 모름
- 나중에 분리할 때: 공개 목록은 도서관 서비스의 공개 API, 저장은 "내 도서관" 서비스의 자원 둘
- 관련: ADR-0048, ADR-0050, ADR-0051
