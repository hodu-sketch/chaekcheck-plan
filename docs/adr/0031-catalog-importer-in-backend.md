# ADR-0031: 한 번 가져오기는 서비스 백엔드 Java, 정리 규칙 코드 한 벌

Status: Accepted
Date: 2026-09-30
Cycle: 04-and-search
Supersedes: 없음

## 배경
수집 목록(`chaekcheck-data`의 SQLite, 파이썬 수집기)과 국가서지 파일을 서비스 PostgreSQL로 한 번 가져와야 한다. 검색어와 저장값은 같은 정리 규칙(NFKC, 공백 제거, 저자 역할, 본제목, 출판사)으로 정리해야 검색이 맞는다. 주기 갱신은 별도 사이클이다.

## 결정
`catalog` 모듈 안의 Java importer(Spring 프로필 `catalog-import` [안])가 SQLite를 읽고 정리·묶기 뒤 `COPY`로 넣는다. 검색어 정리와 같은 코드를 쓴다. Liquibase는 스키마·확장·인덱스만 맡고 데이터는 넣지 않는다.

## 검토한 대안
### 서비스 백엔드 Java (채택)
- 장점: 정리 규칙이 한 벌이라 검색어와 저장값이 어긋나지 않음. 갱신 사이클이 재사용
- 단점: `sqlite-jdbc` 의존성, 국가서지 TTL 읽기를 Java로
### 수집 쪽 Python이 정리한 파일을 만들어 넣음
- 장점: 빨리 만듦
- 단점: 정리 규칙이 Python·Java 두 벌
- 채택하지 않은 이유: [이유 미확인]
### Liquibase loadData
- 장점: 배포 흐름에 포함
- 단점: 280만 행을 changelog에 넣어 느리고 저장소가 부풂
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 정리 규칙을 테스트 벡터 하나로 고정함. 감수하는 점: 수집(Python)과 가져오기(Java)가 다른 언어.
