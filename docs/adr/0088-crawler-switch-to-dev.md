# ADR-0088: 수집은 dev `scripts/crawl/`로 갈아타고, 옛 코드는 지우지 않고 보관한다

Status: Accepted
Date: 2026-10-12
Cycle: 13-crawler-to-dev
Supersedes: 없음 (ADR-0047을 이어서: 옮기기를 끝냄)

> **미리 정함**: 사이클 13은 사이클 12(책 묶기 기준)가 끝나기 전에 나란히 진행해 정한 결정이다. dev에는 사이클 12 handoff 뒤에 넘긴다.

## 배경
ADR-0047로 수집기를 dev `scripts/crawl/`로 옮기기로 했고, dev는 2026-10-05에 복사본을 만들었다. 그 뒤에도 데이터 폴더의 옛 수집기로 수집을 돌려 코드가 두 벌이 되었고, dev 복사본에는 `vendor` 칸 등 뒤에 고친 것이 없다(`docs/research/maintenance/crawler-move.md`). 옮기기 결정 1~7은 그 문서에 [확정]으로 있다.

## 결정
- 앞으로 수집은 dev `scripts/crawl/`(Python 그대로)로만 돌린다. 첫 시험은 여주대(102084) 빈 곳 채우기
- dev 수집기에 `vendor` 칸·옮기기(`migrate`)와 빈 곳 채우기 명령을 더한다 [안: 명령 이름 `refill-pubdt`]
- 데이터 폴더의 옛 `scripts\`, `resume.cmd`는 보관 폴더(`_old-scripts-2026-10-12`)로 옮기고 지우지 않는다. 데이터 폴더의 다른 도구도 dev로 옮긴다
- 수집기 구조 정리는 이번에 하지 않는다(backlog)
- 호출 예절은 그대로(IP마다 한 줄, 1건, 1초 간격). robots.txt는 기록만 하고 수집은 함

## 이유 (사용자 발언)
- "옛 코드는 보관 폴더로 옮기고 백업 용으로 하고 지우지는 마" (2026-10-12)
- "새 사이클 말고 지금 사이클에서 같이 해", "이 작업 cycle 13인 걸로 하자" (2026-10-12)
- Python 그대로 옮김: 사전 결정 7 승인 (2026-10-12). 이유는 [이유 미확인]

## 검토한 대안
### A안: 지금 갈아타고 옛 코드는 보관 (채택)
- 장점: 코드가 한 벌, 옛 코드로 되돌아갈 수 있음
- 단점: 갈아탄 뒤 첫 실행을 시험해야 함
### B안: 갈아타면서 옛 코드를 지움
- 채택하지 않은 이유: "지우지는 마"
### C안: Java로 다시 씀
- 장점: 언어가 하나
- 단점: 큰 일, 호출 예절·문제별 대처를 다시 시험해야 함
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 수집기 코드가 dev git에 하나로 모이고 변경 기록이 남음
- 감수하는 점: 데이터 폴더(수집 DB·사본)와 코드 폴더가 다름. 옛 수집기가 돌고 있으면 새 수집기는 시작하지 않음
- 나중에 되돌리거나 서비스로 분리할 때의 비용: 낮음. 보관 폴더의 옛 코드로 되돌릴 수 있음
