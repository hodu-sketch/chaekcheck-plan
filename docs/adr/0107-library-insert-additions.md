# ADR-0107: 도서관 넣기 명령 보탬 — 새 곳은 최종 주소 줄 필수, 확인한 사라진 곳 파일, 번호는 `nextId()`부터, 종료 코드 5, 운영 반영은 같은 번호가 다른 도서관이면 멈춤

Status: Accepted
Date: 2026-10-14
Cycle: 13-crawler-to-dev (회고)
Supersedes: 없음 (ADR-0084·0085·0086 보완)

## 배경
사이클 13 dev가 넣기 명령을 실데이터(2026-10-12 사본)에 돌리며 설계에 없던 경우를 만났다. 새 6곳 중 2곳이 최종 주소 확인에서 시간 초과였고(약 5.2초, 리다이렉트 없음), 서비스에 켜져 있는 3곳(44 국회도서관, 261 군포시도서관, 269 김천시립도서관)이 수집 DB에서 받지 않음이라 "사라진 곳"으로 나와 기대값 0과 달랐다. 옛 seed 스크립트는 새 곳에 사이클 08에서 비운 2664~2669를 주었으나 `LibraryRegistry.nextId()`는 seed의 `RESTART WITH 2675`를 따라 2675부터 준다. 운영 반영의 도서관 부분은 "있는 번호는 건너뜀"이라, 같은 번호에 다른 도서관이 있어도 지나갈 수 있었다. (dev `plan-feedback.md` 3561~3581·3659~3662행) 2026-10-12 dev 세션에서 정한 것을 2026-10-14 회고에서 ADR로 기록했다.

## 결정
- 새로 넣을 곳은 규칙 폴더 `final_origins.tsv`에 줄이 꼭 있어야 한다. 없으면 규칙 오류(종료 1). 옛 스크립트도 같다.
- 다시 열어 보고 확인한 "사라진 곳"은 규칙 파일 `gone_known.tsv`(칸 `collection_id`, `name`, `decided_on`, `checked_on`, `state`)에 적고, 보고서에는 `goneKnown`에 번호만 둔다. 서비스에서는 켜 둔다(끄는 것은 따로, 지금은 사이클 18). "사라진 곳"은 켜진 서비스 도서관만 본다.
- 새 번호는 `nextId()` = `GREATEST(max(id)+1, IDENTITY 다음 값)`부터. 넣기는 잠금 뒤 `nextId()`가 보고서 첫 번호와 다르면 넣지 않는다(종료 4). 옛 스크립트도 마지막 `RESTART WITH`부터 매긴다.
- 종료 코드 5: DB가 줄을 거절하면 롤백하고 `FAILED` 실행 기록 한 줄. 넣을 곳이 0이면 실행 기록을 남기지 않는다.
- 운영 반영의 도서관 부분: 이미 있는 번호가 다른 도서관(이름·주소가 다름)이거나 짝이 다른 도서관을 가리키면 건너뛰지 않고 멈춘다(롤백, `catalog_import` `FAILED`·`error`·`library part: …`).

## 이유 (사용자 발언)
- 최종 주소 줄 필수: "빠진 곳은 확인해 채움" (2026-10-12)
- 확인한 사라진 곳 파일: "확인하고 빼줘 파일로 적어줘" (2026-10-12)
- 서비스에 있는 곳은 그대로: "기존 DB에 있는 도서관은 기본으로 포함" (2026-10-12)
- 번호 규칙, 종료 코드 5, 넣을 곳 0이면 기록 없음, 다른 도서관이면 멈춤: [이유 미확인] (dev가 정함, 뒤의 것은 java-reviewer 리뷰 반영)
- ADR로 기록·확정: 초안 승인 (2026-10-14, 회고 결정 #15)

## 결과
- 좋아지는 점: 새 6곳(2675~2680)이 넣기 명령으로 들어감. 같은 번호의 다른 도서관을 운영에 덮어쓰지 않음
- 감수하는 점: `gone_known.tsv`를 사람이 고쳐야 함. 서비스에 켜 둔 곳(44·261·269)은 책 목록이 다시 수집되지 않음
- 나중에 서비스로 분리할 때: 해당 없음
