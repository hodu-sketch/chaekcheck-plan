# ADR-0131: 사용자가 화면을 떠나면 서버 모드 묶음은 새 도서관을 띄우지 않고, 이미 넘긴 요청은 끝까지 받아 캐시에 넣는다

Status: Proposed
Date: 2026-10-16
Cycle: 20-lookup-status-and-extension
Supersedes: 없음

## 배경
지금 서버 모드 검색(SSE 스트림)은 사용자가 화면을 떠나도 묶음이 끝까지 돌며 새 도서관을 계속 띄운다. 그동안 검색 자리(`SearchSlots`, 20개)와 도서관 호출이 쓰인다. 앞 제안(앞 결정 페이지 #10)은 "줄에서 기다리던 요청도 취소"였으나, dev 코드를 보니 줄 대기는 캐시 안에서 일어나고 같은 도서관·같은 검색어·같은 쪽을 기다리는 다른 사용자와 같은 요청을 공유할 수 있어(dev `CaffeineSearchPageCache.java:41-43`, 2026-10-16 확인) 취소하면 그 사람 결과까지 실패한다. 또 자리를 바로 돌려주면 떠난 묶음의 요청이 도는 동안 새 묶음이 자리를 받아 "자리 20 × 동시 5 = 최대 100건" 약속이 깨진다.

## 결정
- 서버 모드에서 사용자가 떠난 것을 알아채면(이벤트 보내기 실패 또는 `SseEmitter` 연결 오류·시간 초과 알림 → `clientGone`) **새 도서관을 띄우지 않고 포털 상세도 새로 시작하지 않는다**(남은 후보는 `notSent` → `SKIPPED`, `StopReason` `CLIENT_GONE`).
- 이미 넘긴 요청은 줄 대기 포함 **취소하지 않고 끝까지 받아 캐시에 넣는다**(다른 사용자와 공유될 수 있음).
- 자리는 넘긴 요청이 모두 끝날 때 반납한다(최대 묶음 마감 8초 · 상세 30초).
- 책 화면(소장) 흐름도 같은 규칙. 「더 보기」 서버 모드는 쪽 하나·8초 상한이라 대상 아님.
- 확장 모드는 떠날 때 화면이 마지막 계획을 닫기(`keepalive`)로 알리고 확장은 남은 주소를 버린다(ADR-0119).

## 이유 (사용자 발언)

## 검토한 대안
### A안: 새로 시작하지 않음, 넘긴 요청은 끝까지 (채택)
- 장점: 떠난 뒤 새 도서관 호출이 없어 자리·도서관 부담이 줄고, 공유된 요청을 다른 사용자까지 실패시키지 않으며, "자리 20 × 동시 5" 상한이 지켜짐. 받은 결과는 캐시로 다른 사용자가 씀
- 단점: 이미 넘긴 요청이 끝날 때까지(최대 8초·상세 30초) 자리가 남음
### B안: 줄 대기까지 취소 (앞 결정 페이지 #10)
- 장점: 자리를 더 빨리 돌려줌
- 단점: 캐시에서 공유된 요청을 취소하면 같은 요청을 기다리던 다른 사용자 결과까지 실패, 자리를 바로 돌려주면 동시 도서관 요청 상한이 깨짐
- 채택하지 않은 이유: [이유 미확인] (제안 → 승인)
### C안: 지금대로 (아무것도 안 함)
- 장점: 코드 변경 없음
- 단점: 떠난 뒤에도 새 도서관을 계속 띄움
- 채택하지 않은 이유: [이유 미확인] (제안 → 승인)

## 결과
- 좋아지는 점: 떠난 사용자의 묶음이 새 도서관 호출을 만들지 않음. 이미 받은 결과는 캐시로 다른 사용자에게 쓰임
- 감수하는 점: 떠난 뒤에도 넘긴 요청이 끝날 때까지 자리를 잡음. nginx를 거친 SSE에서 끊김을 알아채는 시점은 dev 시험으로 확인 필요(`design-delta.md` 확인 필요 표)
- 나중에 되돌리거나 서비스로 분리할 때: 묶음 실행 코드(`BatchRunner`·`BatchSession`)의 멈춤 이유 하나라 비용이 작음. 나중에 분리할 때 이 규칙은 조회를 맡는 쪽을 따라감
