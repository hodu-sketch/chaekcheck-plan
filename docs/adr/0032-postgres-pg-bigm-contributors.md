# ADR-0032: 책 목록 검색은 PostgreSQL + pg_bigm, 저자는 사람별 표

Status: Accepted
Date: 2026-09-30
Cycle: 04-and-search
Supersedes: 없음

## 배경
한국어 검색어는 두 글자가 흔하다("행동", "김달"). 측정(2026-09-30, 이 PC, 3.5백만 행 복제본): pg_trgm은 두 글자 검색에서 인덱스를 못 써 전체를 훑고(수 세기 215ms), pg_bigm은 모두 인덱스를 씀(3ms). 가장 무거운 경우는 "사랑" + 출판일순 약 184ms. 저자 검색은 역할(지은이·옮긴이·그림·엮은이)과 "사람 이름 하나와 같음" 완전 일치가 필요하다.

## 결정
서비스 PostgreSQL에 pg_bigm 확장을 쓰고 제목·출판사·사람 이름에 `gin_bigm_ops` 인덱스를 둔다. 저자는 `book_contributor`(책 × 사람 × 역할) 표에서 한 사람 이름 안의 단어 AND로 찾는다. 출판일 인덱스는 `DESC NULLS LAST`와 `ASC NULLS LAST` 둘, 완전 일치는 `COLLATE "C"` B-tree.

## 검토한 대안
### PostgreSQL + pg_bigm, 사람별 표 (채택)
- 장점: 서버 추가 없음. 두 글자 검색 인덱스. 역할·완전 일치를 그대로 표현
- 단점: 사람별 표 구조의 규모 속도는 미측정. 운영 호스팅이 pg_bigm을 지원해야 함
### pg_trgm
- 장점: 기본 확장
- 단점: 두 글자 검색에서 인덱스를 못 씀
- 채택하지 않은 이유: [이유 미확인]
### 책 표에 역할별 칸
- 장점: 측정한 구조와 같아 빠름
- 단점: 다른 사람 이름에 걸친 단어도 맞음
- 채택하지 않은 이유: [이유 미확인]
### OpenSearch 등 검색 서버
- 장점: 순위·오타·형태소
- 단점: 서버 추가와 옮겨 담기
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 지금 스택 안에서 AND·정렬·완전 일치. 감수하는 점: 개발·테스트 DB 이미지에 pg_bigm을 넣어야 함. 흔한 단어의 결과 수 추정이 낮아 실행 계획이 나빠질 수 있음. 느려지면 PGroonga, ParadeDB, OpenSearch 순으로 검토.
