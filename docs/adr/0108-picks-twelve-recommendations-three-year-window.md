# ADR-0108: 사서추천도서는 최근 12번(2년)을 보여 주고, 요청 기간은 3년

Status: Accepted
Date: 2026-10-14
Cycle: 14-librarian-picks
Supersedes: 없음 (ADR-0089의 범위·기간 부분("등록일 2년 범위로 요청 1건, 추천 연월이 다른 최근 6개 달만 남김")을 바꿈. ADR-0092가 ADR-0089 일부를 바꾼 것과 같은 방식)

## 배경
ADR-0089는 "등록일 2년 범위로 요청 1건, 추천 연월이 다른 최근 6개 달만 남김"으로 정했다. 개발 중(2026-10-12) 화면을 본 사용자가 분야마다 10권뿐인 것을 보고 범위를 늘리기로 했다. 국립중앙도서관은 2달에 한 번 네 분야 각 2권(6월·12월은 테마 12권)을 추천하므로 12번이 약 24개월이다. dev는 12번째 추천이 범위 밖으로 빠지지 않게 요청 기간을 3년으로 바꿨다. 2026-10-14 받기 시험: 3년 범위 1건 163건·2,511,752바이트·771ms, 남긴 108권(네 분야 각 18, 테마 36).

## 결정
- 추천 연월이 다른 최근 12개 달(12번, 약 2년)의 책을 남겨 보여 준다 (`KeptPicks.MONTHS` 12)
- 요청은 그대로 1건이고 기간은 받는 날부터 거꾸로 3년(`window` 3y)이다
- 도움말에 "최근 12번(2년)"과 추천 주기를 적는다

## 이유 (사용자 발언)
- 12번: "지금 10권까지만 있는데 그 이상도 안되나? 사서추천도서 분야별로 10권까지야?", 선택지 중 "12번(2년)으로 늘리기" (2026-10-12, dev `plan-feedback.md` 3781행)
- 도움말: "이거 좀 더 구체적으로 12번(2년)이라고 알려주고, 국립중앙도서관은 보통 2달에 한 번, 한 번에 약 8권(문학·인문·사회·자연 각 2권)을 추천해요. 이 정보도 알려줘" (2026-10-12, dev `plan-feedback.md` 3785행)
- 요청 기간 3년: 제안 → 승인 (2026-10-14, 회고 결정 #21). dev가 적은 이유 "12번째 추천이 범위 밖으로 빠질 수 있어서"는 사용자 말이 아님

## 검토한 대안
### A안: 12번 + 요청 3년 (채택)
- 장점: 받는 날과 상관없이 12번이 늘 다 들어옴
- 단점: 응답 1.56MB → 2.51MB (상한 10MB 안)
### B안: 6번 그대로
- 단점: 분야마다 10권 남짓
- 채택하지 않은 이유: "지금 10권까지만 있는데 그 이상도 안되나?" (2026-10-12)
### C안: 12번 + 요청 2년
- 장점: 응답이 작음
- 단점: 받는 날에 따라 11번만 보일 수 있음
- 채택하지 않은 이유: [이유 미확인] (사용자는 3년 안을 승인, 2026-10-14)

## 결과
- 좋아지는 점: 분야마다 2쪽(테마 4쪽), `pick` 108줄·표지 108장 약 1.29MB
- 감수하는 점: 2년 전 추천도 "신간"으로 보임. 응답 2.51MB
- 되돌리기 비용: `KeptPicks.MONTHS`·`window` 값과 도움말 문구만
- 나중에 서비스로 분리할 때: `picks` 모듈 안이라 바꿀 것 없음
