# ADR-0029: 책별 대출 상황은 상세 페이지로 읽고, adapter와 묶음 실행기를 넓혀 처리

Status: Accepted
Date: 2026-09-30
Cycle: 04-and-search
Supersedes: 없음

## 배경
사이클 04는 조건에 맞는 책을 가진 도서관에만 대출·예약 상황을 묻는다. 수집 목록에 책마다 상세 페이지 주소가 있다. 호출 시험(2026-09-30)에서 교보·YES24 3종·강남구 상세 페이지에 수량이 나오고, 교보 구독형은 수량이 없었다. 지금 묶음 실행기(`BatchRunner`)는 검색 페이지만 가져온다.

## 결정
책의 상세 페이지를 읽어 수량을 얻는다. 화면 종류별 adapter에 상세 읽기(`parseDetail`)를 더하고, 묶음 실행기가 검색 페이지와 상세 페이지를 모두 처리하도록 일반화한다(`LookupTask` [안]). 교보 구독형은 요청하지 않고 구독형으로 판정한다.

## 이유 (사용자 발언)
- "나. 상세 페이지 읽기 이걸로해줘" (검색 화면에서 책 코드로 골라내기 대신)
- "열지 않고 구독형으로 표시" (교보 구독형)
- adapter·실행기 넓히기는 [이유 미확인] (추천안 선택)

## 검토한 대안
### 상세 페이지 + 기존 adapter·실행기 넓히기 (채택)
- 장점: 요청 한 번에 정확히 그 책. 호출 예의(캐시·간격·20줄·8초·바쁜 호스트 건너뛰기)를 한곳에서 지킴
- 단점: adapter가 조금 커짐. 화면 종류마다 상세 읽기 코드 필요
### 검색 화면에서 책 코드로 골라내기
- 장점: 기존 읽기 코드 재사용
- 단점: 흔한 제목이면 여러 쪽을 넘겨야 함
- 채택하지 않은 이유: [이유 미확인]
### 상세 전용 읽기 클래스와 실행기를 따로
- 장점: 검색 코드를 안 건드림
- 단점: 호출 예의 코드가 두 벌
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 같은 제목의 다른 책이 섞이지 않고 가진 도서관에만 요청함. 감수하는 점: 교보 구독형은 사이트에서 없어진 책을 바로 알아채지 못함. 강남구는 연관 도서 수량이 섞여 본 책 블록만 읽어야 함.
