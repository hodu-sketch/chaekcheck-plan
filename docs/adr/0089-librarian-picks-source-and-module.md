# ADR-0089: 인기 도서를 사서추천도서로 바꿈 — 출처는 국립중앙도서관 Open API, 새 모듈 `picks`, `popular`는 지움

Status: Accepted
Date: 2026-10-12
Cycle: 14-librarian-picks
Supersedes: 0072, 0073, 0080

## 배경
사이클 10에서 출판유통통합전산망 판매 순위·표지를 받는 `popular` 모듈을 만들었으나(배포 전), 진흥원 출판데이터팀이 이용약관 제10조를 들어 "승인 어려움"으로 회신했다(2026-10-12, `docs/research/popular-books/kpipa.md` 5절). 다른 출처를 조사한 결과(`docs/research/popular-books/alternatives.md`) 전국 단위 성인 인기 전자책 순위를 공식으로 주는 곳은 찾지 못했고, 국립중앙도서관 사서추천도서는 공공데이터포털 표기 공공누리 제1유형이며 우리 전자책 목록과 60.2%(최근 1년 61.5%) 맞았다(3-1절).

## 결정
- 화면 "인기 도서" → "사서추천도서"(`/picks`). 출처는 국립중앙도서관 사서추천도서 Open API(`saseoApi.do`, 인증키)
- 받기: 매주 월요일 05:00, 등록일 2년 범위로 요청 1건, 추천 연월이 다른 최근 6개 달만 남김. 실패하면 앞 목록 그대로, 다음 날 한 번 더. 목록이 없으면 서버가 켜질 때 받음. 인증키는 서버 비밀값(환경 변수)에만 두고 로그·화면·문서에 남기지 않음
- 새 모듈·스키마 `picks`가 받기·저장·API를 맡음. 표는 `fetch_run`, `pick`(지금 목록 하나, 바뀌면 통째로 교체), `cover`. `popular` 모듈·표·changeset(`popular/001`)·출판유통통합전산망 코드와 시험 자료는 지우고 `picks/001`을 새로 씀(배포 전 규칙). 로컬 DB는 `popular` 스키마와 적용 기록을 손으로 지움
- 분류: 전체 → 문학 → 인문 → 사회 → 자연 → 테마 고정, 책이 0권인 분류는 숨김. 모르는 새 분야 코드는 "전체"에 넣고 분류 목록 맨 뒤에 API가 준 이름(비면 "기타")으로 붙이며 받기 기록에 남김
- API `GET /api/v1/picks`, `GET /api/v1/picks/covers/{coverId}`. `/api/v1/popular-books`는 지움
- 출판유통통합전산망에는 어떤 요청도 보내지 않음

## 이유 (사용자 발언)
- "현재 '인기도서' 를 '사서추천도서'로 바꿔주고 출처도 다르게 해줘 그리고 '인기도서'는 이거 백로그에 남겨줘" (2026-10-12)
- 받는 방법: "공식 Open API (추천)" (2026-10-12)
- 범위: "최근 추천 6번 (추천)", 받는 때: "일주일에 한 번" (2026-10-12)
- 이름: "picks로 새로 (추천)" (2026-10-12)
- 분류: "전체·문학·인문·사회·자연·테마 (추천)" (2026-10-12)
- 새 분야: "새 분야 오면 그냥 넣는게 어떨까하는데 어때?" (2026-10-12). 넣는 방식은 사용자 선호 없음 → 추천안
- 저장 방식(지금 목록 하나): 승인 (2026-10-12). 이유 발언은 [이유 미확인]

## 검토한 대안
### A안: 국립중앙도서관 Open API + 새 모듈 `picks`, 옛 changeset 지우고 새로 씀 (채택)
- 장점: 이름이 화면·API와 맞음, changelog에 옛 표 정의가 남지 않음, `popular` 이름은 다음 "인기 도서"를 위해 비워 둠
- 단점: 바꿀 파일이 많음(대부분 이름), 로컬 DB를 손으로 지움
### B안: 모듈 이름 `popular` 그대로, 표만 고침
- 장점: 바꿀 파일이 가장 적음
- 단점: 이름과 뜻이 어긋남
- 채택하지 않은 이유: [이유 미확인]
### C안: `picks`로 바꾸되 옛 changeset을 남기고 지우는 changeset 추가
- 장점: 손으로 DB를 지우지 않음
- 단점: 첫 배포 때 만들었다 지우는 단계가 생김
- 채택하지 않은 이유: [이유 미확인]
### D안: 웹 "엑셀 다운로드"로 받기
- 장점: 키 없이 한 번에 받음
- 단점: 파일의 이용 조건이 화면에 없음
- 채택하지 않은 이유: [이유 미확인] (사용자가 Open API를 고름)
### E안: 도서관 정보나루 인기대출도서
- 채택하지 않은 이유: "아동 도서가 20대 30대 무슨 필터를 걸어도 너무 많아서 쓸 수가 없어" (2026-10-12)
### F안: 받아 둔 사이트 순위 계속 쓰기
- 채택하지 않은 이유: 출판유통통합전산망 회신 "승인 어려움" (2026-10-12)

## 결과
- 좋아지는 점: 이용 조건이 분명한 공공 데이터, 요청이 주 1~2건, 표가 셋으로 줆
- 감수하는 점: 순위가 아니라 사서 추천(분야마다 1년에 10권 안팎). 국립중앙도서관이 추천을 멈추면 마지막 6번이 계속 보임. 인증키를 운영 비밀값으로 관리해야 함
- 나중에 서비스로 분리할 때: `picks` 서비스 하나 = 스키마 하나, 의존은 `catalog`·`library` 공개 API뿐
