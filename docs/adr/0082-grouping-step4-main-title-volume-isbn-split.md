# ADR-0082: 네 번째 묶기 단계는 본제목과 권 표시로 비교하고, ISBN이 다르면 나누며, 자리 채움 값은 없는 것으로 본다

Status: Accepted
Date: 2026-10-12
Cycle: 12-grouping-rules
Supersedes: 없음 (ADR-0035의 네 번째 단계 부분을 바꿈. 번호 체계 부분은 그대로)

## 배경
지금 네 번째 단계(같은 글자)는 전체 제목 + 첫 저자 + 출판사가 같으면 ISBN을 보지 않고 합친다(ADR-0035). 표본 조사(`docs/research/ebook-catalog/same-book-isbn.md` 5.4·5.6, 2026-10-12)에서 판이 다른 ISBN 둘 이상이 한 책에 든 책이 3,079권(사이트 4건 확인 모두 다른 판), 저자·출판사 "기타"로 다른 전자책이 합쳐진 예(「햄릿」 등), 본제목·저자·출판사가 같은데 부제 표기 차이로 따로 남은 묶음 44,461개가 나왔다. 방향은 2026-10-12에 정했다(5.5절 Q2~Q5).

## 결정
네 번째 단계의 키를 "비교 제목(본제목에서 목록에 든 이용 안내 꼬리를 뗌) + 권 표시(숫자 목록, 상·중·하, 판 표시 낱말) + 첫 저자 + 출판사"로 바꾼다. 같은 키 안에서 서로 다른 ISBN이 둘 이상이면 ISBN 있는 묶음은 각자 한 책, ISBN 모르는 묶음끼리 한 책으로 둔다. 저자 "기타"·"unknown", 출판사 "기타"·"미상"·"unknown"은 값 없음(첫 저자가 자리 채움이면 다음 저자). 규칙은 `collection` 가져오기 안(패키지 내부 `SameTextKey`)에 두고 `compact`·`sql`이 같은 함수를 부른다. ③(국가서지)이 쓰는 `BookGrouper.key`·`firstAuthor`와 `catalog`의 정리 함수·검색은 바꾸지 않는다.

## 이유 (사용자 발언)
- 방향: "이대로 해줘" (spec 질문 다섯, 2026-10-12), 설계: "전부 승인" (2026-10-12), 이 ADR 초안: "승인" (2026-10-12)
- 고른 까닭은 사용자 말이 없음 [이유 미확인]

## 검토한 대안
### A안: `collection` 안에서 버킷으로 모은 뒤 ISBN으로 나눔 (채택)
- 장점: 검색·③·`catalog` 공개 기능을 건드리지 않아 서비스 재시작이 필요 없음(ADR-0069). 처리 순서와 상관없이 "ISBN 모르는 책은 어느 판에도 붙이지 않음"을 지킴. 두 방식이 같은 함수를 부름
- 단점: `compact`는 한 번 더 훑고 메모리가 조금 늘어남(계산값 묶음당 약 4바이트) [확인 필요: dev 측정]
### B안: 규칙을 `catalog.normalize`에 둠
- 장점: 정리 도구를 한곳에
- 단점: 검색이 안 쓰는 규칙이 공개 기능으로 늘어남, 검색 규칙 변경(재시작 필요)과 헷갈림
- 채택하지 않은 이유: [이유 미확인]
### C안: 합칠 때마다 두 쪽 ISBN이 다르면 건너뜀
- 장점: 고칠 곳이 적음
- 단점: 순서에 따라 ISBN 모르는 책이 먼저 만난 판에 붙어 spec R1-3([확정])을 어김, `sql`과 결과를 맞추기 어려움
- 채택하지 않은 이유: [이유 미확인]
### D안: 뒤 괄호를 모두 떼고 비교
- 단점: "(영문판)" 같은 다른 판이 합쳐짐
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 판이 다른 책이 판마다 한 줄, 자리 채움 값으로 합쳐지던 다른 책이 따로, 부제만 다른 같은 책이 한 줄. 네 번째 단계가 ISBN 둘을 합치지 않아 "합친 책의 ISBN이 여럿이면 하나만 남김"이 없어짐
- 감수하는 점: 판 표시도 ISBN도 없는 개정판은 여전히 합쳐짐. 이용 안내 꼬리 목록이 틀리면 다른 책이 합쳐질 수 있음(목록에 든 것만 뗌). 로마·한자 숫자 권 표시는 dev 표본 뒤 결정
- 나중에 서비스로 분리할 때: 규칙이 가져오기 쪽에 있어 그대로 함께 감
