# ADR-0025: 검색 조건은 이름 있는 파라미터 하나로 받음 (옛 주소 변환 없음)

Status: Accepted
Date: 2026-09-29
Cycle: 03-search-conditions
Supersedes: 0024

## 배경
ADR-0024는 세 API가 `q` 대신 `title` / `author` / `publisher` 중 하나를 받고, 웹이 사이클 02의 옛 주소 `/search?q=…`를 `/search?title=…`로 바꿔 열도록 정했다. 같은 날 사용자가 옛 주소 변환은 필요 없다고 했다. 아직 배포 전이라 옛 주소로 들어올 사용자가 없다. Accepted ADR은 고치지 않으므로 이 ADR로 대체한다.

## 결정
- 세 API(첫 묶음 스트림, 다음 묶음 스트림, 도서관별 더 보기)는 `q` 대신 `title=` / `author=` / `publisher=` 중 정확히 하나를 받는다.
  - 하나도 없거나 값이 비어 있으면 400 `validation_error`, `errors[].code: required` [안]
  - 둘 이상이면 400 `validation_error`, `errors[].code: too_many` [안]
  - 검색어 글자 수(정규화 후 2~50자) 오류는 지금처럼 400 `invalid_query`
- `q`는 API에서 없앤다. **웹도 `q`를 읽지 않고, 옛 주소를 바꿔 주는 처리를 두지 않는다.**
- `targets` 이벤트는 요청과 같은 이름으로 조건을 돌려준다 (예: `"author":"김달"`). 지금의 `query` 칸은 빠진다.
- 도서관 결과 페이지 객체는 바뀌지 않는다. `query`는 검색어 그대로다.
- 내부 `SearchField`·`SearchQuery(value, field)`·캐시 키(ADR-0009)는 그대로 쓴다.

## 이유 (사용자 발언)
- 이름 있는 파라미터: "나중에 and조건에 그게 나아보임" (2026-09-29)
- 옛 주소 변환을 두지 않음: "이거 왜 있어? 배포 안 되었는데 불필요해" (2026-09-29)
- `targets`에 요청과 같은 이름으로 돌려주는 것: [이유 미확인]

## 검토한 대안
### B안: 이름 있는 파라미터 하나, 옛 주소 변환 없음 (채택)
- 장점: 주소가 읽기 쉬움(`?author=김달`). 나중에 AND 조합으로 넓히기 자연스러움. 웹에 옛 주소 처리 코드가 없음
- 단점: "하나만" 규칙과 오류가 새로 생김. 사이클 02 주소(`?q=`)로 열면 검색어가 빈 첫 화면이 됨
### ADR-0024: B안 + 웹이 옛 `?q=`를 `?title=`로 바꿈
- 채택하지 않은 이유: "배포 안 되었는데 불필요해" (사용자)
### A안: `q` + `field=title|author|publisher` (architect 추천)
- 장점: 옛 주소·기존 호출이 그대로 동작. `filter`·`scope`와 같은 방식
- 채택하지 않은 이유: "나중에 and조건에 그게 나아보임" (B안을 고른 이유로 사용자)
### C안: `q` 안에 접두어 (`q=author:김달`)
- 채택하지 않은 이유: [이유 미확인]
### `targets`에 `query` + `field` 두 칸 (추천안)
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 조건 이름이 요청·주소·`targets`에서 같음. AND 조합을 열 때 파라미터를 더 받는 것으로 넓힐 수 있음
- 감수하는 점: 사이클 02 컨트롤러·스트림·웹 테스트의 `q`를 모두 고쳐야 함. API를 `q`로 부르면 400(`required`)
- 나중에 배포 뒤 파라미터를 바꾸게 되면 그때는 옛 주소 처리를 다시 검토해야 함
