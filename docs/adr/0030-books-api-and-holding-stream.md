# ADR-0030: 책 검색 API와 소장 단위 스트림을 나눔

Status: Accepted
Date: 2026-09-30
Cycle: 04-and-search
Supersedes: 없음

## 배경
사이클 04 화면은 세 가지다: 바로 보기(책 찾기 + 대출 상황), 책 먼저 고르기(책 목록만), 책 화면(책 하나의 대출 상황). 책 찾기는 DB 조회라 빠르고, 대출 상황은 도서관마다 도착하는 대로 흘려보내야 한다. 사이클 01~03은 스트림 하나(`ebook-searches/stream`)로 계획과 결과를 함께 보냈다.

## 결정
`GET /api/v1/books`(책 검색, JSON)와 `GET /api/v1/book-availabilities/stream`(소장 단위 SSE, 다음 묶음은 `…/batches/stream`)을 나눈다. 책 화면은 `GET /api/v1/books/{bookId}` + 같은 스트림. 기존 `ebook-searches` API는 도서관에서 직접 찾기로 그대로 쓴다.

## 이유 (사용자 발언)
- [이유 미확인] (Claude가 맥락을 설명한 뒤 "가. 둘로 나눔" 선택, 2026-09-30)

## 검토한 대안
### 둘로 나눔 (채택)
- 장점: 세 화면이 같은 두 API를 씀. 서버 상태 없음(ADR-0014). 나중에 책 검색과 조회를 따로 떼어 내기 쉬움
- 단점: 바로 보기는 요청이 두 번
### 기존 스트림 하나에 합침
- 장점: 바로 보기 왕복 하나 줄어듦
- 단점: 책 먼저 고르기용 API가 따로 필요하고, 스트림이 사이트 검색·목록 검색 두 뜻을 가짐
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: API마다 할 일이 분명함. 감수하는 점: 웹 계획 상태의 키가 도서관에서 소장(`holdingId`)으로 바뀜. 스트림 이벤트 이름 `holding-*` 추가.
