# ADR-0110: 새 도서관 넣기에서 전자책 0권인 곳을 뺀다

Status: Proposed
Date: 2026-10-14
Cycle: 18-empty-library-holdings
Supersedes: 없음

## 배경
사이클 18 조사에서 켜져 있는데 0권인 22곳 중 14곳은 오디오북만 있는 사이트, 1곳은 책이 없는 사이트였다. 사이클 07 때 "수집 성공"만 보고 들어왔다. 사이클 13의 넣기 명령(ADR-0107)은 빠진 이유 6개(교보 대여·혼합, 받지 않음, 수집 성공 없음, 체험용·운영 중단, 같은 사이트, 시험용)를 본다.

## 결정
넣기 명령이 새 도서관마다 "서비스로 가져올 줄 수"를 가져오기와 같은 거르기 규칙(한 벌로 꺼낸 판정)으로 세고, 0이면 빠진 이유 "전자책 0권"으로 뺀다. 이 이유는 기존 6개 다음 맨 마지막에 보고, 사용자에게 따로 묻지 않는다. 이미 서비스에 있는 도서관에는 적용하지 않는다.

## 이유 (사용자 발언)
- [이유 미확인] (조사 결정 #2, 명세 결정 #1~#5, 설계 결정 #5 승인, 2026-10-14)
- 시험을 넣음: "이거 넣으면서 테스트해야 하는 거 아니야?" (설계 결정 #6)

## 검토한 대안
### A안: 가져오기 거르기 규칙을 한 벌로 꺼내 같이 씀 (채택)
- 장점: "가져오기와 같은 규칙"이 코드로 보장
- 단점: 가져오기 클래스를 조금 다시 짬
### B안: 넣기 명령이 SQL 한 줄로 셈
- 장점: 짧고 빠름
- 단점: 규칙이 두 벌, 주소 호스트 비교를 SQL로 하기 어려움
- 채택하지 않은 이유: [이유 미확인]
### C안: 사이트 권수가 0인 곳만 거름
- 단점: 오디오북만 있는 곳을 못 거름
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 보고서·`library-left-out.md` A에 "전자책 0권"
- 교보 대여·혼합 판정은 그대로(책을 받지 않아 0권이므로 맨 먼저 봄)
- 넣을 주소와 책 주소 호스트가 달라 0줄인 드문 경우도 "전자책 0권"(지금 0곳), 시험과 넣기 절차 한 줄로 확인

## 나중에 분리할 때
- 수집·넣기 쪽 서비스 안에서 끝남
