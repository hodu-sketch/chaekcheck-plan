# ADR-0096: 사용자 행동 기록은 같은 PostgreSQL에 남기고, IP는 30일만, 나머지는 1년

Status: Proposed
Date: 2026-10-13
Cycle: 15-usage-log
Supersedes: 없음

## 배경
다음 사이클의 통계를 위해 검색과 도서관으로 넘어가는 클릭을 기록하기로 했다(사용자: "통계는 다음이고 지금은 기록이야", 2026-10-12). 운영 서버는 메모리 4GB 한 대이고(사용자: "램 4gb로 할건데 그게 걱정되어서"), 서비스는 PostgreSQL 하나를 쓴다. 2026-10-12 조사(`docs/research/usage-log/storage.md` 6절)에서는 "회원 번호·IP·브라우저 식별값을 남기지 않음"으로 정했으나, 2026-10-13 명세에서 IP를 남기기로 바꿨다.

## 결정
검색·도서관 클릭·책 상세 열기 기록을 같은 PostgreSQL의 새 schema에 남긴다. 검색 조건(지역·고른 도서관 포함), 결과 수, 로그인 여부, IP를 남기고 회원 번호·쿠키·User-Agent는 남기지 않는다. IP 칸은 30일 뒤 비우고 나머지는 1년 뒤 지운다(매일 04:30). 화면에서 나올 수 없는 이상한 클릭 알림은 IP와 함께 따로 30일 둔다.

## 이유 (사용자 발언)
- 저장 장소(같은 PostgreSQL): [이유 미확인] (JSONL 비교, DB 부담, 다른 서비스 사례, 4GB 메모리 질문에 답한 뒤 승인, 2026-10-12)
- 지역·도서관도 남김: "검색 요청을 한 사용자의 정보도 남겼으면 해 지역(직장/거주) 도서관 .. 이런거라던가"
- 로그인 여부: "로그인상태 비로그인상태 이것도 기록해줘"
- IP: "책 상세 열기도 기록하려고 하는데 그리고 ip도 기록하려고해" — IP를 남기는 이유 자체는 [이유 미확인]
- 이상한 클릭 알림의 IP: "이상한 값들도 기록해두는게 좋지 않을까? 나중에 파악해서 차단하거나 뭐..", "ip도 남기는 거로 바꿨으면 해", 보관 "30일 보관"
- IP 30일·나머지 1년: 제안 → 승인

## 검토한 대안
### A안: 같은 PostgreSQL 새 schema (채택)
- 장점: 새 프로그램 없음, 도서관·책 정보와 SQL로 바로 맞춰 봄, 기존 Liquibase·백업 그대로
- 단점: 운영 DB 디스크(1년 1~2GB 어림)를 같이 씀
### B안: JSONL 파일
- 장점: DB 부담 없음, 오래된 파일 지우기 쉬움
- 단점: 통계 때 파일을 옮겨 넣어야 함, 서버를 새로 만들면 옮기지 않은 파일이 사라짐
- 채택하지 않은 이유: [이유 미확인]
### C안: Umami / Google Analytics / S3·Athena
- 단점: 새 프로그램(4GB 서버), 국외 이전·보관 제한, 옮기는 길을 새로 만듦
- 채택하지 않은 이유: [이유 미확인]
### D안: IP를 남기지 않음 (2026-10-12 조사 결정)
- 장점: 사람을 알아보기 어려워 개인정보 부담이 가장 작음
- 단점: 같은 사람의 흐름을 못 보고, 이상한 요청을 막을 근거가 없음
- 채택하지 않은 이유: "ip도 기록하려고해" (2026-10-13)

## 결과
- 좋아지는 점: 통계 때 지역·도서관·화면·책 단위로 SQL 집계, 최근 30일은 IP로 이어 보기·비정상 요청 차단
- 감수하는 점: IP가 들어가 처리방침(사이클 16)에 항목·목적·보유 기간을 적어야 함. 사용자가 끄는 설정은 두지 않음(16 확인: 법적 근거 못 찾음, 해석례는 확인 못 함). IP가 실제 사용자 IP가 되려면 사이클 17 nginx가 `CF-Connecting-IP`를 사용자 주소로 읽어야 함
- 나중에 되돌리거나 분리할 때: 통계가 느려지면 기록 표만 분석 전용 저장소로 옮김(나중에 분리할 때). IP를 다시 빼려면 칸을 비우는 작업 하나
