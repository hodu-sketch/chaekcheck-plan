# ADR-0041: 계정 삭제는 AccountDeleted 이벤트로 알리고, 발행 저장소의 완료 기록은 지움

Status: Accepted
Date: 2026-10-04
Cycle: 05-login-account
Supersedes: 없음

## 배경
계정이 지워지면 다른 모듈(사이클 06의 `member`)이 자기 자료를 지워야 한다. 모듈끼리 직접 부르지 않기로 했으므로(ADR-0036) 이벤트로 알린다. 알림 직후 서버가 꺼지면 받는 쪽의 일이 사라질 수 있다. Spring Modulith 발행 저장소는 받는 쪽마다 기록을 만들기 때문에, 받는 쪽이 없는 이번 사이클에는 기록이 생기지 않는다.

## 결정
`AccountDeleted(accountId)`를 계정 삭제와 같은 트랜잭션에서 발행하고 JDBC 발행 저장소에 기록한다. 저장소 표(`event_publication`)는 어느 모듈에도 속하지 않는 별도 스키마에 Liquibase로 만든다. 이번 사이클에는 `auth` 안에 받는 쪽을 하나 둔다(서버 로그에 한 줄). 완료된 기록은 바로 지운다(`completion-mode: delete`).

## 이유 (사용자 발언)
- "공통 + 웹훅 + 이벤트·저장소" (2026-10-01)
- "db에 기록하고 delete 로그 파일은 좀 불안정해서.. 근데 로그 파일도 안전하게 할 수 있으면 나쁘지 않은데 흠 재기동이런거 생각하면" (2026-10-04)

## 검토한 대안
### A안: 계정 삭제는 AccountDeleted 이벤트로 알리고, 발행 저장소의 완료 기록은 지움 (채택)
- 장점 / 단점: "결과" 절 참고
### B안: 받는 쪽을 두지 않고 AC-15를 발행 확인만으로 바꿈
- 장점: 하는 일 없는 코드가 없음
- 채택하지 않은 이유: [이유 미확인] (받는 쪽을 두는 안을 승인)
### C안: 완료 기록을 남기고 따로 정리
- 장점: 나중에 표에서 이력을 볼 수 있음
- 채택하지 않은 이유: "db에 기록하고 delete" (2026-10-04)
### D안: 표를 구간으로 나눠 오래된 구간을 버림 (partition, drop)
- 장점: 큰 표에서 지우는 비용이 작음
- 채택하지 않은 이유: [이유 미확인] (사용자가 물었고, 탈퇴 때만 한 줄 생기는 표에는 과하다는 답을 본 뒤 삭제 방식을 승인)

## 결과
- 좋아지는 점: 받는 쪽이 실패하거나 서버가 꺼져도 기록이 남아 다시 처리할 수 있음. 지워진 계정 번호가 DB에 남지 않음
- 감수하는 점: 완료된 뒤에는 표에서 이력을 볼 수 없어 AC-15를 테스트로 확인함. 이번 사이클의 받는 쪽은 로그 한 줄만 남김
- 되돌리는 비용: 완료 기록을 남기려면 설정 한 줄. 나중에 분리할 때 이 이벤트는 서비스 사이의 메시지가 됨
