# ADR-0034: 전자책 목록(사실 정보)을 서비스 DB에 저장함

Status: Accepted
Date: 2026-09-30
Cycle: 04-and-search
Supersedes: 없음

## 배경
사이클 01은 검색할 때 수량만 읽고 쌓아 두지 않았다(사이클 01 spec 10장, 저작권법 제93조 반복적·체계적 복제 위험). 도서관 사이트는 필드별 AND 검색을 해 주지 않고, 공개된 전자책 소장 목록 데이터는 찾지 못했다(research.md, 2026-09-30).

## 결정
도서관 사이트에서 직접 모은 전자책 목록의 사실 정보(제목·저자·출판사·출판일·소장 여부·상세 주소·표지 주소)를 서비스 DB에 저장한다. 책 소개·저자 소개·목차·서평 문장은 저장하지 않고 표지는 주소만, 대출·예약 수는 저장하지 않고 실시간으로 묻는다. 남(웹러브 북스 등)이 모은 DB는 가져오지 않는다. 비영리 공개를 유지한다.

## 이유 (사용자 발언)
- "크롤링한 데이터베이스를 미리 가지고 있는게 어떨까 해" (2026-09-30)
- "웰러브북스에 있는 책들은 어지간하면 다 수집할 예정이고", "직접 모으는 거 맞아" (2026-09-30)
- 소개글·표지·수량 저장 범위는 사용자 선택 (2026-09-30), 이유 [이유 미확인]

## 검토한 대안
### 사실 정보만 저장 (채택)
- 장점: 여러 조건 AND 검색, 가진 도서관에만 조회
- 단점: 법적 위험이 커짐(출시 전 전문가 확인 필요)
### 계속 쌓아 두지 않음 (사이클 01 방식)
- 장점: 법적 위험이 작음
- 단점: 필드별 AND 검색을 할 수 없음
- 채택하지 않은 이유: [이유 미확인]
### 남이 모은 DB 가져오기
- 장점: 빠름
- 단점: DB 제작자 권리·성과 도용 위험이 가장 큼
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 목록 기반 검색. 감수하는 점: 목록은 수집 시점 기준이라 도서관별 기준일을 보여야 하고 주기 갱신이 필요함. 저작권법 제93조·부정경쟁방지법 위험은 출시 전 전문가 확인 [확인 필요].
