# ADR-0102: 액세스 토큰 쿠키 경로를 `/api/v1`로 넓히고, 로그인 상태 판별은 `auth`의 부품 하나에 모음

Status: Accepted
Date: 2026-10-14
Cycle: 15-usage-log
Supersedes: 없음 (ADR-0042의 "액세스 토큰 쿠키 `Path=/api/v1/me`" 부분만 바꿈)

## 배경
사이클 15 사용 기록에 로그인 여부를 남기기로 했다(사용자: "로그인상태 비로그인상태 이것도 기록해줘", 2026-10-13). 처음에는 화면이 값을 보내기로 했으나, 조작할 수 있다는 점을 보고 서버가 쿠키로 직접 확인하기로 바꿨다(사용자: "서버가 로그인 쿠키로 직접 확인", 2026-10-14). 지금 액세스 토큰 쿠키(15분)는 ADR-0042대로 `Path=/api/v1/me`라 검색 주소로는 오지 않는다. 로그인 기능은 꺼질 수 있다(ADR-0046).

## 결정
- 액세스 토큰 쿠키 경로를 `/api/v1`로 넓힌다. 리프레시 토큰 쿠키(`/api/v1/auth`)와 `Secure`·`HttpOnly`·`SameSite=Lax`는 그대로다.
- 로그인 모듈(`auth`)이 "로그인 상태 판별" 부품 하나를 공개한다. 쿠키 읽기와 서명 확인은 이 부품 안에만 둔다. 우리 서명이 맞으면 만료돼도 "로그인함", 없거나 틀리면 "안 함"이며, 이 판단은 기록에만 쓰고 권한에는 쓰지 않는다.
- 로그인 기능이 꺼져 있으면 쿠키를 보지 않는 판별 부품으로 바꿔 끼우고 늘 "로그인 기능 꺼짐"을 돌려준다.
- 옛 경로(`/api/v1/me`) 쿠키를 지우는 코드는 넣지 않는다. 액세스 쿠키는 15분이면 만료된다(dev `application.yml`) (사용자: "아직 서비스 테스트라서 굳이 옛 경로 지우는 코드 안 넣어도 될 것 같아", 2026-10-14).
- `auth`의 CSRF 보호 주소에 사용 알림 주소(`POST /api/v1/usage-events`)를 더한다. 로그인은 요구하지 않고 CSRF 표시만 검사한다(로그인 기능이 꺼지면 검사 자체가 없음). (2026-10-14 덧붙임, 설계 검토)
- 이 부품은 기록 모듈(`usagelog`)만 부르며, 검색 모듈은 로그인을 모른다. 검색·책 상세·사용 알림은 계속 로그인 없이 되고 쿠키 확인 실패는 오류가 아니다.

## 이유 (사용자 발언)
- 서버 확인: "서버가 로그인 쿠키로 직접 확인" (화면 값은 조작 가능하다는 답을 본 뒤)
- 한곳에 모음·꺼짐이면 확인 안 함: "이 서비스 로그인 한거 안한거 분류되도록 해야 하니까 그거 주의해서 설계해야 해", "로그인 안 쓰기 설정이 되어 있으면 체크 안 하게", "이거 코드 안 더러워지도록 개발하도록 해줘 한 데 모아서 관리하거나 관리하는 부분을 정해서 했으면 해"
- 경로 `/api/v1`, 만료돼도 로그인함, 세 가지 값: 제안 → 승인 [이유 미확인]

## 검토한 대안
### A안: 경로 `/api/v1` + `auth` 판별 부품 (채택)
- 장점: 판별 규칙이 한곳, 검색 모듈은 로그인을 모름, 꺼짐이면 쿠키를 보지 않음
- 단점: `usagelog`가 `auth`에 의존(허용 모듈 library·auth), 쿠키가 모든 API 요청에 실림
### B안: 화면이 로그인 여부를 값으로 보냄
- 채택하지 않은 이유: "서버가 로그인 쿠키로 직접 확인" (조작 가능)
### C안: 쿠키 경로 `/` (`__Host-` 접두어 사용 가능)
- 장점: ADR-0042에서 포기한 `__Host-` 보호를 쓸 수 있음
- 단점: 화면 파일 요청에도 쿠키가 실림
- 채택하지 않은 이유: [이유 미확인]
### D안: 로그인 모듈 필터가 모든 요청에서 판별해 요청에 붙여 둠
- 단점: 숨은 약속(요청 속성), 기록하지 않는 요청까지 판별
- 채택하지 않은 이유: [이유 미확인]
### E안: 만료면 "모름" / 화면이 검색 전에 쿠키를 새로 받아 옴
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 로그인 여부를 조작할 수 없고, 판별 규칙을 바꿀 때 `auth` 한곳만 고침, 로그인 꺼짐 기간을 통계에서 따로 셈
- 감수하는 점: 액세스 쿠키가 모든 API 요청에 실림(여전히 HttpOnly·Secure·SameSite=Lax, 보내기 요청은 CSRF 검사), 검색마다 서명 확인 한 번
- 나중에 되돌리거나 분리할 때: 쿠키 경로를 다시 좁히면 로그인 여부 칸은 "안 함"만 남음. 분리할 때는 판별 부품을 토큰 확인 서비스 호출로 바꾸면 부르는 쪽은 그대로
