# ADR-0010: 도서관 호출 간격 제어 단위를 호스트 이름으로

Status: Accepted
Date: 2026-09-28
Cycle: 02-library-expansion
Supersedes: 0007

## 배경
ADR-0007은 `host:port`마다 동시 1건, 요청 사이 1초 이상을 지켰다. 사이클 02 조사에서 교육청 서버 한 대가 포트만 바꿔 도서관 여러 곳을 올려 둔 것을 확인했다. `ebook.jbe.go.kr` 17곳, `ebook.jne.go.kr` 12곳, `elib.goe.go.kr`·`ebook.gne.go.kr` 각 9곳, `elib.gyeongnam.go.kr` 8곳, `e-lib.ice.go.kr` 7곳이다 (research.md 5절, 2026-09-28). ADR-0007대로라면 이 서버 한 대에 동시에 최대 17건이 간다. 조회 서비스를 여러 대로 나누는 결정(ADR-0011)과 함께 정한다.

## 결정
호출 간격 제어 단위를 **호스트 이름**으로 바꾼다 (포트 무시). 호스트 이름마다 공정한 세마포어 1개와 마지막 요청 종료 시각을 두고, "이전 요청 종료 + 1초"까지 기다린 뒤 요청한다. 기다리는 시간도 요청당 8초 제한에 포함하고, 넘으면 504로 끝낸다 (ADR-0007과 같음). 간격 제어는 본 서비스 한곳에서만 하고, 조회 서버(ADR-0011)는 간격을 제어하지 않는다.

## 이유 (사용자 발언)
- "대응할 수 있게 ADR-0007을 바꿔줘" (2026-09-28)

## 검토한 대안
### A안: 호스트 이름 단위 (채택)
- 장점: 같은 서버에 있는 도서관들에 한 번에 한 건만 감
- 단점: 같은 서버의 도서관들은 차례로 조회되어, 한 검색에서 여러 곳을 조회하면 늦어짐 (17곳이면 17초 넘게 걸릴 수 있음)
### B안: `host:port` 유지 (ADR-0007)
- 장점: 도서관마다 병렬이라 빠름
- 단점: 같은 서버에 동시에 여러 건이 감
- 채택하지 않은 이유: [이유 미확인]
### C안: 호스트 이름 단위로 묶되 동시 N건 허용
- 장점: A안보다 빠름
- 단점: N 값의 근거가 없음
- 채택하지 않은 이유: [이유 미확인]

## 결과
- 좋아지는 점: 교육청처럼 서버 한 대에 도서관이 여러 곳인 경우에도 서버 하나에 동시 1건, 1초 간격이 지켜짐
- 감수하는 점: 같은 서버의 도서관 여러 곳이 한 검색의 대상이면 결과가 늦게 모임. 도서관을 나눠 찾는 검색 구조(scope의 "약 20권씩")에서 한 묶음에 같은 서버 도서관을 몰아넣지 않는 식으로 줄일 수 있음 [안]
- `*.dkyobobook.co.kr`, `*.yes24library.com`처럼 업체가 호스팅하는 도서관은 호스트 이름이 달라 따로 제어됨. 실제로 같은 서버인지는 확인하지 않음 [확인 필요]
- 나중에 본 서비스를 여러 대로 늘릴 때: 간격 제어 상태를 공유해야 함 (ADR-0006과 함께 Redis 검토)
